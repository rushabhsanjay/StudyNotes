# Robot Architecture

## 1. What is robot architecture?

Robot architecture is the complete arrangement of mechanical, electrical, electronic, control, sensing, communication, and safety systems that work together to make an industrial robot perform a task.

An industrial robot is not simply a robotic arm. It is a coordinated system consisting of the arm, motors, drives, controller, sensors, end effector, safety equipment, application software, and interfaces to surrounding production equipment.

In an automotive manufacturing plant, a robot may perform spot welding, arc welding, material handling, machine tending, adhesive dispensing, painting, inspection, or assembly.

For maintenance and development, the objective is to understand how a command travels through the system, how physical motion is produced, how feedback is processed, and how the robot coordinates with the rest of the production line.

## 2. The complete robot system

A typical industrial robot installation contains the following subsystems:

| Subsystem                | Main function                                       | Examples                                                  |
| ------------------------ | --------------------------------------------------- | --------------------------------------------------------- |
| Mechanical manipulator   | Provides the robot's physical movement              | Links, joints, bearings, gears, wrist                     |
| Robot motors             | Produce controlled movement                         | Servo motors                                              |
| Robot drives             | Regulate motor current, torque, speed, and position | Servo amplifiers and drive modules                        |
| Robot controller         | Computes motion and coordinates robot functions     | Industrial robot control cabinet and controller software  |
| Feedback devices         | Report motor or joint movement                      | Encoders, resolvers, other supported sensors              |
| End effector             | Interacts with the workpiece or process             | Gripper, welding gun, suction tool                        |
| Tooling and fixtures     | Locate and hold the workpiece                       | Fixtures, clamps, locating pins                           |
| External sensors         | Detect machine and process conditions               | Proximity sensors, vision cameras, force sensors          |
| Safety system            | Reduces risk from hazardous motion                  | Safety controller, guards, interlocks, scanners           |
| Communication interfaces | Exchange signals and data                           | Industrial Ethernet, fieldbus, digital I/O                |
| Application equipment    | Performs the production process                     | Welding controller, adhesive system, inspection equipment |

The exact hardware depends on the robot manufacturer, robot model, application, and installed options.

## 3. Robot architecture stack

```
Production Process
   ↓
PLC / Line Controller / Cell Coordination
   ↓
Robot Program and Application Logic
   ↓
Robot Controller
   ├── Motion planning and interpolation
   ├── Coordinate transformations
   ├── Servo control
   ├── Robot I/O and communications
   └── Diagnostics and fault handling
          ↓
       Robot Drives
          ↓
       Servo Motors
          ↓
       Mechanical Joints and Links
          ↓
       Tool Centre Point / End Effector
          ↓
       Workpiece or Process

Feedback:
Encoders / Sensors / External Equipment
   → Drives and Controller / PLC as configured

Safety:
Safety devices and safety control functions
   → Defined safe response of robot, tooling, and cell
```

This is a conceptual architecture. A real installation may distribute functions across the robot controller, safety controller, PLC, drives, and application equipment.

## 4. Robot manipulator: mechanical structure

The manipulator is the physical mechanism that positions and orients the end effector.

### Main mechanical components

- Base: Mounts the robot to the floor, pedestal, wall, ceiling, or another approved structure.
- Links: Rigid structural members connecting the joints.
- Joints: Provide controlled relative movement between links.
- Bearings and transmissions: Support motion and transfer motor torque.
- Wrist: Provides the final orientation movements on many industrial robots.
- Tool flange: Mechanical mounting interface for the end effector.
- Cables and hoses: Carry power, signals, air, coolant, or process media as required.
- Dress pack: Routes cables and hoses along the robot or external axes.

The manipulator's geometry determines its reach, workspace, payload capability, stiffness, and accessible orientations.

### Robot types by mechanical structure

| Robot type          | Typical characteristics                                                         | Common applications                              |
| ------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------ |
| Articulated robot   | Multiple rotary joints; often six axes                                          | Welding, handling, assembly, machine tending     |
| SCARA robot         | Selective compliance in a predominantly horizontal working plane                | High-speed assembly and pick-and-place           |
| Cartesian robot     | Linear motion along orthogonal axes                                             | Gantry handling, dispensing, loading             |
| Delta robot         | Parallel-link structure with high-speed motion capability                       | Sorting, picking, packaging                      |
| Collaborative robot | Designed with features intended to support specified collaborative applications | Assembly, handling, selected human-shared tasks  |
| Parallel robot      | Multiple kinematic chains support a moving platform                             | Specialized high-speed or precision applications |

These categories describe different architectures, not interchangeable safety classifications. A robot's safety suitability depends on the complete application and its risk assessment.

## 5. Robot axes and degrees of freedom

A robot axis is a controlled motion coordinate. A degree of freedom describes an independent way the robot can move.

A common six-axis articulated robot has three main positioning axes and three wrist-orientation axes. Other robots can have fewer or more axes.

| Typical axis | General role                   | Typical effect                                         |
| ------------ | ------------------------------ | ------------------------------------------------------ |
| J1           | Base rotation                  | Sweeps the arm around its mounting base                |
| J2           | Lower-arm or shoulder movement | Moves the arm through a major portion of its workspace |
| J3           | Upper-arm or elbow movement    | Extends or retracts the arm                            |
| J4           | Wrist rotation                 | Changes tool orientation                               |
| J5           | Wrist bending                  | Changes tool angle                                     |
| J6           | Final wrist rotation           | Rotates the tool around its final axis                 |

The actual axis naming, directions, and mechanical roles vary by robot model. J1 through J6 is a common convention, not a universal guarantee.

### Joint coordinates versus Cartesian coordinates

- Joint coordinates: Each robot axis is commanded in its own joint units, commonly degrees for rotary joints and millimetres for linear axes.
- Cartesian coordinates: The tool or reference point is commanded by its position and orientation in a coordinate frame.
- Tool coordinates: Describe the tool's position and orientation relative to a selected tool frame.
- World or base coordinates: Describe position relative to a defined reference frame associated with the cell or robot base.

A robot can reach the same Cartesian position using different joint configurations. Not every configuration is reachable or permitted, and some may create singularities or collisions.

## 6. Robot controller

The robot controller is the computational and control centre of the robot system. It executes the robot program, computes motion, coordinates drives, manages I/O, and reports diagnostic information.

The next study topic, `02_Controller`, will cover this subsystem in detail.

At the architecture level, its responsibilities include:

- Interpreting the robot program.
- Planning the required path and motion.
- Transforming between coordinate frames.
- Sending motion commands to the drives.
- Processing feedback from the robot axes.
- Managing configured robot I/O and communications.
- Coordinating application functions and program execution.
- Reporting alarms and diagnostic states.
- Implementing or coordinating applicable safety-related functions.

A robot controller is not the same as the cell PLC. The robot controller specializes in robot motion and robot-specific functions, while the PLC typically coordinates the larger machine or production cell. Some responsibilities can overlap depending on the design.

## 7. Servo motors, drives, and feedback

Industrial robots commonly use servo motors to control the movement of individual axes.

A servo system combines a motion command, a drive, a motor, a mechanical load, and feedback. The drive regulates motor operation so the robot can follow the commanded trajectory.

```
Robot motion command
   ↓
Servo controller / drive
   ↓
Motor current and torque
   ↓
Servo motor
   ↓
Transmission and joint movement
   ↓
Robot axis moves
   ↓
Feedback device measures movement
   ↓
Control system evaluates tracking error
```

The implementation of the control loops depends on the robot platform. Position, velocity, and current or torque control may be distributed between the robot controller and servo drives.

### Important servo concepts

| Term             | Meaning                                          | Maintenance relevance                                        |
| ---------------- | ------------------------------------------------ | ------------------------------------------------------------ |
| Position command | Requested axis position                          | Defines the intended movement                                |
| Actual position  | Position measured through feedback               | Used to determine tracking accuracy                          |
| Position error   | Difference between commanded and actual position | Can indicate tracking problems                               |
| Velocity         | Rate of position change                          | Relevant to motion performance and drive diagnostics         |
| Torque           | Rotational force produced by the motor           | Affected by load, acceleration, friction, and disturbances   |
| Encoder          | Device providing position or movement feedback   | Faults can cause position errors or loss of feedback         |
| Servo drive      | Power electronics and control for the motor      | May report overload, overcurrent, or feedback-related faults |
| Brake            | Holds an axis under specified conditions         | Important for vertical or gravity-loaded axes                |

### Common servo-related faults

- Axis fails to enable.
- Servo drive reports a fault.
- Position error exceeds its permitted limit.
- Motor or drive overheats.
- Axis movement becomes noisy or irregular.
- Brake does not release or engage as expected.
- Feedback signal becomes intermittent.
- Robot reaches a position differently from expected.

Do not assume every position error originates in the encoder. Mechanical resistance, damaged cables, drive faults, brake problems, excessive payload, collision damage, and incorrect configuration can produce related symptoms.

## 8. Robot kinematics and coordinate transformations

Kinematics describes the relationship between robot joint positions and the position and orientation of the tool.

### Forward kinematics

Forward kinematics calculates the tool pose from the known robot joint positions and the configured robot geometry.

Conceptually:

\\[ \text{Joint positions} \rightarrow \text{Tool position and orientation} \\]

### Inverse kinematics

Inverse kinematics calculates one or more possible joint configurations that can achieve a requested tool pose.

\\[ \text{Requested tool pose} \rightarrow \text{Possible joint configurations} \\]

Inverse kinematics can produce multiple solutions. A solution may be unreachable, outside a joint limit, or unsuitable because of collision risk or singularity.

### Coordinate frames

Industrial robot programs often rely on several coordinate frames.

| Frame                   | Purpose                                                                             |
| ----------------------- | ----------------------------------------------------------------------------------- |
| World frame             | Defines a shared reference for the robot cell, where configured                     |
| Robot base frame        | References position to the robot mounting base                                      |
| Joint frame             | Describes motion relative to individual robot joints                                |
| Tool frame              | Defines the tool's position and orientation relative to the tool mounting interface |
| Workpiece or user frame | Defines a coordinate system relative to the workpiece, fixture, or process          |
| External-axis frame     | Represents an additional coordinated axis, where fitted                             |

The exact names and configuration methods depend on the robot manufacturer.

### Why coordinate frames matter

A robot may move correctly in its base coordinate system but miss the workpiece because the tool or workpiece frame is incorrect.

Potential causes include:

- Incorrect tool-centre-point calibration.
- Incorrect workpiece-frame calibration.
- A fixture moved from its calibrated position.
- Incorrect robot mounting or geometry data.
- A tool changed without updating its data.
- Incorrect external-axis configuration.

For precision work, verify both the programmed pose and the coordinate frames used to interpret it.

## 9. Tool centre point and payload

The tool centre point (TCP) is a defined reference point associated with the tool. It is commonly used to specify the intended tool position during robot motion.

For a welding gun, the TCP may be associated with the intended welding reference point. For a gripper, it may be a reference point used to position the gripper relative to a workpiece.

TCP data commonly describes a translation and orientation relative to the tool mounting flange.

### Tool calibration

Tool calibration establishes the relationship between the robot flange and the selected tool reference frame.

If the TCP is incorrect, the robot may reach its programmed flange position but place the actual tool tip at the wrong location.

### Payload data

Payload configuration may include:

- Mass of the tool and carried workpiece.
- Centre of gravity relative to the tool flange.
- Inertia properties where required by the controller.
- Payload identification or monitoring information, where supported.

Incorrect payload data can affect motion performance, tracking, vibration, braking demands, and safety-related assumptions.

Maintenance rule: After a tool or gripper change, verify the approved tool and payload configuration before production. Do not compensate for an incorrect TCP by arbitrarily editing every robot position.

## 10. Robot end effectors and application equipment

The end effector is the device at the robot wrist that performs the task.

| End effector              | Typical purpose                             | Common maintenance concerns                                             |
| ------------------------- | ------------------------------------------- | ----------------------------------------------------------------------- |
| Mechanical gripper        | Holds a component using fingers or jaws     | Jaw wear, actuator condition, clamping confirmation                     |
| Vacuum gripper            | Holds components using suction              | Vacuum supply, leaks, suction cups, pressure or vacuum feedback         |
| Spot-welding gun          | Applies electrode force and welding current | Electrode wear, gun alignment, cooling, force and weld-system condition |
| Arc-welding torch         | Guides the welding process                  | Torch condition, wire feed, gas supply, cable routing                   |
| Adhesive dispenser        | Applies sealant or adhesive                 | Nozzle blockage, pressure, flow, material supply                        |
| Inspection tool or camera | Acquires measurements or images             | Calibration, lighting, contamination, communications                    |
| Screwdriving tool         | Tightens fasteners                          | Torque control, tool wear, fastening feedback                           |

The robot's motion may be correct while the application process fails. For example, a robot can reach the correct spot-welding position while the welding controller reports a process fault.

Separate robot motion faults from end-effector and process-equipment faults.

## 11. Robot I/O and cell coordination

A robot rarely works in isolation. It usually exchanges signals with a PLC, machine tool, conveyor, fixture, safety controller, or another robot.

### Common signal categories

- Digital inputs and outputs.
- Analog inputs and outputs, where supported.
- Industrial Ethernet or fieldbus data.
- Robot status and program-state signals.
- Tool and process signals.
- Safety-related signals through approved safety interfaces.

Examples of cell signals include:

| Signal         | Typical direction                     | Purpose                                           |
| -------------- | ------------------------------------- | ------------------------------------------------- |
| Start request  | PLC to robot                          | Requests a defined robot program or operation     |
| Robot ready    | Robot to PLC                          | Indicates the configured ready condition          |
| Cycle complete | Robot to PLC                          | Indicates completion of the defined operation     |
| Fault active   | Robot to PLC                          | Indicates a robot fault or configured fault state |
| Part present   | Sensor or PLC to robot                | Confirms that a workpiece is present              |
| Gripper closed | End effector or PLC to robot          | Confirms the expected gripper state               |
| Machine ready  | Machine or PLC to robot               | Permits the next coordinated operation            |
| Safety status  | Safety system to relevant controllers | Indicates configured safety conditions            |

These are examples, not universal signal names or wiring conventions.

### Typical robot-cell handshake

```
PLC confirms cell conditions
   ↓
PLC requests robot cycle
   ↓
Robot checks its program and configured conditions
   ↓
Robot performs the assigned operation
   ↓
Robot confirms completion
   ↓
PLC validates machine and cell conditions
   ↓
Next production operation is permitted
```

A missing handshake signal can stop the entire production cell even if the robot has no internal motion fault.

When a robot is waiting, identify the exact condition it is waiting for. Check the signal's source, actual state, expected state, and the logic that generates it.

## 12. Industrial communication networks

Robots may communicate with PLCs, drives, remote I/O, vision systems, safety equipment, and production information systems over supported industrial networks.

The exact protocols depend on the manufacturer, controller generation, and installed options.

| Communication type            | Typical use                                                      | Diagnostic focus                                     |
| ----------------------------- | ---------------------------------------------------------------- | ---------------------------------------------------- |
| Digital I/O                   | Basic machine handshake and status                               | Signal state, wiring, I/O mapping                    |
| PROFINET                      | Industrial Ethernet communication on supported systems           | Device status, configuration, network connection     |
| EtherNet/IP                   | Industrial Ethernet communication on supported systems           | Connection state, device configuration, data mapping |
| PROFIBUS                      | Fieldbus communication on supported legacy or configured systems | Bus diagnostics, device state, wiring                |
| Device-specific robot network | Robot and controller internal communication                      | Manufacturer-specific diagnostics                    |
| TCP/IP-based communication    | Supported data exchange with applications and computers          | Addressing, ports, permissions, service availability |

Never assume a robot supports every protocol or that a protocol is enabled merely because the controller has an Ethernet port.

### Communication troubleshooting

1. Identify which devices are communicating and which are not.
2. Check the exact alarm and affected network or connection.
3. Verify device power and physical connection.
4. Check configured addressing, device names, and I/O mapping where applicable.
5. Inspect network diagnostics and controller status.
6. Confirm that a configuration change has not caused a mismatch.
7. Verify the communication and machine sequence after the correction.

Avoid changing network settings during production without authorization. A communication fault can affect multiple devices and stop an entire cell.

## 13. Robot safety architecture

Robot safety is a system-level engineering responsibility. It includes the robot, tooling, fixtures, external axes, cell equipment, and the people who may enter the hazardous area.

Common protective measures include:

- Fixed guards and access doors.
- Interlocked gates.
- Safety scanners or light curtains where suitable.
- Emergency-stop devices.
- Safety-rated monitored stops or other supported protective functions.
- Safe speed or position monitoring where supported.
- Safety controllers and approved safety communication.
- Defined procedures for setup, recovery, maintenance, and manual operation.

The actual functions must be selected and validated according to the application risk assessment and applicable requirements.

### Important safety distinctions

| Function                         | General purpose                                                      | Important limitation                                   |
| -------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------ |
| Emergency stop                   | Initiates the defined emergency stopping response                    | Does not replace isolation for maintenance             |
| Guard interlock                  | Detects an access condition and invokes the configured response      | Must be correctly designed, installed, and validated   |
| Protective stop                  | Stops or inhibits motion according to the configured safety function | The exact response depends on the implementation       |
| Safe limited speed               | Limits speed under specified safety conditions, where supported      | Requires correct configuration and validation          |
| Safety-rated position monitoring | Monitors configured position limits, where supported                 | Depends on the supported safety architecture and setup |
| Lockout/tagout                   | Controls hazardous energy during applicable maintenance              | Must follow the site's isolation procedure             |

Never bypass a guard, defeat an interlock, or assume that a stopped robot is safe to enter. Some equipment can retain hazardous energy, and automatic operation may resume when conditions change.

## 14. Robot operating modes and program states

Robot controllers generally provide different operating modes and program states for production, setup, jogging, and recovery. The exact mode names and permitted functions vary by manufacturer.

Common concepts include:

- Automatic operation: Executes an approved robot program as part of the production process.
- Manual operation: Allows authorized personnel to interact with the robot under specified conditions.
- Jogging: Commands controlled movement of selected robot axes or the tool.
- Program hold or pause: Temporarily suspends program progression.
- Fault state: Indicates that an alarm or other condition prevents normal operation.
- Recovery state: Supports an approved method of returning the robot or cell to a valid condition.

Mode selection can change which commands are accepted and which movements are permitted.

A robot that refuses to move may be responding correctly to an operating-mode restriction, safety condition, active fault, or program-state requirement.

## 15. External axes and integrated robot cells

Some robot installations include additional axes beyond the robot's own joints.

Examples include:

- Linear tracks.
- Positioners.
- Rotary tables.
- Headstock or workpiece rotators.
- Coordinated transfer equipment.

An external axis may be controlled by the robot controller or another controller, depending on the design. Coordinated motion requires the appropriate configuration and synchronization.

### Common external-axis faults

| Symptom                                        | Possible causes                                                            |
| ---------------------------------------------- | -------------------------------------------------------------------------- |
| Robot waits for positioner                     | Position not reached, missing confirmation, interlock, communication fault |
| Robot and track lose coordination              | Configuration, synchronization, feedback, or motion-planning issue         |
| Positioner does not rotate                     | Drive fault, missing enable, clamp condition, mechanical obstruction       |
| Robot path is incorrect after fixture movement | Incorrect work frame, external-axis setup, or calibration                  |
| Cell cycle stops during transfer               | Missing PLC handshake, safety condition, or incomplete machine sequence    |

When diagnosing an integrated cell, do not inspect only the robot. Trace the operation across the robot controller, PLC, external axis, fixture, sensors, and safety system.

## 16. Common robot faults and diagnostic strategy

| Symptom                                  | Possible causes                                                                 | First diagnostic action                                            |
| ---------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Robot will not enable                    | Active fault, safety condition, mode restriction, drive issue                   | Record the alarm and identify the missing enable condition         |
| Robot stops during motion                | Collision or overload detection, axis fault, safety response, process interlock | Determine what triggered the stop and review the event history     |
| Robot cannot reach a programmed position | Reach limit, joint limit, singularity, incorrect frame, obstruction             | Verify the target pose, coordinate frames, and robot configuration |
| Robot position is inaccurate             | TCP error, calibration issue, mechanical wear, fixture movement                 | Verify tool and work frames and inspect repeatability              |
| Gripper does not pick a part             | Missing part, gripper fault, vacuum loss, I/O issue                             | Check the physical grip and required confirmation signals          |
| Robot waits indefinitely                 | Missing PLC handshake, sensor signal, machine-ready condition                   | Identify the exact expected signal and its source                  |
| Robot program stops                      | Program condition, fault, process signal, operator hold                         | Record the active instruction and controller state                 |
| Network fault occurs                     | Device power, cable, configuration, network or protocol issue                   | Identify affected devices and inspect communication diagnostics    |
| Excessive vibration                      | Payload, mechanical condition, motion settings, tool or fixture issue           | Verify configuration and inspect the system safely                 |
| Welding process fails                    | Welding controller, wire feed, gas, cooling, process signal                     | Separate process-equipment faults from robot-motion faults         |
| Robot has collision damage               | Mechanical shift, damaged tooling, calibration change, internal damage          | Follow the approved inspection and recovery procedure before reuse |

These are general fault categories. Exact alarm definitions and recovery procedures are controller-specific.

## 17. Robot calibration, mastering, and recovery data

Industrial robots rely on configured relationships between joint positions, mechanical geometry, coordinate frames, and tools.

Several concepts must be kept separate.

- Mastering or reference calibration: Establishes the robot's defined joint reference relationship according to the manufacturer's method.
- TCP calibration: Establishes the tool reference point relative to the robot flange.
- Work-frame calibration: Establishes a coordinate system for the workpiece or fixture.
- Payload configuration: Describes the tool and carried load as required by the controller.
- External-axis calibration: Establishes the required relationship for a configured track or positioner.

A robot can move without an alarm while producing inaccurate results if its calibration or coordinate configuration is wrong.

### When to investigate calibration

- A robot or joint has been mechanically disturbed.
- A motor, encoder, reducer, or relevant component has been replaced.
- The robot's programmed paths no longer align with the fixture.
- The tool or fixture has changed.
- Repeatability or accuracy has degraded.
- A collision may have shifted mechanical components.

Do not perform mastering or calibration by guesswork. Use the exact manufacturer's procedure and verified backup data. Incorrect mastering can make every subsequent position incorrect.

## 18. Robot backups and configuration management

A robot backup should preserve the data needed to restore its approved operating configuration. The required contents depend on the controller and installed options.

| Backup item                   | Purpose                                                                                 |
| ----------------------------- | --------------------------------------------------------------------------------------- |
| Robot programs                | Preserve motion sequences and application logic                                         |
| Controller configuration      | Preserve supported system settings                                                      |
| Calibration or mastering data | Preserve the robot's reference configuration, where included                            |
| Tool and work frames          | Preserve TCP and coordinate-frame data                                                  |
| Payload data                  | Preserve configured tool and load information                                           |
| I/O configuration             | Preserve signal assignments and related configuration                                   |
| Communication settings        | Support approved network recovery                                                       |
| Safety configuration          | Preserve applicable safety-related configuration through the authorized procedure       |
| Application data              | Preserve welding, gripping, dispensing, vision, or other process settings as applicable |
| Manuals and software versions | Support compatible recovery and maintenance                                             |

### Backup discipline

- Identify the robot model, controller generation, software version, and installed options.
- Record the backup date and source controller.
- Store backups in an approved location with access controls.
- Maintain a known-good backup separately from experimental changes.
- Verify that the backup is readable and the restoration procedure is documented.
- Follow the manufacturer's requirements for restoring calibration, safety, and controller data.

A program backup alone is not necessarily a complete robot backup. Safety configuration and calibration data may require specific procedures and authorization.

| --------------------- | ----------------------------------------------------------- | ------------------------------------------- |

| Motors and drives     | Drive alarms, cooling, connectors, abnormal temperature     | Fault history and inspection results        |
| Reducers and joints   | Abnormal noise, backlash symptoms, lubrication requirements | Findings and prescribed maintenance records |
| Cables and dress pack | Abrasion, bending, connector damage, interference           | Inspection findings and replacement history |
| Tooling and grippers  | Jaw wear, clamping, vacuum, sensors                         | Functional test results                     |

| Controller cabinet    | Cooling, fans, filters, electrical condition                | Inspection and recurring fault history      |
| Sensors and I/O       | Signal consistency, mounting, wiring                        | Verification and fault records              |

Use the manufacturer's prescribed maintenance intervals and procedures. Lubrication requirements, inspection methods, and replacement intervals differ by robot model and joint design.

## 20. Robot architecture in an automotive production line

Consider a robot that transfers a component into an automated machining station.

```
Component arrives on conveyor
   ↓
Sensor confirms component presence
   ↓
PLC verifies machine and cell readiness
   ↓
PLC requests robot cycle
   ↓
Robot checks configured operating conditions
   ↓
Robot approaches component
   ↓
Gripper closes
   ↓
Grip confirmation is checked
   ↓
Robot transfers component to machine fixture
   ↓
Fixture clamps and confirms component location
   ↓
PLC permits machining cycle
   ↓
Machine reports cycle completion
   ↓
Robot removes the component
   ↓
Component transfers to the next operation
```

Every stage has conditions that must be satisfied. If the robot is waiting at the machine, the problem might be a missing fixture-clamp confirmation rather than a robot fault.

For each operation, identify:

- The command that starts it.
- The conditions required before it can begin.
- The output or motion command.
- The feedback that confirms the physical action.
- The controller responsible for the next step.
- The safe response if the expected feedback does not arrive.

This is the foundation of systematic robot-cell troubleshooting.

## 21. Interview questions and answers

### Q1. What is robot architecture?

It is the arrangement of mechanical, electrical, control, sensing, communication, tooling, and safety subsystems that work together to operate an industrial robot.

### Q2. What is the difference between a robot manipulator and a robot controller?

The manipulator is the physical mechanical arm and its joints. The controller executes the program, computes motion, manages configured interfaces, and coordinates robot operation.

### Q3. What is a degree of freedom?

It is an independent motion coordinate. A six-axis articulated robot typically has six independently controlled joints.

### Q4. What is the purpose of a servo drive?

It regulates the motor operation needed to follow commanded motion, using the control and feedback architecture of the robot.

### Q5. What is an encoder?

An encoder is a feedback device that provides information about movement or position. Its signal helps the control system determine the actual state of the relevant axis.

### Q6. What is forward kinematics?

It calculates the tool position and orientation from the robot's joint positions and configured geometry.

### Q7. What is inverse kinematics?

It calculates possible joint configurations for a requested tool position and orientation.

### Q8. What is the TCP?

The tool centre point is a defined reference point associated with the tool and used to describe its intended position and orientation.

### Q9. What happens if the TCP is incorrect?

The robot may reach its programmed flange position while the actual tool tip is displaced or incorrectly oriented.

### Q10. What is the difference between joint and Cartesian motion?

Joint motion commands movements of individual axes. Cartesian motion specifies a desired tool path or pose in a coordinate frame, with the controller calculating the required joint movements.

### Q11. Why can a robot stop even when no internal robot fault is present?

It may be waiting for a PLC handshake, machine-ready signal, fixture confirmation, external-axis position, or other configured process condition.

### Q12. What is the role of the cell PLC?

It typically coordinates the robot with surrounding machines, conveyors, fixtures, sensors, and production sequences. The exact division of responsibilities depends on the cell architecture.

### Q13. What is a robot payload?

It describes the mass and relevant load properties of the tool and carried workpiece. Incorrect configuration can affect motion performance and other controller functions.

### Q14. What is a work frame?

It is a coordinate system associated with a workpiece, fixture, or process. It allows robot positions to be defined relative to that reference.

### Q15. What is robot mastering?

It is the manufacturer's defined procedure for establishing the robot's joint reference relationship. The exact procedure is controller- and model-specific.

### Q16. What is a robot singularity?

It is a configuration in which the robot's kinematic relationship becomes singular or loses an expected degree of motion authority. It can create motion-planning limitations or require the controller to handle the path differently.

### Q17. Why are safety systems part of robot architecture?

They protect people by controlling hazardous access and motion through appropriately designed, configured, and validated safety functions.

### Q18. Why is an emergency stop not a substitute for isolation?

An emergency stop initiates a defined stopping response, while isolation controls hazardous energy for applicable maintenance work.

### Q19. What should a robot backup contain?

The required programs, configuration, coordinate frames, payload data, I/O and communication configuration, and other applicable recovery information. Calibration and safety-related data may need specific handling.

### Q20. How should a robot that stops mid-cycle be diagnosed?

Record the active program state and alarm, identify the last completed operation, determine which condition or feedback is missing, and trace the sequence through the robot, PLC, tooling, and surrounding equipment.

## 23. Final mental model

An industrial robot is a complete motion and automation system, not just a mechanical arm. The controller interprets the task, computes motion, and coordinates the drives. Motors and mechanical joints produce movement. Feedback devices report the actual state. Tooling performs the process, while the PLC and communication interfaces coordinate the surrounding cell. Safety systems manage hazardous conditions through their validated functions.

For maintenance and development, follow the complete chain:

Command → control logic → motion command → drive and motor → physical movement → feedback → process confirmation.

Understanding that chain prepares you to diagnose robot motion faults, process faults, communication problems, and cell-sequence failures without confusing one subsystem with another.
