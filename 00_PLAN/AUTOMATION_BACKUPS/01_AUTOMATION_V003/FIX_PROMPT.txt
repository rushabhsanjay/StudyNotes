Before you answer, follow these output rules. My converter turns your
reply into HTML, and only the formats listed below survive intact.

USE
- Markdown headings # ## ### (hashes, not underlines)
- **bold**, *italic*, ***bold italic***
- ~~strikethrough~~
- `inline code`
- Fenced code blocks with triple backticks
- Pipe tables with a header row and a --- separator row
- > blockquotes
- Bullet lists with -, *, or +
- Numbered lists with 1. 2. 3.
- Task lists with - [ ] and - [x]
- Links: [text](url)
- Images: ![alt](url)
- Inline math wrapped in \( and \)
- Display math wrapped in \[ and \]  (or $$ .. $$)
- Plain paragraphs

DO NOT USE
- Underlined headings (=== or --- under a line of text)
- Footnote syntax [^1] and its definition
- Definition lists (term then : definition)
- HTML tags of any kind (<br>, <div>, <span>, <font>, <center>, …)
- Mermaid, PlantUML, or any diagram markup
- ASCII flowcharts outside a fenced code block
- Setext-style anything
- Citations like [1] [2] with links to openai.com or any search source
- Image cards of the form [Title](https://images.openai.com/…) — if you
  must show an image, only use the standard ![alt](url) form with a URL
  that is not on images.openai.com
- Stray counters or footers on their own line, e.g. a lone "6" or "9"
- Mixed table syntax (do not put tables inside code fences)
- Nested tables inside tables
- Multiple blank lines in a row
- Emoji used as bullets or headings
- Automatic "References", "Sources", or "Citations" sections
- "Learn more" or "Related" lists with images.openai.com links
- Heading levels deeper than ######
- Indented paragraphs (a line beginning with four spaces becomes code)
- Any link or image pointing at images.openai.com or any cdn.openai.com
  host. If you want to include a picture, use the standard ![](url) form
  with a URL from a public, stable host (Wikipedia, Wikimedia, the
  manufacturer's own site, etc.).

DIAGRAMS AND STRUCTURE
If you want to show a hierarchy, a flow, or an architecture stack, put it
inside a fenced code block with plain arrows made of characters such as
↓ → ← ↑. Do not use mermaid, do not use HTML, do not rely on indentation
outside a code block.

MATH
Keep every equation inside \( \) or \[ \]. Do not wrap math in backticks,
do not use HTML entities, do not mix it with bold markers.

TABLES
One header row. One separator row of dashes. Every data row the same
number of columns. No empty cells for spacing. No line breaks inside cells.
