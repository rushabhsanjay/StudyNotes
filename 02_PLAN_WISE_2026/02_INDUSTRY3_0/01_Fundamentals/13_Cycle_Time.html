Cycle time is the elapsed time required to complete one defined production cycle.

In industrial automation, cycle time is one of the most useful measurements for understanding machine performance, production capacity, delays, and improvement opportunities.

For example, if an automated drilling machine takes 12 seconds to process one component, from the defined cycle-start event to the defined cycle-completion event, its cycle time is 12 seconds.

The machine cycle describes what the machine does. Cycle time measures how long it takes to complete that cycle.

1. Basic cycle time calculation

The basic formula is:

\[ T\_{\text{cycle}}=t\_{\text{end}}-t\_{\text{start}} \]

Where:

  • \(T\_{\text{cycle}}\) = measured cycle time.
  • \(t\_{\text{start}}\) = timestamp of the defined cycle-start event.
  • \(t\_{\text{end}}\) = timestamp of the defined cycle-completion event.

Example:

Event Time
Cycle starts 10:00:00
Cycle completes 10:00:12
Cycle time 12 seconds

The result is valid only if the start and end events are defined consistently. Measuring from the arrival of a component in one instance and from the PLC start command in another would produce inconsistent comparisons.

2. What does cycle time include?

Cycle time may include several operations and delays that occur between the defined start and end events.

Consider an automated drilling station:

Activity Duration
Component positioning 2 s
Clamping 1.5 s
Drill advance and drilling 4 s
Drill retraction 2 s
Unclamping 1.5 s
Transfer and final confirmation 1 s
Total 12 s

The total cycle time is:

\[ T\_{\text{cycle}}=2+1.5+4+2+1.5+1=12\text{ s} \]

This example assumes that the listed activities occur sequentially and do not overlap.

In a real machine, cycle time may also include internal waits, sensor confirmation, communication delays, or other programmed conditions. Some activities may overlap, so simply adding every activity's duration can overestimate the actual cycle time.

3. Cycle time versus related production terms

These terms are connected, but they are not interchangeable.

Term Meaning Example
Machine cycle The complete sequence of machine operations Clamp, drill, retract, release
Cycle time Elapsed time for a defined cycle 12 seconds per component
Takt time Available production time divided by customer demand 15 seconds per component required
Throughput Output produced per unit of time 300 components per hour
Bottleneck The constrained operation limiting the production rate A station requiring 20 seconds per component

The critical distinction is that cycle time describes the time taken by a defined operation, whereas takt time describes the pace required to meet demand.

A machine can have a cycle time lower than takt time and still fail to meet production demand because of downtime, starvation, blocked output, quality losses, or other constraints.

4. Cycle time and production rate

For a machine that completes one component per cycle, the ideal theoretical production rate is:

\[ R=\frac{3600}{T\_{\text{cycle}}} \]

Where:

  • \(R\) = cycles per hour, assuming one component per cycle.
  • \(T\_{\text{cycle}}\) = cycle time in seconds.

For a 12-second cycle:

\[ R=\frac{3600}{12}=300 \]

The theoretical rate is 300 cycles per hour, or 300 components per hour if each cycle produces exactly one component.

This is an ideal rate, not a guarantee of actual production.

If the machine experiences downtime, material shortages, rejected components, or additional delays, its actual good-output rate will be lower.

For a machine producing multiple components per cycle:

\[ R\_{\text{parts}}=\frac{3600\times N}{T\_{\text{cycle}}} \]

Here, \(N\) is the number of components produced per completed cycle. This formula still represents an ideal rate and assumes all produced components count as output.

5. Theoretical versus actual cycle time

Theoretical cycle time is the expected duration under the specified operating assumptions.

Actual cycle time is measured from the machine's real operation using defined events.

For example, a machine may have a nominal cycle time of 12 seconds but repeatedly take 14 seconds because of slower positioning or additional waiting.

Measurement Cycle time
Designed target 12 s
Actual measured cycle 14 s
Difference 2 s
Increase relative to target 16.67%

The percentage increase is calculated as:

\[ \frac{14-12}{12}\times100=16.67\\% \]

This indicates that the measured cycle takes 16.67% longer than the target.

Be careful with the reverse comparison: reducing a 14-second cycle to 12 seconds improves the time by 14.29% relative to the original 14-second cycle. Percentage changes depend on which value is used as the baseline.

6. Where cycle time is lost

Cycle time can increase because of mechanical, electrical, control, communication, process, or material-related conditions.

Cause Industrial example What to investigate
Slow actuator movement Pneumatic cylinder takes longer to extend Air pressure, flow control, cylinder condition, mechanical load
Slow positioning Fixture or robot takes longer to reach position Motion settings, mechanical friction, payload, drive status
Sensor delay or instability Position confirmation occurs late Sensor alignment, mounting, signal stability, input configuration
Excessive programmed waits PLC waits longer than necessary Timer settings and actual process requirements
Communication delay Robot-ready status arrives late Network health, device response, communication configuration
Material variation Component requires additional handling or positioning Workpiece variation, fixtures, upstream process
Repeated retries Machine repeats an operation before succeeding Root cause of the failed operation, not just retry timing
Wear or mechanical resistance Slide or mechanism moves slowly Lubrication, bearings, guides, alignment, mechanical damage

A longer cycle does not automatically mean the PLC program is inefficient. The program may be waiting because the physical operation genuinely takes longer.

7. Sequential versus overlapping operations

One of the major ways cycle time can be improved is by identifying activities that can safely and reliably occur in parallel.

Suppose a machine performs three operations:

  • Clamp: 2 seconds.
  • Processing: 6 seconds.
  • Unclamp: 2 seconds.

If these operations are sequential:

\[ T\_{\text{cycle}}=2+6+2=10\text{ s} \]

If the machine design permits another independent activity to occur during processing, the overall elapsed time may be reduced.

However, not every operation can be overlapped. The clamp must still establish the required condition before processing begins, and release must not occur before the process is complete.

Parallelisation must preserve required process conditions, equipment coordination, quality, and safety.

8. Cycle time in a multi-station production line

In a production line, each station has its own cycle behaviour, but the overall line output depends on how stations interact.

Consider three stations with the following effective processing times:

Station Cycle time
Station A 12 s
Station B 18 s
Station C 14 s

If the stations process different parts simultaneously and each station can release a completed part to the next station, the ideal steady-state output interval is constrained by Station B, which takes 18 seconds.

The line's ideal steady-state rate is therefore approximately:

\[ R=\frac{3600}{18}=200\text{ parts/hour} \]

This assumes compatible part flow, sufficient buffers or transfer capability, and no additional constraints.

The line does not necessarily produce one part every 12 + 18 + 14 = 44 seconds. That sum may represent the processing time experienced by a part across the three stations if the times are sequential and transfer time is excluded. It is not automatically the line's steady-state output interval.

This distinction becomes especially important when studying bottlenecks and throughput.

9. How to measure cycle time in a PLC

Cycle time can be measured using controller logic, timestamps, a production database, or an industrial monitoring system.

A basic measurement method is:

  1. Detect the defined cycle-start event.
  2. Record the start timestamp.
  3. Detect the defined cycle-completion event.
  4. Record the end timestamp.
  5. Calculate the difference.
  6. Store or display the result for analysis.

For example, a PLC may maintain a cycle-start timestamp and calculate elapsed time when the cycle-complete condition becomes true.

A monitoring system such as Node-RED or a SQL-based SCADA application can also record cycle-start and cycle-complete events and calculate cycle duration from their timestamps.

For reliable measurement, consider:

  • Using consistent start and end definitions.
  • Avoiding duplicate completion events.
  • Handling incomplete or aborted cycles separately.
  • Recording units consistently.
  • Considering timestamp resolution and clock synchronisation when events come from multiple controllers.
  • Separating normal cycle time from downtime and recovery periods.

Important: If a cycle starts but never completes, it should not be silently recorded as a normal completed cycle. It may represent an incomplete cycle, an interruption, or a fault that needs separate classification.

10. Cycle time and maintenance analysis

Cycle-time trends can reveal deterioration before a machine stops completely.

For example, suppose the same machine's measured cycle time gradually changes:

Observation period Average cycle time
Initial baseline 12.0 s
Later measurement 12.4 s
Subsequent measurement 13.1 s
Current measurement 14.0 s

The increase is worth investigating, especially if the product, cycle definition, and operating conditions have remained comparable.

Possible causes include mechanical wear, changing actuator performance, increased waiting, unstable sensing, or altered operating parameters.

The trend does not identify the root cause by itself. It tells maintenance where to investigate.

Useful additional measurements include:

  • Time spent in each machine state.
  • Time between an output command and its corresponding feedback.
  • Number of retries per cycle.
  • Number of incomplete cycles.
  • Fault frequency.
  • Production quantity and rejected quantity.
  • Time spent waiting for upstream or downstream equipment.

These measurements can help separate genuine processing time from delays and losses.

11. Common mistakes when interpreting cycle time

  • Comparing inconsistent measurement boundaries: One measurement starts at part detection while another starts at cycle start.
  • Treating theoretical output as actual output: Ideal production rates ignore downtime and other losses.
  • Adding all operation times blindly: Overlapping operations may reduce total elapsed time.
  • Assuming the PLC is responsible for every delay: The cause may be mechanical, pneumatic, electrical, material-related, or communication-related.
  • Mixing cycle time with downtime: A defined cycle's duration and the time lost to machine stoppages are different measurements.
  • Comparing unlike products: Different product variants or recipes may legitimately require different cycle times.
  • Ignoring variation: Average cycle time can hide intermittent slow cycles or repeated delays.

12. Interview questions and answers

Q1. What is cycle time?

Cycle time is the elapsed time required to complete one defined production cycle, measured between specified start and end events.

Q2. How is cycle time calculated?

Subtract the cycle-start timestamp from the cycle-completion timestamp.

Q3. What is the theoretical production rate for a 15-second cycle?

Assuming one component per cycle and ideal continuous operation:

\[ R=\frac{3600}{15}=240\text{ parts/hour} \]

Actual output may be lower.

Q4. Can cycle time increase without a PLC program change?

Yes. Mechanical wear, slow actuator movement, unstable sensor signals, process variation, and communication delays can increase measured cycle time.

Q5. Is cycle time the same as takt time?

No. Cycle time measures the time taken by an operation. Takt time represents the production pace required to meet customer demand.

Q6. Why is the slowest station important in a production line?

When stations process different parts concurrently in steady-state flow, the slowest constrained station commonly limits the ideal output rate. Buffers, parallel machines, transfer constraints, and other conditions can affect the actual result.

Q7. How can cycle time be monitored automatically?

Use defined cycle-start and cycle-complete events, calculate the elapsed time, and record the result in a controller, database, or monitoring system.

Q8. What is the difference between average cycle time and maximum cycle time?

Average cycle time describes the mean duration across measured cycles. Maximum cycle time is the longest observed duration in the measurement set. Both can be useful because an average can hide occasional severe delays.

Q9. Does reducing cycle time always increase production output?

Not necessarily. Output may be limited by another station, downtime, quality losses, material availability, or downstream constraints. Reducing the cycle time of a non-constraining station may not improve total line output.

Q10. What should maintenance check when cycle time gradually increases?

Compare the cycle-time trend and operating conditions, then investigate state durations, actuator response, sensor timing, process parameters, communication, and mechanical condition.

13. Final mental model

Cycle time answers one question: How long does the defined operation take to complete?

For practical industrial work, keep these relationships clear:

  • Machine cycle describes the sequence of operations.
  • Cycle time measures the elapsed duration of that sequence.
  • Takt time describes the pace required by customer demand.
  • Throughput describes actual or theoretical output per unit of time.
  • Bottleneck analysis identifies the constraint limiting overall production.

For maintenance, the most useful approach is to measure cycle time consistently, identify which part of the cycle has become slower, and investigate the cause before changing program timers or motion settings.
