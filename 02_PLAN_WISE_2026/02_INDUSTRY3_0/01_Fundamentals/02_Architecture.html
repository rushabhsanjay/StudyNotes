Industrial automation architecture is the overall structure of an automated industrial system, showing how machines, sensors, controllers, networks, operator interfaces, databases, production systems, and business systems interact.

If Automation Evolution explained how we got here, Industrial Automation Architecture explains what is connected to what, what each component does, and how the entire system operates together.

The fundamental model is:

Physical Process → Field Level → Control Level → Supervisory Level → Production Level → Enterprise Level

This is a conceptual hierarchy. In modern factories, networking and distributed systems can blur the boundaries between these levels.

1. Basic Industrial Automation Architecture

A simplified industrial automation system can be represented as follows:

Enterprise / Business Level

ERP · Planning · Inventory · Business Operations

Production / Operations Level

MES · Production Tracking · Quality · OEE

Supervisory Level

SCADA · HMI · Alarms · Historian

Control Level

PLC · PAC · CNC · Robot Controller · DCS

Field Level

Sensors · Drives · Actuators · Remote I/O

Physical Process

Machine · Cell · Production Line · Plant

Conceptual architecture showing the main levels and their relationships. The arrows represent information and control interactions, not a single fixed communication path.

Information commonly travels upward from machines toward monitoring, production, and business systems. Commands and production instructions can travel downward toward controllers and equipment.

For example, a temperature measurement may follow this path:

Temperature Sensor → PLC → SCADA → Database → Production Report

A control command may follow the opposite direction:

Operator → HMI → PLC → VFD → Motor → Conveyor

These two paths illustrate an important distinction: an industrial system must both control physical equipment and communicate information about its operation.

2. The Physical Process

The physical process is the actual industrial activity being performed. It is the reason the automation system exists.

Examples include:

  • Welding.
  • Machining.
  • Assembly.
  • Painting.
  • Heat treatment.
  • Material handling.
  • Pumping.
  • Packaging.
  • Mixing.

Consider a robotic welding station:

Workpiece → Fixture → Robot → Welding Gun → Weld

The physical process involves the actual workpiece, fixture, robot movement, and welding operation.

The automation system surrounds this process to observe its condition, control its operation, protect people and equipment, and improve production performance.

A controller, network, or HMI is not the physical process itself. It supports the operation of the physical equipment.

3. Field Level

The field level is closest to the physical machine. It contains devices that measure conditions, detect events, or physically act on equipment.

Input devices

Examples include:

  • Proximity sensors.
  • Photoelectric sensors.
  • Limit switches.
  • Pressure sensors.
  • Temperature sensors.
  • Encoders.
  • Flow sensors.
  • Vision sensors.

These devices provide information about the machine or process.

Output devices

Examples include:

  • Solenoid valves.
  • Contactors.
  • Relays.
  • Motors.
  • Indicator lamps.
  • Heaters.
  • Pneumatic actuators.

Drives and remote I/O are also commonly associated with the field and equipment interface.

Example: Pneumatic cylinder

Proximity Sensor

PLC Input

PLC Logic

PLC Output

Solenoid Valve → Cylinder

The sensor detects a condition, the PLC evaluates it, and the output commands the valve to operate the cylinder.

The field level therefore provides the sensing and actuation interface between the control system and the physical world.

4. Control Level

The control level makes decisions based on programmed logic and process conditions.

Typical devices include:

  • PLC: Programmable Logic Controller.
  • PAC: Programmable Automation Controller.
  • DCS controller: Distributed Control System controller.
  • CNC controller.
  • Robot controller.
  • Motion controller.

For Industry 3.0, the PLC is particularly important.

Example: Robot cell permissives

Suppose a machine has these conditions:

Part_Present = TRUE
Guard_Closed = TRUE
Pressure_OK = TRUE
Safety_System_Healthy = TRUE

The control program evaluates the required conditions and determines whether the next operation may proceed.

For example:

Conditions satisfied
        ↓
Command Clamp ON
        ↓
Clamp_Closed confirmed
        ↓
Permit next operation

This is where the following concepts become practical:

  • Sequence.
  • Interlock.
  • Permissive.
  • Handshake.
  • Timer.
  • Counter.
  • Alarm.
  • Fault.

Important: Safety-related functions must be implemented using appropriately designed safety systems. An ordinary PLC indication alone does not establish that a safety function is satisfied.

5. Supervisory Level

The supervisory level primarily supports operator interaction, monitoring, alarms, and the observation of machine or process conditions.

Typical systems include:

  • HMI.
  • SCADA.
  • Operator stations.
  • Alarm systems.
  • Historian systems.

An HMI might display:

Machine Status : RUN
Cycle Number   : 127
Part Present   : YES
Pressure       : 5.8 bar
Motor Speed    : 1450 rpm
Active Alarm   : NONE

Operators may also be provided with commands such as:

AUTO
MANUAL
START
STOP
RESET
JOG

The architecture is generally:

Operator ↔ HMI ↔ PLC ↔ Machine

The HMI provides the operator interface. The PLC normally executes the detailed machine-control logic.

SCADA expands supervisory capabilities across multiple machines or processes, including alarm management, trends, historical records, and supervisory commands.

6. Production and Operations Level

Above individual machine control, manufacturing organizations may use systems concerned with managing production operations.

The main example is:

MES = Manufacturing Execution System

MES capabilities can include:

  • Production orders.
  • Production tracking.
  • Work-in-progress.
  • Product traceability.
  • Quality information.
  • Downtime tracking.
  • Production quantities.
  • Overall Equipment Effectiveness (OEE).
  • Operator information.
  • Machine data.

Consider a production line that manufactures 500 components.

The PLC controls the machine cycle and may count completed components. SCADA can display and record operating information. MES can associate production results with orders, shifts, products, and quality records.

The focus therefore expands from:

"Is the machine running?"

to:

"What is the factory producing, how much has it produced, when was it produced, and how well is production performing?"

MES connects equipment-level activity with manufacturing operations management.

7. Enterprise Level

The enterprise level deals with broader business activities.

A major system at this level is:

ERP = Enterprise Resource Planning

ERP capabilities may include:

  • Production planning.
  • Purchasing.
  • Inventory management.
  • Finance.
  • Sales.
  • Materials management.
  • Human resources.
  • Supply-chain management.

SAP is a common example of an ERP platform used in manufacturing.

A simplified relationship is:

ERP ↔ MES ↔ SCADA/Industrial Data Systems ↔ PLC

For example, an ERP system may contain a production order and material requirements. Manufacturing systems use the relevant production instructions, while production results and material consumption may be reported back to higher-level systems.

Each level has a different primary responsibility:

Level Main question answered
Field What is happening physically?
Control What action should the machine perform?
Supervisory What is the machine or process doing?
Production What is being produced, and how is production performing?
Enterprise What does the business need to plan and manage?

8. The Purdue Model

The Purdue Enterprise Reference Architecture, commonly called the Purdue Model, is a framework used to organize industrial control systems into levels of responsibility.

A simplified representation is:

Level 5

Enterprise Network

Enterprise connectivity in extended models

Level 4

Business Planning and Logistics

ERP, business applications

Level 3

Manufacturing Operations

MES, plant operations management

Level 2

Supervisory Control

SCADA, HMI, supervisory functions

Level 1

Basic Control

PLC, DCS controllers, machine control

Level 0

Physical Process

Sensors, actuators, the process itself

This is a simplified teaching model. Purdue implementations and extended diagrams can differ in how they represent enterprise networks, industrial DMZs, and other infrastructure.

The essential concept is the separation of responsibilities between physical processes, control, supervision, manufacturing operations, and business systems.

Do not treat the levels as immutable rules. Real architectures can combine, redistribute, or bypass some of these layers. Security boundaries and communication paths must be designed for the actual system.

9. Vertical Communication

Vertical communication means exchanging information between different architectural levels.

A simplified example is:

Sensor → PLC → SCADA → MES → ERP

Production data may travel upward, while production instructions, configuration information, or supervisory commands may travel downward.

Example: Production order

  1. ERP: A production order specifies a target quantity of 500 components.
  2. MES: The order is prepared for execution and associated with the appropriate production process.
  3. Machine control: The PLC executes the machine sequence.
  4. Production monitoring: The system records that 497 components have been completed.
  5. MES: The actual production result is recorded.
  6. ERP: Relevant order and inventory information is updated.

The actual implementation depends on how the factory integrates these systems.

The important principle is that physical manufacturing activity can be connected to production management and business operations.

10. Horizontal Communication

Horizontal communication occurs between devices or systems at the same or similar architectural level.

Examples include:

  • PLC ↔ PLC.
  • PLC ↔ Robot controller.
  • PLC ↔ CNC.
  • PLC ↔ Vision system.
  • PLC ↔ VFD.

This is especially important when integrating multiple machines into a production cell or line.

Example: PLC-to-robot handshake

PLC → Robot: Machine Ready
Robot → PLC: Robot Ready
PLC → Robot: Start Cycle
Robot → PLC: Cycle Complete

The handshake establishes a defined exchange of status and commands between the systems.

Both systems must follow compatible signal definitions and sequencing rules. Otherwise, a machine may wait indefinitely for a signal that never arrives, one of industry's less charming traditions.

Horizontal communication is fundamental to coordinated machine operation.

11. Industrial Network Architecture

Industrial automation architecture also includes the physical and logical networks that connect its devices.

A simplified plant structure might look like this:

Plant Network

Cell A

PLC · HMI

Cell B

PLC · HMI

Drive · Robot · Sensors

Drive · CNC · Sensors

Conceptual network layout. Actual network segmentation and topology depend on the installation.

Industrial communication technologies you will study later include:

  • Ethernet.
  • PROFINET.
  • EtherNet/IP.
  • PROFIBUS.
  • Modbus.
  • CC-Link.
  • CAN.
  • DeviceNet.
  • OPC UA.

These technologies do not all serve exactly the same purpose. Some are field-level or controller communication protocols, while others support broader industrial information exchange.

The architecture must account for addressing, topology, device compatibility, communication timing, diagnostics, and network security.

12. Centralized vs. Distributed Architecture

Two fundamental architectural approaches are centralized control and distributed control.

Centralized architecture

A central controller handles a large portion of the machine or system.

Sensors ─┐
Sensors ─┤
Sensors ─┼──→ Main PLC ──→ Outputs
Sensors ─┤
Sensors ─┘

Advantages:

  • Simple conceptual structure.
  • Centralized control logic.
  • Straightforward for smaller machines.
  • A single control program may coordinate the complete sequence.

Limitations:

  • Potentially extensive wiring.
  • A large or complex controller program.
  • A controller failure may affect a substantial portion of the machine.
  • Expansion may become difficult as the system grows.

Distributed architecture

Control functions are divided among multiple controllers or intelligent devices.

                 Main PLC
                /   |   \
               /    |    \
            PLC A  PLC B  PLC C
              |      |      |
           Machine  Robot  Conveyor

Advantages:

  • Modular design.
  • Easier expansion.
  • Local processing.
  • Reduced point-to-point wiring in suitable networked designs.
  • Better separation of control responsibilities.

Limitations:

  • Greater communication dependency.
  • More complex system integration.
  • Additional configuration and troubleshooting requirements.
  • Faults may involve interfaces between controllers rather than one device alone.

Neither architecture is universally superior. The choice depends on machine size, performance requirements, safety, reliability, maintainability, and lifecycle cost.

13. Example: Automated Assembly Machine

Consider an automated assembly machine that detects a component, clamps it, performs an operation, and releases it.

Its architecture can be divided into functional groups.

Field devices

  • Proximity sensors.
  • Photoelectric sensors.
  • Pressure sensors.
  • Solenoid valves.
  • Motors.
  • Cylinder position sensors.

Control

  • PLC.
  • Sequence logic.
  • Interlocks.
  • Timers and counters.
  • Fault handling.

Motion

  • VFD.
  • Servo drive.
  • Robot controller, if required.

Operator interaction

  • HMI.
  • Mode selection.
  • Cycle commands.
  • Alarm display.

Communication

- Industrial Ethernet or another suitable industrial network.

Supervisory and production systems

  • SCADA.
  • MES.
  • Database.

The complete conceptual relationship is:

MES / ERP

Orders and production information

SCADA / HMI

Monitoring and operator interaction

PLC

Sequence, interlocks, control decisions

VFD

Motor control

Servo

Position control

Robot

Programmed motion

Sensors · Actuators · Physical Machine

Functional view of an assembly machine. A real system may use direct connections, networked devices, remote I/O, or separate controllers.

The architecture identifies what each subsystem does and how it interacts with the others.

14. Safety Architecture

Safety must not simply be treated as another ordinary PLC function.

Industrial machines may use:

  • Emergency-stop devices.
  • Safety relays.
  • Safety PLCs.
  • Safety light curtains.
  • Safety scanners.
  • Guard switches.
  • Two-hand controls.
  • Safe motion functions.

A simplified safety architecture is:

Safety Devices → Safety Controller → Safety Outputs → Safe Machine Functions

For example, a safety controller may monitor a guard switch and initiate a defined safe response when the guard is opened.

Modern systems may use safety-rated communication over industrial networks, but the safety functions must meet the applicable design and validation requirements.

Key distinction: Standard automation controls the production sequence. Safety-related control functions are designed to reduce risk to people and equipment. The two may interact, but they are not interchangeable.

15. Architecture vs. Hierarchy

These terms are related, but they are not identical.

Hierarchy describes levels of responsibility.

For example:

Field → Control → Supervisory → Production → Enterprise

Architecture describes how the actual components are arranged and interconnected.

For example:

PLC ↔ Robot Controller ↔ Industrial Network ↔ SCADA Server

The hierarchy tells you the role of each level. The architecture tells you how the actual system is built.

A real factory requires both perspectives.

16. Data Flow vs. Control Flow

Industrial systems carry different types of information for different purposes.

Control flow

Sensor
  ↓
PLC
  ↓
Output
  ↓
Actuator
  ↓
Physical Process
  ↓
Sensor Feedback

The purpose is to control the physical process using measurements, logic, outputs, and feedback.

Data flow

PLC
  ↓
SCADA
  ↓
Historian
  ↓
Database
  ↓
MES / Analytics

The purpose is to collect, store, present, and analyze information.

These flows can overlap. For example, a supervisory system may issue an authorized command while also collecting process data.

The key distinction is the primary function: control flow changes or regulates the physical process; data flow makes information available for monitoring, reporting, and analysis.

17. What Happens During a Machine Cycle?

Suppose an operator presses START on an HMI.

A typical sequence may be:

  1. The HMI sends a start request to the PLC.
  2. The PLC checks the required operating conditions and permissives.
  3. The PLC executes the programmed sequence.
  4. The PLC commands an output or communicates a command to another controller.
  5. A valve, drive, or robot performs the physical operation.
  6. Sensors provide feedback about the result.
  7. The PLC evaluates the feedback and advances the sequence.
  8. The HMI displays the updated status.
  9. SCADA or MES may record the cycle and production result.

The machine therefore operates with several interacting flows:

  • Control flow: Decisions and commands.
  • Feedback flow: Measurements and confirmation of actions.
  • Information flow: Status, alarms, and production records.

These flows work together, but they serve different functions.

18. Architecture from a Maintenance Perspective

This is where architectural knowledge becomes directly useful in industrial maintenance.

When a machine stops, identify the part of the architecture where the failure may be occurring before replacing components.

Case A: Field problem

The sensor has failed or is not detecting the target.

Sensor: NOT DETECTING
       ↓
PLC Input: Does not change
       ↓
Sequence: Cannot advance

Possible investigation areas include sensor alignment, power supply, wiring, target position, and input-channel status.

Case B: Control problem

The sensor works, but the PLC does not issue the expected command.

Sensor: OK
       ↓
PLC Input: OK
       ↓
PLC Logic / Permissive: Investigate
       ↓
Output: Not Activated

Possible investigation areas include program conditions, operating mode, interlocks, fault status, and output logic.

Case C: Output or actuator problem

The PLC commands the output, but the machine does not move.

PLC Command: ON
       ↓
Output Circuit: Check
       ↓
Valve / VFD / Contactor: Check
       ↓
Actuator: Does Not Operate

Possible causes include electrical faults, pneumatic or hydraulic problems, drive faults, wiring failures, and mechanical obstruction.

Case D: Communication problem

The local equipment may be healthy, but another device cannot communicate with it.

PLC: Operating
       ↓
Industrial Network: Fault
       ↓
Robot / CNC / HMI: Unavailable

Investigation may include cable condition, switch ports, addressing, protocol configuration, device status, and communication diagnostics.

Case E: Supervisory problem

The machine works, but the HMI or SCADA shows incorrect or missing information.

Machine: Operating
PLC: Operating
       ↓
HMI / SCADA: Incorrect Display

Possible causes include communication failure, incorrect tag mapping, stale data, configuration errors, or a visualization problem.

The maintenance principle is straightforward: trace the signal or information path, locate where expected behavior stops, and investigate that section of the architecture.

This is more efficient than randomly replacing components that may be perfectly healthy.

Additional systems may include:

  • CNC controllers.
  • Vision systems.
  • Barcode readers.
  • Industrial PCs.
  • Printers.
  • Databases.
  • Engineering workstations.
  • Safety PLCs and safety I/O.
  • Safety devices.

Not every machine contains every component, and the connections will vary. The purpose of this model is to identify the main subsystems and their relationships.

20. The Architecture to Remember

For your Industry 3.0 studies, retain three complementary views.

A. Vertical hierarchy

Physical Process → Field → Control → Supervisory → Production → Enterprise

B. Horizontal communication

PLC ↔ PLC ↔ Robot ↔ CNC ↔ Vision System ↔ Drive

C. Safety architecture

Safety Devices ↔ Safety Controller ↔ Safety-Related Machine Functions

Also remember the two broad information directions:

  • Upward: Process conditions → Data → Information → Production and business systems.
  • Downward: Production instructions or commands → Control logic → Actuators → Physical process.

These are conceptual directions, not a claim that every signal follows a single route.

Core definition

Industrial automation architecture is the organization and interconnection of devices and systems that sense physical processes, make control decisions, execute actions, provide human supervision, exchange information, and integrate manufacturing with higher-level operations.
