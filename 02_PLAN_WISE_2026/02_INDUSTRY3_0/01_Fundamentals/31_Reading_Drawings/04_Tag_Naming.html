1. Definition

Tag naming is the system used to identify electrical devices, cables, terminals, PLC signals, and other components within an industrial automation system.

A tag or reference designation allows engineers and maintenance personnel to identify a component consistently across electrical schematics, panel layouts, cable schedules, I/O lists, PLC programs, spare-parts records, and maintenance reports.

For example, a drawing may identify a contactor as -KM101, a proximity sensor as -B101, and a cable as -W101. These are illustrative identifiers. Actual naming conventions depend on the project's standards and company practices.

The objective is to understand what an identifier refers to, what information it contains, and where to find the corresponding physical component or documentation.

2. Why tag naming matters

Industrial machines may contain thousands of electrical and automation components. Without a consistent identification system, even a simple breakdown can turn into an unnecessary search through panels, cables, drawings, and PLC logic.

Tag naming supports:

  • Faster fault identification and troubleshooting.
  • Cross-referencing components across multiple drawing sheets.
  • Correct spare-parts identification and replacement.
  • Cable tracing and terminal verification.
  • PLC tag mapping and I/O diagnostics.
  • Equipment modifications and retrofits.
  • Maintenance history, root-cause analysis, and audit records.
  • Consistent documentation between engineering, maintenance, production, and suppliers.

For maintenance, the most important benefit is traceability: a device identified in the field should be traceable to its drawing, wiring, controller signals, and maintenance records.

3. Device tags and reference designations

A device tag identifies a component or equipment item according to a defined naming convention.

Common examples include:

Example tag Typical device Function
-QF101 Circuit breaker Switching and circuit protection
-FU101 Fuse Overcurrent protection
-KM101 Contactor Switching an electrical load
-KA101 Auxiliary relay Switching control signals
-M101 Motor Electrical-to-mechanical energy conversion
-B101 Sensor or detector Detecting a physical condition
-S101 Switch or push button Manual or position-dependent switching
-Y101 Solenoid or actuator designation Operating a valve or other actuating device
-X101 Terminal block or connector designation Electrical connection interface
-T101 Transformer Voltage transformation
-A101 Electronic assembly or device Control or electronic function

These are common or illustrative conventions, not a universal dictionary. The meaning of a letter can vary by standard, project, manufacturer, and company. Always consult the drawing legend and reference-designation rules before identifying a device from its tag alone.

Example: -KM101

A tag such as -KM101 might identify a contactor used for a conveyor motor.

  • KM is the device-type code under the project's naming convention.
  • 101 is the identifying number within that convention.
  • The leading hyphen is used in some reference-designation systems to indicate a product or device aspect.

The number 101 does not universally mean conveyor 1, motor 1, or station 1. Its meaning must be established from the project's numbering rules.

4. Device tag versus equipment name versus PLC tag

These identifiers may refer to the same functional item, but they serve different purposes.

Identifier type Example Purpose
Device tag -B101 Identifies the component in engineering drawings
Equipment name Clamp-closed sensor Describes the device's function
PLC tag CLAMP_CLOSED Identifies the signal or variable in the control program
Hardware address Local:1:I.Data.0 Identifies a configured PLC input location
Asset number ASSET-004821 Identifies the equipment in an asset-management system
Part number 12345678 Identifies the manufacturer's specific product or variant

These identifiers are related but not interchangeable.

A replacement sensor may retain the same functional device tag while having a different manufacturer's part number. A PLC tag may remain unchanged even if the physical input channel is reassigned, provided the project is updated correctly.

5. Understanding cable numbers

Cable identification assigns a unique or controlled reference to a cable so that the cable can be located and traced between its endpoints.

Consider an illustrative cable schedule:

Cable number From To Cable purpose
-W101 Panel terminal X1 Sensor -B101 Sensor signal and supply
-W102 PLC output terminal Valve -Y101 Solenoid command
-W103 VFD output terminals Motor -M101 Motor power
-W104 PLC communication port Remote I/O adapter Industrial network communication

The cable prefix W is illustrative. Some projects use other prefixes, alphanumeric codes, cable IDs, or structured designations.

A cable number usually identifies the cable as an assembly. Individual conductors within the cable may have separate core numbers, colors, or wire identifiers.

Cable number versus wire number versus core number

Identifier What it identifies Example
Cable number The cable assembly W101
Core number An individual insulated conductor within the cable 1, 2, 3, G/Y
Wire number A conductor or electrical connection identified in the wiring documentation 2401
Terminal number A connection point on a device or terminal block X1:14
Device tag The connected component -B101

A cable may contain multiple cores, and a wire number may be assigned according to the project's electrical documentation rules. Do not assume that every core has the same identifier as its cable or that a wire number is globally unique throughout the plant.

6. Reading a cable designation in practice

Suppose a cable schedule lists:

Field Example
Cable ID W101
From Terminal block X1, terminals 13 and 14
To Sensor B101
Cable type 3-core, shielded
Core identification 1, 2, 3
Function Sensor supply and signal
Drawing reference Sheet 12

This record tells the technician which cable to locate, where it starts and ends, and which drawing to consult.

The cable type and core allocation above are illustrative. Actual sensor wiring depends on the sensor's electrical design, output type, connector, and the approved wiring diagram.

A disciplined tracing procedure is:

  1. Find the cable ID in the cable schedule or schematic.
  2. Confirm its source and destination.
  3. Locate the relevant panel, connector, or terminal block.
  4. Verify the core numbers and terminal assignments.
  5. Trace the destination device and confirm its device tag.
  6. Compare the actual installation with the drawing.
  7. Update the documentation if an approved modification has changed the routing or connections.

Never rely on cable color alone when identifying a conductor. Colors can be reused, altered during repairs, or applied differently under different standards.

7. Reading terminal block and connector tags

Terminal blocks and connectors provide the interfaces between field wiring, panel wiring, and electronic equipment.

For example:

  • -X1 may identify a terminal block.
  • X1:14 may identify terminal 14 on that block.
  • -B101 may identify the sensor connected through that terminal.
  • W101 may identify the cable running between the sensor and the panel.

These references describe different things.

A schematic may show a terminal block with several numbered terminals, while the panel layout shows its physical location. The terminal plan or connection diagram can then specify which conductor lands on each terminal.

Important: X1:14 is an illustrative notation. Some projects use different separator formats or distinguish terminal strips, connectors, plugs, and individual terminal positions differently.

8. Hierarchical tag naming

Large industrial plants frequently use a hierarchy to identify the location and function of equipment.

For example:

PLANT
  |
  v
SHOP
  |
  v
PRODUCTION LINE
  |
  v
STATION
  |
  v
MACHINE OR ROBOT
  |
  v
DEVICE

A project may incorporate some or all of these levels into its tags.

An illustrative structured identifier could be:

BIW-L01-ST03-ROB01-B101

Possible interpretation:

Segment Illustrative meaning
BIW Body-in-white area
L01 Line 1
ST03 Station 3
ROB01 Robot 1
B101 Sensor 101

This structure is only an example. The segments have no guaranteed meaning unless the project naming standard defines them.

Some projects keep location and device type in separate fields instead of encoding everything in a single tag. That can make databases, spare-parts management, and automated reporting easier to maintain.

9. Tag naming in PLC programs

PLC programs commonly use symbolic tags that describe signal functions rather than only physical addresses.

Examples:

PLC tag Meaning
CLAMP_CLOSED Clamp-closed confirmation
CONVEYOR_MOTOR_RUN_CMD Conveyor motor run command
ROBOT_CYCLE_ACTIVE Robot cycle active status
VFD_FAULT Drive fault indication
AIR_PRESSURE_BAR Scaled air-pressure value
PART_PRESENT Part-present sensor state

Good tag names should be:

  • Meaningful and specific.
  • Consistent in word order and abbreviations.
  • Unambiguous about command versus feedback.
  • Clear about units for analog values where appropriate.
  • Consistent with the project's naming rules.
  • Stable enough to support maintenance and future modifications.

For example, CONVEYOR_RUN_CMD and CONVEYOR_RUNNING_FB distinguish a command from confirmation of actual running status.

This distinction matters because a run command being TRUE does not prove that the conveyor is moving.

10. Naming commands, feedback, faults, and permissives

A useful naming convention distinguishes the type of information represented by a tag.

Suffix or word Possible meaning Example
CMD Command ROBOT_START_CMD
FB Feedback ROBOT_RUNNING_FB
STS Status VFD_READY_STS
FLT or FAULT Fault condition VFD_FAULT
ALM or ALARM Alarm condition LOW_PRESSURE_ALM
EN or ENABLE Enable state or command DRIVE_ENABLE
REQ Request CYCLE_START_REQ
OK A condition judged acceptable AIR_PRESSURE_OK

These suffixes are conventions, not universal requirements. A company may define different abbreviations or reserve specific suffixes for particular signal types.

The most important rule is consistency and clarity. A tag should communicate whether it represents an operator request, a controller command, a physical feedback signal, or a diagnostic condition.

11. Tag naming and industrial networking

Modern automation systems also identify networked devices through names and addresses.

Examples include:

  • PLC controller name and IP address.
  • Remote I/O adapter name and IP address.
  • VFD device name or network address.
  • Robot controller address.
  • HMI or SCADA tag.
  • OPC UA node identifier.
  • Industrial Ethernet port and cable reference.

These identifiers operate at different layers.

Identifier Example Identifies
Device tag -VFD101 Drive in the engineering drawings
IP address 192.168.1.20 Network endpoint
PLC tag CONVEYOR_SPEED_REF Program variable
Network node or device name VFD_LINE1 Configured network device identity
Cable ID W201 Physical cable assembly

A device tag is not an IP address. An IP address is not a PLC tag. A network device name may be configurable and can change independently of the physical component's engineering reference.

When troubleshooting networked equipment, map the engineering device tag to the configured network identity, then confirm the correct connection and controller configuration.

12. Common mistakes

  • Assuming tag prefixes are universal across all manufacturers and projects.
  • Treating a cable number as a wire number or core number.
  • Assuming a numeric suffix identifies a machine or station without checking the naming standard.
  • Confusing the physical device tag with the PLC symbolic tag.
  • Using an old cable schedule after a retrofit.
  • Replacing a component based only on a similar-looking tag.
  • Identifying conductors by color without verifying terminal numbers and documentation.
  • Using an IP address as though it were a permanent equipment identifier.
  • Naming commands and feedback signals identically.
  • Failing to update tags in drawings, PLC programs, HMI screens, and maintenance records after approved changes.

13. Interview questions and answers

Q1. What is a device tag?

A device tag is an engineering reference used to identify a component in drawings, equipment documentation, and associated maintenance records.

Q2. What is the difference between a cable number and a wire number?

A cable number identifies a cable assembly. A wire number identifies a conductor or electrical connection according to the project's documentation rules. A cable may contain multiple cores, each with its own identification.

Q3. Why is consistent tag naming important in industrial automation?

It allows devices, signals, drawings, PLC tags, spare parts, and maintenance records to be cross-referenced reliably.

Q4. What is the difference between a device tag and a PLC tag?

The device tag identifies the physical component in engineering documentation. The PLC tag identifies a program variable or signal that represents a condition, command, or value.

Q5. How would you trace an unidentified cable?

Locate its cable ID in the schedule or drawing, verify the documented endpoints, inspect the terminal and core references, and confirm the physical connections using approved procedures.

Q6. Why should commands and feedback have different names?

A command represents what the control system requests. Feedback represents what a device reports or confirms. Keeping them distinct helps identify situations where the command is issued but the expected physical response does not occur.

Q7. What must be checked before changing a device tag or cable reference during a retrofit?

Check the project's naming standard, affected drawings, PLC and HMI references, cable schedules, network configurations where applicable, maintenance records, and any downstream systems that depend on the identifier.

14. Practical exercise

Select one sensor, one contactor, and one cable from a machine drawing.

  • Record the device tag and physical function.
  • Find the manufacturer's part number.
  • Identify the associated PLC tag and hardware address, if applicable.
  • Locate the cable ID and its documented endpoints.
  • Record the relevant terminal and core numbers.
  • Identify the drawing sheet and revision.
  • Check whether the naming convention distinguishes command, status, feedback, and fault signals.
  • Compare the drawing with the installed equipment.
  • Record any mismatch and follow the approved documentation-change process.

15. Final mental model

Tag naming provides a common identification system across the physical machine and its documentation.

PLANT / LINE / STATION
          |
          v
      DEVICE TAG
          |
          +---- ELECTRICAL SCHEMATIC
          |
          +---- CABLE AND TERMINAL REFERENCES
          |
          +---- PLC TAG AND HARDWARE ADDRESS
          |
          +---- NETWORK DEVICE IDENTITY
          |
          +---- SPARE PARTS AND MAINTENANCE RECORDS

The goal is to make every important component and signal traceable. A good naming system reduces ambiguity, supports reliable troubleshooting, and makes future modifications easier to engineer and maintain.
