1. Definition

An I/O list, or Input/Output list, is an engineering document that maps a controller's input and output addresses to the physical devices, signals, and functions they represent in an industrial automation system.

It establishes the relationship between the field device, electrical wiring, PLC hardware channel, PLC program tag, and intended machine function.

For industrial maintenance, an I/O list answers a critical question:

Which physical device corresponds to this PLC address, and where should the signal be checked when the machine behaves incorrectly?

For example, a PLC input may represent a sensor that detects whether a robot fixture is clamped. The I/O list identifies the sensor, the corresponding PLC address, its signal description, and associated hardware information.

2. What is an I/O point?

An I/O point is an individual input or output signal handled by a controller or its associated I/O system.

There are four fundamental categories.

I/O type Full form Direction relative to PLC Example
DI Digital Input Field device to PLC Proximity sensor detects a fixture
DO Digital Output PLC to field device PLC commands a solenoid valve
AI Analog Input Field device to PLC Pressure transmitter measures pressure
AO Analog Output PLC to field device PLC sends a speed reference to a drive

The direction is always described relative to the PLC, not relative to the field device.

Digital inputs

Digital inputs represent discrete states, commonly ON/OFF or TRUE/FALSE.

Examples:

  • Proximity sensor detects a component.
  • Limit switch confirms a cylinder's position.
  • Push button requests a machine start.
  • Overload relay provides a fault indication.
  • Drive reports a ready or running state.

Digital outputs

Digital outputs command external devices or interface circuits.

Examples:

  • Energize a relay or contactor coil.
  • Operate a solenoid valve.
  • Switch on a tower lamp.
  • Request a robot cycle.
  • Enable a device through a discrete input.

Analog inputs

Analog inputs represent continuously varying measured quantities.

Examples:

  • Pressure transmitter: 4–20 mA.
  • Temperature transmitter: 4–20 mA.
  • Position sensor: 0–10 V.
  • Flow transmitter: 4–20 mA.

The PLC converts the electrical signal into a numeric value and, where configured, scales it into engineering units.

Analog outputs

Analog outputs send a variable command to a receiving device.

Examples:

  • Speed reference to a VFD.
  • Position reference to a controller.
  • Control signal to a proportional valve.
  • Setpoint to an external control system.

A numeric PLC value is not automatically an engineering value. Scaling, units, limits, and the receiving device's configuration must be verified.

3. Anatomy of an I/O list

A practical I/O list typically contains the following information. Actual column names vary between companies and projects.

Column Purpose Example
I/O address Hardware or logical address Local:1:I.Data.0
PLC tag Symbolic program name CLAMP_CLOSED
Signal description What the signal means Clamp closed confirmation
I/O type Signal category DI
Device tag Reference to the field device -B101
Device location Physical location Fixture station 1
Rack/slot/channel Hardware location Rack 0, slot 1, channel 0
Electrical signal Signal type or range 24 V DC
Normal state Expected state in a defined condition ON when clamp is closed
Wiring reference Drawing or terminal reference Sheet 12, terminal X1:14
Destination/source Connected device or system Proximity sensor
Remarks Special conditions Input used as a sequence permissive

Not every project uses every column. The important requirement is that the information is sufficient to trace the signal from the physical device into the control system, or from the controller to the commanded device.

An example mapping:

Item Example
Field device Clamp-closed proximity sensor
Device tag -B101
Electrical signal 24 V DC digital

The identifiers above are illustrative. Actual addresses, terminal numbers, and tag conventions must come from the machine's approved drawings and PLC project.

The same physical signal can have several identifiers, each serving a different purpose. They should be cross-referenced rather than treated as interchangeable.

5. Hardware addresses versus symbolic tags

This distinction is essential when troubleshooting or modifying PLC programs.

Feature Hardware address Symbolic tag
Meaning Identifies a physical or configured I/O point Identifies a variable by its engineering meaning
Example Local:1:I.Data.0 CLAMP_CLOSED
Main use Hardware mapping and diagnostics Program readability and logic
Portability Can change when hardware configuration changes May remain stable if the project preserves the tag
Interpretation Depends on the PLC platform and configuration Depends on the tag definition and mapping

In Allen-Bradley Logix systems, a tag such as CLAMP_CLOSED may alias a physical I/O point or be assigned from another tag. In Siemens systems, the mapping may use a process image address such as %I0.0 alongside a symbolic tag such as "Clamp_Closed".

The address syntax is platform-dependent. Do not assume that the address format from one PLC family applies to another.

6. Reading I/O addresses across PLC platforms

The same physical function can use different address formats in different PLC families.

PLC platform Illustrative address or tag Interpretation
Allen-Bradley ControlLogix Local:1:I.Data.0 Input bit 0 of the configured local module at slot 1
Siemens S7 %I0.0 Input bit at byte 0, bit 0
Mitsubishi PLC X0 A common input-device notation
Rockwell symbolic tag CLAMP_CLOSED Symbolic variable, possibly mapped to a physical input
Siemens symbolic tag "Clamp_Closed" Symbolic variable representing the input function

These are illustrative conventions, not a complete address specification. Remote I/O, network adapters, rack configuration, module type, and PLC software version can change how a point is represented.

Maintenance rule: Verify the exact controller family, hardware configuration, and tag mapping before using an address to identify a physical channel.

7. Understanding a digital input in practice

Suppose an Allen-Bradley controller uses the following example:

Field Value
PLC tag CLAMP_CLOSED
Hardware address Local:1:I.Data.0
Module Digital input module in slot 1
Field device Clamp-closed sensor -B101
Expected state TRUE when the clamp is detected closed

When the clamp closes, the sensor changes its output state. The electrical signal reaches the input module, and the PLC's corresponding input bit changes state, subject to the module configuration and electrical conditions.

The program can then use CLAMP_CLOSED to determine whether the next sequence step is allowed.

If the PLC tag remains FALSE even though the clamp appears closed, investigate the complete signal path rather than immediately editing the PLC logic.

Potential causes include:

  • Sensor not switching.
  • Sensor supply missing.
  • Damaged or disconnected cable.
  • Incorrect terminal connection.
  • Incorrect input common or wiring arrangement.
  • Failed input channel.
  • Wrong hardware address or tag mapping.
  • A different signal being used by the program.
  • The physical clamp reaching a position that does not actually activate the sensor.

8. Understanding a digital output in practice

Consider a PLC commanding a solenoid valve that extends a cylinder.

Field Value
PLC tag CYLINDER_EXTEND_CMD
I/O type DO
Device tag -Y101
Destination Solenoid valve
Program function Requests cylinder extension

The signal path is:

PLC LOGIC
    |
    v
OUTPUT TAG
    |
    v
OUTPUT MODULE CHANNEL
    |
    v
TERMINAL BLOCK AND FIELD WIRING
    |
    v
SOLENOID COIL
    |
    v
VALVE SHIFTS
    |
    v
CYLINDER MOVES

If the output tag is TRUE but the cylinder does not extend, several different faults are possible.

Observation Investigation
PLC output tag is FALSE Check logic conditions, sequence state, faults, and permissives
Tag is TRUE but output channel is OFF Check tag mapping, module status, configuration, and channel diagnostics
Output channel is ON but coil is not energized Check supply, output wiring, protection, and coil circuit
Coil is energized but valve does not shift Check coil condition, valve mechanism, pressure supply, and valve specification
Valve shifts but cylinder does not move Check pneumatic or hydraulic supply, actuator, mechanical obstruction, and downstream conditions

A PLC command proves only that the program variable has a particular value. It does not prove that the field device physically operated.

9. Analog I/O mapping

Analog I/O lists require additional information because a signal represents a range of values rather than just two states.

Consider a pressure transmitter with a 4–20 mA output and a configured measurement range of 0–10 bar.

Field Example
PLC tag AIR_PRESSURE_BAR
Device tag -PT101
I/O type AI
Signal type 4–20 mA
Engineering range 0–10 bar
Raw input Platform-dependent integer or representation
Scaled value Pressure in bar
Alarm threshold Project-defined value

For ideal linear scaling:

\[ PV = \frac{I-4}{20-4}\times 10 \]

where:

  • \(PV\) is pressure in bar.
  • \(I\) is the measured current in mA.
  • 4 mA represents 0 bar.
  • 20 mA represents 10 bar.

For example, a measured current of 12 mA corresponds to:

\[ PV = \frac{12-4}{16}\times10=5\text{ bar} \]

This calculation assumes a correctly configured linear transmitter and input channel, with no additional offsets or nonlinear scaling.

For an analog output, the direction is reversed: the PLC calculates or commands a value, converts it to the configured output signal, and sends it to the receiving device.

An I/O list should make the signal range, engineering units, scaling, and destination clear enough to verify the complete measurement or command chain.

10. How to use an I/O list during breakdowns

A disciplined troubleshooting process follows the signal from one end to the other.

  1. Identify the machine symptom and the device involved.
  2. Find the device tag or functional description in the I/O list.
  3. Confirm the I/O type and PLC tag.
  4. Identify the hardware address, module, slot, and channel.
  5. Locate the relevant terminal and wiring references in the electrical drawings.
  6. Check the actual PLC tag and module diagnostics.
  7. Compare the observed state with the expected state under the current operating condition.
  8. Verify the field device and electrical path using approved procedures.
  9. Check how the signal is used by the PLC sequence, permissive, interlock, or alarm logic.
  10. Record the confirmed fault and update documentation if the installed system differs from the approved records.

The key is to separate the problem into three layers:

  • Signal generation: Is the field device producing the correct signal?
  • Signal transmission and acquisition: Does the signal reach the correct PLC input or output channel?
  • Signal interpretation and action: Is the PLC using the correct tag and producing the intended response?

This separation prevents unnecessary sensor replacements, random wiring changes, and unverified PLC edits.

11. I/O list versus electrical schematic versus PLC program

These documents complement one another. None replaces the others.

Document Main question answered
I/O list Which controller signal corresponds to which field device and function?
Electrical schematic How are the device, terminals, protection, and wiring electrically connected?
PLC hardware configuration Which modules, slots, channels, and addresses are configured?
PLC program How is the signal used in control logic?
Network or device configuration How is a networked device addressed and connected?
Instrument datasheet What are the device's electrical characteristics, ranges, and operating limits?
As-built drawings What is documented as the installed configuration?

For example, the I/O list may identify a sensor as CLAMP_CLOSED. The schematic shows how it is wired. The hardware configuration shows the input module and channel. The PLC program shows which sequence conditions depend on that signal.

12. Common mistakes

  • Confusing a PLC tag with a physical device tag.
  • Assuming every PLC tag corresponds directly to one physical I/O channel.
  • Assuming an input being ON proves that the mechanical position is correct.
  • Assuming an output being ON proves that a valve, motor, or contactor operated.
  • Ignoring input common, output supply, module configuration, and field wiring.
  • Using an address from an old PLC project after hardware has been changed.
  • Treating an analog raw value as an engineering measurement without verifying scaling.
  • Failing to distinguish local I/O from remote or networked I/O.
  • Modifying the PLC program before confirming whether the problem is electrical, mechanical, or logical.
  • Failing to update the I/O list after a retrofit or channel reassignment.

13. Interview questions and answers

Q1. What is an I/O list?

An I/O list maps controller inputs and outputs to field devices, signal descriptions, PLC tags, hardware addresses, and relevant wiring or terminal references.

Q2. What is the difference between DI and DO?

A digital input brings a discrete signal into the PLC. A digital output sends a discrete command from the PLC to a field device or interface circuit.

Q3. What is the difference between a PLC address and a PLC tag?

An address identifies a hardware or configured signal location. A tag provides a symbolic name representing the signal or variable in the PLC program.

Q4. A sensor LED is ON, but the PLC input is OFF. What do you check?

Check whether the LED indicates power or actual switching, then verify sensor output, supply and common, cable continuity, terminal wiring, input-channel configuration, and the correct PLC address.

Q5. A PLC output is ON, but the actuator does not operate. What does that tell you?

It tells you that the observed program variable is ON. It does not prove that the output hardware, wiring, supply, actuator, or mechanical system is functioning.

Q6. Why is an I/O list important during a retrofit?

It provides a baseline for mapping existing signals, identifying spare channels, assessing dependencies, planning changes, and updating PLC hardware and software documentation.

14. Practical exercise

Choose one sensor and one actuator from a machine you maintain. Trace each from the field device to the controller or from the controller to the field device.

  • Record the physical device tag and function.
  • Identify DI, DO, AI, or AO.
  • Find the PLC tag and hardware address.
  • Record the module, slot, and channel where applicable.
  • Locate the terminal numbers and wire references.
  • Identify the electrical signal type and voltage or current range.
  • Find the relevant PLC logic or sequence condition.
  • Record the expected state during stopped, running, and fault conditions.
  • Verify the actual signal path using approved diagnostic procedures.
  • Document any mismatch between the I/O list, PLC project, schematic, and installed wiring.

15. Final mental model

An I/O list connects the physical world to the controller's representation of that world.

FIELD DEVICE
    |
    v
ELECTRICAL SIGNAL
    |
    v
WIRING AND TERMINALS
    |
    v
I/O MODULE AND ADDRESS
    |
    v
PLC TAG
    |
    v
CONTROL LOGIC
    |
    v
MACHINE RESPONSE

For inputs, trace from the field device toward the PLC. For outputs, trace from the PLC toward the commanded device. In both cases, verify each link instead of assuming that a correct tag value guarantees correct physical behavior.

The real value of an I/O list is that it makes the signal traceable, testable, and maintainable throughout the machine's lifecycle.
