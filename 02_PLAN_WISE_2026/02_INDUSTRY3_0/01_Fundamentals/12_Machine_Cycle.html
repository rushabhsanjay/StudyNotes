A machine cycle is the complete, repeatable sequence of operations a machine performs to process one workpiece, complete one production task, or return to a defined starting condition ready for the next operation.

In industrial automation, understanding the machine cycle helps explain how a machine operates, how PLC logic coordinates its actions, where delays occur, and how maintenance faults affect production.

The central idea is that a machine does not merely switch ON and OFF. It performs a series of operations in a defined order, often using sensors, actuators, controller logic, and feedback to complete each cycle.

1. What is a machine cycle?

Consider an automated drilling machine that processes one metal component.

Its cycle might include:

  1. Wait for the component to arrive.
  2. Detect the component using a sensor.
  3. Clamp the component in position.
  4. Verify that the clamp is closed.
  5. Move the drill toward the component.
  6. Drill the required hole.
  7. Retract the drill.
  8. Release the clamp.
  9. Transfer the component to the next station.
  10. Return to the ready state for the next component.

Once the machine completes these operations and reaches its defined ready condition, it can begin the next cycle.

The exact cycle depends on the machine's design. Some machines perform several operations simultaneously, while others execute them sequentially.

2. Basic machine-cycle structure

A typical automatic machine cycle can be understood using these stages:

Ready / Waiting
      ↓
Workpiece Detection
      ↓
Positioning and Clamping
      ↓
Process Operation
      ↓
Operation Completion Verification
      ↓
Unclamping and Workpiece Release
      ↓
Return to Ready State
      ↓
Next Cycle

This is a conceptual example, not a mandatory sequence. A machine may include multiple stations, parallel operations, inspection steps, robot movements, or intermediate waiting states.

The important point is that a cycle has a defined beginning, a set of required operations, and a defined completion condition.

3. Start condition, cycle execution, and completion condition

A machine cycle is easier to understand when divided into three broad parts.

Part Meaning Example
Start condition Conditions required before the cycle can begin Part present, machine in automatic mode, no blocking fault
Cycle execution Operations performed during the cycle Clamp, drill, retract, inspect
Completion condition Conditions that confirm the cycle has finished Drill retracted, clamp released, part transferred

A start command does not necessarily mean that the cycle has started. The controller may receive a start request but wait until the required conditions are satisfied.

Likewise, issuing the final output command does not necessarily mean the cycle is complete. The machine may need feedback confirming that the final movement or operation has finished.

For example, commanding a pneumatic cylinder to retract is different from confirming that its retracted-position sensor has activated.

4. Machine cycle versus individual machine operations

These terms describe different levels of activity.

Term Meaning Example
Machine cycle Complete repeatable operation Processing one component from loading to release
Machine operation One activity within a cycle Clamping the component
Machine state The current operating condition Waiting, clamping, drilling
Cycle start The event or command requesting a cycle Operator presses Cycle Start
Cycle completion The defined condition indicating that the cycle has finished Component released and machine ready
Production cycle A production-related cycle defined for a machine or process Completing one vehicle body at a station

A machine cycle may contain many operations and states. The controller coordinates these states according to the programmed control strategy.

5. Machine cycle in PLC automation

In a PLC-controlled machine, the machine cycle is typically represented by logic that tracks the current stage and determines when to proceed to the next stage.

For example, a drilling machine could use the following sequence:

Step Machine action Typical completion evidence
0 Wait for cycle start Valid start request and required conditions
1 Clamp component Clamp-closed feedback
2 Advance drill Drill-forward position or process condition
3 Perform drilling Required drilling condition or completion signal
4 Retract drill Drill-retracted feedback
5 Release component Clamp-open feedback
6 Complete cycle Required final conditions satisfied

This is an illustrative sequence. A real machine may use additional checks, multiple timers, process measurements, robot coordination, or other conditions.

How the PLC coordinates the cycle

The controller generally needs to determine:

  • Which step is currently active.
  • Which actions are required in that step.
  • Which conditions must be satisfied to proceed.
  • Whether a timeout or fault has occurred.
  • Whether the machine may continue, must wait, or must stop.
  • When the cycle-complete condition becomes true.

The machine cycle is therefore closely connected to control logic and sequence control. The dedicated study topics on sequence, interlocks, permissives, and handshakes will examine those mechanisms in greater detail.

6. Automatic cycle versus manual operation

Industrial machines often provide several operating modes. The exact modes depend on the equipment and its design.

Mode Typical behaviour
Manual An operator commands individual movements or functions according to the machine's operating rules
Automatic The controller executes the programmed production cycle
Setup or jog Equipment is positioned or adjusted using designated controls
Maintenance Functions may be made available for approved servicing tasks under defined conditions

Manual operation does not necessarily bypass every automatic condition, and maintenance mode does not automatically make equipment safe to approach.

Safety-related functions must remain effective as required by the machine's safety design. The permitted movements and conditions depend on the machine, its risk assessment, and the applicable procedures.

Why this distinction matters

Suppose a clamp works in manual mode but does not operate during an automatic cycle.

Possible causes include:

  • The automatic cycle has not started.
  • A required operating condition is not satisfied.
  • The sequence has not reached the clamp step.
  • The controller is waiting for a different signal.
  • A process or communication condition is missing.
  • The automatic-mode logic differs from the manual-command logic.

The fact that a device operates in manual mode does not prove that the automatic sequence is correct. It only provides useful evidence about some parts of the control and physical systems.

7. Single-cycle and continuous-cycle operation

Two common operating behaviours are single-cycle operation and continuous-cycle operation.

Single-cycle operation: The machine performs one cycle after a valid start request and then stops at its defined end condition, waiting for another start request.

Continuous-cycle operation: The machine automatically starts another cycle when the previous cycle finishes and the required conditions for the next cycle are satisfied.

Feature Single cycle Continuous cycle
Number of cycles One per accepted start request Repeated cycles while operation is enabled
Operator involvement May require a new start request after each cycle Usually requires an initial start and an appropriate stop request to end repetition
Typical use Setup, inspection, controlled production Repetitive high-volume production
Common concern Why did the machine not start the next cycle? Why did the machine continue cycling or fail to stop as intended?

The actual behaviour depends on the machine's configured operating modes. A continuous-cycle command must not be confused with a command that overrides faults or safety-related stops.

8. Machine cycle time

Machine cycle time is the elapsed time associated with completing one defined machine cycle.

For a simple machine:

\[ T\_{\text{cycle}}=t\_{\text{completion}}-t\_{\text{start}} \]

If a machine starts processing a component at 10:00:00 and reaches its defined cycle-complete condition at 10:00:12, the measured cycle time is 12 seconds.

The definition must specify the start and end events. Different machines and production systems may use different measurement boundaries.

For example, one measurement may start when the component enters the station, while another starts when the automatic cycle is accepted. Those measurements may differ even though they refer to the same physical equipment.

Cycle time is an important performance measure, but it is not identical to the machine cycle itself:

  • Machine cycle describes the operations and states.
  • Cycle time measures the elapsed time for a defined cycle.

The next dedicated topic, 13_Cycle_Time, will cover the measurement and interpretation of cycle time in detail.

9. Sequential and parallel operations within a machine cycle

Not every operation must wait for the previous operation to finish. Machines can execute certain activities simultaneously.

Sequential operation

A drilling machine may need to clamp a component before advancing the drill.

The drill movement cannot begin until the required clamping condition is satisfied.

Parallel operation

A machine with two independent processing heads may drill two locations simultaneously. A separate station may also prepare the next component while the current component is being processed, provided the equipment and control design allow it.

Characteristic Sequential operations Parallel operations
Execution Operations occur in a required order Independent operations overlap in time
Time relationship Some operations must finish before the next begins Total elapsed time can be reduced by overlapping work
Main control concern Correct order and transition conditions Synchronisation and coordination
Example Clamp, drill, retract Two independent drill heads operating together

Parallel operations do not necessarily reduce the cycle time by the sum of the overlapping durations. The cycle duration depends on the complete operation structure, dependencies, and any shared resources.

10. Abnormal conditions during a machine cycle

A cycle may fail to complete because the physical machine, the controller, or an external dependency does not behave as expected.

Abnormal condition Example Possible consequence
Missing input Component-presence sensor never activates Cycle does not start
Incomplete movement Clamp does not reach its closed position Cycle waits or stops
Process failure Drill does not reach the required condition Operation remains incomplete
Timeout Expected movement takes too long Controller reports or handles an abnormal condition
Communication failure Robot completion status is unavailable PLC cannot confirm that the coordinated operation finished
Unexpected feedback A position sensor changes state at the wrong time Sequence may stop or enter a fault-handling state

The controller's response depends on the program and machine design. It may wait, retry an operation, report a fault, stop the sequence, or enter a defined recovery state.

A timeout does not necessarily identify the failed component. It establishes that an expected condition was not achieved within the configured time. The root cause still needs to be investigated.

11. Machine-cycle troubleshooting

When a machine fails to complete a cycle, start by identifying the last operation that completed successfully and the condition required for the next operation.

A practical troubleshooting procedure is:

  1. Identify the current machine state or sequence step.
  2. Identify the expected action and the conditions required to proceed.
  3. Check the relevant PLC tags and input/output status.
  4. Verify whether the physical device actually performed the commanded action.
  5. Check feedback signals, communications, and timing where relevant.
  6. Identify the root cause before resetting or restarting the machine.

Example: Clamp closes, but drilling does not begin

Suppose the clamp moves to its closed position, but the drill never advances.

Possible causes include:

  • The clamp-closed feedback is not reaching the PLC.
  • The PLC input is present, but the program is waiting for another condition.
  • The machine is not in the expected automatic state.
  • A required process or equipment-ready signal is missing.
  • A controller-to-controller coordination condition has not been received.
  • A fault or timeout is preventing progression.

The correct approach is to identify the condition that prevents the transition to the drilling step, then trace that condition to its source.

Replacing the clamp immediately would be a poor first choice if the clamp already closes correctly. The physical movement and the controller's interpretation of that movement are separate things.

Example: Machine completes the operation but does not release the part

Check whether:

  • The process-complete condition was achieved.
  • The controller advanced to the release stage.
  • The release command was issued.
  • The output circuit operated correctly.
  • The clamp-open feedback changed state.
  • The cycle-complete condition was satisfied.

This separates a process-completion problem from an output, actuator, feedback, or final-state problem.

12. Machine cycle and production performance

A machine cycle is also useful for understanding production losses.

For example, a machine may have a repeatable cycle but still produce less than expected because of:

  • Waiting for upstream material.
  • Delays in loading or unloading.
  • Frequent faults and recovery time.
  • Quality inspection or rework.
  • Downstream equipment being unavailable.
  • Changeovers or planned interruptions.

These factors can influence production output without necessarily changing the programmed machine cycle.

It is useful to distinguish:

  • Machine cycle: The defined set of operations.
  • Cycle time: The elapsed time for a defined cycle.
  • Takt time: The production pace required to meet customer demand.
  • Throughput: The quantity of output produced per unit of time.
  • Bottleneck: The constrained operation that limits the overall production rate.

These topics are related, but they answer different questions. The machine cycle describes what the equipment does; the performance metrics describe its timing and contribution to production.

13. Interview questions and answers

Q1. What is a machine cycle?

A machine cycle is the complete, repeatable sequence of operations performed to process a workpiece or complete a defined task and return to a specified condition for the next cycle.

Q2. What are the typical stages of a machine cycle?

A typical cycle includes a ready condition, workpiece detection, positioning, processing, completion verification, release, and return to the ready condition. The actual stages depend on the machine.

Q3. What is the difference between a machine cycle and cycle time?

A machine cycle describes the sequence of operations. Cycle time measures the elapsed time for a defined cycle.

Q4. Why might a machine fail to start an automatic cycle?

The start request may be missing or rejected, a required condition may be unsatisfied, the machine may be in the wrong mode, or a fault or coordination dependency may be preventing the start.

Q5. Why might a machine complete one cycle but fail to start the next?

It may be configured for single-cycle operation, or the next cycle's required conditions may not be satisfied. The machine may also be waiting for a new start request or a required external signal.

Q6. What is the difference between sequential and parallel operations?

Sequential operations occur in a required order. Parallel operations can overlap when their dependencies and equipment design permit simultaneous execution.

Q7. Why is feedback important in a machine cycle?

Feedback provides evidence of the actual or detected state of equipment. It helps the controller determine whether an operation completed rather than assuming success from the command alone.

Q8. How should a technician troubleshoot an incomplete machine cycle?

Identify the current step, determine the next required condition, inspect the relevant controller tags and I/O, verify physical operation, and trace the missing condition to its cause.

Q9. Does a machine cycle always contain only one operation at a time?

No. A cycle can contain sequential operations, overlapping parallel operations, and coordinated activities across multiple controllers.

Q10. Can cycle time increase even if the machine program has not changed?

Yes. Mechanical wear, slower actuator movement, sensor problems, communication delays, material variation, and other physical or operational factors can increase elapsed cycle time without any program change.

14. Final mental model

Think of a machine cycle as the machine's complete repeatable working routine.

  • The start condition establishes when the machine may begin.
  • The cycle steps define the operations it performs.
  • Feedback helps verify whether those operations succeeded.
  • Completion conditions establish when the cycle is finished.
  • Cycle time measures how long the defined cycle takes.
  • Fault handling determines what happens when the expected sequence cannot be completed.

For maintenance, the most useful principle is to identify the last successfully completed operation and the next unmet condition. That gives a clear starting point for troubleshooting instead of treating the entire machine as one mysterious metal box.
