1. Definition and Purpose

Functional, safety, production, and performance testing are complementary verification activities performed during commissioning and Site Acceptance Testing (SAT) to establish whether an installed machine or automated production system meets its specified requirements.

These activities answer four different questions:

  • Functional testing: Does the machine perform the required operations correctly?
  • Safety testing: Do the required risk-reduction and safety functions operate correctly under their specified conditions?
  • Production testing: Can the system produce acceptable parts or products under representative operating conditions?
  • Performance testing: Does the system meet specified measurable requirements such as throughput, availability, repeatability, accuracy, and resource consumption?

Passing one category does not automatically mean the others have passed. A machine may execute its PLC sequence correctly but fail to produce acceptable components. It may meet cycle time but have an unverified safety function. It may produce good parts but fail to meet the required production rate.

The purpose of SAT testing is to collect objective evidence that the installed system meets the agreed acceptance criteria before the applicable release or handover decision.

The actual test sequence depends on the equipment, risk assessment, project requirements, and approved commissioning procedure. Safety prerequisites must be satisfied before tests that depend on them, and hazardous tests must be controlled by authorized personnel.

3. Functional Testing

3.1 Definition

Functional testing verifies that the machine, control system, and associated equipment perform their specified functions correctly.

It checks whether inputs, logic, outputs, sequences, interlocks, alarms, modes, and interfaces behave as defined in the approved requirements.

Typical systems include:

  • PLC-controlled machines.
  • HMI operator panels.
  • VFD-controlled motors.
  • Servo and motion-control systems.
  • Robots and CNC machines.
  • Pneumatic and hydraulic actuators.
  • Sensors, encoders, and remote I/O.
  • Communication networks and supervisory systems.

3.2 Functional test objectives

  • Verify the correct response to operator commands.
  • Verify sequence order and transition conditions.
  • Confirm that required inputs and feedback signals are interpreted correctly.
  • Verify actuator and motor commands.
  • Check manual, automatic, setup, and maintenance modes where applicable.
  • Confirm alarm generation, acknowledgement, and reset behavior.
  • Verify communication between PLC, HMI, drives, robots, and other devices.
  • Check fault handling and recovery behavior.
  • Confirm that the system returns to an approved state after interruptions.
  • Verify that specified interlocks prevent prohibited operations.

3.3 Typical functional test cases

Test case Expected result
Start command Machine starts only when the required permissives are satisfied
Stop command Machine performs the specified normal stopping sequence
Sensor detection Correct PLC input and sequence response occur
Actuator extension Actuator moves as commanded and required feedback is received
Actuator timeout Appropriate fault is generated if feedback does not arrive within the specified time
Automatic sequence Operations occur in the defined order
Mode selection Only the functions permitted for the selected mode are available
HMI alarm Correct alarm text and status are displayed for the defined fault
Communication loss System responds according to the specified fault strategy
Power restoration Restart behavior follows the approved design and safety requirements
Recipe selection Correct approved recipe and parameter set are selected
Quality-test failure Failed result is handled according to the specified rejection logic

3.4 Functional test procedure

  1. Identify the requirement and its associated test case.
  2. Confirm the correct machine, software revision, and test configuration.
  3. Verify the required installation and safety prerequisites.
  4. Establish the specified initial conditions.
  5. Apply the test input or operator command.
  6. Observe the PLC, HMI, device, and physical machine response.
  7. Compare the actual response with the expected result.
  8. Record the outcome and relevant evidence.
  9. Raise a defect if the result does not meet the acceptance criteria.
  10. Retest after the corrective action is implemented.

Testing should cover normal operation, defined abnormal conditions, and recovery behavior. Testing only the happy path is how machines acquire mysterious faults the moment production starts.

4. Safety Testing

4.1 Definition

Safety testing verifies that specified safety functions and risk-reduction measures behave as required under the defined operating conditions.

Safety functions may include:

  • Emergency stop.
  • Guard-door interlocking.
  • Guard locking.
  • Light curtains and safety scanners.
  • Safe torque off (STO).
  • Safe stop functions.
  • Safe speed monitoring.
  • Prevention of unexpected restart.
  • Safety-related mode selection.
  • Safety-rated robot operating functions.
  • Safety-related pneumatic or hydraulic isolation.

The exact functions depend on the machine risk assessment, applicable standards, and approved safety design.

4.2 Safety function versus ordinary control function

An ordinary PLC function controls the process. A safety function reduces risk by taking the required action when a specified hazardous condition occurs.

For example, an ordinary PLC input may indicate that a guard door is closed. A safety-rated guard interlock must provide the safety behavior required by the safety design. A normal PLC indication alone does not prove that the required safety function is implemented or validated correctly.

Safety functions may use safety relays, safety PLCs, safety-rated drives, safety communication, or other validated architectures.

4.3 Example safety tests

Safety function Test action Expected result
Emergency stop Activate the designated emergency-stop device under the approved test conditions Hazardous motion is stopped or controlled as specified
Guard interlock Open the protected guard during the specified test The defined hazardous operation is prevented or stopped as designed
Guard locking Request access while the guard must remain locked Guard remains locked until the specified safe-release conditions are met
Light curtain Interrupt the protective field under the approved procedure The required protective response occurs
Safe torque off Initiate the specified STO condition Drive torque-producing capability is disabled as designed
Restart prevention Restore a tripped safety condition Hazardous motion does not restart unexpectedly
Reset function Apply the authorized reset procedure Reset clears the permitted fault state but does not itself initiate hazardous motion unless explicitly designed and validated under applicable requirements
Safety fault Introduce a permitted test fault using the approved method The safety system responds according to the validated design

Tests must be conducted by qualified, authorized personnel using the approved safety validation procedure. Do not bypass guards, defeat interlocks, or deliberately introduce faults without the required controls.

4.4 Safety testing principles

  • Identify each safety function and its required response.
  • Confirm the relevant risk assessment and safety requirements.
  • Verify installation and configuration against the approved design.
  • Check the specified stopping behavior and conditions.
  • Verify reset and restart behavior.
  • Record test results and relevant measurements.
  • Confirm any required safety validation and sign-off.
  • Control changes to safety-related software and hardware.
  • Do not treat a successful indicator lamp or HMI message as sufficient proof of safety-function performance.

Where stopping time, stopping distance, or safety response time is specified, measure it using the approved method and compare it with the defined limit.

4.5 Important distinction: emergency stop and isolation

An emergency stop is a protective function, not a substitute for lockout/tagout or another approved hazardous-energy isolation procedure.

Maintenance and intrusive inspection may require isolation of electrical, pneumatic, hydraulic, mechanical, thermal, or other stored energy. Verify the required isolation and zero-energy state before performing work that exposes personnel to hazardous energy.

5. Production Testing

5.1 Definition

Production testing verifies that the installed system can manufacture the intended product under representative production conditions while meeting the specified quality and operational requirements.

It checks more than whether the machine moves. It checks whether the machine performs the actual production process correctly.

5.2 Production test objectives

  • Produce the correct part or product.
  • Verify correct tooling, fixtures, and workpiece positioning.
  • Confirm recipe and process parameter selection.
  • Verify operation with representative production material.
  • Confirm correct process sequence and handling.
  • Check product identification and traceability.
  • Verify pass/fail classification and rejection handling.
  • Confirm measurement and test-result recording.
  • Verify material transfer and downstream interfaces.
  • Demonstrate stable production under the defined test conditions.

5.3 Typical production tests

Test Verification
First-off part Initial product meets specified quality requirements
Representative production run System produces the required product using approved materials and conditions
Product variant change Correct recipe, tooling, and parameters are selected
Part identification Correct product identity is recorded
Quality failure Failed part is identified and handled correctly
Reject mechanism Rejected product is diverted or segregated as specified
Traceability Required process data and test results are associated with the correct part
Material handling Loading, transfer, clamping, and unloading occur correctly
Repeated production Product quality remains within the defined acceptance limits
Downstream integration Finished product is correctly transferred to the next station or system

5.4 Production quality measures

Depending on the process, product acceptance may use:

  • Dimensional measurements.
  • Torque or force measurements.
  • Pressure or leakage results.
  • Electrical test results.
  • Weld or joining parameters.
  • Visual inspection.
  • Functional test results.
  • Traceability records.
  • Statistical process measures where specified.

The acceptance limits must come from the drawing, control plan, process specification, test specification, or other approved requirement. A part that looks acceptable is not automatically a conforming part.

6. Performance Testing

6.1 Definition

Performance testing measures whether the system achieves its specified operating performance under defined conditions.

Performance may include throughput, cycle time, repeatability, accuracy, uptime, reliability, response time, energy consumption, or other project-specific metrics.

Performance testing requires measurable acceptance criteria. Statements such as "the machine should be fast" are not testable requirements until converted into a defined metric and limit.

6.2 Common performance parameters

Parameter Meaning
Cycle time Time required to complete a defined machine or process cycle
Throughput Number of accepted units produced per unit of time
Availability Proportion of the defined period during which the system is available under the agreed definition
Repeatability Closeness of results from repeated operations under specified conditions
Accuracy Closeness of a measured or controlled result to its reference or target
Response time Time between a defined event and the specified system response
First-pass yield Proportion of units accepted without rework on the first pass
Reject rate Proportion of produced units rejected under the defined measurement rules
Energy consumption Energy used over a defined production period or output quantity
Mean time between failures Average operating time between qualifying failures, using the agreed calculation rules

These metrics are not interchangeable. For example, high throughput does not guarantee high first-pass yield, and low cycle time does not guarantee high availability.

6.3 Throughput calculation

If a station produces 360 accepted units in 60 minutes, its observed accepted output rate is:

\[ \text{Throughput}=\frac{360}{60}=6 \]

The result is 6 accepted units per minute, provided the measurement period, accepted-unit definition, and production conditions are specified.

6.4 Availability calculation

A commonly used time-based availability measure is:

\[ \text{Availability}= \frac{\text{Operating Time}} {\text{Planned Production Time}}\times100\\% \]

If planned production time is 480 minutes and qualifying downtime is 24 minutes, operating time is 456 minutes:

\[ \text{Availability}=\frac{456}{480}\times100\\%=95\\% \]

This result is valid only when the project defines planned production time and qualifying downtime consistently. Breaks, planned maintenance, changeovers, minor stops, and other losses may be treated differently by different systems.

6.5 First-pass yield calculation

\[ \text{First-Pass Yield}= \frac{\text{Units Accepted on First Pass}} {\text{Total Units Processed}}\times100\\% \]

If 196 out of 200 units pass without rework:

\[ \text{First-Pass Yield}=\frac{196}{200}\times100\\%=98\\% \]

Reworked units should not be counted as first-pass accepted units unless the agreed metric explicitly defines a different rule.

7. Test Conditions and Acceptance Criteria

Every test should define the conditions under which its result is valid.

Typical conditions include:

  • Equipment configuration and software revision.
  • Product type and material.
  • Tooling and fixture configuration.
  • Supply voltage and other utility conditions.
  • Air or hydraulic pressure.
  • Ambient or process temperature where relevant.
  • Operating mode.
  • Production speed or target cycle time.
  • Sample size and test duration.
  • Required number of repeated cycles.
  • Measurement instrument and calibration status.
  • Permitted faults, interruptions, or exclusions.
  • Acceptance limits and calculation rules.

A performance result without its test conditions can be misleading. A station tested with an empty fixture, reduced speed, or ideal material may not represent actual production conditions.

8. Designing a SAT Test Case

A well-defined test case includes the requirement, test setup, procedure, expected result, acceptance limit, and evidence.

Test field Example
Test ID SAT-FUNC-014
Test title Verify automatic clamping sequence
Requirement Approved sequence specification
Preconditions Machine in approved test mode; required safeguards and utilities verified
Initial state Fixture empty; clamp retracted; required permissives available
Test action Start the approved automatic sequence
Expected result Clamp extends, feedback is confirmed, and the sequence advances as specified
Acceptance criteria Required feedback and sequence transitions occur within specified conditions and limits
Evidence Recorded PLC status, observation, and test result
Result Pass, fail, blocked, or not tested according to the project procedure
Defect reference Linked punch-point or issue ID when applicable
Approval Required tester and verifier sign-off

Avoid vague acceptance criteria such as "works correctly." Define the required behavior and measurable limit.

9. Integrated Testing of PLC, HMI, Drives, and Field Devices

Functional, safety, production, and performance tests frequently cross several subsystems.

Consider a station that clamps a component, runs a test, and releases the component.

Part Detected
      ↓
PLC Verifies Required Permissives
      ↓
Clamp Command Issued
      ↓
Clamp Feedback Confirmed
      ↓
Process or Test Cycle Executes
      ↓
Result Evaluated
      ↓
Pass / Fail Handling
      ↓
Clamp Releases When Permitted
      ↓
Part Identification and Result Stored

The sequence above is illustrative. The actual behavior must follow the approved machine design, and safety functions must remain independent of ordinary process assumptions where required by the safety architecture.

During testing, verify:

  • The sensor input changes correctly.
  • The PLC uses the correct input and state.
  • The actuator reaches its required position.
  • Feedback is received within the defined time.
  • The HMI displays the correct status.
  • The test equipment returns valid measurement data.
  • The pass/fail logic matches the acceptance criteria.
  • The correct part result is stored.
  • Faults are handled as specified.
  • The machine does not advance when required conditions are absent.

If a calibrated instrument is required, verify its calibration status and suitability for the measurement range and uncertainty needed.

11. Failure Handling and Retesting

When a test fails:

  1. Stop or contain the affected activity as required by the risk and procedure.
  2. Record the actual result and the expected result.
  3. Preserve relevant diagnostic information.
  4. Identify the equipment, software revision, test conditions, and event sequence.
  5. Raise a defect or punch point.
  6. Investigate the root cause to the extent appropriate to the risk and impact.
  7. Implement an authorized correction.
  8. Repeat the original test or an approved equivalent.
  9. Perform regression tests for related functions affected by the change.
  10. Record the new result and obtain the required approval.

Do not overwrite a failed result with a later successful result. Preserve both records so the defect and its resolution remain traceable.

A software correction to a PLC sequence may require regression testing of upstream permissives, downstream operations, fault handling, HMI status, and associated safety interactions where applicable.

12. Safety Boundaries During SAT

SAT frequently involves testing equipment that is installed and connected to real utilities. Test planning must therefore control both electrical and mechanical hazards.

  • Use the approved commissioning risk assessment and work permit process.
  • Confirm required guarding and safety prerequisites before operating the equipment.
  • Use lockout/tagout or the site's approved hazardous-energy control procedure for work requiring isolation.
  • Control access to robot cells and other hazardous zones.
  • Never defeat a safety function merely to complete a test.
  • Use approved methods for testing safety-related hardware and software.
  • Confirm the effect of test actions before commanding motors, cylinders, axes, or robots.
  • Prevent unexpected restart after faults, resets, or power restoration.
  • Control manual mode, jogging, and setup operations according to the approved design.
  • Ensure test personnel understand the stop methods and emergency arrangements.
  • Do not release equipment for production while mandatory safety validation remains incomplete.

A safety function that has not been adequately verified must be treated as unverified, not assumed to be correct because the machine completed a production cycle.

13. Test Reports and Acceptance Status

The SAT report should provide a traceable summary of what was tested and what remains unresolved.

Typical contents include:

  • Equipment and project identification.
  • Test scope and acceptance requirements.
  • Software and configuration revisions.
  • Test dates and personnel.
  • Test conditions and instruments.
  • Test-case IDs and results.
  • Measurements and supporting evidence.
  • Defect and punch-point references.
  • Corrective actions and retest outcomes.
  • Approved deviations and restrictions.
  • Outstanding tests and reasons they were not performed.
  • Required approvals and final acceptance status.

Useful result labels include:

  • Pass: The acceptance criteria were met.
  • Fail: The acceptance criteria were not met.
  • Blocked: The test could not proceed because a prerequisite was unavailable or unsafe.
  • Not tested: The test was not executed.
  • Not applicable: The requirement does not apply, with the reason documented where required.

A blocked test is not a pass. An untested safety requirement is not verified. The project acceptance procedure determines how outstanding results affect release.

14. Practical Automotive Plant Example

Consider a new automated component-testing station installed on an automotive production line. The station clamps a component, performs a pressure test, records the result, and sends the component to the appropriate destination.

Functional testing

  • Verify part detection and correct clamping.
  • Confirm that the pressure-test sequence starts only when required permissives are satisfied.
  • Verify the pressure sensor value and engineering-unit scaling.
  • Confirm the PLC receives the test result.
  • Verify that the HMI displays the correct status and alarm.
  • Confirm the sequence handles timeout and communication faults as specified.

Safety testing

  • Verify the required guarding and interlocks.
  • Test the emergency-stop response under the approved procedure.
  • Verify required prevention of unexpected restart.
  • Complete the specified safety validation and documentation.

Production testing

  • Run representative approved components.
  • Confirm the correct test recipe is selected.
  • Verify pass/fail classification.
  • Confirm rejected components are handled correctly.
  • Verify traceability between the component ID and its test result.

Performance testing

  • Measure cycle time under the specified production conditions.
  • Confirm accepted throughput over the defined measurement period.
  • Calculate first-pass yield.
  • Record downtime and excluded periods according to the agreed metric.
  • Verify that performance limits are met without compromising safety or product quality.

A station is not ready for acceptance merely because it completes the sequence. It must also meet the required safety, product-quality, and performance criteria.

15. Acceptance Checklist

Functional testing

  • Required operating modes are verified.
  • Inputs, outputs, sequence transitions, and feedback are correct.
  • Alarms, timeouts, and fault recovery are tested.
  • PLC, HMI, drives, robots, CNC, and other interfaces behave as specified.
  • Approved program and configuration revisions are recorded.

Safety testing

  • Required safety functions are identified from the approved safety design.
  • Installation and validation prerequisites are satisfied.
  • Safety devices and required responses are tested under the approved procedure.
  • Reset and restart behavior meet the specified requirements.
  • Required measurements and safety validation records are complete.
  • No unapproved bypass or override remains.

Production testing

  • Representative approved material or products are used.
  • Tooling, fixtures, recipes, and process settings are correct.
  • Product quality requirements are met.
  • Reject and rework handling behave as specified.
  • Traceability and test-result recording are verified.

Performance testing

  • Cycle-time limits and measurement rules are defined.
  • Throughput is measured over the specified period.
  • Availability and downtime are calculated using agreed definitions.
  • Repeatability, accuracy, yield, or other required metrics are verified.
  • Test conditions are representative and documented.
  • Required performance limits are met.

Closure and handover

  • Test failures are documented.
  • Corrective actions and retests are traceable.
  • Outstanding items are formally dispositioned.
  • Required reports and supporting evidence are complete.
  • Authorized acceptance and release approvals are recorded.

16. Interview Questions and Answers

Q1. What is the difference between functional and performance testing?

Functional testing checks whether the system performs the required behavior. Performance testing measures whether it meets defined quantitative targets such as cycle time, throughput, repeatability, or availability.

Q2. Why is safety testing separate from functional testing?

A machine can perform its normal process correctly while a protective function remains defective. Safety testing verifies the required risk-reduction functions against their specified requirements.

Q3. What is the difference between production testing and performance testing?

Production testing focuses on the ability to manufacture conforming products under representative conditions. Performance testing measures specified operating metrics, which may include throughput, cycle time, availability, and quality-related indicators.

Q4. What is a SAT acceptance criterion?

It is a defined condition or limit that determines whether the test result meets the approved requirement.

Q5. What should happen when a test is blocked?

Record the blocked status and reason, maintain the required safety controls, resolve the missing prerequisite, and perform the test later. Do not record an unexecuted test as passed.

Q6. Why is regression testing required after a PLC change?

A change intended to fix one issue may affect other sequence steps, permissives, alarms, interfaces, or fault-recovery behavior. Regression testing checks relevant previously verified functions for unintended effects.

Q7. Can a machine pass performance testing while failing safety testing?

It may meet the measured performance targets, but it cannot be considered fully accepted or released if a mandatory safety requirement remains unmet.

Q8. Why must test conditions be documented?

Results are meaningful only in relation to their conditions, configuration, measurement method, and acceptance criteria. Documented conditions make the result reproducible and auditable.

Q9. How is first-pass yield different from throughput?

First-pass yield measures the proportion of processed units accepted without rework on the first pass. Throughput measures output per unit of time. A system can have high throughput but poor first-pass yield.

Q10. What is the purpose of an SAT report?

It records the tests performed, actual results, supporting evidence, failures, corrective actions, outstanding issues, and acceptance decision.

17. Key Takeaway

Functional testing verifies behavior. Safety testing verifies specified protective functions. Production testing verifies the ability to manufacture conforming products. Performance testing verifies measurable operating targets.

These four areas complement one another and should be evaluated against approved requirements using controlled test conditions, objective evidence, and formal acceptance criteria.
