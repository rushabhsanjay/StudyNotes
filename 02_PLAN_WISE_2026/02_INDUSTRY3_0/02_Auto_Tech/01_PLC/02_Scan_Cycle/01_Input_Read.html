1. Definition

Input read is the stage in a PLC scan cycle in which the controller acquires input data from physical or configured I/O sources and makes that data available to the control program.

In a traditional cyclic PLC execution model, the CPU reads the states of its inputs and stores them in an area of memory commonly called the input image table or process image of inputs.

The program then uses these stored values during logic execution.

For example, a proximity sensor detects a component on an automotive fixture. The PLC acquires the input state and makes it available to the program through an input address or symbolic tag such as PART_PRESENT.

The program evaluates that value when executing the relevant logic.

2. Where input read fits in the PLC scan cycle

A simplified cyclic PLC scan can be represented as:

| Acquire input states         |
| Update input image data      |
+--------------+--------------+
               |
               v
+-----------------------------+
| 2. PROGRAM EXECUTION         |
| Execute user logic           |
| Evaluate conditions          |
+--------------+--------------+
               |
               v
+-----------------------------+
| 3. OUTPUT UPDATE             |
| Transfer output commands     |

This is a simplified model. Actual execution differs across PLC platforms, task types, I/O architectures, and configuration settings. Some controllers update I/O asynchronously, use scheduled tasks, or provide different process-image arrangements.

For foundational study, however, the key concept is that the program may use an acquired snapshot of input data rather than directly sampling the physical terminal every time an input instruction is evaluated.

3. What is an input image table?

The input image table is a logical area of controller data that represents the current acquired states of configured inputs.

Think of it as a snapshot of input information made available to the program.

For example, a PLC might have these digital inputs:

Input signal Physical condition Acquired input value
PART_PRESENT Component detected TRUE
CLAMP_CLOSED Clamp-closed sensor active TRUE
GUARD_CLOSED Guard sensor active TRUE
AIR_PRESSURE_OK Pressure switch active FALSE

The program can evaluate these values without independently measuring each field terminal every time it encounters the corresponding instruction.

The input image is not the physical sensor, the field wiring, or the sensor's electrical voltage. It is the controller's representation of the acquired input data.

4. Physical input versus input image

These are related but distinct concepts.

Concept Meaning
Physical input Electrical signal present at the input circuit
Input module state State detected by the module after its electrical processing
Input image Input data made available to the program
PLC input tag Program-level name or reference for that data
Physical condition Actual state of the machine or process

Consider a sensor connected to a PLC input.

Component reaches sensor
          |
          v
Sensor output changes
          |
          v
Input module detects the signal
          |
          v
Controller acquires input data
          |
          v
Input image is updated
          |
          v
PLC program reads PART_PRESENT

A change at the physical sensor does not necessarily become visible to the program at that exact instant. Input filtering, module conversion, communication updates, and the controller's execution model can introduce delays.

This is why an input may appear to change slightly after the physical event.

5. Why use an input image instead of reading every input continuously?

A conventional input-image approach provides several useful properties.

Consistency during logic execution

The program can evaluate a consistent set of acquired input values during a defined execution interval.

Suppose the PLC program checks PART_PRESENT in three different places. With a conventional input image that remains unchanged throughout the relevant program execution, each check can use the same acquired state.

Without such a model, a physical input changing between two checks could produce different results within the same logic execution.

Efficient program execution

The controller can acquire input data through its I/O mechanism and then execute logic against the stored values. The program does not need to perform a separate physical I/O transaction for every ordinary input instruction.

Separation of field hardware and logic

The program can evaluate input data in memory, while the I/O hardware handles the electrical interface.

This separation helps organize the controller architecture and makes program behavior easier to understand.

These benefits describe a traditional input-image model. Controllers with asynchronous I/O, immediate I/O instructions, or different task architectures can behave differently.

6. Example: reading a clamp-closed input

Assume an automotive fixture has a proximity sensor connected to a digital input.

The relevant PLC tag is:

CLAMP_CLOSED

Suppose the sensor becomes active just before the controller's next input acquisition.

Stage Event Input image value
1 Clamp has not reached the sensor FALSE
2 Clamp reaches the sensed position Physical sensor becomes active
3 Controller acquires the input TRUE
4 Program evaluates CLAMP_CLOSED TRUE
5 Program can permit the next sequence step Depends on all required logic conditions

The important point is that the input must be acquired and made available to the program before the program can act on the new value through the ordinary input-image path.

The program may still refuse to proceed if other permissives are not satisfied.

For example, the next step might also require PART_PRESENT, acceptable pressure, and a valid robot status.

7. Input acquisition and scan timing

A field input can change at any point during the PLC's execution cycle.

Consider a simplified scan that takes 10 ms. The 10 ms value is illustrative, not a universal PLC scan time.

If an input changes just after the controller has acquired the input image, the program may not see the new state until a later input update.

Time ---------------------------------------------------->

Input acquisition      Program execution      Output update
       |                       |                    |
       v                       v                    v
       A-----------------------B--------------------C
          Sensor changes here ^

If the sensor changes immediately after point A, the input image may still contain the previous value during that program execution.

The controller can acquire the new state during a subsequent update, subject to the actual I/O architecture and update timing.

Important timing terms

  • Input filtering: Suppresses short electrical transitions or noise according to the configured filter behavior.
  • Input update time: Time associated with updating the input data from the module or I/O system.
  • Scan time: Time associated with the controller's execution cycle in a cyclic execution model.
  • Response time: Time between the original physical event and the resulting system response.

These are different quantities. The total response time can include sensor response, input filtering, module processing, network update, program execution, output processing, and actuator response.

A PLC scan time of 10 ms does not automatically guarantee that every input change is detected and acted on within 10 ms.

8. Can a PLC miss a short input pulse?

Yes. A short pulse can be missed if it occurs entirely between relevant input acquisitions or is suppressed by input filtering.

For example, suppose an input pulse lasts 2 ms, while a conventional input image is refreshed every 10 ms. Depending on when the pulse occurs and how the input module processes it, the controller may never observe the active state.

This is a significant consideration for high-speed production equipment.

Common solutions

Requirement Possible solution
Detect short digital pulses High-speed input module or suitable pulse-capture feature
Count fast events High-speed counter
Measure encoder movement Dedicated encoder or motion interface
Capture a transition independently of the normal scan Hardware latch or supported event input
Improve detection of slow signals affected by noise Appropriate input filtering and electrical design

The correct solution depends on the signal duration, maximum event frequency, module specifications, and required response time.

Reducing the PLC scan time alone may not solve a problem if the input module's filtering or update behavior is the limiting factor.

9. Input read with remote I/O

When inputs come from a remote I/O station, the controller's available input data also depends on the remote communication architecture.

A simplified path is:

Field sensor
     |
     v
Remote input module
     |
     v
Remote I/O adapter
     |
     v
Industrial network
     |
     v
Controller input data
     |
     v
PLC program

The remote station may acquire and exchange I/O data according to its own update mechanism. The PLC then uses the data made available through the configured communication and controller architecture.

Consequently, a remote input can have additional timing and communication dependencies compared with a local input.

If a remote station loses communication, the controller may report a fault and the data may become invalid, stale, or behave according to the configured fault handling. Do not assume that a displayed input value is fresh merely because the tag still contains a Boolean value.

10. Input image behavior differs between PLC platforms

The input-image concept is fundamental, but its exact implementation is not identical across all controllers.

Platform or architecture Important consideration
Traditional cyclic PLC Often uses a process image acquired according to the scan or configured update model
Siemens S7 systems Process-image partitions and update behavior depend on CPU, task, and configuration
Rockwell ControlLogix I/O data is exchanged through configured module connections; task execution and I/O update behavior must be considered
Mitsubishi PLCs Input/output refresh behavior depends on PLC family, execution model, and parameters
Remote I/O systems Network and adapter update mechanisms affect when fresh data becomes available
Event-driven or high-speed interfaces May capture or process data outside the ordinary cyclic input-image pattern

For maintenance, always distinguish the general PLC concept from the behavior of the actual installed controller.

In particular, do not assume that every controller copies all physical inputs into one universal image table at the exact same point in every execution cycle.

11. Common input-read problems

Symptom Possible cause What to check
Physical sensor changes, but PLC input does not Wiring fault, sensor fault, wrong channel, module fault Sensor output, terminal voltage, module LED, channel configuration
Input LED changes, but program tag does not Wrong address, incorrect tag mapping, configuration issue Hardware configuration, tag reference, module data
Input changes appear delayed Input filtering, module update, network delay, scan timing Filter settings, update intervals, task execution, diagnostics
Short pulse is missed Pulse shorter than effective detection capability Input response specification, filter settings, high-speed input requirements
Input remains active after field signal disappears Stale data, fault behavior, incorrect wiring, module or mapping issue Actual terminal state, module status, communication health, configured behavior
Remote inputs become unavailable together Station power, adapter, network, or connection fault Remote station diagnostics, power, network link, controller fault information
PLC input appears active when the process condition is false Incorrect sensor adjustment, wiring issue, failed device, wrong mapping Physical condition, sensor behavior, wiring, channel identity

A disciplined investigation traces the signal from the field device through the module and controller data to the program. Replacing the CPU because one sensor value is wrong is not a diagnostic strategy. It is expensive guessing.

12. Input read versus program execution

These stages are connected, but they are not the same operation.

Input read Program execution
Acquires or updates input data Evaluates logic using available data
Makes field states available to the program Uses those states to calculate conditions and commands
Depends on I/O acquisition and update behavior Depends on the execution model and program structure
Example: CLAMP_CLOSED becomes TRUE in the input data Example: logic evaluates whether the clamp is allowed to proceed

Suppose the input image reports:

PART_PRESENT = TRUE
CLAMP_CLOSED = TRUE
AIR_PRESSURE_OK = TRUE

The input-read stage makes those values available. It does not itself decide whether to start welding or move a robot.

That decision belongs to the program logic and its required conditions.

13. Interview questions

Q1. What is an input image table?

It is a logical representation of acquired input states made available to the PLC program. In a traditional cyclic model, the controller updates this data during the input acquisition stage.

Q2. Why does a PLC use an input image?

It supports consistent access to acquired input states during logic execution and separates ordinary program evaluation from the electrical acquisition of field signals.

Q3. Does the PLC read the physical sensor every time an input instruction executes?

Not necessarily. In a traditional input-image model, the instruction reads the stored input data. Immediate I/O operations and other architectures can behave differently.

Q4. Can an input change be missed?

Yes. A pulse may be too short for the effective input acquisition interval or may be suppressed by filtering. Suitable high-speed hardware or event-capture features may be required.

Q5. Why might a remote input be delayed?

Remote input data may depend on the input module's processing, station update mechanism, network communication, and controller execution timing.

Q6. Does an active input tag prove that a machine condition is physically correct?

No. It shows the state represented by the controller's input data. Sensor failure, incorrect adjustment, wiring errors, or mapping errors can produce misleading information.

Q7. What is the difference between input read and program execution?

Input read acquires input data and makes it available. Program execution evaluates that data and calculates the resulting control decisions.

14. Practical study exercise

Choose a digital input from an approved machine I/O list, such as PART_PRESENT or CLAMP_CLOSED.

Record:

  1. Field device and physical function.
  2. PLC input module and channel.
  3. PLC address and symbolic tag.
  4. Expected electrical state when the device activates.
  5. How the input state appears in the controller's data.
  6. Which program logic uses the tag.
  7. Input filter and update settings, where applicable.
  8. Any diagnostic indication associated with the channel.

Then trace one ordinary sensor activation through the field device, input module, controller input data, and program logic. Do not force inputs or interfere with live production equipment.
