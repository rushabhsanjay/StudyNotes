1. Definition

In a PLC, a tag is a named variable used to represent a value, signal, state, command, or data item. An address identifies where the corresponding data is located or accessed within the PLC's memory or I/O system.

PLC programs can refer to data through symbolic names, absolute addresses, or a combination of both, depending on the controller and programming environment.

For example:

Symbolic tag:     Motor_Running
Absolute address: %I0.0

In a platform that supports this address format, %I0.0 may represent a digital input bit. The symbolic name Motor_Running gives the signal a meaningful identity in the program.

The exact address syntax and meaning depend on the PLC manufacturer and controller family.

2. What Is a Tag?

A tag is a named variable that represents a particular item of data.

Examples:

Motor_Start_Command
Motor_Running_Feedback
Part_Present
Pressure_Bar
Robot_Ready
Drive_Fault
Part_Count

Each tag normally has properties such as:

  • Name.
  • Data type.
  • Value.
  • Scope or accessibility.
  • Address or memory association, where applicable.
  • Documentation or description.
  • Access permissions or other platform-specific attributes.

For example:

Tag name Data type Example value Meaning
Motor_Start_Command BOOL TRUE Start command is active
Motor_Running_Feedback BOOL TRUE Running feedback is active
Pressure_Bar REAL 6.75 Pressure in bar
Part_Count DINT 125000 Accumulated production count
Drive_Fault_Code INT or DINT 12 Numeric fault code

The type must match the intended data and the requirements of the PLC instructions and connected systems.

3. What Is an Absolute Address?

An absolute address identifies data using a specific memory location, I/O location, or controller-defined address.

For example, in a Siemens S7 environment using conventional address notation:

%I0.0     Digital input bit
%Q0.0     Digital output bit
%M0.0     Marker or internal memory bit
%MW10     Memory word
%MD20     Memory double word

These are illustrative examples. Availability and exact meaning depend on the CPU, addressing configuration, and programming environment.

In a conventional address-based program, logic might refer directly to an input or output location.

%I0.0 AND %I0.1 -> %Q0.0

Conceptually, this means that output %Q0.0 is commanded when both input conditions are true. The notation above illustrates the logic relationship rather than a complete, executable PLC instruction.

3.1 Advantages of Absolute Addresses

  • Direct relationship to a known memory or I/O location.
  • Useful for understanding physical I/O mapping.
  • Can be convenient in small or legacy programs.
  • Helps during certain commissioning and troubleshooting tasks.
  • Often necessary when dealing with fixed memory layouts or external interfaces.

3.2 Limitations of Absolute Addresses

  • The address itself may not explain the signal's purpose.
  • Logic becomes harder to understand when many numeric addresses are used.
  • Hardware changes may require address updates.
  • Incorrect addresses can cause a program to read or write the wrong data.
  • Reused address patterns can make maintenance and fault tracing difficult.

Compare these expressions:

%I0.0 AND %I0.1 -> %Q0.0

and:

Part_Present AND Safety_Permissive -> Conveyor_Command

The second representation communicates the intended function more clearly. However, a descriptive tag name does not prove that the tag is correctly mapped to the physical device.

4. What Is a Symbolic Tag?

A symbolic tag is a variable accessed by its meaningful name rather than by directly writing its physical or memory address into the logic.

Example:

Part_Present : BOOL
Conveyor_Command : BOOL

The program refers to these names:

Conveyor_Command :=
    Part_Present AND Safety_Permissive;

The programming environment determines how the named variables are stored, accessed, or associated with hardware.

Symbolic tags may be:

  • Directly associated with physical I/O.
  • Internal variables without a physical address.
  • Members of a function block or program instance.
  • Elements of arrays or structures.
  • Communication-facing variables exposed to an HMI, robot, or SCADA system.

A symbolic tag does not necessarily correspond to a single physical terminal. It may represent an internal calculation or a value received over a network.

4.1 Advantages of Symbolic Tags

  • Improve program readability.
  • Make the purpose of data easier to understand.
  • Reduce dependence on numeric addresses throughout the logic.
  • Support reusable functions and structured programming.
  • Make documentation, online monitoring, and troubleshooting easier.
  • Help organize large programs into meaningful variables and data structures.

4.2 Limitations of Symbolic Tags

  • Poorly chosen names can still make logic confusing.
  • A tag may be incorrectly mapped to a physical signal.
  • Changes to a tag's data type or interface can affect dependent logic.
  • External systems may still require a defined address, data layout, or communication mapping.
  • Some legacy systems rely heavily on absolute addressing.

Symbolic programming improves clarity, but it does not eliminate the need to understand memory, I/O mapping, and communication interfaces.

5. Symbolic vs Absolute Addressing

Feature Symbolic tag Absolute address
Reference method Meaningful name Defined memory or I/O location
Example Part_Present %I0.0
Readability Usually high with good naming Depends on address documentation
Physical location visible in logic Not necessarily Often more directly visible
Hardware changes Can be easier if mapping is maintained May require address changes
Reusability Often easier with structured data and reusable blocks Depends on platform and program design
Typical use Modern structured PLC programming Direct I/O access, legacy logic, fixed layouts

The important distinction is not that one is always correct and the other is always wrong. The right choice depends on the PLC platform, application, and interface requirements.

A common engineering approach is to use symbolic names throughout application logic while maintaining a clear and verified mapping to physical I/O and external data.

6. Physical I/O, Memory, and Symbolic Names

Three concepts must remain separate.

6.1 Physical I/O

Physical I/O refers to signals connected to input and output hardware.

Examples:

  • Proximity sensor connected to a digital input.
  • Push button connected to a digital input.
  • Solenoid valve controlled by a digital output.
  • Analog transmitter connected to an analog input.

6.2 Internal Memory

Internal memory holds data used by the PLC program. Depending on the platform, it can include internal bits, words, variables, instance data, arrays, and structures.

Examples:

Cycle_Active
Part_Count
Pressure_Setpoint
Previous_Sensor_State

An internal variable may not have a fixed physical I/O address.

6.3 Symbolic Name

A symbolic name identifies the meaning of the data.

For example:

Physical input: Proximity sensor at a station
Symbolic tag:   Part_Present
Program use:    Part_Present AND Station_Ready

The symbolic tag is the program-facing name. The hardware configuration and mapping determine how the physical signal reaches the program.

Conceptually:

Physical sensor
      |
      v
Digital input module
      |
      v
PLC input data
      |
      v
Symbolic tag: Part_Present
      |
      v
PLC control logic
      |
      v
Symbolic tag: Conveyor_Command
      |
      v
PLC output data
      |
      v
Digital output module
      |
      v
Conveyor actuator interface

This is a conceptual signal path. Actual execution and I/O update timing depend on the controller architecture and configuration.

7. Addressing Across PLC Manufacturers

Addressing syntax is not universal. A format that is valid for one PLC family may be invalid or mean something different in another.

7.1 Siemens PLCs

Conventional Siemens addressing may use inputs, outputs, markers, data blocks, and symbolic variables.

Examples:

%I0.0
%Q0.0
%M0.0
%MW10
%DB1.DBX0.0

General interpretation:

  • %I: Input area.
  • %Q: Output area.
  • %M: Marker or internal memory area.
  • %MW: Marker word.
  • %DB1.DBX0.0: A bit in a specified data block, using conventional notation.

Exact accessibility depends on the CPU and project configuration. Modern TIA Portal projects can use symbolic access extensively, and optimized data blocks may not behave like traditional fixed-layout data blocks.

7.2 Rockwell Automation / Allen-Bradley

Logix-family controllers commonly use tag-based programming.

Examples:

Motor_Start
Motor_Running
Part_Count
Robot_Ready

Controller-scoped and program-scoped tags can be used, and tags can be associated with I/O modules through controller-defined structures and aliases.

A program may use a symbolic tag rather than directly addressing a fixed memory word as in some older PLC families.

Legacy Allen-Bradley platforms, such as certain PLC-5 and SLC 500 systems, use different addressing conventions, so do not assume that all Rockwell controllers use the same model.

7.3 Mitsubishi PLCs

Mitsubishi PLCs commonly use device identifiers such as:

X0       Input device
Y0       Output device
M0       Internal relay
D100     Data register

The exact device syntax and memory behavior depend on the PLC series and programming environment. Symbolic labels can provide meaningful names for these devices.

7.4 Comparison

Concept Siemens example Rockwell Logix example Mitsubishi example
Physical input %I0.0 Module input tag or alias X0
Physical output %Q0.0 Module output tag or alias Y0
Internal Boolean %M0.0 or symbolic variable Motor_Running M0 or symbolic label
Integer-like storage %MW10 or typed variable Typed controller/program tag D100 or typed label
Application-level reference Motor_Running Motor_Running Motor_Running

These are representative examples, not direct one-to-one equivalents. Memory widths, data typing, module mapping, and syntax must be verified for the specific controller.

8. Tag Scope: Where Can a Tag Be Used?

A tag's scope determines where it can be accessed.

Common arrangements include:

  • Global or controller-scoped: Accessible across the relevant program or controller.
  • Program-scoped: Accessible within a particular program or execution context.
  • Block or function-block scoped: Associated with a particular block or instance.
  • Local or temporary: Used within a limited execution context, where supported.

The names and exact rules differ by platform.

For example, a reusable motor-control block may have local variables for internal timing and state, while exposing interface variables for commands and feedback.

Motor_Control
    Inputs:
        Start_Request
        Stop_Request
        Fault_Input

    Outputs:
        Run_Command
        Running_Status
        Fault_Status

The block's internal variables should not automatically be exposed to every other part of the program. Clear interfaces reduce unintended dependencies and simplify testing.

9. Tag Naming Standards

A good tag name should communicate the signal's function without requiring the reader to decode an arbitrary number.

Examples:

Poor or unclear name Better name Reason
M1 Conveyor_Motor_Running Identifies equipment and purpose
B12 Station12_Part_Present Identifies location and condition
D100 Pressure_Setpoint Explains engineering meaning
Flag_7 Robot_Ready Explains the logical state
Value1 Pressure_Bar Communicates the measured quantity and unit

A practical naming standard should be consistent across PLC code, HMI screens, electrical drawings, maintenance documentation, and SCADA data.

Useful naming elements include:

  • Equipment or station identifier.
  • Device or function.
  • Signal purpose.
  • Direction or role when necessary.
  • Engineering unit for analog quantities.

For example:

FR1010_Robot1_Ready
FR1010_Conveyor_Run_Command
FR1010_Pressure_Bar
FR1010_Part_Count

These names are illustrative. Use the site's established naming standard where one exists.

Avoid creating excessively long names or inventing several competing naming conventions within the same project.

10. I/O Mapping and Tag Mapping

I/O mapping connects physical or communication data to meaningful application variables.

For example, a sensor may be wired to a particular digital input channel. The program can then reference that channel through a symbolic tag.

A well-organized design separates:

  1. Hardware configuration.
  2. Physical I/O mapping.
  3. Application logic.
  4. HMI and communication interfaces.

Conceptually:

Hardware channel
      |
      v
I/O mapping
      |
      v
Symbolic application tag
      |
      v
Control logic

This separation is useful during retrofits. If a sensor moves to another input channel, the hardware configuration and mapping may need to change, but the application logic can remain unchanged if the symbolic interface is preserved and the mapping is updated correctly.

However, this benefit depends on the software architecture. Direct-address references scattered throughout the program can make hardware changes more expensive.

11. Aliases and Indirect References

Some PLC platforms support aliases, references, pointers, or indirect addressing.

These mechanisms can allow one name to refer to another tag or allow a program to access data based on a variable index or reference.

11.1 Alias

An alias gives another name to an existing data item, where supported.

For example:

Physical input: Local:1:I.Data.0
Alias:          Part_Present

The exact syntax depends on the platform.

Aliases can improve readability, but they also create a dependency. If the underlying reference is wrong, the alias can expose the wrong signal under a convincing name.

11.2 Indirect Addressing

Indirect addressing uses a calculated index or reference to select data.

For example, a program might select one of several station values based on a station number.

Selected_Station = Station_Data[Station_Index]

This example uses array notation to illustrate the concept. The specific PLC language determines how indexing and bounds are handled.

Indirect addressing is useful for reusable logic, but it requires careful range checking. An invalid index can cause a fault, an invalid access, or platform-specific behavior.

12. PLC Tags and HMI, Robot, CNC, and SCADA Interfaces

A symbolic tag in the PLC does not automatically guarantee that another system can interpret it correctly.

When exchanging data between a PLC and an HMI, robot, CNC, SCADA platform, or database, verify:

  • Tag or variable name.
  • Data type and signedness.
  • Address or communication path.
  • Data width and layout.
  • Scaling and engineering units.
  • Read/write permissions.
  • Update rate and data freshness.
  • Connection and error status.
  • Whether the interface uses a symbolic name or a fixed offset.

For example, a PLC may store a production count as a DINT, while an external interface expects a 16-bit integer. A mismatch can produce truncated, invalid, or incorrectly interpreted values.

Similarly, a tag named Pressure_Bar may contain a raw analog count if the scaling logic is missing. The name alone does not validate the value.

14. Best Practices

  • Use meaningful symbolic names for application logic wherever the platform supports them.
  • Maintain a documented mapping between physical I/O and application tags.
  • Keep tag names consistent across PLC, HMI, robot, CNC, and SCADA documentation.
  • Match data types and memory layouts across interfaces.
  • Use aliases carefully and verify their underlying references.
  • Avoid unnecessary direct-address references scattered throughout large programs.
  • Document unavoidable absolute addresses, especially in legacy systems.
  • Separate hardware configuration from application logic when practical.
  • Check scope and access permissions when a tag cannot be referenced.
  • Validate indirect indices and memory references.
  • Use online monitoring and controller diagnostics to trace signals from physical devices through logic to outputs.
  • Never assume a descriptive tag name proves that the underlying signal is correctly wired or mapped.

15. Interview Questions and Answers

Q1. What is the difference between a tag and an address?

A tag is a named variable representing data. An address identifies a location or access point for data within a controller's memory or I/O system.

Q2. What is symbolic addressing?

Symbolic addressing uses meaningful variable names, such as Motor_Running, instead of requiring the programmer to reference the data through a numeric or device address throughout the logic.

Q3. What is absolute addressing?

Absolute addressing refers to data through a specific memory or I/O location, using the address syntax supported by the PLC.

Q4. Is symbolic addressing always better?

Symbolic names generally improve readability and maintainability. However, absolute addresses may be required for certain hardware mappings, legacy programs, or fixed interfaces. The best design depends on the platform and application.

Q5. Does every tag have a physical address?

No. A tag may represent internal memory, calculated data, block-instance data, an array element, or a communication value. Some platforms also abstract physical storage from the programmer.

Q6. What is I/O mapping?

I/O mapping connects hardware channels or communication data to meaningful application variables used by the control logic.

Q7. What is an alias tag?

Where supported, an alias provides another name for an existing data item or reference. It improves readability but must be mapped correctly.

Q8. Why can a symbolic tag still contain the wrong value?

The tag may be incorrectly mapped, incorrectly calculated, forced, simulated, or receiving stale or invalid communication data. Symbolic naming does not guarantee signal correctness.

Q9. Why does tag scope matter?

Scope determines where a variable can be accessed. Appropriate scope helps prevent unintended dependencies and keeps reusable program blocks organized.

Q10. What should be checked when an HMI displays the wrong PLC value?

Check the tag reference, address or communication path, data type, signedness, scaling, access configuration, and communication status.

16. Practical Exercises

Exercise 1: Identify Symbolic Tags and Addresses

Using a PLC project or simulator, identify:

  • Three physical input signals.
  • Three physical output signals.
  • Three internal variables.
  • Three symbolic tags.
  • Any absolute addresses associated with those tags.

Record the tag name, data type, physical or logical source, address if applicable, and purpose.

Exercise 2: Trace a Physical Input

Select a proximity sensor or push button.

Trace its signal through:

  1. The electrical drawing.
  2. The input module and channel.
  3. The PLC input data.
  4. The symbolic tag.
  5. The logic that uses the signal.
  6. The resulting status or output command.

Confirm the actual signal state through online monitoring, using approved procedures.

Exercise 3: Improve Tag Naming

Take five poorly named variables from a test project and replace them with descriptive names according to a consistent naming convention.

Verify that the changes do not break references, HMI connections, or external interfaces.

Exercise 4: Verify an HMI Interface

Choose one PLC value displayed on an HMI.

Compare the PLC tag's type, value, mapping, and units with the HMI configuration. Introduce a controlled test value in a simulator and verify that the HMI displays the expected result.

Exercise 5: Investigate a Mapping Error

In an offline test project, intentionally map a symbolic tag to the wrong simulated input. Observe the resulting behavior, identify the incorrect mapping, and restore the correct configuration.

Do not deliberately mis-map live production equipment.

17. Final Mental Model

  • Tag: What the data is called.
  • Data type: What kind of value the variable represents.
  • Address: Where or how the data is accessed.
  • I/O mapping: How a physical or communication signal becomes available to application logic.
  • Scope: Where the variable can be accessed.
  • Interface mapping: How another system reads or writes the value.

A maintainable PLC program uses clear symbolic names, verified I/O mappings, suitable data types, and documented interfaces. Absolute addresses remain important, but they should not become an unexplained maze of numbers.
