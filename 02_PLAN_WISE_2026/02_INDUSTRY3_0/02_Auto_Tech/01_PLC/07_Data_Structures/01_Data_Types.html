1. Definition

A PLC data type defines what kind of value a variable can store, how that value is represented, and which operations can be performed on it.

For example, a motor-running signal needs a Boolean value, a production counter needs an integer, and a pressure calculation may need a floating-point value.

The four fundamental PLC data types in this topic are:

  • BOOL: Boolean, representing TRUE or FALSE.
  • INT: Signed integer, representing whole numbers within a defined range.
  • DINT: Double-width signed integer on platforms using the common 32-bit definition.
  • REAL: Floating-point number, allowing fractional values.

Choosing the correct data type is essential for reliable control logic, mathematical calculations, communication, memory management, and troubleshooting.

2. What Is a Variable or Tag?

A variable is a named storage location used by a program. Many modern PLC environments call these variables tags.

Examples:

Motor_Running
Part_Count
Pressure_Bar
Drive_Fault_Code

Each variable has a data type that determines what it can represent.

Tag Data type Example value Purpose
Motor_Running BOOL TRUE Indicates running status
Part_Count INT 125 Stores a whole-number count
Total_Count DINT 250000 Stores a larger count
Pressure_Bar REAL 6.75 Stores a fractional pressure value

The names and values above are illustrative.

A tag name describes the purpose of the variable. The data type defines the kind of value it can store. These are separate properties.

3. BOOL: Boolean Data Type

3.1 Definition

A BOOL represents a logical state with two possible values:

  • TRUE
  • FALSE

A Boolean is commonly used for digital signals, commands, conditions, status indicators, and interlocks.

Examples:

Start_PB       : BOOL
Stop_PB        : BOOL
Safety_OK      : BOOL
Motor_Command  : BOOL
Drive_Fault    : BOOL
Robot_Ready    : BOOL

Exact declaration syntax depends on the PLC programming language.

3.2 Typical Applications

Application Example tag Meaning
Operator command Start_Request Start has been requested
Process feedback Part_Present A part is detected
Equipment status Motor_Running Running condition is indicated
Fault detection Drive_Fault Drive fault is active
Permissive Pressure_OK Pressure condition is acceptable
Sequence state Cycle_Complete The cycle-complete condition is true

3.3 Boolean Logic

Boolean tags are commonly combined using logical operations.

AND: All required conditions must be TRUE.

Motor_Command =
    Start_Request
    AND Safety_OK
    AND Permissive_OK
    AND NOT Drive_Fault

OR: At least one condition must be TRUE.

Alarm_Active =
    High_Pressure
    OR Low_Pressure
    OR Sensor_Fault

NOT: Reverses a Boolean state.

Drive_Healthy = NOT Drive_Fault

These expressions illustrate ordinary control logic. Actual machine designs must account for signal validity, stop behavior, and the required safety architecture.

3.4 Important Distinction: BOOL Is Not Necessarily a Physical Input

A Boolean tag can represent a physical input, a physical output, an internal condition, a calculated result, or a communication status.

For example:

DI_Part_Sensor       Physical input representation
Part_Present         Process status
Part_Detected_Once   Internal event state
HMI_Part_Indicator   HMI-facing status

All four could be Boolean values, but they serve different purposes.

A TRUE value does not automatically prove that the physical device is working correctly. A signal could be forced, simulated, stale, incorrectly mapped, or derived from other logic.

4. INT: Signed Integer

4.1 Definition

An INT commonly represents a 16-bit signed integer on PLC platforms using the standard 16-bit definition.

A signed integer can represent negative and positive whole numbers, including zero.

For a 16-bit two's-complement integer:

\[ -2^{15}\ \text{to}\ 2^{15}-1 \]

Therefore, the usual range is:

\[ -32768\ \text{to}\ 32767 \]

Always verify the data type definition for the specific PLC platform.

4.2 Typical Applications

  • Small production counts.
  • Integer setpoints.
  • Analog module raw values.
  • Step numbers.
  • Small signed offsets.
  • Parameters that do not require fractional precision.

Example:

Part_Count      : INT
Recipe_Number   : INT
Raw_Pressure    : INT
Position_Offset : INT

4.3 INT Limitations

An INT cannot represent every whole-number value.

Suppose:

Part_Count = 32767

If the program attempts to increment the value, the outcome depends on the PLC instruction and platform behavior. It may wrap, report an error, or behave according to the documented arithmetic rules.

Do not rely on overflow behavior for production counting.

For a counter that may exceed the supported INT range, select a suitable wider type, such as DINT, and validate the arithmetic.

4.4 INT Does Not Mean Physical Integer Units

An integer value can represent a raw analog count, a recipe number, a scaled quantity, or a code.

For example:

Raw_Pressure = 13824

This might be a raw analog value, not a pressure of 13824 bar.

The engineering meaning comes from the signal configuration and program logic, not from the data type alone.

5. DINT: Double-Width Integer

5.1 Definition

On PLC platforms using the common definition, DINT is a 32-bit signed integer.

Its typical range is:

\[ -2^{31}\ \text{to}\ 2^{31}-1 \]

That is:

\[ -2147483648\ \text{to}\ 2147483647 \]

A DINT supports a much larger integer range than a 16-bit INT.

5.2 Typical Applications

  • Large production counters.
  • Accumulated machine cycles.
  • Large integer calculations.
  • Fault codes requiring a wider integer range.
  • Sequence counters.
  • Integer values exchanged with other systems that expect a 32-bit signed representation.

Examples:

Total_Part_Count : DINT
Machine_Cycles   : DINT
Fault_Code       : DINT

5.3 Why Use DINT Instead of INT?

Consider a production line that produces 1,000 parts per shift over multiple years.

A 16-bit signed integer has a maximum of 32,767. A counter accumulating total production could exceed that value relatively quickly.

A 32-bit DINT supports a much larger positive count.

Property INT DINT
Common width 16 bits 32 bits
Typical signed range -32,768 to 32,767 -2,147,483,648 to 2,147,483,647
Suitable for Smaller integer values Larger integer values
Fractional values No No

A DINT does not store fractional values simply because it is wider. It remains an integer type.

5.4 DINT Is Not Unlimited

Even a DINT has a maximum and minimum value. If a calculation exceeds its supported range, overflow may occur.

For counters that must operate for long periods, consider:

  • Maximum expected count.
  • Increment frequency.
  • Reset and retention requirements.
  • Whether the PLC supports a wider integer type.
  • How the value is transmitted to HMI, SCADA, SQL, or another PLC.

Changing the PLC tag type alone is insufficient if a connected system still expects a narrower data representation.

6. REAL: Floating-Point Data Type

6.1 Definition

REAL commonly represents a 32-bit IEEE 754 floating-point number on PLC platforms using the standard REAL definition.

It supports fractional values and a much wider numerical range than ordinary 16-bit or 32-bit integers. However, its precision is finite.

Examples:

Pressure_Bar    : REAL
Temperature_C   : REAL
Speed_RPM       : REAL
Flow_Rate       : REAL
Position_mm     : REAL

Illustrative values:

Pressure_Bar  = 6.75
Temperature_C = 32.4
Speed_RPM     = 1475.5
Flow_Rate     = 12.25

6.2 Typical Applications

REAL is useful when a calculation requires fractional values, including:

  • Analog scaling.
  • Pressure and temperature calculations.
  • Speed and flow calculations.
  • PID control calculations.
  • Position and distance calculations.
  • Engineering-unit conversions.
  • Ratios, averages, and other mathematical operations.

6.3 REAL Does Not Store Every Decimal Exactly

A common misconception is that REAL stores every decimal value exactly.

Binary floating-point can represent many values only approximately. For example, some decimal fractions cannot be represented exactly in binary floating-point.

This means that a calculated result may appear as:

0.30000001

instead of exactly:

0.3

The exact displayed result depends on the calculation and platform.

For comparisons, avoid assuming that two independently calculated REAL values will always be bit-for-bit identical.

Instead of checking:

Measured_Value = Target_Value

a suitable application may check whether the difference is within a tolerance:

\[ |Measured-Target|\leq Tolerance \]

For example, a temperature control system may consider a measured temperature acceptable when it is within a defined tolerance of the target.

The tolerance must be chosen based on sensor accuracy, process requirements, and control design.

6.4 REAL Versus DINT

Property DINT REAL
Common width 32 bits 32 bits
Stores fractional values No Yes
Stores whole numbers Yes Yes, within its precision limits
Representation Signed integer Floating-point
Typical use Counts, IDs, integer calculations Analog values and fractional calculations
Exact integer representation Within its integer range Limited by floating-point precision

Although both commonly occupy 32 bits, DINT and REAL do not store data in the same numerical representation.

The bit pattern for a DINT value of 100 does not represent the REAL value 100.0 when simply reinterpreted as floating-point bits. A proper numerical conversion is required.

7. Comparing the Four Data Types

Feature BOOL INT DINT REAL
Meaning Logical state Signed integer Wider signed integer Floating-point
Common width 1 logical bit, storage implementation varies 16 bits 32 bits 32 bits
Fractional values No No No Yes
Negative values Not applicable Yes Yes Yes
Example TRUE 125 250000 6.75
Typical use Commands and states Small counts and raw values Large counts Analog engineering values

The BOOL storage size deserves special attention: a Boolean represents one logical bit, but a PLC may allocate or pack Boolean variables in larger memory units depending on the platform.

Likewise, the table describes common type definitions, not an unconditional guarantee for every PLC family.

8. Data Type Conversion

PLC programs often need to convert a value from one data type to another.

Examples include:

  • INT to REAL for analog scaling.
  • DINT to REAL for fractional calculations.
  • REAL to INT when an integer output is required.
  • INT to DINT when a wider integer range is needed.

8.1 INT to REAL

Suppose an analog input provides:

Raw_Pressure : INT = 13824

Converting it to REAL gives a floating-point value representing the same numerical quantity:

Raw_Pressure_REAL = 13824.0

The conversion changes the data representation, not the engineering meaning.

The value is still a raw analog count until the program scales it into pressure units.

8.2 INT to DINT

Converting an INT to DINT can provide a wider integer representation.

For example:

Part_Count_INT  = 1200
Part_Count_DINT = 1200

The numerical value remains the same, but the destination can represent a wider integer range.

8.3 REAL to INT

Suppose:

Pressure_Setpoint_REAL = 12.8

Converting this to INT may produce 12 or 13, depending on the conversion instruction's truncation or rounding behavior.

The exact result must be verified for the selected PLC instruction.

If the conversion is being used for a physical command, also validate the allowable range before converting.

8.4 Conversion Versus Reinterpretation

These operations are different:

  • Numerical conversion: Converts a value into another type while attempting to preserve its numerical meaning.
  • Bit reinterpretation: Treats the existing bits as a different data type without performing a numerical conversion.

For example, the binary representation of a DINT and a REAL is different. Reinterpreting the bits is not a substitute for converting the numerical value.

This distinction becomes important when diagnosing communication mappings, raw data buffers, and PLC-to-PLC interfaces.

9. Data Types in Analog Processing

Consider a pressure transmitter whose analog module provides a raw integer from 0 to 27648 for a configured engineering range of 0 to 10 bar. These values are illustrative and are not universal to all modules.

The program may use:

Raw_Pressure : INT
Pressure_Bar : REAL

The raw input represents an integer count. The engineering value can contain a fraction.

The linear scaling formula is:

\[ PressureBar=\frac{Raw}{27648}\times10 \]

For a raw value of 13824:

\[ PressureBar=\frac{13824}{27648}\times10=5.0 \]

A suitable implementation converts the raw value to a floating-point type before performing fractional arithmetic.

Conceptually:

Raw_Pressure_REAL := INT_TO_REAL(Raw_Pressure);

Pressure_Bar :=
    (Raw_Pressure_REAL / 27648.0) * 10.0;

The conversion syntax varies by PLC platform.

Important: The correct raw range depends on the analog module, configured signal range, data representation, and fault behavior. Always verify the hardware documentation.

10. Data Types and Arithmetic

Data types affect how mathematical operations are evaluated.

10.1 Integer Division

Suppose the program calculates:

13824 / 27648

If the operands are integers and the platform evaluates this as integer division, the fractional part may be discarded, resulting in 0.

If the result is then multiplied by 10, the final result may still be 0, rather than 5.0.

Using REAL operands avoids this particular integer-division problem.

10.2 Overflow

Suppose:

INT_Value = 30000

Adding 10000 exceeds the usual maximum value of a 16-bit signed INT.

The result is platform- and instruction-dependent. Do not rely on overflow to produce a useful count or fault condition.

10.3 Type Compatibility

A mathematical instruction may impose restrictions on operand types or perform implicit conversions according to the platform.

When a result is unexpected, check:

  • Source type.
  • Destination type.
  • Intermediate result type.
  • Whether integer or floating-point arithmetic is used.
  • Whether the destination can represent the result.
  • Whether conversion is implicit or explicit.

The displayed tag value alone does not reveal every detail of how the expression was evaluated.

11. Selecting the Correct Data Type

Use the required numerical range and representation to select the type.

Requirement Likely choice Reason
Motor command BOOL Two-state logical value
Part-present sensor BOOL Discrete status
Small recipe number INT or another suitable integer type Whole-number identifier
Large production count DINT or a wider supported integer Greater counting range
Raw analog input Often INT or another module-defined type Must match the module's data representation
Pressure in bar REAL Fractional engineering values
Temperature in °C REAL Fractional measurement values
Calculated average REAL Fractional result
Fault code Suitable integer type Must match the defined code range and interface

Do not select a type merely because it is familiar. Match the type to the signal, calculation, interface, and permitted range.

12. Common Data Type Faults

Symptom Likely cause Investigation
Fractional value disappears Integer destination or integer arithmetic Check the operand and destination types
Counter stops or behaves incorrectly near a limit Integer overflow Check maximum expected count and type range
REAL comparison fails unexpectedly Floating-point precision Use an appropriate tolerance where justified
Analog engineering value is wrong Incorrect conversion or scaling Check raw type, range, and formula
Negative values appear unexpected Signed/unsigned mismatch or conversion behavior Verify the types and documented conversion rules

13. Best Practices

  • Use BOOL for logical states, not as a substitute for an entire status model.
  • Use INT only when its numerical range is sufficient.
  • Use DINT for larger integer values when supported and appropriate.
  • Use REAL for fractional calculations and engineering values that require it.
  • Verify data types against hardware manuals and communication specifications.
  • Use explicit conversions when arithmetic behavior could otherwise be ambiguous.
  • Validate ranges before narrowing a value or converting between signed and unsigned types.
  • Avoid direct equality comparisons for independently calculated REAL values when a tolerance-based comparison is more appropriate.
  • Define what a tag represents, including units for engineering values.
  • Check data types at PLC-to-PLC, PLC-to-HMI, robot, CNC, and SCADA boundaries.
  • Test minimum, maximum, negative, fractional, and out-of-range values in a safe environment.

14. Interview Questions and Answers

Q1. What is a PLC data type?

A data type defines the kind of value a variable can represent, its representation and range, and the operations supported for that value.

Q2. What is the difference between INT and DINT?

INT is commonly a 16-bit signed integer, while DINT is commonly a 32-bit signed integer. DINT supports a much wider integer range.

Q3. Can INT store decimal values?

No. INT stores whole-number values. A suitable floating-point type such as REAL is commonly used for fractional calculations.

Q4. What is REAL used for?

REAL is commonly used for fractional numerical values, including analog engineering units, scaling, averages, and control calculations.

Q5. Why can two REAL values fail an exact equality comparison?

Floating-point values may contain small representation or calculation differences. A suitable tolerance-based comparison can be more appropriate.

Q6. Why convert INT to REAL before scaling?

To enable fractional arithmetic and prevent unintended loss of the fractional part through integer division.

Q7. What is integer overflow?

Overflow occurs when an arithmetic result exceeds the range that the selected integer type can represent. The resulting behavior depends on the PLC platform and instruction.

Q8. Are DINT and REAL interchangeable because both are commonly 32 bits?

No. They use different numerical representations. A numerical conversion is required when changing the data type.

Q9. Does converting a raw analog INT to REAL automatically produce engineering units?

No. Conversion changes the data type. Scaling is required to map the raw value into engineering units.

Q10. What should be checked when a PLC and HMI display different values?

Check the data type, signedness, scaling, communication mapping, and conversion behavior at the interface.

15. Practical Exercises

Complete these exercises using a PLC simulator or offline test project.

Exercise 1: BOOL Logic

Create Start_Request, Permissive_OK, Drive_Fault, and Run_Command as Boolean tags.

Implement and test the conditions that permit a run command. Verify the output for every relevant combination of inputs.

Exercise 2: INT and DINT Limits

Create an INT counter and a DINT counter.

Test values near their maximum limits in a simulator. Observe the controller's documented overflow behavior and determine which type is appropriate for the expected production count.

Exercise 3: REAL Scaling

Create an integer raw input and a REAL engineering value.

Use the illustrative raw range 0 to 27648 and engineering range 0 to 10 bar. Test the minimum, midpoint, maximum, and out-of-range values.

Exercise 4: Conversion and Precision

Convert a simulated REAL value such as 12.8 to an integer using the available conversion instruction.

Observe whether the operation truncates or rounds. Test a negative value and a value near the destination's limits.

Exercise 5: Interface Verification

Create simulated tags representing a PLC value sent to an HMI or another controller.

Verify that the receiving system uses the correct data type, numerical representation, and engineering units.

16. Final Mental Model

  • BOOL: Is the condition true or false?
  • INT: What whole-number value is stored within the INT range?
  • DINT: What larger whole-number value is stored?
  • REAL: What numerical value may include a fractional component?
  • Conversion: How is the numerical value represented in another data type?
  • Scaling: How is the raw numerical value mapped to engineering units?

A PLC value is only useful when its type, range, representation, and engineering meaning are understood together.
