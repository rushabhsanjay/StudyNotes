1. Definition

An array is a data structure that stores multiple elements of the same data type under one variable name. Each element is accessed using an index.

Instead of creating separate tags for every sensor, motor, station, or production value, an array allows related values to be organized into a single indexed collection.

For example, instead of declaring ten separate Boolean tags:

Sensor_1
Sensor_2
Sensor_3
Sensor_4
...
Sensor_10

a program can use an array:

Sensors[0]
Sensors[1]
Sensors[2]
...
Sensors[9]

The exact array declaration syntax and index conventions depend on the PLC platform.

Arrays are especially useful when a machine contains repeated equipment, multiple stations, similar sensors, production counters, or a series of analog values.

2. Why Are Arrays Needed?

Consider a robotic production line containing 20 stations, each with a part-present sensor.

Without an array, the program might contain:

Station01_PartPresent
Station02_PartPresent
Station03_PartPresent
Station04_PartPresent
...
Station20_PartPresent

With an array, the same information can be organized as:

Station_PartPresent[0]
Station_PartPresent[1]
Station_PartPresent[2]
...
Station_PartPresent[19]

The array contains 20 elements, each storing one Boolean value.

Benefits include:

  • Reduced repetitive variable declarations.
  • Consistent organization of related data.
  • Easier implementation of loops where supported.
  • Easier access to a selected station using an index.
  • Simplified reusable program logic.
  • More systematic handling of repeated equipment.

Arrays do not automatically make a program better. If the equipment has significantly different behaviors or interfaces, separate named tags or structured data may be more appropriate.

3. Array Structure

An array consists of three important properties:

  1. Array name: Identifies the collection.
  2. Element data type: Defines the type of every element.
  3. Index or subscript: Selects a particular element.

For example:

Station_Ready[5]

Here:

  • Station_Ready is the array name.
  • 5 is the index.
  • The selected element stores the value associated with that index.

If the array is Boolean, Station_Ready[5] contains either TRUE or FALSE.

Conceptually:

Array: Station_Ready

Index:       0       1       2       3       4
          +-------+-------+-------+-------+-------+
Value:    | FALSE | TRUE  | TRUE  | FALSE | TRUE  |
          +-------+-------+-------+-------+-------+

This example uses zero-based indexing. Some PLC environments support other index ranges, so the declared lower and upper bounds must be checked.

4. Declaring an Array

An array declaration defines how many elements exist and what type each element uses.

4.1 Boolean Array

Example concept:

Station_Ready : ARRAY[0..19] OF BOOL

This represents 20 Boolean elements, indexed from 0 through 19, in a language that supports this declaration syntax.

Typical uses:

  • Station ready states.
  • Sensor states.
  • Fault flags.
  • Robot status bits.
  • Interlock results.

4.2 Integer Array

Part_Count : ARRAY[0..19] OF DINT

This represents 20 integer counters, one per indexed element.

Typical uses:

  • Production count per station.
  • Reject count per machine.
  • Cycle count per robot.
  • Number of completed operations.

4.3 REAL Array

Pressure_Bar : ARRAY[0..7] OF REAL

This represents eight floating-point values.

Typical uses:

  • Pressure measurements from multiple points.
  • Temperature readings.
  • Analog process values.
  • Position or speed measurements.

These declarations illustrate common array concepts. Exact syntax, supported types, and storage rules vary by PLC programming language.

5. Array Indexing

An index identifies which element of an array is being accessed.

For an array declared as:

Station_Count : ARRAY[0..4] OF DINT

the valid indexes are 0, 1, 2, 3, and 4.

Examples:

Station_Count[0] := 100;
Station_Count[1] := 250;
Station_Count[2] := 175;

Each assignment changes a different element.

Index Value Meaning
0 100 Count for the first mapped station
1 250 Count for the second mapped station
2 175 Count for the third mapped station
3 0 Count for the fourth mapped station, if initialized
4 0 Count for the fifth mapped station, if initialized

The zero values in the table are illustrative. Actual initial values depend on the controller, declaration, startup behavior, and initialization logic.

5.1 Index Is Not Necessarily the Physical Station Number

An array index is a programming reference, not automatically a physical equipment number.

For example:

Station_Count[0]

might represent physical station 1, while:

Station_Count[1]

represents physical station 2.

A different project may use an index range that directly matches its station numbering.

Document the mapping clearly. Otherwise, an engineer may troubleshoot station 7 while accidentally monitoring array element 6.

6. Reading and Writing Array Elements

Array elements can be read and written just like individual variables.

Example:

Current_Count := Part_Count[3];
Part_Count[3] := Part_Count[3] + 1;

Conceptually, the first statement reads element 3. The second increments that element.

Whether this syntax is valid depends on the selected PLC language.

In industrial control logic, an array element might represent:

  • A specific station's count.
  • A sensor's state.
  • A robot's status.
  • A drive's measured speed.
  • A fault code from one of several machines.

The program must ensure that the selected index corresponds to the intended equipment.

7. Fixed Index vs Variable Index

There are two common ways to select an array element.

7.1 Fixed Index

A fixed index is specified directly.

Pressure_Bar[0]
Pressure_Bar[1]
Pressure_Bar[2]

This is useful when the logic explicitly addresses known elements.

7.2 Variable Index

A variable index is calculated or selected at runtime.

Selected_Pressure := Pressure_Bar[Station_Index];

If Station_Index is 2, the program reads Pressure_Bar[2].

Variable indexing is useful when one reusable section of logic must process different stations.

For example:

FOR i := 0 TO 7 DO
    Pressure_Check[i] := Pressure_Bar[i] <= Pressure_Limit[i];
END_FOR;

This is illustrative Structured Text. Loop syntax and execution limits vary by platform.

The program checks each pressure value against its corresponding limit.

Variable indexing and loops can reduce repetitive code, but they also introduce a critical requirement: the index must remain within the array's valid bounds.

8. Array Bounds and Invalid Indexes

An array has a defined range of valid indexes.

For example:

Station_Ready : ARRAY[0..19] OF BOOL

Valid indexes are:

0 through 19

Indexes -1 and 20 are outside the declared range.

An invalid index can cause a controller fault, an invalid access, an error indication, or other platform-specific behavior. Do not assume that every PLC handles an invalid index identically.

8.1 Why Invalid Indexes Occur

Common causes include:

  • An index variable is not initialized.
  • A station number is used directly even though the array starts at zero.
  • A loop's upper bound is incorrect.
  • An external value contains an unexpected station number.
  • A count is mistaken for the highest valid index.
  • A program changes the array size but not the related logic.

8.2 Defensive Index Validation

Before accessing an array using a variable index, verify that it is within the declared range.

Conceptually:

IF Station_Index >= 0 AND Station_Index <= 19 THEN
    Selected_Ready := Station_Ready[Station_Index];
ELSE
    Index_Error := TRUE;
END_IF;

The exact syntax and short-circuit evaluation behavior must be checked for the selected PLC language. Where evaluation order is uncertain, validate the index in a separate step before performing the array access.

A safe design also defines what should happen when the index is invalid. It might reject the request, raise a diagnostic, or use a documented fallback value.

9. Array Dimensions

Arrays can be one-dimensional or multidimensional.

9.1 One-Dimensional Array

A one-dimensional array is a simple list of elements.

Motor_Running[0..7]

It can represent eight motors.

Motor_Running[0]
Motor_Running[1]
Motor_Running[2]
...
Motor_Running[7]

9.2 Two-Dimensional Array

A two-dimensional array represents rows and columns.

For example:

Sensor_State[0..3, 0..7]

Conceptually, this might represent four machines, each with eight sensors.

                 Sensor index
              0   1   2   3   4   5   6   7
Machine 0    [ ] [ ] [ ] [ ] [ ] [ ] [ ] [ ]
Machine 1    [ ] [ ] [ ] [ ] [ ] [ ] [ ] [ ]
Machine 2    [ ] [ ] [ ] [ ] [ ] [ ] [ ] [ ]
Machine 3    [ ] [ ] [ ] [ ] [ ] [ ] [ ] [ ]

The program might access a specific element using two indexes, depending on the language's syntax.

Multidimensional arrays can organize regular data, but they can become difficult to maintain when each machine has a different configuration or number of sensors.

9.3 Higher-Dimensional Arrays

Some PLC environments support arrays with more than two dimensions. Their practical value depends on the controller and the application.

For many machine-control applications, a one-dimensional array or an array of structured records is easier to understand and maintain.

10. Arrays and Data Types

All elements of an ordinary typed array share the same element data type.

Array Element type Example value
Sensor_State[0..19] BOOL TRUE
Part_Count[0..19] DINT 12500
Pressure_Bar[0..7] REAL 6.75
Fault_Code[0..9] INT 12

If a collection contains several different kinds of information per machine, such as ready status, production count, pressure, and fault code, a user-defined structure may be a better fit than separate unrelated arrays.

That leads directly to the next topic, UDTs.

11. Arrays in Industrial Automation

11.1 Repeated Equipment

Suppose a production line has eight identical conveyor motors.

An array could hold the running feedback:

Conveyor_Running[0..7] : BOOL

It could also hold a command or fault state, although the precise control architecture should be designed around the equipment's safety and operating requirements.

11.2 Production Counters

A line might contain several stations with separate part counters.

Station_Part_Count[0..19] : DINT

A shared logic routine could increment the counter associated with a selected station.

The design must define when a part is counted, prevent duplicate counts, and handle counter retention and reset requirements.

11.3 Analog Measurements

A machine may have multiple pressure sensors.

Pressure_Bar[0..7] : REAL

The array can simplify monitoring and comparison, provided that each index is consistently mapped to the correct sensor.

11.4 Fault Tracking

A controller may store fault codes from several devices:

Drive_Fault_Code[0..11] : DINT

The type must be selected according to the fault-code range and the interface specification of the connected equipment.

An array stores the values; it does not automatically define fault severity, reset rules, or diagnostic meaning.

12. Arrays and Loops

Arrays are especially useful when the same operation must be performed on several related elements.

For example, a program might check eight temperature measurements against eight individual limits.

FOR i := 0 TO 7 DO
    Temperature_High[i] :=
        Temperature_C[i] > Temperature_Limit[i];
END_FOR;

This illustrates the principle of indexed processing.

Before using a loop in a PLC program, verify:

  • The supported loop syntax.
  • The number of iterations.
  • The maximum execution time.
  • The valid index range.
  • Whether the logic must execute every scan.
  • Whether processing all elements in one scan is acceptable.

A loop with too many operations can increase scan time. In time-critical control, the number and duration of iterations must be considered.

13. Arrays and PLC Scan Behavior

An array is a data organization mechanism. It does not inherently mean that all elements are updated simultaneously or that an entire array is processed atomically.

Actual behavior depends on the program and controller architecture.

For example, if a loop checks 100 elements, those operations consume execution time. If an array is populated by communication data while another task reads it, the program may also need to account for consistency and update timing.

Important questions include:

  • Who writes each array element?
  • Who reads it?
  • When is the data refreshed?
  • Can multiple tasks access the same data?
  • Can an element change during a multi-step calculation?
  • Does the platform provide mechanisms for consistent data transfer?

These concerns become more important when arrays contain large datasets or data received from another controller.

14. Arrays and Memory Usage

An array's memory requirements depend on its element type, number of elements, alignment, and the PLC's implementation.

For a simple estimate, multiply the number of elements by the storage size of one element.

For example, if a platform stores each DINT as 32 bits, an array of 100 DINT elements requires approximately:

\[ 100 \times 32 = 3200\text{ bits} \]

This equals 400 bytes before considering any platform-specific allocation or alignment overhead.

Similarly, 100 REAL elements commonly require 400 bytes when each REAL occupies 4 bytes.

Boolean arrays may be packed into bits or stored using a larger allocation unit, depending on the controller and data structure.

Memory use should be checked against the actual PLC's documentation, especially for large arrays and memory-constrained systems.

15. Common Array Mistakes

Mistake Possible result Prevention
Using an invalid index Fault or invalid data access Validate index bounds
Confusing station numbers with array indexes Wrong device selected Document the mapping
Using an unsuitable element type Overflow or loss of fractional values Select the type based on range and precision
Incorrect loop bounds Elements skipped or invalid accesses Match loop limits to array bounds
Forgetting initialization Unexpected startup values Define startup and initialization behavior
Using parallel arrays inconsistently Data from different devices becomes mismatched Use consistent indexing or structured records
Excessively large loop Increased scan time Measure execution time and limit iterations
Multiple uncontrolled writers Unexpected values or race-like behavior Define data ownership and execution order
Incorrect external mapping Values assigned to the wrong elements Verify communication mapping and index conventions

16. Best Practices

  • Use arrays for repeated items with a common data type and consistent meaning.
  • Give arrays meaningful names that describe the collection.
  • Document what each index represents, particularly when indexes map to physical stations or devices.
  • Validate variable indexes before accessing array elements.
  • Define initialization and retention behavior.
  • Select element types based on expected range and precision.
  • Use loops only when their execution time and behavior are understood.
  • Keep array dimensions manageable and meaningful.
  • Avoid maintaining several parallel arrays when a structure would better represent one complete device record.
  • Check PLC, HMI, robot, and SCADA indexing conventions carefully. Some systems use zero-based indexes while others expose different index ranges.
  • Test minimum and maximum indexes, invalid indexes, startup behavior, and counter limits in a simulator before commissioning.
  • Keep safety-critical functions within the appropriate validated safety architecture rather than assuming an ordinary array or Boolean tag provides safety protection.

17. Interview Questions and Answers

Q1. What is an array in a PLC?

An array is a collection of elements of the same data type accessed using indexes.

Q2. Why use an array instead of separate tags?

Arrays organize repeated data consistently, reduce repetitive declarations, and support indexed access and reusable processing logic.

Q3. What is an array index?

An index identifies a specific element within an array.

Q4. What is the difference between a fixed and a variable index?

A fixed index is explicitly specified in the program. A variable index is determined at runtime, allowing the program to select different elements dynamically.

Q5. What happens when an invalid index is used?

The behavior depends on the PLC platform and instruction. It may cause an error, invalid access, or controller fault. Index bounds should always be validated.

Q6. Can an array contain BOOL, INT, DINT, and REAL elements together?

A conventional typed array has one element type. If each record needs different field types, a structure or UDT is often more suitable.

Q7. What is a multidimensional array?

It is an array with more than one index dimension, such as rows and columns.

Q8. Do arrays automatically reduce scan time?

No. Arrays can reduce repetitive code, but processing their elements still consumes execution time. Loops and data access must be designed with scan-time requirements in mind.

Q9. How do arrays help with repeated equipment?

They allow similar values from multiple motors, sensors, stations, or drives to be stored and processed using consistent indexing.

Q10. When is a UDT preferable to an array?

A UDT is useful when several different data types describe one device or object, such as a motor's command, feedback, fault, and counter. An array is useful when multiple elements share a common type, and an array of UDTs can combine both approaches.

18. Practical Exercises

Exercise 1: Boolean Array

Create an array of eight Boolean elements to represent eight simulated sensors.

Change each element independently and verify that the selected index controls the intended sensor status.

Exercise 2: Production Counter Array

Create an array of eight DINT counters, one per simulated station.

Increment the selected station's counter and confirm that the other counters remain unchanged.

Exercise 3: Analog Array

Create an array of eight REAL values representing simulated pressure readings.

Compare each reading against its corresponding limit and generate an array of high-pressure status flags.

Exercise 4: Variable Index

Create a station-index variable that selects one element from an array.

Test the lowest valid index, highest valid index, and invalid indexes. Confirm that the program rejects invalid requests before accessing the array.

Exercise 5: Loop Execution

Write a loop that processes all elements of an array.

Verify that every intended element is processed and inspect the execution time using the tools supported by the PLC environment.

Exercise 6: Choose Between an Array and a UDT

Design a data model for ten motors.

First, represent motor-running feedback using an array of BOOL values. Then list the additional information required for each motor, such as start command, fault status, speed, and cycle count.

Determine whether separate arrays or an array of motor structures would make the application clearer and easier to maintain.

19. Final Mental Model

  • Array: A collection of similarly typed elements.
  • Index: Selects one element.
  • Element type: Defines what each element can store.
  • Array bounds: Define the valid indexes.
  • Variable indexing: Allows a program to select an element dynamically.
  • Loop: Processes multiple elements using repeated logic.
  • Array of structures: Organizes complete records for repeated devices.

Arrays are most useful when data repeats in a predictable pattern. The key engineering responsibility is to maintain correct indexing, bounds, data types, and device mapping.
