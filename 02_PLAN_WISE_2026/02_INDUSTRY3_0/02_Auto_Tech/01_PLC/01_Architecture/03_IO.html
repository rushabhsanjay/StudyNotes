1. Definition

Input/Output (I/O) is the interface between a PLC control system and the physical equipment it monitors or controls.

  • Inputs bring information from field devices into the PLC.
  • Outputs carry control commands from the PLC to field devices.
  • I/O modules electrically interface these signals with the PLC system.
  • I/O addressing identifies the particular input or output channel represented in the PLC program.

For example, a robot fixture may have a proximity sensor that detects whether a clamp is closed. The PLC reads this sensor through an input channel. When the program determines that the next operation is permitted, it can activate an output channel connected to a solenoid valve.

This is a simplified architecture. Local I/O modules communicate through the PLC rack or backplane, while remote I/O modules typically communicate through an industrial network.

The CPU does not normally connect directly to every sensor and actuator. I/O modules provide the required electrical interface and convert physical signals into data the control system can use.

3. Main types of PLC I/O

I/O type Full form Purpose Typical field devices
DI Digital Input Reads discrete ON/OFF signals Proximity sensor, limit switch, pushbutton
DO Digital Output Commands discrete ON/OFF actions Solenoid valve, relay, indicator lamp
AI Analog Input Reads continuously varying signals Pressure transmitter, temperature transmitter
AO Analog Output Sends continuously varying commands Speed reference, proportional valve command

Additional specialized modules include high-speed counters, encoder interfaces, thermocouple and RTD modules, load-cell modules, motion-control interfaces, and safety I/O.

These are not interchangeable with ordinary digital or analog modules. Their electrical interfaces, timing requirements, configuration, and diagnostic capabilities can differ substantially.

Example from an automotive manufacturing line

Field device I/O type Example function
Clamp-closed proximity sensor DI Confirms the clamp position
Start pushbutton DI Requests cycle initiation
Solenoid valve DO Commands pneumatic clamp movement
Stack light DO Indicates machine status
Pressure transmitter AI Measures pneumatic pressure
Variable-speed drive reference AO Commands a speed setpoint, if analog control is used

A device's physical function does not determine its I/O type by itself. For example, a drive can communicate its speed over a network instead of using an analog signal. In that case, the speed value is exchanged through communication data rather than a conventional analog channel.

4. Input modules: how field information reaches the CPU

An input module receives electrical signals from field devices and presents their states or measured values to the PLC.

For a digital input, the simplified path is:

Proximity sensor detects metal
          |
          v
Sensor output changes state
          |
          v
PLC input terminal receives signal
          |
          v
Input channel detects electrical state
          |
          v
PLC input data is updated
          |
          v
Program reads the input tag or address

Suppose a fixture has a sensor named CLAMP_CLOSED.

  • Sensor detects the closed position.
  • The sensor output changes to its active electrical state.
  • The input module recognizes the signal.
  • The corresponding PLC input data becomes active.
  • The PLC program can use that input in its sequence logic.

Important: An input being active means the PLC has received an active electrical state through the configured channel. It does not automatically prove that the mechanical device is physically in the expected condition. Incorrect sensor adjustment, wiring faults, or a failed sensor can produce misleading information.

Input modules may also provide input filtering, channel isolation, diagnostics, and configurable signal behavior. Exact capabilities depend on the module.

5. Output modules: how CPU commands reach the machine

An output module converts a PLC output command into an electrical output suitable for the connected load or interface.

For example:

PLC program commands CLAMP_SOLENOID = ON
                 |
                 v
PLC output data becomes active
                 |
                 v
Output module channel switches
                 |
                 v
Electrical signal reaches the field circuit
                 |
                 v
Solenoid coil energizes
                 |
                 v
Valve changes position
                 |
                 v
Pneumatic actuator moves

Every step can fail independently.

A PLC output tag being ON does not prove that the output terminal has the expected voltage, that the solenoid is energized, or that the actuator has moved.

The output circuit may have a blown fuse, missing field supply, disconnected wire, damaged coil, failed module channel, or a separate permissive preventing movement.

This distinction is especially important during breakdown troubleshooting.

6. Local I/O and remote I/O

Local I/O

Local I/O modules are installed in the PLC's local rack or supported local expansion arrangement.

PLC rack
+-----------------------------------+
| CPU | DI module | DO module | AI   |
+-----------------------------------+

The modules exchange data with the CPU through the rack or backplane.

Typical advantages:

  • Direct integration with the PLC hardware configuration.
  • No separate remote I/O network connection for each local module.
  • Convenient for equipment concentrated near the PLC panel.

Remote I/O

Remote I/O modules are installed away from the main PLC rack and communicate through an industrial network.

PLC CPU
   |
   | EtherNet/IP, PROFINET, or another network
   |
   v
Remote I/O adapter
   |
   +---- DI module
   +---- DO module
   +---- AI module
   +---- AO module

Common industrial networks include EtherNet/IP, PROFINET, and CC-Link IE, depending on the automation platform.

Remote I/O reduces the need to route every field signal back to one central panel. It can simplify wiring on large machines and production lines.

However, it introduces additional dependencies:

  • Network connectivity and configuration.
  • Remote adapter or head-station status.
  • Correct module configuration.
  • Connection health and update timing.
  • Power supply at the remote station.

A remote I/O fault can affect multiple channels even when the field sensors and actuators themselves are healthy.

7. Understanding I/O addressing

An I/O address identifies a particular input or output point within the PLC's addressing system.

Consider a digital input module with 16 channels. The individual channels may be numbered 0 through 15. The PLC needs a way to associate each channel with the correct program data.

There are three concepts to distinguish:

Concept Meaning Example
Physical location Where the module is installed Rack 0, slot 1
Channel/address Which I/O point is being referenced Input channel 3
Symbolic tag A meaningful name used in the program CLAMP_CLOSED

The exact address format depends on the PLC family, hardware configuration, and programming environment.

Rockwell ControlLogix example

An illustrative tag might be:

Local:1:I.Data.0

In a typical ControlLogix configuration, this refers to input data bit 0 associated with the local module in slot 1.

An illustrative output reference might be:

Local:2:O.Data.3

This refers to output data bit 3 associated with the local module in slot 2, assuming a compatible module and configured data format.

These are examples, not universal addresses. Module types, tag structures, and data formats can change the exact reference.

A symbolic tag such as CLAMP_CLOSED may be mapped to or used in place of the hardware reference, depending on the project design.

Siemens example

Typical Siemens address notation includes:

Address General meaning
%I0.0 Input bit 0 in input byte 0
%I0.1 Input bit 1 in input byte 0
%Q0.0 Output bit 0 in output byte 0
%IW64 Input word beginning at input byte 64
%QW64 Output word beginning at output byte 64

Here, I means input, Q means output, B commonly denotes a byte, and W denotes a word. Exact address allocation is determined by the configured hardware and CPU.

Mitsubishi example

Mitsubishi PLCs commonly use device notation such as:

  • X0: a digital input device.
  • Y0: a digital output device.

The actual device numbering and mapping depend on the PLC family, module arrangement, and parameter configuration.

Why addresses and tags both matter

Compare these two references:

%I0.0
CLAMP_CLOSED

The first is a hardware-oriented address. The second is a meaningful symbolic name.

The symbolic name tells a technician what the signal is intended to represent. The address helps identify the actual PLC data point.

A good project uses meaningful tags and maintains a reliable mapping between the program, hardware configuration, I/O list, and electrical drawings.

8. How hardware configuration determines addresses

The PLC project must describe the installed I/O hardware correctly. Depending on the platform, configuration can include:

  • CPU model and firmware compatibility.
  • Module type and catalog number.
  • Rack, chassis, slot, or remote station.
  • Input and output address allocation.
  • Number of channels and data format.
  • Voltage or current range.
  • Input filter settings.
  • Network connection parameters and update time.
  • Module-specific diagnostics and operating modes.

For example, replacing an eight-channel module with a different module type may change the address layout, supported data types, or configuration requirements.

Never assume that an I/O address remains correct after a module replacement or hardware modification. Verify the configured module and address mapping against the actual installation and approved documentation.

9. Digital and analog I/O: an important distinction

Digital I/O represents discrete states, often interpreted as ON and OFF. Analog I/O represents values that vary over a range.

A digital input may indicate whether a pressure switch has reached its threshold. An analog input may report the actual pressure measured by a transmitter.

For example:

  • Digital signal: PRESSURE_OK = TRUE
  • Analog signal: AIR_PRESSURE = 5.8 bar

An analog signal must generally be interpreted through scaling and engineering-unit conversion. Its raw PLC value is not necessarily the physical pressure or temperature.

The next study topic, 04_Digital_Analog_Modules, will examine the signal types, electrical ranges, and module characteristics in more detail.

10. Digital input electrical considerations

A digital input module must be compatible with the field device's electrical signal.

Common considerations include:

  • Rated input voltage, such as 24 V DC.
  • Input current and switching thresholds.
  • PNP or NPN sensor output compatibility.
  • Module common-terminal arrangement.
  • Input filtering and response time.
  • Electrical isolation and diagnostic features.
  • Correct field power supply and wiring.

For example, a common arrangement uses a PNP sensor with a compatible sinking input circuit. A different arrangement may use an NPN sensor and a compatible sourcing input circuit. The module's actual wiring requirements must be checked in its manufacturer's documentation.

Do not confuse these concepts:

  • NO/NC: describes the contact or sensor's normal switching arrangement.
  • PNP/NPN: describes the transistor output arrangement of a sensor.
  • Sourcing/sinking: describes how current is supplied or returned in a circuit.

These describe different properties of an electrical interface.

11. Digital output module types

Digital output modules are not all electrically equivalent.

Output type General characteristics Important checks
Relay Mechanical contacts; may switch supported AC or DC loads Contact rating, switching frequency, contact wear
Transistor Electronic switching, generally for DC loads Polarity, sourcing/sinking type, current and thermal limits
Triac Electronic switching for supported AC loads AC load compatibility, leakage current, minimum load

The correct type depends on the load and application. A module's nominal voltage rating alone is not sufficient to determine suitability.

For solenoids, contactors, and other inductive loads, check the required suppression arrangement and module specifications. Do not connect a load that exceeds the rated current or switching capability of the output channel.

In many industrial applications, a PLC output drives an interface relay, contactor coil, valve coil, or drive logic input rather than directly powering the machine's main load.

12. Analog I/O and scaling basics

Analog inputs may accept standard current or voltage signals, such as 4–20 mA or 0–10 V, when supported by the particular module.

Consider a pressure transmitter measuring 0–10 bar and producing a 4–20 mA signal.

Transmitter current Pressure represented
4 mA 0 bar
8 mA 2.5 bar
12 mA 5 bar
16 mA 7.5 bar
20 mA 10 bar

For a linear transmitter, pressure can be calculated from measured current using:

\[ P=\frac{I-4}{20-4}\times 10 \]

Where:

  • \(P\) is pressure in bar.
  • \(I\) is measured current in mA.
  • The transmitter range is 0–10 bar.

For \(I=12\text{ mA}\):

\[ P=\frac{12-4}{16}\times10=5\text{ bar} \]

In a real PLC, the module may return a raw digital count rather than a current value. The raw minimum and maximum must come from the module configuration and documentation. Do not assume every module uses the same numerical range.

The 4 mA lower endpoint is called a live zero. It allows a system to distinguish the valid lower endpoint from a zero-current condition, although fault detection depends on the transmitter, module, and configured diagnostics.

13. Troubleshooting I/O problems

Troubleshooting is faster when each layer is checked separately rather than replacing modules on the strength of a suspicious-looking LED.

Symptom Possible causes Checks
Sensor is active but PLC input is OFF Incorrect wiring, missing supply, wrong channel, address mismatch, faulty input channel Check sensor output, voltage at terminal, module LED, configured address
Input LED is ON but program tag is OFF Wrong address or tag mapping, hardware configuration mismatch, data-format issue Compare the hardware configuration, tag reference, and I/O list
PLC output tag is ON but output LED is OFF Incorrect output mapping, module fault, inhibited or unavailable module, connection issue Check module status, configured tag, diagnostics, and output data
Output LED is ON but actuator does not operate Missing field supply, blown fuse, wiring fault, failed coil, incorrect load or common connection Measure the approved circuit safely and check the load and supply
Analog value is zero or implausible Open loop, incorrect polarity, wrong range, missing transmitter supply, scaling error Check loop current, channel configuration, wiring, raw value, and scaling
Analog value is noisy Electrical interference, grounding or shielding issue, unstable sensor supply, poor termination Inspect cable routing, shield termination, signal quality, and module diagnostics
Several remote I/O points fail together Remote station power loss, network fault, adapter fault, configuration mismatch Check station power, network status, adapter diagnostics, and connection parameters

These are diagnostic possibilities, not guaranteed causes. Use the actual module's status indicators, fault codes, electrical measurements, and manufacturer's manual to narrow down the fault.

A useful troubleshooting sequence

  1. Identify the exact field device and its intended function.
  2. Confirm the I/O type and the correct module/channel.
  3. Compare the electrical drawing, I/O list, hardware configuration, and PLC tag.
  4. Check the field supply, wiring, terminal connections, and relevant module indicators.
  5. Inspect PLC diagnostics and the live input or output data.
  6. Trace the signal from field device to PLC, or from PLC output to actuator.
  7. Record the confirmed cause and corrective action.

For safety-related I/O or live machinery, follow the approved isolation and verification procedures. Do not force production outputs, bypass interlocks, or override safety functions as a troubleshooting shortcut.

14. Four documents that must agree

Document or system Main purpose
I/O list Maps field devices to signal types, tags, addresses, and channels
Electrical schematic Shows wiring, terminals, supplies, and circuit connections
PLC hardware configuration Defines the CPU, modules, channel configuration, and address mapping
PLC program Defines how input data is interpreted and how output commands are generated

If these disagree, troubleshooting becomes unnecessarily difficult. A correct program can still operate incorrectly if the hardware configuration or field wiring does not match the intended design.

For maintenance and retrofit work, changes should be reflected in all relevant documentation, not just the PLC program.

15. Practical example: a pneumatic clamp

Assume a station uses a proximity sensor to confirm that a clamp has closed, a solenoid valve to move the clamp, and a pressure transmitter to monitor air pressure.

Item Signal type Example tag Purpose
Clamp-closed sensor DI CLAMP_CLOSED Confirms the sensed clamp position
Clamp solenoid DO CLAMP_SOLENOID Commands valve operation
Air-pressure transmitter AI AIR_PRESSURE Provides measured pressure
Pressure-control command AO, if used PRESSURE_SETPOINT Commands a compatible proportional device

A simplified sequence might be:

Cycle request
     |
     v
Check required permissives
     |
     v
Command clamp solenoid
     |
     v
Wait for CLAMP_CLOSED
     |
     v
Verify required pressure
     |
     v
Permit the next sequence step

This is an illustrative sequence, not a complete safety or machine-control design. Real machinery may require additional position checks, timeouts, interlocks, and safety functions.

The important point is that the program's decision depends on the validity of its input information and the correct operation of its output circuits. If the clamp does not move, the fault may be in the sequence logic, I/O mapping, electrical circuit, valve, air supply, or mechanical system.

16. Common interview questions

Q1. What is the function of a PLC I/O module?

It interfaces field signals with the PLC system. Input modules acquire signals from field devices, while output modules deliver control signals to connected devices or interfaces.

Q2. What is the difference between an I/O address and a tag?

An address identifies a data location in the PLC's I/O system. A tag is a named program variable that identifies the signal or data by a meaningful name and may reference the hardware data.

Q3. What is the difference between local and remote I/O?

Local I/O is installed in the PLC's local rack or supported expansion arrangement. Remote I/O is installed elsewhere and exchanges data with the controller through a supported communication link.

Q4. If the output tag is ON, why might the actuator remain stationary?

The tag indicates the PLC's commanded data state, not guaranteed physical operation. The module, field supply, wiring, load, valve, air supply, or mechanical assembly may be faulty.

Q5. Why must the I/O configuration be checked after replacing a module?

The replacement may have different electrical characteristics, channel layout, data format, address mapping, or configuration requirements. The project must match the installed hardware.

Q6. Why is remote I/O communication status important?

The controller depends on the remote station's network connection and configuration to exchange I/O data. A communication or adapter fault may affect many points simultaneously.

Q7. Why should an I/O LED not be treated as conclusive proof of a healthy machine?

An LED indicates a particular electrical or module state. It does not independently verify the entire signal path, program interpretation, actuator response, or physical machine condition.

17. Practical study exercise

Choose one digital input, one digital output, and one analog signal from a machine's approved documentation. Record the following for each:

  • Field device name and function.
  • Signal type and electrical range.
  • PLC module model and location.
  • Channel number and PLC address.
  • Symbolic tag name.
  • Terminal number and wiring reference.
  • Expected field condition and PLC indication.
  • Program logic that uses the signal.
  • Relevant diagnostic indicators or fault codes.

Then compare the I/O list, electrical drawing, hardware configuration, and PLC program. Record any discrepancy without changing the live system.

This exercise develops the ability to trace a signal across the entire control system, which is much more useful during a breakdown than merely memorizing address formats.
