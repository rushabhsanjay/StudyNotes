1. Definition

Compare and math instructions allow a PLC to evaluate numerical values, perform calculations, and convert raw measurements into useful engineering values.

Bit logic works primarily with Boolean conditions such as TRUE and FALSE. Compare and math instructions work with numerical data such as integers, floating-point values, counts, temperatures, pressures, speeds, positions, and analog signals.

Common industrial applications include:

  • Checking whether a temperature exceeds a limit.
  • Comparing actual motor speed with the speed reference.
  • Calculating production totals.
  • Scaling analog input values into engineering units.
  • Calculating conveyor speed or process deviations.
  • Checking whether a measurement is within an acceptable range.
  • Generating alarms when values cross configured thresholds.

For example, a PLC might receive a raw analog input value from a pressure transmitter and convert it into a pressure measurement in bar. It can then compare the calculated pressure against a configured limit.

2. Comparison instructions

Comparison instructions evaluate a relationship between two or more numerical values and produce a Boolean result.

Common comparison operations include:

Operation Meaning Example
= Equal to ActualSpeed = TargetSpeed
<> Not equal to MachineState <> 0
> Greater than Temperature > 80
< Less than Pressure < 5
>= Greater than or equal to Count >= 100
<= Less than or equal to Speed <= MaximumSpeed

Instruction names and symbols vary by PLC platform. For example, a platform may use instructions such as EQU, NEQ, GRT, LES, GEQ, and LEQ.

2.1 Equal to

An equality comparison evaluates TRUE when the two values are equal according to the data type and comparison rules.

Example:

ActualPosition = TargetPosition

This can be useful when comparing integer states or exact digital values.

However, comparing floating-point values for exact equality can be unreliable when calculations introduce small rounding differences.

For example, a calculated value might be 9.999999 instead of exactly 10.0.

For analog values, a tolerance comparison is often more appropriate.

2.2 Not equal to

The not-equal comparison evaluates TRUE when two values differ.

Example:

MachineState <> 0

This may indicate that the machine is in any state other than state zero.

It does not necessarily indicate a fault. The meaning depends on the application and the state definitions.

2.3 Greater than and less than

These instructions are commonly used for limit monitoring.

Examples:

Temperature > 80
Pressure < 5
ActualSpeed >= MinimumSpeed
ProductionCount >= TargetCount

Suppose a machine should raise a high-temperature alarm when its measured temperature exceeds 80°C.

Conceptually:

Temperature > 80
        |
        v
HighTemperatureAlarm = TRUE

If the comparison is strictly > 80, a value of exactly 80 does not satisfy the condition. If the requirement is to alarm at 80°C or higher, use >= 80.

That single symbol can decide whether an alarm activates at the specified limit or one increment later. Industrial equipment has little appreciation for mathematical ambiguity.

3. Comparison truth table

Consider the comparison A > B.

A B Result
10 5 TRUE
5 5 FALSE
3 5 FALSE

Now consider A >= B.

A B Result
10 5 TRUE
5 5 TRUE
3 5 FALSE

The difference is whether equality is accepted.

When implementing process limits, decide whether the threshold is inclusive or exclusive based on the actual requirement.

4. Range checking

A range check determines whether a numerical value falls between a lower and upper limit.

For example, a pressure measurement may be acceptable between 4 and 6 bar.

The Boolean condition is:

\[ Pressure \geq 4 \land Pressure \leq 6 \]
Pressure Within range?
3.5 bar No
4.0 bar Yes
5.0 bar Yes
6.0 bar Yes
6.5 bar No

A conceptual PLC expression is:

Pressure >= 4.0 AND Pressure <= 6.0

4.1 Inside-range and outside-range conditions

Inside range:

Pressure >= LowLimit AND Pressure <= HighLimit

Outside range:

Pressure < LowLimit OR Pressure > HighLimit

These conditions are logical opposites when the limits are valid and the values are comparable.

Range checking is useful for:

  • Pressure monitoring.
  • Temperature limits.
  • Position tolerance.
  • Robot-axis position verification.
  • Analog signal plausibility checks.
  • Product dimensional inspection.

Always check whether the application requires inclusive or exclusive boundaries.

5. Floating-point tolerance

Industrial calculations often use floating-point data types such as REAL or LREAL.

These types can represent fractional values, but many decimal fractions cannot be represented exactly in binary floating-point arithmetic.

Therefore, this comparison can be problematic:

MeasuredValue = 10.0

If MeasuredValue is the result of several calculations, it may be very close to 10.0 without being exactly equal.

A tolerance-based comparison is often better.

For example:

\[ |MeasuredValue-TargetValue|\leq Tolerance \]

Suppose:

  • Target value = 10.0 mm.
  • Permitted tolerance = 0.1 mm.
  • Measured value = 10.04 mm.

Then:

\[ |10.04-10.0|=0.04 \]

Since \(0.04 \leq 0.1\), the measurement is within tolerance.

This approach is useful for calculated values and measurements. The tolerance must come from the process or measurement specification, not an arbitrary number chosen because the program happens to work.

6. Addition and basic math instructions

Math instructions perform arithmetic operations on numerical values.

Common operations include:

Operation Mathematical symbol Example
Addition \(+\) Total = A + B
Subtraction \(-\) Difference = A - B
Multiplication \(\times\) Power = Voltage * Current
Division \(/\) Average = Total / Count
Absolute value \(\|x\|\) Deviation = ABS(Actual - Target)
Minimum MIN Select the smaller value
Maximum MAX Select the larger value
Limit or clamp LIMIT or equivalent Restrict a value to a defined range

Exact instruction availability and syntax depend on the PLC platform.

6.1 Addition

Addition combines two or more numerical values.

Example:

TotalParts = GoodParts + RejectedParts

If:

  • Good parts = 950.
  • Rejected parts = 50.

Then:

\[ TotalParts=950+50=1000 \]

This is useful for production reporting and batch monitoring.

6.2 Subtraction

Subtraction calculates the difference between values.

Example:

SpeedDeviation = TargetSpeed - ActualSpeed

If the target speed is 1500 rpm and actual speed is 1450 rpm:

\[ SpeedDeviation=1500-1450=50\text{ rpm} \]

A positive result means the actual speed is below the target in this particular definition. If the subtraction order is reversed, the sign also reverses.

Always define the meaning of the calculated difference.

6.3 Multiplication

Multiplication is used for scaling, unit conversion, and process calculations.

Example: calculate total production time for a batch when each cycle has a known duration.

\[ TotalTime=CycleTime\times NumberOfCycles \]

If a cycle takes 12 seconds and 100 cycles are planned:

\[ TotalTime=12\times100=1200\text{ s} \]

This equals 20 minutes, excluding delays and other process effects.

6.4 Division

Division is used for averages, ratios, and unit conversions.

Example:

\[ AverageCycleTime=\frac{TotalCycleTime}{CompletedCycles} \]

If total cycle time is 1200 seconds across 100 cycles:

\[ AverageCycleTime=\frac{1200}{100}=12\text{ s} \]

Important: protect against division by zero.

Conceptual logic:

IF CompletedCycles > 0 THEN
    AverageCycleTime := TotalCycleTime / CompletedCycles;
ELSE
    AverageCycleTime := 0;
END_IF;

This is Structured Text-style pseudocode. Actual syntax and numeric behavior depend on the target PLC.

Also consider integer division. If both operands are integers, some platforms return an integer result, discarding the fractional part. Use an appropriate floating-point data type when fractional precision is required.

7. Data types and numerical limits

A math instruction's result depends on the data types of its inputs and output.

Common PLC numeric types include:

Data type Typical purpose Important consideration
BOOL TRUE/FALSE conditions Not a general-purpose numeric measurement type
INT Integer values Limited numerical range
DINT Larger integer values Still has a finite range
UINT / UDINT Unsigned integers Cannot represent negative values
REAL Floating-point values Approximate fractional representation
LREAL Higher-precision floating-point values on supported platforms More precision, but still finite

Exact sizes and ranges depend on the PLC platform and data type definition.

Common arithmetic problems

  • Overflow: the result exceeds the data type's representable range.
  • Underflow: a result becomes too small for the supported representation, particularly with floating-point values.
  • Truncation: fractional information is discarded during a conversion or integer operation.
  • Division by zero: the divisor is zero, causing an invalid operation or platform-specific behavior.
  • Type mismatch: an operation uses incompatible types or implicit conversions that do not produce the intended result.
  • Precision loss: a calculated floating-point value differs slightly from the mathematically exact result.

For industrial calculations, check the input type, result type, permitted range, units, and conversion rules.

8. Analog scaling

Scaling converts a raw input value into a useful engineering value.

Analog input modules may deliver a raw integer representing an electrical measurement such as 4 to 20 mA or 0 to 10 V.

The PLC program may need to convert that raw value into:

  • Pressure in bar.
  • Temperature in °C.
  • Flow in litres per minute.
  • Speed in rpm.
  • Position in millimetres.
  • Level in percentage.

The raw range depends on the specific module, configuration, and signal type. Never assume a universal raw range across all PLCs.

8.1 Linear scaling formula

For a linear relationship:

\[ EU=EU\_{\min}+ \frac{Raw-Raw\_{\min}}{Raw\_{\max}-Raw\_{\min}} (EU\_{\max}-EU\_{\min}) \]

Where:

  • \(Raw\) = measured raw input value.
  • \(Raw\_{\min}\) = configured raw value at the lower endpoint.
  • \(Raw\_{\max}\) = configured raw value at the upper endpoint.
  • \(EU\_{\min}\) = engineering value at the lower endpoint.
  • \(EU\_{\max}\) = engineering value at the upper endpoint.
  • \(EU\) = calculated engineering value.

8.2 Worked example: pressure transmitter

Assume a configured analog input range of 0 to 27648 represents a pressure range of 0 to 10 bar.

These are illustrative configured endpoints, not universal module specifications.

Given:

  • Raw input = 13824.
  • Raw minimum = 0.
  • Raw maximum = 27648.
  • Engineering minimum = 0 bar.
  • Engineering maximum = 10 bar.

Substitute into the formula:

\[ EU=0+\frac{13824-0}{27648-0}(10-0) \]
\[ EU=0.5\times10=5\text{ bar} \]

Therefore, the calculated pressure is 5 bar.

8.3 Example: a non-zero lower endpoint

Assume a transmitter's configured raw endpoints correspond to 4 mA and 20 mA, and the process range is 0 to 100 bar.

If the raw value is exactly halfway between the configured endpoints, the scaled pressure is:

\[ Pressure=0+\frac{1}{2}(100-0)=50\text{ bar} \]

For a 4 to 20 mA signal, 4 mA normally represents the configured lower endpoint, not zero current. The PLC module may also provide diagnostics for under-range or over-range conditions.

Scaling must use the actual module configuration and transmitter range.

9. Scaling in a PLC program

A conceptual Structured Text implementation is:

IF RawMax > RawMin THEN
    ScaledValue :=
        EU_Min
        + (REAL(RawValue) - RawMin)
        / (RawMax - RawMin)
        * (EU_Max - EU_Min);
ELSE
    ScalingFault := TRUE;
END_IF;

This is conceptual pseudocode. Conversion syntax and data types must be adapted to the target PLC.

The key requirement is that the denominator must not be zero.

Also ensure the arithmetic is performed using suitable numeric types. If integer division occurs before conversion to floating point, the fractional result may already have been lost.

10. Clamping and limiting calculated values

Scaling may produce values outside the intended engineering range if the raw input falls outside its configured endpoints.

For example, a pressure input might scale to 10.5 bar even though the nominal range ends at 10 bar.

There are two separate decisions:

  1. Measurement validity: Is the raw signal valid, or does it indicate a fault or out-of-range condition?
  2. Value limiting: Should a calculated value be restricted to a permitted range for a particular control operation?

A clamp operation can restrict a value mathematically:

\[ LimitedValue=\min(\max(Value,Minimum),Maximum) \]

For example, restricting a control reference to 0 through 100:

Input value Limited value
-10 0
25 25
100 100
120 100

Do not automatically clamp every invalid sensor measurement to the nearest limit. Doing so can hide a transmitter fault or make a failed sensor appear to report a valid process condition.

For measurement scaling, retain appropriate diagnostic information. For control references, limiting may be appropriate if specified by the control design.

11. Scaling, comparison, and alarm generation together

These instructions are commonly combined.

Consider a pressure monitoring application:

Analog input
     |
     v
Raw pressure value
     |
     v
Scale raw value into bar
     |
     v
Check signal validity
     |
     v
Compare pressure with limits
     |
     +------ Pressure > HighLimit
     |                |
     |                v
     |          High alarm
     |
     +------ Pressure < LowLimit
                      |
                      v
                 Low alarm

A good implementation separates the following concerns:

  • Raw input acquisition.
  • Scaling and unit conversion.
  • Signal validity checks.
  • Process comparisons.
  • Alarm handling.
  • Control response.

This makes troubleshooting easier because an incorrect displayed pressure can be traced to the raw signal, scaling formula, data type, or alarm logic rather than treated as one mysterious PLC failure.

13. Troubleshooting compare and math instructions

Symptom Possible cause What to check
Alarm activates at the wrong value Incorrect comparison operator or limit Check > versus >= and the configured threshold
Equality comparison never becomes TRUE Floating-point precision differences Use a justified tolerance comparison
Calculated value is unexpectedly zero Integer division or incorrect input values Check operand types and live values
Math result becomes negative unexpectedly Incorrect operand order or signedness Inspect the formula and data types
Calculated value exceeds the permitted range Raw input outside range or missing limiting logic Check input diagnostics and intended control limits
Scaled value is incorrect Wrong raw endpoints, engineering endpoints, or units Verify module configuration and transmitter range
Scaling produces invalid results Raw maximum equals raw minimum Validate the denominator and configuration
Value changes in large steps Integer arithmetic, truncation, or input resolution Check data types and analog module resolution
Alarm flickers near a threshold Measurement noise or no hysteresis Consider filtering or separate ON/OFF thresholds
Counter total or average is incorrect Overflow, wrong units, or incorrect arithmetic Check operand ranges, conversion, and calculation order

Hysteresis for unstable thresholds

A value near an alarm threshold can fluctuate between TRUE and FALSE because of measurement noise.

For example, if a temperature alarm activates above 80°C and clears immediately below 80°C, a measurement fluctuating around 80°C can make the alarm flicker.

Hysteresis uses different activation and clearing thresholds.

Example:

  • Activate the alarm at 80°C or above.
  • Clear it only when temperature falls below 77°C.

This creates a 3°C hysteresis band.

Hysteresis should be implemented according to the alarm or control requirements, not added indiscriminately. Some applications require separate latching and acknowledgement behavior.

14. Best practices

  • Define the engineering units for every numerical tag.
  • Verify data types before performing arithmetic.
  • Use floating-point calculations where fractional precision is required.
  • Guard against division by zero and invalid scaling configurations.
  • Check whether comparisons should be inclusive or exclusive.
  • Use tolerance comparisons for calculated floating-point values when appropriate.
  • Confirm analog module endpoints and transmitter configuration before scaling.
  • Distinguish out-of-range measurement faults from values that merely need limiting.
  • Document the reason for every process limit.
  • Use hysteresis where justified to prevent unstable switching.
  • Check overflow, signedness, and conversion behavior.
  • Separate scaling, validation, comparison, and alarm logic where practical.

15. Interview questions and answers

Q1. What is a comparison instruction?

It compares numerical values and produces a Boolean result indicating whether the specified relationship is true.

Q2. What is the difference between > and >=?

> excludes equality. >= includes equality.

Q3. Why can exact floating-point equality be unreliable?

Floating-point values may contain small representation and rounding differences. A tolerance-based comparison is often more appropriate for calculated measurements.

Q4. What is scaling in a PLC?

Scaling converts a raw signal value into an engineering value, such as converting an analog input count into pressure in bar.

Q5. Why is division by zero important in scaling?

The scaling denominator includes the difference between raw endpoints. If those endpoints are equal, the calculation is invalid.

Q6. Why can integer division cause incorrect results?

Some PLC implementations discard fractional portions when dividing integers. Use suitable operand and result types when fractional precision is required.

Q7. What is hysteresis?

Hysteresis uses different activation and deactivation thresholds to prevent unstable switching when a value fluctuates near a limit.

Q8. What is the difference between scaling and limiting?

Scaling converts a value from one range into another. Limiting restricts a value to a permitted range.

Q9. Why should a scaled measurement have validity checks?

An out-of-range or faulty signal may produce a plausible-looking number. Validity checks help distinguish a genuine process measurement from a sensor or configuration problem.

Q10. What should be checked when an alarm activates at the wrong value?

Check the raw measurement, scaling, engineering units, comparison operator, configured threshold, data type, and any filtering or hysteresis.

16. Practical exercise

Build an offline training program for a pressure transmitter and production counter.

Required tags:

  • RawPressure
  • ScaledPressure
  • PressureLowLimit
  • PressureHighLimit
  • PressureLowAlarm
  • PressureHighAlarm
  • GoodParts
  • RejectedParts
  • TotalParts
  • TargetParts
  • BatchComplete

Perform these exercises:

  1. Scale a simulated raw input into a 0 to 10 bar engineering range.
  2. Raise a high alarm when pressure is greater than or equal to 8 bar.
  3. Raise a low alarm when pressure is below 2 bar.
  4. Calculate total production using addition.
  5. Calculate the difference between target production and actual production.
  6. Check batch completion using a greater-than-or-equal comparison.
  7. Test floating-point comparisons using a tolerance.
  8. Test an invalid scaling configuration where the raw endpoints are equal.
  9. Simulate a measurement fluctuating around an alarm threshold and implement suitable hysteresis.
  10. Test minimum, maximum, below-range, and above-range inputs.

Record the raw value, scaled value, units, comparison results, calculated values, and alarm states for each test.

17. Final mental model

  • Compare: Determines whether numerical conditions are satisfied.
  • Add: Combines numerical values.
  • Subtract: Calculates differences and deviations.
  • Multiply and divide: Perform arithmetic and ratio calculations.
  • Scale: Converts raw measurements into engineering units.
  • Limit: Restricts a value to an allowed range.
  • Tolerance: Defines an acceptable deviation from a target.
  • Hysteresis: Prevents unstable switching near a threshold.
  • Data types: Determine numerical range, precision, and calculation behavior.

The practical troubleshooting order is to verify the raw input, confirm the data type and units, validate the calculation, and then inspect the comparison or alarm condition.
