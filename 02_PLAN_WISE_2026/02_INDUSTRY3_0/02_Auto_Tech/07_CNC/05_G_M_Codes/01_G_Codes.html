01_G_Codes - G-codes: Motion and mode commands

1. Definition of G-codes

G-codes are CNC programming commands used primarily to define tool movement, machining geometry, coordinate interpretation and operating modes.

They tell the CNC controller how to interpret and execute a machining program. The controller then coordinates the axes, spindle and other machine functions as required.

Typical applications include:

  • Rapid positioning.
  • Linear and circular interpolation.
  • Absolute and incremental positioning.
  • Plane selection.
  • Unit selection.
  • Work coordinate selection.
  • Cutter compensation.
  • Tool-length compensation.
  • Canned machining cycles.
  • Coordinate transformations and advanced motion functions.

G-codes do not directly describe every physical action in the machine. They define instructions that the CNC interpreter processes, subject to active modes, machine configuration, interlocks and controller-specific behaviour.

For example, a command specifying a target X coordinate does not mean that the X-axis will necessarily move immediately. The controller must interpret the block, check the active modes and machine conditions, and generate the required motion.

2. G-codes versus M-codes

Feature G-codes M-codes
Primary purpose Motion, geometry and modal operating conditions Machine functions and auxiliary operations
Common examples G00, G01, G02, G03, G90, G91 M03, M04, M05, M06, M30
Typical functions Positioning, interpolation, coordinate modes Spindle control, tool change, program stop and end
Execution Interpreted by the CNC system Often handled through CNC logic and machine-builder interfaces
Standardization Many common conventions exist, but details vary Many functions are configurable or machine-specific

The distinction is useful, but not absolute. A CNC controller may implement some functions differently, and certain codes may be manufacturer-specific.

For example, M06 commonly requests a tool change, but the actual tool-changing sequence depends on the machine's PLC logic, ATC hardware and interlocks.

3. How a CNC controller processes G-codes

A simplified execution path is:

CNC program
     |
     v
Read and interpret program block
     |
     v
Apply active modal settings
     |
     v
Resolve coordinates, offsets and compensation
     |
     v
Calculate the commanded path
     |
     v
Interpolator generates coordinated motion
     |
     v
Servo systems move the axes
     |
     v
Feedback and machine status are monitored

The CNC controller must interpret the current block together with the modes already active from earlier blocks.

This is important because many G-codes are modal. A modal command remains active until another command replaces it or the controller's rules cancel it.

4. Modal and non-modal G-codes

4.1 Modal commands

A modal G-code establishes a state that remains active across subsequent program blocks.

Examples commonly include:

  • G00: Rapid positioning mode.
  • G01: Linear interpolation mode.
  • G17: XY plane selection.
  • G21: Metric units.
  • G90: Absolute programming mode.
  • G91: Incremental programming mode.

The exact modal groups and cancellation behaviour depend on the controller.

4.2 Non-modal commands

A non-modal command applies to a particular block or operation rather than establishing a continuing mode in the same way.

G04, commonly used for dwell, is a typical example. The programmed dwell duration and syntax vary by controller.

4.3 Why modal states matter

Consider this illustrative sequence:

G21
G90
G01 X50.0 F300
X80.0
Y40.0

Conceptually, on a controller using these conventions:

  • G21 selects metric units.
  • G90 selects absolute programming.
  • G01 selects linear feed movement.
  • The next block moves to X = 80.0 while the linear interpolation mode remains active.
  • The following block moves to Y = 40.0 while the applicable modal states remain active.

The exact path, starting point and result depend on the machine's current position, coordinate system, offsets and other active modes.

The practical lesson: a line containing only X80.0 is not necessarily an incomplete command. The CNC may inherit its movement mode from an earlier block.

5. G00: Rapid positioning

G00 commonly commands rapid positioning to a specified target.

Example:

G00 X100.0 Y50.0

This requests positioning to the programmed X and Y coordinates under the active coordinate and unit settings.

Typical uses:

  • Moving the tool toward the next machining location.
  • Retracting the tool away from a cut.
  • Positioning before a drilling or milling operation.
  • Moving between machining features without cutting.

Important characteristics

  • Rapid movement uses the machine's configured rapid-motion behaviour.
  • The path is not necessarily a straight line at constant vector speed. Axis coordination and trajectory behaviour depend on the CNC controller.
  • Actual motion may be limited by axis velocity, acceleration, machine configuration and interlocks.
  • Rapid positioning is not intended to define an ordinary cutting feed rate.

Safety point: A rapid command can produce very fast movement. The tool, fixture, workpiece and machine travel envelope must be considered when validating a program.

6. G01: Linear interpolation

G01 commands linear interpolation between the current programmed position and the target position, typically using a programmed feed rate.

Example:

G01 X100.0 Y50.0 F500

Assuming the usual metric feed-per-minute convention, this requests a linear path to X = 100.0 and Y = 50.0 at a programmed feed rate of 500 mm/min.

Typical applications:

  • Straight-line milling.
  • Facing and turning movements.
  • Drilling approaches and retracts where programmed.
  • Chamfering and linear contouring.

Feed-rate interpretation

The meaning of F500 depends on the active feed mode and controller.

Common interpretations include:

  • Feed per minute.
  • Feed per revolution.
  • Other controller-supported feed modes.

For milling, feed per minute is commonly used. For turning, feed per revolution is often useful because it relates tool feed to spindle rotation.

Do not interpret an F value without checking the active feed mode and units.

7. G02 and G03: Circular interpolation

G02 and G03 commonly command clockwise and counterclockwise circular interpolation, respectively, in the selected machining plane.

Code Common meaning
G02 Clockwise circular interpolation
G03 Counterclockwise circular interpolation

Typical applications:

  • Circular pockets.
  • Arcs and curved contours.
  • Boring paths.
  • Rounded profiles.
  • Circular transitions between machining features.

7.1 Plane selection

The selected plane affects how the CNC interprets the arc.

Code Common plane
G17 XY plane
G18 XZ plane
G19 YZ plane

These are widely used conventions, although controller-specific details must still be checked.

7.2 Defining the arc

Depending on the controller, circular interpolation may be defined using:

  • A radius value, commonly represented by R.
  • Arc-centre offsets, commonly represented by I, J and K.
  • Other controller-supported formats.

The relevant parameters depend on the selected plane and programming convention.

An invalid radius, inconsistent endpoint or incorrect centre specification may result in a program alarm or an unintended path.

7.3 Direction is plane-dependent

Clockwise and counterclockwise interpretation must be considered from the controller's defined viewing direction for the selected plane.

Do not determine the intended physical direction merely by looking at the screen from an arbitrary viewing angle.

8. G04: Dwell

G04 commonly introduces a programmed pause or dwell.

A dwell may be used to:

  • Allow a process to stabilize.
  • Maintain a tool position briefly.
  • Support certain machining operations.
  • Coordinate timing with machine functions where the controller permits it.

The dwell parameter and units vary by controller. Some use seconds, while others support alternative formats or settings.

A dwell does not automatically prove that a spindle has reached the required speed, that a tool is clamped or that a machine function is complete. When sequencing matters, use the appropriate machine status or completion logic.

9. G20 and G21: Inch and metric units

These codes commonly select the programming units.

Code Common meaning
G20 Inch programming
G21 Metric programming, usually millimetres

For example, a coordinate of X25.0 means 25 millimetres under the relevant metric configuration, but 25 inches under inch programming.

That is not a minor difference. It is a very effective way to turn a normal machining operation into a spectacularly expensive lesson.

Before running a program, verify:

  • Active unit mode.
  • Coordinate values.
  • Feed-rate units.
  • Tool and work offsets.
  • Controller-specific unit handling.

Do not assume that every stored parameter, tool measurement or external device value automatically changes units in the same way as programmed coordinates.

10. G90 and G91: Absolute and incremental positioning

These codes determine how programmed coordinates are interpreted on many CNC controllers.

10.1 Absolute positioning: G90

Under absolute programming, coordinates are interpreted relative to the active coordinate origin.

Example:

G90
G01 X100.0 F300

The requested X coordinate is 100.0 in the active coordinate system, assuming the applicable unit and coordinate settings.

10.2 Incremental positioning: G91

Under incremental programming, the programmed coordinate value represents a movement increment from the relevant current position.

Example:

G91
G01 X10.0 F300

This requests a 10-unit incremental movement in X, under the active units and other applicable settings.

10.3 Comparison

Feature G90 G91
Interpretation Absolute target Incremental movement
Reference Active coordinate origin Relevant current position
Repeated identical X value Targets the same absolute coordinate Requests the same increment each time
Common uses Part coordinates and defined target positions Repeated steps and incremental movements

10.4 Practical risk

If a program assumes absolute mode but incremental mode is active, the resulting movement can differ substantially from the intended path.

The reverse error is equally important.

Always establish and verify the intended coordinate mode before interpreting the program's axis commands.

11. G17, G18 and G19: Plane selection

Plane selection determines the plane used for certain operations, particularly circular interpolation.

Code Selected plane Common axes defining the plane
G17 XY X and Y
G18 XZ X and Z
G19 YZ Y and Z

For example, a circular movement programmed in the XY plane uses X and Y as the principal arc coordinates. In the XZ plane, the corresponding arc is defined in X and Z.

Plane selection is especially important when interpreting arcs on milling machines, turning centres and machines with multiple controlled axes.

Do not assume that the selected plane automatically determines every rotary-axis or tool-orientation behaviour. Those functions depend on the controller and machine kinematics.

12. G54 to G59: Work coordinate systems

Many CNC controllers provide work coordinate systems such as G54, G55, G56, G57, G58 and G59.

These codes commonly select stored work offsets.

A work offset defines the relationship between the programmed workpiece origin and the machine coordinate system.

Example concept:

Machine coordinate system
          |
          v
Selected work offset, e.g. G54
          |
          v
Programmed part coordinates
          |
          v
Tool movement in the machine

Why work offsets matter

A correct machining program can produce the wrong physical result if the work offset is incorrect.

For example:

  • The part is loaded in a different position.
  • The wrong work offset is selected.
  • The stored offset was changed.
  • The workpiece reference was measured incorrectly.
  • The fixture was replaced or repositioned.

The CNC may execute the programmed coordinates correctly relative to the selected offset while the tool moves to the wrong location relative to the actual part.

Maintenance distinction: Machine reference, work offset and tool offset are different concepts. Verifying one does not validate the others.

13. G28 and G53: Reference movement and machine coordinates

These commands require particular care because their behaviour depends on the controller and the configured machine.

13.1 G28

On many controllers, G28 commands a return toward a predefined reference position, often through an intermediate point.

The precise motion and interpretation depend on the controller, active coordinate mode and machine configuration.

A programmed intermediate coordinate may matter. Incorrect assumptions about the active coordinate mode can result in unexpected movement.

13.2 G53

On many controllers, G53 specifies movement in the machine coordinate system for the relevant block, rather than using the active work coordinate system in the usual way.

Its modal behaviour and supported usage depend on the controller.

13.3 Practical distinction

Concept Purpose
Reference return or homing Establishes or verifies the machine reference
G28 Commonly requests a configured reference-position movement
G53 Commonly specifies movement using machine coordinates
G54 and related offsets Select a work coordinate system

These functions are not interchangeable.

A machine-coordinate move can be entirely valid and still be unsafe if the destination is inappropriate for the current tool, fixture or machine state.

Never execute an unfamiliar reference or machine-coordinate command on a production machine without validating its exact controller-specific behaviour and travel path.

14. G43 and G49: Tool-length compensation

Tool-length compensation accounts for differences in tool length relative to the machine's configured reference.

14.1 G43

G43 commonly activates positive tool-length compensation, often with an H offset identifier on milling controllers.

Illustrative syntax:

G43 H01

This indicates a common method of activating tool-length compensation using the specified offset number. The exact syntax and required axis words depend on the controller.

14.2 G49

G49 commonly cancels tool-length compensation on controllers that support this convention.

14.3 Why it matters

Different tools have different lengths. Without correct compensation, the actual cutting tip may not be at the intended programmed position.

Tool-length errors can cause:

  • Incorrect cutting depth.
  • Incorrect Z positioning.
  • Tool or workpiece collision.
  • Damage to fixtures.
  • Tool breakage.

Tool offsets must be measured, entered and verified according to the machine's procedure. The active compensation mode should be checked before running an unfamiliar program.

15. G40, G41 and G42: Cutter-radius compensation

Cutter compensation adjusts the programmed path to account for the cutter's radius.

Code Common meaning
G40 Cancel cutter-radius compensation
G41 Cutter compensation to the left of the programmed path
G42 Cutter compensation to the right of the programmed path

The left/right interpretation depends on the programmed direction of travel and the controller's conventions.

15.1 Why cutter compensation is needed

The programmer may define the intended component contour rather than the exact path followed by the centre of the cutter.

The CNC uses the configured cutter radius or offset data to calculate the required tool-centre path.

15.2 Common problems

  • Incorrect cutter-radius value.
  • Wrong offset number.
  • Incorrect compensation direction.
  • Invalid entry or exit geometry.
  • Insufficient clearance.
  • Compensation state carried over unexpectedly.

Incorrect compensation can cause dimensional errors or collisions.

The actual compensation rules, lead-in requirements and permissible geometry must be checked in the controller documentation.

16. G94 and G95: Feed-rate modes

These codes commonly select how the feed rate is interpreted.

Code Common meaning
G94 Feed per minute
G95 Feed per revolution

16.1 Feed per minute

Under feed-per-minute mode, the programmed feed is expressed as distance per minute, using the active units.

For example, a feed of 300 mm/min describes the intended linear feed rate in metric programming.

16.2 Feed per revolution

Under feed-per-revolution mode, the programmed feed is expressed as distance per spindle revolution.

For turning, this can help maintain a consistent feed per workpiece revolution as spindle speed changes, provided the controller and operating mode support the intended behaviour.

16.3 Practical example

If feed per revolution is 0.2 mm/rev and the spindle operates at 1,000 RPM, the ideal corresponding feed per minute is:

\[ F=0.2\times1000=200\text{ mm/min} \]

If spindle speed doubles to 2,000 RPM, the corresponding ideal feed per minute becomes 400 mm/min.

The controller's actual behaviour depends on the active feed mode, spindle feedback, configured limits and machining conditions.

17. Canned cycles: G81 and related codes

Canned cycles are predefined machining sequences that reduce repetitive programming.

A drilling cycle, for example, may coordinate approach, feed movement, retraction and return behaviour according to the controller's cycle definition.

Common examples on many milling controllers include:

Code Common use
G81 Basic drilling cycle
G82 Drilling cycle with dwell
G83 Peck-drilling cycle
G84 Tapping cycle
G80 Cancel canned cycle

Availability, syntax, axis behaviour and cycle details vary by controller and machine configuration.

17.1 Basic drilling cycle

A drilling cycle may specify a target depth, retract level and feed rate.

The CNC then executes the configured drilling sequence rather than requiring every movement to be programmed as a separate block.

17.2 Peck drilling

Peck drilling divides a drilling operation into multiple increments, with retraction or chip-clearing behaviour defined by the cycle.

It is useful for suitable deep-hole operations, but the correct cycle and parameters depend on tool type, material, hole geometry, coolant and machine capability.

17.3 Tapping

Tapping cycles coordinate spindle rotation and axial feed so that the tool can cut or form a thread.

The controller may require spindle synchronization, a suitable tapping mode and other specific conditions. Some machines use rigid tapping; others use a floating holder or another arrangement.

17.4 Cycle cancellation

A canned cycle may remain active across multiple blocks until it is cancelled or replaced according to the controller's rules.

Programmers must verify cycle state and the meaning of subsequent blocks. Otherwise, a coordinate block intended for ordinary movement may be interpreted as part of the active cycle.

18. G-code modal groups and state management

CNC controllers organize many modal G-codes into groups. Typically, only one code from a particular modal group can be active at a time, although exact grouping and exceptions are controller-specific.

Examples of commonly exclusive modes include:

  • Rapid positioning versus linear feed interpolation.
  • Absolute versus incremental positioning.
  • Different selected machining planes.
  • Different unit modes.
  • Different feed-rate modes.

18.1 Why modal groups matter

Suppose a program contains G01 and later G00. On a typical controller, the motion mode changes from linear feed interpolation to rapid positioning.

A subsequent coordinate block may inherit the newly selected mode.

This means the same axis coordinates can produce different movement behaviour depending on the active modal state.

18.2 Modal-state review

Before running a program, identify the active states for:

  1. Units.
  2. Coordinate mode.
  3. Motion mode.
  4. Selected plane.
  5. Work coordinate system.
  6. Tool-length compensation.
  7. Cutter compensation.
  8. Feed mode.
  9. Canned cycle state.
  10. Spindle mode and relevant machine functions.

Not every controller uses identical groups or startup states. Use the controller manual and the machine's approved program format.

19. Program structure and G-code blocks

A CNC program is made of blocks. Each block may contain a sequence number, preparatory functions, axis words, feed or speed commands, auxiliary functions and comments.

Illustrative block:

N120 G01 X80.0 Y40.0 F250

Conceptually:

  • N120: Block or sequence number.
  • G01: Linear feed interpolation.
  • X80.0 Y40.0: Target coordinates.
  • F250: Programmed feed value, interpreted according to the active feed mode and units.

A block can contain more than one function, but the controller determines how those functions interact and whether the combination is permitted.

19.1 Program startup

A program may establish units, coordinate mode, plane, work offset, compensation state and other initial conditions before machining begins.

Many controllers support a startup block that places the machine in a known set of modal states.

However, a generic startup block should not be copied blindly between machines. Unsupported codes, different machine options or different safety requirements can make a familiar block inappropriate.

19.2 Program end

Program-end and program-stop functions are often handled by M-codes, such as M30 on many controllers. These functions are distinct from the G-code motion and mode commands covered here.

20. Controller dialects and machine-specific differences

G-code is widely standardized, but real CNC implementations are not identical.

Differences can include:

  • Supported G-codes.
  • Modal groups.
  • Arc definition and tolerance.
  • Coordinate transformations.
  • Canned-cycle parameters.
  • Tool compensation behaviour.
  • Feed-rate modes.
  • Reference-position movement.
  • Rotary-axis behaviour.
  • Macro and custom-cycle functions.

A code that is valid on one controller may be unsupported or have different details on another.

Common CNC control families include Fanuc, Siemens SINUMERIK, Mitsubishi, Haas and other manufacturer-specific systems. Their programming manuals define the authoritative syntax and behaviour for each implementation.

Practical rule: Treat standard G-code meanings as a starting point. Confirm the exact implementation before editing or executing a program on a real machine.

21. Common G-code mistakes and their symptoms

Mistake Possible consequence What to verify
Wrong units Incorrect travel or dimensions G20/G21 and programmed values
Wrong absolute/incremental mode Unexpected target or repeated movement G90/G91 and current position
Wrong motion mode Rapid movement instead of feed movement, or vice versa G00/G01 and inherited modal state
Wrong work offset Entire path shifted relative to the workpiece Selected work coordinate and offset measurement
Wrong plane Incorrect arc interpretation G17/G18/G19
Incorrect arc geometry Program alarm or incorrect contour Endpoint, radius, centre offsets and active plane
Incorrect tool-length compensation Wrong tool-tip position or depth Active G43/G49 state and tool data
Incorrect cutter compensation Dimensional error or collision G40/G41/G42 and radius data
Wrong feed mode Unexpected cutting feed G94/G95 and feed units

Unsupported code Program alarm or ignored function, depending on controller Controller programming manual

22. Practical G-code troubleshooting workflow

When a CNC program alarms or produces unexpected movement, use the following sequence.

Step 1: Identify the exact block

Record the program line, alarm number, alarm text and the machine state when the alarm occurred.

Do not assume the line displaying the alarm is always the original cause. A preceding modal command or missing condition may have created the problem.

Step 2: Check the active modal states

Review the active motion mode, units, coordinate mode, plane, feed mode, work offset and compensation settings.

Step 3: Verify coordinate interpretation

Check the programmed coordinates against the intended part origin, machine position, work offset and tool data.

Determine whether the command is absolute or incremental.

Step 4: Check geometry and motion constraints

For linear and circular movements, verify the target coordinates, arc definition, selected plane, axis travel limits and machine working envelope.

Step 5: Check the controller-specific syntax

Confirm that the code and its parameters are supported by the exact CNC control and software configuration.

Step 6: Validate safely

Use the machine's approved program-validation process, such as simulation, graphics, dry run or another supported verification mode.

Where the machine's procedure permits, use appropriate reduced-risk settings and maintain all required safeguards. These modes do not eliminate collision risk.

Step 7: Document the correction

Record the original block, active modes, confirmed cause, correction and validation result.

Do not make several unrelated program changes simultaneously. Otherwise, determining which change actually solved the problem becomes unnecessarily difficult.

23. CNC G-code interview questions and answers

Q1. What is a G-code?

A CNC programming command used primarily for motion, geometry and modal operating conditions.

Q2. What is the difference between G-code and M-code?

G-codes commonly define motion and operating modes. M-codes commonly request auxiliary machine functions such as spindle control, tool changes and program stops.

Q3. What is the difference between G00 and G01?

G00 commonly commands rapid positioning. G01 commonly commands linear interpolation at the programmed feed rate.

Q4. What is the difference between G02 and G03?

They commonly command clockwise and counterclockwise circular interpolation, respectively, in the selected plane.

Q5. What is a modal G-code?

A command that establishes a state which remains active until changed or cancelled according to the controller's rules.

Q6. What is the difference between G90 and G91?

G90 commonly selects absolute positioning, while G91 commonly selects incremental positioning.

Q7. What is the purpose of G17, G18 and G19?

They commonly select the XY, XZ and YZ machining planes.

Q8. What is the purpose of G20 and G21?

They commonly select inch and metric programming units, respectively.

Q9. What is the purpose of G54?

It commonly selects a stored work coordinate system.

Q10. What is the difference between G28 and G53?

G28 commonly requests a configured reference-position movement. G53 commonly specifies movement using machine coordinates for the relevant block. Their exact behaviour depends on the controller.

Q11. What is tool-length compensation?

It accounts for the tool's length relative to the configured machine and programming reference.

Q12. What is cutter-radius compensation?

It adjusts the programmed tool path to account for cutter radius, using the configured compensation data and direction.

Q13. What is the difference between G94 and G95?

They commonly select feed per minute and feed per revolution, respectively.

Q14. What is a canned cycle?

A predefined machining sequence, such as drilling or tapping, that reduces the need to program every individual movement.

Q15. Why can a coordinate-only block still move the machine?

The block may inherit an active modal motion command from an earlier block.

Q16. Why can the same coordinate produce different physical movements?

The result can differ because of units, absolute or incremental mode, work offsets, tool compensation, active transformations and machine configuration.

Q17. Why should G-code not be transferred blindly between different CNC controllers?

Controllers can differ in supported codes, syntax, modal groups, compensation, canned cycles and machine-specific behaviour.

Q18. What should be checked first when a program generates unexpected movement?

The active modal states, units, coordinate mode, work offset, compensation data and exact controller-specific interpretation of the relevant blocks.

24. Practical exercises

Exercise 1: Interpret modal movement

Given a program containing G21, G90, G01, followed by several blocks containing only axis coordinates, explain how the active modes affect each movement.

Exercise 2: Absolute versus incremental positioning

Starting from X = 20 mm, compare the intended result of an absolute command to X = 50 mm with an incremental command of X = 50 mm.

Exercise 3: Arc interpretation

Explain how changing the selected plane from G17 to G18 affects the interpretation of a circular interpolation command. Identify the additional geometry and controller details that must be verified.

Exercise 4: Work-offset error

A program runs without a syntax alarm, but the machined feature is displaced from the expected location. Develop a diagnostic sequence that checks the work offset, tool compensation, reference state and actual part location.

Exercise 5: Feed-mode error

A lathe program produces an unexpected feed rate. Determine how the active feed mode, spindle speed, programmed F value and controller configuration could explain the result.

Exercise 6: Build a G-code reference sheet

Create a table containing the code, common meaning, modal or non-modal status where applicable, required parameters, controller-specific cautions and typical failure symptoms.

25. Final mental model

G-code program
      |
      v
CNC interprets commands and active modes
      |
      v
Coordinates and offsets are resolved
      |
      v
Motion path is calculated
      |
      v
Interpolator coordinates the axes
      |
      v
Servo systems execute the movement
      |
      v
Feedback verifies actual machine response

The key principles are:

  • G-codes define motion and operating modes.
  • Modal states affect how later blocks are interpreted.
  • Units and coordinate modes determine the meaning of numeric coordinates.
  • Work and tool offsets relate programmed geometry to the physical machining setup.
  • Interpolation coordinates axis movements to generate a path.
  • Controller-specific manuals determine the exact behaviour of each supported code.
  • Simulation and careful validation reduce risk but do not replace machine safeguards.

G-code troubleshooting becomes much easier when the program is treated as a sequence of state changes and movement instructions, rather than a pile of letters that supposedly explain themselves.
