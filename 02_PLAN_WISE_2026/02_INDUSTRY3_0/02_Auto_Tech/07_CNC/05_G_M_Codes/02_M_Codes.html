02_M_Codes - M-codes: Machine functions, PLC-linked

1. Definition of M-codes

M-codes are CNC program commands used primarily to request auxiliary machine functions. These functions commonly include spindle operation, coolant control, tool changing, program stopping and other machine-specific sequences.

Unlike G-codes, which primarily define motion and operating modes, M-codes often initiate actions that require coordination between the CNC controller, the machine PLC and physical equipment.

Examples include:

  • Spindle start, direction and stop.
  • Coolant on and off.
  • Automatic tool change.
  • Program stop and program end.
  • Chuck clamping and unclamping on suitable machines.
  • Tailstock, pallet changer or other auxiliary operations, where supported.
  • Machine-builder-specific sequences.

The important distinction is that an M-code typically requests an operation; it does not, by itself, prove that the physical operation has completed successfully.

For example, issuing a tool-change command does not guarantee that the new tool has been transferred, clamped and verified. The machine must execute its configured sequence and confirm the required conditions.

2. M-code execution architecture

A typical machine-builder implementation works like this:

CNC program
     |
     v
M-code interpreted by CNC
     |
     v
CNC / PLC interface
     |
     v
Machine PLC evaluates interlocks
     |
     v
Outputs and sequence logic
     |
     v
Physical device or mechanism
     |
     v
Sensors / feedback signals
     |
     v
PLC verifies completion
     |
     v
CNC continues, waits or reports an alarm

The exact architecture depends on the CNC controller and machine design. Some functions are handled internally by the CNC or drive, while others are implemented through the PLC.

Example: Coolant operation

Suppose a program requests coolant using a supported M-code.

  1. The CNC interprets the command.
  2. The CNC and PLC coordinate the requested operation.
  3. PLC logic evaluates the relevant conditions.
  4. The appropriate output is activated.
  5. The pump or valve operates.
  6. Feedback may confirm pressure, flow or another condition if the machine is equipped with it.
  7. The CNC continues according to the configured execution and synchronization behaviour.

A coolant command may be accepted even if a failed pump prevents coolant from reaching the cutting tool. The command and the physical result are separate things, because industrial equipment enjoys making simple ideas unnecessarily interesting.

3. Common M-codes

Many CNC controllers support familiar M-code conventions, but their meanings and implementation must be verified against the machine's programming manual.

M-code Common meaning Important consideration
M00 Program stop Requires operator or configured restart action
M01 Optional stop Behaviour depends on optional-stop enablement
M02 Program end Exact end behaviour depends on the controller
M03 Spindle clockwise start Direction convention and interlocks are machine-dependent
M04 Spindle counterclockwise start Verify tool and workholding requirements
M05 Spindle stop Does not prove complete energy isolation
M06 Tool change Commonly initiates an ATC sequence on equipped machines
M08 Coolant on Exact coolant function depends on machine configuration
M09 Coolant off May control one or more coolant functions, depending on the machine
M19 Spindle orientation Supported behaviour and parameters vary
M30 Program end and reset/rewind behaviour Exact restart and reset behaviour is controller-specific

These are common conventions, not a universal guarantee. Some M-codes may be reassigned, extended or handled differently by the machine builder.

4. M00, M01, M02 and M30: Program control

4.1 M00: Program stop

M00 commonly requests an unconditional program stop.

Typical applications:

  • Operator inspection.
  • Manual measurement.
  • Workpiece repositioning where the approved process requires it.
  • A planned manual operation.
  • Process verification before continuing.

The machine's precise stop behaviour depends on the controller and configuration. Spindle, coolant and other functions may behave differently across implementations.

4.2 M01: Optional stop

M01 commonly requests a stop only when the optional-stop function is enabled.

Typical uses include:

  • Intermediate dimensional checks.
  • Operator inspection during setup.
  • Trial production verification.
  • Additional checks during process validation.

If optional stop is disabled, the program may continue without stopping at the M01 block.

4.3 M02: Program end

M02 commonly indicates program end.

Its effects on modal states, program position and restart behaviour depend on the controller.

4.4 M30: Program end and reset

M30 commonly ends a program and performs a reset or rewind-related action.

Do not assume that all controllers reset every modal state or machine condition identically. Verify the behaviour before relying on it for program restart.

Comparison

Feature M00 M01 M02 M30
Primary purpose Unconditional stop Optional stop Program end Program end with common reset/rewind behaviour
Operator involvement Usually required to resume Depends on optional-stop setting Controller-dependent Controller-dependent
Common application Inspection or manual intervention Optional inspection Ending a program Ending a production program

A program stop is a sequencing function, not a substitute for the machine's safety system.

5. M03, M04 and M05: Spindle control

These commands commonly control spindle operation.

  • M03: Start the spindle in the configured clockwise direction.
  • M04: Start the spindle in the configured counterclockwise direction.
  • M05: Request spindle stop.

The CNC and PLC may coordinate these commands with spindle-drive enablement, speed commands, interlocks and feedback.

Typical spindle-start sequence

M03 / M04 request
        |
        v
Check machine and spindle conditions
        |
        v
Enable spindle drive
        |
        v
Apply speed command
        |
        v
Monitor spindle feedback
        |
        v
Confirm required speed condition, if configured

A machine may require the spindle to reach a specified speed before a subsequent machining operation is allowed.

Common faults

  • Spindle drive not ready.
  • Missing spindle-enable signal.
  • Safety or machine interlock active.
  • Incorrect gear-range condition.
  • Speed feedback fault.
  • Drive overload or another drive alarm.
  • PLC sequence condition not satisfied.

Diagnostic approach

Compare the requested spindle state, actual drive status, commanded RPM, actual RPM, relevant interlocks and alarm history.

Do not infer that a spindle is safe to approach simply because M05 was issued. The spindle may still be rotating, and other hazardous energy may remain present.

6. M08 and M09: Coolant control

M08 commonly requests coolant on, while M09 commonly requests coolant off.

Depending on the machine, coolant functions may include:

  • Flood coolant.
  • Through-spindle coolant.
  • High-pressure coolant.
  • Separate coolant circuits.
  • Other machine-builder-specific fluid functions.

The assignment of particular codes to these functions varies.

Coolant system architecture

CNC M-code
    |
    v
PLC sequence and interlocks
    |
    v
Output / starter / contactor / drive
    |
    v
Pump and valves
    |
    v
Coolant delivery
    |
    v
Flow or pressure feedback, if installed

If coolant does not operate

Check:

  1. Whether the CNC issued the intended command.
  2. Whether the PLC received and accepted it.
  3. Whether permissive conditions are satisfied.
  4. Whether the output is commanded.
  5. Whether the starter, contactor or pump drive is healthy.
  6. Whether the pump, valves, filters and coolant circuit are functioning.
  7. Whether flow or pressure feedback is available and consistent.

An output being ON does not establish that fluid is flowing. A pump may be electrically energized but mechanically damaged, airlocked or blocked downstream.

7. M06: Automatic tool change

M06 commonly requests an automatic tool change on CNC machines equipped with a suitable tool-changing system.

The actual sequence is usually implemented through CNC/PLC coordination and machine-specific logic.

Typical tool-change sequence

CNC requests M06
       |
       v
Verify tool-change permissives
       |
       v
Stop spindle
       |
       v
Orient spindle, if required
       |
       v
Move changer to exchange position
       |
       v
Release current tool
       |
       v
Transfer tools
       |
       v
Clamp new tool
       |
       v
Verify tool and mechanism status
       |
       v
Complete sequence and permit continuation

This is a conceptual sequence. Actual machines may use different mechanisms, additional checks or different step ordering.

PLC conditions that may be involved

  • Spindle stopped.
  • Spindle orientation complete.
  • Axes in a permitted position.
  • Tool changer at a valid starting position.
  • Magazine or carousel position confirmed.
  • Tool-clamp and unclamp states valid.
  • Pneumatic or hydraulic pressure adequate.
  • Guard and safety conditions satisfied.
  • Tool identification or pocket information valid, where supported.

Common M06-related faults

Symptom Possible cause
Tool change does not start M-code handshake, missing permissive or CNC/PLC state
Spindle orientation timeout Feedback, drive configuration or mechanical issue
Tool will not release Clamp mechanism, pressure supply or sensor problem
Carousel does not rotate Drive, motor, indexing sensor or interlock
Tool is transferred but not clamped Drawbar, pressure, mechanism or confirmation sensor
CNC waits indefinitely Completion handshake not received
Wrong tool selected Tool data, magazine mapping, pocket logic or sequence problem

Maintenance diagnostic method

Identify the exact sequence step where the tool change stops.

Then compare:

  • The commanded output.
  • The expected sensor input.
  • The actual sensor state.
  • The sequence step or state variable.
  • The active interlock.
  • The alarm or timeout condition.

This is more effective than replacing sensors randomly, a time-honoured industrial tradition that produces invoices rather than understanding.

Safety: Never manually force an ATC mechanism or bypass clamp, guard or sequence interlocks to complete a tool change.

8. M19: Spindle orientation

M19 commonly requests spindle orientation on controllers that support it.

The function positions the spindle at a defined angular location, which may be necessary for tool changing or other operations.

Depending on the controller and configuration, orientation may involve:

  • Encoder feedback.
  • Spindle-drive positioning functions.
  • PLC coordination.
  • Orientation-complete feedback.
  • Machine-specific angular parameters.

Common orientation faults

  • Encoder or feedback signal failure.
  • Incorrect orientation parameters.
  • Spindle-drive fault.
  • Mechanical resistance.
  • Orientation-complete signal missing.
  • Incorrect spindle-control mode.

Diagnostic approach

Compare the orientation request, actual spindle position or feedback, drive status, completion signal and sequence timeout.

Do not assume that every M19 implementation uses the same angle, parameter syntax or positioning method.

9. Machine-specific M-codes

Many machine functions do not have one universal M-code assignment.

Examples include:

  • Chuck clamp and unclamp.
  • Tailstock movement.
  • Pallet changing.
  • Door control.
  • Chip conveyor.
  • Parts catcher.
  • Air blast.
  • Auxiliary clamping.
  • Special coolant functions.
  • Machine-specific inspection or probing sequences.

A machine builder may assign custom codes and connect them to PLC routines.

For example, one machine may use a particular code for chuck clamping while another machine assigns the same code to a different function. Never infer a custom function from the code number alone.

How to identify a machine-specific M-code

  1. Consult the CNC programming manual for the exact control.
  2. Consult the machine-builder documentation and M-code list.
  3. Identify the CNC-to-PLC interface used by the control.
  4. Trace the relevant PLC sequence and conditions.
  5. Verify the associated physical outputs and feedback inputs.
  6. Confirm the behaviour through the approved diagnostic or commissioning procedure.

If source code or ladder logic is unavailable, use the machine's supported diagnostics and electrical documentation rather than guessing.

10. CNC-to-PLC handshake

A handshake is an exchange of status and control information between systems.

A typical M-code handshake may involve a request, acceptance, execution and completion indication.

CNC                     PLC
 |                       |
 |---- M-code request -->|
 |                       |
 |<--- Accepted/status --|
 |                       |
 |                  Check permissives
 |                  Execute sequence
 |                  Monitor feedback
 |                       |
 |<--- Complete/status --|
 |                       |
 | Continue program      |

This is a simplified example. Actual signals, bit assignments, acknowledgement rules and timing depend on the CNC/PLC platform.

Important handshake signals

Signal concept Meaning
Request CNC requests a machine function
Accepted or active PLC or machine logic has recognized the request
Busy Operation is still in progress
Complete Required sequence conditions have been satisfied
Fault or timeout Operation failed or did not complete within the permitted time

A missing completion signal may have several causes:

  • The PLC never received the request.
  • The request was received but rejected.
  • A permissive condition was not satisfied.
  • The sequence started but stopped at a later step.
  • A sensor failed to change state.
  • The sequence completed physically, but the completion handshake failed.
  • Communication or interface logic failed.

The first diagnostic task is to distinguish between a request that never arrived, an operation that never started and an operation that started but never completed.

11. M-code execution and synchronization

M-code timing is important because some machine functions must complete before machining can continue.

A controller may support synchronized or non-synchronized handling for certain auxiliary operations, depending on the code and configuration.

For example, a tool-change operation usually requires the CNC to wait for the required completion conditions before continuing with a machining block.

Other auxiliary operations may be permitted to overlap with movement or other activity if the controller and machine-builder logic explicitly support it.

Do not assume that every M-code is executed in the same way or at the same time relative to axis motion. Check the exact controller's execution rules and the machine's documented sequence.

12. Common M-code troubleshooting workflow

Step 1: Record the failure

Capture the exact M-code, program block, alarm, current machine state and expected physical action.

Step 2: Verify the CNC request

Determine whether the CNC recognized the code and generated the intended request.

Check for syntax errors, unsupported codes and controller-specific restrictions.

Step 3: Check the CNC/PLC interface

Verify the request and acknowledgement or status signals using the machine's supported diagnostic tools.

Step 4: Identify the PLC sequence state

Determine whether the sequence is idle, active, waiting for a permissive, waiting for feedback or in a fault state.

Step 5: Compare commanded and actual signals

Check the relevant output command, physical output state, device response and sensor feedback.

For example, a pump output may be commanded ON while a flow switch remains OFF. Those observations point toward different diagnostic branches than a pump output that never activates.

Step 6: Check the physical equipment

Inspect the motor, actuator, valve, mechanism, pressure supply, wiring or sensor according to the fault and approved maintenance procedure.

Step 7: Verify completion and recovery

Confirm that the sequence finishes, the completion handshake returns to the expected state and the CNC can proceed normally.

Record the root cause and validation result. Do not bypass the interlock merely to make the alarm disappear.

13. Interview questions and answers

Q1. What is an M-code?

A CNC program command used primarily to request auxiliary machine functions.

Q2. What is the difference between G-codes and M-codes?

G-codes primarily define motion and operating modes. M-codes commonly request auxiliary machine functions.

Q3. What is the purpose of M03, M04 and M05?

They commonly start the spindle clockwise, start it counterclockwise and request spindle stop, respectively.

Q4. What is the difference between M00 and M01?

M00 commonly requests an unconditional program stop. M01 commonly requests a stop only when optional stop is enabled.

Q5. What is the common purpose of M30?

Program end with reset or rewind-related behaviour, depending on the controller.

Q6. What is M06?

A common command for requesting an automatic tool change on equipped CNC machines.

Q7. Why can an M06 command remain incomplete even if the tool changer motor is running?

The sequence may still be waiting for tool-position, clamp, orientation, sensor or other completion conditions.

Q8. What is an M-code handshake?

The exchange of request, status and completion information between the CNC and the machine control system.

Q9. What causes an M-code timeout?

A request may not be accepted, a permissive may be missing, a physical action may fail or the expected feedback/completion signal may not arrive in time.

Q10. What is the common purpose of M08 and M09?

They commonly request coolant on and coolant off, subject to machine-specific implementation.

Q11. What is spindle orientation?

Positioning the spindle at a defined angular location using the available control and feedback functions.

Q12. Why can the PLC output be ON while the requested function is not complete?

The electrical output command does not prove that the physical device operated or that the required completion feedback was received.

Q13. Are M-codes universally standardized across all CNC machines?

No. Common conventions exist, but many functions and assignments depend on the controller and machine builder.

Q14. How should a technician troubleshoot a failed machine-specific M-code?

Check the CNC request, interface status, PLC sequence state, permissives, commanded outputs, physical response, feedback and completion handshake.

Q15. Why should a PLC interlock not be bypassed to complete an M-code?

The interlock may prevent unsafe motion, incorrect sequencing or equipment damage. The underlying condition must be identified and corrected.

Q16. Can two M-codes appear in the same program block?

Some controllers permit certain combinations, while others impose restrictions or specific execution rules. Verify the controller manual and machine-builder requirements.

Q17. What is the difference between a command and a completion signal?

A command requests an action. A completion signal indicates that the configured completion conditions have been met.

Q18. Why is PLC sequence-state monitoring useful for maintenance?

It identifies the step where execution stopped and helps distinguish an input, output, permissive, physical mechanism or handshake fault.

14. Practical exercises

Exercise 1: Coolant command fails

An M08 command appears in the program, but coolant does not reach the tool.

Create a diagnostic tree covering the CNC request, PLC logic, output, pump starter, pump, valve, coolant circuit and available feedback.

Exercise 2: Automatic tool change timeout

An M06 operation begins, but the CNC never resumes the program.

Identify how to establish whether the failure occurred during spindle stopping, orientation, tool release, tool transfer, clamping or completion acknowledgement.

Exercise 3: Spindle starts but machining does not continue

The spindle rotates at the requested speed, but the CNC remains waiting.

Investigate the configured spindle-at-speed condition, feedback, interlocks and execution synchronization.

Exercise 4: Machine-specific M-code fails

An auxiliary function does not operate.

Prepare a diagnostic record containing the M-code, intended function, CNC request status, PLC state, permissives, output commands, actual feedback, alarm, root cause and validation.

Exercise 5: Trace a CNC/PLC handshake

Using an approved training or offline environment, document the request, acknowledgement, busy state, physical sequence, completion condition and timeout path for one auxiliary machine function.

Exercise 6: Build an M-code reference register

Record:

  • M-code number.
  • Documented function.
  • Controller and machine model.
  • CNC/PLC implementation.
  • Required permissives.
  • Completion feedback.
  • Related alarms.
  • Recovery procedure.
  • Safety restrictions.

15. Final mental model

CNC program issues M-code
           |
           v
CNC interprets and requests function
           |
           v
CNC / PLC interface
           |
           v
PLC checks permissives and sequence state
           |
           v
Physical device operates
           |
           v
Feedback confirms required condition
           |
           v
Completion handshake
           |
           v
CNC proceeds or reports a fault

The key principles are:

  • An M-code requests a machine function; it does not guarantee success.
  • The PLC often coordinates the physical sequence and its interlocks.
  • Sensors and status signals establish whether the expected conditions were achieved.
  • A timeout indicates that a required event did not complete as expected, not necessarily that the device itself is defective.
  • Machine-specific M-code assignments must be verified against the correct documentation.
  • Troubleshooting should follow the request, interface, sequence, output, physical response and feedback layers.
  • Safety interlocks must remain operational throughout diagnosis and recovery.

For industrial maintenance, understanding the CNC/PLC handshake is often more useful than memorizing a long list of M-codes. It tells you where the operation actually failed.
