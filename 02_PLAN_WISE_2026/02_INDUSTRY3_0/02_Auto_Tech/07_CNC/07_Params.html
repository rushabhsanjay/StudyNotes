07_Params - Parameters

1. Definition of CNC parameters

CNC parameters are configuration values that define how a CNC controller, its axes, drives and associated machine functions behave.

They establish machine-specific settings used by the control system to interpret programs, calculate positions, coordinate motion and interact with the machine's hardware.

Depending on the controller, parameters may configure:

  • Axis travel limits and reference-return behaviour.
  • Encoder resolution and position feedback.
  • Servo control and motion characteristics.
  • Spindle control and orientation.
  • Coordinate systems and compensation behaviour.
  • Acceleration, deceleration and feed control.
  • Tool-change and machine interface functions.
  • Communication with drives and external devices.
  • Alarm detection and machine protection.
  • Optional features and control modes.

Parameters are not the same as ordinary CNC program commands. A G-code requests a programmed operation, while a parameter helps define how the controller interprets or performs that operation.

For example, a CNC program might command an axis to move 100 mm. Controller configuration determines how encoder counts correspond to position, how the axis responds to motion commands and which configured limits apply.

Critical principle: A parameter can affect the behaviour of the machine globally, not just one program. An incorrect change may cause positioning errors, unexpected motion, alarms or machine downtime.

3. Parameter categories

CNC manufacturers organize parameters differently. The same type of setting may have a different number, name, storage location or adjustment method on another controller.

Category Typical purpose Example
Axis configuration Defines axis behaviour and configuration Axis enable or axis type
Position feedback Relates feedback signals to position Encoder scaling
Reference return Defines homing/reference-return behaviour Reference direction or grid settings
Travel limits Defines permitted axis travel Software overtravel limits
Servo and motion Configures motion response Acceleration or control-loop settings
Spindle Configures spindle functions Speed or orientation-related settings
Coordinate systems Controls coordinate-related behaviour Supported coordinate functions
Tool compensation Configures compensation-related behaviour Controller-specific compensation options
PLC interface Connects CNC requests to machine sequences Machine-function interface settings
Alarms and monitoring Configures detection or monitoring behaviour Thresholds and diagnostic options
Communications Configures supported interfaces Network or drive communication settings
Optional features Enables licensed or configured functions Advanced machining options

Not every controller exposes all these categories as user-editable parameters. Some settings are configured through protected service menus, machine-builder software or separate drive tools.

4. CNC parameters versus other machine data

Several kinds of data may appear in CNC setup screens. They must not be treated as interchangeable.

Data type Purpose Example
CNC program Defines the machining operation G01 X100.0 F200
CNC parameter Defines controller or machine behaviour Axis configuration
Work offset Defines the part coordinate origin G54 values
Tool offset Defines tool geometry or correction Tool length and radius data
PLC data Controls machine sequences and status Tool-changer sequence state
Servo-drive parameter Configures drive behaviour Motor identification or tuning
Tool management data Tracks tools and their assignments Tool number and magazine pocket
Machine calibration data Records measured geometric corrections Axis compensation tables

The exact boundary depends on the machine architecture. Some functions normally called CNC parameters may be stored in a PLC, servo drive or separate configuration file.

Practical example

Suppose a machined hole is positioned incorrectly.

Potential causes include:

  • Incorrect work offset.
  • Incorrect program coordinates.
  • Incorrect axis scaling or machine calibration.
  • Mechanical backlash or coupling problems.
  • Incorrect feedback configuration.

Changing a CNC parameter before establishing the actual cause can make the fault worse. First determine whether the error comes from the program, coordinate data, configuration, feedback or physical machine.

5. Axis parameters

Axis parameters define aspects of how the controller manages individual machine axes.

Typical areas include:

  • Axis type and configuration.
  • Position feedback scaling.
  • Reference-return behaviour.
  • Software travel limits.
  • Axis direction and coordinate conventions.
  • Motion constraints.
  • Axis-specific monitoring.
  • Compensation and calibration functions.

A three-axis machining centre may configure X, Y and Z separately. A machine with a rotary table may also require A, B or C axis configuration.

Example: Axis scaling

The controller must relate its internal position representation to physical movement.

Conceptually:

\[ \text{Position} = \text{Feedback counts} \times \text{Scale factor} \]

This is a simplified model. Actual scaling may include encoder resolution, electronic gearing, screw pitch, transmission ratios, interpolation and controller-specific conventions.

If the configured scaling does not match the actual mechanical and feedback system, commanded and measured positions may disagree.

Possible symptoms include:

  • Incorrect movement distance.
  • Incorrect displayed position.
  • Positioning errors.
  • Servo following errors.
  • Unexpected overtravel conditions.

Example: Software travel limits

Software travel limits restrict commanded axis movement within configured positions.

They complement, but do not replace, physical limit switches and safety systems.

If the configured range is inconsistent with the machine's actual geometry, the axis may encounter premature software overtravel alarms or be permitted to approach an unsuitable region.

Never change travel limits simply to clear an alarm. Determine why the limit was reached and verify the machine's documented travel range first.

6. Reference return and homing parameters

Reference return establishes the machine's reference position according to its configured homing method.

Depending on the machine, the procedure may use:

  • Reference switches.
  • Encoder reference markers.
  • Absolute encoders.
  • A combination of switches and encoder feedback.
  • Machine-specific reference sequences.

Relevant parameters may configure direction, sequence, reference detection or other controller-specific behaviour.

An incorrect reference configuration can result in:

  • Failed homing.
  • Incorrect machine position after reference return.
  • Reference-return alarms.
  • Axis movement in an unexpected direction.
  • Incorrect software limit relationships.

Diagnostic example

An axis repeatedly fails to establish its reference.

Investigate:

  1. Whether the reference command is accepted.
  2. Whether the axis moves in the expected direction.
  3. Whether the reference sensor changes state.
  4. Whether the encoder feedback is valid.
  5. Whether the reference marker or absolute-position procedure operates correctly.
  6. Whether the relevant machine configuration matches the installed hardware.

Do not modify homing parameters before checking the switch, encoder, wiring and mechanical condition. Configuration is one possible cause, not the automatic culprit.

7. Servo and motion parameters

Servo-related configuration affects how the controller and drive coordinate commanded movement with feedback.

Relevant areas may include:

  • Position-loop and speed-loop settings.
  • Gain and filtering.
  • Acceleration and deceleration limits.
  • Torque or current limits.
  • Following-error monitoring.
  • Positioning tolerance.
  • Feed-forward functions.
  • Vibration suppression.
  • Electronic gearing or synchronization.

Some of these values are CNC parameters, while others reside in the servo drive.

Why these parameters matter

A motion command passes through the motion planner, controller and servo system before producing physical movement.

If the settings are inappropriate for the installed motor, load and mechanics, possible symptoms include:

  • Excessive vibration.
  • Overshoot.
  • Positioning errors.
  • Following-error alarms.
  • Slow settling.
  • Excessive motor heating.
  • Unstable motion.

Important distinction

A motion symptom does not prove that the parameter settings are wrong.

Mechanical looseness, worn bearings, coupling damage, encoder faults, excessive load, lubrication problems and drive faults can produce similar symptoms.

Before adjusting gains or filters, compare the fault with the drive diagnostics, mechanical condition and approved commissioning data.

8. Spindle parameters

Spindle-related parameters configure aspects of spindle control and monitoring.

Depending on the controller and drive architecture, they may relate to:

  • Speed command scaling.
  • Maximum permitted speed.
  • Gear-range selection.
  • Orientation functions.
  • Feedback and encoder configuration.
  • Acceleration and deceleration.
  • Spindle monitoring.
  • Drive communication.

Example: Incorrect spindle speed

The program requests a spindle speed of 2,000 RPM, but the spindle runs at an unexpected speed.

Possible causes include:

  • Incorrect programming mode or command.
  • Speed command scaling.
  • Gear-range or transmission configuration.
  • Drive configuration.
  • Speed feedback error.
  • A configured maximum-speed restriction.

A diagnostic sequence should compare the programmed request, CNC speed command, drive reference, actual spindle speed and active alarms.

Do not increase a maximum-speed parameter merely because the spindle fails to reach the requested speed. First verify the spindle rating, tooling, gearing, drive configuration and machine-builder limits.

9. CNC parameters and PLC-linked machine functions

CNC machine functions often depend on interaction between the CNC and the machine PLC.

Parameters or configuration data may determine how certain machine functions are interpreted or enabled. The PLC then evaluates conditions and executes the appropriate machine sequence.

Examples include:

  • Tool-change coordination.
  • Spindle orientation.
  • Chuck or workholding functions.
  • Pallet changing.
  • Coolant and auxiliary equipment.
  • Machine-specific interlocks and status reporting.

The implementation depends on the controller and machine builder.

Example: Tool-change function does not complete

If the sequence stops, possible causes include:

  • Incorrect tool-change configuration.
  • Missing permissive.
  • PLC logic fault.
  • Failed sensor or actuator.
  • Incorrect feedback.
  • Interface or completion-handshake problem.

A parameter change should be considered only after the sequence and its actual failure point have been identified.

10. Parameter backup and restore

A parameter backup is a saved copy of controller configuration data used for recovery, comparison or approved machine restoration.

Backup requirements vary by CNC platform. A complete machine restoration may require more than the CNC parameter file.

Depending on the machine, relevant data can include:

  • CNC parameters.
  • Servo-drive parameters.
  • PLC program and data.
  • Tool and work offset data.
  • Pitch-error or compensation tables.
  • Tool management configuration.
  • Machine-builder configuration files.
  • Options, licenses or system-specific settings.

Why backups matter

An incorrect parameter change may introduce faults that were not present before the change.

A verified backup provides a reference for identifying differences and restoring an approved configuration when the controller supports that recovery method.

Recommended parameter-control register

Field Purpose
Machine ID Identifies the CNC machine
CNC make and model Identifies the controller
Parameter number/name Identifies the setting
Original value Records the approved baseline
Proposed value Records the intended change
Reason Describes the fault or requirement
Evidence Alarm, measurement or diagnostic result
Approval Records required authorization
Backup reference Identifies the saved configuration
Validation result Records post-change verification
Technician/date Provides traceability

Change-control principles

  1. Record the original value before an authorized change.
  2. Obtain the required technical approval.
  3. Verify the exact parameter definition for the controller and machine.
  4. Use the approved backup procedure.
  5. Change only the intended setting.
  6. Follow the controller's requirements for activation or restart.
  7. Verify operation using the approved test procedure.
  8. Record the result and retain the updated backup where required.

Do not assume that a file from one CNC can be safely restored to another, even if both machines use the same controller family. Hardware, options, firmware and machine-builder configurations may differ.

11. Parameter changes: Risks and restrictions

CNC parameters can affect positioning, speed, travel, interlocks, compensation and machine operation.

Potential consequences of an incorrect change include:

  • Axis movement in an unexpected direction.
  • Incorrect positioning or scaling.
  • Loss of reference accuracy.
  • Unexpected spindle behaviour.
  • Tool or fixture collision.
  • Disabled or altered monitoring functions.
  • Machine alarms or failure to start.
  • Loss of a valid configuration.
  • Production downtime.

Some parameters are protected because their effects are safety-critical, machine-specific or difficult to recover from without specialized procedures.

Never change a parameter to suppress an alarm without identifying the alarm's cause. Do not alter safety-related settings, disable monitoring or bypass machine-builder restrictions as a shortcut.

Use the OEM documentation and authorized engineering process.

12. Parameter troubleshooting workflow

When a CNC problem may involve configuration, use a structured diagnostic method.

Step 1: Capture the symptom

Record the alarm number, alarm text, operating mode, axis or function involved and the exact sequence that produces the fault.

Step 2: Establish the baseline

Determine whether the machine previously operated correctly and whether a parameter, component, program, tool or mechanical assembly was recently changed.

Step 3: Check direct causes first

Inspect relevant sensors, wiring, feedback, drive status, mechanical condition and machine sequence logic.

Step 4: Identify the correct parameter definition

Use the documentation for the exact CNC model, software version and machine-builder implementation.

Parameter numbers are not universally interchangeable between controllers.

Step 5: Compare against approved data

Check the current value against a verified machine backup, approved setup record or documented OEM specification.

Step 6: Determine whether the parameter is actually implicated

Use measured evidence, diagnostic status and the parameter's documented function. Do not assume that proximity to an alarm makes a parameter responsible.

Step 7: Apply approved change control

If a parameter correction is justified, obtain authorization, save the original value and use the prescribed procedure.

Step 8: Validate the machine

Follow the specified test sequence, including reference return, axis checks, relevant interlocks and controlled functional verification where required.

Step 9: Record the outcome

Document the original symptom, evidence, approved change, result and final configuration reference.

This method helps distinguish a genuine configuration problem from a failed sensor, damaged cable, worn mechanical component or incorrect program.

14. CNC parameter management across controller families

Different CNC platforms use different parameter organizations and tools.

Controller family General approach
FANUC CNC parameter screens, diagnostic functions and platform-specific backup/restore procedures
Siemens SINUMERIK Machine data, setting data and controller-specific commissioning tools
Mitsubishi CNC CNC parameters and platform-specific setup/diagnostic functions
Other CNC platforms Manufacturer-specific parameter structures, tools and access controls

Terminology differs. For example, Siemens commonly distinguishes machine data from setting data, while other platforms may group configuration values differently.

The same general principles still apply:

  • Identify the exact control and version.
  • Consult the correct documentation.
  • Preserve the original configuration.
  • Understand the effect of the change.
  • Validate the machine after an approved modification.

15. Interview questions and answers

Q1. What are CNC parameters?

Configuration values that define how the CNC controller and associated machine functions operate.

Q2. What is the difference between a CNC parameter and a G-code?

A G-code requests an operation or selects a mode within a program. A CNC parameter configures controller or machine behaviour.

Q3. What is the difference between a work offset and a CNC parameter?

A work offset establishes the part coordinate origin. A CNC parameter configures a machine or controller function.

Q4. Why are axis parameters important?

They configure axis-related behaviour such as feedback interpretation, travel restrictions and reference-return functions.

Q5. What can happen if axis scaling is incorrect?

The controller's interpretation of position can disagree with physical movement, resulting in positioning errors or related alarms.

Q6. What are software travel limits?

Configured boundaries that restrict commanded axis travel. They complement rather than replace physical protection and safety systems.

Q7. What is the purpose of reference-return parameters?

They configure aspects of how the machine establishes its reference position, depending on the controller and homing method.

Q8. Can servo parameters affect positioning accuracy?

Yes. Motion response, feedback configuration and compensation settings can influence positioning, but mechanical and feedback faults must also be investigated.

Q9. Why should the original parameter values be recorded?

They provide a baseline for comparison, traceability and approved recovery.

Q10. Is a CNC parameter backup always sufficient to restore a machine?

No. PLC, drive, compensation, tool data, options and other machine-specific configuration may also be required.

Q11. Can parameters be copied between two identical CNC controllers?

Not safely by default. The machines may differ in hardware, software, options and machine-builder configuration.

Q12. Why can a tool-change problem be related to configuration?

The CNC/PLC interface and machine-function setup may affect how the tool-change request is coordinated, although PLC logic, sensors and actuators must also be checked.

Q13. What is the difference between a CNC parameter and a servo-drive parameter?

CNC parameters configure controller functions, while servo-drive parameters configure drive functions. The exact division depends on the architecture.

Q14. What should be checked before changing a parameter?

The exact controller documentation, fault evidence, current value, approved baseline, expected effect and change authorization.

Q15. Why should an alarm not simply be disabled by changing a parameter?

The alarm may identify a genuine equipment, positioning or safety-related problem. Suppressing it can conceal the cause and increase risk.

Q16. What is a machine-builder parameter?

A configuration value or setting associated with the machine manufacturer's implementation of the CNC and its functions.

Q17. Why might a parameter change require a restart?

Some settings take effect only after a specified activation procedure or controller restart. The exact requirement is platform-specific.

Q18. How should a technician investigate a parameter-related fault?

Record the symptom, check direct hardware and sequence causes, verify the documented parameter definition, compare against an approved baseline and make only an authorized, validated change.

16. Practical exercises

Exercise 1: Axis scaling fault

An axis is commanded to move 100 mm but the measured physical displacement is incorrect.

Create a diagnostic sequence that checks:

  • Programmed distance and units.
  • Feedback scaling.
  • Encoder and drive configuration.
  • Mechanical transmission ratio.
  • Screw pitch or other relevant mechanism.
  • Measurement method and machine calibration.

Explain why changing the scaling value without checking the hardware can create a new error.

Exercise 2: Reference-return failure

An axis fails to establish its reference position.

Separate possible causes into:

  • Sensor and wiring.
  • Encoder feedback.
  • Mechanical movement.
  • CNC configuration.
  • Drive or communication faults.

Identify the evidence needed before considering a parameter change.

Exercise 3: Spindle speed mismatch

The program requests 1,500 RPM, but the actual spindle speed differs.

Build a diagnostic chain from program command to CNC request, drive reference, gear configuration, actual speed feedback and alarms.

Exercise 4: Parameter change control

Create a parameter-change record for a hypothetical approved correction.

Include the original value, documented purpose, diagnostic evidence, authorization, backup reference, validation method and final result.

Do not invent a real parameter number or value. Those must come from the specific controller's documentation.

Exercise 5: CNC versus PLC fault

A tool-change sequence fails before the tool is transferred.

Determine how to distinguish between a CNC configuration problem, an interface request issue, a missing PLC permissive, a sensor fault and a mechanical problem.

Exercise 6: Backup and recovery

Prepare a recovery checklist for a machine that experiences startup problems after an authorized configuration change.

Include configuration identification, comparison with the approved baseline, OEM recovery procedure, relevant drive and PLC data, functional validation and documentation.

      |

      v

      |
      v

      |
      v
Produce expected motion and machine behaviour

Remember:

  • CNC parameters configure the controller and machine behaviour.
  • Work offsets define the part origin.
  • Tool offsets account for tool geometry and corrections.
  • PLC logic executes many machine-specific auxiliary sequences.
  • Servo-drive parameters configure drive behaviour.
  • Backups and change control protect the approved machine configuration.
  • A parameter should be changed only when evidence and documentation support the change.
  • Successful recovery must be verified through an approved functional test.

The practical maintenance rule is straightforward: diagnose first, compare against the approved baseline, change only what is justified, and validate the result. A parameter screen is not a place for experimental button pressing.
