Control Source: Local vs Remote Command

1. Definition

The control source of a Variable Frequency Drive (VFD) determines where the drive receives its operating commands, such as start, stop, forward, reverse, reset, and sometimes speed reference selection.

A VFD can commonly receive commands from two broad sources:

  • Local control: Commands are issued directly through the drive's keypad, local operator interface, or an associated local control method.
  • Remote control: Commands are received from an external source, such as a PLC, HMI, SCADA system, hardwired push buttons, or an industrial communication network.

The exact meaning of local and remote depends on the VFD manufacturer and configuration. A drive's local/remote selection may change the command source, the speed-reference source, or both.

For example, on an automotive assembly-line conveyor, a maintenance technician might use the VFD keypad to test motor operation during an approved maintenance procedure. During normal automatic production, the PLC commands the VFD to start and stop the conveyor and sets its speed reference.

The important distinction is that the command source determines who controls the drive's operation, while the speed-reference source determines where the requested speed comes from. They may be configured independently.

3. Local control

Local control allows an operator or technician to command the drive directly, usually using the keypad mounted on the drive or an approved local operator panel.

Typical local functions include:

  • Start and stop commands.
  • Setting a speed or frequency reference.
  • Selecting forward or reverse, if supported and permitted.
  • Monitoring output frequency, motor current, DC bus voltage, and drive status.
  • Viewing and resetting eligible faults.

Example: Maintenance testing

A technician is investigating a conveyor motor that has stopped unexpectedly.

Under the approved maintenance procedure, the technician selects local control, checks the drive status, and performs a controlled test from the keypad.

If the drive is configured to use a local speed reference, the technician may enter a test frequency such as 10 Hz.

However, local mode does not make an unsafe machine safe. Guards, interlocks, isolation requirements, stored energy, and the machine's safety procedures still apply. Local commands must not bypass safety functions.

Advantages of local control

  • Useful for commissioning and troubleshooting.
  • Allows direct observation of drive behavior.
  • Can help isolate whether a problem lies in the external command path or the drive itself.
  • May allow basic testing without a functioning PLC-to-drive command path, where the system design permits it.

Limitations of local control

  • The PLC may no longer have authority over normal start/stop commands.
  • The machine sequence may not operate as intended.
  • Other equipment may remain active even if the drive is being controlled locally.
  • An unexpected mode change can create a hazard if the machine is not prepared for it.

Important: Never assume that selecting local mode automatically stops every machine sequence or disables all remote commands. Verify the actual drive behavior and the machine's control design.

4. Remote control

Remote control allows an external system or operator station to command the drive.

Common remote command sources include:

Source Typical purpose
PLC digital outputs Start, stop, direction, reset, or selection signals
PLC analog output Speed reference through a supported analog input
Industrial Ethernet Commands, speed reference, status, diagnostics, and sometimes parameter access
Hardwired push buttons Start/stop or other discrete commands through configured inputs
HMI Operator commands and speed entry through the PLC or supported drive interface
SCADA Supervisory commands and monitoring, subject to the system's permissions and design

A remote source does not necessarily mean a physically distant location. A push button on a nearby panel can be a remote command source relative to the drive's own keypad.

Example: PLC-controlled conveyor

HMI: Conveyor Start
          |
          v
         PLC
          |
          | Start command
          | Speed reference = 35 Hz
          v
         VFD
          |
          v
     Conveyor motor

The PLC may issue the start command and a speed reference of 35 Hz. The drive then operates according to its configured command source, speed-reference source, limits, ramp times, and control mode.

The HMI does not necessarily communicate directly with the drive. In many installations, it sends a request to the PLC, which checks operating conditions and issues the drive command.

5. Command source vs speed-reference source

This distinction is essential for troubleshooting.

Command source answers: Who tells the drive to start, stop, or change direction?

Speed-reference source answers: Where does the drive obtain the requested speed?

These can be configured separately.

Command source Speed-reference source Example
Keypad Keypad Technician starts the drive and enters the speed locally.
PLC digital I/O Analog input PLC controls start/stop while a 0 to 10 V signal sets speed.
PLC over industrial Ethernet Network reference PLC sends start/stop and a speed value through the drive communication interface.
Hardwired controls Keypad or preset speed A configured digital input starts the drive while speed comes from another selected source.

The final row is an illustrative configuration, not a universal default.

A drive might accept a start command from the PLC but obtain its speed reference from an analog input. Consequently, switching only the command source may not produce the expected speed behavior.

6. Local/remote selection and mode transitions

A VFD may offer a keypad key, digital input, parameter, or network command to select local or remote operation. Some machines implement mode selection through the PLC or operator panel instead.

Possible behaviors during a mode change include:

  • The drive transfers command authority to the newly selected source.
  • The drive stops and requires a new start command.
  • The drive continues operating, depending on its configuration.
  • The drive accepts the new command only after specific conditions are satisfied.
  • The speed reference changes immediately or follows a configured transition.

These behaviors vary by drive and application. Never assume a local/remote change is inherently bumpless or that the motor will stop automatically.

Example: Unexpected start after changing mode

A conveyor is stopped while the drive is in local mode. A remote PLC start command remains active.

If the drive's configuration allows the remote command to take effect immediately after switching back to remote, the motor may start unexpectedly.

Engineering controls can prevent this, for example by requiring a fresh start command after mode selection, coordinating PLC and drive states, and validating the transition behavior.

The correct approach is to test mode transitions during commissioning and document the actual behavior.

7. Hardwired control vs network control

Remote commands may travel through physical I/O or an industrial communication network.

Feature Hardwired control Network control
Signal path Electrical inputs and outputs Industrial communication protocol
Typical commands Start/stop, direction, enable Start/stop, direction, reference, status, diagnostics
Wiring Individual signal conductors plus common/reference as required Network cable or supported communication medium
Diagnostics Input LEDs, terminal measurements, PLC I/O status Communication status, connection health, drive status words
Common failures Broken wire, incorrect polarity, loose terminal, missing supply Lost connection, incorrect configuration, timeout, addressing or mapping error
Data capability Depends on number and type of physical signals Often supports richer cyclic and diagnostic data

Examples of network interfaces include EtherNet/IP, PROFINET, and Modbus, depending on the drive and PLC.

A network connection does not automatically mean the drive is configured to accept commands over that network. The communication option, parameter settings, command assembly or telegram mapping, and PLC logic must all agree.

8. Common parameters to identify

Parameter numbers differ across manufacturers and models. Use the drive manual rather than memorizing a parameter number from a different product.

During commissioning, identify the settings that correspond to:

  1. Start/stop command source.
  2. Speed-reference source.
  3. Local/remote selection method.
  4. Forward/reverse command source.
  5. Digital-input assignments.
  6. Analog-input scaling, if used.
  7. Network command and reference configuration, if used.
  8. Communication-loss response.
  9. Restart behavior after power recovery or fault reset.
  10. Access permissions and parameter locking.

For a network-controlled drive, also verify the PLC's output command word, reference scaling, status word, and communication-health monitoring.

9. Troubleshooting matrix

Symptom Possible cause Checks
PLC start command does not start the motor Drive in local mode, wrong command source, missing enable, active fault Check drive mode, command-source parameter, status, interlocks, and fault history.
Keypad start does not work Drive in remote mode, keypad commands disabled, missing enable, active fault Check local/remote state, keypad configuration, drive status, and permissives.
Drive starts but speed is incorrect Wrong speed-reference source, scaling error, active limits, incorrect preset selection Compare commanded reference, selected source, actual frequency, and limit settings.
Start works but stop does not Wrong stop-command mapping, logic error, incorrect terminal configuration Verify the command path and the configured stopping method. Use approved safe isolation if stopping cannot be assured.
Drive changes speed when switching modes Different reference sources, reference scaling, transition configuration Inspect both reference sources and test the mode transition under controlled conditions.
Network command stops working Communication loss, connection timeout, PLC mapping error, wrong address Check network diagnostics, connection status, configuration, and drive communication parameters.
Drive starts unexpectedly after mode change Remote command remains active or transition logic permits immediate restart Review PLC logic, drive configuration, restart policy, and mode-transition design.
Drive reports running but motor does not rotate Output inhibited, zero reference, motor/cable issue, mechanical problem Check output frequency, current, status, motor circuit, and mechanical condition using approved procedures.

Diagnostic sequence for a nonresponsive drive

If a PLC-controlled drive does not start, investigate in this order:

  1. Confirm whether the drive reports local or remote mode.
  2. Check for active faults, inhibits, and required enables.
  3. Verify the configured command source.
  4. Confirm that the PLC's start command actually reaches the drive through the intended path.
  5. Check the selected speed-reference source and requested frequency.
  6. Verify interlocks and permissives in the PLC logic.
  7. Inspect hardwired I/O or network diagnostics, depending on the control method.
  8. Review the drive's status indicators and fault history before changing parameters.

This sequence separates command-path problems from speed-reference problems and drive-side restrictions.

10. Safety and control-system design

Local/remote control is an operational mode, not a safety function by itself.

A robust machine design should address:

  • Who is authorized to control the drive in each mode.
  • Whether the machine sequence must be stopped before changing modes.
  • How active remote commands are handled during mode transitions.
  • How PLC permissives and interlocks are enforced.
  • How loss of network communication is handled.
  • How unexpected restart is prevented where required.
  • Which safety functions independently prevent hazardous motion.

A standard PLC interlock or ordinary VFD command should not be assumed to provide a safety-rated function. The safety design must use suitable equipment and be validated for the machine's risks.

11. Practical automotive maintenance example

Consider a conveyor VFD controlled by a PLC through EtherNet/IP.

The HMI indicates that the conveyor should be running, but the motor remains stopped.

A disciplined investigation would be:

  1. Check the VFD display for local or remote status.
  2. Confirm that the drive is configured to accept its start command from the network.
  3. Check the PLC's run-command bit and the drive's received command/status data.
  4. Verify that required enables and process permissives are satisfied.
  5. Check the requested speed and the selected reference source.
  6. Review drive faults and communication status.
  7. Confirm the actual output frequency and motor current.

If the drive is in local mode, that may explain why it ignores the normal PLC run command. But do not stop investigating merely because one plausible cause has appeared. Confirm the actual command path and the configured behavior.

12. Interview questions and answers

Q1. What is the control source of a VFD?

It is the configured source from which the drive receives operating commands such as start, stop, and direction.

Q2. What is the difference between local and remote control?

Local control generally uses the drive keypad or local interface. Remote control uses an external source such as a PLC, hardwired controls, HMI-mediated logic, or an industrial network.

Q3. What is the difference between command source and speed-reference source?

The command source determines who commands the drive's operation. The speed-reference source determines where the requested speed comes from. They may be configured independently.

Q4. Why might a VFD ignore a PLC start command?

The drive may be in local mode, configured for another command source, inhibited, faulted, missing an enable, or not receiving the expected command through its I/O or network path.

Q5. Why might a drive run at the wrong speed even though the PLC start command works?

The speed-reference source may be incorrect, the reference may be scaled incorrectly, or an active frequency limit, preset-speed selection, or ramp configuration may affect the response.

Q6. What should be checked when switching from local to remote?

Verify the command and reference sources, active commands, restart behavior, interlocks, and the configured response to the mode transition.

Q7. What is the difference between hardwired and network-based drive control?

Hardwired control uses physical electrical signals. Network control communicates commands and status through a supported industrial protocol and requires correct communication configuration and data mapping.

Q8. Does local mode bypass machine safety interlocks?

It must not be assumed to do so. Actual behavior depends on the machine design, and safety functions must remain effective regardless of ordinary command-source selection.

13. Practical exercises

  1. Draw the command path from an HMI start request to a VFD-controlled conveyor.
  2. Explain why a drive may accept a PLC start command but still run at the wrong speed.
  3. List the parameters and diagnostics to check when a drive does not respond to a remote command.
  4. Compare hardwired start/stop control with network-based control.
  5. Describe how an unexpected restart could occur when changing from local to remote mode.
  6. Prepare a commissioning record with the command source, speed-reference source, mode-selection method, communication-loss response, restart behavior, and test results.

14. Final mental model

  • Local vs remote identifies where the drive's operating commands originate.
  • Command source vs speed-reference source are separate configuration decisions.
  • The selected source must match the intended wiring, PLC logic, or communication configuration.
  • A drive may reject commands because of its mode, active faults, missing enables, interlocks, or communication problems.
  • Mode transitions and restart behavior must be tested, not guessed.
  • Local/remote selection does not replace machine-safety design.
