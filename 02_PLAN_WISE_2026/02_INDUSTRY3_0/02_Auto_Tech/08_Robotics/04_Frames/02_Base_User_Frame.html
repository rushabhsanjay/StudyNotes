Base/User Frame: Workpiece or Fixture Reference

1. Definition

A base frame is a coordinate reference associated with the robot's mechanical base. A user frame or work frame is a coordinate reference defined relative to a fixture, workpiece, machine, or other application-specific reference.

The terminology varies between robot manufacturers. Some controllers distinguish the robot base frame from a user frame, while others use terms such as work object, task frame, or user coordinate system.

The central purpose of a user frame is to make robot positions meaningful relative to the object being processed, rather than requiring every target to be taught relative to the robot's own base.

For example, a welding robot may need to weld the same seam on a component even when the fixture is moved or repositioned. If the component's user frame is updated correctly, the programmed targets can remain defined relative to that component.

2. Why Base and User Frames Matter

Robot programs operate using coordinate relationships. The robot controller must know where the target is and which direction the target's axes point.

The base frame provides a reference tied to the robot installation. The user frame provides a reference tied to the task.

Without a correctly defined user frame:

  • A fixture relocation may cause all process targets to shift.
  • A workpiece may be positioned correctly in the fixture but processed at incorrect locations.
  • Reusing a program for another fixture can require extensive re-teaching.
  • Position errors can be misdiagnosed as robot mastering or mechanical problems.
  • Different robots may interpret shared workpiece positions inconsistently.

A properly established frame separates the robot's installation geometry from the geometry of the workpiece.

3. Base Frame vs World Frame vs User Frame

These frames have different purposes, although their definitions can overlap.

Frame Reference Main purpose
World frame Common reference for the robot cell Describes positions across the cell
Robot base frame Robot's mechanical base Describes positions relative to an individual robot
User or work frame Fixture, workpiece, or process reference Describes application targets relative to the task
Tool frame Tool center point and tool orientation Describes the tool's position and orientation relative to the robot flange

The world and base frames may be aligned in a particular installation. A user frame may be defined relative to either the world frame, the robot base, or another supported reference, depending on the controller.

Always verify the frame hierarchy used by the actual robot system.

4. Coordinate Frame Structure

World frame
     |
     +---- Robot base frame
     |          |
     |          +---- Robot flange
     |                    |
     |                    +---- Tool frame
     |
     +---- Fixture or workpiece frame
                    |
                    +---- Process target positions

This is a conceptual relationship. The exact transformation hierarchy depends on the robot controller and application.

The controller uses the configured transformations to relate the robot's base and tool to the user frame and the targets defined within it.

5. Coordinate Axes and Origin

A Cartesian user frame contains:

  • An origin, which establishes the reference point.
  • An X-axis, which defines one direction.
  • A Y-axis, perpendicular to X.
  • A Z-axis, perpendicular to both X and Y.

The origin should be chosen using a repeatable physical feature, such as a fixture datum, locating pin, machined surface, or defined workpiece reference point.

A frame should not be chosen merely because its origin is convenient to reach. Its location and orientation must be repeatable and suitable for the process.

The axes follow the configured coordinate convention, commonly using a right-handed coordinate system.

6. Defining a User Frame

The method depends on the controller, but a user frame is typically established by identifying physical reference points or entering a known transformation.

A common conceptual three-point method uses:

  1. Origin point: Establishes the frame origin.
  2. X-direction point: Establishes the positive X direction relative to the origin.
  3. Plane point: Establishes the orientation of the XY plane and therefore the positive Y and Z directions.

The exact point-selection order and calculation vary by manufacturer.

The three reference points must be geometrically suitable. If the points are nearly collinear, the frame orientation can become poorly determined and highly sensitive to measurement errors.

Example: Fixture coordinate system

Suppose a fixture has a locating datum at its front-left reference point. The desired frame is defined as follows:

  • Origin: the locating datum.
  • Positive X: along the fixture's length.
  • Positive Y: across the fixture.
  • Positive Z: normal to the fixture's reference plane.

A target at \(X=400\text{ mm}\), \(Y=150\text{ mm}\), and \(Z=80\text{ mm}\) is then interpreted relative to that fixture frame, not directly relative to the robot base.

The meaning of those coordinates remains consistent when the fixture is relocated, provided the user-frame relationship is updated correctly and the fixture geometry itself remains unchanged.

7. Mathematical Representation

A point expressed in a user frame can be transformed into the robot base frame using the relative transformation between those frames.

The general relationship is:

\[ {}^{B}\mathbf{T}\_{T} = {}^{B}\mathbf{T}\_{U} {}^{U}\mathbf{T}\_{T} \]

Where:

  • \(B\) represents the robot base frame.
  • \(U\) represents the user frame.
  • \(T\) represents the target or tool pose.
  • \({}^{B}\mathbf{T}\_{U}\) is the user frame's pose relative to the robot base.
  • \({}^{U}\mathbf{T}\_{T}\) is the target pose expressed relative to the user frame.
  • \({}^{B}\mathbf{T}\_{T}\) is the resulting target pose relative to the robot base.

Each transformation includes the relevant translation and rotation.

7.1 Translation-only example

Assume the user-frame origin is located at:

\[ {}^{B}\mathbf{p}\_{U} = \begin{bmatrix} 1000\\\ 500\\\ 0 \end{bmatrix} \text{ mm} \]

Assume the user-frame axes are aligned with the robot base axes.

A target is located at:

\[ {}^{U}\mathbf{p}\_{T} = \begin{bmatrix} 400\\\ 150\\\ 80 \end{bmatrix} \text{ mm} \]

The target's base-frame position is:

\[ {}^{B}\mathbf{p}\_{T} = \begin{bmatrix} 1400\\\ 650\\\ 80 \end{bmatrix} \text{ mm} \]

This simple addition is valid only because the frames are aligned. If the user frame is rotated, its target coordinates must first be rotated into the base coordinate system.

8. Rotation and Orientation

A user frame defines not only where the origin is located but also how its axes are oriented.

Consider a fixture rotated by 90 degrees around the base Z-axis. A target that lies along the fixture's positive X-axis will no longer lie along the robot base's positive X-axis.

Consequently, the controller must account for both translation and rotation.

For a rotation of 90 degrees about Z, the corresponding rotation matrix is:

\[ \mathbf{R}\_Z(90^\circ) = \begin{bmatrix} 0 & -1 & 0\\\ 1 & 0 & 0\\\ 0 & 0 & 1 \end{bmatrix} \]

A user-frame position of \((400,150,80)\text{ mm}\), transformed using this rotation and the previously specified origin translation, becomes:

\[ {}^{B}\mathbf{p}\_{T} = \begin{bmatrix} 850\\\ 900\\\ 80 \end{bmatrix} \text{ mm} \]

The transformation assumes the frame's origin is at \((1000,500,0)\text{ mm}\) in the base frame and the user frame is rotated by positive 90 degrees around base Z.

This is why simply adding the user-frame coordinates to the origin is incorrect when the frame is rotated.

9. User Frames and Program Reuse

User frames make robot programs easier to adapt to different workpiece locations.

For example, a robot may perform the same drilling or dispensing pattern on several identical fixtures installed at different locations.

If the process targets are defined relative to a user frame, the program can potentially be reused by updating the user-frame transformation rather than individually changing every target.

This is useful for:

  • Fixture relocation.
  • Product variants.
  • Reusable welding paths.
  • Adhesive dispensing.
  • Robotic inspection.
  • Machine tending.
  • Repeated assembly operations.

However, program reuse is valid only if the workpiece geometry, tool configuration, target definitions, reachability, collision clearances, and process conditions remain compatible.

10. User Frames in Automotive Manufacturing

In an automotive production cell, a robot may weld a bracket on a body component located in a fixture.

A practical arrangement may include:

  1. The robot base frame, fixed to the robot installation.
  2. A user frame, defined relative to the fixture or body datum.
  3. A tool frame, defined at the welding torch's working point.
  4. Weld targets, defined relative to the selected work reference.

If the fixture is repositioned, the robot's base does not necessarily move. Instead, the transformation between the fixture and robot base may need to be updated.

A correctly configured user frame can preserve the intended relationship between the weld targets and the fixture, but the changed arrangement must be validated before production.

11. Relationship Between User Frame and Tool Frame

The user frame and tool frame solve different problems.

The user frame answers: Where is the target relative to the workpiece or fixture?

The tool frame answers: Where is the actual working point relative to the robot flange, and how is the tool oriented?

For example, the user frame describes a weld location on a component. The tool frame describes the welding torch's TCP relative to the robot flange.

Both transformations are needed to place the physical tool at the intended process target.

An incorrect user frame may displace many targets relative to the fixture. An incorrect tool frame may displace the actual tool tip relative to the programmed robot pose.

12. Common User-Frame Errors

Symptom Possible cause Diagnostic approach
All targets are shifted similarly Incorrect user-frame origin Verify the origin against the fixture datum
Position error increases along one direction Incorrect frame orientation or axis definition Check reference points and axis directions
Targets shift after fixture replacement Frame not updated for the new fixture position Verify fixture geometry and base-to-user transformation
Robot reaches correct coordinates but tool orientation is wrong Frame rotation or target orientation issue Verify the complete pose, not only XYZ
Frame definition changes unpredictably Poor reference-point geometry or inconsistent measurements Repeat the frame definition using suitable, well-separated points
Only one target is wrong Incorrect target data or local teaching error Compare the target with neighboring points and approved program data
Robot is correct on one fixture but wrong on another Incorrect fixture-specific frame or setup selection Verify the selected frame and its configuration
Position errors appear after restoration Frame configuration or calibration data changed Compare the restored data with the approved backup and records

Do not change robot mastering merely because workpiece targets are displaced. Establish which transformation is incorrect before modifying calibration-related data.

13. Troubleshooting Procedure

When a robot does not reach the intended workpiece position:

Step 1: Identify the target reference

Determine whether the target is defined in the world, base, user, or another supported frame.

Step 2: Verify the selected frame

Confirm that the program and controller are using the intended user frame, not a different frame with a similar name.

Step 3: Check the physical datum

Inspect the fixture reference point, locating features, and installation condition. Confirm that the physical datum matches the frame definition.

Step 4: Verify the frame origin and orientation

Check the recorded frame values and reference-point measurements. Confirm axis directions and units.

Step 5: Check the tool configuration

Verify the selected tool and TCP. A correct user frame cannot compensate for an incorrect tool definition.

Step 6: Compare target and actual positions

Use the controller's displayed data and approved measurement methods to determine whether the error is a consistent offset, an orientation error, or a local target error.

Step 7: Correct and validate

Make the approved correction, then verify approach paths, process positions, clearances, and the complete sequence under the appropriate safety procedure.

14. Calibration and Maintenance

A user frame is a configuration item, not merely a set of convenient coordinates.

Good maintenance practice includes:

  • Documenting the physical datum used to define each important frame.
  • Recording the origin and orientation or the controller's equivalent frame data.
  • Identifying which programs depend on the frame.
  • Backing up configuration before approved changes.
  • Verifying frame selection after controller restoration or program transfer.
  • Checking the frame after fixture relocation, replacement, or mechanical repair.
  • Recording the method used to measure and validate the frame.
  • Validating all dependent targets after significant frame changes.

Where production quality depends on precise positioning, use the plant's approved calibration and measurement process rather than relying solely on visual alignment.

15. Safety Considerations

Frame changes can cause a robot to move along a different physical path even when the program's displayed target coordinates remain unchanged.

Therefore:

  • Do not edit a production frame without authorization and change control.
  • Use the approved manual or validation procedure after changing frame data.
  • Check for collisions with fixtures, grippers, cables, tools, and neighboring equipment.
  • Do not bypass interlocks or safety functions to validate a position.
  • Verify all affected process positions and approach paths before returning the cell to production.
  • Follow lockout/tagout and other isolation requirements for work that involves hazardous energy.

A mathematically correct transformation does not guarantee a collision-free or safe trajectory.

16. Interview Questions and Answers

Q1. What is a user frame?

A coordinate frame defined relative to a workpiece, fixture, machine, or other application-specific reference to simplify target definition and robot programming.

Q2. What is the difference between a robot base frame and a user frame?

The base frame is associated with the robot's mechanical base. The user frame is associated with the task or workpiece and is defined relative to a supported reference frame.

Q3. Why are user frames useful?

They allow target positions to be defined relative to the workpiece or fixture, making programs easier to reuse when the work reference moves.

Q4. How is a user frame commonly taught?

A controller may support a three-point method using an origin, a point defining the X direction, and another point defining the frame plane. Exact procedures vary by manufacturer.

Q5. Why must the three reference points be geometrically suitable?

Poorly arranged points, particularly nearly collinear points, make the frame orientation difficult to determine accurately.

Q6. What happens if the user frame is translated but not rotated correctly?

Targets may have a systematic position or orientation error because the controller is transforming coordinates using the wrong frame relationship.

Q7. Can a user-frame change affect many robot targets?

Yes. Every target that depends on that frame may be interpreted differently after the frame changes.

Q8. How does a user frame differ from a tool frame?

The user frame describes the work reference. The tool frame describes the tool's position and orientation relative to the robot flange.

Q9. Should mastering be changed when a fixture-related position error occurs?

Not without evidence. First check the user frame, fixture datum, tool data, target values, and actual mechanical condition.

Q10. What should be checked after relocating a fixture?

Verify the fixture datum, user-frame transformation, selected frame, dependent targets, approach paths, and process positions before returning to production.

17. Practical Exercises

  • Identify the base frame and user-frame terminology used by an available robot controller.
  • Draw a robot base frame and a fixture user frame with different origins.
  • Calculate a target position in the base frame when the user frame is translated but not rotated.
  • Explain how a 90-degree rotation of the user frame changes target coordinates.
  • Identify three suitable physical features that could be used to define a fixture reference frame.
  • Diagnose a hypothetical case where every weld target is displaced by the same amount.
  • Compare the effect of an incorrect user frame with an incorrect TCP.
  • Create a configuration record listing the physical datum, frame definition, dependent program, and validation procedure.

18. Final Mental Model

The robot base frame describes positions relative to the robot installation. The user frame describes positions relative to the workpiece or fixture.

Robot base frame
       ↓
Relationship to user frame
       ↓
Target defined on workpiece
       ↓
Tool-frame transformation
       ↓
Robot calculates required joint movement
       ↓
Tool reaches the intended process location

For industrial maintenance and retrofits, the key is to identify which coordinate relationship defines the error. If multiple targets move incorrectly together, investigate their shared frame before changing individual positions or robot mastering.
