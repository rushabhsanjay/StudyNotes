Teach Pendant: Operation, Jogging, Programming, and Diagnostics

1. Definition and Purpose

A teach pendant is a handheld operator interface used to interact with an industrial robot controller. It allows authorized personnel to teach positions, jog robot axes, create and edit programs, monitor controller status, inspect alarms, and perform approved setup and recovery tasks.

The teach pendant is the operator's direct interface to the robot controller. It does not normally perform the primary servo control calculations itself. Instead, it sends commands and displays information provided by the controller.

Teach pendant layouts vary across ABB, FANUC, KUKA, Yaskawa, Kawasaki, and other manufacturers. Button names, screen layouts, menu structures, and operating procedures must be learned from the specific controller documentation.

2. Main Functions

A teach pendant commonly supports:

  • Manual robot jogging and positioning.
  • Teaching and recording robot target positions.
  • Creating, editing, selecting, and executing robot programs.
  • Selecting coordinate systems and motion types.
  • Setting or selecting tool and work frames.
  • Adjusting permitted manual or program speed settings.
  • Monitoring robot position, joint values, and controller status.
  • Viewing alarms, diagnostic messages, and program execution states.
  • Managing I/O and communication diagnostics where authorized.
  • Performing approved mastering, calibration, and recovery operations.

Access to individual functions depends on the robot model, software options, user permissions, and operating mode.

4. Teach Pendant and Robot Controller

Teach pendant Robot controller
Provides the operator interface Executes the robot control software
Sends jogging and programming commands Calculates and coordinates motion
Displays program and alarm information Processes feedback and monitors motion
Allows authorized changes to program data Stores and applies controller configuration
Provides controls for approved manual operation Coordinates axes, I/O, and external communication

A pendant can display an alarm without being the source of the fault. For example, a servo-drive failure may be reported on the pendant even though the underlying problem is in the drive, motor, feedback wiring, or mechanical system.

5. Operating Modes

Industrial robots commonly provide manual and automatic operation modes, with specific variants depending on the manufacturer.

Mode General purpose Typical characteristics
Manual or teach Teaching, jogging, and setup Operator-controlled movement under specified restrictions
Manual reduced speed Setup and teaching at restricted speed where supported Limits movement speed according to the configured safety system
Manual high speed Available on certain systems and under specific conditions Requires strict adherence to manufacturer and site procedures
Automatic Production-cycle execution Program and external equipment coordinate the cycle
Recovery or maintenance state Authorized recovery and service tasks Availability and restrictions vary by system

Do not assume all robots offer the same modes or use the same terminology. The selected mode, enabling device, speed restriction, protective devices, and controller state jointly determine whether an action is permitted.

6. Enabling Device and Emergency Stop

These are two distinct safety-related controls.

6.1 Enabling device

A three-position enabling device is common on industrial robot teach pendants. Its usual operating principle is:

  • Released position: movement permission is not granted.
  • Middle position: movement permission may be granted when all other required conditions are satisfied.
  • Fully squeezed position: movement permission is removed.

The exact behavior and implementation must be confirmed from the specific robot's safety documentation.

Never tape, wedge, defeat, or bypass an enabling device. It is intended to reduce the risk of unintended movement while an operator is in a manual operating situation.

6.2 Emergency stop

The emergency-stop button requests the configured emergency-stop response. It is not necessarily a substitute for lockout/tagout or verified energy isolation.

Before working on equipment, follow the plant's safety procedure and the machine-specific risk assessment.

7. Coordinate Selection for Jogging

A teach pendant may let the operator jog the robot in joint coordinates or in a Cartesian coordinate system.

7.1 Joint coordinate jogging

Each robot axis is commanded individually.

For a typical six-axis articulated robot:

  • J1 commonly rotates the base.
  • J2 and J3 commonly position the arm.
  • J4, J5, and J6 commonly orient the wrist and tool.

The exact joint functions depend on the robot's mechanical design.

Joint jogging is useful for checking individual axes, approaching positions, and investigating certain motion problems.

7.2 Cartesian jogging

The operator commands tool or reference-frame movement along coordinate directions, often represented as X, Y, and Z, with corresponding rotational directions.

Cartesian jogging can be useful when approaching a fixture or moving a tool along a process direction. The controller converts the requested tool movement into coordinated joint movement.

7.3 Coordinate systems compared

Jogging reference What the commands represent Common application
Joint coordinates Individual axis movement Checking or repositioning specific axes
World coordinates Movement relative to the configured world reference General cell positioning
Base coordinates Movement relative to the robot base reference Robot-relative positioning
Tool coordinates Movement relative to the selected tool orientation Moving along the tool's approach or process direction
Work or user coordinates Movement relative to a defined fixture or workpiece frame Teaching process positions

Available coordinate options vary by manufacturer and configuration. World, base, and work frames are not necessarily identical.

8. Jogging Speed and Override

Teach pendants commonly provide a means of selecting or adjusting permitted jogging speed. Some controllers also expose program speed override.

These are related but different concepts:

  • Jog speed: Controls the rate of commanded manual movement, subject to the controller and safety restrictions.
  • Program speed: Relates to the speed programmed for an automatic or manual program execution.
  • Speed override: Scales the programmed speed within the controller's allowed operating limits.

For example, a program may specify a tool speed of \(500\ \text{mm/s}\). A 50% override might request a lower operating speed, but the actual motion depends on the controller, trajectory, acceleration limits, and other constraints.

A displayed override percentage is not proof that a safety-rated speed limit is being enforced. Safety-rated speed monitoring, where required, is a separate safety function.

9. Teaching Robot Positions

Teaching means defining and storing target positions for the robot program.

A typical teaching procedure involves:

  1. Verify the correct operating mode and required safety conditions.
  2. Confirm the selected tool and coordinate frame.
  3. Move the robot to the required target using the approved jogging procedure.
  4. Verify tool orientation, clearance, and approach direction.
  5. Record the position using the controller's teaching function.
  6. Confirm that the correct program instruction and target data were updated.
  7. Validate the taught position and motion sequence under the approved procedure.

A taught target may contain Cartesian position and orientation, joint values, configuration information, or a combination determined by the controller's programming model.

9.1 Why correct tool data matters

The robot controller must know the relationship between the robot mounting flange and the actual working tool.

If the TCP is wrong, the pendant may show an apparently reasonable robot position while the physical tool tip is displaced from the intended point.

Before teaching production positions, verify the correct tool data and the applicable work frame.

9.2 Why correct work-frame data matters

A work frame establishes the coordinate reference associated with a fixture or workpiece. If the frame is incorrect, several taught positions may all be displaced in a similar direction.

This can make a frame error look like multiple incorrect teaching points.

10. Program Editing Through the Teach Pendant

The pendant commonly supports viewing and modifying robot programs.

Typical program elements include:

  • Motion instructions.
  • Position or target data.
  • Tool and work-frame selection.
  • Speed and acceleration settings.
  • Input and output commands.
  • Wait conditions.
  • Conditional branches and loops.
  • Subroutine calls.
  • Program start, stop, and recovery operations.

A simplified conceptual program is:

Select program
     ↓
Check start conditions
     ↓
Move to approach target
     ↓
Wait for fixture confirmation
     ↓
Move to process target
     ↓
Perform the process operation
     ↓
Verify completion condition
     ↓
Move to the next target
     ↓
Report cycle completion

This is a conceptual sequence, not executable robot code.

10.1 Program modification discipline

Before modifying an existing production program:

  • Confirm the correct robot, controller, program, and revision.
  • Obtain authorization and establish the approved machine state.
  • Make an approved backup or controlled copy.
  • Identify dependencies such as PLC handshakes, tool data, and work frames.
  • Change only the intended instructions or data.
  • Test using the authorized procedure and required safety controls.
  • Record the change and validation results.

Changing a position instruction can affect collision clearance, cycle time, process quality, and coordination with surrounding equipment.

11. I/O Monitoring and Diagnostics

A pendant may provide a screen for viewing digital inputs, outputs, and communication-related signals.

Typical examples include:

  • Part present.
  • Fixture clamped.
  • Robot start request.
  • Robot ready.
  • Cycle complete.
  • Robot fault.
  • Gripper open or closed.
  • Process ready.

When a robot is waiting for a condition, identify the exact signal the program expects.

A useful diagnostic chain is:

Physical sensor or PLC condition
          ↓
Electrical signal or fieldbus data
          ↓
Robot controller I/O mapping
          ↓
Program condition
          ↓
Program continues or remains waiting

If the pendant shows the input as false, determine whether the physical condition is absent, the sensor or wiring is faulty, or the signal is incorrectly mapped. If the pendant shows the input as true but the program remains waiting, inspect the exact program condition and any additional required conditions.

Do not force outputs or bypass interlocks merely to make a sequence proceed. Any approved test must preserve the safety of personnel and equipment.

12. Alarm Display and Troubleshooting

The teach pendant is often the first place an operator sees a robot alarm.

Symptom Possible causes Initial diagnostic action
Pendant screen is blank Pendant power, cable, connection, or hardware problem Check approved connection and controller status
Pendant cannot communicate Damaged cable, connector, interface, or controller issue Inspect diagnostics and connection status
Jogging is unavailable Incorrect mode, enabling-device condition, active fault, or other restriction Read the controller state and permitted-operation conditions
Robot will not start Program selection, start conditions, active fault, or external permission Check program status and start requirements
Program remains waiting Missing input, PLC handshake, process condition, or timer Identify the active wait instruction and expected condition
Robot position appears incorrect Wrong tool, frame, mastering, or target data Verify configuration and calibration records
A particular axis faults Drive, feedback, wiring, mechanical, or limit-related issue Review axis-specific diagnostics
Program stops at the same point Repeatable condition failure, collision, motion limit, or program logic issue Inspect the exact instruction and recorded fault

Always record the full alarm text and controller model. Alarm numbers and recovery procedures are manufacturer- and version-specific.

13. Manual Operation Versus Automatic Operation

Aspect Manual or teach operation Automatic operation
Movement initiation Operator commands or authorized teaching actions Program and cell logic initiate motion
Primary purpose Setup, teaching, diagnosis, recovery Production execution
Typical control interface Teach pendant PLC, HMI, robot program, or cell controller
External coordination Often used for setup and testing Usually integrated with production handshakes
Main concern Controlled movement near equipment Safe, coordinated execution of the production cycle

The robot may remain in automatic mode while stopped or waiting. Conversely, selecting manual mode does not automatically guarantee that every manual operation is permitted.

14. Common Maintenance Scenarios

Scenario 1: Robot is ready, but jogging does not work

Check the operating mode, enabling-device condition, active faults, configured restrictions, and controller messages. Do not assume the servo system has failed simply because jogging is unavailable.

Scenario 2: Robot jogs, but the tool moves in an unexpected direction

Check the selected coordinate system, tool orientation, frame selection, and axis configuration. If movement is unexpected or unsafe, stop according to the approved procedure and investigate before continuing.

Scenario 3: Robot reaches the target, but the component is misplaced

Check TCP calibration, work-frame data, fixture location, target values, and robot mastering or calibration history. Determine whether the error affects one point or many points before changing configuration.

Scenario 4: Program stops at a wait instruction

Read the active instruction, identify the expected input or condition, and trace it through the PLC, sensor, wiring, or network mapping.

Scenario 5: Pendant displays a drive fault

Record the complete diagnostic message and affected axis. Follow the controller and drive manufacturer's diagnostic procedure. Do not repeatedly reset the fault without identifying the cause.

Scenario 6: Pendant cable is damaged

Remove the equipment from service as required by site procedures. Have the cable or pendant inspected and replaced using the approved method. Do not improvise repairs that compromise electrical or safety functions.

15. Preventive Maintenance

Teach pendant maintenance should be performed according to manufacturer guidance and plant procedures.

  • Inspect the housing, screen, buttons, and jog controls for physical damage.
  • Inspect the cable and connector for cuts, crushing, loose connections, and excessive strain.
  • Verify that the enabling device and emergency-stop controls are intact and functioning according to the prescribed test procedure.
  • Keep the screen and controls clean using approved materials.
  • Check for intermittent connection faults and recurring pendant communication alarms.
  • Verify that the pendant is stored safely when not in use.
  • Maintain controlled records of program and configuration changes made through the pendant.
  • Confirm that required safety checks are completed after relevant repairs.

Never continue using a pendant with a damaged enabling device, emergency-stop control, or other safety-related component.

16. Interview Questions and Answers

Q1. What is a teach pendant?

A handheld interface used to jog, teach, program, monitor, and diagnose an industrial robot through its controller.

Q2. Does the teach pendant control the servo motors directly?

Normally, it sends commands to the robot controller. The controller and servo system handle the motion-control functions.

Q3. What is the difference between joint and Cartesian jogging?

Joint jogging commands individual robot axes. Cartesian jogging commands movement relative to a selected coordinate system, with the controller calculating coordinated joint motion.

Q4. What is the purpose of an enabling device?

It provides an intentional manual-operation permission under specified conditions. It is part of the safety design and must not be defeated.

Q5. What is the difference between a tool frame and a work frame?

The tool frame describes the tool's position and orientation relative to the robot mounting reference. The work frame describes a reference associated with a fixture, workpiece, or process area.

Q6. Why might a robot program remain waiting even when the robot is ready?

The program may require an external input or another condition that has not become true.

Q7. What is speed override?

It scales the programmed motion speed within the controller's permitted limits. It is not automatically equivalent to a safety-rated speed restriction.

Q8. What should be checked before teaching a new position?

The correct robot, program, operating mode, tool, work frame, approach direction, clearance, and applicable safety conditions.

Q9. Why should production programs be backed up before editing?

To preserve a known version for controlled comparison and recovery if the modification introduces a fault.

Q10. Can the same teach pendant procedure be used on every robot brand?

No. Operating modes, menus, syntax, safety functions, and recovery procedures vary by manufacturer and controller version.

Q11. What should be recorded when an alarm appears?

The full alarm message, controller model, affected axis if applicable, program and instruction, operating state, relevant I/O conditions, and recent changes.

Q12. Why should a technician avoid changing mastering to correct every position error?

The underlying cause may be incorrect tool or work-frame data, target data, or a mechanical issue. Unnecessary mastering changes can create additional position errors.

17. Practical Exercises

  • Identify the pendant display, jog controls, enabling device, emergency-stop button, and connection cable on an available robot.
  • Find the current controller state, active program, and diagnostic history without changing operating conditions.
  • Compare joint jogging with Cartesian jogging in an approved training environment.
  • Identify the currently selected tool and work frame and explain how each affects a taught target.
  • Inspect a robot program and identify motion instructions, waits, I/O commands, and subroutine calls.
  • Trace a PLC handshake input from its source to the program condition displayed on the pendant.
  • Create a diagnostic record for a simulated missing-input condition.
  • Review the plant's approved pendant inspection and safety-function test procedures.

18. Final Mental Model

The teach pendant is the operator's interface to the robot controller. It allows a trained and authorized person to specify what the robot should do, observe what the controller reports, and investigate why the expected operation has not occurred.

Operator action
      ↓
Teach pendant
      ↓
Robot controller
      ↓
Program execution and motion control
      ↓
Servo drives and robot movement
      ↓
Feedback and diagnostic status
      ↓
Information displayed on the pendant

For industrial maintenance, the essential skill is to distinguish an operator-interface problem from a controller problem, a motion problem, an incorrect frame or target, a missing PLC signal, or a safety-related restriction. That distinction helps resolve faults without introducing unnecessary changes to a working robot cell.
