Motion Types: PTP, Linear, Circular

1. Introduction to Robot Motion Types

Industrial robot motion types define how the robot moves from its current pose to a commanded target pose. The selected motion type affects the path followed by the tool, cycle time, smoothness, process quality, collision risk, and coordination with other equipment.

The three fundamental motion types are:

  • PTP (Point-to-Point): The robot moves between target poses without guaranteeing a specific straight-line path for the tool.
  • Linear (LIN): The tool center point follows a straight-line path in Cartesian space, subject to the controller's motion constraints.
  • Circular (CIRC): The tool center point follows a circular arc defined by suitable geometric points or controller-specific parameters.

These motion types are available in many industrial robot systems, although the exact names, syntax, interpolation methods, and motion-planning behavior differ between manufacturers.

2. Robot Pose and Motion Fundamentals

Before comparing motion types, distinguish a robot's pose from its path.

A pose defines a position and orientation. A robot target generally specifies where the TCP should be and how the tool should be oriented.

The position is represented by three coordinates:

  • X: Position along the X-axis.
  • Y: Position along the Y-axis.
  • Z: Position along the Z-axis.

The orientation specifies the tool's rotational alignment, using the controller's supported convention.

A path describes the sequence of positions and orientations followed between two poses.

Starting pose
     ↓
Motion planning
     ↓
Robot joint commands
     ↓
Robot movement
     ↓
Target pose

The controller uses inverse kinematics and trajectory planning to determine how the robot's joints should move. Joint limits, speed limits, acceleration limits, singularities, collision constraints, and controller-specific settings can influence the resulting motion.

Two programs can use the same start and target poses but produce different paths because they use different motion types.

3. PTP Motion: Point-to-Point

3.1 Definition

PTP motion commands the robot to move from its current pose to a target pose while prioritizing point-to-point movement rather than a prescribed Cartesian path.

The controller plans the motion through the robot's joint space or using a manufacturer-specific equivalent. The resulting TCP trajectory is generally not guaranteed to be a straight line.

PTP is commonly used for transfers between work areas, approaching a station, moving to a safe intermediate position, or repositioning the robot when the exact path between the endpoints is not process-critical.

3.2 Operating Principle

The robot controller determines a feasible joint configuration for the target. It then plans coordinated joint motion according to its trajectory-generation rules.

Start pose
    ↓
Calculate target joint configuration
    ↓
Plan joint movement
    ↓
Coordinate robot axes
    ↓
Reach target pose

The actual trajectory depends on the robot's kinematics, selected motion settings, controller, and active configuration.

A PTP command should not be interpreted as permission for an arbitrary path. The planned movement still needs to respect the robot's programmed limits and applicable safety constraints, but the TCP path between the endpoints is not inherently straight.

3.3 Characteristics

  • Often efficient for non-process transfers.
  • May reduce cycle time when the controller can use suitable joint trajectories.
  • Can produce curved or otherwise non-linear TCP movement.
  • May involve substantial changes in several robot axes simultaneously.
  • Requires checking intermediate clearance, not just the start and end poses.
  • Does not inherently maintain a constant TCP speed along a Cartesian line.

3.4 Example

A robot picks a component from a conveyor and transfers it toward an assembly fixture.

If the robot only needs to reach a safe approach pose near the fixture, PTP may be appropriate. The exact path may not matter as long as it clears all equipment and the process requirements are met.

However, moving directly from the pickup point to a placement point using PTP may be unsafe if the robot swings through a fixture, conveyor, or nearby machine.

3.5 PTP Is Not the Same as Moving One Joint

A PTP command generally coordinates multiple axes to reach a target. It does not mean that only one joint moves.

The controller may move several joints concurrently according to its planning method. Some systems also provide explicit joint-target commands, which are related but not identical to Cartesian target commands.

A Cartesian target used with PTP may still specify a target TCP pose. The distinction is in how the motion between the endpoints is planned.

4. Linear Motion: LIN

4.1 Definition

Linear motion commands the robot to move its TCP along a straight-line Cartesian path between the current pose and a target pose.

The controller calculates the corresponding joint movement needed to follow that path while satisfying the robot's kinematic and motion constraints.

Linear motion is commonly used where the tool must approach, contact, follow, or leave a surface along a controlled trajectory.

4.2 Operating Principle

The controller generates intermediate TCP positions along a straight line and calculates the required robot configurations.

For a straight path between positions \(P_0\) and \(P_1\), the position along the path can be expressed as:

\[ P(s) = P_0 + s(P_1-P_0) \]

where \(s\) ranges from 0 to 1.

  • \(s=0\): Starting position.
  • \(s=1\): Target position.
  • Intermediate values: Positions along the straight line.

The orientation is planned according to the controller's interpolation convention. A straight-line TCP position path does not automatically mean that all orientation angles change linearly in the same way.

4.3 Characteristics

  • Maintains a straight Cartesian TCP position path between the programmed endpoints, subject to the controller's path and tolerance behavior.
  • Useful for controlled approaches and retracts.
  • Common in welding, dispensing, insertion, and other process operations.
  • Requires the robot to remain kinematically capable of following the requested path.
  • May require slower speeds or additional planning near singularities or joint limits.
  • Can take longer than PTP for the same endpoints.

4.4 Example: Vertical Insertion

A robot must insert a component vertically into a fixture.

A linear motion can keep the TCP on a straight insertion path, reducing unintended lateral movement of the tool reference during the insertion segment.

The correct TCP and work frame are essential. If either is incorrect, the robot can follow a mathematically straight path that is physically misaligned with the fixture.

4.5 Constant Speed and Linear Path Are Different Concepts

A linear motion defines the intended Cartesian path, but it does not guarantee constant speed under every condition.

Actual speed can be affected by:

  • Programmed speed.
  • Acceleration and deceleration settings.
  • Motion blending.
  • Singularities.
  • Joint limits.
  • Controller-specific path tolerances.
  • External-axis coordination.

A process requiring tightly controlled speed must use the controller's appropriate process-motion settings and be validated under real operating conditions.

5. Circular Motion: CIRC

5.1 Definition

Circular motion commands the TCP to follow a circular arc between programmed positions.

The controller generally requires enough geometric information to define the arc, such as a starting point, an intermediate point, and an endpoint. Other controllers may use different combinations of points, radius, center, or direction parameters.

The exact command syntax is manufacturer-specific.

5.2 Operating Principle

A circular path is defined by a center, radius, and angular position in the relevant plane.

For a circle in a two-dimensional plane:

\[ x(\theta)=x_c+r\cos(\theta) \]
\[ y(\theta)=y_c+r\sin(\theta) \]

where:

  • \(x_c,y_c\) are the circle center coordinates.
  • \(r\) is the radius.
  • \(\theta\) is the angular position along the arc.

A three-dimensional circular path lies in a plane in Cartesian space. The controller uses the programmed geometric data to determine the arc and calculate the corresponding robot movement.

5.3 Characteristics

  • Maintains a circular TCP position path along the specified arc, subject to controller behavior and tolerances.
  • Useful for curved process paths and rounded contours.
  • Requires valid geometry to define the intended arc.
  • Can be more sensitive to incorrect points or frame data than a simple point-to-point transfer.
  • May encounter joint limits or singularities along the arc even when both endpoints are reachable.
  • Requires correct handling of arc direction and intermediate points.

5.4 Example: Circular Dispensing

A robot must apply sealant around a circular feature.

Circular motion can follow the required arc while the controller manages the robot joints. The application still needs the correct TCP, work frame, nozzle orientation, speed, and dispensing synchronization.

If the intermediate point is incorrectly taught, the controller may generate an unintended arc or reject the motion because the points do not define a valid circle.

5.5 Circular Motion Is Not Always a Complete Circle

A circular motion command usually describes an arc segment, not necessarily a full 360-degree circle.

A full circular path may require multiple arc segments or a controller-specific full-circle command. Some systems require a distinct endpoint and intermediate point arrangement.

Always check the specific controller's rules for arc definition, direction, and full-circle programming.

7. Motion Speed, Acceleration, and Deceleration

Motion type determines the path-planning behavior, while speed and acceleration settings determine how the robot traverses that path.

A robot program may specify different speeds for PTP, linear, and circular movements. The meaning and units of the speed setting vary by controller.

Typical concepts include:

  • Joint speed: Rate of movement of a robot joint, commonly expressed as angular speed.
  • Cartesian speed: TCP linear speed, commonly expressed in mm/s or another distance-per-time unit.
  • Acceleration: Rate of change of velocity.
  • Deceleration: Reduction of velocity as the robot slows down.
  • Jerk: Rate of change of acceleration, relevant to motion smoothness and mechanical loading.

A PTP move may use joint-oriented speed parameters, while linear and circular moves commonly use TCP speed parameters. This is a general pattern, not a universal programming rule.

The controller may automatically limit motion to satisfy joint-speed, acceleration, reachability, or other constraints.

Why Excessive Speed Is a Problem

Excessive speed can lead to:

  • Larger stopping distances.
  • Higher dynamic loads.
  • Increased vibration.
  • Reduced process quality.
  • Greater collision consequences.
  • Inaccurate results if the tool, part, or fixture deflects.

Speed settings should be selected according to the process, robot capabilities, risk assessment, and validated operating conditions.

8. Blending and Path Continuity

Many robot controllers support blending between consecutive movements.

Blending allows the robot to transition between target segments without necessarily stopping at every programmed point. The controller may deviate from the exact target or path within its configured tolerance.

For example:

Target A → Target B → Target C

Without blending, the robot may decelerate or stop at B, depending on the motion and controller settings.

With blending, the controller may begin transitioning toward C before reaching B exactly, allowing a smoother and potentially faster trajectory.

Important: Blending can change the actual path near a programmed target. It must not be assumed that every programmed point is reached exactly when blending is active.

When Blending Is Useful

  • Non-critical transfer paths.
  • Smooth movement between process segments.
  • Reducing cycle time.
  • Avoiding unnecessary stops that affect process quality.

When Exact Positioning May Be Required

  • Component insertion.
  • Tight-tolerance inspection.
  • Precise pick or place positions.
  • Tool engagement with a feature.
  • Operations where the robot must settle at a defined pose.

The exact-point behavior and blending syntax differ by controller.

9. Path Accuracy, Repeatability, and Process Quality

Motion type alone does not determine process accuracy.

Important factors include:

  • TCP calibration.
  • Work-frame calibration.
  • Robot mechanical condition.
  • Robot repeatability and absolute accuracy.
  • Tool rigidity.
  • Payload configuration.
  • Programmed speed and acceleration.
  • Motion blending and controller tolerances.
  • Workpiece location and fixture repeatability.
  • External-axis configuration.
  • Process-specific requirements.

A linear path can be mathematically correct but physically displaced if the work frame is incorrect. A circular path can be geometrically correct but have the wrong radius if the taught points are inaccurate.

For demanding processes, verify the path using suitable measurement methods and actual production conditions.

10. Robot Motion and Inverse Kinematics

Robot targets are often programmed in Cartesian coordinates, but the robot moves using its joints.

Inverse kinematics determines which joint configurations can achieve a specified TCP pose.

The same Cartesian pose may have multiple valid joint configurations on some robot designs. The controller selects a feasible solution according to its algorithms, current configuration, and programmed constraints.

Motion feasibility depends on:

  • Joint limits.
  • Robot reach.
  • Wrist and arm configuration.
  • Singularities.
  • Tool and workpiece geometry.
  • External axes, if present.
  • Controller motion-planning rules.

A target may be reachable while the path leading to it is not feasible. This is particularly important for linear and circular motions because they constrain the TCP path between targets.

11. Singularities and Motion-Type Selection

A robot singularity is a configuration where the robot loses one or more effective Cartesian motion capabilities or where small Cartesian movements can require very large joint movements.

Near a singularity, the controller may slow down, alter motion behavior within its allowed rules, issue a warning, or reject a requested path.

Common considerations include:

  • Wrist singularities.
  • Arm or elbow singularities.
  • Workspace boundary conditions.

Linear and circular motions can be affected when the requested Cartesian path passes through or near a singularity. PTP motion can also encounter joint configurations or motion limitations.

Do not attempt to resolve a singularity merely by increasing speed or relaxing motion settings. Review the robot configuration, target poses, path, and applicable manufacturer guidance.

12. Choosing the Appropriate Motion Type

Use the process requirement to determine the motion type rather than choosing solely on the basis of speed.

Requirement Typical starting choice Reason
Transfer between safe intermediate poses PTP Exact intermediate TCP path may not be critical
Straight insertion into a fixture Linear Requires a controlled straight TCP path
Straight welding or dispensing segment Linear Follows a straight process path
Curved or circular process segment Circular Follows a defined arc
Move through a region with limited clearance Carefully planned linear or circular path, or validated PTP path Path must be checked against obstacles
Approach a part precisely Often linear for the final approach Supports controlled direction of approach
Move quickly away from a process area PTP may be suitable if the entire path is safe Allows efficient repositioning

The best choice depends on the application, robot configuration, tool orientation, surrounding equipment, and validated trajectory.

14. Practical Industrial Example

Consider a robot that picks a component from a conveyor, transfers it to an assembly fixture, inserts it, and applies sealant along a curved edge.

A possible motion strategy is:

Pickup approach
    ↓
Linear movement to grasp position
    ↓
Grasp component
    ↓
PTP transfer to a safe approach region
    ↓
Linear insertion into fixture
    ↓
Linear movement to process start
    ↓
Circular movement along curved sealant path
    ↓
Linear retract from process area
    ↓
PTP transfer to the next station

This is only an illustrative sequence. Actual motion selection depends on the part, gripper, fixture geometry, process requirements, controller behavior, and safety validation.

A production program must also coordinate gripper control, process enable signals, station interlocks, completion checks, and fault handling. Motion commands alone do not constitute a complete automation sequence.

15. Safety and Validation

Robot motion must be validated as a complete trajectory, not just as a collection of safe endpoints.

Before releasing a program to production:

  • Confirm the active TCP and work frame.
  • Check all targets and intermediate path segments.
  • Verify the tool and payload configuration.
  • Confirm adequate clearance from fixtures, conveyors, guarding, and other equipment.
  • Review speed, acceleration, blending, and stopping behavior.
  • Check for joint limits, singularities, and external-axis constraints.
  • Test using the approved commissioning and recovery procedure.
  • Verify process timing and machine interlocks.
  • Record validated program and configuration revisions.

Simulation is useful for identifying potential path problems, but it cannot replace physical validation. Real tool geometry, mounting errors, cables, hoses, part variation, and mechanical deflection can create conditions not represented accurately in the simulation.

Never bypass protective functions to test a motion path.

16. Manufacturer-Specific Terminology

The concepts are broadly consistent across industrial robot platforms, but the exact motion names and programming syntax vary.

These are general associations, not complete command references. Exact names, parameters, speed conventions, and blending behavior depend on the controller and software version.

17. Interview Questions and Answers

Q1. What is PTP motion?

PTP motion moves the robot between target poses without guaranteeing that the TCP follows a straight Cartesian path between them.

Q2. What is linear motion?

Linear motion commands the TCP to follow a straight-line Cartesian position path between programmed endpoints, subject to the controller's constraints and tolerances.

Q3. What is circular motion?

Circular motion commands the TCP to follow a defined circular arc using the geometric information required by the controller.

Q4. Why is PTP often used for transfer movements?

Because the exact Cartesian path may not be process-critical, and the controller can plan an efficient joint-coordinated movement between the endpoints.

Q5. Why is linear motion useful for insertion?

It allows the TCP to follow a straight approach or insertion path, helping reduce unintended lateral movement during engagement.

Q6. Why does circular motion require suitable intermediate geometry?

The controller needs enough information to determine the intended arc. Invalid or poorly selected points can define an incorrect arc or make the motion infeasible.

Q7. Does linear motion guarantee constant speed?

No. It specifies the intended Cartesian path, while speed can vary due to acceleration, deceleration, blending, singularities, and controller constraints.

Q8. What is blending?

Blending allows smoother transitions between consecutive motions, often reducing stops but potentially deviating from exact programmed points within configured tolerances.

Q9. Can a reachable target still be unreachable using linear motion?

Yes. The target may be reachable while the required straight path passes through a singularity, joint limit, or infeasible robot configuration.

Q10. What is the difference between joint-space and Cartesian motion?

Joint-space motion describes movement in robot joint coordinates. Cartesian motion describes the TCP's movement in three-dimensional position and orientation space.

Q11. Does PTP mean only one robot joint moves?

No. PTP commonly coordinates multiple robot joints to reach the target. It does not imply movement of only one joint.

Q12. Why must motion paths be checked even when the endpoints are safe?

Because the tool or robot links may collide with fixtures, guarding, or other equipment while moving between those endpoints.

18. Practical Exercises

Exercise 1: Choose the Motion Type

Choose a suitable starting motion type for each operation and justify the choice.

  • Transfer a component between two open areas.
  • Insert a pin into a close-fitting hole.
  • Apply sealant along a straight seam.
  • Follow a circular contour around a machined feature.
  • Retract a tool from a fixture before transferring to another station.

Exercise 2: Diagnose an Unexpected Path

A robot program uses PTP to move from a pickup pose to a placement pose. The endpoints are correct, but the gripper swings close to a fixture during the transfer.

Explain why the path can differ from the straight line between the endpoints and identify how you would review and correct the motion safely.

Exercise 3: Diagnose an Incorrect Arc

A circular movement is rejected by the controller after an intermediate point is edited.

Identify the geometric and configuration checks required to determine whether the programmed points define a valid arc.

Exercise 4: Compare Path and Speed

A robot follows the correct linear path but produces inconsistent dispensing quality.

List the other factors to check, including TCP calibration, speed behavior, process timing, payload, tool orientation, and material delivery.

Exercise 5: Build a Motion Sequence

Develop a motion sequence for a robot that picks a component, transfers it, inserts it into a fixture, and follows a circular inspection path.

Identify where PTP, linear, and circular motion may be appropriate, and list the safety and process conditions that must be validated.

19. Final Mental Model

PTP, linear, and circular motion describe different ways of moving a robot between programmed targets.

  • PTP: Prioritizes movement between target poses. The TCP path is not guaranteed to be straight.
  • Linear: Controls the intended straight-line TCP position path.
  • Circular: Controls the intended circular TCP position path along a defined arc.

Motion type must be selected according to the process, path geometry, robot capabilities, and clearance requirements. Speed, acceleration, blending, TCP configuration, work-frame accuracy, and robot kinematics determine how the motion behaves in practice.

A reliable robot program does not merely reach the correct endpoints. It follows a suitable, validated path while meeting process, accuracy, cycle-time, and safety requirements.
