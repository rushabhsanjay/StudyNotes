1. Definition and Purpose

An HMI trend is a graphical representation of how one or more process variables change over time.

Trends help operators and maintenance engineers understand not only the current value of a variable, but also its behavior before, during, and after an event.

Examples of values commonly displayed on industrial trends include:

  • Motor speed and current.
  • Hydraulic or pneumatic pressure.
  • Process temperature.
  • Cycle time.
  • Conveyor speed.
  • Production count.
  • Tank level.
  • Robot cycle duration.
  • Equipment downtime.
  • Analog sensor measurements.

For example, a motor may currently show a normal current of 8 A. A trend might reveal that its current has gradually increased from 5 A to 8 A over several days. That pattern could justify investigating increasing mechanical load, bearing friction, alignment, or another underlying cause.

The current value alone would not reveal that history.

The main purposes of HMI trends are to:

  1. Observe process behavior over time.
  2. Identify abnormal variations and recurring patterns.
  3. Compare multiple process variables.
  4. Investigate faults and production interruptions.
  5. Monitor cycle time and process performance.
  6. Support preventive and condition-based maintenance.
  7. Verify whether a corrective action improved performance.

A trend is a diagnostic tool. It does not automatically identify the root cause of a problem.

2. Basic Trend Architecture

A trend depends on process data being acquired and displayed over time.

                 |

                 |
                 v
          Trend Data Storage
                 |
                 v
           HMI Trend Chart
                 |

The actual architecture depends on the platform.

Some HMIs display recently acquired values directly from memory. Others store samples in a local archive or database to support historical trends. SCADA systems may use a centralized historian to store data from multiple PLCs and production lines.

Important: A trend chart and a historical data archive are not the same thing. A chart can display live data without retaining it for long-term analysis.

3. Live Trends Versus Historical Trends

3.1 Live Trend

A live trend displays values as new samples arrive.

Typical uses include:

  • Observing motor current during startup.
  • Monitoring pressure during a machine cycle.
  • Watching temperature during a heating process.
  • Checking drive speed during acceleration.
  • Observing a sensor signal during commissioning.

Example:

Time Motor current
10:00:00 2.1 A
10:00:01 4.8 A
10:00:02 7.2 A
10:00:03 6.9 A
10:00:04 6.8 A

The values illustrate a motor current rising during startup and settling afterward.

A live trend is particularly useful when the engineer needs to observe a process while it is happening.

3.2 Historical Trend

A historical trend displays previously recorded data.

Typical uses include:

  • Comparing process conditions before and after a breakdown.
  • Investigating intermittent faults.
  • Comparing production shifts.
  • Reviewing temperature or pressure excursions.
  • Examining long-term motor-current changes.
  • Verifying the effect of a maintenance intervention.

Historical trends require the relevant data to have been retained. If the system did not record the data, a chart cannot reconstruct the missing measurements merely because someone now wants a graph. Technology remains annoyingly literal about this.

3.3 Comparison

Feature Live trend Historical trend
Main purpose Observe current behavior Investigate past behavior
Data source Recent acquired samples Previously stored samples
Typical time range Seconds or minutes Minutes, hours, days, or longer
Requires historical archive Not always Yes, for the period being reviewed
Typical use Commissioning and live diagnosis Root-cause analysis and long-term monitoring

An HMI can support both types of trends in the same application.

4. What Is a Trend Pen?

A trend pen is a plotted data series representing one variable on a trend chart.

For example, a chart may contain three pens:

  • Motor_Speed_PV
  • Motor_Current_PV
  • Drive_Temperature_PV

Each pen represents one variable over the selected time range.

A trend pen typically has configuration properties such as:

Property Purpose
Tag or data source Identifies the variable
Pen name Describes the plotted signal
Color or visual style Distinguishes one series from another
Engineering unit Identifies the measurement unit
Value range Defines the displayed scale where configured
Sampling or logging settings Determines how data is acquired or retained
Display visibility Controls whether the series appears on the chart

The term "pen" comes from traditional chart recorders, where a physical pen traced a measurement on moving chart paper. Modern software performs the equivalent function digitally.

5. Understanding Trend Axes

A typical trend chart has two main axes.

X-axis: Time

The horizontal axis represents time.

Examples:

  • Last 30 seconds.
  • Last 10 minutes.
  • Current production cycle.
  • Previous shift.
  • Last 24 hours.

Y-axis: Process value

The vertical axis represents the measured variable.

Examples:

  • Motor current in amperes.
  • Temperature in degrees Celsius.
  • Pressure in bar.
  • Speed in RPM.
  • Cycle time in seconds.

6. Trend Sampling and Update Rate

A trend requires values to be acquired at appropriate intervals.

Suppose motor current is sampled once per second:

Time Current
12:00:00 4.0 A
12:00:01 5.0 A
12:00:02 8.0 A
12:00:03 7.0 A

The trend plots the acquired samples. If the current rises sharply and falls between samples, the peak may not be captured.

Sampling interval

The sampling interval is the time between acquired samples.

Examples:

  • 100 ms.
  • 500 ms.
  • 1 second.
  • 5 seconds.
  • 1 minute.

The appropriate interval depends on the process and the event being investigated.

Application Sampling considerations
Slow temperature process A relatively slow interval may be sufficient
Tank-level monitoring Depends on how quickly the level can change
Motor current during startup A faster interval may be necessary
Rapid servo motion Ordinary HMI trends may be too slow for detailed motion analysis
Production counts Sampling can often be slower if the PLC maintains an accurate counter
Long-term energy monitoring Periodic samples or accumulated values may be suitable

These are general considerations, not universal interval recommendations.

Important distinction: scan time, update rate and sample interval

  • PLC scan time: How long the controller takes to execute its program cycle or task.
  • HMI tag update rate: How frequently the HMI receives or refreshes a tag value.
  • Trend sampling interval: How frequently the trend system acquires a sample.
  • Historical logging interval: How frequently values are stored in the archive, where configurable.

These values are related, but they are not necessarily equal.

A PLC may execute logic every few milliseconds while an HMI trend samples a value once per second. In that case, the trend will not capture every PLC-level change.

7. Sampling Methods and Data Logging

Different platforms offer different ways to acquire or store trend data.

7.1 Periodic Sampling

The system records a value at a configured time interval.

Example:

10:00:00  Motor_Current = 5.1 A
10:00:01  Motor_Current = 5.4 A
10:00:02  Motor_Current = 5.8 A
10:00:03  Motor_Current = 6.0 A

Periodic sampling is useful when the engineer needs to understand how a variable changes over time.

7.2 Change-Based Logging

Where supported, the system records a new value when the variable changes sufficiently or satisfies a configured change condition.

This can reduce unnecessary storage for variables that remain stable for long periods.

However, if the configured change threshold is too large, small but meaningful variations may be missed.

7.3 Event-Triggered Capture

Some systems can capture or preserve data when a defined event occurs.

For example, the system may record a period around a drive fault or cycle failure.

Depending on the platform, this may require dedicated event logging, a triggered archive, a PLC buffer, or another data-capture mechanism.

7.4 Logging Versus Display

A trend display determines how acquired data is visualized.

A logger or archive determines what data is retained and for how long.

Changing a trend's visible time range does not necessarily change the historical retention period. Likewise, displaying a tag on a trend does not guarantee that it is being permanently archived.

8. Trend Value Ranges and Scaling

The vertical axis must represent the data meaningfully.

Suppose motor speed normally varies from 0 to 1500 RPM.

A chart configured with a range of 0 to 2000 RPM may provide useful context.

If the chart instead uses a range of 0 to 10000 RPM, normal variations may appear almost flat.

Conversely, an excessively narrow range can exaggerate small variations.

Good scaling practices

  1. Use the correct engineering units.
  2. Select a meaningful range.
  3. Make abnormal excursions visible without hiding normal behavior.
  4. Avoid misleading comparisons between differently scaled variables.
  5. Clearly label automatic or manually configured ranges.
  6. Check whether values are raw or scaled engineering values.

Multiple Y-axes

A trend may display variables with very different units and ranges, such as motor speed and temperature.

A platform may support separate axes for these values. This can be useful, but it can also make visual comparisons misleading if the axes are poorly configured.

Always interpret each variable against its own labelled scale.

9. Comparing Multiple Variables

One of the most useful features of trends is the ability to compare related signals over the same time period.

For example, an engineer investigating a motor overload may trend:

  • Motor current.
  • Motor speed.
  • Drive load.
  • Motor running feedback.
  • Machine cycle state.

The combined trend can help establish the sequence of events.

Observed pattern Possible interpretation
Current rises while speed falls Increasing load, mechanical resistance, or another drive-related issue
Current rises during every startup May be normal inrush or acceleration behavior, depending on the system
Speed command increases but feedback does not Drive, load, control, or feedback issue
Temperature gradually increases over several hours Cooling problem, rising load, ambient changes, or sensor-related issue
Pressure drops before several stations stop A shared utility problem may be involved
Cycle time increases while machine state remains otherwise normal Process delay, reduced speed, or repeated waiting condition

These patterns are diagnostic clues, not proof of a root cause. Confirm them with equipment measurements, PLC logic, alarm history, and physical inspection.

10. Trend Versus Alarm Versus Event Log

These tools answer different questions.

Tool Primary question Example
Trend How did the value change over time? How did pressure change before a station stopped?
Alarm system What abnormal condition required attention? Why was a low-pressure alarm generated?
Event log What happened, and when? When did the operator change the machine mode?
Current status display What is the reported state now? Is the drive ready at this moment?

They work best together.

For example, a low-pressure alarm may identify the time of an abnormal condition. The trend shows how pressure behaved before and after that time. The event log may reveal whether a valve, mode, or production state changed at the same time.

11. HMI Trends in Industrial Maintenance

Trends can support several maintenance activities.

11.1 Breakdown Analysis

After a breakdown, the engineer can examine recorded values leading up to the failure.

For example:

  • Did motor current increase before the trip?
  • Did pressure fall before the machine stopped?
  • Did the temperature rise before a fault?
  • Did the drive-ready signal disappear before the sequence stopped?

This can narrow the investigation.

11.2 Condition Monitoring

Repeated measurements can reveal changes in equipment behavior over time.

Examples:

  • Gradually increasing motor current.
  • Rising hydraulic temperature.
  • Increasing cycle duration.
  • Repeated pressure fluctuations.
  • A growing delay between a command and feedback.

Trends can support condition-based maintenance, although they do not replace appropriate inspection, measurement, or specialist diagnostic techniques.

11.3 Process Optimization

Trend data can help evaluate process stability and operating performance.

Examples:

  • Comparing cycle times across stations.
  • Investigating repeated production delays.
  • Evaluating pressure stability.
  • Reviewing energy or utility consumption.
  • Checking process temperature consistency.

11.4 Corrective Action Verification

After a repair, compare measurements from before and after the intervention.

For example, if a conveyor's motor current was unusually high before maintenance, trend the current under comparable production conditions after the repair.

A meaningful comparison requires similar operating loads, speeds, and process conditions.

12. Cycle-Time Trends

Cycle time is the duration required to complete a defined machine or process cycle.

A cycle-time trend helps reveal variation across successive cycles.

Example:

Cycle number Cycle time
1 42.1 s
2 41.8 s
3 42.0 s
4 43.6 s
5 42.2 s
6 46.4 s

The sixth cycle took significantly longer than the preceding cycles.

The trend may help establish whether the increase is isolated or recurring.

Further investigation could include:

  • Sequence step duration.
  • Robot motion duration.
  • Clamp or cylinder response time.
  • Conveyor transfer time.
  • Waiting for upstream or downstream equipment.
  • Operator interaction.
  • Repeated interlock delays.

A single cycle-time trend does not identify the bottleneck by itself. The engineer must compare it with sequence states and related equipment signals.

13. Trend Storage, Retention and Data Volume

Historical trends require storage. The amount of data depends on how many tags are logged, the sampling frequency, the record format, and the retention period.

A simple approximation for the number of samples is:

\[ N = \frac{T}{\Delta t} \]

Where:

  • \(N\) is the number of samples.
  • \(T\) is the total recording duration.
  • \(\Delta t\) is the sampling interval.

For example, logging one tag every second for 24 hours gives:

\[ N = \frac{24 \times 60 \times 60}{1} = 86{,}400 \]

That is 86,400 samples for one tag in one day.

For 100 tags sampled at the same interval:

\[ N\_{\text{total}} = 100 \times 86{,}400 = 8{,}640{,}000 \]

This counts samples, not the exact storage size. Actual storage depends on timestamps, metadata, database overhead, compression, and the historian implementation.

Retention considerations

A trend system should define:

  • Which variables must be recorded.
  • The sampling interval for each variable.
  • How long data should be retained.
  • Where data is stored.
  • How archived data can be retrieved.
  • What happens when storage becomes full.
  • Whether data is backed up.
  • Who is authorized to access or export it.

High-frequency logging of every available PLC tag is usually unnecessary and can create avoidable communication and storage loads.

14. Common Trend Problems and Troubleshooting

Symptom Possible cause Investigation
Trend line is flat Constant source value, incorrect tag mapping, or insufficient display resolution Compare the live tag and chart scale
Trend shows gaps Communication interruption, missing samples, or archive problem Check data quality, timestamps, and logging status
Peaks are missing Sampling interval is too slow Compare the expected event duration with the sample interval
Trend value differs from the PLC value Different scaling, data source, or timestamp Compare raw values, engineering conversion, and acquisition time
Historical data is unavailable Logging was disabled, retention expired, or archive failed Verify archive configuration and data availability
Trend is too slow to load Excessive data volume or inefficient query Reduce the selected time range or optimize the data configuration
Values appear noisy Genuine process variation, sensor noise, or signal-quality issue Compare the source signal and appropriate measurements
Several variables appear misaligned Different acquisition times, update rates, or timestamp handling Inspect data timestamps and acquisition configuration
Long-term trend loses detail Data compression, aggregation, or coarse historical sampling Check archive resolution and retention policy
Trend axes are misleading Incorrect range or incompatible units Verify axis labels, engineering units, and scale settings

Troubleshooting sequence

  1. Identify the trend pen and its source tag.
  2. Confirm that the source value is changing.
  3. Verify the tag mapping and engineering units.
  4. Check tag quality and communication status.
  5. Inspect the trend sampling interval.
  6. Confirm that historical logging is enabled if historical data is expected.
  7. Check the time range, timestamps, and axis configuration.
  8. Verify archive availability and retention settings.
  9. Compare the chart against another reliable source where possible.
  10. Record the findings and correct the underlying configuration problem.

15. Practical Example: Robot Station Trend Analysis

Consider an automotive robotic station identified as FR1010.

The maintenance engineer wants to investigate an intermittent increase in cycle time.

The HMI or SCADA trend is configured to display:

Tag Data type Purpose
Cycle_Time_s Numeric Records the cycle duration
Robot_Running_FB Boolean Indicates robot running feedback
Robot_Ready Boolean Indicates robot readiness
Drive_Current_A Numeric Records drive current
Clamp_Extend_Time_s Numeric Records clamp extension duration
Cycle_Complete Boolean Indicates cycle completion

Investigation process

  1. Select a time range containing several normal cycles and at least one slow cycle.
  2. Identify the time of the increased cycle duration.
  3. Compare robot running feedback with cycle state.
  4. Examine clamp extension duration around the affected cycle.
  5. Review alarms and sequence diagnostics at the same time.
  6. Determine whether the delay appears to originate from robot motion, clamp response, a waiting condition, or another part of the sequence.
  7. Verify the suspected cause using PLC diagnostics and physical inspection.
  8. Compare trend behavior after corrective action under comparable operating conditions.

Suppose the trend shows that clamp extension duration increased during the same cycles in which total cycle time increased. This suggests a possible relationship, but the engineer should verify the sequence timing and clamp feedback before concluding that the clamp caused the delay.

16. HMI Trends, SCADA and Historians

A local HMI may provide short-term live and historical trends. Larger supervisory systems may use a historian or database to retain data across many devices and longer time periods.

Feature Local HMI trend SCADA or historian-based trend
Typical scope Individual machine or station Multiple machines or production areas
Data retention Depends on local configuration Often designed for longer-term centralized storage
Historical comparison May be limited by the archive Can support wider time ranges and cross-machine analysis
Data sources Commonly one or a few PLCs Multiple PLCs, devices, gateways, or systems
Analysis Operational troubleshooting Production analysis, maintenance, and process-performance analysis

These are common patterns rather than strict boundaries. Some modern HMI platforms provide advanced historical logging, while SCADA systems vary in their historian capabilities.

For your local SCADA architecture, PLC tags can be acquired through Node-RED, stored in SQL Server, and visualized in Grafana. In that design, SQL Server can retain historical samples while Grafana displays the time-series data. The quality of the resulting trends still depends on the acquisition interval, timestamps, correct tag mapping, and logging reliability.

17. Interview Questions and Answers

Q1. What is an HMI trend?

An HMI trend is a graph showing how one or more process variables change over time.

Q2. What is the difference between a live trend and a historical trend?

A live trend displays recently acquired values. A historical trend displays previously recorded values and depends on the availability of retained data.

Q3. What is a trend pen?

A trend pen is an individual data series plotted on a trend chart, such as motor speed, pressure, or temperature.

Q4. What is a trend sampling interval?

It is the time between acquired trend samples. It determines how frequently the trend system records or captures values.

Q5. Why can a trend miss a short-duration fault?

The event may occur and disappear between samples. The sampling interval or acquisition mechanism may be insufficient to capture it.

Q6. What is the difference between PLC scan time and trend sampling interval?

PLC scan time describes controller program execution timing. Trend sampling interval describes how frequently the trend system acquires samples. They are separate settings.

Q7. Why are trends useful in maintenance?

They help identify changes, intermittent problems, recurring patterns, and relationships between process variables before or during equipment failures.

Q8. What is the difference between a trend and an alarm?

A trend shows how values change over time. An alarm notifies personnel when a configured condition requires attention.

Q9. Does displaying a tag on a trend guarantee historical retention?

No. Historical retention requires suitable logging or archiving configuration.

Q10. How would you investigate a missing trend peak?

Check the source signal, acquisition interval, tag update rate, logging configuration, and timestamps. Confirm whether the event was captured by another suitable diagnostic source.

Q11. What causes gaps in a trend?

Possible causes include communication interruptions, missing samples, archive failures, or data-quality problems.

Q12. How can trends help verify a repair?

Compare measurements before and after the repair under comparable operating conditions, and verify that the abnormal behavior has improved or disappeared.

18. Practical Study Exercises

Use a simulator or an approved non-production training system.

  1. Create a live trend for a numeric PLC tag.
  2. Add a second pen to compare two related variables.
  3. Configure meaningful engineering units and value ranges.
  4. Compare a live trend with a historical trend.
  5. Change the sample interval and observe how the chart captures rapid changes.
  6. Simulate a short-duration signal transition and investigate whether it appears in the trend.
  7. Review the system's behavior during communication loss.
  8. Create a cycle-time trend from recorded cycle durations.
  9. Compare motor current and speed during a simulated operating cycle.
  10. Configure or inspect historical data retention.
  11. Calculate the number of samples generated by a selected tag count and logging interval.
  12. Investigate a simulated cycle-time increase using related status tags and alarm history.
  13. Document the trend's source tags, sample interval, units, retention settings, and intended diagnostic use.

          |
          v

          |
          v

          |
          v

The key concepts are:

  • Live trend: Shows recent behavior.
  • Historical trend: Shows previously retained behavior.
  • Trend pen: Represents one variable.
  • Sampling interval: Determines how frequently samples are acquired.
  • Historical logging: Determines whether data is retained for later analysis.
  • Trend analysis: Helps identify patterns but does not, by itself, prove root cause.

A well-configured trend makes changes in machine behavior visible, helps engineers investigate intermittent problems, and provides evidence for evaluating corrective actions.
