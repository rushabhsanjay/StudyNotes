1. Definition

WinCC is Siemens' HMI and SCADA software family used to design operator interfaces, visualize industrial processes, monitor equipment, manage alarms, display trends, and interact with PLCs and other automation systems.

WinCC products are used across a range of industrial applications, from local machine operator panels to PC-based visualization and plant-level SCADA systems.

For industrial maintenance, the important skill is not simply knowing how to create screens. It is understanding how the HMI project connects to the PLC, how tags are configured, how alarms and diagnostics are generated, how projects are transferred, and how communication faults are investigated.

For example, a Siemens PLC controlling an automotive assembly station can provide WinCC with:

  • Automatic and manual mode status.
  • Robot and fixture readiness.
  • Sensor and actuator feedback.
  • Current machine sequence.
  • Active alarms and diagnostic messages.
  • Process values and historical trends.
  • Approved recipe parameters.

WinCC displays and manages this information through the configured project. The PLC remains responsible for its programmed machine-control functions.

2. WinCC Product Family

One of the first things to understand is that WinCC is a product family, not one single software application. Different editions target different hardware and application sizes.

The main product groups you should recognize are:

WinCC product Typical application
WinCC Basic Engineering for supported Basic Panels
WinCC Comfort Engineering for supported operator panels, including Comfort Panels
WinCC Advanced Engineering for panels and PC-based HMI applications using Runtime Advanced
WinCC Professional Engineering for supported panels and PC-based Runtime Advanced or Runtime Professional applications
WinCC Unified Modern visualization platform for supported Unified panels and PC-based applications
WinCC Classic Earlier PC-based visualization and SCADA product family, commonly associated with WinCC V7.x

Siemens documents the differences between these editions in its WinCC product overview.

3. Engineering Software Versus Runtime Software

WinCC work involves two major environments.

3.1 Engineering environment

The engineering environment is where the HMI project is created and configured.

Typical tasks include:

  • Creating screens and navigation.
  • Configuring PLC connections.
  • Creating HMI tags.
  • Configuring alarms and diagnostic displays.
  • Creating trends and data logs.
  • Configuring recipes.
  • Setting up user permissions.
  • Compiling and transferring the project.

In the TIA Portal ecosystem, WinCC engineering is integrated with other automation engineering tools, including STEP 7 for supported PLC projects.

3.2 Runtime environment

Runtime is the environment that executes the deployed visualization application.

It reads PLC data, updates displays, handles operator interactions, and performs configured runtime functions.

Examples include:

  • A Comfort Panel running its configured HMI application.
  • A Windows PC running WinCC Runtime Advanced.
  • An industrial PC running WinCC Runtime Professional as a SCADA system.
  • A supported Unified Comfort Panel running WinCC Unified Runtime.

The precise runtime depends on the project type and target device.

5. TIA Portal and WinCC

TIA Portal stands for Totally Integrated Automation Portal. It is Siemens' engineering environment for configuring supported automation devices and software.

Depending on the installed software and licenses, a TIA Portal project may include:

  • PLC hardware configuration.
  • PLC program.
  • HMI device configuration.
  • HMI screens.
  • HMI tags.
  • PLC-HMI connections.
  • Alarm configuration.
  • Recipes.
  • Device network settings.

A major advantage is the ability to configure supported PLC and HMI devices within a coordinated engineering project.

Example

Suppose an S7-1500 PLC contains these tags:

Machine_Ready
Robot_Ready
Station_Faulted
Clamp_Closed_FB
Cycle_Count

The HMI project can use the relevant PLC tags to create indicators, numeric displays, alarms, and operator controls.

When PLC and HMI engineering are integrated in TIA Portal, symbolic tags and configured connections can simplify engineering. The exact integration depends on the project type and supported devices.

7. Creating an HMI Screen

A typical machine screen contains objects such as:

  • Text labels.
  • Buttons.
  • Indicators.
  • Numeric displays.
  • Input fields.
  • Alarm views.
  • Navigation controls.
  • Equipment graphics.

Each object may be linked to an HMI tag or configured runtime function.

For example, a status indicator can be connected to Robot_Ready.

Conceptually:

PLC tag: Robot_Ready
          |
          v
       HMI tag
          |
          v
   Status indicator
          |
          v
 TRUE  -> Robot ready
 FALSE -> Robot not ready

The display must reflect the actual meaning of the PLC tag. A false value may indicate that the robot is not ready, but it does not automatically prove that the robot has a fault.

Communication quality must also be considered. If the data is unavailable or stale, the HMI should not falsely present the last received value as a confirmed current state.

8. WinCC Tags and PLC Communication

WinCC tags are used to access PLC values and internal HMI data.

External tags

External tags communicate with a PLC or another supported device.

Examples:

  • Machine_Ready
  • Clamp_Closed_FB
  • Cycle_Count
  • Actual_Temperature

Internal tags

Internal tags are maintained within the HMI runtime and do not require a direct PLC address.

They may be used for interface behavior, navigation, temporary values, or other supported internal functions.

Tag configuration

For an external tag, check:

  1. Correct PLC connection.
  2. Correct symbolic name or address.
  3. Correct data type.
  4. Correct read or write behavior.
  5. Appropriate update settings.
  6. Correct engineering units and scaling, where applicable.

A tag can be configured incorrectly even when the PLC connection itself is healthy.

Communication through PROFINET

WinCC supports configured communication with compatible Siemens PLCs through PROFINET. Depending on the runtime and hardware, other communication drivers and protocols may also be available.

Siemens' documentation explains how HMI connections are configured for supported S7-1200 and runtime combinations. See WinCC communication via PROFINET.

9. WinCC Alarms and Diagnostics

WinCC can display configured alarms and diagnostic information obtained from PLC tags, HMI alarm configuration, and supported device information.

Common applications include:

  • Station fault indication.
  • Actuator timeout alarms.
  • Missing sensor feedback.
  • Drive fault messages.
  • Communication status.
  • Machine-not-ready messages.
  • Process limit alarms.

Example:

Alarm:
FR1010 - CLAMP CLOSING TIMEOUT

Diagnostic information:
Close command       = ON
Closed feedback     = OFF
Timeout elapsed     = TRUE
PLC communication   = HEALTHY

This is an illustrative example. Actual messages and signals depend on the machine program.

The alarm identifies the abnormal condition, while the diagnostic display helps the maintenance engineer investigate it.

10. WinCC Trends and Data Logging

Trends show how process values change over time.

Typical applications include:

  • Temperature monitoring.
  • Pressure monitoring.
  • Cycle-time analysis.
  • Drive speed monitoring.
  • Process setpoint versus actual value.
  • Investigation of intermittent faults.

WinCC projects can use supported data logging and trend functions, but the exact capabilities depend on the runtime edition and configuration.

For example, a trend may compare a target temperature with the measured temperature. If the values diverge, maintenance can investigate the control loop, sensor, actuator, or process conditions.

Historical data is only available when the relevant logging has been configured and the required data has been retained.

11. WinCC Recipes

Recipes group process parameters for different products or operating conditions.

For example, an automotive station may have approved recipes for different component variants.

A recipe workflow may be:

  1. Select the recipe.
  2. Retrieve the configured parameters.
  3. Transfer the values to the intended destination.
  4. Validate the values.
  5. Apply the parameters at the permitted point in the machine sequence.
  6. Confirm the active recipe.

The exact recipe features depend on the WinCC edition. Siemens documents differences between Runtime Advanced and Runtime Professional, including recipe-related functionality.

12. WinCC Unified: What Makes It Different?

WinCC Unified is a modern Siemens visualization platform with engineering tools and supported runtime environments for Unified panels and PC-based applications.

Its ecosystem includes:

  • Unified Comfort Panels and supported Unified Basic Panels.
  • WinCC Unified PC Runtime.
  • Web-oriented visualization capabilities.
  • Screen and object configuration.
  • User administration.
  • Supported scripting and runtime functions.

WinCC Unified is not merely another name for every older WinCC product. Its project structure, runtime behavior, supported objects, and engineering workflows differ from earlier WinCC generations.

Siemens provides specific guidance for modernizing projects from older Comfort, Advanced, and Professional systems to Unified. Migration support varies by source project and feature, so conversion must be followed by functional verification.

14. Practical Workflow for Maintenance Engineers

When working with an existing WinCC application, follow this order:

  1. Identify the WinCC product, version, and runtime.
  2. Identify the HMI panel or PC target.
  3. Locate the approved engineering source and backup.
  4. Check the PLC connection configuration.
  5. Verify key tags against the PLC program.
  6. Inspect alarms, diagnostics, and relevant machine states.
  7. Test changes in an approved environment.
  8. Archive the modified project with revision information.
  9. Transfer the approved project to the correct target.
  10. Verify runtime operation and PLC communication.
  11. Confirm the required machine-interface functions.
  12. Document the changes and recovery procedure.

For troubleshooting, distinguish between a problem in the HMI project, a communication problem, a PLC logic problem, and a physical equipment problem. They can produce similar symptoms, but they require different corrective actions.

15. Interview Questions and Answers

Q1. What is WinCC?

WinCC is Siemens' visualization software family for HMI and SCADA applications.

Q2. What is the difference between WinCC engineering and runtime?

Engineering is used to create and configure the project. Runtime executes the deployed application.

Q3. What is TIA Portal?

TIA Portal is Siemens' integrated engineering environment for configuring supported automation devices and software, including PLC and HMI projects.

Q4. What is the difference between WinCC Advanced and WinCC Professional?

They support different application scopes and runtime capabilities. Runtime Professional supports PC-based SCADA configurations with capabilities beyond those of Runtime Advanced in several areas.

Q5. What is WinCC Unified?

It is a modern Siemens visualization platform for supported Unified panels and PC-based applications, with its own engineering and runtime architecture.

Q6. What is an external HMI tag?

An external HMI tag accesses data from a PLC or another supported device.

Q7. Why can a WinCC tag fail while the PLC connection is healthy?

The tag may have an incorrect name, address, data type, access configuration, or mapping.

Q8. What should be checked before downloading a WinCC project?

Verify the target device, project revision, software compatibility, backup, communication configuration, and approved transfer conditions.

Q9. Why must a migrated project be tested?

Migration may not preserve every feature or behavior identically across product generations. Functional verification confirms that the converted project meets its requirements.

Q10. Can WinCC communicate with non-Siemens PLCs?

Some WinCC runtime editions support communication drivers for other manufacturers, including supported Allen-Bradley and Mitsubishi interfaces. Availability depends on the runtime, driver, and configuration.

16. Practical Exercises

Use a simulator or approved non-production system.

  1. Create a basic WinCC project in a supported engineering environment.
  2. Create a screen with machine-ready and fault indicators.
  3. Configure HMI tags linked to PLC tags.
  4. Add a numeric display for a process value.
  5. Configure an alarm for a simulated fault.
  6. Add a trend for a simulated process variable.
  7. Configure a recipe for two sample product variants.
  8. Simulate a communication interruption and observe the HMI response.
  9. Compile the project and review diagnostic messages.
  10. Run the project in a supported simulator or runtime.
  11. Create an archive and record the project version.
  12. Document the difference between the engineering project and deployed runtime.

Remember these distinctions:

  • WinCC: Siemens HMI and SCADA software family.
  • TIA Portal: Integrated engineering environment.
  • Engineering: Project creation and configuration.
  • Runtime: Execution of the deployed HMI application.
  • HMI tags: Data references used by the interface.
  • Communication driver: Connects the runtime to a supported PLC or device.
  • WinCC Unified: Modern visualization platform with its own supported project and runtime architecture.

The practical skill is to trace the entire path from the PLC tag, through the communication connection and HMI tag, to the displayed object, then verify that the runtime behaves correctly.
