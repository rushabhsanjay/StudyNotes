1. Definition and Purpose

An HMI tag is a named data reference used by an HMI application to read, display, or write a value.

Tags connect the HMI's visual elements to information from a PLC, an internal HMI variable, or another configured data source.

Examples include:

  • Motor_Running: Indicates whether a motor is running.
  • Drive_Ready: Indicates whether a drive is ready.
  • Fault_Active: Indicates whether a fault is active.
  • Production_Count: Stores or displays a production count.
  • Temperature_Value: Represents a temperature measurement.
  • Start_Request: Represents an operator's request to start a machine.

An HMI tag is not necessarily a physical input or output. It is a logical reference to data.

For example, an HMI might display a green motor symbol when Motor_Running is true. The tag may reference a PLC variable that is updated using motor feedback, drive status, or other control logic.

2. Basic HMI Tag Architecture

       Physical Sensor
              |
              v
         PLC Input
              |
              v
        PLC Program
              |
              v
         PLC Variable
              |
       Communication
              |
              v
           HMI Tag
              |
              v
       Screen Indicator

For an operator command, the information path works in the opposite direction:

       Operator presses button
                 |
                 v
          HMI command tag
                 |
           Communication
                 |
                 v
           PLC command tag
                 |
                 v
       PLC validates conditions
                 |
                 v
         Machine action, if permitted

The PLC must validate operator requests against the required control conditions. An HMI button should not directly bypass machine interlocks or safety functions.

3. Main Types of HMI Tags

3.1 External Tags

External tags obtain data from a PLC or another connected device.

Examples:

  • Motor running feedback.
  • Cylinder extended feedback.
  • Robot ready status.
  • Drive fault code.
  • Analog temperature value.
  • Production counter.

Example configuration:

Property Example
Tag name Motor_Running
Data source PLC
PLC variable Motor_Running_FB
Data type Boolean
Access Read
Purpose Display motor running status

External tags depend on the communication connection, the configured address, and the source device's availability.

3.2 Internal Tags

Internal tags are stored and managed within the HMI application rather than being directly mapped to a PLC variable.

Typical uses include:

  • Temporary screen-selection state.
  • Local display settings.
  • Acknowledgement or navigation state.
  • HMI-only calculations.
  • Temporary user-interface values.

Example:

Tag name Data type Purpose
Selected_Station Integer Stores the currently selected station
Show_Diagnostics Boolean Controls diagnostic-panel visibility
Display_Unit Integer or enumeration Stores a display preference

An internal tag is not automatically shared with the PLC. If the controller needs the value, an explicit supported communication or data-transfer mechanism is required.

3.3 Derived or Calculated Tags

A derived tag represents a value calculated from other values or expressions.

Examples:

  • Total production calculated from multiple counters.
  • Temperature converted from raw counts into engineering units.
  • Availability percentage calculated from operating and downtime values.
  • A summary status derived from several equipment states.

For example:

\[ \text{Availability} = \frac{\text{Operating Time}}{\text{Planned Production Time}} \times 100 \]

A derived value may be calculated by the HMI, PLC, SCADA application, or another system. The correct location depends on timing requirements, reuse, reliability, and the application's architecture.

3.4 System Tags

System tags represent information about the HMI runtime or its environment where the platform supports them.

Examples may include:

  • Current user.
  • Runtime status.
  • System time.
  • Communication status.
  • Application state.

Available system tags vary by HMI product and runtime.

4. PLC Tags Versus HMI Tags

These terms are related, but they are not identical.

Feature PLC tag or variable HMI tag
Main purpose Stores or represents data used by the control system References data used by the HMI
Location PLC memory or controller data model HMI project or runtime configuration
Used by PLC program and supported external clients Screens, alarms, trends, scripts and other HMI features
Example Motor_Running_FB Motor_Running_Display
Data source PLC logic, I/O mapping, communications or other configured sources PLC variable, HMI memory or another configured source
Control responsibility May participate in machine-control logic Typically presents information or requests actions

An HMI tag may reference a PLC tag without having the same name.

For example:

PLC variable:  FR1010_Robot_Run_Feedback
HMI tag:       Robot_Run_Status_Display
Screen object: Robot status indicator

The mapping between these elements must be configured correctly.

5. Tag Data Types

The data type determines what kind of value a tag can represent.

Data type Meaning Typical HMI use
Boolean True or false Motor status, sensor status, fault flag
Integer Whole number Production count, station number
Floating point Numeric value with fractional precision Temperature, pressure, speed
String Text Message, product code, operator information
Array Collection of elements Grouped measurements or status values
Structured data Group of related fields Motor information, equipment status
Date/time Date or time value Event timestamps or process records

The exact names, sizes, ranges, and supported types depend on the HMI platform and the PLC data source.

Example tag list

Tag name Data type Example value Meaning
Robot_Ready Boolean TRUE Robot reports ready
Robot_Fault Boolean FALSE No active robot fault indicated
Production_Count Integer 1250 Production count
Motor_Speed Floating point 1450.5 Speed value, if defined in RPM
Station_Name String FR1010 Station identifier

The units and meaning of numeric values should be documented. A value of 1450.5 is ambiguous without knowing whether it represents RPM, a scaled raw value, or another quantity.

6. Tag Addressing

An HMI tag must identify the correct source value. The way this is configured depends on the PLC and HMI software.

6.1 Address-Based Tags

Older or address-oriented systems may use direct PLC addresses.

Examples include:

  • Siemens: I0.0, Q0.0, DB10.DBX0.0.
  • Mitsubishi: X0, Y0, M10, D100.
  • Legacy Allen-Bradley: B3:0/0, N7:0, and other supported data-file addresses.

These examples illustrate platform-specific addressing. They are not universal addresses and should not be copied into a project without checking the controller configuration.

6.2 Symbolic Tags

Modern PLC projects commonly use meaningful variable names.

Examples:

Motor_Run_Command
Motor_Running_Feedback
Drive_Ready
Station_Interlocks_OK
Fault_Active
Production_Count

Symbolic tags make projects easier to read, document, and maintain.

However, a symbolic tag must still be mapped to the correct source and supported data type.

6.3 Address Mapping

A tag mapping defines the relationship between an HMI tag and its source.

HMI tag Source PLC variable Purpose
Motor_Status Motor_Running_FB Display motor status
Drive_Ready_Display Drive_Ready Display drive readiness
Production_Total Production_Count Display production count
Temperature_Display Temperature_Value Display process temperature

A mapping error can cause an HMI to display incorrect information even when the PLC is operating correctly.

7. Read-Only and Writable Tags

Tags should be classified according to their intended use.

Read-only tags

These display information without allowing the HMI to change the source value.

Examples:

  • Sensor feedback.
  • Motor running status.
  • Drive fault code.
  • Current production count.
  • Temperature feedback.

Writable tags

These allow an HMI function to write a value to an external source or modify an internal value where supported.

Examples:

  • Operator start request.
  • Approved speed setpoint.
  • Recipe selection.
  • Reset request.
  • Manual command request.

Writable tags require careful design because a write can change machine behavior.

A good control architecture separates commands from feedback.

For example:

Tag Direction Meaning
Motor_Start_Request HMI to PLC Operator requests starting
Motor_Run_Command PLC to drive or output Controller issues the run command
Motor_Running_FB Drive or field device to PLC Actual running feedback
Motor_Status_Display PLC to HMI Value used for visual indication

Pressing Start does not prove the motor has started. The HMI should show the actual feedback separately from the requested command.

8. Tag Naming Conventions

Consistent tag naming improves troubleshooting, program readability, and maintenance.

A useful tag name communicates the equipment, function, and signal meaning.

Examples:

FR1010_Robot_Ready
FR1010_Robot_Fault
FR1010_Cycle_Start_Request
FR1010_Cycle_Complete
FR1010_Part_Present
FR1010_Production_Count

A naming convention may include:

  • Station or equipment identifier.
  • Device or subsystem.
  • Function.
  • Signal meaning.
  • Unit or engineering context where needed.

Avoid vague names such as Tag1, Value2, Status, or Bit15 unless they are constrained by a legacy addressing system and documented elsewhere.

Example naming pattern

[Station]_[Equipment]_[Function]_[Signal]

Example:

FR1010_Conveyor_Motor_Running_FB

This pattern is illustrative. The final naming convention should match the plant's existing standards and software constraints.

Common suffixes

Suffix Typical meaning
_CMD Command
_REQ Request
_FB Feedback
_STS Status
_ALM Alarm
_FLT Fault
_SP Setpoint
_PV Process value

Suffixes are conventions, not universal standards. Document their meanings so that every engineer interprets them consistently.

9. Scaling and Engineering Units

PLC values often need conversion before they can be displayed meaningfully.

For example, an analog input may provide a raw integer value that represents a temperature sensor measurement. The HMI should display the converted temperature rather than an unexplained raw count.

A general linear scaling equation is:

\[ Y = Y\_{\min} + \frac{X-X\_{\min}}{X\_{\max}-X\_{\min}} (Y\_{\max}-Y\_{\min}) \]

Where:

  • \(X\) is the raw input.
  • \(X\_{\min}\) and \(X\_{\max}\) define the raw range.
  • \(Y\) is the converted engineering value.
  • \(Y\_{\min}\) and \(Y\_{\max}\) define the engineering range.

For example, suppose an input range of 0 to 27648 represents a temperature range of 0 to 100 °C.

If the raw value is 13824:

\[ Y = \frac{13824}{27648}\times100 = 50^\circ C \]

This result assumes the stated linear scaling and range. Actual analog modules may use different raw ranges, diagnostics, or scaling conventions.

Important: Scaling may be performed in the PLC, HMI, or data-acquisition layer. Avoid applying the same conversion twice.

Always document the engineering unit, expected range, raw range, and conversion location.

10. Tag Quality, Freshness and Communication Status

A tag value should not be interpreted without considering whether its source data is valid and current.

For example, an HMI may continue showing the last received value after communication is lost, depending on the platform's behavior.

Important concepts include:

  • Value: The most recently available data.
  • Quality: Whether the platform considers the data valid.
  • Timestamp: When the value was acquired or updated, where supported.
  • Communication status: Whether the data source is connected and communicating.
  • Update rate: How frequently the value is refreshed.

These concepts are especially important for monitoring robot status, drive feedback, process temperatures, and production counts.

A displayed value of TRUE does not necessarily prove that the field device is currently active if the communication status is bad or the value is stale.

Where supported, use explicit communication-quality indicators and design the HMI to distinguish unknown data from a genuine healthy or stopped state.

11. Tag Update Rates and Performance

HMI tags consume communication and processing resources. Excessive polling can degrade performance.

The update rate depends on the HMI runtime, communication driver, PLC, network, number of tags, and application requirements.

Typical design considerations:

  • Rapidly changing values may need faster updates.
  • Slowly changing parameters do not require frequent polling.
  • Alarm and status updates should meet operational requirements.
  • Historical logging should use a suitable sampling interval.
  • Large tag groups should be organized efficiently.
  • Unnecessary repeated reads should be avoided.

A 10 ms PLC task does not mean every HMI tag is updated every 10 ms. PLC execution timing, communication update timing, and screen refresh timing are separate concepts.

12. Tag Security and Validation

Writable tags should be protected against invalid or unauthorized values.

Examples include:

  • Speed setpoints.
  • Temperature limits.
  • Production recipe parameters.
  • Manual movement requests.
  • Reset and restart requests.

Recommended controls include:

  1. Restrict write access to authorized users.
  2. Define valid minimum and maximum values.
  3. Validate commands and parameters in the PLC.
  4. Reject invalid values where required.
  5. Separate operator requests from actual equipment commands.
  6. Record important changes where appropriate.
  7. Avoid using HMI visibility or disabled buttons as the only security control.

A value entered through the HMI must not be assumed valid merely because the screen accepts it.

Safety-related conditions must be enforced by the appropriate safety architecture, not by relying on HMI tag permissions.

13. Common Tag Problems and Troubleshooting

Symptom Possible cause First checks
Tag displays zero Wrong address, source value zero, or failed communication Compare the tag with the live PLC value
Tag shows the wrong state Incorrect mapping, inversion, or incorrect data type Check the source variable and mapping
Tag remains frozen Communication loss or stale cached value Check quality, connection status and timestamp
HMI button has no effect Wrong writable tag, access restriction, or PLC permissive false Monitor the request and PLC logic
Numeric value is unrealistic Incorrect scaling, units, or data type Verify raw value and conversion formula
Tag cannot be written Read-only configuration, PLC access restriction, or unsupported write Check permissions and source configuration
Alarm does not activate Wrong trigger tag, polarity, threshold or alarm configuration Check the condition and alarm definition
Tag works in one screen but not another Different tag mapping, screen-specific configuration, or update settings Compare the objects and tag references
Values become inconsistent Duplicate mappings, race conditions, or different update rates Trace the source and update behavior

Troubleshooting sequence

  1. Identify the HMI object displaying or using the tag.
  2. Determine the exact HMI tag name.
  3. Verify its data source and address.
  4. Check its data type and read/write configuration.
  5. Compare its value with the live PLC variable.
  6. Check communication quality and freshness.
  7. Review scaling and formatting.
  8. Verify the result after correcting the cause.

14. Practical Example: Robot Status Tags

Consider an automotive robotic station with these PLC variables:

FR1010_Robot_Ready
FR1010_Robot_Running
FR1010_Robot_Fault
FR1010_Cycle_Start_Request
FR1010_Cycle_Complete

The HMI uses the variables as follows:

HMI tag Source Display or function
Robot_Ready_Display FR1010_Robot_Ready Indicates robot readiness
Robot_Running_Display FR1010_Robot_Running Indicates running feedback
Robot_Fault_Display FR1010_Robot_Fault Indicates fault status
Cycle_Start_Button FR1010_Cycle_Start_Request Requests a cycle start
Cycle_Complete_Display FR1010_Cycle_Complete Indicates cycle completion

The correct diagnostic sequence is to monitor the actual PLC variables and confirm the HMI mappings.

If the HMI shows the robot as ready but the PLC variable is false, investigate the HMI tag mapping, quality, and update behavior. If the PLC variable is also false, investigate the robot interface and its readiness conditions.

This separates a visualization problem from an actual control-system problem.

15. Interview Questions and Answers

Q1. What is an HMI tag?

A named data reference used by the HMI to display, calculate, log, or modify a value.

Q2. What is the difference between an internal and an external tag?

An internal tag is managed within the HMI application. An external tag reads from or writes to a configured external data source, such as a PLC.

Q3. What is the difference between a PLC tag and an HMI tag?

A PLC tag belongs to the controller's data model. An HMI tag is a reference configured in the HMI project. The HMI tag may point to the PLC tag, but their names and internal representations need not be identical.

Q4. Why should command and feedback tags be separate?

A command indicates what the control system has been asked to do. Feedback indicates the reported state of the equipment. Keeping them separate helps operators and maintenance personnel identify failed starts, missing feedback, and communication issues.

Q5. What is tag scaling?

Tag scaling converts a raw value into a meaningful engineering value, such as converting analog input counts into degrees Celsius or pressure units.

Q6. Why can a tag show an old value after communication fails?

Some systems retain the last received value. Without checking communication quality or freshness, the HMI may display stale data as if it were current.

Q7. What is the difference between a tag value and tag quality?

The value is the reported data. Quality indicates whether that data is considered valid or trustworthy by the platform.

Q8. Why are tag naming conventions important?

They make tags easier to identify, troubleshoot, document, reuse, and maintain across machines and engineering teams.

Q9. Why should PLC logic validate HMI setpoints?

HMI-side limits can be bypassed or incorrectly configured. The PLC should validate values against the required control constraints before using them.

Q10. Does a fast PLC scan guarantee fast HMI updates?

No. PLC scan time, communication update rate, and HMI screen refresh rate are separate timing mechanisms.

16. Practical Study Exercises

Use a simulator or an approved test system.

  1. Create a tag list containing Boolean, integer, floating-point, and string variables.
  2. Identify which tags are internal and which are connected to a PLC.
  3. Map one HMI tag to a PLC variable and verify the live value.
  4. Create separate command and feedback tags for a training motor.
  5. Document the address, data type, units, source, and read/write access of each tag.
  6. Convert an example raw analog value into an engineering unit.
  7. Identify how the HMI indicates communication failure or stale data.
  8. Trace a displayed robot status back to its PLC source.
  9. Review tag names and standardize inconsistent naming in a training project.
  10. Test valid and invalid setpoint handling in a non-production environment.

17. Final Mental Model

Physical equipment
       |
       v
PLC inputs and logic
       |
       v
PLC variables
       |
       v
Communication connection
       |
       v
HMI tags
       |
       v
Screens, indicators, alarms and trends

For operator commands, the data path runs in reverse: an HMI tag transmits a request to the PLC, and the PLC validates the request before controlling the equipment.

A reliable HMI tag design requires correct source mapping, appropriate data types, clear naming, valid scaling, sensible update rates, communication-quality awareness, and controlled write access.
