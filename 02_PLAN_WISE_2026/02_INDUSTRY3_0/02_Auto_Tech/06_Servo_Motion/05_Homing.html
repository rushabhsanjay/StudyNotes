1. Definition of homing

Homing is the process of establishing a known reference position for a machine axis so that the controller can interpret position measurements as meaningful machine coordinates.

An encoder may report rotation or position, but the machine controller also needs to know how that measurement relates to the machine's coordinate system.

For example, a transfer slide may have an encoder that measures motor movement. After startup, the controller may not know where the slide is relative to the loading station, fixture station, and physical travel limits. A homing sequence establishes the required reference.

Homing commonly involves controlled movement, a reference sensor or other position-detection method, and sometimes an encoder index pulse.

Typical applications include:

  • CNC machine axes.
  • Robotic transfer units.
  • Servo-driven indexing tables.
  • Linear positioning slides.
  • Automated assembly stations.
  • Conveyor tracking axes.
  • Pick-and-place mechanisms.

Important distinction: Homing is not simply moving a motor to its mechanical end stop. It is a defined procedure that establishes a repeatable coordinate reference according to the machine design.

2. Why homing is necessary

Consider a linear axis with a physical travel range of 0 to 800 mm.

The controller receives a command to move to 500 mm. That command is meaningful only if the controller has a valid relationship between the feedback measurement and the machine coordinate system.

Without a valid reference, the controller may know that the motor has moved 100,000 counts, but it may not know whether the physical axis is at 200 mm, 500 mm, or another machine coordinate.

Homing establishes the required relationship.

Common reasons for homing include:

  1. Establishing the machine coordinate origin.
  2. Recovering a valid reference after startup when required.
  3. Compensating for uncertainty in the initial axis position.
  4. Establishing a repeatable position for subsequent absolute moves.
  5. Verifying that a reference sensor and associated sequence operate correctly.

The exact need for homing depends on the encoder, controller, machine design, and reference-retention method.

The diagram is conceptual. The home sensor may connect to the PLC, motion controller, or drive, depending on the system architecture. Encoder feedback is processed by the supported drive or motion-control interface.

A typical homing sequence may use:

  • A home or reference switch.

Machine zero and home sensor location are not necessarily identical. The controller can detect a sensor at one physical location and apply an offset to establish the intended machine coordinate origin.

5. Common homing methods

The available methods and their names depend on the controller, drive, and motion library.

5.1 Home switch only

The axis moves toward a reference switch. When the switch changes state, the controller establishes the reference according to the configured method.

Conceptual sequence:

  1. Confirm that the axis is ready.
  2. Move in the configured search direction.
  3. Detect the home switch.
  4. Stop or execute the configured reference sequence.
  5. Establish the reference coordinate.
  6. Set the homed or reference-valid status.

This method is straightforward, but accuracy depends on sensor repeatability, detection behavior, movement speed, controller timing, and the mechanics.

5.2 Home switch followed by encoder index

This method uses a home sensor to identify a reference region and an encoder index pulse to refine the reference.

A common conceptual sequence is:

  1. Search for the home switch.
  2. Detect the switch transition.
  3. Back off or continue according to the configured method.
  4. Approach the reference in the specified direction.
  5. Detect the encoder index pulse.
  6. Apply the configured home offset.
  7. Establish the machine coordinate.

The exact order depends on the homing mode. Some methods approach the switch first and then use the index; others use a different sequence.

This method can improve repeatability when the index pulse and reference method are properly implemented.

5.3 Limit-switch-based homing

A limit switch may be used as part of the reference procedure.

The axis approaches a defined limit or reference sensor and establishes the coordinate according to the controller configuration.

A travel-limit device must not automatically be treated as a home sensor. Its intended function, electrical arrangement, and safety role must be confirmed.

If the same device is used for homing and limit detection, the control sequence must be designed to prevent unsafe movement or incorrect reference establishment.

5.4 Absolute encoder-based reference

An absolute encoder can report a position value without requiring the receiver to reconstruct all motion from incremental pulses since power-up.

This may reduce or eliminate the need for routine homing, but it does not guarantee that the machine coordinate reference is automatically valid.

The controller may still require:

  • Initial commissioning or reference calibration.
  • Validation of the retained position.
  • Verification that the load has not moved while position was unavailable.
  • A reference check after certain faults or maintenance.
  • A machine-specific homing procedure.

An absolute encoder knows its position according to its own measurement system. The controller must still know how that position maps to the machine coordinate system.

6. Homing sequence in detail

A typical sensor-based homing procedure follows these stages.

Stage 1: Pre-checks

Before movement, verify:

  • Servo drive is ready.
  • Required safety functions are healthy.
  • No blocking drive fault is active.
  • The axis is within a permissible starting condition.
  • The home sensor input is valid.
  • Search direction and speed are configured correctly.
  • The intended movement path is clear.
  • Any required brake-release sequence is correct.

The exact preconditions depend on the machine's risk assessment and control design.

Stage 2: Initial search

The axis moves toward the reference using the configured search direction and speed.

If the sensor is already active, the controller may back away before searching, depending on the selected homing mode.

Stage 3: Reference detection

The controller detects the relevant sensor transition or reference event.

This may be the sensor turning on, turning off, or the encoder index being detected. The expected event must match the selected homing method.

Stage 4: Back-off and precise approach

Some methods move away from the sensor and then approach it again at a lower speed.

This can improve repeatability by using a consistent direction of approach and reducing variation associated with sensor switching or mechanical backlash.

Not every homing method uses a back-off movement.

Stage 5: Reference establishment

The controller assigns the reference coordinate or applies the configured offset.

For example, the sensor may activate at a physical coordinate of 25 mm, while the controller assigns the machine coordinate 0 mm at that detected reference. The configured offset defines the relationship.

Stage 6: Completion verification

The controller confirms successful completion and sets the relevant status.

The sequence should distinguish between:

  • Homing command accepted.
  • Homing in progress.
  • Homing completed successfully.
  • Homing aborted.
  • Homing failed.
  • Reference invalid.

A timer alone should not be used to declare the axis homed.

7. Home offsets and coordinate systems

A home offset defines how the detected reference relates to the machine coordinate origin.

Suppose the reference sensor is detected at a particular physical position. The controller can assign a configured coordinate to that position.

Example:

  • Detected reference location: physical position associated with the sensor.
  • Configured machine coordinate at detection: 20 mm.
  • Desired machine zero: 0 mm at another calibrated location.

The controller applies the configured coordinate relationship so that subsequent position commands use the intended machine coordinates.

The sign convention and exact calculation vary by controller.

Why home offsets matter

Incorrect offsets can cause:

  • Every position to be shifted by a constant amount.
  • Incorrect station alignment.
  • Unexpected movement toward a fixture.
  • Reduced clearance from machine limits.
  • Incorrect absolute positioning after homing.

When a machine repeatedly reaches the same incorrect coordinate, check the offset and scaling before assuming the encoder is defective.

8. Homing speed and approach direction

Homing speed affects both cycle time and reference quality.

Parameter Purpose Consideration
Search speed Moves the axis toward the reference region Faster movement reduces homing time but may reduce detection margin
Approach speed Allows a more controlled final reference approach Lower speed can improve repeatability in suitable methods
Back-off distance Moves away from an active sensor Must be sufficient to clear the required sensor state
Search direction Defines the direction used to find the reference Must match the machine arrangement and coordinate convention
Acceleration/deceleration Controls how motion begins and ends Must suit the mechanism and reference method
Home offset Establishes the coordinate relationship Must be validated against the physical machine

The fastest homing routine is not necessarily the best one. A small reduction in homing time is rarely worth repeated reference errors or a collision with the machine structure.

9. Home sensors and their electrical behavior

Homing can depend on proximity sensors, limit switches, optical sensors, or other supported reference devices.

Common industrial sensor arrangements include:

  • Inductive proximity sensors.
  • Mechanical limit switches.
  • Optical sensors.
  • Magnetic sensors.
  • Dedicated reference sensors.

The input may be normally open (NO) or normally closed (NC), depending on the design.

The controller must interpret the sensor state correctly. An incorrectly configured input can make the axis believe the reference is active when it is not, or fail to detect a valid reference.

Checks include:

  • Sensor supply voltage.
  • Correct output type and PLC input compatibility.
  • Correct wiring and polarity.
  • Sensor mounting and target alignment.
  • Input filtering and response time.
  • Sensor state before homing begins.
  • Correct configured active state.
  • Cable damage and intermittent connections.

For safety-related limit functions, the required architecture and diagnostic coverage must follow the machine's safety design. An ordinary sensor input does not automatically provide a safety-rated function.

10. Incremental versus absolute encoders during homing

Feature Incremental encoder Absolute encoder
Position information Based on counted movement from an established reference Encoded position value within its supported range
Power-cycle behavior Position reference may be lost unless retained by the system Position information can be available after power-up, depending on encoder type and system
Routine homing Often required May be unnecessary in a validated system
Index pulse Common on supported incremental encoders Not necessarily used in the same way
Main reference concern Establishing a known count origin Validating the encoder value against the machine coordinate system
Typical fault Lost counts or invalid reference Invalid data, communication error, or invalid coordinate mapping

Some absolute encoders are single-turn, while others are multi-turn. A single-turn encoder reports position within one revolution; a multi-turn encoder also tracks position across multiple revolutions within its specified range.

Even a multi-turn encoder does not automatically eliminate every need for homing. The mechanical axis, controller configuration, retained-position behavior, and maintenance history must be considered.

11. Homing versus positioning

Feature Homing Positioning
Primary purpose Establish or validate the reference Move to a target coordinate
Typical target Reference event or calibrated home coordinate Requested position
Main inputs Sensor, encoder reference, configuration Target position and motion parameters
Completion meaning Reference established according to the selected method Target move completed according to configured criteria
Common failure Reference not detected or invalid Target not reached or position error
Relationship Often establishes the basis for absolute commands Uses the configured coordinate system

Homing is often performed before normal absolute positioning, but the required sequence depends on the machine design.

12. Homing state machine

A robust control sequence should track the homing state explicitly.

          Start request
                |
                v
          Check readiness
                |
                v
          Check sensor state
                |
                v
           Search motion
                |
                v
         Detect reference
                |
                v
       Back-off if required
                |
                v
       Precise approach if required
                |
                v
       Establish coordinate
                |
                v
          Verify completion
                |
                v
            HOMED = TRUE

Fault paths must exist at appropriate stages:

Homing active
     |
     +---- Timeout ----------> Homing fault
     |
     +---- Drive fault ------> Abort / fault handling
     |
     +---- Safety condition -> Stop according to safety design
     |
     +---- Invalid sensor ---> Diagnostic / abort

The specific stop behavior must follow the drive, controller, and machine safety requirements.

Important sequence logic

  • Prevent duplicate homing commands from unintentionally restarting the procedure.
  • Monitor the correct sensor transition.
  • Use a timeout as a fault detector, not as proof of successful homing.
  • Abort or stop according to the specified response when a blocking fault occurs.
  • Clear or invalidate the homed status when reference validity is lost.
  • Prevent normal absolute movement if the required reference is invalid.
  • Record the failure stage to simplify troubleshooting.

13. PLC motion-control implementation

Motion-control platforms use different function blocks and status bits. A conceptual sequence is:

IF Axis_Ready AND Homing_Request AND Safety_OK THEN
    Start_Homing_Command
END_IF

IF Homing_Active THEN
    Monitor_Reference_Sensor
    Monitor_Drive_Fault
    Monitor_Homing_Timeout
END_IF

IF Homing_Done AND NOT Homing_Error THEN
    Set_Reference_Valid
END_IF

This is illustrative logic, not a complete production-ready program. Real implementation must handle command-edge requirements, axis state, abort behavior, reset behavior, timeout timing, and the specific controller's motion library.

Common motion-control platforms may provide a dedicated homing instruction, such as MC_Home, but the exact interface and behavior depend on the implementation.

Common PLC logic errors

  • Setting Homed when the command starts instead of when it completes.
  • Failing to reset Homed when reference validity is lost.
  • Ignoring a sensor that is already active at startup.
  • Using the wrong sensor transition.
  • Missing a timeout or fault path.
  • Allowing normal movement while homing is still active.
  • Treating a drive-ready bit as proof that the axis is referenced.

14. Common homing faults and troubleshooting

Symptom Possible causes Checks
Axis moves but never homes Sensor not detected, incorrect input mapping, wrong search direction Check sensor state, wiring, configuration, and motion direction
Homing fails immediately Sensor already active, axis not ready, invalid starting condition Check the starting sensor state and axis diagnostics
Axis moves away from the reference Incorrect direction configuration or wrong homing mode Verify positive direction and configured search direction
Reference changes between cycles Sensor repeatability, mounting movement, variable approach direction, backlash Inspect sensor mounting and homing sequence
Axis reaches the sensor but does not complete Wrong transition expected, missing index, incorrect mode Check sensor transition and encoder index requirements
Homing times out Sensor not reached, wrong speed, obstruction, incorrect timeout Verify travel path, configured speed, sensor, and timeout
Homed status is lost after power cycle Reference not retained, incremental feedback, configured invalidation behavior Check encoder type and controller reference-retention settings

Axis reaches the wrong machine coordinate after homing Incorrect home offset, scaling, or reference assignment Check offsets, encoder resolution, and mechanical transmission

Home sensor flickers Poor alignment, vibration, electrical interference, wiring issue Check mounting, sensor target, wiring, and input filtering
Homing works only intermittently Loose connectors, cable damage, inconsistent sensor transitions Inspect physical connections and monitor the input during motion

15. Practical troubleshooting procedure

When homing fails, use a staged diagnostic method.

  1. Record the drive or motion-controller fault code and the homing stage where the failure occurred.
  2. Verify the axis is in the required ready state and all necessary safety conditions are satisfied.
  3. Check the home sensor's live state in the PLC or controller.
  4. Confirm the sensor's active polarity and the transition expected by the selected homing method.
  5. Verify the configured search direction, speed, acceleration, and travel range.
  6. Check whether the encoder index pulse is required and whether the system can detect it.
  7. Review the home offset, scaling, and coordinate assignment.
  8. Inspect sensor mounting, mechanical backlash, cable damage, and connector condition.
  9. Validate timeout and abort handling.
  10. After correction, execute a controlled test under the approved procedure and verify the resulting physical coordinate.

Do not keep retrying homing if the axis moves in an unexpected direction. Establish the cause before another movement attempt.

16. Safety considerations

Homing often moves an axis without relying on a previously validated machine coordinate. That makes the sequence particularly important to design and test correctly.

  • Confirm that the movement path is clear before starting homing.
  • Verify the correct search direction and travel assumptions.
  • Do not assume a home sensor is a safety-rated limit device.
  • Ensure the axis cannot cause a collision if the sensor fails or is incorrectly mapped.
  • Secure vertical or gravity-loaded axes against uncontrolled movement.
  • Confirm required guards and safety functions are active.
  • Follow the specified response to drive faults, invalid feedback, or loss of safety conditions.
  • Do not bypass reference or limit checks to force a homing-complete status.
  • Validate sensor changes and homing parameter changes under controlled conditions.
  • Ensure maintenance work follows the site's isolation and authorization procedures.

A homing routine is operational control logic. It does not replace the independent safety functions required by the machine risk assessment.

17. Interview questions and answers

1. What is homing?

Homing establishes or validates the reference position used by the machine coordinate system.

2. Why is homing required with an incremental encoder?

The controller may lose its position reference after power loss or loss of count integrity. Homing establishes a known reference before coordinate-dependent movement.

3. Does an absolute encoder eliminate homing?

Not always. The encoder may provide a valid position value, but the controller may still need to validate the machine coordinate relationship or execute a machine-specific reference procedure.

4. What is a home offset?

A configured coordinate adjustment that relates the detected reference to the intended machine coordinate origin.

5. Why does some homing use an encoder index pulse?

The index pulse can provide a repeatable encoder reference event after the home sensor identifies the reference region.

6. Why does a homing routine use a slow approach?

A controlled approach can improve reference repeatability and reduce the effect of detection timing and mechanical variation.

7. What happens if the home sensor is active before homing starts?

The controller must follow the selected homing method's defined behavior, which may include backing away before searching. The starting sensor state should not be ignored.

8. What is the difference between machine zero and the home sensor location?

The sensor identifies a physical reference event. The controller can apply an offset so that the corresponding machine coordinate is different from the sensor's physical location.

9. Why is a homing timeout needed?

It detects a failure to complete the expected sequence within the permitted time. It should trigger fault handling, not declare the axis homed.

10. What causes inconsistent home positions?

Possible causes include sensor variation, loose mounting, backlash, different approach directions, incorrect input filtering, or poor signal integrity.

11. What is homed status?

It indicates that the controller considers the reference procedure complete according to its configured conditions. The exact semantics depend on the platform.

12. Why should normal absolute moves be inhibited when the reference is invalid?

The controller may not know the true machine coordinate, so the commanded target may not correspond to the intended physical location.

13. Can a limit switch be used for homing?

It can be part of a supported homing method, but its intended function, configuration, and safety role must be verified.

14. Why can a home offset cause every station to be misaligned?

Because all subsequent machine coordinates are interpreted relative to the established reference and configured offset.

15. What should be checked if homing works in one direction but not the other?

Check search direction, sensor location and state, axis limits, the selected homing mode, and the configured coordinate convention.

18. Practical exercises

Exercise 1: Homing timeout

A linear transfer axis moves toward its home sensor but reaches the configured timeout without setting Homed.

Investigate:

  • Live sensor state.
  • Sensor wiring and input mapping.
  • Search direction and permitted travel.
  • Sensor mounting and target alignment.
  • Whether the selected homing mode expects a rising or falling transition.
  • Whether an encoder index pulse is required.

Record the failure stage rather than repeatedly restarting the routine.

Exercise 2: Repeatability problem

The axis homes successfully every time, but its physical reference differs slightly between cycles.

Investigate:

  • Sensor switching repeatability.
  • Mechanical looseness and backlash.
  • Approach direction and speed.
  • Whether a back-off and precise approach are required.
  • Encoder index usage.
  • Coordinate offset and scaling.

Separate variation in the reference-detection process from variation caused by the mechanical system.

Exercise 3: Absolute encoder after maintenance

A machine uses an absolute encoder. After a gearbox replacement, the encoder reports a valid position, but the machine's station coordinates are incorrect.

Investigate:

  • Changed transmission ratio or mechanical relationship.
  • Coordinate mapping and offset.
  • Encoder mounting and mechanical alignment.
  • Retained position versus actual load position.
  • Whether the machine requires recalibration or homing after maintenance.

An absolute encoder cannot compensate automatically for a changed mechanical relationship.

19. Final mental model

Homing establishes the relationship between the feedback system and the machine coordinate system.

  • Encoder feedback reports motion or position.
  • Home sensors and index pulses can identify a reference event.
  • The homing method determines how that event is found.
  • The home offset and scaling determine how the event maps to machine coordinates.
  • The controller establishes reference validity only after the required sequence succeeds.
  • Positioning commands then use the configured coordinate system.
  • Safety functions constrain hazardous movement independently of ordinary homing logic where required.

A valid encoder reading does not automatically mean the machine is correctly referenced. Homing is complete only when the defined reference procedure has succeeded and the resulting coordinate relationship is valid.
