1. Purpose and Scope

Industrial machine vision inspection tools analyze captured images to determine whether a component is present, correctly positioned, dimensionally acceptable, correctly assembled, or visually consistent with a reference.

The camera captures pixels. The lighting creates useful contrast. The inspection tools convert image information into measurable features and decisions.

In automotive manufacturing, these tools are commonly used for:

  • Checking whether clips, bolts, nuts, connectors, seals, and labels are present.
  • Verifying component orientation and assembly position.
  • Measuring hole diameters, distances, gaps, offsets, and edge positions.
  • Matching a component against a trained reference pattern.
  • Detecting incorrect variants or misplaced components.
  • Reading barcodes, QR codes, Data Matrix codes, and characters.
  • Detecting surface defects and abnormal features.
  • Sending pass/fail results and measurements to a PLC or robot.

The central engineering objective is to select an inspection method that detects the actual failure modes reliably, while minimizing false acceptance, false rejection, processing time, and maintenance effort.

The inspection program normally consists of several dependent operations rather than one isolated tool.

For example, a system checking a bolt on a metal bracket might first locate the bracket, then identify the bolt region, check bolt presence, measure its position, and finally evaluate whether the measured position falls within tolerance.

If the bracket is not located correctly, measurements and presence checks that depend on its location may also become invalid.

4. Image Preprocessing

Image preprocessing modifies an image before the inspection tools analyze it. The objective is to improve the reliability of subsequent operations without removing the information needed to detect defects.

Common preprocessing operations include:

  • Grayscale conversion.
  • Brightness and contrast adjustment.
  • Thresholding.
  • Noise filtering.
  • Morphological operations.
  • Region-of-interest cropping.
  • Image normalization.
  • Geometric correction.
  • Color-space conversion.

4.1 Grayscale conversion

A color image contains multiple color channels. Grayscale conversion reduces the image to intensity values.

This can simplify inspection when the feature is defined by brightness or contrast rather than color.

However, converting to grayscale can eliminate useful distinctions between colors that have similar brightness. If color is essential to identifying a component variant, retain the relevant color information.

4.2 Thresholding

Thresholding classifies pixels according to an intensity value or a range of values.

For a simple grayscale threshold:

\[ I(x,y) \geq T \]

Where:

  • \(I(x,y)\) is the pixel intensity.
  • \(T\) is the selected threshold.

Pixels meeting the condition may be assigned to the foreground, while other pixels are assigned to the background.

Thresholding is useful for high-contrast presence detection, silhouette analysis, and counting isolated objects. It becomes unreliable when lighting changes, the surface is reflective, or foreground and background intensities overlap.

4.3 Noise filtering

Noise filtering reduces unwanted pixel variations that can create false edges, fragmented regions, or unstable measurements.

Examples include median filtering and Gaussian filtering. These methods have different effects on edges and fine details.

Excessive filtering can erase small defects or shift apparent boundaries. The filter should be selected according to the smallest feature that must be preserved.

4.4 Morphological operations

Morphological processing modifies the shape of binary regions.

  • Erosion: Shrinks foreground regions.
  • Dilation: Expands foreground regions.
  • Opening: Erosion followed by dilation, often used to remove small foreground objects.
  • Closing: Dilation followed by erosion, often used to fill small gaps or holes.

These operations can clean binary images, but they may also remove valid small features or merge separate objects. Kernel size and shape must be chosen carefully.

5. Region of Interest (ROI)

A region of interest is the portion of an image in which an inspection tool is allowed to operate.

For example, if a camera captures an entire automotive bracket, the presence check for a clip may only need to examine a small area around the expected clip position.

Using an ROI can:

  • Reduce processing time.
  • Exclude irrelevant features.
  • Reduce interference from background objects.
  • Improve the stability of thresholding and measurement.
  • Simplify inspection logic.

However, a fixed ROI is only reliable if the part position is sufficiently repeatable.

If the part shifts on the fixture, the expected feature may move outside the ROI. A more robust approach is to locate the part first and then position the ROI relative to that detected reference.

5.1 Fixed versus part-relative ROI

Characteristic Fixed ROI Part-relative ROI
Reference Fixed image coordinates Located part or feature
Processing Usually simpler Requires a reliable locating step
Position variation Sensitive to part movement Can accommodate defined translation and rotation
Typical use Stable fixtures Variable positioning or robot-loaded parts
Main risk Feature moves outside ROI Incorrect localization propagates downstream

A part-relative ROI is often preferable when the component is not guaranteed to appear at exactly the same pixel coordinates in every cycle.

6. Presence and Absence Inspection

Presence inspection determines whether a required component or feature exists in the expected region.

Examples include:

  • Clip present or missing.
  • Bolt installed or absent.
  • Connector inserted or disconnected.
  • Seal present or missing.
  • Label applied or absent.
  • Hole open or obstructed.
  • Adhesive bead present in a specified region.

6.1 Common methods

Intensity or threshold check: Determine whether a region contains pixels above or below a threshold.

Blob analysis: Identify connected regions and check their size, location, or count.

Pattern matching: Search for the expected appearance of a component.

Edge or shape detection: Confirm that a required boundary or geometric feature exists.

Color check: Determine whether the expected color is present in a region.

Feature-based classification: Use multiple visual features or a trained classifier to determine whether the component is present.

The method should match the physical appearance of the component and the expected failure modes.

6.2 Example: clip presence

Suppose a plastic clip must be installed on a metal bracket.

A possible inspection sequence is:

  1. Locate the bracket.
  2. Define an ROI relative to the bracket.
  3. Check for the expected clip shape or pattern.
  4. Evaluate the detection score and position.
  5. Return PRESENT, MISSING, or INVALID.

A simple brightness check may fail if a dark stain or shadow resembles the clip. Pattern matching or a combination of shape and position checks may be more reliable.

6.3 Important distinction: missing versus invalid

A missing component is a valid inspection finding. An invalid result means the inspection could not produce a trustworthy decision.

Examples of invalid conditions include:

  • Camera image not received.
  • Part not located.
  • Image too dark or saturated.
  • Tool execution failure.
  • Confidence below an acceptable limit.
  • Inspection timeout.

These states should not be combined into a single pass/fail output without defining the intended fault behavior.

7. Pattern Matching

Pattern matching locates a known visual pattern in a new image.

The vision system uses a trained or configured reference pattern and searches for a sufficiently similar region in the captured image.

Depending on the algorithm, the pattern may tolerate changes in translation, rotation, scale, illumination, or partial visibility. The supported transformations and tolerance limits depend on the specific tool.

7.1 How pattern matching works

A typical process is:

  1. Capture a reference image of the target feature.
  2. Select the pattern region.
  3. Configure the permitted search region.
  4. Define acceptable rotation or scale variation if supported.
  5. Run the search on a new image.
  6. Evaluate the matching score and detected position.
  7. Reject ambiguous or low-confidence matches.

7.2 Matching score

Many vision systems return a score indicating how closely a detected region resembles the reference pattern.

A score may be represented on a normalized scale, such as 0 to 1 or 0 to 1000, but scoring conventions vary by manufacturer and algorithm.

A high score does not automatically prove that the part is correct. A visually similar incorrect component may also produce a high score.

Set acceptance criteria using representative good and bad parts rather than selecting a threshold based on one successful image.

7.3 Translation and rotation

A component may move horizontally, vertically, or rotate slightly between images.

A suitable pattern-matching tool may return:

  • X position.
  • Y position.
  • Rotation angle.
  • Match score.
  • Number of detected matches.
  • Validity status.

These outputs can be used to reposition downstream inspection regions or provide a robot with a corrected target location.

7.4 Pattern matching versus presence inspection

Pattern matching can be used to perform presence inspection, but the concepts are not identical.

Presence inspection asks whether a required feature exists. Pattern matching is one method for finding a known visual pattern.

A simple presence check may be faster and more robust when the feature has a stable, high-contrast signature. Pattern matching is more useful when the component can move or rotate within a defined range.

7.5 Limitations

Pattern matching can become unreliable when:

  • Lighting differs significantly from the reference.
  • The part is rotated beyond the supported range.
  • Scale changes exceed the permitted tolerance.
  • The target is partly hidden.
  • Surface appearance varies between acceptable parts.
  • Background objects resemble the target.
  • The target pattern is repetitive or has insufficient distinctive features.

For repeated components, use the returned location and score together with other checks. Do not assume that the first detected match is always the correct component.

8. Edge Detection

Edge detection identifies a boundary where image intensity or color changes.

Typical applications include:

  • Measuring distances between two boundaries.
  • Finding the outer profile of a component.
  • Measuring slot width.
  • Detecting the edge of a hole.
  • Locating a machined shoulder.
  • Measuring gaps and offsets.

8.1 Edge polarity

An edge may be defined by a transition from dark to bright or bright to dark.

For example:

  • A dark component against a bright backlight creates one type of transition at each boundary.
  • A bright marking against a dark surface creates the opposite transition.

Selecting the expected edge polarity can reduce false detections.

8.2 Edge position and measurement

If two detected edges are located at coordinates \(x_1\) and \(x_2\), their image-space separation is:

\[ d\_{\text{pixels}} = |x_2-x_1| \]

If a valid calibration gives a scale \(s\) in millimetres per pixel, a simplified physical distance estimate is:

\[ d\_{\text{mm}} = d\_{\text{pixels}} \times s \]

This conversion assumes that the calibration scale is appropriate for the measurement direction and location. Perspective, lens distortion, tilted parts, and varying depth can require a more complete calibration model.

8.3 Subpixel edge localization

Some tools estimate an edge position to a fraction of a pixel by analyzing the intensity profile around the boundary.

Subpixel estimation can improve measurement resolution, but it does not guarantee equivalent physical accuracy. Optical blur, contrast, noise, calibration error, and mechanical variation still affect the result.

9. Dimensional Measurement Tools

Dimensional tools calculate physical or image-space properties from detected features.

Common measurements include:

  • Distance between two points.
  • Distance between parallel edges.
  • Diameter and radius.
  • Width and height.
  • Angle between lines.
  • Hole spacing.
  • Gap and offset.
  • Center position.
  • Contour dimensions.
  • Relative alignment.

9.1 Measurement workflow

Locate Part
    ↓
Find Relevant Edges or Features
    ↓
Fit Lines, Circles, or Other Geometry
    ↓
Calculate Dimensions
    ↓
Apply Calibration
    ↓
Compare With Specification Limits
    ↓
PASS / FAIL / INVALID

The precise sequence depends on the vision platform. Some systems perform calibration and geometric fitting as part of the measurement tool.

9.2 Tolerance checking

Suppose a hole diameter must be between 9.90 mm and 10.10 mm.

The decision logic is:

\[ 9.90 \leq d \leq 10.10 \]

If the measured diameter is 10.03 mm, it lies within the specified limits. If the measurement is 10.14 mm, it lies outside the limits.

The inspection should also account for invalid measurements. A tool failure must not be interpreted as a valid measurement inside tolerance.

9.3 Measurement accuracy considerations

Reliable measurement depends on:

  • Suitable camera resolution and pixel scale.
  • Lens quality and distortion.
  • Stable illumination and edge contrast.
  • Calibration quality.
  • Part positioning and fixturing.
  • Mechanical vibration.
  • Temperature effects.
  • Algorithm repeatability.
  • Reference-standard accuracy.

A vision system should be verified with known reference dimensions across the actual measurement range, not merely checked using one part at the center of the image.

10. Blob Analysis

Blob analysis identifies connected regions of pixels that meet defined image criteria.

A blob is a connected foreground region in a binary image or a segmented region identified by the algorithm.

Blob tools commonly calculate:

  • Area.
  • Centroid.
  • Bounding rectangle.
  • Width and height.
  • Perimeter.
  • Circularity.
  • Aspect ratio.
  • Orientation.
  • Number of detected regions.

10.1 Typical applications

  • Counting clips or fasteners.
  • Checking whether a connector pin is present.
  • Measuring the visible area of a feature.
  • Detecting contamination or missing material.
  • Identifying connected regions after thresholding.
  • Comparing region shapes.

10.2 Area

The simplest blob area is the number of pixels belonging to the connected region.

\[ A\_{\text{pixels}} = N\_{\text{foreground pixels}} \]

If a suitable calibration maps the image to a physical plane and each pixel represents a constant area, an approximate physical area can be calculated. In real systems, perspective and distortion may require spatially varying calibration.

10.3 Centroid

The centroid represents the geometric center of a detected region. It is useful for estimating feature position or comparing the location of a component against an expected coordinate.

10.4 Limitations

Blob analysis can fail when:

  • Separate objects merge into one region.
  • A single object breaks into multiple regions.
  • Lighting creates false foreground pixels.
  • Thresholding removes weakly contrasted areas.
  • Surface texture produces noise.
  • Shadows change the apparent shape.

Morphological processing may improve segmentation, but it must be configured so that legitimate defects and small components are not removed.

11. Counting and Object Verification

Counting tools identify multiple objects or features and compare the detected count with an expected quantity.

Examples include:

  • Checking that four clips are installed.
  • Confirming a specified number of connector pins are visible.
  • Counting components in a tray.
  • Verifying the number of fasteners in an assembly.
  • Counting products on a conveyor.

A simple count check may be expressed as:

\[ N\_{\text{detected}} = N\_{\text{expected}} \]

If six fasteners are required, a detected count of five should fail the inspection.

However, count alone does not prove that the correct objects are present. One incorrect component may replace a missing component while keeping the total count unchanged.

A robust inspection can combine:

  • Object count.
  • Individual component presence.
  • Expected spatial positions.
  • Component type or pattern.
  • Orientation and dimensional checks.

12. Color Inspection

Color inspection determines whether a feature has the expected color or falls within an acceptable color range.

Typical applications include:

  • Identifying connector variants.
  • Checking colored clips or labels.
  • Verifying paint or coating appearance.
  • Detecting incorrect wire colors.
  • Distinguishing products with similar geometry.

Color tools may operate in RGB, HSV, Lab, or another color space.

12.1 Why color space matters

RGB values depend on the camera's color response, white balance, illumination spectrum, and exposure.

HSV separates hue, saturation, and value into different components, which can simplify some color classification tasks.

Lab represents color using lightness and chromatic components and is useful in some color-difference applications.

No color space eliminates the need for controlled illumination and calibration where color accuracy is important.

12.2 Common failure modes

  • Different illumination wavelengths alter the recorded color.
  • Automatic white balance changes image appearance.
  • Reflections introduce highlights with low color saturation.
  • Dirt or oil changes the apparent color.
  • Incorrect exposure clips one or more color channels.
  • A color threshold is too narrow for normal production variation.

Color inspection should be validated using real components under the final lighting conditions.

13. OCR, OCV, and Code Reading

These tools are related but serve different purposes.

OCR, Optical Character Recognition: Reads text from an image and converts it into machine-readable characters.

OCV, Optical Character Verification: Checks whether printed or marked characters match an expected reference or satisfy defined quality criteria.

Barcode and 2D-code reading: Decodes encoded information from symbols such as barcodes, QR codes, and Data Matrix codes.

Typical applications include:

  • Serial-number traceability.
  • Part-number verification.
  • Date and batch-code reading.
  • Label verification.
  • Component identification.
  • Production history tracking.

A successful read does not necessarily mean the code belongs to the correct part. The decoded value may need to be compared against a recipe, production order, or PLC-provided expected value.

Likewise, a valid code does not prove that the component is correctly assembled. Identification and physical inspection are separate requirements.

14. Surface Defect Inspection

Surface inspection looks for visual abnormalities such as:

  • Scratches.
  • Cracks.
  • Dents.
  • Burrs.
  • Contamination.
  • Stains.
  • Missing coatings.
  • Incomplete adhesive or sealant.
  • Unusual surface texture.

Possible approaches include:

  • Intensity thresholding.
  • Edge and contour analysis.
  • Blob analysis.
  • Reference-image comparison.
  • Texture analysis.
  • Classical feature-based methods.
  • Machine-learning or deep-learning classification and segmentation.

14.1 Rule-based versus learning-based inspection

Rule-based inspection uses explicitly configured measurements, thresholds, geometry, or image features. It is often easier to interpret and maintain for stable, well-defined tasks.

Learning-based inspection uses examples to learn patterns associated with classes or defects. It can be useful for complex surface variation that is difficult to describe using fixed rules.

Learning-based systems require representative training and validation data, controlled model versions, and monitoring for changes in production conditions. They are not automatically more reliable than classical tools.

15. Pattern Matching Versus Edge Detection Versus Blob Analysis

Feature Pattern matching Edge detection Blob analysis
Main objective Locate a known visual pattern Find boundaries Analyze connected regions
Typical output Position, angle, score Edge coordinates Area, centroid, shape
Handles defined rotation Depending on tool configuration Usually through geometric processing Orientation can be calculated for suitable regions
Requires segmentation Not always Usually not full binary segmentation Commonly uses segmented regions
Best suited for Component localization and known shapes Dimensional boundaries Counting and region properties
Main weakness Similar-looking patterns or appearance changes Weak or noisy edges Merged or fragmented regions

These tools are complementary. A robust inspection often uses pattern matching to locate a component, edge detection to measure a feature, and blob analysis to count or evaluate regions.

16. Inspection Sequencing and Dependency Management

Inspection tools should be arranged in a deliberate order.

For example, consider a fixture that must confirm the presence and position of two fasteners.

Acquire Image
     ↓
Check Image Validity
     ↓
Locate Main Component
     ↓
Calculate Part Coordinate Frame
     ↓
Inspect Fastener 1
     ↓
Inspect Fastener 2
     ↓
Evaluate Position and Presence
     ↓
Combine Results
     ↓
Send Final Status to PLC

The main component is located before the fasteners are inspected because their expected positions depend on the component's location.

If the main component cannot be located, downstream measurements should be marked invalid. Continuing with stale coordinates can produce plausible-looking but incorrect results.

16.1 Result aggregation

A basic final decision may be:

  • PASS: All required checks completed successfully and met their criteria.
  • FAIL: At least one valid inspection found a nonconforming feature.
  • INVALID: A trustworthy decision could not be produced.
  • FAULT: The vision system or communication process encountered a defined fault.

Some systems use separate result codes for inspection failure, camera failure, communication failure, and processing timeout.

The exact state model should be agreed with the PLC programmer and quality process owner.

17. Thresholds, Scores, and Decision Limits

Thresholds determine where an inspection tool draws a decision boundary.

Examples include:

  • Minimum pattern-matching score.
  • Minimum blob area.
  • Maximum permitted diameter.
  • Acceptable color range.
  • Minimum edge contrast.
  • Maximum positional offset.
  • Minimum classification confidence.

Thresholds should be selected using representative samples, including normal variation and known failure conditions.

17.1 False acceptance and false rejection

False acceptance: A defective or incorrect part is accepted.

False rejection: An acceptable part is rejected.

Both affect manufacturing performance, but their consequences may differ significantly depending on the characteristic being inspected.

Decision outcome Actual acceptable part Actual defective part
System accepts Correct acceptance False acceptance
System rejects False rejection Correct rejection

The target balance depends on the quality risk, customer requirements, and process capability. For critical defects, the system may prioritize reducing false acceptance, while maintaining a controlled and measurable false-rejection rate.

17.2 Avoid tuning to a single sample

One good part is not enough to establish a reliable threshold.

Validation should include:

  • Multiple acceptable parts.
  • Known defective parts.
  • Different component lots and finishes.
  • Position and orientation variation.
  • Expected lighting variation.
  • Production-speed conditions.
  • Realistic background and contamination conditions.

The threshold should separate the expected distributions of acceptable and defective cases with an adequate safety margin.

18. Example: Complete Inspection of an Automotive Bracket

Suppose an assembly contains a bracket, two bolts, and one plastic clip.

The inspection requirements are:

  • Confirm the bracket is correctly positioned.
  • Confirm both bolts are present.
  • Measure the distance between the bolt centers.
  • Confirm the clip is installed.
  • Return a single final result to the PLC.

A suitable design is:

  1. Locate the bracket using pattern matching or geometric features.
  2. Define bolt and clip ROIs relative to the bracket coordinate frame.
  3. Use presence tools or pattern matching to detect each bolt and the clip.
  4. Use edge or circle fitting to locate the bolt centers.
  5. Calculate the center-to-center distance.
  6. Compare the measurement with the engineering tolerance.
  7. Confirm every required tool returned a valid result.
  8. Aggregate the results into the final inspection state.
  9. Send the result and, if required, measurement values to the PLC.

Example decision logic:

IF bracket_location_valid
AND bolt_1_present
AND bolt_2_present
AND clip_present
AND bolt_spacing_within_tolerance
THEN
    RESULT = PASS
ELSE IF all_required_inspections_valid
    RESULT = FAIL
ELSE
    RESULT = INVALID

The exact implementation must distinguish an actual failed component check from a tool or acquisition error. A production system should also associate the result with the correct part and inspection cycle.

19. PLC and Robot Integration Considerations

Although the next topic covers communication in detail, inspection tools should be designed with the result interface in mind.

Typical data exchanged with a PLC or robot includes:

  • Trigger acknowledgment.
  • Inspection busy status.
  • Inspection complete status.
  • Overall pass/fail status.
  • Invalid or fault status.
  • Position coordinates.
  • Rotation angle.
  • Measurement values.
  • Pattern-matching score.
  • Defect or failure code.
  • Part identification or tracking information.

The vision system should produce clearly defined outputs rather than relying on ambiguous combinations of bits.

For example, a measurement value of zero should not be used to indicate both a real zero measurement and a failed measurement. A separate validity flag or status code is required.

A PLC should also detect missing results, unexpected state transitions, and timeouts. It must not reuse the previous part's result for the current part.

21. Maintenance, Validation, and Version Control

Vision inspection programs should be treated as controlled production systems rather than collections of adjustable thresholds.

Recommended practices include:

  • Back up inspection programs, camera settings, calibration files, and reference patterns.
  • Record tool versions and parameter changes.
  • Store representative acceptable and defective images.
  • Verify measurement tools using known reference artifacts.
  • Challenge presence and pattern tools with known missing or incorrect components.
  • Monitor false-rejection and false-acceptance trends.
  • Check that ROIs remain correctly positioned after mechanical changes.
  • Validate after camera, lens, lighting, fixture, or software changes.
  • Record the reason, approver, and validation result for parameter changes.
  • Keep a documented recovery procedure for corrupted or incorrect inspection configurations.

Where traceability is required, save the inspection result alongside the part identity, timestamp, program version, and relevant measurement data.

22. Interview Questions and Answers

1. What is a region of interest?

An ROI is the image area in which an inspection tool operates. It reduces irrelevant processing and can improve reliability when correctly positioned.

2. What is pattern matching used for?

It locates a known visual pattern in an image and may return the position, rotation, and matching score.

3. What is blob analysis?

Blob analysis identifies connected image regions and calculates properties such as area, centroid, dimensions, orientation, and count.

4. What is the difference between presence inspection and pattern matching?

Presence inspection is the objective of confirming that a feature exists. Pattern matching is one possible technique for locating and confirming a known appearance.

5. Why should the part be located before downstream measurements?

The location establishes the coordinate reference for subsequent ROIs and measurements. If the part moves, a fixed inspection region may target the wrong area.

6. What is the difference between a false acceptance and a false rejection?

A false acceptance occurs when a defective part passes. A false rejection occurs when an acceptable part fails.

7. Why is a high pattern-matching score not sufficient proof of a correct assembly?

An incorrect component or a similar background feature may resemble the reference. Additional checks may be needed to verify identity, position, dimensions, or assembly state.

8. Why is calibration necessary for dimensional inspection?

Calibration establishes the relationship between image coordinates and physical dimensions and can correct systematic optical or geometric effects.

9. What should happen when a vision tool returns an invalid result?

The system should report the invalid state and execute the defined recovery or fault-handling sequence. It should not automatically treat the result as a pass.

10. Why is a single good image insufficient for validation?

A single image does not represent normal production variation, defective conditions, position changes, or environmental effects. Representative validation samples are necessary.

11. Can several vision tools be combined in one inspection?

Yes. A common sequence locates the part, checks presence, measures dimensions, evaluates tolerances, and combines the results into one final decision.

12. What is the difference between OCR and OCV?

OCR reads characters and returns text. OCV verifies that characters or markings match an expected appearance or standard.

23. Practical Exercises

  1. Create a simple presence inspection for a component that can be removed and reinstalled.
  2. Test a fixed ROI and a part-relative ROI while deliberately shifting the part.
  3. Train or configure a pattern-matching tool and record its position and score for different orientations.
  4. Measure a known distance using edge detection and compare the result with a calibrated reference.
  5. Use blob analysis to count components and observe how shadows or merged regions affect the count.
  6. Compare grayscale thresholding with color-based inspection on a colored component.
  7. Test acceptable and defective samples to estimate false-acceptance and false-rejection behavior.
  8. Create a sequence with PASS, FAIL, and INVALID results and verify the state transitions.
  9. Simulate a part-location failure and ensure downstream tools do not reuse stale coordinates.
  10. Back up the inspection program and verify that it can be restored without losing calibration or reference data.

24. Final Mental Model

Machine vision inspection is a sequence of image-processing and decision-making operations.

  • Presence tools answer whether a required feature exists.
  • Pattern matching locates known visual patterns.
  • Edge detection identifies boundaries.
  • Measurement tools calculate dimensions and positions.
  • Blob analysis evaluates connected regions and counts.
  • Color, OCR, code-reading, and defect tools handle specialized inspection requirements.
  • Result logic combines tool outputs into a valid production decision.

Reliable inspection depends on good image quality, correct tool selection, stable calibration, representative validation, and disciplined handling of invalid results.

The most robust design uses the simplest combination of tools that can reliably detect the real production failure modes, with explicit tolerance limits and a defined response for every possible result state.
