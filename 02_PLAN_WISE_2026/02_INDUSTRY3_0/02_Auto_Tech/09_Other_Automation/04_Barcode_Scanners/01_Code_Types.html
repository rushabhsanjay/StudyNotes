1. Purpose and Scope

Barcode technology converts information into a machine-readable pattern. A scanner captures the pattern, decodes it, and transfers the resulting data to a PLC, industrial PC, traceability system, or manufacturing execution system (MES).

In industrial automation, barcodes are used to identify parts, assemblies, containers, tools, fixtures, and production batches. The decoded value can determine which recipe to load, which operation to perform, whether a part belongs to the correct variant, and which production records must be associated with that part.

Typical applications include:

  • Reading component and assembly serial numbers.
  • Identifying automotive parts on conveyors and assembly lines.
  • Tracking engine, transmission, and chassis assemblies.
  • Verifying part numbers before a process starts.
  • Associating inspection results with a specific serial number.
  • Managing work-in-process (WIP) and production genealogy.
  • Identifying bins, racks, tools, fixtures, and material containers.
  • Supporting rework, repair, and final inspection traceability.

The important distinction is that a barcode identifies something only through the data it encodes and the system that interprets that data. A scanner reading a code successfully does not prove that the part is correct for the operation.

2. What Is a Barcode?

A barcode is a machine-readable representation of data using a defined pattern of bars and spaces, dots, squares, or other geometric elements.

A barcode system typically includes:

  • Code or symbol: The printed, etched, or marked pattern.
  • Scanner or reader: The device that captures the symbol.
  • Decoder: The logic that interprets the captured pattern according to the symbology.
  • Interface: The communication path used to transmit decoded data.
  • Application: The PLC, computer, database, or manufacturing system that uses the data.

The word symbology means the specific rules used to represent information in a barcode format. Code 128, Code 39, Data Matrix, and QR Code are examples of symbologies.

A scanner may support several symbologies, but that does not mean every barcode reader supports every format. The supported symbologies must be verified in the device specification and configuration software.

3. One-Dimensional Barcodes (1D)

A one-dimensional barcode encodes information using variations in the widths and arrangement of bars and spaces along one primary direction.

The scanner interprets the sequence of bars and spaces to recover the encoded data.

3.1 How a 1D Barcode Works

Printed bars and spaces
          ↓
Optical sensor captures reflected light
          ↓
Decoder measures transitions and widths
          ↓
Symbology rules interpret the pattern
          ↓
Decoded characters or numbers
          ↓
PLC / Industrial PC / Database

A conventional 1D barcode is usually read across the bars. The barcode can often be read at different angles as long as the scan path crosses enough of the symbol in a suitable direction.

3.2 Common 1D Symbologies

Symbology Characteristics Typical use
Code 39 Alphanumeric, relatively simple encoding Industrial labels and equipment identification
Code 128 Compact, high-density alphanumeric encoding Logistics, manufacturing labels, part tracking
UPC-A Fixed-length numeric format Retail product identification
EAN-13 Fixed-length numeric format Retail and international product identification
ITF-14 Interleaved numeric format Outer packaging and trade-item identification
Codabar Older numeric-oriented format with defined start/stop characters Legacy libraries, laboratories, and logistics
GS1-128 Code 128 with GS1 application identifiers Supply-chain data such as batch, date, and serial information

These symbologies are not interchangeable. A Code 39 reader configuration does not automatically decode a Code 128 label unless Code 128 support is enabled.

3.3 Advantages of 1D Barcodes

  • Simple to print and widely supported.
  • Often inexpensive to deploy.
  • Human-readable text can be printed alongside the code.
  • Suitable for straightforward part and product identification.
  • Easy to integrate into many existing industrial systems.

3.4 Limitations of 1D Barcodes

  • Generally lower data capacity than 2D symbols of comparable physical size.
  • Often require a sufficiently long, clear scan path across the bars.
  • Damage across critical bars can prevent decoding.
  • Long encoded strings require longer symbols.
  • Some symbols need adequate label width and quiet zones, limiting placement options.

A 1D barcode is often a sensible choice when a short identifier is enough and the marking area supports a reliable scan.

4. Two-Dimensional Barcodes (2D)

A two-dimensional barcode encodes data across two dimensions. Instead of relying only on a sequence of bar widths, it uses a two-dimensional arrangement of elements such as squares, cells, or other modules.

Common 2D formats include Data Matrix and QR Code.

4.1 How a 2D Barcode Works

2D symbol
    ↓
Area image captured by an imaging reader
    ↓
Symbol location and orientation detected
    ↓
Grid / modules reconstructed
    ↓
Error correction and decoding
    ↓
Decoded data
    ↓
PLC / Industrial PC / Traceability System

Most industrial 2D readers use imaging technology to capture an area of the symbol. The reader locates the symbol, determines its orientation and grid, decodes the data, and applies the symbology's error-correction rules where applicable.

4.2 Advantages of 2D Barcodes

  • Can encode more information in a compact area.
  • Suitable for small component markings.
  • Can support direct part marking, including laser-etched symbols.
  • Some symbologies can recover data when portions of a symbol are damaged.
  • Can encode serial numbers, product identifiers, and structured data.
  • Often suitable for part-level traceability where the marking area is limited.

4.3 Limitations of 2D Barcodes

  • Small modules require sufficient optical resolution.
  • Poor contrast, glare, surface curvature, and marking defects can reduce read reliability.
  • Reading often requires an imaging reader rather than a basic 1D laser scanner.
  • Configuration may require correct focus, lighting, exposure, and decoding settings.
  • More encoded data can increase symbol complexity or physical size.
  • Error correction does not guarantee successful reading when a symbol is severely damaged.

5. Data Matrix

Data Matrix is a two-dimensional barcode symbology widely used in industrial manufacturing, electronics, medical devices, and component traceability.

The common square Data Matrix ECC 200 format uses a distinctive L-shaped finder pattern along two adjacent sides, with alternating dark and light elements along the other two sides. The finder pattern helps the reader locate the symbol and determine its orientation and module structure.

Rectangular Data Matrix formats are also available.

5.1 Structure of a Data Matrix Symbol

A typical square symbol contains:

  • Finder pattern: Helps the decoder locate the symbol and establish its orientation.
  • Timing pattern: Alternating dark and light modules help establish the grid.
  • Data region: Contains encoded information and error-correction data.
  • Quiet zone: Required clear space around the symbol, according to the applicable specification and marking conditions.

The exact symbol layout depends on the selected Data Matrix format and symbol size.

5.2 ECC 200 and Error Correction

ECC 200 is the commonly used modern Data Matrix format. It uses Reed-Solomon error correction, which adds redundant information to allow recovery from certain data errors or damaged modules.

This is particularly valuable when a code is laser-marked on a metal component or printed in a harsh industrial environment.

However, error correction has limits. If too much of the symbol is missing, distorted, blurred, or obscured, the decoder may not recover the original data.

5.3 Why Data Matrix Is Common in Automotive Manufacturing

Data Matrix is often suitable for component-level traceability because it can encode identifiers in a relatively small marking area.

Applications include:

  • Engine and transmission components.
  • Machined metal parts.
  • Electronic control units and circuit boards.
  • Bearings, housings, brackets, and other serialized parts.
  • Components marked by laser etching, dot peening, or suitable printing processes.

A part may carry a Data Matrix symbol containing a serial number or a unique identifier that links to a database record. The database can then hold detailed production history without forcing all that information into the symbol itself.

5.4 Direct Part Marking (DPM)

Direct Part Marking means applying the symbol directly to the part rather than attaching a separate label.

Common methods include:

  • Laser marking.
  • Dot peen marking.
  • Electrochemical etching.
  • Other qualified marking processes.

DPM presents optical challenges because the symbol may have low contrast, reflective metal surfaces, irregular texture, or uneven module geometry.

A standard reader configured for high-contrast printed labels may struggle with a direct-marked code. Reader selection, lighting, optics, and image-processing settings must match the actual marking method.

6. QR Code

QR Code, short for Quick Response Code, is a two-dimensional barcode format originally developed for rapid data capture and widely used in consumer and industrial applications.

A QR Code can encode numeric, alphanumeric, binary, and other supported data modes. Its distinctive finder patterns are generally visible as three large square patterns near three corners of the symbol.

6.1 Structure of a QR Code

A QR Code can include:

  • Finder patterns: Three prominent square patterns help locate the symbol and determine orientation.
  • Timing patterns: Help establish the module grid.
  • Alignment patterns: Assist with geometric correction in applicable symbol sizes.
  • Format and version information: Identify decoding parameters and symbol structure.
  • Data and error-correction codewords: Carry the encoded payload and redundancy.
  • Quiet zone: Clear space surrounding the symbol.

Not every QR Code contains alignment patterns in the same arrangement. The exact structure depends on its version.

6.2 Error Correction Levels

QR Code supports four error-correction levels: L, M, Q, and H.

Level General characteristic Typical trade-off
L Lower redundancy More capacity for a given symbol size
M Moderate redundancy Balanced capacity and recovery
Q Higher redundancy More recovery capability with less data capacity
H Highest redundancy Greater recovery capability with lower data capacity

Higher error correction generally requires more redundant codewords, which reduces the space available for payload data in a symbol of the same version. It does not make a QR Code immune to damage.

6.3 QR Code vs Data Matrix

Feature Data Matrix ECC 200 QR Code
Common visual feature L-shaped finder pattern Three large corner finder patterns
Common industrial use Compact component identification and DPM Labels, tracking, and general data exchange
Small marking suitability Strong fit for compact industrial markings Also suitable, depending on module size and application
Error correction Reed-Solomon in ECC 200 Reed-Solomon with selectable levels
Data formats Multiple encoding modes supported by the symbology Numeric, alphanumeric, binary, and other supported modes
Reader requirement Compatible 2D reader Compatible 2D reader
Best choice Depends on marking area, substrate, and traceability requirements Depends on data, readability, and system requirements

Neither symbology is universally superior. For compact direct part marking in manufacturing, Data Matrix is frequently selected. QR Code is also useful where the ecosystem, data structure, and application favor it.

7. Understanding Capacity, Density, and Module Size

A common misconception is that a 2D code always occupies less physical space than a 1D code. Its physical size depends on the amount of data, symbol configuration, module size, and required quiet zone.

A module is the smallest nominal element of a 2D symbol. In a square Data Matrix or QR Code, it is typically one square cell.

Smaller modules can produce a more compact symbol, but they place greater demands on the optical system.

If the module size on the part is \(m\) millimetres and the image scale is \(s\) pixels per millimetre, the approximate module width in the captured image is:

\[ p = m \times s \]

Where:

  • \(p\) is the module width in pixels.
  • \(m\) is the physical module size.
  • \(s\) is the image scale.

For example, a module measuring \(0.20\text{ mm}\) captured at \(20\text{ pixels/mm}\) would occupy approximately \(4\) pixels across.

This calculation is a starting point, not a universal readability guarantee. Actual performance depends on optics, focus, motion blur, sensor quality, contrast, distortion, reader algorithms, and the applicable verification criteria.

8. Encoding and Data Interpretation

A scanner returns decoded data. It does not automatically understand the business meaning of that data.

Suppose a component contains this identifier:

ENG-A7-00018452

The reader may output that exact string. The PLC or production application then determines whether the identifier is valid, whether the part belongs to the current production order, and which recipe should be used.

A more structured payload might contain:

01:09506000134352
10:BATCH24A
21:00018452

This is an illustrative representation of application identifiers and values, not a universal barcode payload format. Actual GS1 data encoding has specific rules for identifiers, separators, and data lengths.

8.1 GS1 and Application Identifiers

GS1 standards define ways to encode and interpret structured identification data. Application identifiers specify the meaning of a data element.

Examples include:

  • 01: Global Trade Item Number (GTIN).
  • 10: Batch or lot number.
  • 17: Expiration date.
  • 21: Serial number.

These identifiers have defined formats and data rules. For example, an expiration date under AI 17 is represented using a specified six-digit date format.

A scanner may decode a GS1 symbol, but the receiving application must parse the fields correctly. Variable-length fields, separators, and supported symbologies matter.

Do not confuse a barcode's symbology with its data standard. Code 128 is a symbology; GS1-128 is a structured application of Code 128 using GS1 rules.

9. Scanner Output in Industrial Automation

The decoded barcode value may reach the control system through digital I/O, a serial interface, an industrial Ethernet protocol, or a computer interface.

A common architecture is:

Barcode on Part
       ↓
Barcode Reader
       ↓
Decoded String + Read Status
       ↓
PLC or Industrial PC
       ↓
Validation / Part Matching
       ↓
Recipe Selection / Routing / Traceability
       ↓
Production Database or MES

The reader's exact output structure depends on the product and interface. Some devices return the data as a string; others use a defined field, a status word, or a structured message.

The application should distinguish at least these conditions:

  • A valid code was decoded.
  • No code was detected.
  • A code was detected but could not be decoded.
  • Multiple codes were detected and the wrong one may have been selected.
  • The reader is offline or reporting a fault.
  • The decoded value does not match the expected part or order.

A missing or invalid read should not automatically be treated as an accepted part.

10. Choosing the Appropriate Code Type

Select the code based on the application rather than choosing a format simply because it looks compact.

Requirement Potentially suitable choice Key consideration
Simple retail identification UPC-A or EAN-13 Retail standards and compatibility
General alphanumeric label Code 128 Data length and label width
Legacy industrial label Code 39 Existing reader and label compatibility
Compact component marking Data Matrix Module size and marking quality
Direct marking on metal parts Data Matrix ECC 200 is common Surface reflectivity and DPM reader capability
General-purpose 2D tracking QR Code or Data Matrix Application compatibility and payload
Structured logistics information GS1-128 or an appropriate GS1 2D format Correct GS1 data structure
Very small electronic components Data Matrix or another qualified compact marking Optical resolution and manufacturing process

Before standardizing a code type, confirm the downstream system supports the selected format and data structure.

Reads are intermittent Poor contrast, focus, or illumination Inspect marking quality, optics, exposure, and lighting
2D code fails on metal Glare, low contrast, or irregular marking Evaluate DPM-capable optics and suitable lighting
Small codes fail at high speed Insufficient image resolution or motion blur Review module size, exposure, distance, and reader performance
Wrong part number is returned Multiple symbols in view or incorrect selection rule Define the target region and expected symbology
Extra characters appear Prefix, suffix, or interface configuration Inspect output formatting and parser behavior

Code reads but part is rejected Incorrect application parsing or database mismatch Validate decoded data, expected format, and part records
Damaged code reads inconsistently Damage exceeds reliable decoding capability Improve marking quality and inspect code condition
Duplicate records appear Repeated read events or missing deduplication Associate reads with part events and transaction IDs

12. Code Quality and Verification

A barcode that can be read once is not necessarily suitable for production. Manufacturing applications may require consistent readability across shifts, reader replacements, environmental changes, and product variation.

Relevant quality factors include:

  • Contrast between dark and light elements.
  • Module geometry and uniformity.
  • Symbol dimensions and quiet zone.
  • Print or marking defects.
  • Distortion, damage, and contamination.
  • Optical resolution and reader configuration.
  • Reading distance and angle.
  • Motion speed and exposure time.

Barcode verification is different from simply decoding a code. A verifier measures symbol quality against an applicable standard and reports defined quality parameters. A production reader primarily attempts to decode the symbol and may report additional quality metrics if supported.

For 1D and 2D codes, verification methods and grading criteria differ by symbology and applicable standard. Direct part marking may require an appropriate verification method rather than a grading setup intended for conventional printed labels.

13. Maintenance and Configuration Control

Barcode readers are often treated as simple sensors, but their configuration can affect production routing and traceability.

Maintain records of:

  • Reader make, model, serial number, and firmware.
  • Enabled symbologies and relevant decoding settings.
  • Communication protocol and output format.
  • Prefixes, suffixes, separators, and data length limits.
  • Trigger mode and read timeout.
  • Lighting, focus, and working distance where applicable.
  • Expected payload format and validation rules.
  • PLC tag mapping and application parsing.
  • Approved sample codes and test results.
  • Backup configuration and restoration procedure.

After replacing a reader, changing a code format, moving the mounting bracket, or modifying lighting, test representative production codes. Verify both successful reads and expected failure behavior.

14. Interview Questions and Answers

1. What is the difference between 1D and 2D barcodes?

A 1D barcode encodes data using bars and spaces along one primary direction. A 2D barcode encodes data across two dimensions using a matrix or other two-dimensional pattern, generally allowing greater data density in a compact area.

2. What is a barcode symbology?

It is the set of rules defining how data is represented and decoded. Examples include Code 39, Code 128, Data Matrix, and QR Code.

3. Why is Data Matrix popular in automotive manufacturing?

It can encode a useful identifier in a compact area and is widely used for component-level traceability, including direct part marking on suitable surfaces.

4. What is the difference between Data Matrix and QR Code?

They are different 2D symbologies with different symbol structures and application characteristics. Data Matrix is common in compact industrial part marking, while QR Code is widely used for general-purpose tracking and information exchange.

5. What is ECC 200?

It is a commonly used Data Matrix format that includes error-correction capability, allowing recovery from certain damaged or unreadable modules.

6. Does error correction mean a barcode can always be read when damaged?

No. Error correction has a finite recovery capability. Severe damage, poor optics, low contrast, or distorted geometry can still prevent decoding.

7. What is the difference between a reader and a verifier?

A reader attempts to decode a symbol. A verifier measures symbol quality against defined grading criteria and helps establish whether the code meets the applicable quality requirements.

8. What is direct part marking?

It is the application of a code directly to the component, for example by laser marking or dot peening, instead of attaching a separate label.

9. Why might a reader decode a code correctly while the PLC rejects the part?

The decoded identifier may be syntactically valid but not match the expected part, recipe, order, or database record. Decoding success and application acceptance are separate decisions.

10. Why is Code 128 not identical to GS1-128?

Code 128 is a barcode symbology. GS1-128 applies GS1 data-structure rules to Code 128, including application identifiers and their defined data formats.

15. Practical Exercises

  1. Symbology identification: Collect examples of Code 39, Code 128, Data Matrix, and QR Code. Identify their visible structural features and determine which reader capabilities are required.
  2. Payload interpretation: Decode sample identifiers and distinguish the raw decoded string from the business meaning assigned by the PLC or application.
  3. Reader integration: Create a PLC sequence that accepts a valid read, validates the decoded string, associates it with a part event, and handles no-read and timeout conditions.
  4. Read reliability test: Evaluate representative codes at different distances, angles, lighting conditions, and surface conditions. Record read success and failure patterns.
  5. Traceability design: Define a part identifier format and document how it links to a recipe, production order, inspection record, and serial-number history.
  6. Configuration backup: Save a reader configuration and document the verification procedure required after replacement or restoration.

16. Final Mental Model

  • 1D uses bars and spaces and is well suited to many label-based identification tasks.
  • Data Matrix is a 2D symbology widely used for compact industrial identification and direct part marking.
  • QR Code is a versatile 2D symbology suitable for general tracking and structured information exchange.
  • The scanner captures and decodes the symbol.
  • The PLC or application validates what the decoded data means for the current production operation.
  • The traceability system associates the identifier with production history and inspection records.
  • Code quality and reader configuration determine whether the system can read the marking reliably in actual plant conditions.

The key principle is that a successful barcode read confirms only that the reader decoded data. Correct part identification requires application-level validation as well.
