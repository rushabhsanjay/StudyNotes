1. Definition and Purpose

Section isolation is a systematic troubleshooting method used to divide a machine, electrical circuit, control system, or process into smaller functional sections and test them independently to narrow down the location of a fault.

Instead of investigating an entire machine at once, maintenance personnel identify the boundaries between its functional sections and determine which section contains the abnormal condition.

The basic principle is:

Divide the system into logical sections, test the relevant boundaries, and use the results to narrow the fault location.

For example, if a PLC commands a conveyor motor to run but the conveyor does not move, the fault could exist in the PLC logic, output circuit, drive, motor cable, motor, gearbox, or conveyor mechanism. Testing the system in logical sections helps distinguish a control problem from an electrical, drive, or mechanical problem.

The purpose is to:

  • Reduce the number of possible fault locations.
  • Avoid replacing healthy components unnecessarily.
  • Separate upstream faults from downstream faults.
  • Make troubleshooting faster and more repeatable.
  • Gather evidence before performing repairs.
  • Avoid changing multiple variables at the same time.
  • Identify the actual fault location rather than merely clearing its alarm.

Section isolation is particularly useful for PLC-controlled machinery, CNC equipment, VFD-driven motors, servo axes, robots, pneumatic systems, hydraulic systems, sensors, and industrial communication networks.

2. The Fundamental Principle

A complex machine is a collection of connected functional sections. Each section receives something, performs a function, and produces an output or response.

A simplified control and motion chain may look like this:

Operator Command
      ↓
HMI / PLC Logic
      ↓
PLC Output or Network Command
      ↓
Drive / Control Interface
      ↓
Motor / Actuator
      ↓
Mechanical Machine
      ↓
Sensor / Feedback
      ↓
PLC Input and Sequence Confirmation

A failure anywhere in this chain can prevent the expected machine operation.

The goal is to identify the earliest section where the observed behavior no longer matches the expected behavior.

For example:

  • The PLC never generates the run command: investigate logic, permissives, and sequence conditions.
  • The PLC generates the command, but the drive does not receive it: investigate output wiring or communication.
  • The drive receives the command but trips: investigate drive diagnostics, supply, motor, and load.
  • The motor rotates, but the conveyor does not move: investigate coupling, gearbox, transmission, or mechanical obstruction.
  • The conveyor moves, but the PLC does not detect movement: investigate feedback sensing and signal processing.

The exact boundaries depend on the machine architecture. The objective is not to divide everything arbitrarily, but to select boundaries that provide useful diagnostic evidence.

Isolation does not always mean physically disconnecting equipment. It can also mean logically separating functions through diagnostics, measurements, software monitoring, or controlled tests. Physical isolation is required whenever the work or hazard assessment demands it.

4. Select the Correct Section Boundaries

A useful boundary divides the system at a point where the input and output can be observed or tested.

Common boundaries include:

  • PLC command to output module.
  • Output module to relay or contactor.
  • PLC communication interface to drive.
  • Drive output to motor.
  • Motor shaft to gearbox or transmission.
  • Sensor output to PLC input.
  • PLC sequence command to actuator response.
  • CNC controller to servo drive.
  • Robot controller to peripheral equipment.
  • Remote I/O adapter to the field I/O network.
  • Power supply output to the devices it supplies.

4.1 Example: PLC-controlled motor

Section Input Expected output or response
PLC sequence logic Start request and permissives Run command becomes active
PLC output or communication Run command Correct electrical output or network command
Drive Valid command and healthy supply Drive becomes ready and runs as commanded
Motor and cable Drive output Motor develops torque and rotates

5. The Split-System Troubleshooting Method

Step 1: Define the exact symptom

Describe the failed function precisely.

Weak description: Machine not working.

Useful description: PLC run command is active, but the VFD remains stopped and no motor rotation occurs.

The second description already eliminates some possibilities and gives a clear starting point.

Record:

  • What should happen.
  • What actually happens.
  • When the fault occurs.
  • Whether it is continuous or intermittent.
  • Relevant alarms and diagnostic codes.
  • Whether the machine worked normally before the event.
  • Recent changes, repairs, or component replacements.

Step 2: Establish the safe state

Before inspecting or testing, identify the hazards and required safety controls.

  • Follow the machine-specific safe-work procedure.
  • Apply lockout/tagout and verify absence of hazardous energy whenever required.
  • Account for stored electrical energy, rotating parts, gravity, pneumatic pressure, hydraulic pressure, and unexpected automatic movement.
  • Use only authorized energized diagnostic methods.
  • Confirm the machine cannot restart unexpectedly during inspection.

A PLC stop command is not equivalent to electrical isolation. A VFD display showing zero speed does not prove the DC bus is safe. A robot in a stationary position is not necessarily in a safe state.

Never create a fault by disconnecting live equipment or defeat an interlock merely to see what happens.

Step 3: Identify the major sections

Break the affected function into meaningful sections based on the electrical drawings, control architecture, mechanical layout, and sequence of operation.

For a VFD-driven conveyor, the sections might be:

  1. Start request and PLC permissives.
  2. PLC output or network command.
  3. VFD supply and readiness.
  4. Motor cable and motor.
  5. Gearbox and conveyor mechanics.
  6. Running feedback and PLC confirmation.

Do not begin replacing components until the relevant sections and their expected behaviors are understood.

Step 4: Choose the first test boundary

Start at the boundary closest to the observed failure, using existing diagnostic information and the safest useful test.

Suppose the PLC run command is already confirmed active. The next question is whether the drive receives that command and is in a state that permits operation.

Check the drive's command source, status, active fault, enable conditions, and diagnostic information before disturbing wiring or changing parameters.

Step 5: Compare input and output behavior

At each section, establish whether:

  • The required input is present.
  • The section is in a valid operating state.
  • The expected output is produced.
  • The next section receives that output.
  • The expected response occurs within the specified time.

If the input to a section is correct but its output is not, investigate that section and its required conditions.

If the section produces the correct output but the next section does not receive it, investigate the boundary between the sections.

If the output is correct and the expected physical response still does not occur, investigate the downstream section.

This is the core logic of fault localization.

Step 6: Divide the suspect section again

Once the fault is narrowed to one section, divide it into smaller parts.

For example, if a drive receives the run command but the motor does not turn, possible sub-sections include:

  • Drive enable and protective status.
  • Drive power stage.
  • Motor cable.
  • Motor windings.
  • Mechanical load.

Use the manufacturer's diagnostic procedure to determine which checks are appropriate. Do not assume the drive is defective just because it is the last electrical device before the motor.

Step 7: Confirm the fault with evidence

A fault should be localized using repeatable evidence, not intuition alone.

Useful evidence includes:

  • Measured voltage or current within the correct test conditions.
  • PLC input/output status.
  • Device diagnostic history.
  • Communication status.
  • Sensor switching behavior.
  • Motor or actuator response.
  • Mechanical inspection findings.
  • Comparison with a known-good signal or approved configuration.

Where possible, change only one diagnostic variable at a time so the result remains interpretable.

Step 8: Record the result

Document which section was tested, what was expected, what was observed, and what the result means.

A negative result is valuable too. If a test confirms that a section operates correctly under the tested conditions, it helps narrow the investigation, although it does not necessarily rule out an intermittent fault.

6. The Two-Half Method

The two-half method divides a system into two logical sections at a selected boundary. The purpose is to determine which half requires further investigation.

For example, a machine function can be divided into:

  • Half A: Control command and command transmission.
  • Half B: Actuation, physical process, and feedback response.

The split must be chosen according to the symptom. It is not always the physical midpoint of the machine.

6.1 Example: Sensor-to-PLC feedback failure

A proximity sensor detects a metal component, but the PLC does not recognize the sensor input.

Divide the system into two sections:

  • Half A: Target, sensor, sensor power supply, and sensor output.
  • Half B: Signal wiring, PLC input channel, input mapping, and PLC logic.

Investigate the boundary between the two halves using approved diagnostic methods.

If the sensor's output changes correctly but the corresponding PLC input does not, the investigation shifts toward the cable, terminals, input module, supply reference, or addressing.

If the sensor output itself does not change, investigate the target position, sensor mounting, sensing distance, sensor supply, and sensor condition.

This division narrows the search, but the result must still be verified. A sensor output indication alone does not prove that the signal reaches the PLC correctly.

6.2 Example: Conveyor fails to move

Half A: Control and command
Start request → PLC permissives → Run command

Half B: Drive and physical movement
Drive response → Motor → Gearbox → Conveyor movement

If the run command is absent, investigate Half A first.

If the run command is present, inspect the drive status and the downstream sections. The run command alone does not prove that the drive is enabled, healthy, receiving the correct reference, or capable of rotating the motor.

6.3 Binary splitting is not always the best method

A simple two-half split is useful when the boundary is observable and each half can be evaluated independently. It is less useful when:

  • Multiple faults exist simultaneously.
  • The failure is intermittent.
  • The two halves share a common power supply or communication path.
  • The system contains feedback loops or distributed control.
  • A fault depends on timing, sequence state, or a combination of permissives.
  • Physical isolation would introduce an unacceptable risk.

In these situations, use the actual system architecture and diagnostic evidence to select a more informative boundary.

7. Section Isolation in PLC Systems

PLC troubleshooting requires distinguishing the program's logical behavior from the field devices and signals it controls.

7.1 Trace the complete signal path

For a digital output controlling a solenoid valve, investigate:

  1. The sequence condition that should command the valve.
  2. The relevant PLC logic and permissives.
  3. The commanded output tag.
  4. The physical output channel and module status.
  5. The output wiring and any intermediate relay.
  6. The solenoid coil and valve condition.
  7. The pneumatic or hydraulic supply.
  8. The actuator's movement.
  9. The position feedback signal.

The correct starting point depends on the evidence already available. If the PLC command is not being generated, checking the solenoid coil first may waste time.

7.2 Logical isolation versus electrical isolation

Logical isolation means examining a function independently through program monitoring, device diagnostics, or signal tracing without necessarily disconnecting equipment.

Examples:

  • Monitoring a PLC tag online.
  • Checking a sequence state.
  • Reading a drive's command and status words.
  • Inspecting a remote I/O diagnostic buffer.
  • Comparing the expected and actual sensor states.

Electrical or physical isolation means separating energy or connections according to an approved procedure so a section can be safely inspected or tested.

Examples:

  • Isolating a motor supply before cable or motor inspection.
  • Isolating a pneumatic supply and releasing stored pressure before actuator maintenance.
  • Disconnecting a circuit for an approved insulation test.
  • Separating a network segment under an authorized diagnostic procedure.

Logical isolation does not make a circuit electrically safe. Physical isolation must account for all relevant energy sources and stored energy.

7.3 Avoid forcing signals as a substitute for diagnosis

Forcing a PLC input or output can bypass the natural relationship between a physical device and the program.

A forced input may make the program believe that a clamp is closed even when it is not. A forced output may cause an actuator to move without the normal sequence conditions.

Do not force signals unless the specific test is authorized, risk-assessed, controlled, and performed by qualified personnel under the applicable procedure. Never use a force to bypass a safety function or conceal an unresolved fault.

8. Section Isolation in VFD and Motor Systems

For a motor that fails to run, the investigation should separate the command path, drive condition, motor circuit, and mechanical load.

Section Diagnostic question Useful evidence
Control request Is a valid run request being generated? PLC logic, command tag, operating mode
Drive command interface Does the drive receive the correct command and reference? Control source, command/status words, network diagnostics
Drive readiness Is the drive healthy and permitted to run? Fault history, enable status, safety-related status
Drive power and supply Are supply and drive conditions within specification? Diagnostic data and approved electrical measurements
Motor circuit Is the motor cable and motor circuit healthy? Inspection and approved tests
Mechanical load Can the driven mechanism move as intended? Safe mechanical inspection, coupling and gearbox condition
Feedback Is the expected running or speed signal reaching the controller? Drive status, encoder or speed feedback, PLC input

8.1 A useful diagnostic distinction

If the PLC run request is active but the drive reports Not Enabled, investigate the drive's enable conditions and status before suspecting the motor.

If the drive reports a fault, preserve the fault code and history before following the prescribed recovery procedure.

If the drive reports that it is running but the motor does not rotate, investigate the exact meaning of the running indication and use approved diagnostics to distinguish a status-word issue from a motor-circuit or mechanical problem.

If the motor rotates but the mechanism does not move, investigate the transmission and driven equipment rather than repeatedly changing drive parameters.

8.2 Electrical testing precautions

Motor and drive circuits can contain hazardous voltage and stored energy. Insulation-resistance testing can also damage connected electronic equipment if performed incorrectly.

  • Isolate and verify the required safe state.
  • Follow the drive manufacturer's discharge-time and testing instructions.
  • Disconnect electronic devices from an insulation test where the procedure requires it.
  • Use instruments rated for the circuit and measurement category.
  • Do not measure resistance on an energized circuit.
  • Do not disconnect or reconnect motor cables while the drive is energized unless a specific manufacturer-approved procedure explicitly permits the activity.

9. Section Isolation in Servo and CNC Systems

Servo and CNC faults can originate in the command path, motion controller, drive, feedback system, mechanical axis, or safety-related control.

For a CNC axis that fails to move, divide the function into:

  1. CNC command and axis enable conditions.
  2. Motion controller and servo command.
  3. Servo drive status and power stage.
  4. Motor and feedback system.
  5. Mechanical transmission and axis load.
  6. Position feedback and CNC monitoring.

Use controller and drive diagnostics to identify where commanded motion and actual motion begin to disagree.

For example, if a CNC commands axis movement but the drive reports a feedback fault, investigate the encoder or feedback circuit according to the manufacturer's procedure. If the drive reports that the axis is enabled but a following error occurs under load, investigate mechanical resistance, motion demand, feedback integrity, and approved tuning parameters.

Do not adjust servo gains, following-error limits, torque limits, or CNC parameters merely to suppress an alarm. Capture the original settings and involve authorized controls personnel where parameter changes are necessary.

For a CNC machine, also distinguish between an axis fault and a machine-builder interlock. A controller may inhibit motion because a door, chuck, hydraulic clamp, lubrication condition, or other permissive is not satisfied.

10. Section Isolation in Robots

A robot cell is a coordinated system involving the robot controller, safety system, PLC, tooling, sensors, communication network, and peripheral equipment.

For a robot that will not start a cycle, separate the investigation into:

  • Robot program and operating mode.
  • Robot controller readiness and active alarms.
  • Safety-system status.
  • PLC-to-robot handshake signals.
  • Tooling and peripheral permissives.
  • Robot motion and servo condition.
  • End-effector feedback and part-presence signals.

Example: The PLC reports Robot not ready.

The robot controller may be in a different operating mode, have an active axis fault, or be waiting for a safety or program-start condition. Alternatively, the robot may be ready, but the PLC may not receive the expected ready signal because of a communication or mapping problem.

Compare the robot's actual status with the PLC's interpreted status. This helps distinguish a robot-side condition from a handshake or communication fault.

Do not bypass robot guarding, safety interlocks, enabling devices, or protective stops to perform section-isolation tests. Follow the robot manufacturer's and site's authorized diagnostic procedures.

11. Section Isolation in Pneumatic and Hydraulic Systems

Fluid-power systems also benefit from splitting the control path from the physical actuation path.

11.1 Pneumatic example

A cylinder does not extend when commanded.

Section What to inspect
PLC logic Is the extend command permitted and active?
Output circuit Is the correct output or relay operating?
Solenoid valve Is the coil commanded and is the valve functioning?
Air supply Is pressure available within the required specification?
Pneumatic circuit Are hoses, fittings, flow controls, and exhaust paths correct?
Cylinder and load Is movement obstructed or the cylinder damaged?
Position feedback Does the end-position sensor respond correctly?

A lit solenoid indicator does not prove that the valve shifts correctly. A valve that shifts does not prove that adequate air pressure reaches the cylinder. A cylinder that extends does not prove that the feedback signal reaches the PLC.

Each section needs its own relevant test.

11.2 Hydraulic example

A hydraulic clamp fails to reach pressure.

Separate the investigation into the command and interlock logic, pump and motor, hydraulic supply, directional and pressure-control valves, hydraulic circuit, cylinder, and pressure feedback.

Use the hydraulic schematic and the specified measurement points. Never loosen a pressurized hydraulic connection to check for flow. Stored hydraulic pressure can cause severe injection injuries, even when a system appears stopped.

12. Section Isolation in Industrial Networks

Communication faults can affect multiple devices, so section isolation should follow the network topology.

For example, if a PLC cannot communicate with several remote I/O modules, check whether the devices share a switch, power supply, network trunk, adapter, or communication path.

Investigate the network in logical sections:

  • PLC communication interface.
  • Switches, adapters, and network infrastructure.
  • Network cables and connectors.
  • Remote device interface.
  • Device power and diagnostic status.
  • Communication configuration and addressing.
  • Application-level data mapping and connection state.

If several devices fail together, a shared dependency is a strong investigation candidate. It is not proof that the shared device is defective, but it helps prioritize the checks.

Use approved network diagnostics and configuration backups. Avoid disconnecting active industrial networks without authorization because the test itself may stop production or affect other equipment.

Use the following table as a general guide. The actual diagnostic sequence must follow the machine design and safety requirements.

14. Intermittent Faults Require a Different Approach

A section that passes one test may still fail intermittently. This is especially common with loose connectors, damaged cables, thermal faults, electromagnetic interference, unstable supplies, and faults that occur only at a specific machine position or load.

For intermittent faults:

  • Record the exact conditions under which the failure occurs.
  • Capture timestamps and device diagnostic histories.
  • Compare healthy and failed operating states.
  • Check for movement, vibration, heat, load, and cycle-position dependence.
  • Use suitable monitoring or logging where available.
  • Avoid unnecessary connector reseating or parameter changes before collecting evidence.
  • Use controlled tests only when authorized and safe.

Do not repeatedly cycle a machine in an attempt to reproduce a fault if doing so may damage equipment or expose personnel to hazards.

15. Common Mistakes During Section Isolation

  • Dividing the machine into arbitrary sections without understanding the functional architecture.
  • Testing downstream components before checking a missing command or permissive.
  • Assuming an indicator light proves that a device performs its intended function.
  • Assuming a PLC status bit proves the physical condition is correct.
  • Changing several parameters at once and losing the ability to identify which change mattered.
  • Replacing a component because it is easy to access rather than because evidence implicates it.
  • Physically disconnecting circuits without proper isolation and authorization.
  • Ignoring shared power supplies or common communication paths.
  • Treating a passing test as proof that an intermittent fault cannot exist.
  • Bypassing interlocks or forcing signals to make the sequence proceed.
  • Failing to document the boundaries tested and the evidence obtained.
  • Returning the machine to production without confirming the full function.

17. Interview Questions and Answers

Q1. What is section isolation in troubleshooting?

Section isolation is the process of dividing a system into logical or physical sections and testing each section to narrow down the location of a fault.

Q2. What is the two-half method?

The two-half method divides a system at a useful diagnostic boundary. The technician tests the two sides to determine which side requires further investigation, then subdivides the suspect side if necessary.

Q3. How do you troubleshoot a motor that does not start?

Check the start request and PLC permissives, verify the run command, examine the drive's readiness and diagnostics, and then investigate the motor circuit, mechanical load, and feedback as indicated by the evidence.

Q4. Why should the input and output of each section be checked?

Comparing the expected and actual input and output helps determine whether the fault is inside a section or at the boundary between connected sections.

Q5. Does a successful test prove that a section is healthy?

It proves only that the section passed the specific test under the conditions tested. Intermittent faults, load-dependent failures, and timing-related faults may require additional evidence.

Q6. What is the difference between logical and physical isolation?

Logical isolation separates functions for diagnosis using signals, software monitoring, and device diagnostics. Physical isolation separates equipment or energy sources according to an approved safety procedure.

Q7. Why should only one diagnostic variable be changed at a time?

Changing one variable at a time makes the test result easier to interpret and helps establish a cause-and-effect relationship.

Q8. How would you troubleshoot a PLC output that commands a solenoid, but the cylinder does not move?

Trace the command from the PLC logic through the output circuit and solenoid valve, then check the fluid supply, circuit condition, cylinder mechanics, and feedback. Use the evidence to select the next test rather than replacing components at random.

Q9. Why is a common dependency important when several devices fail together?

Multiple failures may share a common cause, such as a power supply, remote I/O module, network connection, or common interlock. Checking shared dependencies can narrow the investigation efficiently.

Q10. When is section isolation complete?

It is complete when the fault has been narrowed sufficiently, the cause has been verified, the required corrective action has been performed, and the affected function has passed its prescribed verification tests.

18. Completion Checklist

  • Explain section isolation and the two-half method.
  • Identify useful diagnostic boundaries in a machine.
  • Trace PLC commands and feedback through the complete signal path.
  • Isolate control, drive, motor, mechanical, and feedback faults logically.
  • Apply the correct safety procedure before physical testing.
  • Distinguish a missing command from a failed response.
  • Troubleshoot PLC, VFD, servo, CNC, robot, pneumatic, and network systems using section-based reasoning.
  • Account for common dependencies and intermittent faults.
  • Record test conditions, expected results, actual results, and remaining possibilities.
  • Verify the root cause and confirm correct operation after repair.
