1. Purpose of CNC PLC/PMC Troubleshooting

A CNC machine depends on both numerical control and machine-sequence control. The CNC executes machining programs and coordinates motion, while the PLC or PMC manages machine functions such as clamping, lubrication, tool changing, door interlocks, hydraulic systems, coolant, and machine-ready conditions.

A PLC/PMC-related breakdown may appear as:

  • Machine cycle does not start.
  • CNC displays an interlock or machine-builder alarm.
  • Tool changer stops halfway through a sequence.
  • Hydraulic or pneumatic clamping does not operate.
  • Coolant, lubrication, or chip conveyor fails to start.
  • A limit switch or proximity sensor is not detected.
  • An output command is present, but the actuator does not operate.
  • An input signal changes physically but not in the diagnostic screen.
  • A sequence waits indefinitely for a confirmation signal.
  • Multiple machine functions fail because of a common I/O or communication problem.

Core diagnostic principle: Trace the complete signal path from the physical condition to the PLC/PMC input, through the machine logic, to the output and final actuator. Do not replace an I/O module merely because an input or output appears incorrect.

2. CNC, PLC/PMC, Drives and Field Devices

          CNC Control
              ↓
        PLC / PMC Logic
              ↓
      Output I/O Module
              ↓
 Relay / Contactor / Valve Driver
              ↓
       Field Actuator
              ↓
    Physical Machine Movement
              ↓
     Sensor / Limit Switch
              ↓

The actual architecture varies. Some CNCs integrate PLC/PMC functions into the CNC controller, while others use separate modules or remote I/O networks.

The PLC/PMC generally handles discrete machine sequencing. It may also process analog signals, counters, timers, data registers, and communication with drives or other devices.

3. Important PLC/PMC Terminology

Term Meaning
PLC Programmable Logic Controller used to control industrial machine sequences

Input Signal received from a sensor, switch, drive, or other device
Output Command sent to a relay, valve, contactor, lamp, or other device

Important: Address formats, signal naming, memory organization, and diagnostic tools differ between CNC manufacturers. Always use the electrical drawings, I/O list, and controller-specific documentation for the machine under investigation.

4. Main Responsibilities of CNC PLC/PMC Logic

4.1 Machine sequence control

The PLC/PMC coordinates operations such as:

  • Machine startup and readiness.
  • Axis and spindle enable conditions.
  • Tool change sequence.
  • Pallet or fixture clamping.
  • Hydraulic and pneumatic operations.
  • Coolant and lubrication.
  • Chip conveyor operation.
  • Door locking and access interlocks.
  • Automatic cycle start and completion.
  • Machine alarm generation.

4.2 Interlock management

The PLC/PMC checks whether required conditions are satisfied before allowing an operation.

For example, a tool-change sequence may require:

  • The machine to be in an allowed operating state.
  • The spindle to be stopped or at the required orientation.
  • The axes to be at an approved tool-change position.
  • The tool magazine to be in the required state.
  • The unclamp or clamp confirmation to be valid.
  • The relevant safety conditions to be satisfied.

The exact requirements depend on the machine builder's design.

4.3 Signal processing

The PLC/PMC interprets field signals and produces control decisions.

Examples include:

  • Proximity sensor detects a slide position.
  • Pressure switch confirms hydraulic pressure.
  • Limit switch confirms a mechanical end position.
  • Drive-ready signal confirms drive availability.
  • Contactor feedback confirms an expected electrical state.
  • Tool clamp sensor confirms the tool retention mechanism's state.

4.4 Alarm generation

The PLC/PMC may generate an alarm when:

  • A required input is missing.
  • A sequence does not complete.
  • Two conditions contradict each other.
  • An actuator fails to reach the expected state.
  • A pressure, temperature, or position condition is outside its allowed range.
  • A communication or device-ready condition is lost.

The alarm text is often defined by the machine builder. It should be interpreted alongside the corresponding logic and electrical drawings.

5. Digital Inputs and Outputs

5.1 Digital inputs

Digital inputs represent discrete states, commonly ON/OFF or TRUE/FALSE.

Examples:

  • Door closed.
  • Hydraulic pressure healthy.
  • Tool unclamped.
  • Slide at home position.
  • Spindle drive ready.
  • Emergency-stop chain status, where monitored through the applicable control interface.
  • Limit switch operated.

A digital input is not necessarily a direct indication of a physical state. The signal may pass through contacts, relays, terminal blocks, interface circuits, or networked I/O before reaching the PLC/PMC.

5.2 Digital outputs

Digital outputs command devices such as:

  • Solenoid valves.
  • Interposing relays.
  • Contactors.
  • Indicator lamps.
  • Pneumatic valve manifolds.
  • Coolant pumps through approved control circuits.
  • Lubrication pumps.
  • Chip conveyor controls.

A PLC/PMC output turning ON does not prove that the actuator has operated. The output circuit, field wiring, supply, load, and actuator must still function correctly.

5.3 Input and output diagnostic comparison

Observation Possible causes Diagnostic direction
Sensor physically changes, input stays OFF Sensor supply, wiring, polarity, input module, address mapping Check the field signal and input circuit
Input stays ON when sensor is inactive Short circuit, incorrect wiring, stuck contact, sensor failure Verify the sensor output and wiring against the drawing

6. Understanding PLC/PMC Signal Logic

6.1 Command versus confirmation

A machine sequence normally distinguishes between a command and the confirmation that the requested action occurred.

Example: hydraulic clamping.

Clamp Request
      ↓
Check Required Permissives
      ↓
Activate Clamp Output
      ↓
Hydraulic Valve Operates
      ↓
Cylinder Moves
      ↓
Clamp Sensor Changes State
      ↓
PLC/PMC Confirms Clamp Complete

If the clamp command is ON but the clamp confirmation remains OFF, the failure may lie in the output circuit, hydraulic system, mechanical mechanism, sensor, or feedback wiring.

6.2 Permissive conditions

A permissive is a condition required before an operation can begin.

For example:

Tool Change Permissives
        ↓
Machine in Allowed State
        AND Spindle Condition Valid
        AND Axis Position Valid
        AND Magazine State Valid
        AND Required Safety Conditions Valid
        ↓
Tool Change Sequence Allowed

The actual logic must be obtained from the machine's PLC/PMC program and documentation.

6.3 Interlock versus fault

An interlock may simply indicate that a required condition is not satisfied. It does not necessarily mean a component is defective.

For example, a door-open condition may prevent automatic cycle start by design. Replacing the door sensor without verifying the actual door state and signal path would be an impressive demonstration of how to waste maintenance time.

A fault indicates an abnormal condition according to the control design, such as a timeout, device error, or contradictory feedback.

7. PLC/PMC Troubleshooting Workflow

Step 1: Establish the machine state

Record:

  • CNC alarm text and number.
  • PLC/PMC alarm or message.
  • Operating mode.
  • Sequence step when the fault occurred.
  • Physical machine condition.
  • Last operation that completed successfully.
  • Recent maintenance or changes.

Do not clear alarms before recording useful evidence.

Step 2: Identify the expected operation

Determine what the machine was trying to do.

Examples:

  • Clamp a fixture.
  • Move an axis to a reference position.
  • Change a tool.
  • Start the spindle.
  • Activate coolant.
  • Complete a door-locking sequence.

Step 3: Identify the required signals

Use the machine's electrical drawings, I/O list, ladder logic, and diagnostic screen to identify:

  • Command bit.
  • Required permissives.
  • Output address.
  • Feedback input.
  • Sequence timer.
  • Alarm condition.

Do not guess addresses from a different machine or controller model.

Step 4: Compare logic with physical conditions

Check whether each required condition is actually satisfied.

For a missing input:

  • Verify the sensor's physical state.
  • Check the sensor supply and output.
  • Check the signal at the relevant terminal using the approved method.
  • Check the corresponding PLC/PMC diagnostic input.
  • Verify address mapping and module status.

For a missing output:

  • Check whether the command is requested.
  • Determine which permissive or logic condition prevents activation.
  • If the output is commanded, verify the output circuit and load.
  • Check actuator operation and feedback.

Step 5: Isolate the fault domain

Determine whether the fault is in:

  • Control logic.
  • Sensor or switch.
  • Wiring or terminal.
  • I/O module.
  • Shared supply or return.
  • Network or remote I/O.
  • Relay, contactor, or output interface.
  • Hydraulic, pneumatic, or mechanical equipment.

Step 6: Correct the confirmed cause

Use an approved repair method. Do not force outputs, bypass interlocks, or change logic simply to make the machine cycle.

Step 7: Verify the complete sequence

Confirm that the command, physical action, feedback, and sequence completion all occur correctly.

Test the machine only under the authorized operating procedure and required safety conditions.

8. PLC/PMC Ladder Logic: Practical Interpretation

Ladder logic represents control conditions and actions. In a simplified example, a machine output may require a start request and several permissives.

Start_Request
    AND Door_Closed
    AND Hydraulic_Pressure_OK
    AND Drive_Ready
        ↓
    Cycle_Enable

This is a conceptual example, not executable ladder logic. Actual machine logic may include latches, timers, edge detection, mode checks, safety interfaces, and additional conditions.

8.1 Trace the logic backward

When an output is OFF:

  1. Find the output coil or output command in the PLC/PMC program.
  2. Identify all conditions that must be true for it to activate.
  3. Monitor those conditions online using the approved diagnostic tool.
  4. Find the first condition that is not satisfied.
  5. Trace that condition to its source, which may be another logic bit, an input, a drive status, or a communication signal.
  6. Verify the physical condition before deciding on a repair.

8.2 Trace the logic forward

When an input changes but the machine does not respond:

  1. Confirm the input address and actual diagnostic state.
  2. Locate the logic that uses the input.
  3. Check whether the logic condition becomes true.
  4. Follow the resulting internal bits or sequence state.
  5. Check whether the expected output command is generated.
  6. Verify the physical output circuit and actuator.

Practical rule: A signal can be electrically correct but mapped to the wrong address, ignored by the active logic, or blocked by another permissive.

9. PLC/PMC I/O Module Faults

9.1 Input module fault

Possible causes:

  • Missing module supply.
  • Missing field supply.
  • Blown fuse in a shared circuit.
  • Incorrect common connection.
  • Damaged input channel.
  • Loose terminal or connector.
  • Incorrect module configuration.
  • Remote I/O communication failure.

Diagnostic method:

  1. Identify the exact input channel.
  2. Check the module and channel status.
  3. Verify the sensor supply and signal according to the circuit design.
  4. Compare the signal at the field device, terminal, and diagnostic screen.
  5. Check common wiring and module configuration.
  6. Replace the module only when evidence supports the diagnosis.

9.2 Output module fault

Possible causes:

  • Output supply missing.
  • Short circuit or overload.
  • Failed output channel.
  • Incorrect common connection.
  • Defective relay or interface circuit.
  • Wiring fault.
  • Remote I/O communication problem.
  • Output inhibited by the controller or module protection.

Diagnostic method:

  1. Confirm the output command state.
  2. Check module status and diagnostic alarms.
  3. Verify the specified output supply.
  4. Check the output circuit and load.
  5. Determine whether the fault is at the module or downstream.
  6. Repair the confirmed fault and verify operation.

Never assume that an ON indication on the PLC/PMC screen means rated voltage is present at the load terminals.

10. Sensor and Switch Faults

Common devices in CNC machines include proximity sensors, limit switches, pressure switches, temperature switches, position sensors, and tool-clamp sensors.

10.1 Proximity sensor

Possible issues:

  • Sensor misalignment.
  • Incorrect sensing distance.
  • Metal target not positioned correctly.
  • Damaged cable.
  • Missing supply.
  • Sensor output failure.
  • Incorrect PNP/NPN compatibility.
  • Contamination or mechanical damage.

Check the sensor's rated supply, output type, sensing distance, and wiring diagram.

10.2 Limit switch

Possible issues:

  • Mechanical actuator not reaching the switch.
  • Switch damage.
  • Contact wear.
  • Incorrect adjustment.
  • Broken wiring.
  • Loose mounting.
  • Incorrect normally open/normally closed interpretation.

Verify the physical operating point and the expected electrical state.

10.3 Pressure switch

Possible issues:

  • Insufficient hydraulic or pneumatic pressure.
  • Pressure switch setpoint incorrect.
  • Failed switch.
  • Blocked pressure port.
  • Wiring or supply fault.
  • Pressure instability.

A pressure-switch input can be electrically healthy while correctly reporting that the hydraulic system has insufficient pressure. Diagnose the physical pressure before changing the electrical signal.

11. Output Devices and Actuator Faults

11.1 Solenoid valve

Possible causes of failure:

  • Coil open circuit.
  • Coil short circuit.
  • Incorrect coil voltage.
  • Missing supply or return.
  • Sticking valve spool.
  • Insufficient pressure.
  • Blocked flow path.
  • Defective output relay or module.

Check electrical and fluid-system conditions separately. A coil can be energized while the valve fails to shift mechanically.

11.2 Relay or contactor

Possible causes:

  • Coil supply missing.
  • Coil failure.
  • Burnt or worn contacts.
  • Loose terminal.
  • Incorrect interlock condition.
  • Defective auxiliary feedback contact.

Check the control circuit and the power circuit according to the electrical drawings.

11.3 Hydraulic or pneumatic actuator

Possible causes:

  • Low pressure.
  • Leakage.
  • Sticking cylinder.
  • Valve fault.
  • Mechanical obstruction.
  • Incorrect flow adjustment.
  • Faulty end-position feedback.

Do not diagnose a mechanical or fluid-power fault solely from the PLC output status.

12. CNC Machine Interlocks

Common machine interlocks include:

  • Door or guard condition.
  • Hydraulic pressure condition.
  • Lubrication status.
  • Axis reference status.
  • Spindle status.
  • Tool-clamp confirmation.
  • Tool-magazine position.
  • Fixture-clamp confirmation.
  • Coolant or temperature conditions.
  • Drive-ready status.

The exact conditions depend on the machine builder.

Troubleshooting method

  1. Identify the blocked operation.
  2. Find the alarm description and relevant sequence.
  3. List the required permissives.
  4. Check each condition on the diagnostic screen.
  5. Verify the corresponding physical condition.
  6. Identify the first unsatisfied condition.
  7. Repair the cause and retest the sequence.

Safety-critical distinction: Safety functions such as emergency stops, guard monitoring, and safety-rated enabling functions may be implemented through dedicated safety relays, safety PLCs, or safety-rated controller functions. Standard PLC/PMC logic is not automatically a substitute for a safety-rated system. Never bypass a safety device to clear a machine interlock.

13. Sequence Timeout Faults

A sequence timeout occurs when the controller expects a condition to become true within a specified time, but it does not.

Examples:

  • Tool clamp confirmation does not arrive.
  • Hydraulic pressure is not established in time.
  • A tool magazine fails to reach the requested position.
  • A slide does not reach its end position.
  • A spindle-ready signal does not arrive.
  • A door-lock confirmation is missing.

Diagnostic method

  1. Identify the sequence step and timeout alarm.
  2. Identify the command issued at that step.
  3. Identify the expected confirmation.
  4. Check whether the command was actually generated.
  5. Verify actuator movement and physical conditions.
  6. Check the feedback sensor and its input path.
  7. Check the timer configuration only if the approved diagnosis indicates a timing problem.

Increasing a timer is not a valid first-line repair. If a cylinder is sticking or a sensor is not detecting position, a longer timeout merely allows the machine to wait longer before admitting defeat.

14. Remote I/O and Communication Problems

Modern CNC machines may use remote I/O modules connected over an industrial network or proprietary fieldbus.

Possible symptoms include:

  • Several inputs suddenly becoming unavailable.
  • Multiple outputs being reported as faulty.
  • Remote I/O station alarm.
  • Communication loss with a valve manifold.
  • Intermittent machine-ready signal.
  • Multiple sequence alarms following one network fault.

Potential causes:

  • Remote station power failure.
  • Network cable damage.
  • Connector or termination issue, where applicable.
  • Defective network interface.
  • Incorrect configuration.
  • Communication fault in a shared device.
  • Electrical interference or grounding issue.

Troubleshooting priorities

  • Identify the affected station and devices.
  • Check the station's power and status indicators.
  • Determine whether all devices on the station are affected.
  • Inspect the relevant communication path.
  • Review network diagnostics and device configuration.
  • Check common supply and grounding conditions.
  • Replace the suspected component only after confirming the failure.

When multiple devices fail together, a common power or communication fault is often a better starting point than replacing each device individually.

15. Common CNC PLC/PMC Breakdown Cases

Case 1: Automatic cycle will not start

Symptoms: The CNC is powered and no obvious hardware failure is present, but the cycle-start command does not initiate machining.

Diagnostic steps:

  1. Record the displayed machine alarm or interlock message.
  2. Check the active mode and required machine-ready conditions.
  3. Review the PLC/PMC cycle-start logic.
  4. Check required door, pressure, lubrication, reference, and drive-ready signals as applicable.
  5. Identify the first unsatisfied permissive.
  6. Verify the corresponding field device and wiring.
  7. Correct the confirmed cause and retest.

Possible root causes: Missing interlock signal, incomplete reference return, low hydraulic pressure, drive not ready, or a failed sensor.

Case 2: Tool changer stops halfway through the sequence

Symptoms: The tool-change operation begins but stops before completion.

Diagnostic steps:

  1. Record the sequence step and alarm.
  2. Identify the last command issued.
  3. Identify the expected confirmation signal.
  4. Check spindle state, magazine position, tool-clamp state, and relevant axis conditions.
  5. Check the associated outputs and feedback inputs.
  6. Inspect the actuator, sensor, and mechanical mechanism.
  7. Restore the required condition and verify the complete tool-change sequence.

Possible root causes: Failed position sensor, solenoid valve problem, mechanical obstruction, missing spindle-orientation confirmation, or a sequence timeout.

Never manually force the mechanism without following the machine builder's tool-change recovery procedure.

Case 3: Hydraulic clamp command is ON, but clamping does not occur

Symptoms: The PLC/PMC output indicates a clamp command, but the fixture does not clamp.

Diagnostic steps:

  1. Verify the output address and command.
  2. Check the output module status.
  3. Measure the specified electrical signal using the approved method.
  4. Check the solenoid coil and valve.
  5. Verify hydraulic pressure and fluid-system condition.
  6. Check cylinder movement and mechanical obstruction.
  7. Verify clamp confirmation feedback.

Possible root causes: Missing load supply, failed output channel, open solenoid coil, defective valve, low hydraulic pressure, or mechanical failure.

Case 4: Physical sensor operates, but the CNC still reports an interlock

Symptoms: A door, limit switch, or proximity sensor appears to operate, but the PLC/PMC does not recognize the required condition.

Diagnostic steps:

  1. Confirm the sensor's actual operating state.
  2. Check the sensor supply and output type.
  3. Verify wiring and terminal connections.
  4. Check the input signal at the PLC/PMC diagnostic screen.
  5. Confirm the I/O address mapping.
  6. Trace the signal through the logic to the interlock condition.

Possible root causes: Incorrect sensor alignment, broken conductor, incorrect PNP/NPN interface, input-channel failure, wrong address, or a separate unmet permissive.

Case 5: Several I/O signals fail at once

Symptoms: Multiple inputs or outputs become unavailable, causing several unrelated machine alarms.

Diagnostic steps:

  1. Identify all affected channels and modules.
  2. Determine whether they share a module, field supply, common connection, or remote I/O station.
  3. Check module status and communication diagnostics.
  4. Verify the shared supply and return path.
  5. Inspect connectors and wiring under safe conditions.
  6. Repair the common cause before replacing individual devices.

Possible root causes: Blown shared fuse, failed I/O supply, loose common connection, remote I/O communication failure, or defective module.

16. Safe Testing and Electrical Precautions

PLC/PMC troubleshooting can involve 24 VDC circuits, higher-voltage control circuits, contactors, motors, stored energy, and fluid-power actuators.

  • Follow the site's lockout/tagout and isolation procedures.
  • Verify absence of hazardous energy before touching exposed conductors.
  • Use correctly rated test instruments and approved measurement methods.
  • Check circuit drawings before probing terminals.
  • Do not disconnect or reconnect I/O modules under power unless explicitly supported and authorized by the manufacturer.
  • Do not force outputs or change machine logic to bypass interlocks.
  • Do not bypass guards, door switches, emergency stops, or safety functions.
  • Consider unexpected actuator movement when testing valves and outputs.
  • Use approved online monitoring and force functions only under authorized procedures, with appropriate safeguards.
  • Restore all temporary test connections and confirm the machine is in its approved operating configuration.

Safety rule: If a diagnostic test requires a safety function to be defeated, stop and use the approved maintenance or recovery procedure instead.

17. Preventive Maintenance Checklist

PLC/PMC and I/O

  • Review recurring machine-sequence and I/O alarms.
  • Check PLC/PMC and remote I/O status indicators.
  • Inspect accessible connectors and terminals during planned isolation.
  • Check specified control supplies and shared I/O supplies.
  • Verify that module diagnostics show no unresolved faults.
  • Review changes to logic, parameters, and I/O configuration.

Sensors and actuators

  • Inspect sensor mounting and target alignment.
  • Check cable condition and connector security.
  • Inspect switches for mechanical wear.
  • Check solenoid valves and relay interfaces according to the maintenance plan.
  • Review hydraulic and pneumatic pressure-related alarms.
  • Confirm that required feedback signals correspond to actual machine conditions.

Sequence and documentation

  • Maintain current electrical drawings and I/O lists.
  • Maintain approved PLC/PMC backups.
  • Record machine-specific interlocks and sequence recovery procedures.
  • Document recurring timeouts and their confirmed causes.
  • Record logic or parameter changes through change control.
  • Verify operation after maintenance using the approved test procedure.

19. Interview Questions and Answers

Q1. What is the function of PLC/PMC in a CNC machine?

It controls machine sequencing, interlocks, auxiliary functions, and I/O. It coordinates functions such as clamping, tool changing, lubrication, coolant, and machine readiness.

Q2. What is the difference between a command and feedback?

A command requests an operation, while feedback confirms a device state or completed action. A command being ON does not prove that the requested physical action occurred.

Q3. Why does a CNC machine fail to start its automatic cycle?

A required permissive may be missing, such as door status, reference position, pressure confirmation, lubrication status, or drive readiness. The exact cause should be identified from the logic and diagnostic data.

Q4. What is a sequence timeout?

It occurs when a required condition does not become true within the configured time. The investigation should check the command, actuator, physical process, feedback sensor, and signal path.

Q5. How do you diagnose an input that does not change in the PLC/PMC?

Check the physical device, supply, output signal, wiring, terminal, input channel, module status, and address mapping in a controlled sequence.

Q6. What if a PLC/PMC output is ON but the actuator does not move?

Check the output supply and circuit, relay or interface, field wiring, actuator, and process conditions such as hydraulic or pneumatic pressure.

Q7. Why should interlocks not be bypassed to clear a fault?

Interlocks may prevent hazardous movement or operation under an unsafe condition. Bypassing them can expose personnel and equipment to serious danger and can conceal the actual fault.

Q8. What causes multiple I/O signals to fail simultaneously?

Possible causes include a shared supply failure, common return problem, defective I/O module, remote I/O communication loss, or common connector fault.

Q9. What is the difference between PLC logic and field-device troubleshooting?

PLC logic troubleshooting determines whether the required conditions and commands are being processed correctly. Field-device troubleshooting verifies the sensor, wiring, output circuit, actuator, and physical process.

Q10. What is the best way to find the root cause of a machine interlock?

Identify the blocked operation, trace its required permissives, find the first unsatisfied condition, verify the physical signal path, correct the confirmed cause, and retest the complete sequence.

20. Completion Checklist

  • Understand the CNC PLC/PMC architecture and responsibilities.
  • Distinguish inputs, outputs, commands, feedback, and permissives.
  • Understand machine interlocks and sequence timeouts.
  • Trace ladder logic backward from an output and forward from an input.
  • Diagnose input-module, output-module, and remote I/O faults.
  • Check sensors, relays, solenoids, and field wiring systematically.
  • Separate logic faults from electrical, mechanical, hydraulic, and pneumatic faults.
  • Understand the risks of forcing outputs and bypassing interlocks.
  • Record the confirmed root cause and verify the complete sequence.
