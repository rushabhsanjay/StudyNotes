1. Definition and Purpose

A speed reference signal tells a variable frequency drive (VFD) what speed or operating frequency is being requested. The reference may originate from a PLC, HMI, analog input, communication network, potentiometer, or another configured source.

The speed reference is different from the start/stop command. A start command requests the drive to operate, while the speed reference specifies the desired speed.

For example, a conveyor may receive a RUN command but remain stationary because its speed reference is zero. Alternatively, the drive may receive a reference of 40 Hz but remain stopped because its run command is absent.

Common speed-reference sources include:

  • Analog voltage, such as 0–10 V.
  • Analog current, such as 4–20 mA.
  • Digital communication over PROFINET, EtherNet/IP, Modbus, or another supported network.
  • Local keypad or HMI.
  • Motorized or manual potentiometer.
  • Internal preset or fixed-speed selections.
  • PID controller output.
  • Pulse or frequency input, where supported.

The purpose of troubleshooting is to identify whether the reference is missing, incorrect, incorrectly scaled, limited, overridden, or not being accepted by the drive.

2. Speed Reference Signal Architecture

A typical PLC-controlled VFD speed-control system follows this path:

Operator HMI / Process Sensor
              ↓
       PLC Program or PID
              ↓
      Speed Reference Value
              ↓
    Analog Output or Fieldbus
              ↓
        VFD Reference Input
              ↓
   Scaling, Limits, and Ramps
              ↓
       Drive Speed Control
              ↓
        Motor and Load

In an analog-controlled system, the PLC may send a voltage or current signal to the drive. In a network-controlled system, the reference is usually transmitted as a digital value in a configured data structure.

The drive may apply scaling, minimum and maximum limits, ramp rates, PID functions, or other processing before determining its final operating frequency or speed command.

Therefore, the raw reference from the PLC and the final reference displayed by the drive may not be identical.

A speed reference may be represented in Hz, rpm, percentage, engineering units, or a drive-specific internal format. Always confirm the unit and interpretation of the value being monitored.

4. Analog Speed Reference: 0–10 V

A 0–10 V signal is commonly used to represent a speed command.

For a simple linear mapping:

  • 0 V corresponds to the configured minimum reference.
  • 10 V corresponds to the configured maximum reference.
  • Intermediate voltages correspond to intermediate reference values.

Suppose the drive is configured so that 0–10 V corresponds to 0–50 Hz.

The ideal relationship is:

\[ f\_{\text{ref}}=\frac{V\_{\text{in}}}{10}\times50 \]

For an input of 6 V:

\[ f\_{\text{ref}}=\frac{6}{10}\times50=30\text{ Hz} \]

This calculation assumes linear scaling, a 0–10 V input range, and no additional limits or overrides.

4.1 Common 0–10 V faults

  • Missing analog signal.
  • Incorrect analog common connection.
  • Loose or damaged wire.
  • Wrong input terminal.
  • Analog input configured for current instead of voltage.
  • Incorrect scaling parameters.
  • Electrical noise.
  • Incorrect reference-source selection.
  • PLC analog output fault.
  • Incorrect grounding or shield termination.

4.2 Troubleshooting

  1. Confirm the drive is configured to use the intended analog input.
  2. Check the PLC analog output value.
  3. Measure the signal at the source using the approved procedure.
  4. Measure the signal at the drive input.
  5. Compare the measured voltage with the drive's analog-input monitor.
  6. Verify the configured minimum and maximum scaling.
  7. Check whether the drive's final reference is being limited or overridden.

A correct voltage does not prove that the drive interprets it correctly. Input configuration and scaling must also be verified.

5. Analog Speed Reference: 4–20 mA

A 4–20 mA signal is widely used in industrial control because it can provide good noise immunity and support fault detection when configured appropriately.

In a common linear mapping:

  • 4 mA corresponds to the configured minimum reference.
  • 20 mA corresponds to the configured maximum reference.
  • Intermediate currents represent intermediate values.

Suppose 4–20 mA corresponds to 0–50 Hz.

The reference is:

\[ f\_{\text{ref}}= \frac{I\_{\text{in}}-4}{20-4}\times50 \]

For an input of 12 mA:

\[ f\_{\text{ref}}= \frac{12-4}{16}\times50 =25\text{ Hz} \]

This calculation assumes the stated linear mapping and no additional limits.

5.1 Why 4–20 mA is useful

The 4 mA lower endpoint, sometimes called a live zero, can help distinguish a valid zero-scale measurement from certain wiring or instrument faults. However, this distinction only works when the transmitter, input module, wiring, and configured fault thresholds support it.

5.2 Common faults

  • Open circuit.
  • Incorrect loop wiring.
  • Failed PLC analog output.
  • Incorrect current/voltage input configuration.
  • Wrong scaling range.
  • Incorrect loop power arrangement.
  • Excessive electrical interference.
  • Poor terminal connections.
  • Analog input channel failure.

5.3 Troubleshooting

  • Verify whether the loop is active or passive and how it is powered.
  • Confirm the wiring diagram and polarity.
  • Check the current at the specified test point using suitable equipment.
  • Compare the PLC output value with the drive's analog-input monitor.
  • Verify the configured signal range and scaling.
  • Check whether an input fault threshold is configured.
  • Confirm that the final drive reference follows the expected value.

Do not insert a meter into a current loop without understanding the circuit and using the correct measurement connection.

6. Analog Signal Scaling

Scaling converts a raw signal into the engineering range used by the application.

For a linear mapping:

\[ Y=Y\_{\min}+ \frac{X-X\_{\min}}{X\_{\max}-X\_{\min}} (Y\_{\max}-Y\_{\min}) \]

Where:

  • \(X\) is the measured input.
  • \(X\_{\min}\) and \(X\_{\max}\) are the configured input endpoints.
  • \(Y\_{\min}\) and \(Y\_{\max}\) are the corresponding reference endpoints.
  • \(Y\) is the calculated output reference.

For example, if 4–20 mA represents 10–50 Hz, then 12 mA corresponds to:

\[ f\_{\text{ref}}= 10+\frac{12-4}{20-4}(50-10) \]
\[ f\_{\text{ref}}=30\text{ Hz} \]

The same electrical signal can produce different reference values when the scaling parameters differ.

6.1 Scaling-related symptoms

  • Motor reaches only part of the expected speed.
  • Maximum speed is reached before the analog signal reaches its maximum.
  • Speed remains at a fixed percentage.
  • Reference does not reach zero when expected.
  • PLC display and drive display disagree.
  • Speed changes nonlinearly or unexpectedly.

6.2 Diagnostic approach

Compare four values:

  1. The intended reference on the HMI or process controller.
  2. The raw analog output or transmitted network value.
  3. The signal or value received by the drive.
  4. The final reference accepted by the drive.

The first point where the values diverge is the most useful diagnostic location.

7. Digital Speed Reference Through Fieldbus

When the PLC controls the drive over a network, the speed reference is usually transmitted as a numeric value in the output data or reference word.

The transmitted number may represent frequency, speed, torque, percentage, or a normalized value. The interpretation depends on the drive profile, scaling convention, and configured data mapping.

For example, a drive might use a normalized reference where a specified numeric value represents 100% of the reference range. That representation is not universal.

7.1 Common network-related faults

  • Incorrect communication profile.
  • Wrong data mapping.
  • Wrong reference word or tag.
  • Incorrect scaling in the PLC.
  • Data value not updating.
  • Communication timeout.
  • Drive configured for analog reference instead of network reference.
  • Reference word interpreted with the wrong sign or unit.
  • PLC and drive use different engineering ranges.
  • Preset-speed logic overrides the network reference.

7.2 Troubleshooting method

  1. Confirm that the PLC and drive communication is healthy.
  2. Monitor the reference value generated by the PLC.
  3. Verify the output data address or configured assembly.
  4. Check the actual transmitted numeric value.
  5. Verify the drive's received reference monitor.
  6. Confirm the selected reference source.
  7. Compare the received value with the drive's final reference.
  8. Check minimum and maximum limits, scaling, and any active override.

Network connectivity alone does not prove that the correct reference value is being transmitted or interpreted.

8. Reference Source Selection

A drive may support several possible reference sources. Only the configured source, or a configured combination of sources, will control the final command.

Examples include:

  • Analog input 1.
  • Analog input 2.
  • Fieldbus reference.
  • Keypad reference.
  • Preset speeds.
  • Motorized potentiometer.
  • PID controller output.

8.1 Common failure

The PLC sends a valid reference over the network, but the drive continues operating at a fixed speed because its selected reference source is a preset-speed function.

Other possibilities include:

  • The drive is in local mode.
  • An analog input is selected instead of the network reference.
  • A digital input selects a preset speed.
  • A reference source selector is incorrectly configured.
  • The PLC command source and speed reference source are configured independently.

8.2 Diagnostic checks

  • Identify the configured command source.
  • Identify the configured speed reference source separately.
  • Check local/remote mode.
  • Inspect preset-speed selection inputs.
  • Check the drive's raw and final reference monitors.
  • Compare actual behavior with the approved parameter configuration.

Do not assume that selecting PLC control for start/stop automatically selects the PLC as the speed reference source.

9. Minimum and Maximum Frequency Limits

The drive may restrict the requested reference to a configured operating range.

A simplified model is:

\[ f\_{\text{cmd}}= \min\left(f\_{\max}, \max(f\_{\min},f\_{\text{ref}})\right) \]

Where:

  • \(f\_{\text{ref}}\) is the requested reference.
  • \(f\_{\min}\) is the configured minimum frequency.
  • \(f\_{\max}\) is the configured maximum frequency.
  • \(f\_{\text{cmd}}\) is the reference after these limits are applied.

For example, if the reference requests 45 Hz but the maximum frequency is set to 35 Hz, the drive may limit the command to 35 Hz.

The equation illustrates simple upper and lower limits only. Actual drives may apply additional limits, overrides, PID behavior, torque restrictions, or operating-mode constraints.

9.1 Symptoms of incorrect limits

  • Motor never reaches the expected maximum speed.
  • Motor continues operating above the expected minimum speed.
  • Reference display changes but operating frequency remains capped.
  • Different operating modes have different speed ranges.

Check the active limits and the final reference monitor before changing parameters.

10. Acceleration and Deceleration Ramps

A valid reference does not necessarily become the actual operating frequency immediately. The drive may apply acceleration and deceleration ramps.

For a simplified constant frequency ramp:

\[ t\_{\text{acc}}= \frac{f\_{\text{target}}-f\_{\text{start}}} {\text{Acceleration rate}} \]

If the acceleration rate is expressed in Hz/s, the result is in seconds.

Some drives instead define ramp time as the time to reach a specified reference range. Always use the manufacturer's definition when calculating expected acceleration time.

10.1 Typical symptoms

  • Reference changes immediately but motor speed rises slowly.
  • Stop command is received but frequency decreases gradually.
  • Motor trips during rapid acceleration.
  • Actual frequency does not track a rapidly changing reference.
  • Drive applies a different ramp selected by the active mode or input.

10.2 Troubleshooting

  • Compare the requested reference with the drive's ramped frequency command.
  • Verify acceleration and deceleration settings.
  • Check for alternative ramp selection.
  • Check whether the drive is current-limiting or torque-limiting.
  • Confirm that the mechanical load can follow the commanded ramp.
  • Verify braking requirements when rapid deceleration is needed.

Do not reduce ramp time without checking motor current, mechanical stress, drive limits, and regenerative energy.

11. PID Control and Process References

Some drives regulate a process variable rather than directly following a fixed speed command.

Examples include:

  • Pump pressure.
  • Fan duct pressure.
  • Tank level.
  • Flow rate.
  • Temperature-related process control where the drive application supports it.

A PID controller compares a setpoint with feedback and adjusts its output to reduce the error.

\[ e(t)=SP(t)-PV(t) \]

Where:

  • \(SP\) is the setpoint.
  • \(PV\) is the measured process variable.
  • \(e(t)\) is the control error.

The PID output may become the drive's effective speed reference.

11.1 Common PID-related symptoms

  • Speed remains at minimum despite a high setpoint.
  • Speed reaches maximum but the process value remains below target.
  • Speed oscillates.
  • Speed does not respond to the expected HMI command.
  • Feedback is fixed, missing, or incorrectly scaled.
  • Manual mode works but automatic mode does not.

11.2 Troubleshooting

  1. Confirm whether the drive is in PID or direct-speed mode.
  2. Verify the setpoint value.
  3. Verify the process feedback signal.
  4. Check feedback scaling and units.
  5. Monitor the PID error and output.
  6. Check output limits and sleep or wake-up functions, if configured.
  7. Verify whether the PID output is selected as the active reference.
  8. Investigate tuning only after signal validity and configuration are confirmed.

A PID setpoint is not necessarily the motor speed command. It may be a process target, such as pressure, that the controller uses to calculate the required speed.

12. Preset Speeds and Reference Overrides

Many drives support multiple preset speeds selected by digital inputs or network commands.

This can be useful for machines with fixed operating steps, but it can also make troubleshooting confusing when a preset speed takes priority over an analog or network reference.

Potential causes include:

  • Preset-speed selection input stuck ON.
  • Incorrect PLC output mapping.
  • Wrong preset frequency parameter.
  • Reference priority configuration.
  • Jog mode active.
  • Local reference override.
  • PID mode selected unexpectedly.

Check the drive's active reference source and selected preset-speed status before assuming that the analog or network reference is defective.

14. Practical Breakdown Example: 10 V Input but Motor Runs at Low Speed

Machine condition: The PLC analog output reaches 10 V, but the drive operates at only 25 Hz instead of the expected 50 Hz.

Initial observations:

  • Run command is present.
  • Drive has no active fault.
  • Analog output reaches 10 V.
  • Drive reference monitor indicates 25 Hz.

Investigation:

  1. Verify the drive is configured to use the correct analog input.
  2. Confirm the analog input is configured for voltage rather than current.
  3. Measure the voltage at the drive input.
  4. Check the configured input scaling range.
  5. Review minimum and maximum reference limits.
  6. Inspect the final reference monitor for additional overrides.

Possible root cause: The analog input scaling is configured for a maximum of 25 Hz at 10 V.

Corrective action: Restore the approved scaling configuration for the application, subject to the motor and machine operating limits.

Verification: Confirm that the input produces the expected reference at several points across the range, then verify normal operation under approved conditions.

15. Practical Breakdown Example: PLC Reference Changes but Drive Speed Does Not

Machine condition: The PLC sends a changing speed reference over the industrial network, but the drive remains at a fixed speed.

Investigation:

  1. Confirm that communication diagnostics show the drive online.
  2. Monitor the reference generated by the PLC.
  3. Verify the transmitted output data and mapping.
  4. Check the reference value received by the drive.
  5. Confirm that network reference is selected as the active speed source.
  6. Check preset-speed selection and local/remote configuration.
  7. Review the final reference after limits and overrides.

Possible root cause: The drive is configured to use a preset-speed selection rather than the fieldbus reference.

Corrective action: Restore the intended reference-source configuration and verify the digital input assignments.

Verification: Change the PLC reference through several approved operating points and confirm that the drive's received and final references respond as intended.

16. Practical Breakdown Example: Speed Oscillation

Machine condition: A pump motor repeatedly speeds up and slows down while automatic pressure control is active.

Investigation:

  1. Confirm the actual speed command and drive operating mode.
  2. Trend the pressure setpoint and pressure feedback.
  3. Check the stability and scaling of the feedback signal.
  4. Inspect for loose wiring, noise, or intermittent sensor readings.
  5. Monitor PID error and output.
  6. Check output limits and any configured sleep/wake logic.
  7. Evaluate PID tuning only after the measurement and configuration are verified.

Possible root cause: The pressure feedback signal is noisy, causing the PID controller to continually adjust its output.

Corrective action: Correct the source of the unstable measurement and apply the approved signal-conditioning or control-system correction.

Verification: Confirm stable feedback, smooth reference changes, and acceptable pressure control under representative operating conditions.

17. Safety and Parameter Management

  • Follow approved electrical isolation procedures before modifying wiring.
  • Use suitable equipment for analog measurements.
  • Do not short or inject signals into analog terminals without an approved test method.
  • Verify terminal assignments and signal types before connecting a PLC output.
  • Check motor and machine operating limits before increasing the reference range.
  • Preserve the original parameter values before making changes.
  • Use change control for PLC scaling and drive parameters.
  • Verify safe behavior when analog signals or communications are lost.
  • Confirm the behavior of minimum-speed, maximum-speed, and restart functions.
  • Validate changes under controlled conditions before releasing the machine to production.

19. Interview Questions and Answers

Q1. What is a speed reference signal?

It is the requested operating speed or corresponding frequency command provided to the drive through an analog input, communication network, keypad, or another configured source.

Q2. What is the difference between a run command and a speed reference?

The run command requests operation, while the speed reference defines the requested operating point. A drive may receive one without the other.

Q3. Why is 4–20 mA commonly used in industrial control?

It offers good noise immunity in many industrial installations and can support detection of certain signal faults when the loop and input are correctly configured.

Q4. What is signal scaling?

Scaling converts an electrical input or transmitted numeric value into the engineering range required by the application, such as 4–20 mA representing 0–50 Hz.

Q5. Why does a correct analog voltage not guarantee the correct speed?

The drive may use the wrong input source, incorrect scaling, configured frequency limits, a preset reference, or another active override.

Q6. What is the difference between reference frequency and actual motor speed?

Reference frequency is the commanded electrical operating frequency. Actual motor speed is the shaft's rotational speed, which depends on motor construction, slip or control method, and operating conditions.

Q7. Why can a network-connected drive ignore the PLC speed command?

Possible causes include incorrect data mapping, wrong reference-source selection, incorrect scaling, a control-mode mismatch, or a communication problem affecting the command data.

Q8. What does a maximum-frequency limit do?

It restricts the commanded operating frequency to the configured upper limit, even if the incoming reference requests a higher value.

Q9. What is the role of PID in a drive application?

PID control compares a process setpoint with feedback and adjusts its output to reduce the difference. That output may become the effective speed reference.

Q10. What is the correct troubleshooting approach for an incorrect speed reference?

Compare the intended reference, source output, drive input or received network value, and final drive reference. Verify source selection, scaling, limits, ramps, and overrides before changing parameters.

20. Completion Checklist

  • Explain the difference between run command, speed reference, and actual speed.
  • Understand analog 0–10 V reference scaling.
  • Understand analog 4–20 mA reference scaling.
  • Calculate linear scaling for a given input and output range.
  • Trace PLC analog output to the drive input.
  • Diagnose network-based reference values and data mapping.
  • Verify the active reference source.
  • Understand minimum and maximum frequency limits.
  • Distinguish reference changes from acceleration and deceleration behavior.
  • Understand PID setpoint, feedback, and output.
  • Identify preset-speed and reference-override conditions.
  • Record the source value, received value, and final reference.
  • Verify correct reference response after repairs.
