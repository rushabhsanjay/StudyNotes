1. Definition and Purpose

A drive command signal tells a VFD or servo drive what action to perform, such as starting, stopping, enabling, resetting a fault, or selecting a direction of rotation.

A drive can have healthy power, a healthy motor, and a valid speed reference but still fail to run because the start command is missing, the enable signal is inactive, a safety interlock is open, or the control source is configured incorrectly.

The purpose of command-signal troubleshooting is to identify where the intended command is lost, blocked, incorrectly configured, or rejected.

Common command functions include:

  • Start or run command.
  • Stop command.
  • Forward and reverse commands.
  • Drive enable.
  • Fault reset.
  • Jog command.
  • Local/remote selection.
  • Automatic/manual selection.
  • Safety-related permission signals.
  • PLC sequence and interlock conditions.

Important distinction: A run command requests motion. It does not guarantee that the motor will rotate. The drive must also be ready, enabled, free of active blocking faults, and supplied with a valid reference and operating conditions.

2. Start/Stop Command Architecture

A typical industrial drive control path is:

Operator Push Button / HMI / Machine Sensor
                    ↓
             PLC Input or Logic
                    ↓
          PLC Sequence and Interlocks
                    ↓
       PLC Output / Fieldbus Command
                    ↓
             VFD Control Interface
                    ↓
       Drive Enable and Run Conditions
                    ↓
             VFD Output to Motor
                    ↓
             Motor and Machine

The exact arrangement depends on whether commands are hardwired, transmitted over a fieldbus, generated by the drive's own terminals, or provided by a combination of these methods.

A missing command must be traced through the actual installed architecture. Replacing the drive before checking the PLC output, control wiring, and command-source settings is an expensive way to discover a loose wire.

3. Common Command Sources

3.1 Hardwired digital inputs

The PLC or operator circuit sends a discrete ON/OFF signal to the drive's digital input.

Typical examples:

  • DI1: Forward run.
  • DI2: Reverse run.
  • DI3: Enable.
  • DI4: Fault reset.

These assignments are examples only. Actual terminal assignments must be verified from the drive configuration and electrical drawings.

3.2 Fieldbus commands

The PLC communicates with the drive over an industrial network such as PROFINET, EtherNet/IP, PROFIBUS, Modbus, or another supported protocol.

The command may be contained in a control word or structured output data.

Typical command information includes:

  • Enable operation.
  • Start or stop.
  • Direction.
  • Fault reset.
  • Jog.
  • Control-word bits.

If the fieldbus is disconnected, the PLC is not in the correct mode, or the control word is incorrect, the drive may not receive the intended run command.

3.3 Local keypad or HMI control

Some drives can be operated from their local keypad or a configured HMI interface.

The drive may be set to local control, remote control, terminal control, or network control. The exact terminology varies by manufacturer.

If the drive is configured to accept commands from the keypad but the PLC is sending a hardwired run signal, the motor may not start even though the signal is physically present.

3.4 Internal drive logic

Some drives support internal timers, programmable logic, application functions, or built-in sequence control.

In these systems, the final run command may depend on multiple internal conditions rather than a single external input.

4. Two-Wire and Three-Wire Start/Stop Control

Two common hardwired control arrangements are two-wire and three-wire control. Their behavior must be understood before troubleshooting a drive that starts unexpectedly or refuses to start.

4.1 Two-wire control

Two-wire control generally uses a maintained contact or maintained logic state to represent the run request.

For example, a maintained ON signal requests running, and an OFF signal requests stopping.

Run Switch ON
     ↓
Run Command Active
     ↓
Drive Permissives Satisfied
     ↓
Motor Runs

Run Switch OFF
     ↓
Run Command Removed
     ↓
Drive Stops According to Stop Mode

Typical applications include PLC outputs and maintained machine-control signals.

A key risk is that if the run signal remains ON during a power interruption or control restart, the drive may restart when its conditions permit. Restart behavior depends on the drive configuration, control scheme, and applicable safety requirements.

4.2 Three-wire control

Three-wire control commonly uses separate momentary start and stop push buttons, with the control circuit or drive maintaining the run state after the start button is released.

A typical arrangement includes:

  • Normally open START push button.
  • Normally closed STOP push button.
  • Holding or seal-in logic.
  • Appropriate drive run-command configuration.

Conceptually:

STOP Circuit Healthy
        ↓
START Button Pressed
        ↓
Run State Latched
        ↓
Motor Runs

STOP Button Pressed
        ↓
Run State Cleared
        ↓
Motor Stops

The latching behavior may be implemented in PLC logic, relay logic, or the drive's configured control mode.

4.3 Comparison

Feature Two-wire control Three-wire control
Typical input behavior Maintained run state Momentary start and stop actions
Run-state retention Maintained command remains active Separate logic retains run state
Common use PLC-controlled run request Push-button start/stop stations
Restart consideration Maintained ON command may permit restart Start logic often requires a new start action, depending on implementation
Main diagnostic focus Run input state and command source Start/stop circuit and latching logic

Neither arrangement is automatically safer in every application. Restart behavior must be designed and validated for the actual machine risk assessment.

5. Stop Commands and Stop Modes

A stop command does not always mean the drive immediately removes all motor torque. The response depends on the configured stop mode and any active safety functions.

Common stop behaviors include:

  • Ramp stop: The drive decelerates according to a configured ramp.
  • Coast stop: The drive removes its active drive command and the motor slows according to its mechanical characteristics.
  • DC injection braking: The drive applies a controlled DC component to create braking torque where supported and configured.
  • Dynamic braking: A braking circuit dissipates regenerated energy, commonly through a braking resistor where the drive supports it.
  • Safety-related stop functions: Safety functions such as Safe Torque Off (STO) act through a safety-rated system and must be designed and validated according to the applicable safety requirements.

The terms and exact behavior vary by drive manufacturer and application.

5.1 Why a stop command may appear ineffective

Possible reasons include:

  • The PLC continues asserting the run command.
  • The wrong command source is selected.
  • A fieldbus control word is not updating.
  • The stop input is assigned incorrectly.
  • The stop mode is configured differently from expectations.
  • A different operating mode overrides the intended command.
  • The machine is coasting after torque removal.
  • A brake or mechanical load affects the stopping behavior.

If a stop command is not working as expected, verify the command state and configured stop mode. Do not assume that removing the run signal guarantees immediate mechanical stopping.

6. Drive Enable and Run Command Are Different

A drive enable signal generally permits operation, while the run command requests the drive to execute motion.

The precise distinction depends on the drive's control architecture.

A simplified condition is:

\[ \text{Run permitted} = \text{Drive ready} \land \text{Enable active} \land \text{Run request active} \land \text{Permissives satisfied} \]

This is a conceptual relationship, not a universal internal drive equation.

A drive may therefore show:

  • Ready but not running.
  • Enabled but not running.
  • Run command present but operation inhibited.
  • Running status active while the motor is still accelerating.
  • Stop command accepted while the motor continues decelerating.

6.1 Common enabling conditions

  • No active blocking fault.
  • Control supply available.
  • Drive enable input active.
  • Safety system in the required state.
  • Correct control mode selected.
  • Valid communication, if network control is used.
  • Machine sequence permitting operation.
  • Correct direction and operating mode selection.
  • Valid speed or torque reference where required.

Some drives use different status words and permissive structures, so verify the exact meaning in the relevant manual.

7. PLC-to-Drive Command Troubleshooting

When a PLC-controlled motor fails to start, trace the command from the operator request to the drive's accepted command.

7.1 Diagnostic sequence

  1. Confirm the operator request on the HMI or push button.
  2. Check whether the corresponding PLC input changes state.
  3. Verify the PLC sequence conditions and interlocks.
  4. Check whether the PLC logic generates the intended run command.
  5. Verify the PLC output module or fieldbus output data.
  6. For hardwired control, measure the control signal using the approved procedure.
  7. Confirm that the signal reaches the correct drive terminal.
  8. Check the drive's digital input monitor or control-word monitor.
  9. Verify the configured command source.
  10. Check the drive-ready, enable, fault, and inhibit status.
  11. Confirm that the drive accepts the command.
  12. Investigate the reference and output conditions if the command is accepted but motion does not occur.

The purpose is to find the first point where the actual signal differs from the intended state.

7.2 Signal tracing table

Test point Expected condition If incorrect, investigate
HMI or push button Start request present Operator input, HMI logic, button contacts
PLC input Input state changes correctly Sensor, field wiring, input module
PLC sequence Start conditions satisfied Interlocks, sequence state, permissives
PLC output or network data Run command generated PLC logic, output mapping, communication
Drive input monitor Command received Wiring, terminal assignment, input configuration
Drive control source Correct source selected Local/remote mode, parameter settings
Drive status Ready and permitted Active fault, enable, safety status, inhibit
Drive output Output behavior matches command and reference Drive diagnostics, configuration, motor circuit

8. Digital Input Electrical Checks

Hardwired commands may use 24 V DC digital inputs, but the actual voltage and input circuit must be confirmed from the drive documentation.

8.1 Common issues

  • Missing control supply.
  • Blown control fuse.
  • Loose terminal.
  • Broken conductor.
  • Incorrect common or reference connection.
  • Wrong NPN/PNP or sinking/sourcing arrangement.
  • Incorrect input polarity.
  • Incorrectly assigned digital input.
  • Failed PLC output transistor or relay contact.
  • Input configured for an unexpected function.

8.2 Safe measurement method

  • Review the electrical drawing and terminal assignment.
  • Confirm the specified control voltage.
  • Use a suitable meter and approved test procedure.
  • Check the signal at the source and at the drive input.
  • Compare the measured electrical state with the drive's input monitor.
  • Inspect the common/reference arrangement.
  • Restore covers and barriers after testing.

A voltage reading alone does not always prove that an input circuit is functioning correctly. The drive's diagnostic monitor and the configured input function are also important.

Never short terminals or apply an external voltage to a drive input unless the circuit and procedure explicitly permit it.

9. Fieldbus Command Troubleshooting

When the drive is controlled over a network, the PLC may send a control word and receive a status word.

The names, bit positions, and meanings depend on the drive's communication profile and configuration.

9.1 Common causes

  • Network cable disconnected.
  • PLC or drive communication fault.
  • Wrong IP address or device name.
  • Incorrect fieldbus configuration.
  • Drive not configured for network control.
  • Wrong control-word mapping.
  • PLC output data not updating.
  • Drive in local mode.
  • Communication watchdog timeout.
  • Fault reset or enable bit not handled correctly.
  • Incorrect telegram or assembly configuration.

9.2 Diagnostic method

  1. Check the PLC communication diagnostics.
  2. Check the drive's network status.
  3. Verify the configured device and communication profile.
  4. Confirm that the PLC output data changes as expected.
  5. Monitor the transmitted control word.
  6. Read the drive's returned status word.
  7. Verify the correct command-source configuration.
  8. Check communication watchdog and timeout behavior.
  9. Confirm the drive's interpretation of the command.

A connected network does not prove that the drive is receiving the correct run command. Communication health, data mapping, command-source selection, and permissive logic are separate checks.

10. Local/Remote and Hand/Auto Selection

Many industrial systems support local and remote operation.

Common modes include:

  • Local: Commands come from the drive keypad or another locally configured interface.
  • Remote: Commands come from the configured external source, such as PLC terminals or fieldbus.
  • Hand: Operator-controlled operation, often through an HMI or local control station.
  • Auto: Commands are determined by PLC sequence logic or process control.

The exact definitions vary by installation.

10.1 Common failure

The operator presses START on the HMI, but the drive remains stopped because it is in local mode and ignores the remote command.

Alternatively, the drive may be in remote mode while a technician expects the keypad to control it.

10.2 Checks

  • Verify the selected control mode.
  • Confirm the configured command source.
  • Check whether the mode is selected by a parameter, digital input, HMI, or fieldbus.
  • Confirm that the requested mode transition is permitted.
  • Check for a local/remote status indication.
  • Follow the plant's authorization procedure before changing modes.

Mode changes can alter how a machine responds to maintained commands. Verify restart behavior and machine safety before returning to automatic operation.

11. Fault Reset and Start Command Interaction

A fault reset command is not the same as a start command.

A reset typically acknowledges or clears a resettable fault after the underlying fault condition has been removed. It does not necessarily start the motor.

11.1 Typical sequence

Drive Fault Occurs
        ↓
Drive Output Stops or Is Inhibited
        ↓
Fault Cause Investigated
        ↓
Underlying Fault Corrected
        ↓
Reset Command Applied If Permitted
        ↓
Drive Returns to Ready State
        ↓
Valid Start Command Applied
        ↓
Drive Runs If All Conditions Are Satisfied

11.2 Common problems

  • Reset is issued while the fault remains active.
  • Reset input is assigned incorrectly.
  • Reset command is held continuously when a pulse is expected.
  • PLC reset logic repeats unexpectedly.
  • A start command remains active while the fault is reset.
  • A fault clears but a separate interlock still blocks operation.

Do not repeatedly reset a drive without understanding the cause. A reset is an acknowledgement mechanism, not a repair technique.

12. Interlocks and Permissives

An interlock prevents an operation when a required condition is not satisfied. A permissive is a condition that must be true before an operation is allowed.

Examples include:

  • Guard or access condition satisfied.
  • Lubrication pressure available.
  • Cooling system healthy.
  • Conveyor downstream ready.
  • Hydraulic pressure within limits.
  • Process equipment in the correct state.
  • No conflicting direction command.
  • Machine sequence at the correct step.
  • Safety system in the required operating state.

Interlocks may be implemented in PLC logic, hardwired control circuits, the drive, or a safety-rated control system.

12.1 Important distinction

A standard PLC interlock is not automatically a safety-rated function. Personnel protection must use the designed and validated safety system, including appropriate safety-rated devices and functions.

Never bypass an interlock or safety circuit merely to make the motor run. Identify why the condition is false and use the approved troubleshooting method.

13. Direction and Conflicting Commands

Some drives support separate forward and reverse commands. Others use a run command plus a direction bit.

Possible faults include:

  • Forward and reverse commands active simultaneously.
  • Incorrect direction mapping.
  • Wrong PLC output assignment.
  • Inconsistent direction state between PLC and drive.
  • Direction reversal attempted outside permitted conditions.

The drive may reject conflicting commands, prioritize one input, stop, or behave according to its configured logic.

Verify the manufacturer's truth table and the plant's intended logic rather than assuming a universal response.

15. Practical Breakdown Example: PLC Run Command Missing

Machine condition: A motor does not start from the HMI. The VFD has no active fault and displays ready.

Initial observations:

  • HMI START button responds.
  • Drive shows ready.
  • Motor does not rotate.
  • No run command is visible in the drive input monitor.

Investigation:

  1. Verify that the HMI request reaches the PLC.
  2. Check sequence state and permissive conditions.
  3. Monitor the PLC's internal run-command bit.
  4. Verify the mapped output or fieldbus command.
  5. Check the output module and wiring where hardwired control is used.
  6. Verify the drive's command-source selection.
  7. Check the drive's input monitor and terminal assignment.

Possible root cause: A PLC output address was changed during a program modification, but the physical drive command remained wired to the original output.

Corrective action: Restore the correct mapping under change control and verify the logic and electrical drawing.

Verification: Confirm the start request travels through the expected path and the motor starts and stops correctly under the approved test conditions.

16. Practical Breakdown Example: Drive Runs from Keypad Only

Machine condition: The motor operates from the drive keypad but does not start from the PLC.

Investigation:

  1. Record the active control mode.
  2. Verify whether the drive is configured for local or remote command control.
  3. Check the configured remote source.
  4. If hardwired, monitor the digital input and verify the terminal assignment.
  5. If fieldbus-controlled, inspect communication status, output data, and control-word mapping.
  6. Check whether enable and permissive conditions are satisfied.

Possible root cause: The drive is configured for keypad control rather than the intended PLC command source.

Corrective action: Correct the command-source configuration according to the approved machine settings.

Verification: Confirm that PLC commands are accepted, local/remote behavior matches the design, and unexpected restart behavior is not introduced.

17. Practical Breakdown Example: Motor Does Not Stop as Expected

Machine condition: An operator issues STOP, but the motor continues rotating for several seconds.

Investigation:

  1. Verify that the stop request reaches the PLC or drive.
  2. Confirm that the run command is removed or the appropriate stop command is transmitted.
  3. Check the configured stop mode and deceleration ramp.
  4. Review whether the load has significant inertia.
  5. Check the mechanical braking arrangement if rapid stopping is required.
  6. Verify that the machine's required stopping performance is met.

Possible root cause: The drive is configured for ramp stopping, and the load has sufficient inertia to require several seconds to decelerate.

Corrective action: Apply the approved stop behavior and braking design for the machine. Do not arbitrarily shorten the ramp or alter braking parameters without checking drive limits, regenerative energy, mechanical constraints, and safety requirements.

Verification: Measure the stopping time under representative operating conditions and confirm compliance with the machine design.

18. Safety Considerations

  • Apply the approved isolation and lockout/tagout procedure before electrical work.
  • Verify absence of hazardous voltage before touching conductors.
  • Observe the manufacturer's DC bus discharge time and verify the required safe condition.
  • Never assume a stopped motor is electrically isolated.
  • Do not use a standard drive run/stop command as a substitute for an emergency-stop or safety-rated stop function.
  • Never bypass safety circuits to force a start command.
  • Confirm the machine's restart behavior after power loss, communication loss, fault reset, or mode changes.
  • Use approved procedures for live measurements and only where necessary.
  • Keep guards and protective barriers in place during normal operation.
  • Follow plant authorization and change-control procedures for drive parameters and PLC logic.

20. Interview Questions and Answers

Q1. What is the difference between a start command and a speed reference?

The start command requests operation. The speed reference specifies the desired speed or frequency. A drive may receive a valid speed reference while remaining stopped because the run command or enable is missing.

Q2. Why can a drive be ready but not run?

The drive may be ready but not receiving a run command, may be disabled, may be in the wrong control mode, or may be blocked by an interlock or permissive condition.

Q3. What is the difference between two-wire and three-wire control?

Two-wire control generally uses a maintained run state. Three-wire control commonly uses momentary start and stop actions with a latched run state implemented in logic or by the drive.

Q4. Why does a drive run from its keypad but not from the PLC?

The drive may be configured for local control, the remote command source may be incorrect, or the PLC output, wiring, fieldbus data, or control-word mapping may be faulty.

Q5. What is a drive permissive?

A permissive is a required condition that must be satisfied before an operation is allowed, such as cooling availability, correct machine sequence, or an acceptable process condition.

Q6. Why might a reset command fail to clear a fault?

The fault condition may still be active, the reset input may be incorrectly configured, the reset signal may not be received, or the fault may require a different approved recovery procedure.

Q7. Does a stop command immediately stop the motor?

Not necessarily. Depending on the stop mode, the drive may ramp down or remove torque and allow the motor to coast. Mechanical stopping time depends on the drive, motor, load, and braking system.

Q8. What should be checked first when the drive has no fault but the motor does not start?

Check the actual run-command state, enable status, command source, drive-ready status, and active permissives. Trace the signal from the operator request to the drive rather than immediately replacing hardware.

Q9. What is a control word?

A control word is a structured set of bits transmitted over a communication interface to command a drive. Its exact bit meanings depend on the communication profile and drive configuration.

Q10. Why must restart behavior be checked after troubleshooting?

Power restoration, communication recovery, fault reset, or switching control modes can change whether a maintained run request is accepted. Unexpected restart can create serious machine hazards.

21. Completion Checklist

  • Explain the start/stop command path from operator request to drive.
  • Distinguish run command, drive enable, ready status, and speed reference.
  • Explain two-wire and three-wire control.
  • Identify ramp stop, coast stop, and relevant braking behavior.
  • Trace hardwired digital inputs safely.
  • Diagnose PLC output and sequence-related command failures.
  • Diagnose fieldbus control-word and status-word issues.
  • Verify local/remote and hand/auto control modes.
  • Understand fault reset and its limitations.
  • Check interlocks, permissives, and direction commands.
  • Verify restart behavior after power or communication recovery.
  • Document the root cause and confirm correct start/stop operation.
