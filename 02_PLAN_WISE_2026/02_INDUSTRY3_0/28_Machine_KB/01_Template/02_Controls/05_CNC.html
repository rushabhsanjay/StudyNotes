1. Purpose of CNC Documentation

Computer Numerical Control (CNC) is used to control machine movements and operations through a programmed sequence of commands. A CNC system coordinates axis motion, spindle operation, tool changes, auxiliary functions, and process conditions according to the machine configuration.

In industrial maintenance, CNC documentation must help a technician understand:

  • Which CNC controller operates the machine.
  • Which axes and spindles the controller manages.
  • How machine coordinates and workpiece coordinates are defined.
  • How tool geometry and wear offsets affect machining.
  • Where CNC programs, parameters, and compensation data are stored.
  • How the CNC communicates with the PLC, drives, HMI, and machine peripherals.
  • How to diagnose faults without losing important evidence or introducing unsafe movement.
  • How to restore the machine after controller, drive, encoder, or storage failure.

A CNC knowledge base is not simply a list of G-codes and M-codes. It is a controlled record of the complete machine-control configuration.

The exact architecture varies by CNC manufacturer and machine builder. Some controllers integrate PLC functions, while others use a separate PLC or machine-control subsystem.

2.1 CNC controller

The CNC controller interprets the part program and coordinates the machine's motion and auxiliary functions.

Its responsibilities may include:

  • Program interpretation.
  • Axis interpolation.
  • Coordinate transformations.
  • Feed-rate control.
  • Tool and work offset management.
  • Spindle commands.
  • Canned cycles and machining functions.
  • Alarm handling.
  • Communication with drives and PLC logic.

2.2 PLC or machine-control logic

The machine PLC or integrated PLC functionality manages the sequencing and interlocks required to operate the machine.

Examples include:

  • Confirming that a tool change is permitted.
  • Operating coolant pumps.
  • Controlling hydraulic or pneumatic clamps.
  • Monitoring guard and door interlocks.
  • Checking lubrication and pressure conditions.
  • Managing pallet changers and conveyors.

The CNC program may request an auxiliary operation, but the PLC and machine logic determine how that operation is executed and interlocked.

2.3 Axis drives and spindle drive

Servo drives operate controlled feed axes. A spindle drive controls spindle rotation according to the installed architecture.

The spindle may use a dedicated spindle motor and drive rather than the same type of servo axis used for linear positioning.

Record the actual architecture instead of assuming that every motor is controlled by an identical drive.

3.2 Common CNC controller families

Examples of industrial CNC platforms include:

  • FANUC CNC systems.
  • Siemens SINUMERIK systems.

4.3 Machine coordinate direction

Machine coordinates define the machine's reference coordinate system. Positive and negative directions must be established from the CNC configuration and machine builder's documentation.

For maintenance work, verify direction using the approved diagnostic procedure. Never infer it solely from the physical appearance of the machine.

An incorrect assumption about axis direction can cause tool, fixture, or machine collision during recovery or commissioning.

5. Coordinate Systems in CNC

CNC machines may use several coordinate representations simultaneously. Confusing them is a common source of positioning errors.

5.1 Machine coordinate system

The machine coordinate system defines axis positions relative to the machine's established reference.

It is used for functions such as:

  • Machine referencing.
  • Travel-limit management.
  • Machine position diagnostics.
  • Certain machine setup and recovery operations.

Machine coordinates are not necessarily the same as the displayed workpiece coordinates.

5.2 Workpiece coordinate system

A workpiece coordinate system defines the location of the part or fixture relative to the machine.

Common CNC programming conventions include work coordinate systems such as G54, G55, and additional supported work offsets. Availability and behavior depend on the controller and programming configuration.

For example, the programmer may define the top face of a component as the workpiece Z-zero reference. The machine's physical reference is still maintained separately.

5.3 Local coordinate systems

Some CNC controllers support local coordinate shifts, rotations, scaling, or other coordinate transformations.

These functions can be useful for repeated features and complex setups, but their interaction with the active work coordinate system must be understood.

Record any machine-specific transformations or local offsets that are necessary to reproduce the intended machining setup.

5.4 Simplified coordinate relationship

Conceptually, a workpiece position is related to the machine position through a coordinate transformation.

For a simple one-dimensional translation:

\[ X\_{\text{machine}} = X\_{\text{work}} + X\_{\text{work offset}} \]

This simplified relationship is illustrative only. Actual CNC coordinate calculations may include sign conventions, tool compensation, local shifts, rotations, kinematics, and controller-specific rules.

Do not use this equation as a universal formula for editing CNC offsets. Confirm the controller's actual coordinate convention before making changes.

6. Work Offsets

A work offset defines the relationship between a programmed workpiece coordinate and the machine coordinate system.

6.1 Purpose of work offsets

Work offsets allow a part program to use a consistent coordinate reference even when the workpiece is mounted at a different position on the machine.

They are commonly used for:

  • Setting the part datum.
  • Machining multiple fixtures.
  • Repeating operations on multiple workpieces.
  • Managing palletized production.
  • Reusing a program across compatible setups.

6.2 Common work offset fields

6.3 Work offset versus machine zero

Machine zero and workpiece zero serve different purposes.

  • Machine reference: Establishes the machine's coordinate reference.
  • Workpiece datum: Establishes the coordinate origin used for the part program.
  • Tool reference: Describes the relevant tool geometry relative to the tool or machine reference, according to the controller's tool-management system.

Changing a work offset is not the same as rehoming the machine. Changing the machine reference configuration can affect the interpretation of all machine positions and must be treated as a controlled engineering action.

6.4 Multiple work offsets

A machine may have several work coordinate systems for different fixtures, parts, or machining positions.

The setup documentation should identify which work offset is intended for each part number and fixture.

Do not assume that the first available work offset is the correct one. Confirm the program, fixture, setup sheet, and active coordinate selection.

7. Tool Offsets

Tool offsets account for tool dimensions or tool-specific corrections so that programmed positions correspond to the intended cutting geometry.

The exact offset structure varies by CNC system and machine configuration.

7.1 Common tool offset categories

Tool length compensation: Accounts for the effective length of a tool relative to the applicable machine or tool reference.

Tool radius or diameter compensation: Accounts for the cutting tool's effective radius or diameter when supported and correctly applied by the program.

Tool geometry data: Stores measured or defined tool dimensions.

Tool wear compensation: Applies a controlled correction to account for wear or dimensional deviation.

Nose radius compensation: Used on applicable turning operations to account for insert nose geometry.

7.2 Typical tool-offset register

Field Description

7.3 Geometry and wear are not interchangeable records

Tool geometry describes the established tool dimensions according to the controller's offset model. Wear compensation applies a correction to account for tool condition or dimensional deviation.

Combining these values without understanding the controller's convention can create a setup error.

Use the approved tool measurement procedure and record the reason for significant offset changes.

8. CNC Offsets: Practical Distinctions

Offset or reference Main purpose Common maintenance concern
Machine reference Defines the machine coordinate origin Incorrect reference or encoder recovery
Work offset Defines the part or fixture coordinate origin Incorrect datum or setup selection
Tool length offset Accounts for tool length Incorrect tool measurement or offset selection
Tool radius compensation Accounts for cutter radius Wrong cutter data or program compensation
Tool wear offset Applies a correction for wear Excessive or unexplained correction
Local coordinate shift Applies a local coordinate transformation Unexpected shift or inherited setup state
Rotary-axis offset Defines an applicable rotary reference or transformation Incorrect alignment or kinematic configuration
Compensation table Corrects supported position-dependent errors Invalid or lost compensation data

The names and exact behavior of these features vary by CNC manufacturer and configuration. Some controllers combine or organize them differently.

9. CNC Programming Fundamentals

A CNC program contains commands that define movement and machining operations.

Programs commonly contain:

  • Preparatory functions, commonly called G-codes.
  • Auxiliary functions, commonly called M-codes.
  • Axis coordinates.
  • Feed rates.
  • Spindle commands.
  • Tool-selection and tool-change commands.
  • Tool and work compensation commands.
  • Dwell, canned-cycle, and other controller-specific instructions.

9.1 Illustrative program structure

This is not a production-ready machining program. It demonstrates only the structure of a small set of commands. The tool-change syntax, spindle sequence, safe positions, axis limits, work setup, and machine-specific requirements must be verified for the installed controller.

Even apparently standard commands can behave differently depending on the machine builder's integration and configured options.

9.2 Modal and non-modal commands

A modal command remains active until it is cancelled or replaced by another command in the same modal group.

A non-modal command typically applies to a specific block or operation.

Understanding modal state matters because a program may inherit an active coordinate system, feed mode, compensation mode, or motion mode from an earlier block.

A maintenance technician reviewing a program should identify the active modal state before diagnosing unexpected motion.

9.3 Absolute and incremental positioning

Many CNC systems distinguish absolute positioning from incremental positioning.

  • Absolute positioning refers to a location within the active coordinate system.
  • Incremental positioning describes movement relative to the current position.

The common programming conventions include G90 and G91, but their exact behavior must be verified for the controller and programming context.

An incorrect assumption about absolute or incremental mode can cause unexpected movement.

10.2 Program change control

For every approved program change, record:

  • Reason for the change.
  • Original revision.
  • Revised program revision.
  • Affected operations.
  • Expected effect on part quality and cycle time.
  • Required tool or fixture changes.
  • Simulation or verification results where applicable.
  • Approval and release status.
  • Recovery path to the previous approved revision.

Do not overwrite the only known-good production program with an unverified modification.

10.3 Program comparison

When a fault begins after a program change, compare the last known-good revision with the current version.

Check for changes in:

  • Axis coordinates.
  • Feed and spindle commands.
  • Work offset selection.
  • Tool selection and compensation.
  • Motion mode.
  • Coordinate shifts and rotations.
  • Canned cycles.
  • Auxiliary commands.
  • Subprogram calls.
  • Tool-change or machine-sequence interactions.

A program comparison should preserve the original files and establish which revision was active when the problem occurred.

11. CNC Parameters and Configuration

CNC parameters define system behavior beyond the individual part program. Their function may include axis configuration, machine dynamics, coordinate handling, compensation, communication, and machine-builder-specific behavior.

11.1 Common parameter categories

  • Axis and servo configuration.
  • Encoder and feedback scaling.
  • Reference-return settings.
  • Machine travel limits.
  • Spindle configuration.
  • Coordinate and kinematic configuration.
  • Tool-management configuration.
  • Compensation data.
  • Communication and interface settings.
  • PLC or machine-builder integration settings.
  • Display and operator-interface configuration.

11.2 Parameter management principles

  • Record the parameter name or number, description, value, unit, and source.
  • Maintain an approved baseline.
  • Capture a backup before an authorized change.
  • Document the reason and approval for each change.
  • Verify the exact controller model and software version.
  • Use manufacturer and machine-builder documentation to interpret parameters.
  • Validate the machine after changes according to the approved procedure.

Do not copy a parameter value from another CNC machine merely because the controller model looks similar. Machine-builder integration, axis hardware, feedback configuration, and software revisions can make apparently identical machines different.

12. CNC and PLC Interaction

CNC and PLC functions work together to coordinate machining and auxiliary operations.

Examples include:

  • Tool change requests and completion.
  • Spindle enable and status.
  • Coolant commands and feedback.
  • Clamping and unclamping.
  • Pallet exchange.
  • Guard and door interlocks.
  • Lubrication and pressure monitoring.
  • Automatic cycle start and completion.
  • Alarm reporting and recovery states.

A CNC program may request an operation, but the machine logic must confirm the required conditions before completing it.

12.1 CNC-to-PLC interface register

Interface item Information to document

PLC condition Logic or interlock required
Feedback Signal confirming the operation's state
Timeout Configured timeout and behavior
Alarm Associated diagnostic message
Recovery Approved sequence for recovering the operation

Do not assume that a normal PLC status bit is a safety-rated signal. Safety functions must be documented and verified according to the machine's safety design.

13. CNC Fault Diagnosis

CNC alarms can originate from the controller, servo drives, spindle drive, PLC, feedback devices, lubrication system, pneumatic or hydraulic equipment, or the machining process.

The displayed alarm may identify the affected subsystem without identifying the ultimate root cause.

Symptom Initial investigation
Axis fails to reference Reference switch, encoder, axis configuration, travel conditions
Axis following error Load, drive state, feedback, motion profile, mechanical condition
Position differs from expected Work offset, tool offset, reference state, coordinate mode, setup
Toolpath unexpectedly shifts Active coordinate system, local shifts, program revision, tool compensation
Spindle fails to start Spindle drive, command conditions, interlocks, fault history
Tool change fails Tool changer sequence, position confirmation, PLC logic, mechanical condition
CNC communication alarm Network, device configuration, cable condition, controller state
Program stops unexpectedly Alarm history, modal state, program flow, PLC interlock, operator input
Poor dimensional accuracy Tool condition, offsets, backlash, thermal effects, workholding, measurement method
Repeated alarm after reset Underlying fault, unstable signal, mechanical obstruction, incorrect configuration

13.1 Diagnostic evidence

Capture the following before clearing alarms whenever safe and practical:

  • Exact alarm text and code.
  • Date and time.
  • Machine operating mode.
  • Active program and revision.
  • Current program block or sequence step.
  • Active tool and tool offsets.
  • Active work coordinate system.
  • Machine and workpiece coordinates.
  • Servo and spindle drive status.
  • Relevant PLC interlock or sequence state.
  • Recent maintenance or configuration changes.
  • Corrective action and validation result.

Avoid repeated resets without diagnosis. They can erase useful evidence and may allow a recurring fault to return during production.

14. CNC Backup and Disaster Recovery

A complete CNC recovery plan may require more than the part programs.

Potentially required data includes:

  • CNC system and machine parameters.
  • Axis and spindle configuration.
  • PLC program and data.
  • Tool-management data.
  • Work offsets.
  • Tool offsets and wear values.
  • Compensation tables.
  • Kinematic configuration.
  • Part programs and subprograms.
  • Macros and custom cycles.
  • Machine-builder settings.
  • Network and communication configuration.
  • HMI settings and messages.
  • Applicable software, licenses, and version information.

The exact backup scope depends on the CNC architecture and machine-builder requirements.

14.2 Recovery after storage or controller failure

A controlled recovery process should:

  1. Identify the failed component and preserve available diagnostic evidence.
  2. Confirm the approved backup and its compatibility with the installed hardware.
  3. Restore the system according to the machine builder's procedure.
  4. Verify controller, PLC, drive, and network communication.
  5. Verify axis configuration and feedback.
  6. Confirm machine reference and coordinate behavior.
  7. Restore or validate work offsets, tool data, and compensation data.
  8. Verify safety functions and machine interlocks.
  9. Perform the prescribed commissioning and test procedure.
  10. Record the restored configuration and release approval.

Restoring files does not automatically prove that the machine is safe, geometrically accurate, or ready for production.

15. Offset-Related Failure Examples

Case 1: All parts are consistently machined at the wrong location

Possible causes: Incorrect work offset, incorrect fixture datum, wrong active work coordinate, or setup mismatch.

Investigation: Compare the approved setup sheet, active work offset, program coordinate selection, fixture position, and measured part location.

Corrective approach: Identify the incorrect datum or configuration and restore the approved setup. Validate the result using the established inspection method.

Case 2: Only one tool produces incorrect dimensions

Possible causes: Incorrect tool geometry, tool wear compensation, tool identification, tool measurement, or tool installation.

Investigation: Verify the selected tool, corresponding offset record, measured tool dimensions, and actual cutting condition.

Corrective approach: Correct the verified tool-data problem and perform the required dimensional verification.

Case 3: Position changes after encoder or battery-related intervention

Possible causes: Lost reference, invalid absolute-position data, changed configuration, or an altered mechanical relationship.

Investigation: Follow the controller's recovery diagnostics. Verify reference validity, encoder state, coordinate configuration, and any movement that occurred during maintenance.

Corrective approach: Restore the approved reference and configuration using the machine-specific procedure. Do not compensate for an unknown reference error by arbitrarily changing work offsets.

Case 4: A program worked previously but now moves unexpectedly

Possible causes: Different program revision, changed modal state, different work offset, changed tool data, or a machine configuration change.

Investigation: Preserve the current program and compare it with the approved revision. Verify the active setup and machine state.

Corrective approach: Identify the change that explains the behavior and validate the approved correction before returning to production.

18. CNC Knowledge Check and Interview Questions

1. What is the difference between machine coordinates and workpiece coordinates?

Machine coordinates refer to the machine's established coordinate reference. Workpiece coordinates establish the datum used by the part program.

2. What is the purpose of a work offset?

It defines the relationship between the programmed workpiece datum and the machine coordinate system.

3. What is the difference between tool geometry and tool wear compensation?

Geometry records the tool's defined or measured dimensions. Wear compensation applies a controlled correction to account for dimensional deviation or tool wear.

4. Why can a correct program still machine a part incorrectly?

The active work offset, tool data, fixture setup, coordinate state, machine geometry, or tool condition may be incorrect.

5. Why should CNC parameters not be copied blindly between machines?

Machines can differ in axis hardware, feedback configuration, kinematics, builder integration, and software versions.

6. Why is program revision control important?

It establishes which program is approved, preserves the known-good version, and supports diagnosis of faults introduced by a change.

7. What should be checked after controller restoration?

Verify configuration, communication, axis and feedback behavior, reference state, offsets, programs, safety functions, and the prescribed commissioning results.

8. Why is a CNC alarm not necessarily the root cause?

The alarm may report the detected failure condition while the underlying cause lies in another subsystem, such as a mechanical obstruction, feedback problem, or PLC interlock.

9. What is the danger of changing a work offset to correct an unexplained position error?

It may conceal a lost reference, configuration error, or mechanical fault and create an unsafe or incorrect coordinate relationship.

10. What makes a CNC knowledge base useful during a breakdown?

Accurate equipment identification, approved backups, clear configuration records, fault history, controlled recovery procedures, and verified acceptance criteria.

19. Final CNC Documentation Checklist

  • CNC manufacturer, model, software, and firmware are recorded.
  • PLC and machine-control architecture are documented.
  • Axis and spindle configurations are identified.
  • Axis directions, reference methods, and approved travel limits are documented.
  • Machine, workpiece, and local coordinate systems are distinguished.
  • Work offsets and their approved setup references are recorded.
  • Tool geometry and wear compensation are documented.
  • CNC programs have controlled revisions and approvals.
  • CNC parameters and machine-builder settings have approved backups.
  • PLC interfaces, interlocks, and recovery sequences are documented.
  • Fault evidence and corrective actions are retained.
  • Recovery procedures include configuration and safety verification.
  • Backup restoration readiness is periodically verified.
  • Obsolete components and migration risks are documented.
  • As-built documentation is updated after approved changes.
