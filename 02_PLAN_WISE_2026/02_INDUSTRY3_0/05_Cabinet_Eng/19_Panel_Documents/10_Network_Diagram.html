1. Purpose of an Industrial Network Diagram

An industrial network diagram is an engineering document that represents how automation devices communicate, how they are physically connected, how network traffic is organized, and how the network interfaces with other control systems or plant networks.

It provides a structured view of the communication infrastructure connecting PLCs, HMIs, SCADA systems, remote I/O, VFDs, robots, CNC controllers, engineering workstations, servers, switches, routers, and firewalls.

A network diagram is used during:

  • Electrical and automation system design.
  • Panel manufacturing and network component installation.
  • PLC, HMI, drive, robot, and CNC commissioning.
  • Fault diagnosis and breakdown recovery.
  • Network expansion and machine retrofits.
  • OT cybersecurity assessments.
  • Equipment migration, replacement, and obsolescence management.
  • Maintenance handover and future troubleshooting.

The key purpose is to answer five questions:

  1. Which devices communicate with one another?
  2. Through which physical connections and network devices?
  3. Which IP addresses, protocols, and network segments are used?
  4. What happens if a cable, switch, or network path fails?
  5. How can the system be diagnosed or modified without creating an avoidable production stoppage?

A drawing showing only Ethernet cables is insufficient for a complex automation system. A useful diagram also documents addressing, network segmentation, device interfaces, communication protocols, redundancy, and the boundary between operational technology (OT) and information technology (IT).

2. Network Diagram Versus Other Engineering Documents

Network diagrams complement electrical schematics, panel layouts, cable schedules, and PLC documentation. They do not replace them.

Document Primary purpose Example information
Network diagram Shows communication architecture and connections PLC connected to switch SW01 on port 5
Electrical schematic Shows electrical circuits and control logic wiring PLC output energizes a relay coil
Panel layout Shows physical component placement PLC mounted on DIN rail beside switch
Cable schedule Identifies individual cables and their routing Cable C-NET-014 from SW01 to PLC01
IP address list Records network addressing PLC01 = 10.20.10.11
PLC I/O list Documents controller input and output assignments Input I0.0 = clamp sensor
Control architecture diagram Shows the overall automation system hierarchy PLC, HMI, SCADA, MES, and historian relationships
Firewall rule matrix Documents permitted traffic across security boundaries SCADA server to PLC subnet on approved ports

A complete project normally contains several of these documents because each answers a different engineering question.

3. Types of Network Diagrams

3.1 Physical network diagram

Shows the actual devices, interfaces, switches, cables, and physical connections.

It should identify:

  • Device tag and equipment name.
  • Switch name and port number.
  • Cable identifier.
  • Copper, fiber-optic, or serial media.
  • Connector or interface type where relevant.
  • Link speed when specified.
  • Redundant connections and physical routes.
  • Panel, machine, cabinet, or installation location.

Example:

PLC01 Ethernet Port 1
        |
        | Cable C-NET-001
        |
SW01 Port 1
        |
        | Cable C-NET-002
        |
HMI01 Ethernet Port 1

This shows physical connectivity, but it does not by itself define IP addressing or permitted communication.

3.2 Logical network diagram

Shows logical communication relationships and network organization, which may differ from the physical cable arrangement.

It can represent:

  • IP subnets.
  • VLANs.
  • Routing boundaries.
  • Communication protocols.
  • Firewall zones.
  • Logical links between PLCs, SCADA, servers, and engineering stations.
  • Connections between machines and plant systems.

A physical switch may carry several VLANs, so a single physical network device can support multiple logical networks.

3.3 Layer 2 and Layer 3 diagrams

Layer 2 diagram: Focuses on Ethernet switching, MAC addresses, VLANs, switch ports, and local network connectivity.

Layer 3 diagram: Focuses on IP subnets, routers, routing interfaces, gateways, and communication between different IP networks.

A PLC and HMI on the same subnet may communicate through Layer 2 switching. If they are on different subnets, routing is normally required, subject to the network design and any security controls.

3.4 Control network architecture diagram

Shows the relationship between automation layers and systems.

Enterprise / Business IT
          |
     IT Firewall
          |
   OT Security Boundary
          |
   SCADA / Historian
          |
    OT Core Switch
          |
   Machine Network Switch
          |
   +------+-------+--------+
   |              |        |
  PLC01          HMI01    Robot01
   |
 Remote I/O / Drives

This is a conceptual example, not a universal plant architecture. Actual designs may separate machine control, supervisory systems, safety systems, and business interfaces into distinct network zones.

3.5 Redundancy and failover diagram

Documents alternate communication paths, ring networks, redundant switches, or dual network interfaces.

It must make clear whether redundancy exists at the:

  • Physical cable level.
  • Ethernet switching level.
  • Network protocol level.
  • Controller or device level.
  • Application or server level.

Two cables do not automatically create a functioning redundant network. The switches, protocols, device interfaces, and configuration must all support the intended failover behavior.

Industrial switch Connects Ethernet devices Switch tag, port numbers, VLANs
Router Connects IP networks Interface IPs, routes, gateway

Robot controller Controls robot motion and communicates with PLC IP, interface, protocol

A gateway and a switch are not interchangeable. A switch forwards network traffic within supported network arrangements; a protocol gateway translates or maps data between protocols or interfaces.

5. Industrial Communication Protocols

A protocol defines how devices exchange and interpret data. It is different from the physical medium used to carry that data.

Protocol or technology Typical application Engineering consideration
EtherNet/IP PLCs, remote I/O, drives, robots CIP communication, multicast behavior, device compatibility
PROFINET PLCs, distributed I/O, drives Real-time communication classes and topology support
Modbus TCP PLCs, meters, gateways, SCADA Register mapping, function codes, data representation
EtherCAT Motion control and distributed devices Master/slave architecture and timing requirements
OPC UA Structured data exchange between industrial systems Endpoint security, certificates, namespaces
MQTT Telemetry and publish/subscribe data exchange Broker, topic structure, authentication
PROFIBUS Legacy and existing fieldbus installations Bus wiring, termination, node addressing
DeviceNet Legacy device-level communication CAN-based network, power and data wiring
CC-Link Industrial control and device communication Network generation and product compatibility
IO-Link Sensors and actuators through IO-Link masters Point-to-point device connection and master interface
Modbus RTU Serial device communication RS-485 wiring, addressing, baud rate, parity
Serial ASCII / vendor protocols Legacy instruments and controllers Protocol specification and serial settings

Protocol selection must consider device compatibility, timing, determinism, supported topology, diagnostics, safety requirements, and the existing installed base.

Important distinctions:

  • Ethernet is a family of physical and data-link technologies, not a single industrial application protocol.
  • TCP/IP is a communication suite, not a substitute for an application protocol such as Modbus TCP.
  • OPC UA and MQTT serve different communication models and are not direct replacements for every real-time PLC fieldbus.
  • A device with an Ethernet port does not necessarily support every industrial Ethernet protocol.
  • A protocol gateway only translates the functions and data types supported by its hardware, firmware, and configuration.

6. Network Topologies

Topology describes how devices and communication links are arranged.

6.1 Star topology

Each device connects to a central switch.

             PLC01
               |
               |
HMI01 ------ SW01 ------ ROBOT01
               |
               |
             SCADA01

Advantages:

  • Straightforward troubleshooting.
  • Failure of one endpoint cable usually affects only that endpoint.
  • Easy to add supported devices and monitor switch ports.

Limitations:

  • Failure of the central switch may disconnect every device depending on it.
  • The switch must be sized for port count, performance, environment, and redundancy requirements.

Typical application: machine control panels and local automation networks.

6.2 Line or daisy-chain topology

Devices are connected sequentially, often using built-in switch ports.

SW01 ---- PLC01 ---- HMI01 ---- DRIVE01 ---- DRIVE02

Advantages:

  • Can reduce cable length and switch count.
  • Useful where devices support integrated Ethernet switching.

Limitations:

  • A failed device or intermediate link may isolate downstream devices.
  • Not all devices support forwarding or line topology.
  • Ring recovery must not be assumed unless a supported ring architecture is actually configured.

6.3 Ring topology

Devices or switches are connected in a closed loop using a supported ring mechanism.

        SW01 -------- SW02
         |              |
         |              |
        SW04 -------- SW03

Advantages:

  • Can provide an alternate path after a supported link failure.
  • May improve availability in distributed installations.

Limitations:

  • Requires compatible ring-management features and correct configuration.
  • Recovery time depends on the technology and implementation.
  • Misconfiguration can create network interruptions or loops.

Industrial examples include vendor-specific device-level rings and media-redundancy protocols. Device-level rings, PROFINET media redundancy, and spanning-tree mechanisms are not automatically interchangeable.

6.4 Tree topology

A hierarchy of switches connects machine networks to distribution or core switches.

             CORE-SW01
             /       \
       DIST-SW01    DIST-SW02
        /     \       /    \
      PLC01  HMI01  PLC02  ROBOT02

Advantages:

  • Supports structured expansion.
  • Helps separate machines, production areas, and network zones.
  • Makes network ownership and boundaries easier to document.

Limitations:

  • Failure of an upstream switch can affect an entire branch.
  • Poorly designed uplinks can create bottlenecks or single points of failure.

6.5 Dual-homing and redundant paths

A device may have two independent network interfaces or connections to separate switches. The intended behavior must be documented.

Before drawing dual connections, confirm whether the device supports:

  • Two independent interfaces.
  • A vendor-specific redundant network.
  • Link aggregation.
  • A supported ring or redundancy protocol.
  • Active/standby communication paths.

Connecting two ordinary Ethernet ports into a loop without an appropriate design can disrupt the network.

7. IP Addressing and Subnetting

Each IP-connected device requires a valid network configuration appropriate to its network design.

Typical IPv4 settings include:

  • IP address.
  • Subnet mask or prefix length.
  • Default gateway, where routing is required.
  • DNS server, where name resolution is required.
  • Device hostname.
  • VLAN or network zone.

Example:

Device IP address Subnet mask Gateway
PLC01 10.20.10.11 255.255.255.0 10.20.10.1
HMI01 10.20.10.12 255.255.255.0 10.20.10.1
ROBOT01 10.20.10.21 255.255.255.0 10.20.10.1
SCADA01 10.20.20.10 255.255.255.0 10.20.20.1

These are illustrative private addresses, not a recommendation to copy them into a production network. The actual addressing plan must be approved for the site.

The first three devices in the example belong to 10.20.10.0/24; SCADA belongs to 10.20.20.0/24. Communication between these subnets requires an appropriate Layer 3 path and any required security rules.

7.1 Subnet mask

The subnet mask identifies the network portion and host portion of an IPv4 address.

For a /24 network, the subnet mask is 255.255.255.0. In a conventional IPv4 subnet, the first 24 bits identify the network prefix.

Do not assign IP addresses based only on the device's machine number. Confirm the subnet, address reservation, gateway, VLAN, and site addressing standard.

7.2 Default gateway

The default gateway is the next-hop router used to reach destinations outside the local IP subnet when no more specific route applies.

Devices communicating only within the same subnet may not need a default gateway for that local communication. However, remote access, SCADA connections, time services, or other routed services may require one.

7.3 Static addressing versus DHCP

Static addressing is commonly used for PLCs, HMIs, drives, robots, switches, and other infrastructure devices where predictable addressing is important.

DHCP automatically assigns IP configuration. It may be appropriate for selected clients and supported infrastructure, but its use in control systems must be deliberately designed.

A DHCP reservation can provide predictable addressing based on a device identifier, but the behavior depends on the DHCP server, network design, and client support.

7.4 Duplicate IP addresses

A duplicate IP address occurs when two devices claim the same address on a network where the addresses are expected to be unique.

Symptoms can include:

  • Intermittent PLC-to-HMI communication.
  • Connections reaching the wrong device.
  • ARP table changes.
  • Unstable diagnostics and unpredictable access.

A duplicate IP must be resolved by identifying both devices and correcting the address plan. Randomly changing a running PLC's address may create a larger production problem.

8. MAC Addresses, Switch Ports, and VLANs

8.1 MAC address

A MAC address identifies a network interface at the Ethernet data-link layer. Switches use learned MAC addresses to forward frames within a Layer 2 network.

The MAC address is not the same as the IP address. A device may have several network interfaces, each with its own MAC address.

Record MAC addresses when useful for:

  • Device identification.
  • Switch troubleshooting.
  • DHCP reservations.
  • Network access control.
  • Asset inventory.

8.2 Switch port documentation

Each network link should identify the source and destination interface.

Example:

Switch Port Connected device VLAN Link
SW01 1 PLC01 Port 1 110 1 Gbps copper
SW01 2 HMI01 Port 1 110 1 Gbps copper
SW01 3 ROBOT01 Port 1 110 1 Gbps copper
SW01 24 OT-DIST01 Port 1 100, 110 Fiber uplink

The VLAN example assumes a trunk or tagged uplink that carries both VLANs. Actual port modes and VLAN membership must be confirmed against the switch configuration.

8.3 VLAN

A VLAN logically separates Layer 2 traffic on supporting switches.

Potential uses include separating:

  • Machine control devices.
  • Supervisory systems.
  • Engineering workstations.
  • Robot or CNC networks.
  • Infrastructure management interfaces.

VLANs can improve traffic organization and reduce broadcast scope, but a VLAN is not, by itself, a complete cybersecurity boundary. Communication between VLANs is controlled by routing and, where required, firewall or access-control policies.

8.4 Access and trunk ports

An access port typically carries traffic for one assigned VLAN without requiring the connected endpoint to tag frames.

A trunk port can carry multiple VLANs using VLAN tagging, subject to the supported configuration.

Incorrect VLAN assignment can prevent communication even when the cable, IP address, and device appear correct.

9. Physical Media and Cabling

9.1 Copper Ethernet

Common in-panel and machine-level Ethernet uses twisted-pair copper cabling.

Document:

  • Cable ID.
  • Cable category or industrial cable specification.
  • Connector type.
  • Endpoints and ports.
  • Cable length where required.
  • Shielding and bonding arrangement.
  • Installation environment.

Conventional Ethernet copper channels are generally limited to 100 m under the applicable channel specification, but the actual limit depends on Ethernet type, cabling category, channel construction, and equipment requirements. Industrial designs must follow the relevant standard and manufacturer specifications.

9.2 Fiber-optic Ethernet

Fiber is useful for longer distances, electrical isolation, and environments where electromagnetic interference is a concern.

Specify:

  • Single-mode or multimode fiber.
  • Fiber type and supported wavelength.
  • Connector type.
  • Transceiver type at each endpoint.
  • Number of cores and spare cores.
  • Route and termination location.
  • Link speed and optical budget requirements.

Do not assume two fiber transceivers are compatible merely because both connectors physically fit.

9.3 Serial communication

Legacy instruments, meters, CNC interfaces, and controllers may use RS-232 or RS-485.

Document:

  • Protocol.
  • Baud rate.
  • Data bits.
  • Parity.
  • Stop bits.
  • Node address.
  • Cable and connector details.
  • RS-485 termination and biasing requirements where applicable.

A serial network may require a separate drawing from the Ethernet network, especially when the wiring topology and termination are important.

9.4 Shielding and cable routing

For industrial network cabling:

  • Separate network cables from high-noise power and motor cables according to applicable standards and manufacturer instructions.
  • Use suitable industrial cable and connectors for oil, vibration, temperature, and mechanical exposure.
  • Maintain the intended shielding and bonding arrangement.
  • Avoid improvised shield termination and uncontrolled grounding changes.
  • Observe bend radius and tensile limits.
  • Label both ends of every serviceable cable.
  • Keep network routing clear of moving machinery and pinch points.

Shielding does not compensate for poor cable selection, bad termination, or incorrect routing.

10. Managed and Unmanaged Switches

An unmanaged switch provides basic Ethernet switching with little or no configuration.

A managed switch may support:

  • VLAN configuration.
  • Port status and error counters.
  • Network diagnostics.
  • Port mirroring.
  • Access control features.
  • Redundancy protocols.
  • Quality of Service (QoS).
  • Multicast management.
  • SNMP monitoring and event logging.

For complex industrial networks, managed switches can significantly improve diagnostics and maintainability.

10.1 IGMP snooping

Some industrial protocols use IP multicast. IGMP snooping allows a supporting switch to learn which ports need particular multicast traffic.

Incorrect multicast handling may cause unnecessary traffic or interfere with device communication. The appropriate configuration depends on the protocol, switch capabilities, and device requirements.

10.2 QoS

Quality of Service can prioritize selected traffic classes. It does not magically make an overloaded or incorrectly designed network deterministic.

Priority markings, queues, and end-to-end behavior must be compatible with the actual network architecture.

10.3 Redundancy mechanisms

Examples include:

  • Rapid Spanning Tree Protocol (RSTP).
  • Media Redundancy Protocol (MRP).
  • Device-level ring mechanisms.
  • Vendor-specific controller or device redundancy features.
  • Link aggregation where explicitly supported.

These mechanisms have different operating principles and compatibility requirements. Do not combine them casually or assume every industrial switch supports every mechanism.

Consider an automation cell with a PLC, HMI, robot controller, VFDs, SCADA, and an engineering workstation.

                        |
                 OT Firewall / Router
                        |
                  OT-DIST-SW01
                        |
                  Fiber Uplink
                        |
                     SW01
              _________|__________
             |         |          |
           PLC01     HMI01     ROBOT01
             |
          DRIVE01
             |
          DRIVE02

This is a simplified architecture. The actual connections of the drives depend on whether they use Ethernet, a dedicated fieldbus, integrated daisy-chain ports, or another supported interface.

12. How to Create a Network Diagram

Step 1: Collect source information

Gather:

  • Existing network diagrams.
  • PLC and HMI hardware configurations.
  • Robot and CNC communication settings.
  • Switch configuration backups.
  • IP address registers.
  • Cable schedules.
  • Vendor manuals.
  • Firewall and router configuration records.
  • Existing OT architecture and cybersecurity requirements.

Do not assume the existing drawing reflects the current installed system. Compare it with the actual equipment and configuration.

Step 2: Identify all network-connected assets

Create an asset list covering controllers, HMIs, drives, robots, CNCs, switches, routers, firewalls, servers, gateways, wireless equipment, and engineering stations.

Record devices with multiple network ports separately at the interface level.

Step 3: Identify the communication interfaces

For each device, determine:

  • Ethernet or serial interface.
  • Interface count.
  • IP or node address.
  • Protocol support.
  • Required communication partners.
  • Supported network topology.
  • Redundancy capability.
  • Whether the interface is dedicated to control, management, safety, or another purpose.

Step 4: Establish physical topology

Trace each cable from its actual source to its destination.

For example:

PLC01 Port 1 -> C-NET-001 -> SW01 Port 1

Confirm whether intermediate switches, couplers, media converters, or patch panels exist.

Step 5: Establish logical topology

Document:

  • Subnets and prefix lengths.
  • VLAN membership.
  • Routing interfaces.
  • Default gateways.
  • Protocols and communication relationships.
  • Firewall boundaries.
  • Remote access paths.

Step 6: Identify failure points

Determine which devices or connections are single points of failure.

Ask:

  • Does one switch support the entire cell?
  • Does one uplink disconnect the machine from SCADA?
  • Is the ring actually configured and tested?
  • Does the controller support the intended alternate path?
  • Will a firewall or router failure isolate a required service?

Record the actual design rather than drawing an idealized redundant system that does not exist.

Step 7: Verify the diagram against the installed system

Use approved methods such as switch diagnostics, device configuration tools, port status, cable testing, and controlled communication tests.

Avoid making live network changes simply to test a theory.

Step 8: Release the controlled document

Include drawing number, revision, date, prepared-by and approved-by fields, equipment scope, applicable standards, and related document references.

Store the editable source and approved PDF according to the plant's document-control procedure.

13. Required Information on a Professional Network Diagram

A good drawing should contain enough information to support maintenance without becoming an unreadable inventory dump.

13.1 Minimum identification

  • Drawing title and number.
  • Machine or production-line name.
  • Revision and date.
  • Device tags.
  • Device type and role.
  • Physical connections.
  • Switch and port numbers.
  • Cable identifiers.
  • IP addresses or node addresses.
  • Network boundaries.

13.2 Additional information for complex networks

  • Subnet masks or CIDR prefixes.
  • VLAN IDs and names.
  • Protocols.
  • Link speed and media.
  • Fiber type and transceivers.
  • Redundant links and failover mechanism.
  • Router and firewall interfaces.
  • Relevant communication flows.
  • Network management addresses.
  • References to the IP register and cable schedule.

13.3 Example cable register

Cable ID Source Destination Media Notes
C-NET-001 PLC01 Port 1 SW01 Port 1 Industrial copper Ethernet Machine control

14. Network Diagram Symbols and Naming Conventions

There is no single universal symbol set that covers every industrial network drawing. Follow the project's approved CAD library, company drafting standard, and applicable documentation standards.

Use consistent representations for:

  • PLCs and controllers.
  • Industrial switches.
  • Routers and firewalls.
  • Servers and workstations.
  • Copper Ethernet links.
  • Fiber-optic links.
  • Serial links.
  • Wireless connections.
  • Redundant links.
  • Network zones and VLAN boundaries.

Prefer clear device tags such as:

  • PLC01 for the main PLC.
  • HMI01 for an operator panel.
  • SW01 for a network switch.
  • FW01 for a firewall.
  • SCADA01 for a SCADA server.
  • GW01 for a protocol gateway.
  • ROBOT01 for a robot controller.

Naming conventions should remain consistent across network diagrams, electrical schematics, asset registers, cable schedules, and maintenance systems.

Avoid vague labels such as PLC, SWITCH, or ETHERNET CABLE when multiple devices exist.

15. OT Network Segmentation and Cybersecurity

Industrial networks require both availability and controlled access. A network that communicates successfully but allows uncontrolled access is not a well-designed network.

15.1 Segmentation

Separate systems according to operational function and risk, where appropriate.

Possible zones include:

  • Machine control.
  • Supervisory control.
  • Engineering and maintenance.
  • OT infrastructure management.
  • Industrial DMZ.
  • Enterprise IT.

The actual number of zones depends on the plant's risk assessment and architecture.

15.2 Firewalls and communication rules

Document approved communication paths between zones.

A firewall rule matrix can include:

Source Destination Service Purpose
SCADA01 PLC subnet Approved control protocol Supervisory data exchange
ENG-WS01 Authorized PLC Approved programming service Engineering access
OT historian SCADA data source Approved data interface Data collection
Remote access gateway Approved maintenance host Controlled remote session Vendor support

The services shown are conceptual. The actual ports and protocols must be determined from the specific products, configuration, and security requirements.

Apply least privilege: permit only the communication needed for the defined operational purpose.

15.3 Practical controls

  • Maintain an accurate OT asset inventory.
  • Restrict unauthorized connections to control networks.
  • Disable unused switch ports where operationally appropriate.
  • Use approved remote-access paths with authentication and logging.
  • Maintain configuration backups for PLCs, switches, firewalls, and other supported devices.
  • Control changes to IP addresses, VLANs, routing, and firewall rules.
  • Monitor unexpected devices and network changes.
  • Avoid direct, uncontrolled connections between office networks and machine networks.

A network diagram supports cybersecurity, but it does not replace firewall policies, access-control procedures, risk assessments, or configuration management.

16. Commissioning and Validation Checklist

  • Verify device tags against the installed equipment.
  • Confirm all physical connections and switch port assignments.
  • Confirm cable labels at both ends.
  • Verify IP addresses, subnet masks, and gateways.
  • Check for duplicate IP addresses.
  • Confirm VLAN membership and access/trunk configuration.
  • Verify routing and firewall rules where required.
  • Confirm that the selected protocols are supported by both endpoints.
  • Check switch link status, speed, duplex, and error counters.
  • Confirm that multicast handling and redundancy settings match the design.
  • Test required device communication using approved procedures.
  • Test redundancy and failover where designed.
  • Confirm SCADA and engineering access through approved paths.
  • Save configuration backups and diagnostic evidence.
  • Update the as-built diagram and IP register.
  • Obtain required review and approval.

Use ping only where ICMP is permitted and appropriate. A failed ping does not prove that an industrial protocol is unavailable, and a successful ping does not prove that the application protocol works.

17. Network Troubleshooting Method

Troubleshoot systematically from the physical layer toward the application layer. Randomly rebooting devices and changing addresses is a popular human tradition, but it is not a diagnostic method.

17.2 Common faults

Symptom Possible cause Diagnostic action
No link LED Cable fault, disconnected port, failed interface Inspect cable, connector, and port status
Intermittent connection Loose connector, damaged cable, electrical interference Inspect physical installation and switch errors
PLC unreachable Wrong IP, duplicate IP, wrong subnet, disconnected link Verify addressing and physical connectivity
HMI cannot reach PLC Incorrect target address, protocol settings, routing issue Check HMI configuration and network path
Communication fails across VLANs Missing route, wrong gateway, ACL or firewall block Trace the routed path and inspect rules
Some devices work, others fail VLAN mismatch, port fault, device-specific configuration Compare affected and working devices
Excessive network traffic Loop, multicast flooding, broadcast storm, misconfiguration Review switch counters and topology
Ring fault alarm Broken link, failed device, incompatible configuration Inspect ring diagnostics and recovery status
Intermittent SCADA values Application timeout, packet loss, server load, polling issue Correlate network counters and application logs
Communication after replacement fails Wrong firmware, IP, protocol, or device configuration Compare replacement settings with approved records

17.3 Layer-based troubleshooting

Physical layer: Verify power, cables, connectors, media compatibility, link LEDs, and physical damage.

Data-link layer: Check switch port status, MAC learning, VLAN membership, loops, and Ethernet errors.

Network layer: Check IP addressing, subnet masks, gateways, routing, and duplicate addresses.

Transport and application layers: Check the expected ports, connection states, protocol configuration, device compatibility, application diagnostics, and firewall rules.

A fault can involve more than one layer. Preserve diagnostic evidence before changing the configuration.

18. Network Changes and Retrofit Management

When adding or replacing a PLC, robot, CNC, HMI, switch, or other network device, follow a controlled change process.

  1. Review the existing approved network diagram and IP register.
  2. Confirm the replacement's interfaces, supported protocols, and addressing requirements.
  3. Reserve a unique IP address and verify subnet and VLAN allocation.
  4. Check switch capacity, port availability, power, media compatibility, and topology restrictions.
  5. Confirm firewall and routing changes, if any, through the approved process.
  6. Back up the existing configuration before making changes.
  7. Schedule the change according to production and safety requirements.
  8. Verify communications, alarms, diagnostics, and required control functions.
  9. Test redundancy or recovery behavior where applicable.
  10. Update drawings, cable schedules, asset records, configuration backups, and maintenance instructions.

Replacing an old device with a new one does not guarantee that the new device uses the same protocols, timing, addressing behavior, or redundancy features. Confirm compatibility before installation.

19. Revision Control and Handover

The network diagram must reflect the installed system, not merely the original design.

A useful revision record includes:

Revision Change Reason
A Initial issue New machine installation
B Added robot controller connection Automation expansion
C Updated switch ports and IP register Hardware replacement
D Added OT segmentation boundary Approved network redesign

For maintenance handover, keep the following together:

  • Approved network diagram.
  • Current IP address and device register.
  • Switch, router, and firewall configuration backups, subject to access controls.
  • Cable schedule and physical port labels.
  • Relevant PLC, HMI, robot, and CNC communication settings.
  • Troubleshooting instructions.
  • Change history and approval records.
  • Recovery procedures for critical network components.

Store sensitive network configuration and credentials according to the site's security and document-access policies. A drawing should identify the required information without unnecessarily exposing passwords or other secrets.

20. Common Engineering Mistakes

  • Drawing only devices and cables without port numbers.
  • Reusing IP addresses without checking the existing address register.
  • Confusing MAC addresses with IP addresses.
  • Treating VLANs as complete security controls.
  • Assuming two cables provide redundancy.
  • Connecting ring networks without a supported redundancy design.
  • Omitting fiber type or transceiver details.
  • Failing to identify unmanaged switches and hidden intermediate devices.
  • Ignoring the difference between physical and logical diagrams.
  • Using a protocol label without confirming the actual device configuration.
  • Allowing undocumented laptop, wireless, or vendor connections.
  • Updating the PLC configuration but not the network drawing.
  • Keeping only a PDF while losing the editable source.
  • Treating a successful ping as proof that all application communications are healthy.

22. Interview Questions and Answers

1. What is the purpose of an industrial network diagram?

It documents physical and logical communication relationships, device interfaces, network addressing, protocols, segmentation, and redundancy so engineers can design, commission, maintain, and troubleshoot the system.

2. What is the difference between a physical and a logical network diagram?

A physical diagram shows actual devices, cables, ports, and media. A logical diagram shows network organization, addressing, VLANs, routing, communication relationships, and security boundaries.

3. What is the difference between a switch and a router?

A switch forwards frames within supported Layer 2 networks using MAC-address information. A router forwards packets between IP networks using routing information.

4. Why can two devices with valid IP addresses still fail to communicate?

Possible causes include incorrect subnet masks, VLAN mismatch, missing routes, firewall restrictions, protocol incompatibility, incorrect application settings, or physical connectivity faults.

5. What is the difference between an IP address and a MAC address?

An IP address provides network-layer addressing. A MAC address identifies an Ethernet interface at the data-link layer.

6. Why are VLANs used in industrial networks?

VLANs logically separate Layer 2 traffic, help control broadcast domains, and support network organization. They do not replace routing controls or security policies.

7. What is the difference between an access port and a trunk port?

An access port normally carries one assigned VLAN for an endpoint. A trunk port carries multiple VLANs using supported tagging, subject to its configuration.

8. Why might a PLC communicate with its HMI but not with SCADA?

The PLC and HMI may share a local subnet while SCADA resides on a different subnet. Missing routes, gateway errors, firewall restrictions, or application configuration may prevent the routed connection.

9. What is the purpose of IGMP snooping?

It helps a capable switch forward IP multicast traffic to interested ports instead of flooding that traffic unnecessarily across all ports in a VLAN.

10. Does a ring topology guarantee uninterrupted communication?

No. Recovery depends on supported redundancy mechanisms, correct configuration, device compatibility, and the nature of the fault.

11. Why is a network diagram important during breakdown maintenance?

It identifies the affected communication path, relevant switch ports, cable IDs, device addresses, and network boundaries, reducing diagnosis time and unnecessary configuration changes.

12. What should be checked before replacing an industrial switch?

Verify port count, managed features, VLAN configuration, supported redundancy mechanisms, speed, fiber or copper interfaces, multicast requirements, environmental rating, configuration backups, and the expected production impact.

13. What is an as-built network diagram?

It is the controlled drawing updated to reflect the actual installed and commissioned network, including approved changes made after the original design.

14. How should an OT network connect to the enterprise network?

Through an approved architecture with defined security boundaries, controlled routing, required firewall rules, and appropriate access management rather than an unrestricted direct connection.

15. What is the first step when a PLC loses network communication?

Confirm the fault and its operational scope, then check device status and physical connectivity before progressing to switch diagnostics, addressing, VLANs, routing, and application-level checks.

23. Final Engineering Standard

A network diagram is useful only when it accurately represents the installed system and contains enough detail to support safe maintenance and controlled modification.

For industrial automation, maintain three connected views:

  • Physical view: Devices, interfaces, cables, ports, and media.
  • Logical view: IP addressing, VLANs, protocols, routing, and communication relationships.
  • Operational view: Redundancy, security boundaries, failure impact, diagnostics, and recovery procedures.

Together with the IP register, cable schedule, configuration backups, and change history, these documents turn an undocumented collection of connected machines into a maintainable industrial network.
