1. Definition and purpose

A component list is an engineering document that identifies the electrical, electronic, automation, safety, networking, and mechanical components used in a machine or control panel. It records each component's identity, technical specification, function, physical location, and references to related engineering documents.

The component list connects the electrical design to the actual hardware installed in the machine.

Its main purposes are:

  • Identify exactly which component is installed or specified.
  • Connect component tags to electrical schematics and panel layouts.
  • Support procurement, maintenance, troubleshooting, and replacement.
  • Verify that the installed component matches the approved design.
  • Track manufacturer part numbers, internal material codes, and lifecycle status.
  • Maintain accurate as-built documentation after modifications.
  • Identify obsolete components and approved replacement alternatives.
  • Provide a reliable foundation for spare-parts management.

A component list should answer five questions quickly:

  1. What is the component?
  2. What is its function?
  3. Which exact model or variant is used?
  4. Where is it installed?
  5. Where can its electrical connections and physical position be found in the drawings?

2. Component list versus related engineering documents

Several documents describe the same machine from different perspectives. They are related, but they are not interchangeable.

Document Primary purpose Typical information
Component list Identify and locate individual components Tag, model, rating, function, location
Bill of Materials (BOM) Define materials required for procurement or assembly Material number, description, quantity
Electrical schematic Explain electrical operation and connections Contacts, coils, wiring, power circuits
Panel layout Show physical component arrangement Mounting position, dimensions, rail location
I/O list Define controller input/output signals PLC address, signal tag, type, description
Terminal plan Identify terminal connections Terminal numbers, wire references, destinations
Cable schedule Track cables between equipment Cable ID, endpoints, cable type
Network topology Describe communication connections IP addresses, switches, ports, protocols
Spare-parts list Identify maintainable replacement inventory Spare code, quantity, criticality, lead time
Device parameter list Record configurable device settings Drive parameters, PLC configuration, IP settings

The distinction is important. A BOM may specify ten terminal blocks of one type, while the component list identifies which terminals or terminal groups perform specific functions. The schematic shows how the electrical circuit works, while the layout shows where the devices physically sit.

A component list can include quantities, but it should not be treated as a substitute for a controlled BOM.

3. Basic component identification structure

A useful component record combines several different identifiers.

Identifier Meaning Example
Component tag Engineering identity of the device QF1
Description Human-readable function Main control-circuit breaker
Manufacturer Original equipment manufacturer Siemens
Manufacturer part number Exact commercial product variant 5SY...
Internal material code Company's ERP or inventory identifier MAT-104582
Location code Physical installation location CP01-PLATE-A
Drawing reference Where the device appears in the design E-012, Grid B4

Firmware version Software version, when relevant Vx.y

These identifiers must not be confused.

For example, QF1 identifies a device within the engineering design. It does not uniquely identify the commercial model or the physical serial-numbered unit.

A component can retain the same engineering tag while its manufacturer part number changes during an approved retrofit. Such a change must be documented and reviewed for technical compatibility.

4. Component tags and reference designations

A component tag is a unique engineering identifier used to reference a device across the drawings and maintenance records.

Common examples include the following. Exact letters and numbering conventions vary with the company's drafting rules and applicable standards.

Tag example Typical component Function
QF1 Circuit breaker Overcurrent protection and isolation where rated
FU1 Fuse Overcurrent protection
KM1 Contactor Switching a power circuit
KA1 Auxiliary relay Logic or interposing switching
PS1 Power supply Converts incoming power to a DC supply
PLC1 PLC Machine control
DI1 Digital input module Receives discrete signals
DO1 Digital output module Sends discrete control signals
AI1 Analog input module Receives analog signals
AO1 Analog output module Sends analog reference signals
HMI1 Operator interface Displays machine status and accepts operator commands
VFD1 Variable-frequency drive Controls an AC motor
SR1 Safety relay Performs defined safety-related control functions
X1 Terminal block or connector group Provides connection points
M1 Motor Converts electrical energy into mechanical motion
S1 Switch or sensor designation Depends on the project's convention
B1 Sensor or transducer designation Depends on the project's convention

Important: These are illustrative conventions, not universal rules. Use the project's approved designation system, drawing legend, and applicable standards. Do not infer the device type from a tag alone when the project uses different conventions.

4.1 Tagging rules

A good tagging system should be:

  • Unique within the defined project or equipment scope.
  • Consistent across schematics, layouts, I/O lists, and maintenance records.
  • Stable enough to preserve historical fault and maintenance references.
  • Structured so that similar components can be distinguished.
  • Independent of the component's physical position when possible.

For example:

  • VFD1 identifies a drive.
  • VFD2 identifies another drive.
  • VFD1 should not be renamed simply because it is moved to another DIN rail.
  • If VFD1 is replaced by another model, its tag may remain the same if its engineering function remains the same and the project rules allow it.

A tag must not be reused for an unrelated component while old maintenance records still depend on that identity.

8. How the component list relates to the BOM

The BOM and component list should share a common source of truth wherever practical.

Consider a panel containing three identical interposing relays.

  • The component list may contain KA1, KA2, and KA3, each linked to its circuit function and drawing reference.
  • The BOM may contain one material line for the relay model with a quantity of three.
  • The schematic shows the function and contacts of each relay.
  • The panel layout shows where the three relays are mounted.

A simplified relationship is:

Component List
    ↓
Component tags and device identity
    ↓
Electrical schematic + panel layout
    ↓
BOM material references
    ↓
Procurement and assembly
    ↓
Physical verification
    ↓
As-built component list and BOM

The component list may have one row per component instance, or one row per component type with separate tag and location details. For maintenance-heavy industrial systems, one record per individually tagged device is generally easier to trace and audit.

Where a component is represented as a grouped item, the record structure must still preserve the identity and location of each individually maintainable device.

8.1 Quantity rules

Quantities must have a defined meaning.

  • Designed quantity: number specified in the approved engineering design.
  • Installed quantity: number physically installed and verified.
  • BOM quantity: procurement or assembly requirement, potentially including allowances.
  • Spare quantity: number available in inventory.

These values can differ legitimately. A component list should not silently replace designed quantity with stock quantity or BOM quantity.

9. Component list creation workflow

A component list should be generated from controlled engineering information, then verified against the physical installation.

Step 1: Establish the scope

Identify the project, machine, line, cabinets, remote panels, field devices, and document revision being covered.

Define whether the list includes:

  • Cabinet-mounted devices only.
  • All machine-mounted electrical devices.
  • Field sensors, actuators, motors, and junction boxes.
  • Networking and safety equipment.
  • Mechanical accessories and consumables.
  • Installed spares or only operational components.

The scope must be explicit. Otherwise, two engineers can produce different lists for the same machine and both believe they are correct.

Step 2: Review the engineering documents

Collect the latest approved versions of:

  • Electrical schematics.
  • Panel layout drawings.
  • Terminal plans.
  • PLC hardware configuration.
  • I/O list.
  • Network topology.
  • BOM.
  • Device parameter or configuration records.
  • Equipment specifications and manufacturer manuals.

Check that document revisions are consistent before extracting component information.

Step 3: Extract component tags

Read the schematics and identify the components used in power, control, safety, networking, and field circuits.

Record each unique component tag, its description, and the relevant drawing reference.

Do not confuse a contact symbol with a separate physical component. For example, the main contacts and auxiliary contacts of one contactor usually refer to the same physical device unless the design identifies separate hardware.

Step 4: Identify exact component variants

Determine the manufacturer and full ordering code from approved specifications, device labels, purchase records, or manufacturer documentation.

Check variants carefully. Products in the same family can differ in:

  • Rated voltage or current.
  • Number of channels.
  • Connector type.
  • Input/output electrical characteristics.
  • Communication options.
  • Firmware or hardware generation.
  • Safety certification.
  • Mounting dimensions.

A family name is not a substitute for an exact part number.

Step 5: Assign locations

Cross-reference the panel layout, mounting plate, rail position, door layout, machine zone, and remote installation location.

For field-mounted equipment, record the actual equipment or zone identifier and, where appropriate, junction box and cable references.

Step 6: Link engineering references

Add the schematic sheet, grid reference, layout drawing, terminal reference, and associated I/O or network records where relevant.

Use the approved document numbering and revision conventions.

Step 7: Verify technical data

Validate ratings against the design calculations and manufacturer datasheets. Pay particular attention to protection devices, power supplies, drives, safety equipment, and communication modules.

A component list is not an electrical design verification by itself, but it should not contradict the approved design.

Step 8: Perform physical verification

During assembly, commissioning, maintenance, or retrofit, verify the actual installed hardware.

Check:

  • Tag labels.
  • Manufacturer and model labels.
  • Physical location.
  • Electrical ratings.
  • Connection and interface types.
  • Installed accessories.
  • Firmware or hardware revision when relevant.
  • Differences from the approved design.

Mark discrepancies for engineering review rather than quietly modifying the record.

Step 9: Release and maintain the controlled list

Record the document revision, author or responsible function, approval status, verification date, and associated change reference.

Store the released version in the approved document-control location.

10. Component list versus as-built verification

The design component list represents the approved engineering intent. The as-built component list represents the hardware actually installed after approved changes and verification.

Differences can arise from:

  • Approved substitutions.
  • Hardware upgrades.
  • Obsolete component replacements.
  • Cabinet modifications.
  • Additional field devices.
  • Removal of unused hardware.
  • Changes made during breakdown repair.
  • Replacement with a different firmware or hardware revision.

For example, a drive might be replaced with a successor model during maintenance. If the successor requires different communication settings or parameter mappings, updating only the manufacturer part number is insufficient.

The engineering change should address all affected records, including the component list, BOM, drawings, PLC configuration, parameter backups, network records, spare-parts mapping, and maintenance instructions as applicable.

Never convert an undocumented field change into an approved design merely by editing the spreadsheet.

11. Revision control and change management

A controlled component list should preserve a history of changes.

A useful change record includes:

Field Example purpose
Change ID Unique engineering change identifier
Component tag Identifies the affected device
Previous part number Records the original variant
New part number Records the approved replacement
Reason Obsolescence, failure, redesign, or standardization
Technical review Confirms engineering compatibility
Safety review Evaluates safety-related impact where applicable
Affected documents Lists drawings, BOM, I/O records, and configurations
Approval status Tracks authorization
Implementation date Records when the change was applied
Verification result Confirms the installed configuration
Record revision Identifies the released document version

For complex systems, a formal management-of-change process is preferable to an informal spreadsheet edit.

11.1 Revision principles

  • Keep revision numbering consistent with the document-control system.
  • Identify whether a change is proposed, approved, implemented, or verified.
  • Retain prior released versions according to company policy.
  • Record who authorized and implemented the change.
  • Avoid overwriting the only copy of an approved as-built record.
  • Reconcile engineering documents with actual hardware after modifications.

12. Lifecycle and obsolescence management

Industrial components can remain in service for many years, even after their manufacturer stops selling them. A component list can support lifecycle management if it captures sufficient information.

Useful fields include:

  • Current manufacturer part number.
  • Lifecycle status.
  • Last known orderability or verification date.
  • Manufacturer-declared successor.
  • Approved replacement model.
  • Compatibility assessment.
  • Spare stock and consumption history.
  • Procurement lead time.
  • Installed machine or cabinet references.
  • Migration or retrofit priority.

12.1 Replacement assessment

A successor component should be evaluated across several dimensions.

Assessment area Questions to verify
Electrical Are voltage, current, protection, and power requirements compatible?
Mechanical Does it fit the mounting space and required clearances?
Connections Are terminal assignments, connectors, and pinouts compatible?
Control Does the existing control logic support the new device?
Communication Are protocol, addressing, data types, and timing compatible?
Software Are firmware, engineering tools, and project files compatible?
Safety Are safety functions and required certifications maintained?
Environment Are temperature, vibration, ingress protection, and EMC requirements met?
Documentation Are manuals, wiring drawings, and configuration records available?
Availability Is the replacement supported and procurable over the required period?

A manufacturer-designated successor is a starting point, not automatic proof of drop-in compatibility.

13. Component list in Excel or a database

For a small machine, a controlled Excel table may be adequate. For a large plant with multiple lines and thousands of components, a structured database or CMMS/EAM integration can improve traceability.

13.1 Recommended spreadsheet structure

Keep the main table in a proper tabular format with one header row, one record per defined component instance, and no merged cells.

Recommended worksheets include:

  • COMPONENT_MASTER: component identity, model, ratings, and lifecycle status.
  • LOCATION_MASTER: cabinets, machines, zones, and physical locations.
  • MANUFACTURER_MASTER: standardized manufacturer names.
  • MATERIAL_MASTER: internal material codes and ERP descriptions.
  • DOCUMENT_MASTER: drawing numbers, revisions, and controlled document locations.
  • CHANGE_LOG: change history and approvals.
  • LOOKUPS: controlled dropdown values.

For small projects, these can be combined into one table, but separate reference tables become useful as the system grows.

13.2 Data-quality rules

  • Enforce uniqueness for component tags within their defined scope.
  • Validate that manufacturer part numbers are not truncated.
  • Use dropdowns for category, status, and approval state.
  • Store ratings in consistently defined fields and units.
  • Use dates as dates, not free-text descriptions.
  • Avoid multiple unrelated component tags in one cell.
  • Avoid mixing installed quantity and spare quantity.
  • Require a drawing reference for devices covered by controlled drawings.
  • Identify records missing model numbers or location information.
  • Track changes rather than overwriting critical history.
  • Use a unique internal record ID where tag or location may change.
  • Restrict edits to authorized roles for released records.

13.3 Useful automated checks

A spreadsheet or database can flag:

  • Duplicate component tags.
  • Missing manufacturer part numbers.
  • Components without a physical location.
  • Components without a drawing reference.
  • Obsolete components without an assessed replacement.
  • Different part numbers assigned to the same tag in the same approved revision.
  • Installed components that are not present in the approved list.
  • Components in the list that cannot be found in the installed equipment.
  • Missing change-control references.
  • Records not verified for an unusually long period.

Automated checks should flag potential errors for review. They should not automatically approve technical substitutions.

14. Integrating the component list with maintenance systems

A well-maintained component list can become a useful bridge between engineering and maintenance.

A practical relationship is:

Component tag
    ↓
Component master record
    ↓
Machine / cabinet / physical location
    ↓
Drawing and terminal references
    ↓
Installed model and manufacturer part number
    ↓
ERP material code and stock availability
    ↓
Maintenance history and work orders
    ↓
Obsolescence and replacement planning

14.1 Example maintenance scenario

A 24 V DC power supply fails in a machine control panel.

The technician identifies the tag PS1 on the panel label.

Using the component list, the technician can determine:

  • The exact installed manufacturer part number.
  • The output voltage and current rating.
  • The cabinet and mounting position.
  • The relevant schematic and layout references.
  • The internal material code.
  • The available replacement stock.
  • Whether the device is obsolete.
  • Whether a proposed successor requires engineering approval.

This reduces the risk of ordering a superficially similar but incompatible device.

The technician must still apply safe isolation, verify the fault, and confirm the replacement's suitability before installation.

16. Safety and engineering considerations

The component list is a supporting engineering record. It does not replace electrical risk assessment, design calculations, approved schematics, or safe work procedures.

During component verification or replacement:

  • Follow the site's electrical isolation and lockout/tagout procedure.
  • Verify the absence of hazardous voltage using an appropriate, verified instrument.
  • Consider stored energy in DC bus capacitors, UPS systems, and other energy-storage devices.
  • Use approved replacement components and required accessories.
  • Verify protective-device ratings and coordination.
  • Maintain protective-earth and bonding arrangements.
  • Preserve safety-related circuit architecture and validated functions.
  • Review changes to control hardware, firmware, and safety configuration before commissioning.
  • Update the controlled documentation after authorized work.

For safety-related devices, record the relevant model, certification, configuration, and safety function as needed. Do not infer that a replacement maintains the required safety performance simply because it fits the same mounting position.

17. Component list verification checklist

Use this checklist during design review, panel inspection, commissioning, and maintenance handover.

  • Every required component has a unique engineering tag.
  • Descriptions are consistent and unambiguous.
  • Exact manufacturer part numbers are recorded.
  • Internal material codes are verified where applicable.
  • Electrical ratings match the approved design.
  • Cabinet, machine zone, or physical location is recorded.
  • Schematic and layout references are correct.
  • I/O and network references are linked where relevant.
  • Installed hardware has been compared with the approved list.
  • Substitutions have undergone engineering review.
  • Obsolete components have been identified.
  • Replacement compatibility has been assessed where necessary.
  • Installed and spare quantities are distinguished.
  • Revision and change history are maintained.
  • Related BOMs, drawings, and configuration records have been updated.
  • The released list is available to authorized maintenance personnel.

18. Interview questions and answers

Q1. What is a component list?

A component list identifies the devices used in an electrical or automation system, including their tags, descriptions, manufacturer part numbers, technical attributes, locations, and engineering references.

Q2. What is the difference between a component list and a BOM?

A component list emphasizes device identity, function, specification, and location. A BOM emphasizes the materials and quantities needed for procurement, manufacturing, or assembly. The documents are linked but serve different purposes.

Q3. Why is the component tag important?

It provides a consistent reference across schematics, panel layouts, maintenance records, and work orders. It allows technicians to identify the intended device without relying only on its physical appearance.

Q4. Why should the complete manufacturer part number be recorded?

Different variants within one product family may have different ratings, terminal arrangements, interfaces, or capabilities. The complete part number reduces the risk of incorrect selection and replacement.

Q5. Can a component retain its tag after replacement?

Yes, when the engineering function and project tagging rules permit it. The new manufacturer part number and relevant configuration changes must be documented, and the replacement must be approved.

Q6. What is an as-built component list?

It is the controlled list updated to represent the hardware actually installed after implementation and verification of authorized changes.

Q7. What should happen when a component becomes obsolete?

Its lifecycle status should be updated, the affected equipment identified, and possible replacements assessed for electrical, mechanical, software, communication, safety, and environmental compatibility. A migration plan may be needed.

Q8. Why link the component list to the panel layout?

The schematic explains electrical function, but the layout helps locate the physical device. Together, they reduce troubleshooting and maintenance time.

Q9. What is the difference between a component tag and a material code?

A component tag identifies a device instance in the engineering design. A material code identifies an item in the company's inventory or ERP system. Multiple component tags may use the same material code if they represent the same stocked product.

Q10. How can component-list accuracy be maintained?

Use controlled document revisions, standardized fields, unique identifiers, validation rules, physical verification, and formal change management. Reconcile the list after commissioning and every relevant modification.

Q11. What is the risk of an incorrect component list during breakdown maintenance?

The technician may select an incompatible spare, waste diagnostic time, introduce wiring or configuration errors, or return equipment to service with an unintended design change.

Q12. How would you manage component obsolescence across multiple machines?

Build a master mapping of installed tags to manufacturer part numbers, material codes, machine locations, lifecycle status, stock levels, and approved successors. Use that mapping to prioritize critical equipment, procure spares, and plan validated migrations.

19. Practical exercise

Create a component list for a small industrial control cabinet containing:

  • One main circuit breaker.
  • One 24 V DC power supply.
  • One PLC CPU.
  • One digital input module.
  • One digital output module.
  • One HMI.
  • One industrial Ethernet switch.
  • Two interposing relays.
  • One terminal group.
  • One VFD.

For each device, enter the tag, description, category, manufacturer, complete part number, relevant ratings, location, schematic reference, layout reference, internal material code, lifecycle status, and verification date.

Then perform these checks:

  1. Confirm that every tag is unique.
  2. Compare each listed device against the schematic.
  3. Compare each physical location against the panel layout.
  4. Verify the manufacturer labels on the installed hardware.
  5. Compare the list against the BOM.
  6. Identify any missing material codes or document references.
  7. Simulate a component replacement and record the required change.
  8. Mark one device as obsolete and document the compatibility checks required before replacement.
  9. Produce a verified as-built revision.
  10. Confirm that another technician can locate any listed device using only the component tag and its document references.

The exercise is complete when the list can reliably support engineering verification, procurement, troubleshooting, replacement, and handover without depending on the person who originally created it.
