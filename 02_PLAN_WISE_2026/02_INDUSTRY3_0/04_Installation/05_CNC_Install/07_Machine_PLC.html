1. Purpose and Scope of a Machine PLC

A machine PLC (Programmable Logic Controller) is an industrial controller responsible for coordinating the machine's auxiliary functions, operating sequences, interlocks, and equipment status.

In a CNC machine, the CNC control typically handles machining programs, axis interpolation, tool paths, and coordinated motion. The machine PLC typically handles functions such as tool changing, clamping, lubrication, coolant, hydraulic systems, doors, and machine sequencing. The exact division depends on the machine builder and control architecture.

The machine PLC connects field I/O, operator controls, drives, sensors, actuators, and the CNC interface into one coordinated system.

2. CNC Control Versus Machine PLC

Function CNC control Machine PLC
Execute machining program Primary responsibility Usually not primary
Coordinate feed-axis motion Primary responsibility May provide permissives and status
Control spindle machining functions CNC and spindle-control functions May control auxiliary spindle sequences
Tool-change sequence Requests and coordinates as configured Often sequences the tool changer
Coolant control May request coolant Often controls pumps and valves
Hydraulic system May request a machine function Often manages the hydraulic sequence
Door and guard status Consumes required status signals Processes signals according to the architecture
Machine alarms Displays CNC and machine alarms Detects and reports machine-sequence faults
Safety functions Depends on the safety architecture Standard PLC logic alone is not safety-rated
Operator interface CNC display and machining interface Supplies machine states and commands to the HMI

The CNC and machine PLC are complementary. Neither should be assumed to control every function without checking the actual machine documentation.

3. Machine PLC Architecture

OPERATOR PANEL / HMI
          ↓
      CNC CONTROL
          ↕
   CNC-PLC INTERFACE
          ↕
     MACHINE PLC
          ↕
    PLC I/O SYSTEM
          ↕
SENSORS / VALVES / RELAYS / CONTACTORS
          ↕
HYDRAULICS / PNEUMATICS / COOLANT / TOOL CHANGER

The machine may also include remote I/O, drive networks, a safety PLC, or distributed controllers. Some CNC platforms integrate the PLC runtime within the CNC control hardware, while others use a separate PLC.

4. Machine PLC Hardware

4.1 CPU

The central processing unit executes the control program and manages communications, diagnostics, and data processing.

Important characteristics include:

  • Program and memory capacity.
  • Scan performance.
  • Supported programming languages.
  • Communication interfaces.
  • I/O capacity.
  • Retentive-memory behavior.
  • Supported firmware and engineering software.

4.2 Digital Input Modules

These modules read discrete signals from sensors, switches, and other devices.

Typical signals include door status, pressure switches, axis limit indications, tool-clamp feedback, and contactor auxiliary contacts.

4.3 Digital Output Modules

These modules command discrete loads or interface devices.

Examples include solenoid valves, relay coils, contactor coils, stack lights, and auxiliary commands.

The output module must be compatible with the connected load's voltage, current, and switching characteristics.

4.4 Analog I/O

Analog input modules receive variable signals such as pressure, temperature, or level. Analog output modules generate variable references for compatible equipment.

Signal scaling, range configuration, grounding, and noise control are essential.

4.5 Communication Interfaces

Communication interfaces connect the PLC to the CNC, remote I/O, drives, HMIs, and other industrial devices.

Depending on the platform, these may use PROFINET, PROFIBUS, EtherNet/IP, CC-Link, Modbus, or proprietary CNC interfaces.

Protocol compatibility, addressing, configuration, and update-time requirements must be verified.

5. PLC Program Organization

Machine PLC programs are commonly organized into tasks, routines, function blocks, functions, and data structures. The exact terminology depends on the PLC platform.

Typical program sections include:

  • Main execution logic.
  • Input conditioning.
  • Operating-mode management.
  • Machine-state management.
  • Sequence control.
  • Output control.
  • Alarm processing.
  • Communication handling.
  • Diagnostics and maintenance functions.

A well-organized program separates the physical I/O interface from machine sequence logic where practical. This improves readability, troubleshooting, testing, and future modifications.

5.1 Input Processing

Input processing converts raw electrical states into usable logical conditions.

It may include filtering, debouncing, plausibility checks, signal inversion, and fault detection.

A raw input being ON does not automatically mean the machine function is valid. The program may need to check other conditions before accepting it.

5.2 Sequence Logic

Sequence logic coordinates multiple actions in a defined order.

For example, a tool-change sequence may require the spindle to stop, the tool-change position to be reached, the correct interlocks to be satisfied, and the tool changer to complete its movement before machining resumes.

5.3 Output Processing

Output processing converts logical requests into physical commands.

The program should ensure that outputs are controlled according to the operating state, permissives, feedback, and required fault handling.

6. PLC Scan Cycle

A conventional PLC scan may involve reading inputs, executing program logic, updating outputs, and performing communications or diagnostics. Actual behavior depends on the controller, task configuration, and I/O architecture.

READ OR UPDATE INPUT DATA
          ↓
EXECUTE PLC PROGRAM
          ↓
UPDATE OUTPUT DATA
          ↓
COMMUNICATIONS / DIAGNOSTICS
          ↓
NEXT EXECUTION CYCLE

Some controllers use process images, asynchronous I/O updates, periodic tasks, event tasks, or distributed execution. Therefore, the diagram is a simplified model, not a universal execution sequence.

6.1 Scan Time

Scan time is the time required for a defined program execution cycle or task execution, according to the controller's timing model.

A long or variable scan time can affect sequence response and event detection.

Important factors include:

  • Program complexity.
  • Communication load.
  • Number of instructions and function blocks.
  • Task priorities.
  • Interrupts and event processing.
  • Controller performance.
  • I/O update behavior.

Fast, safety-related, or high-speed functions require an architecture designed for their timing and performance requirements.

7. PLC Programming Languages

IEC 61131-3 defines common PLC programming languages and related programming concepts. Supported languages vary by controller and engineering environment.

7.1 Ladder Diagram (LD)

Ladder Diagram represents logic using contacts, coils, and other graphical instructions.

It is widely used for discrete machine sequencing, interlocks, and maintenance troubleshooting.

Example concept:

|----[ START_REQUEST ]----[ PERMISSIVES_OK ]----( RUN_REQUEST )----|

This is a simplified logical illustration, not a complete machine-control program.

7.2 Function Block Diagram (FBD)

FBD represents logic through interconnected function blocks.

It can be useful for signal processing, analog calculations, timers, comparisons, and control functions.

7.3 Structured Text (ST)

Structured Text is a textual language suited to calculations, complex conditions, data handling, and structured algorithms.

Example:

IF Permissives_OK AND Start_Request THEN
    Run_Request := TRUE;
ELSE
    Run_Request := FALSE;
END_IF;

The example illustrates basic logic only. A production program must handle operating modes, stop requests, faults, and state transitions according to the machine design.

7.4 Sequential Function Chart (SFC)

SFC represents sequential logic using steps and transitions where supported.

It can make multi-stage machine sequences easier to understand, especially when each stage has defined entry conditions, actions, and completion criteria.

8. Machine State and Operating Modes

A machine PLC often manages operating states such as:

  • Power-up or initialization.
  • Ready.
  • Manual operation.
  • Automatic operation.
  • Cycle running.
  • Cycle hold or pause.
  • Faulted.
  • Recovery or maintenance state.

The actual state model depends on the machine.

8.1 State-Based Control

A state-based design makes the current machine condition explicit and defines which actions are allowed in each state.

INITIALIZATION
      ↓
CHECK MACHINE CONDITIONS
      ↓
READY
      ↓
AUTOMATIC CYCLE
      ↓
CYCLE COMPLETE
      ↓
READY

ANY RELEVANT FAULT
      ↓
FAULT HANDLING
      ↓
CONTROLLED RECOVERY

This structure can improve troubleshooting because the technician can identify which transition or condition prevents the next step.

8.2 Manual and Automatic Modes

Manual mode typically allows selected operations under defined conditions. Automatic mode executes the programmed sequence.

Mode selection must be implemented according to the machine's risk assessment and design. Manual mode does not inherently make movement safe, and it must not be used to bypass required safety functions.

9. Interlocks and Permissives

A permissive is a condition that must be satisfied before an action can begin.

An interlock is a condition or logic arrangement that prevents an action when required conditions are not met.

Examples include:

  • Spindle start permitted only when relevant conditions are satisfied.
  • Tool change permitted only when the spindle and axes are in the required states.
  • Hydraulic clamping permitted only under the approved operating conditions.
  • Automatic cycle permitted only when required guards, systems, and machine states are valid.

Interlocks may be process-related or safety-related. Safety-related interlocks must use an appropriate safety architecture and validated implementation.

9.1 Interlock Design

A robust interlock should identify:

  • The controlled action.
  • Required permissive conditions.
  • Conditions that cancel or inhibit the action.
  • Expected feedback.
  • Timeout behavior.
  • Alarm and recovery behavior.
  • Whether the function is safety-related.

Avoid creating logic that allows an output to remain active indefinitely after its permissive disappears unless that behavior is explicitly required and safe.

10. Timers, Counters, and Edge Detection

10.1 Timers

Timers are used to implement delays, response timeouts, and time-dependent logic.

Common concepts include on-delay, off-delay, and pulse timing.

For example, a clamp command may start a timeout. If clamp confirmation does not arrive within the permitted period, the PLC raises a fault.

The timeout must be based on the real equipment response and machine-builder requirements.

10.2 Counters

Counters track events such as completed cycles, tool-change operations, or maintenance intervals.

Counter behavior must account for reset conditions, retentive behavior, overflow, and whether counts must survive a power interruption.

10.3 Edge Detection

Edge detection identifies a transition rather than a maintained state.

  • Rising edge: OFF to ON.
  • Falling edge: ON to OFF.

Edge detection is useful for momentary requests, event counting, and sequence transitions. It must be used carefully when signals may bounce, remain active at startup, or arrive asynchronously.

11. Machine PLC and CNC Interface

The machine PLC and CNC exchange commands and status data.

Typical interface signals include:

  • Cycle-start request and status.
  • Machine-ready indication.
  • Spindle start and stop requests.
  • Tool-change requests and completion.
  • Feed-hold or cycle-stop status.
  • Machine alarm and reset status.
  • Axis-position or in-position status.
  • Mode and program-state information.

The interface may use hardwired I/O, shared data, a fieldbus, or a vendor-specific CNC interface.

11.1 Handshaking

Handshaking coordinates a request and its completion status between two control systems.

A generic handshake may follow this pattern:

CONTROLLER A ASSERTS REQUEST
          ↓
CONTROLLER B CHECKS CONDITIONS
          ↓
CONTROLLER B STARTS ACTION
          ↓
CONTROLLER B ASSERTS COMPLETE
          ↓
CONTROLLER A ACCEPTS COMPLETION
          ↓
REQUEST AND COMPLETE ARE CLEARED
          ↓
NEXT TRANSACTION

Actual handshakes may use additional states, acknowledgements, timeouts, and fault handling.

11.2 Handshake Faults

Common causes include:

  • Request bit never becomes active.
  • Completion bit never becomes active.
  • Request is cleared too early.
  • Completion remains latched.
  • Incorrect polarity or mapping.
  • Different assumptions about signal timing.
  • Communication failure.
  • A permissive remains false.
  • One controller is waiting for a state the other never enters.

Troubleshooting should establish which system owns each signal and which transition is missing.

12. Tool-Change Sequence Example

A machine PLC may control a tool changer, but the exact sequence depends on the machine design.

A simplified conceptual sequence is:

  1. Receive the tool-change request.
  2. Confirm required machine conditions.
  3. Stop the spindle and verify the required spindle state.
  4. Move to the approved tool-change position.
  5. Verify axis position and other required permissives.
  6. Operate the tool-release mechanism.
  7. Confirm the required unclamped state.
  8. Operate the tool changer and magazine mechanisms.
  9. Confirm the new tool position and required clamp state.
  10. Complete the handshake with the CNC.
  11. Return to the ready state or raise a fault if a required condition fails.

A tool-change sequence must not assume that issuing an output proves the mechanism moved. Physical feedback and suitable timeout handling are important.

13. PLC Alarms and Diagnostics

A machine PLC should provide useful fault information rather than only a generic machine-alarm bit.

A useful alarm record includes:

  • Alarm code.
  • Clear description.
  • Machine subsystem.
  • Triggering condition.
  • Timestamp where available.
  • Relevant state or sequence step.
  • Required operator action.
  • Reset conditions.
  • Fault history where supported.

13.1 Alarm Versus Interlock

An alarm communicates a fault or abnormal condition. An interlock prevents an operation from proceeding when required conditions are not met.

The same condition may trigger both an alarm and an interlock, but the concepts are not identical.

13.2 Fault Latching

A latched fault remains active until defined reset conditions are satisfied.

Latching can preserve important fault information after the original condition disappears. Reset behavior must be designed so that a reset does not unexpectedly restart motion or bypass the cause of the fault.

14. PLC Installation and Commissioning

14.1 Hardware Installation

  • Verify the PLC and module catalog numbers.
  • Confirm rack, slot, and power-supply compatibility.
  • Check mounting, environmental rating, and ventilation.
  • Verify protective earth and bonding.
  • Check field wiring and terminal assignments.
  • Confirm network addressing and cable routing.
  • Verify the compatibility of remote I/O and communication modules.

14.2 Program and Configuration Verification

  • Confirm the approved PLC program version.
  • Verify the hardware configuration.
  • Check I/O addressing and tag mapping.
  • Confirm CNC interface assignments.
  • Review timers, counters, and sequence parameters.
  • Verify retentive data behavior.
  • Check alarm logic and reset behavior.
  • Ensure approved backups are available.

14.3 Functional Commissioning

  1. Confirm the machine is in the approved commissioning state.
  2. Verify input signals and module diagnostics.
  3. Test outputs using the approved controlled procedure.
  4. Validate interlocks and permissives.
  5. Verify CNC-PLC handshakes.
  6. Test normal machine sequences.
  7. Verify timeout and fault handling.
  8. Validate recovery behavior.
  9. Test safety functions using the required safety validation procedure.
  10. Save the final approved configuration and test records.

Testing must not bypass required safety devices or expose personnel to uncontrolled machine movement.

15. Online Monitoring and Troubleshooting

When troubleshooting a machine PLC, monitor the sequence and its conditions rather than changing logic immediately.

A practical investigation should establish:

  • Current machine state.
  • Current sequence step.
  • Requested action.
  • Required permissives.
  • Raw input states.
  • Output commands.
  • Physical feedback.
  • Active alarms.
  • Timer status.
  • CNC interface bits.
  • Communication and module diagnostics.

15.1 Output Command Is ON, but the Actuator Does Not Move

Check the complete chain:

PLC LOGIC REQUEST
       ↓
PLC OUTPUT STATUS
       ↓
OUTPUT MODULE AND SUPPLY
       ↓
TERMINAL / FIELD WIRING
       ↓
RELAY / CONTACTOR / VALVE
       ↓
ACTUATOR
       ↓
PHYSICAL FEEDBACK

Possible causes include missing supply, an open circuit, output-channel failure, a failed relay, a damaged solenoid coil, mechanical jamming, or a feedback problem.

15.2 Sequence Is Stuck at One Step

Check:

  1. Which step is active?
  2. What condition is required for the next transition?
  3. Is the relevant input electrically valid?
  4. Is the input mapped correctly?
  5. Has the required output been commanded?
  6. Did the mechanism complete the action?
  7. Did the completion sensor change state?
  8. Has a timer expired?
  9. Is another interlock blocking the transition?
  10. Is the CNC waiting for a handshake acknowledgement?

The missing transition condition is often more informative than the alarm displayed to the operator.

17. PLC Backup, Version Control, and Change Management

Before modifying a production machine PLC:

  • Identify the correct controller and machine.
  • Obtain the approved program and current configuration.
  • Upload or retrieve the existing program where permitted.
  • Compare online and offline versions.
  • Record existing alarms and operating symptoms.
  • Review the impact of the proposed change.
  • Follow authorization and change-control procedures.
  • Preserve a recoverable backup.
  • Test changes under controlled conditions.
  • Verify the complete affected sequence.
  • Document the change and final program version.

An upload is not always equivalent to a complete recoverable backup. Hardware configuration, drive parameters, safety projects, HMI files, recipes, passwords, and retained data may need separate handling.

Never download a program to a live production machine merely to see whether it fixes the problem. Verify the target, version, compatibility, and operational consequences first.

The exact controller, programming language, communication method, and backup procedure must be identified from the installed system.

19. Safety and Machine PLC Boundaries

A standard machine PLC can coordinate normal machine operation, but ordinary PLC logic alone is not a substitute for a safety-rated control system.

Safety-related functions may require:

  • Safety PLCs or safety relays.
  • Safety-rated I/O.
  • Appropriate guard interlocks.
  • Emergency-stop circuitry.
  • Safe drive functions where applicable.
  • Defined safety performance requirements.
  • Validation and periodic inspection.

The required architecture depends on the machine risk assessment and applicable standards.

Important distinctions:

  • A normal PLC input monitoring an emergency-stop contact does not by itself make the stop function safety-rated.
  • A software interlock is not automatically an approved substitute for a physical safety function.
  • Resetting an alarm must not automatically restart hazardous movement unless the designed safety and restart conditions explicitly permit it.
  • Maintenance and commissioning must follow the approved isolation and safeguarding procedures.

20. Practical Diagnostic Example

Scenario: A CNC machine displays “Tool change incomplete” even though the tool changer appears to have moved into position.

Step 1: Identify the active sequence state

Monitor the machine PLC's active tool-change step and determine the exact transition condition that remains false.

Step 2: Check the requested output

Confirm that the PLC has issued the expected command to the tool-change mechanism.

Step 3: Verify the physical mechanism

Check for incomplete movement, a mechanical obstruction, an actuator fault, or an incorrectly seated tool.

Step 4: Check feedback signals

Verify the relevant position, clamp, unclamp, or magazine confirmation inputs at the module and in the PLC program.

Step 5: Verify I/O mapping

Confirm that the physical input is mapped to the correct symbolic tag and that the logic uses the intended signal.

Step 6: Check timing and handshaking

Determine whether the sequence timed out or whether the CNC is waiting for a completion acknowledgement that the PLC has not generated.

Step 7: Correct and validate

Repair the identified electrical, mechanical, configuration, or logic fault. Then verify the complete tool-change sequence and its fault-handling behavior under controlled conditions.

The key principle is to distinguish the requested action from the verified physical result. A mechanism looking correct to a person does not prove that its feedback signal is valid.

21. Interview Questions and Answers

Q1. What is the role of a machine PLC in a CNC machine?

It coordinates auxiliary machine functions, I/O, interlocks, operating sequences, and communication with the CNC and other control systems.

Q2. What is the difference between CNC and PLC?

The CNC primarily manages machining programs and coordinated motion, while the machine PLC commonly manages machine sequencing and auxiliary equipment. The actual division depends on the machine architecture.

Q3. What is a PLC scan cycle?

It is a controller execution cycle or task cycle in which program logic and associated I/O or processing operations are performed according to the controller's execution model.

Q4. What is a permissive?

A condition that must be satisfied before a defined operation is allowed to begin.

Q5. What is an interlock?

A condition or logic arrangement that prevents an action when required conditions are not met.

Q6. Why are timers used in machine sequencing?

They detect missing or delayed responses, implement controlled timing, and support fault handling.

Q7. What is a CNC-PLC handshake?

A defined exchange of request, acknowledgement, completion, and sometimes fault signals that coordinates an operation between the CNC and machine PLC.

Q8. Why can a machine sequence remain stuck even when the actuator moves?

The completion sensor may not operate, the input may be miswired, the address may be wrong, or the PLC transition condition may not be satisfied.

Q9. Why is fault latching useful?

It preserves fault information until the defined reset conditions are met, helping prevent a transient fault from disappearing before it can be investigated.

Q10. What is the difference between an alarm and an interlock?

An alarm communicates a fault or abnormal condition. An interlock prevents a defined operation when its required conditions are not satisfied.

Q11. Why must PLC backups be verified?

A program file alone may not include all required hardware configuration, parameters, safety projects, HMI files, and retained data needed for complete recovery.

Q12. Can a standard PLC replace a safety PLC?

Not when the application requires a safety-rated control function. The hardware, architecture, software, and validation must satisfy the applicable safety requirements.

Q13. What should be checked before changing machine PLC logic?

Confirm the machine and controller identity, obtain a recoverable backup, compare program versions, understand the active sequence, assess the impact, and follow approved change-control procedures.

Q14. How should an output fault be diagnosed?

Trace the signal from the program request through the output module, wiring, interface device, actuator, and physical feedback. This separates logic problems from electrical and mechanical failures.

22. Practical Knowledge Checklist

  • Explain the roles of the CNC and machine PLC.
  • Identify PLC CPU, I/O, and communication modules.
  • Understand PLC program organization and scan behavior.
  • Recognize Ladder Diagram, Function Block Diagram, and Structured Text.
  • Understand machine states, operating modes, and sequence logic.
  • Explain permissives, interlocks, timers, counters, and edge detection.
  • Troubleshoot CNC-PLC handshakes.
  • Diagnose stuck sequences and missing feedback.
  • Understand PLC alarm and fault-latching behavior.
  • Perform approved PLC commissioning and I/O verification.
  • Maintain complete backups and change records.
  • Distinguish standard PLC control from safety-rated control.
  • Identify the installed controller platform and its diagnostic tools.
