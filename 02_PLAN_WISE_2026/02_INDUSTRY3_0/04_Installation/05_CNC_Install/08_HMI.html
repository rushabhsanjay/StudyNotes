1. Purpose and Scope of HMI in CNC Machines

A Human-Machine Interface (HMI) is the operator-facing interface used to monitor machine conditions, enter commands, select operating functions, view alarms, and access machine information.

In CNC machines, the HMI may be integrated into the CNC control panel or implemented as a separate industrial panel PC or operator terminal.

The HMI allows operators and maintenance personnel to interact with the CNC, machine PLC, drives, and auxiliary systems without directly accessing the underlying control logic for routine operations.

Typical functions include:

  • Displaying machine status, operating mode, and cycle progress.
  • Showing CNC program information, coordinates, offsets, and machining status.
  • Displaying machine alarms and diagnostic messages.
  • Providing manual-operation controls where authorized.
  • Displaying tool, workpiece, and machine parameters.
  • Allowing approved recipe, setting, and production-data entry.
  • Displaying maintenance counters and equipment status.
  • Supporting authorized configuration and service functions.

The HMI is not necessarily the controller executing the machine sequence. It may display information received from the CNC or PLC and send operator commands to those systems.

2. HMI, CNC, PLC, and SCADA Differences

System Primary responsibility Typical example
CNC control Machining program execution and coordinated motion Axis interpolation and tool-path execution
Machine PLC Machine sequencing and auxiliary equipment control Tool changer, coolant, clamps, lubrication
HMI Operator interaction and machine visualization Start request, alarm display, status screens
SCADA Supervisory monitoring and data collection across equipment Production dashboards, historical trends
MES Manufacturing operations and production coordination Work orders, traceability, production tracking
Safety control system Safety-related control functions Guard monitoring and safety-rated stop functions

A CNC control may combine several of these functions in one integrated product. The functional responsibilities still need to be distinguished.

3. HMI System Architecture

OPERATOR
    ↓
CNC HMI / MACHINE OPERATOR PANEL
    ↓
CNC CONTROL AND/OR MACHINE PLC
    ↓
CONTROL LOGIC AND INTERLOCKS
    ↓
DRIVES / ACTUATORS / AUXILIARY EQUIPMENT
    ↓
SENSORS AND STATUS FEEDBACK
    ↓
PLC / CNC STATUS DATA
    ↓
HMI DISPLAY

The actual architecture depends on the machine builder. An HMI may communicate with the CNC, PLC, or both. A separate industrial PC may also connect to a machine network or supervisory system.

4. HMI Hardware

4.1 Operator Panel

The operator panel provides the physical interface for machine operation.

It may contain:

  • Touchscreen display.
  • Physical pushbuttons and selector switches.
  • Emergency-stop hardware.
  • Mode-selection controls.
  • Manual pulse generator or handwheel.
  • Keyboard or keypad.
  • USB or service interfaces.
  • Status indicators and machine lamps.

Emergency-stop and other safety-related devices must be implemented through the approved safety architecture. Their safety function must not depend solely on a touchscreen graphic.

4.2 Display and Touchscreen

Important characteristics include:

  • Screen size and resolution.
  • Brightness and viewing angle.
  • Touch technology and responsiveness.
  • Resistance to oil, dust, vibration, and cleaning agents.
  • Operating-temperature range.
  • Glove compatibility where required.
  • Mounting and ingress-protection ratings.
  • Availability of replacement panels.

A touchscreen can fail even when the underlying CNC and PLC remain operational.

4.3 Panel PC and Integrated HMI

An integrated CNC HMI may run within the CNC control system. A separate HMI may run on an industrial PC or dedicated terminal.

A separate HMI introduces additional considerations such as operating-system configuration, storage health, application compatibility, network communication, and software licensing.

5. HMI Software and Screen Organization

6. HMI Design Principles

A good HMI should help the operator identify the machine state and understand what action is permitted.

6.1 Clear Status Presentation

Use consistent labels for machine states such as:

  • Ready.
  • Running.
  • Held.
  • Stopped.
  • Faulted.
  • Manual mode.
  • Automatic mode.
  • Maintenance mode.

Do not use color as the only indication of state. Text, symbols, and clear status descriptions should also be provided.

6.2 Consistent Navigation

Related screens should follow a predictable layout. Operators should be able to find important functions without navigating through unnecessary menus.

Critical information such as active alarms, operating mode, and machine readiness should be easy to identify.

6.3 Command Feedback

When an operator requests an action, the interface should show the command state and, where appropriate, the actual machine response.

For example, a coolant button may indicate that a coolant command was requested. The HMI should not imply that coolant flow is physically confirmed unless suitable feedback is available.

6.4 Avoid Ambiguous Controls

Buttons should have clear labels and distinguish commands from status indicators.

Destructive or high-impact actions may require confirmation, suitable authorization, or additional safeguards according to the machine design.

7. HMI Commands Versus Physical Machine State

One of the most important HMI concepts is the distinction between a command, a control-system state, and a physical result.

For example:

  • Command: Request the hydraulic clamp to close.
  • PLC state: The clamp-close output is active.
  • Physical result: The clamp reaches its required position and the feedback sensor confirms it.

These are three different facts.

An HMI must not be treated as proof that an actuator physically operated. The display may show the command or a PLC bit rather than verified physical feedback.

A useful diagnostic chain is:

OPERATOR COMMAND
       ↓
HMI COMMUNICATION
       ↓
PLC / CNC RECEIVES REQUEST
       ↓
CONTROL CONDITIONS SATISFIED
       ↓
OUTPUT COMMAND ISSUED
       ↓
ACTUATOR OPERATES
       ↓
FEEDBACK CONFIRMS RESULT
       ↓
HMI UPDATES STATUS

When a displayed status is wrong, determine which stage of this chain is incorrect.

8. HMI Communication with CNC and PLC

The HMI communicates using a supported interface or protocol. Depending on the system, this may include a proprietary CNC interface, OPC UA, Modbus TCP, EtherNet/IP, PROFINET, or another supported mechanism.

The presence of an Ethernet port does not guarantee that two devices can communicate. Protocol support, configuration, addressing, drivers, licensing, and data mapping must all be compatible.

8.1 Communication Parameters

Important configuration items include:

  • Device IP address where Ethernet is used.
  • Subnet mask and routing configuration.
  • PLC or CNC station address.
  • Communication driver or protocol selection.
  • Data block, register, or tag mapping.
  • Update rate and timeout settings.
  • Authentication and access permissions.
  • Connection status and error diagnostics.

Some integrated CNC HMIs do not expose all these settings to the operator. Follow the machine-builder documentation.

8.2 Communication Failure Symptoms

Common symptoms include stale values, missing status indicators, failed commands, blank screens, communication alarms, and delayed updates.

When a value is stale, the display may still show the last valid value. A robust design should make loss of communication distinguishable from a valid but unchanged machine state.

9. HMI Tags and Data Mapping

A tag is a named data point used by the HMI or associated control software.

Examples include:

  • Machine_Ready
  • Cycle_Running
  • Active_Alarm
  • Spindle_Running
  • Coolant_Command
  • Clamp_Confirmed
  • Part_Count
  • Cycle_Time

These names are illustrative. Actual tags depend on the machine project.

9.1 Tag Types

Data type Typical use Example
Boolean ON/OFF status or command Machine_Ready
Integer Count, index, or enumerated state Part_Count
Real Measured or calculated value Spindle_Load
String Text information Active_Alarm_Text
Array or structure Grouped data Tool information or alarm records

9.2 Mapping Verification

Incorrect tag mapping can create misleading displays or send commands to the wrong control variable.

Verify:

  • Correct source controller.
  • Correct address or symbolic tag.
  • Correct data type.
  • Correct scaling and engineering units.
  • Correct polarity and state interpretation.
  • Correct read/write permissions.
  • Correct update behavior.
  • Correct handling of communication loss.

10. CNC-Specific HMI Functions

10.1 Coordinate Display

CNC interfaces may show machine coordinates, work coordinates, relative positions, and remaining travel.

These coordinate systems are not interchangeable. The displayed values depend on the selected coordinate system, offsets, and control configuration.

10.2 Tool and Work Offsets

HMI screens may allow authorized personnel to view or modify tool geometry, tool wear, work offsets, and related parameters.

Incorrect offset entry can cause dimensional errors or collisions. Changes must follow approved setup procedures and be verified before production.

10.3 Program Selection and Execution

Depending on permissions and configuration, the HMI may allow operators to select programs, inspect program status, start execution, pause, or stop a cycle.

The HMI command does not override the CNC's program conditions, operating-mode requirements, interlocks, or safety functions.

10.4 M-Code and Auxiliary Functions

CNC programs may request auxiliary machine functions using M-codes or equivalent mechanisms. The machine PLC or CNC-specific logic may execute the corresponding sequence.

For example, a program may request a tool change or coolant operation. The precise meaning of each code is machine- and configuration-dependent, so it must be checked against the machine documentation.

11. Alarm Display and Alarm Management

A useful alarm display provides enough information to identify the subsystem and investigate the cause.

Typical alarm information includes:

  • Alarm number.
  • Alarm description.
  • Alarm source.
  • Timestamp, where available.
  • Active or historical status.
  • Associated sequence or machine condition.
  • Approved recovery instructions.

11.1 CNC Alarms Versus Machine Alarms

CNC alarms may relate to program execution, axes, spindle operation, CNC parameters, or internal control functions.

Machine alarms may relate to hydraulic pressure, lubrication, tool changing, clamps, doors, coolant, or other auxiliary equipment.

The distinction varies by platform. Some machines present both types in a unified alarm list.

11.2 Alarm Reset

Resetting an alarm is not the same as repairing its cause.

Before resetting:

  1. Read the complete alarm message.
  2. Identify the relevant machine subsystem.
  3. Check the initiating condition.
  4. Determine whether movement or stored energy could create a hazard.
  5. Correct the fault using the approved procedure.
  6. Reset only when permitted.
  7. Verify the machine returns to the intended state.

Do not repeatedly reset a fault without investigating it.

12. User Access, Security, and Permissions

HMI permissions help prevent unauthorized changes to machine settings and commands.

Common access levels include operator, setup technician, maintenance technician, and engineering or administrator access. These are examples rather than universal role definitions.

Good practices include:

  • Apply role-based access where supported.
  • Restrict write access to important parameters.
  • Protect engineering and service functions.
  • Avoid shared credentials where individual accounts are supported.
  • Control USB and external-media use.
  • Protect remote access.
  • Follow approved password and backup procedures.
  • Record important configuration changes.

An HMI password is not a substitute for physical safeguarding, electrical isolation, or a validated safety system.

13. HMI Installation

13.1 Mechanical Installation

Verify:

  • Panel cutout and mounting dimensions.
  • Mounting strength and vibration conditions.
  • Required clearance and ventilation.
  • Environmental rating.
  • Cable-entry arrangements.
  • Screen visibility and operator reach.
  • Protection from coolant, oil, chips, and cleaning agents.

The panel should be positioned so the operator can view relevant machine conditions without entering a hazardous area.

13.2 Electrical Installation

Verify:

  • Supply voltage and power rating.
  • Protective earthing and bonding.
  • Fuse or circuit-protection requirements.
  • Correct terminal connections.
  • Cable routing and segregation.
  • Shielding and grounding requirements.
  • Network cable specifications.
  • Connector retention and strain relief.

Power wiring and signal wiring should be routed according to the machine design and applicable EMC requirements.

13.3 Network Installation

Confirm the configured network address, subnet, protocol, and connection path. Ensure that the HMI is connected to the intended machine network rather than an unintended production or corporate network.

Apply the site's approved cybersecurity and network-segmentation requirements.

14. HMI Commissioning

14.1 Hardware Checks

  • Verify the model and hardware revision.
  • Confirm mounting and environmental protection.
  • Check supply voltage and protective earth.
  • Verify connectors and cable condition.
  • Confirm display and touchscreen operation.

14.2 Software and Configuration Checks

  • Verify the approved HMI project and version.
  • Confirm the correct CNC or PLC connection.
  • Validate tag mapping and data types.
  • Verify screen navigation and language settings.
  • Check alarms and event history.
  • Confirm access permissions.
  • Verify recipes, parameters, and engineering units where applicable.

14.3 Functional Checks

  • Verify displayed machine state against the actual control-system state.
  • Confirm that command buttons operate only under the required conditions.
  • Check command feedback and physical feedback separately.
  • Verify alarm generation, display, acknowledgement, and reset behavior.
  • Confirm communication-loss indication.
  • Test recovery after a permitted restart or communication interruption.
  • Confirm that safety-related functions work independently through their approved architecture.

14.4 Acceptance Records

Document the HMI version, hardware identity, communication configuration, functional-test results, outstanding defects, and approved backup location.

15. HMI Troubleshooting

15.1 HMI Does Not Power On

Check the approved power source, supply voltage, protective device, wiring, connector condition, and device diagnostics.

Do not assume the panel itself has failed until its power supply and wiring have been verified.

15.2 HMI Powers On but Shows No Machine Data

Check:

  1. HMI communication status.
  2. CNC or PLC operating status.
  3. Network link and addressing.
  4. Protocol or driver configuration.
  5. Controller-side communication diagnostics.
  6. Tag mapping and access permissions.
  7. Whether the displayed data is stale or invalid.

15.3 HMI Button Works but the Machine Does Not Respond

Check the request path from the HMI to the controller, the controller's permissives and interlocks, output status, actuator response, and feedback.

The button may have successfully transmitted a request that the PLC correctly rejected because a required condition was absent.

15.4 HMI Displays Incorrect Values

Check the source tag, data type, byte or word interpretation where applicable, scaling, units, offsets, update behavior, and whether the value is being converted or formatted by the HMI.

15.5 Touchscreen Does Not Respond Correctly

Possible causes include surface contamination, physical damage, calibration issues where supported, driver faults, or hardware failure.

Use approved cleaning and service procedures. Do not use sharp tools or aggressive solvents on the display.

15.6 HMI Freezes or Restarts

Investigate application errors, operating-system faults where applicable, storage problems, overheating, power instability, resource exhaustion, and communication-driver issues.

Preserve diagnostic logs before changing the configuration when practical.

16. Common HMI Faults and Diagnostic Methods

Symptom Possible causes Diagnostic approach

17. HMI Backup and Version Management

HMI backups are essential because a replacement panel may not contain the original machine screens, tags, alarms, languages, or communication settings.

Maintain the following where applicable:

  • HMI application or project file.
  • Runtime version and software compatibility details.
  • Hardware model and revision.
  • Communication-driver configuration.
  • Tag database and alarm configuration.
  • Screen and navigation configuration.
  • Recipes and approved machine settings.
  • License and activation information.
  • User-role configuration, handled securely.
  • Firmware or operating-system recovery information.
  • Restoration instructions.

Record the approved version and backup date. Where possible, store backups in controlled locations and verify that they can be restored to compatible hardware.

A screenshot collection is not a complete HMI backup. It preserves appearances, not the underlying application, data mapping, or behavior.

18. HMI Maintenance and Obsolescence

HMI maintenance includes cleaning, inspecting cables and connectors, checking panel temperature, verifying screen response, monitoring storage health where applicable, and confirming that backups remain usable.

For obsolete HMIs, identify:

  • Exact manufacturer and model.
  • Hardware revision.
  • Display and mounting dimensions.
  • Supply voltage and power requirements.
  • Supported communication protocols.
  • Available engineering software.
  • Runtime and operating-system compatibility.
  • Project conversion requirements.
  • Licensing requirements.
  • Spare availability.
  • Replacement and migration options.

A physically compatible replacement may still be incompatible with the original project, communications, or software runtime.

Before replacing an HMI, confirm the replacement plan and validate the machine functions affected by the migration.

19. HMI and Industrial Cybersecurity

HMIs can be access points to machine-control systems. Security controls should be applied without disrupting validated machine operation.

Recommended practices include:

  • Keep engineering access restricted.
  • Remove unnecessary services and applications where supported.
  • Control removable media.
  • Apply approved patching and firmware procedures.
  • Restrict remote connections.
  • Use network segmentation and approved firewall rules.
  • Maintain configuration backups.
  • Monitor relevant security and system events.
  • Coordinate changes with operations and maintenance teams.

Do not install arbitrary software or apply operating-system updates to a production HMI without verifying compatibility and following the site's change-control procedure.

20. Practical Diagnostic Case Study

Scenario: The HMI displays Clamp Closed, but the machine refuses to start the automatic cycle.

Step 1: Verify the displayed value

Determine whether Clamp Closed represents the actual clamp-position sensor, a PLC command, or a derived software status.

Step 2: Check the controller source

Monitor the corresponding PLC input, internal status bit, or CNC interface signal using the approved diagnostic tools.

Step 3: Check the machine permissives

Identify all conditions required for automatic cycle start. The clamp may be closed while another required condition remains false.

Step 4: Compare the HMI tag with the source

Verify the address, tag, data type, polarity, and any scaling or logic used to produce the displayed status.

Step 5: Inspect the alarm and sequence state

Check the active machine state, relevant interlocks, and any fault preventing the transition into automatic operation.

Step 6: Correct the actual fault

Repair the sensor, wiring, mapping, or other confirmed cause. Do not modify the logic simply to make the HMI display the expected state.

Step 7: Validate the complete function

Confirm that the clamp status is accurate, the required permissives are satisfied, the cycle starts correctly, and the fault response remains effective.

This case illustrates a central maintenance principle: a correct-looking HMI screen does not prove that the underlying machine state is correct.

21. Interview Questions and Answers

Q1. What is an HMI?

An HMI is an operator interface used to monitor machine conditions, enter commands, view alarms, and access machine information.

Q2. What is the difference between HMI and PLC?

The HMI provides visualization and operator interaction. The PLC executes control logic and manages machine I/O and sequences.

Q3. Can an HMI directly control a machine actuator?

An HMI can issue a command through its supported control interface, but the PLC or other designated controller should enforce the required logic, permissives, and interlocks.

Q4. What is an HMI tag?

A named data point associated with a controller variable, register, or other supported data source.

Q5. Why can an HMI show stale data?

The communication may have failed while the application continued displaying the last received value, or the application or data-update mechanism may have stopped refreshing.

Q6. What is the difference between an alarm and an event?

An alarm indicates a condition requiring attention. An event records an occurrence or state change, which may or may not require immediate action.

Q7. Why must HMI tag mapping be verified?

Incorrect mapping, data types, polarity, or scaling can display misleading information or send commands to unintended variables.

Q8. What should be checked if an HMI command is ignored?

Check whether the command was transmitted, received by the controller, permitted by the current machine state, accepted by the logic, and followed by the expected physical response.

Q9. Why is an HMI backup important?

It preserves the application configuration, screens, tags, alarms, and communication settings needed to restore or replace the interface.

Q10. Can an HMI touchscreen replace a physical emergency-stop button?

Not merely by displaying an emergency-stop graphic. Required emergency-stop functions must use the approved safety-related hardware and architecture.

Q11. What is the difference between an integrated CNC HMI and a separate HMI?

An integrated HMI is part of the CNC control environment. A separate HMI may require its own hardware, runtime, application, communication drivers, and operating-system maintenance.

Q12. Why might a replacement HMI not work with the original machine?

The replacement may differ in hardware compatibility, runtime version, communication drivers, licensing, supported protocols, or project format.

22. Practical HMI Installation and Maintenance Checklist

  • Verify the HMI model, revision, mounting, and environmental rating.
  • Confirm supply voltage, protective earth, and wiring.
  • Verify network connections and communication settings.
  • Confirm the correct application and runtime versions.
  • Check CNC and PLC connectivity.
  • Validate tag addresses, data types, scaling, and units.
  • Verify command feedback against actual machine feedback.
  • Test alarm display, acknowledgement, and reset behavior.
  • Confirm communication-loss and stale-data indication.
  • Check operator roles and engineering access restrictions.
  • Validate required safety functions independently.
  • Save the approved application and configuration backups.
  • Record commissioning results and configuration changes.
  • Review spare availability and obsolescence risks.
