1. Purpose and Scope of Machine Builder Integration

Machine builder integration is the engineering process of combining mechanical assemblies, electrical systems, CNC controls, PLC logic, drives, sensors, tooling, operator interfaces, safety systems, and software into a complete, functional machine.

A CNC controller or PLC working correctly in isolation does not guarantee that the complete machine will work correctly. Integration ensures that all subsystems communicate, follow the intended sequence, meet performance requirements, and operate safely.

For example, a CNC machine may contain:

  • CNC controller and machining software.
  • Machine PLC or CNC-integrated PMC.
  • Servo axes and spindle drive.
  • Tool magazine and automatic tool changer (ATC).
  • Hydraulic and pneumatic systems.
  • Coolant, lubrication, and chip-removal systems.
  • HMI and operator controls.
  • Industrial networks and remote I/O.
  • Safety relays, safety PLC, and safety-rated drive functions.
  • Measurement, probing, and process-monitoring systems.

Machine builder integration connects these systems into one coordinated machine.

2. Role of the Machine Builder

The machine builder is responsible for designing or integrating the machine as a complete product, according to the contractual scope and applicable requirements.

Typical responsibilities include:

  • Defining the machine architecture.
  • Selecting compatible components.
  • Designing mechanical and electrical interfaces.
  • Configuring the CNC and PLC.
  • Developing machine sequences and interlocks.
  • Integrating drives, sensors, actuators, and field devices.
  • Developing HMI screens and alarm messages.
  • Implementing the required safety functions.
  • Performing commissioning and functional testing.
  • Preparing drawings, manuals, backups, and maintenance instructions.
  • Supporting installation, acceptance, and handover.

Some functions may be supplied by specialist vendors. Responsibility boundaries must be explicitly documented because several suppliers can contribute to one machine without any single supplier automatically owning every interface.

4. Machine Builder Versus Component Vendor

Party Typical responsibility Example
CNC vendor CNC hardware, software, supported control functions Axis control and CNC diagnostics
PLC vendor PLC hardware, programming environment, supported communications CPU and I/O configuration
Drive vendor Drive hardware, parameters, supported motion functions Servo drive commissioning
Robot vendor Robot controller and robot-specific functions Robot motion and recovery
Machine builder Complete machine integration within contractual scope Tool-change sequence and machine interfaces
System integrator Integration of equipment or systems within an agreed scope Robot-to-CNC production cell
End user Operation, maintenance, local compliance, and change control within its responsibilities Preventive maintenance and production operation

The exact allocation depends on contracts, design authority, and applicable regulations. A supplier's component warranty does not automatically establish responsibility for the behavior of the complete integrated machine.

5. Requirements and Interface Definition

Integration begins with defining what the machine must do and how each subsystem will interact.

5.1 Functional Requirements

Typical requirements include:

  • Workpiece size and machining operations.
  • Axis travel and motion performance.
  • Spindle speed and power requirements.
  • Tool capacity and tool-change time.
  • Required accuracy and repeatability.
  • Production cycle time.
  • Coolant, lubrication, and chip-removal requirements.
  • Operator access and setup requirements.
  • Required communication with factory systems.
  • Maintenance access and spare-parts requirements.

Requirements should be measurable wherever practical.

For example, a requirement stating that the machine must achieve a specified cycle time should also define the part, machining program, tool configuration, operating conditions, and measurement method.

5.2 Interface Definition

An interface specifies how two subsystems connect and interact.

Examples include:

  • Mechanical mounting dimensions.
  • Electrical supply and protection.
  • Digital and analog I/O assignments.
  • CNC-PLC handshake signals.
  • Communication protocol and addressing.
  • Pneumatic pressure and connection requirements.
  • Hydraulic pressure and flow requirements.
  • Safety-related signals and responsibilities.
  • Software version and parameter compatibility.

5.3 Interface Control Document

An Interface Control Document (ICD) records the agreed interface details between systems or suppliers.

A useful ICD may contain:

  • Interface identification.
  • Sending and receiving systems.
  • Signal or data name.
  • Electrical or communication characteristics.
  • Normal state and polarity.
  • Data type and scaling.
  • Timing and timeout requirements.
  • Fault response.
  • Ownership and responsible supplier.
  • Verification method.
  • Revision and approval history.

The ICD prevents different suppliers from implementing incompatible assumptions about the same interface.

6. Machine Design Integration

6.1 Mechanical Integration

Mechanical integration ensures that components fit, align, and operate within the intended physical limits.

Typical checks include:

  • Mounting and alignment.
  • Axis travel and mechanical limits.
  • Tool and workpiece clearances.
  • Cable carrier routing.
  • Lubrication access.
  • Coolant and chip-flow paths.
  • Guarding and access doors.
  • Maintenance and replacement access.
  • Vibration and thermal effects.

A mechanical design change can affect electrical wiring, sensor positions, cable lengths, CNC travel limits, and PLC sequence timing.

6.2 Electrical Integration

Electrical integration combines power distribution, control wiring, field devices, and protective systems.

Typical activities include:

  • Verifying supply voltage and current requirements.
  • Coordinating protection and disconnect devices.
  • Integrating motors, drives, contactors, and braking arrangements.
  • Verifying I/O module compatibility.
  • Confirming sensor supply and output types.
  • Establishing protective bonding and grounding.
  • Implementing cable segregation and EMC practices.
  • Verifying panel and machine wiring against approved drawings.

Electrical compatibility must be verified using the actual component specifications rather than connector appearance alone.

6.3 Control Integration

Control integration ensures that the CNC, PLC, drives, and auxiliary systems execute the intended sequence.

Typical activities include:

  • Establishing controller responsibilities.
  • Configuring I/O and communications.
  • Implementing permissives and interlocks.
  • Developing startup and shutdown behavior.
  • Implementing alarm and fault recovery logic.
  • Defining machine states and operating modes.
  • Coordinating axis, spindle, and auxiliary functions.
  • Verifying reset and restart behavior.

7. CNC, PLC, and Drive Integration

7.1 CNC and Machine PLC

The CNC usually manages machining-program execution and coordinated motion, while the machine PLC or CNC-integrated PMC commonly manages auxiliary sequences.

Their interface may include:

  • Cycle-start requests.
  • Machine-ready status.
  • Feed-hold and cycle-stop status.
  • Tool-change requests and completion.
  • Spindle-related requests and feedback.
  • Machine alarms.
  • Axis-position or in-position conditions.
  • Mode and sequence information.

The actual signal names and ownership vary by CNC platform.

7.2 PLC and Servo Drives

Integration requires correct drive configuration, communication, and motion-related status handling.

Verify:

  • Drive identity and firmware compatibility.
  • Motor and feedback-device compatibility.
  • Network or fieldbus configuration.
  • Enable and ready signals.
  • Fault reporting and reset behavior.
  • Motion limits and reference procedures.
  • Braking and stopping behavior.
  • Supported safety functions.

A drive that communicates with the PLC may still be incorrectly configured for the motor or mechanical axis.

7.3 Spindle Integration

Spindle integration may involve speed references, enable requests, speed feedback, orientation, braking, and tool-change permissives.

Typical verification includes:

  • Correct motor and drive data.
  • Rotation direction.
  • Speed command and feedback scaling.
  • Required acceleration and deceleration behavior.
  • Spindle orientation where used.
  • Overload and drive-fault response.
  • Coordination with the tool-change sequence.

Testing must use the machine-builder's approved procedure and respect mechanical speed limits.

8. Tool Changer and Auxiliary System Integration

An automatic tool changer is a useful example of multi-subsystem integration.

The CNC may request a tool change, the PLC coordinates the sequence, sensors confirm the mechanism position, actuators move the changer, and the HMI reports the resulting status.

A typical conceptual sequence is:

CNC REQUESTS TOOL CHANGE
          ↓
PLC CHECKS REQUIRED CONDITIONS
          ↓
SPINDLE AND AXES REACH REQUIRED STATES
          ↓
TOOL-CHANGE MECHANISM OPERATES
          ↓
POSITION AND CLAMP FEEDBACK VERIFIED
          ↓
PLC COMPLETES CNC HANDSHAKE
          ↓
CNC RESUMES APPROVED SEQUENCE

The actual sequence depends on the machine design.

The same integration principle applies to:

  • Pallet changers.
  • Automatic doors.
  • Hydraulic clamping.
  • Pneumatic fixtures.
  • Coolant systems.
  • Chip conveyors.
  • Lubrication systems.
  • Part-loading robots.
  • In-process measurement equipment.

Each sequence requires clear ownership of commands, feedback, timeout behavior, and fault recovery.

9. Robot-to-CNC Integration

A production cell may include a robot that loads and unloads workpieces from a CNC machine.

The robot and CNC must coordinate their operating states and physical access.

Typical exchanged signals include:

  • Robot ready.
  • CNC ready for loading.
  • Door-open request and confirmation.
  • Robot inside machine status.
  • Workpiece loaded or unloaded.
  • Clamp confirmation.
  • Cycle-start request.
  • Cycle-complete status.
  • Fault and recovery status.

A conceptual sequence is:

CNC CYCLE COMPLETE
          ↓
MACHINE REACHES APPROVED LOAD STATE
          ↓
ACCESS CONDITIONS VERIFIED
          ↓
ROBOT LOADS / UNLOADS PART
          ↓
PART POSITION AND CLAMPING CONFIRMED
          ↓
ROBOT CLEARS MACHINE AREA
          ↓
DOOR AND REQUIRED CONDITIONS VERIFIED
          ↓
CNC CYCLE PERMITTED

The sequence must be supported by the machine's actual mechanical arrangement and safety design.

Robot and CNC signals alone are not necessarily sufficient to establish safe access. Required protective measures must be designed and validated for the integrated cell.

10. HMI and Alarm Integration

The HMI should present a consistent view of the integrated machine.

Important considerations include:

  • Common naming for machine states.
  • Consistent alarm codes and descriptions.
  • Clear identification of the affected subsystem.
  • Distinction between command and confirmed feedback.
  • Appropriate operator and maintenance permissions.
  • Clear recovery instructions.
  • Visibility of communication faults.
  • Accurate display of cycle and production status.

A useful integrated alarm should identify what failed, where it failed, and what diagnostic information is available.

For example, “Tool change incomplete” is more useful when accompanied by the active sequence step and the missing completion condition.

Alarm text must not instruct personnel to bypass safety devices or perform unsafe recovery actions.

11. Safety Integration and Risk Assessment

Safety integration addresses hazards created by the complete machine and its interactions, not merely the individual components.

Relevant hazards may include:

  • Rotating spindle and tools.
  • Moving axes.
  • Tool-changing mechanisms.
  • Robot movement.
  • Crushing and trapping points.
  • Ejected workpieces or tools.
  • Stored hydraulic or pneumatic energy.
  • Electrical shock.
  • Unexpected restart.
  • Maintenance access to hazardous areas.

11.1 Safety Functions

Depending on the risk assessment and machine architecture, functions may include:

  • Emergency stop.
  • Guard monitoring and interlocking.
  • Prevention of unexpected restart.
  • Safe torque off (STO).
  • Safe operating modes.
  • Safety-related speed monitoring.
  • Safe access and isolation arrangements.

Not every machine requires every listed function. Selection and implementation depend on the risk assessment and applicable requirements.

11.2 Standard Control Versus Safety Control

A standard PLC may coordinate normal operating sequences, but standard PLC logic alone does not establish a safety-rated function.

Safety-related functions require suitable components, architecture, engineering, and validation. Communication between the robot, CNC, and PLC must not be treated as a substitute for required protective measures.

11.3 Safety Validation

Validation should confirm that the implemented safety functions achieve the required behavior under normal operation and relevant fault conditions.

The validation plan should identify the function, initiating condition, expected response, test method, result, and approval record.

12. Software and Version Compatibility

Integrated machines often contain several software and firmware components.

Examples include:

  • CNC software.
  • PLC firmware and program.
  • HMI runtime and project.
  • Drive firmware and parameters.
  • Remote I/O firmware.
  • Robot controller software.
  • Network switch configuration.
  • Safety-controller project.
  • Measurement and inspection software.

12.1 Compatibility Matrix

Maintain a compatibility matrix for the installed system.

Component Information to record Why it matters
CNC Model, software version, options Program and interface compatibility
PLC CPU, firmware, project version Program execution and I/O compatibility
HMI Model, runtime, project version Display and communication compatibility
Servo drive Model, firmware, parameters Motor and motion compatibility
Remote I/O Model, firmware, configuration I/O and network compatibility
Robot Controller, software, program revision Cell interface and motion compatibility
Safety system Hardware and approved project revision Safety-function integrity
Network switch Model, firmware, configuration Communication and topology behavior

A component update may require coordinated updates elsewhere. A software change that appears local can affect timing, data types, communications, and sequence behavior.

12.2 Change Management

Before a change:

  1. Identify the existing approved configuration.
  2. Record the problem and intended change.
  3. Assess hardware, software, safety, and production impacts.
  4. Obtain the required authorization.
  5. Back up all affected components.
  6. Implement the change under controlled conditions.
  7. Test affected functions and interfaces.
  8. Update the compatibility matrix and documentation.
  9. Preserve the final approved configuration.

Do not assume that a new firmware version is automatically compatible with the existing machine project.

13. Factory Acceptance Test and Site Acceptance Test

13.1 Factory Acceptance Test (FAT)

FAT is performed at the supplier's facility before shipment or delivery, according to the agreed acceptance plan.

Typical checks include:

  • Machine configuration against the specification.
  • Basic functional operation.
  • CNC and PLC sequences.
  • I/O and communication checks.
  • Alarm behavior.
  • Tool-change and auxiliary functions.
  • Required safety tests within the FAT scope.
  • Sample machining or process tests where specified.
  • Documentation and backup delivery.

FAT scope should identify which functions can be fully tested at the supplier site and which require site utilities, installation, or customer-specific integration.

13.2 Site Acceptance Test (SAT)

SAT verifies the machine after installation at the intended site.

Typical checks include:

  • Installation and utility connections.
  • Electrical supply and protective bonding.
  • Network and factory-system connectivity.
  • Machine alignment and setup.
  • Functional operation under site conditions.
  • Required safety validation.
  • Production trials and acceptance criteria.
  • Operator and maintenance training.
  • Final documentation and handover.

Passing FAT does not automatically establish that SAT requirements have been satisfied.

14. Commissioning Strategy

A staged commissioning plan reduces the risk of diagnosing several interacting faults simultaneously.

A practical sequence is:

  1. Mechanical inspection and installation verification.
  2. Electrical power and wiring verification.
  3. Controller and hardware configuration checks.
  4. I/O verification.
  5. Network and communication checks.
  6. Individual drive and actuator checks.
  7. CNC-PLC interface testing.
  8. Manual-function testing under controlled conditions.
  9. Sequence and interlock testing.
  10. Fault and recovery testing.
  11. Safety-function validation.
  12. Automatic cycle testing.
  13. Production and acceptance trials.
  14. Documentation and handover.

The order may be adjusted to suit the machine architecture and approved commissioning plan. Safety requirements apply throughout commissioning, not merely at the end.

16. Integration Failure Analysis

When an integrated machine fails, classify the fault before replacing components.

Useful fault categories include:

  • Mechanical: Misalignment, obstruction, excessive friction, damaged mechanism.
  • Electrical: Missing supply, incorrect wiring, damaged cable, failed output device.
  • Instrumentation: Faulty sensor, incorrect range, wrong polarity, unstable feedback.
  • Control logic: Incorrect sequence, missing permissive, timer error, faulty state transition.
  • Communication: Network failure, configuration mismatch, protocol fault, stale data.
  • Software compatibility: Firmware mismatch, incorrect project version, incompatible parameters.
  • Safety-related: Fault in a protective device, safety controller, or validated safety function.
  • Process-related: Incorrect setup, workpiece, tooling, recipe, or machining conditions.

A fault can span several categories. For example, a tool-change timeout may be caused by a mechanical obstruction, a failed sensor, incorrect I/O mapping, or a PLC sequence error.

17. Root Cause Analysis and Corrective Action

Integration faults should be resolved through evidence-based diagnosis.

A practical workflow is:

  1. Record the exact symptom and operating conditions.
  2. Identify the affected machine function and subsystem.
  3. Collect alarms, status data, and event history.
  4. Reproduce the fault only under an approved safe procedure.
  5. Identify the first condition that deviates from expected behavior.
  6. Determine the root cause rather than only the visible symptom.
  7. Implement the corrective action.
  8. Verify the original fault is resolved.
  9. Test related functions and possible side effects.
  10. Update drawings, software versions, and maintenance records.

For example, replacing a sensor may restore operation, but the root cause may be cable damage caused by poor routing. Corrective action should address the routing issue if supported by the evidence.

18. Documentation and Handover

A complete handover package should contain the records needed to operate, maintain, diagnose, and recover the integrated machine.

Typical deliverables include:

  • Final electrical schematics.
  • Mechanical drawings and assembly documentation.
  • CNC, PLC, HMI, and robot backups where applicable.
  • Drive parameters and motor data.
  • Network architecture and addressing records.
  • I/O lists and signal mapping.
  • Interface Control Documents.
  • Safety documentation and validation records.
  • FAT and SAT results.
  • Alarm lists and troubleshooting procedures.
  • Operating and maintenance manuals.
  • Preventive maintenance requirements.
  • Spare-parts list and approved alternatives.
  • Software and firmware compatibility matrix.
  • Training records.
  • Open-issue and deviation register.
  • Change history and final acceptance approvals.

Handover is incomplete if the machine works but the customer cannot restore its software or identify the installed components.

19. Spare Parts and Lifecycle Management

The machine builder and end user should define spare-parts and support arrangements within their respective responsibilities.

Important items include:

  • CNC CPU and supported replacement hardware.
  • PLC CPU and I/O modules.
  • HMI panel and compatible runtime.
  • Servo and spindle drives.
  • Remote I/O adapters.
  • Industrial switches and communication modules.
  • Sensors and actuator interfaces.
  • Safety components.
  • Power supplies and interface relays.
  • Special cables, connectors, and adapters.

For each item, record the installed model, manufacturer, firmware where relevant, approved successor, configuration requirements, lead time, and replacement procedure.

A replacement should be assessed for functional and safety compatibility, not merely physical fit.

20. Practical Integration Case Study

Scenario: A CNC machine is integrated with a robot for automatic loading. The CNC completes machining, but the robot does not begin unloading.

Step 1: Confirm the CNC state

Verify that the CNC has actually reached the defined cycle-complete state rather than merely displaying a finished program block.

Step 2: Check the interface signal

Monitor the signal that informs the robot or cell controller that unloading may begin.

Step 3: Verify machine permissives

Check whether the CNC, PLC, door system, fixture, and robot controller agree on the required machine state.

Step 4: Check the access sequence

Determine whether the required access or door sequence has completed and whether the robot has received the correct authorization.

Step 5: Check communication and acknowledgements

Compare the request, acknowledgement, and completion signals at both endpoints. Identify whether one controller is waiting for a condition the other never asserts.

Step 6: Investigate the first missing transition

Use PLC monitoring, robot diagnostics, CNC status, and event history to identify the earliest deviation from the expected sequence.

Step 7: Correct and validate

Repair the confirmed cause and test the complete load/unload sequence, fault handling, recovery behavior, and relevant safety functions under the approved procedure.

Do not force the robot to enter the machine or bypass the access interlocks to restore the cycle.

21. Interview Questions and Answers

Q1. What is machine builder integration?

It is the process of combining mechanical, electrical, control, software, communication, and safety subsystems into a complete functional machine.

Q2. Why can individually functional components fail when integrated?

Their interfaces, timing, configuration, signal definitions, software versions, or operating assumptions may be incompatible.

Q3. What is an Interface Control Document?

A controlled record defining how two systems interact, including signals, electrical characteristics, communication details, timing, fault behavior, ownership, and verification.

Q4. What is the difference between FAT and SAT?

FAT verifies agreed functions at the supplier's facility. SAT verifies installation and operation at the intended site against the applicable acceptance requirements.

Q5. Why is CNC-PLC handshake testing important?

It confirms that the CNC and machine PLC agree on requests, acknowledgements, completion states, and fault handling.

Q6. How should a tool-change timeout be diagnosed?

Identify the active sequence step, requested output, physical mechanism state, expected feedback, permissives, timer status, and CNC handshake state.

Q7. What is a compatibility matrix?

A record of installed hardware, firmware, software versions, parameters, and approved combinations used to prevent incompatible changes.

Q8. Why must safety be assessed at machine level?

The complete machine may create hazards through interactions between otherwise compliant components, so protective functions must address the integrated system.

Q9. What is the difference between a symptom and a root cause?

A symptom is the observed failure. The root cause is the underlying condition that produces it and must be addressed to prevent recurrence.

Q10. What should be included in machine handover?

Approved drawings, software backups, parameters, network and I/O records, safety documentation, acceptance results, manuals, maintenance instructions, spare-parts information, and change records.

Q11. Why might a replacement PLC or HMI not work with the existing machine?

Hardware, firmware, software runtime, communication drivers, I/O mapping, licensing, or project compatibility may differ.

Q12. How should machine cycle-time problems be investigated?

Measure the actual sequence, identify delays and waiting states, compare against the defined requirements, and determine whether the limiting factor is motion, logic, communication, tooling, or auxiliary equipment.

Q13. Why is a reset not always sufficient to recover a machine?

The initiating fault may still exist, the sequence state may be invalid, or the machine may require a specific recovery procedure before operation can safely resume.

Q14. What is the purpose of a controlled commissioning sequence?

It allows subsystems and interfaces to be verified progressively, making faults easier to isolate and reducing the risk of unsafe or confusing interactions.

22. Practical Machine Builder Integration Checklist

  • Confirm functional requirements and acceptance criteria.
  • Identify system boundaries and responsible suppliers.
  • Verify mechanical and electrical interfaces.
  • Approve I/O lists and interface definitions.
  • Confirm CNC, PLC, HMI, drive, and robot compatibility.
  • Verify network architecture and communication settings.
  • Validate sequences, interlocks, timeouts, and fault handling.
  • Confirm safety functions and required validation records.
  • Complete the agreed FAT and SAT procedures.
  • Investigate faults using evidence and root cause analysis.
  • Maintain approved software and configuration backups.
  • Update drawings, network records, and compatibility matrices.
  • Prepare maintenance instructions and spare-parts information.
  • Complete operator and maintenance training.
  • Obtain required acceptance and handover approvals.
