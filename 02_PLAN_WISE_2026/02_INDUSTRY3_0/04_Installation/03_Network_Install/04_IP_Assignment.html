1. Definition and purpose

IP assignment is the process of allocating and configuring Internet Protocol (IP) addresses for devices connected to an IP network.

In industrial automation, IP addresses enable devices such as PLCs, HMIs, robot controllers, remote I/O adapters, VFDs, industrial PCs, SCADA servers, and managed switches to communicate over Ethernet-based networks.

Correct IP assignment is essential for:

  • Establishing communication between automation devices.
  • Preventing duplicate-address conflicts.
  • Separating machine, cell, and plant networks.
  • Enabling engineering access and diagnostics.
  • Supporting SCADA, data collection, and remote monitoring.
  • Controlling traffic between network segments.
  • Maintaining reliable communication after device replacement.
  • Documenting and troubleshooting production networks.

An Ethernet link can be physically healthy while IP communication fails because of an incorrect address, subnet mask, VLAN, route, or firewall rule.

Static IP Address configured manually or assigned through a controlled reservation process
DHCP Dynamic Host Configuration Protocol, used to supply IP configuration automatically

ARP Address Resolution Protocol, which resolves IPv4 addresses to link-layer addresses on a local network

Loopback address Address used by a device to refer to itself, such as IPv4 127.0.0.1

3. IPv4 address structure

An IPv4 address contains 32 bits and is normally written as four decimal octets separated by dots.

Example:

192.168.10.25

Each octet ranges from 0 to 255.

The binary representation is:

192       . 168       . 10        . 25
11000000  . 10101000  . 00001010  . 00011001

The subnet mask or prefix length determines which bits identify the network and which identify the host.

For example, 192.168.10.25/24 means that the first 24 bits identify the network.

IP address:  192.168.10.25
Prefix:      /24
Mask:        255.255.255.0
Network:     192.168.10.0
Broadcast:   192.168.10.255
Host range:  192.168.10.1 to 192.168.10.254

This example assumes a conventional IPv4 /24 subnet. The usable host range and special-address rules vary with the prefix length and network design.

4. Private IPv4 address ranges

Private IPv4 ranges are commonly used for internal industrial networks.

Private range Prefix Common context
10.0.0.0 to 10.255.255.255 /8 Large enterprise and plant networks
172.16.0.0 to 172.31.255.255 /12 Enterprise and industrial networks
192.168.0.0 to 192.168.255.255 /16 Small networks and machine cells

These are the three standard private IPv4 address ranges.

Private addresses are not directly globally routable on the public Internet. However, they still require planning inside an organisation.

Important precautions

  • Do not choose a subnet solely because it is commonly used by factory equipment.
  • Check whether the range already exists elsewhere in the plant.
  • Consider VPNs, remote engineering, vendor access, and future network integration.
  • Avoid duplicate or overlapping subnets where routing between them is required.
  • Follow the plant's approved IP allocation plan.

A machine network using 192.168.0.0/24 may work in isolation but conflict with another machine or remote-access network using the same subnet.

5. Subnet masks and CIDR notation

A subnet mask defines the network portion of an IPv4 address.

CIDR notation represents the number of leading network bits using a slash followed by a number.

Prefix Subnet mask Total IPv4 addresses Conventional usable host addresses
/8 255.0.0.0 16,777,216 16,777,214
/16 255.255.0.0 65,536 65,534
/24 255.255.255.0 256 254
/25 255.255.255.128 128 126
/26 255.255.255.192 64 62
/27 255.255.255.224 32 30
/28 255.255.255.240 16 14
/30 255.255.255.252 4 2

The conventional usable-host calculation excludes the network and broadcast addresses in ordinary IPv4 subnets. Special-purpose links and particular subnetting arrangements can use different rules.

5.1 Calculating subnet size

For an IPv4 prefix length \(p\), the total number of addresses is:

\[ N = 2^{32-p} \]

For a conventional subnet where both the network and broadcast addresses are excluded:

\[ H = 2^{32-p}-2 \]

For a /24 network:

\[ H = 2^{32-24}-2 = 254 \]

5.2 Practical example

A machine cell needs 20 IPv4 host addresses.

A /27 subnet provides 32 total addresses and 30 conventional usable host addresses, which meets this requirement.

A /28 subnet provides only 14 conventional usable host addresses, so it would be too small.

Allow for future expansion and network infrastructure such as management interfaces, gateways, and diagnostic devices when choosing the subnet size.

6. Determining whether two devices are on the same subnet

Devices with correctly configured addresses in the same IPv4 subnet can normally communicate directly at Layer 2, assuming the VLAN, physical connectivity, and other relevant settings are correct.

Consider these addresses:

  • PLC: 192.168.10.10/24
  • HMI: 192.168.10.20/24

Both are in the 192.168.10.0/24 subnet.

Now consider:

  • PLC: 192.168.10.10/24
  • HMI: 192.168.20.20/24

These addresses belong to different /24 subnets. Communication between them generally requires a router or Layer 3 device and suitable routing and security rules.

A default gateway is not normally needed for communication between devices in the same subnet. It is typically required when a device must send traffic to destinations outside its local subnet.

Common configuration error

An engineer changes a PLC from 192.168.10.10/24 to 192.168.20.10/24 but leaves the HMI at 192.168.10.20/24.

The Ethernet link may remain active, but the devices may no longer communicate directly as intended. Correct the addressing plan rather than repeatedly replacing cables or switches.

7. Static IP assignment

A static IP address is manually configured on a device or maintained through a controlled network configuration process.

Static addressing is common for industrial equipment that must remain reachable at a known address.

Typical examples include:

  • PLC Ethernet interfaces.
  • HMI panels.
  • Robot controllers.
  • Remote I/O adapters.
  • Managed switches.
  • SCADA servers.
  • Industrial PCs and gateways.
  • VFDs and servo drives with Ethernet interfaces.

7.1 Advantages

  • Predictable device addressing.
  • Easier mapping between IP addresses and equipment.
  • Suitable for devices referenced by fixed communication configurations.
  • No dependency on a DHCP server for the device to obtain its configured address.

7.2 Limitations

  • Manual configuration takes time.
  • Incorrect settings can interrupt communication.
  • Duplicate addresses may occur if allocation is poorly managed.
  • Replacing a device may require restoring its network configuration.
  • Address changes must be reflected in dependent applications and documentation.

7.3 Static configuration fields

A typical IPv4 configuration may contain:

Field Example Purpose
IP address 192.168.10.10 Identifies the interface within the subnet
Subnet mask 255.255.255.0 Defines the local IPv4 subnet
Default gateway 192.168.10.1 Provides a next hop for off-subnet traffic
Preferred DNS 192.168.10.5 Resolves DNS names when required
Alternate DNS 192.168.10.6 Optional secondary DNS server

These are illustrative values, not a recommended configuration for every machine. The gateway and DNS fields may be unnecessary for an isolated machine network.

8. DHCP and automatic IP assignment

DHCP dynamically supplies IP configuration to compatible devices.

Depending on the network, a DHCP server can supply an IP address, subnet mask, default gateway, DNS servers, lease duration, and other options.

8.1 Basic DHCP sequence

The familiar DHCPv4 process is commonly described as DORA:

Client → DHCP Discover
Server → DHCP Offer
Client → DHCP Request
Server → DHCP Acknowledgment

This is the usual sequence for initial address allocation, although renewal, rebinding, and other DHCP exchanges can follow different paths.

8.2 Advantages

  • Reduces manual configuration effort.
  • Helps centralise address allocation.
  • Can reduce accidental duplicate assignments when properly managed.
  • Simplifies deployment for compatible devices.

8.3 Limitations in industrial systems

  • The device depends on a reachable DHCP service to obtain or renew configuration as required.
  • A device may receive a different address if the allocation policy permits it.
  • PLC communication paths and HMI configurations may expect a specific address.
  • DHCP relay, VLAN configuration, or server availability may affect address acquisition.
  • Device replacement may change the client's identity from the server's perspective.

Do not enable DHCP on an industrial device without checking the network design and application requirements.

9. Static addressing versus DHCP reservation

A DHCP reservation configures the DHCP server to assign a consistent address to a recognised client identity. This is different from manually setting a static address on the device.

Feature Manually configured static IP DHCP reservation
Address configured at Device interface DHCP server and client DHCP process
Requires DHCP service for allocation No Yes
Central allocation management Depends on external records Usually centralised
Risk of conflicts Possible if poorly coordinated Possible if reservation and address pools are mismanaged
Device replacement Configuration may need to be restored Reservation may need updating if the client identity changes
Suitable use Fixed industrial endpoints where approved Devices supported by a managed DHCP design

Both approaches can be reliable when properly planned. The choice depends on the equipment, plant policy, recovery requirements, and network infrastructure.

10. IP address planning for a machine network

IP planning should be completed before equipment is connected or commissioned.

10.1 Define network boundaries

Identify the intended subnet or subnets for:

  • Individual machines or cells.
  • Production-line networks.
  • Plant-level monitoring.
  • Engineering access.
  • Network management.
  • Any required routed connections.

The exact segmentation should follow the approved architecture and security policy.

10.2 Allocate address blocks

Reserve address ranges for known device groups and future expansion. Avoid assigning addresses randomly during commissioning.

Example of an illustrative /24 machine subnet:

Address range Intended use
192.168.10.1 Planned gateway, if required
192.168.10.2 to 192.168.10.19 Switches and network infrastructure
192.168.10.20 to 192.168.10.49 PLCs and remote I/O
192.168.10.50 to 192.168.10.79 HMIs and operator stations
192.168.10.80 to 192.168.10.119 Robots, drives, and other automation devices
192.168.10.120 to 192.168.10.199 Engineering and approved integration devices
192.168.10.200 to 192.168.10.253 Reserved capacity for planned expansion
192.168.10.255 Broadcast address for this /24 subnet

This is an example allocation scheme, not a universal industrial convention. Each assigned address must be checked against actual network usage and infrastructure requirements.

10.3 Avoid address overlap

Overlapping subnets can cause routing ambiguity and connectivity problems, particularly when connecting previously isolated machines to a plant network or remote engineering environment.

Before integration, verify the subnets at both ends of the connection, including VPNs and vendor support networks where applicable.

11. IP assignment procedure for PLCs and industrial devices

The exact interface varies by manufacturer, device family, firmware, and engineering software. The following is a general procedure.

Step 1: Collect device information

Record:

  • Manufacturer and model.
  • Device name and physical location.
  • Ethernet interface or port.
  • MAC address, if available.
  • Current IP configuration.
  • Required communication partners.
  • Applicable network and security requirements.

Step 2: Confirm the approved address

Obtain the intended IP address, subnet mask or prefix, and gateway configuration from the network plan.

Do not choose an address merely because it responds to a ping or appears unused at that moment. An address may be reserved, temporarily offline, or assigned to a device that is not currently connected.

Step 3: Check for existing use

Use approved network records and diagnostic methods to check for duplicate-address risk.

A ping test alone cannot prove that an address is unassigned. A powered-off device, firewall rule, or isolated VLAN can hide existing use.

Step 4: Configure the device

Depending on the product, configuration may be performed through:

  • The device's local display.
  • A web interface.
  • Vendor engineering software.
  • A device discovery or commissioning tool.
  • An approved DHCP service.

Some devices require a specific procedure to assign the address initially.

Step 5: Verify the settings

Check the configured IP address, subnet mask, gateway, and any other required fields. Confirm that the configuration was saved and persists after a restart where the device's procedure permits verification.

Step 6: Verify communication

Test connectivity from the intended network location and confirm the application-level communication.

For a PLC and HMI, successful ping responses do not necessarily prove that the HMI driver, PLC service, or application data exchange is working.

Step 7: Record the result

Update the IP allocation register, device configuration records, network drawing, and relevant machine documentation.

12. Address assignment on Siemens, Allen-Bradley, and Mitsubishi equipment

Different automation platforms use different engineering tools and device discovery methods.

Platform Common configuration context Important considerations
Siemens TIA Portal, device configuration, and supported online-access or discovery functions Verify the configured interface, device name where applicable, IP settings, and project consistency
Allen-Bradley Studio 5000 Logix Designer, FactoryTalk tools, and supported module or device configuration utilities Distinguish controller Ethernet ports, communication modules, and embedded switch or DLR interfaces
Mitsubishi GX Works and supported Ethernet parameter or device configuration functions Verify the CPU or module's supported Ethernet settings and the communication partner configuration
Industrial HMI Panel configuration or the manufacturer's engineering software Verify both the HMI interface settings and the PLC destination address
Managed switch Web interface, command-line interface, or vendor management software Distinguish the switch management address from the addresses of devices connected to its ports

Exact procedures differ between models and software versions. Never assume that assigning an IP address to a PLC automatically configures every Ethernet module or device connected to it.

Important distinction: IP address versus device name

Some industrial protocols use a device name or other identity during commissioning in addition to IP addressing.

For example, certain PROFINET configurations use a device name to identify and commission a device. The device name and IP address serve different purposes; changing one does not necessarily update the other.

13. Default gateway and routing

The default gateway is the next-hop router a device uses when its IP stack determines that a destination is outside the local subnet and no more specific route applies.

Example:

PLC:             192.168.10.10/24
HMI:             192.168.10.20/24
Default gateway: 192.168.10.1

The PLC and HMI are in the same subnet, so ordinary local communication does not need to pass through the gateway.

If the PLC needs to communicate with a destination in 192.168.20.0/24, a suitable router and routing configuration are generally required.

Common gateway mistakes

  • Configuring a gateway that is not reachable on the local network.
  • Using a gateway address outside the intended local subnet.
  • Omitting a gateway when off-subnet communication is required.
  • Assuming that setting a gateway automatically permits traffic through firewalls.
  • Configuring a gateway on an isolated network where none is needed.

A gateway setting does not create a physical connection, establish a route on other devices, or bypass network security controls.

14. DNS and name resolution

DNS translates domain names or hostnames into IP addresses when the relevant name records and client configuration support the lookup.

For example:

scada-server.example.local → 192.168.10.50

Industrial devices may communicate directly through configured IP addresses instead of DNS names. In such systems, DNS may not be required for basic PLC-to-HMI communication.

DNS becomes relevant when devices or applications use hostnames, domain services, centralised servers, or other name-based connections.

Troubleshooting should distinguish between:

  • Failure to resolve a name.
  • Failure to reach the resolved IP address.
  • Failure of the application service at that address.

A DNS problem does not necessarily indicate an Ethernet or IP-routing fault.

15. MAC addresses, ARP, and duplicate IP addresses

15.1 MAC address

A MAC address is a link-layer identifier associated with a network interface. Ethernet switches commonly use source MAC addresses to learn which devices are reachable through their ports.

A MAC address and an IP address are not interchangeable.

  • The MAC address supports communication over the local Ethernet segment.
  • The IP address supports logical addressing and routing across IP networks.

15.2 ARP

ARP is used by IPv4 devices to resolve the link-layer address associated with a destination IPv4 address on the local network.

For a remote destination, a host typically resolves the MAC address of its next-hop gateway rather than the remote host's MAC address.

15.3 Duplicate IP addresses

A duplicate IP occurs when two devices use the same IPv4 address in a network where those assignments conflict.

Possible symptoms include:

  • Intermittent communication.
  • Connections reaching the wrong device.
  • Duplicate-address warnings.
  • ARP entries changing between different MAC addresses.
  • Unexpected loss of PLC, HMI, or engineering access.

15.4 Troubleshooting a duplicate address

  1. Confirm the affected IP address and subnet.
  2. Check the approved address allocation register.
  3. Review duplicate-address warnings and relevant logs.
  4. Inspect ARP information from an appropriate device.
  5. Identify the MAC addresses associated with the conflicting address.
  6. Trace the devices to their physical switch ports using authorised diagnostics.
  7. Determine which device should own the address.
  8. Correct the incorrect assignment through the approved change process.
  9. Verify communication and update the records.

Do not randomly change the IP address of a production PLC or robot controller. The address may be referenced by multiple applications and configuration files.

16. Static routes and multiple network interfaces

Some industrial PCs, gateways, and controllers have multiple network interfaces.

Example:

Industrial PC
  Interface 1 → Machine Network
  Interface 2 → Plant Monitoring Network

Multiple interfaces can provide access to separate networks, but they introduce routing and security considerations.

Potential problems include:

  • Overlapping subnets.
  • Incorrect interface metrics or route selection.
  • Traffic leaving through the unintended interface.
  • Unintended routing between machine and plant networks.
  • Multiple default gateways creating ambiguous or unexpected paths.
  • Firewall rules that differ between interfaces.

Do not connect an industrial PC to multiple networks without an approved design. Dual-homing a computer does not automatically create a safe or correctly routed network boundary.

Static routes may be required for particular designs, but their destination prefixes, next hops, and return paths must be planned together.

17. IPv6 awareness

IPv6 uses 128-bit addresses and supports a much larger address space than IPv4.

Example of an IPv6 address:

2001:db8:10::25

IPv6 introduces concepts including:

  • Prefix lengths such as /64.
  • Link-local addresses.
  • Global and unique local addressing.
  • Neighbor Discovery.
  • Stateless Address Autoconfiguration (SLAAC).
  • DHCPv6, where supported and required.
  • IPv6 routing and firewall policies.

The 2001:db8::/32 range is reserved for documentation examples and is not intended for ordinary production addressing.

Many industrial installations primarily use IPv4, but IPv6 may still be enabled by default on engineering PCs or other equipment. Follow the site's policy rather than enabling or disabling IPv6 indiscriminately.

18. IP address assignment and cybersecurity

IP assignment is part of network security because addresses, network boundaries, and access rules influence which devices can communicate.

Good practices include:

  • Maintain an approved IP allocation register.
  • Restrict access to address-management functions.
  • Use network segmentation according to the security design.
  • Limit engineering access to authorised devices and paths.
  • Avoid exposing machine networks directly to untrusted networks.
  • Use approved remote-access and VPN arrangements.
  • Monitor unexpected devices and address changes where supported.
  • Keep switch, firewall, and routing configurations under change control.
  • Protect configuration backups and management credentials.

An IP address is not a security credential. A device does not become trusted simply because it has an address from the expected subnet.

19. IP assignment tools and commands

Use diagnostic tools appropriate to the operating system, device, and site permissions.

19.1 Windows IP configuration

ipconfig
ipconfig /all

These commands display network interface configuration. The /all option provides additional details such as MAC addresses, DHCP status, and configured DNS servers.

19.2 Ping

ping 192.168.10.10

Ping tests whether the destination responds to ICMP echo requests.

A failed ping does not prove that the device is disconnected. ICMP may be blocked, disabled, or filtered, and the device may still support its required application protocol.

19.3 ARP information

arp -a

This displays available IPv4-to-MAC mappings in the local ARP cache.

ARP information can help investigate local-network reachability and possible duplicate-address conditions, but the results are not a complete inventory of every device on the network.

19.4 Route information

route print

This displays the Windows routing table and helps identify the routes and interfaces used to reach destinations.

19.5 Path diagnostics

tracert 192.168.20.10

This attempts to show the IP hops toward a destination. Some network devices do not respond to the probes, so missing responses do not necessarily mean the route is broken.

19.6 Port and application testing

Test-NetConnection 192.168.10.10 -Port 44818

This PowerShell command tests TCP connectivity to the specified destination port. Port 44818 is commonly associated with EtherNet/IP explicit messaging, but the actual service and port requirements must be verified for the device and application.

A successful TCP connection does not prove that the industrial application is configured correctly or that every required protocol function is operational.

20. Commissioning checklist

Before assignment

  • Obtain the approved network plan.
  • Verify the device model and Ethernet interface.
  • Record the device name and MAC address where available.
  • Confirm the intended subnet and address range.
  • Check for overlapping subnets and duplicate-address risk.
  • Identify required gateway and DNS settings.
  • Confirm VLAN membership and routing requirements.
  • Arrange authorisation for changes to production equipment.

During assignment

  • Configure the approved address.
  • Enter the correct subnet mask or prefix.
  • Configure the gateway only as required.
  • Configure DNS or other network options where required.
  • Save the settings using the manufacturer's procedure.
  • Confirm the configuration is applied to the correct interface.
  • Avoid changing unrelated network settings.

After assignment

  • Verify the configured address and mask.
  • Check for duplicate-address symptoms.
  • Test local and routed reachability as appropriate.
  • Verify the required application communication.
  • Check switch-port status and relevant diagnostics.
  • Confirm the settings persist where required.
  • Update the IP register and network drawings.
  • Record any exceptions or unresolved faults.

22. Practical example: PLC, HMI, and SCADA

A machine uses a PLC and HMI on a machine subnet. A gateway provides approved access to a separate SCADA network.

Illustrative configuration:

Device IP address Subnet mask Default gateway
PLC 192.168.10.10 255.255.255.0 192.168.10.1
HMI 192.168.10.20 255.255.255.0 192.168.10.1
Machine switch management 192.168.10.2 255.255.255.0 192.168.10.1
Machine gateway interface 192.168.10.1 255.255.255.0 Depends on gateway routing design
SCADA server 192.168.20.50 255.255.255.0 According to SCADA network design

The addresses are examples only. They must be replaced by addresses from the actual approved network plan.

Expected communication

  • The PLC and HMI are on the same subnet and can communicate directly when the relevant network and application settings are correct.
  • The switch management address allows authorised management access but is not required for ordinary Layer 2 frame forwarding.
  • Communication between the machine subnet and SCADA subnet requires suitable routing and security rules.
  • Configuring a default gateway alone does not establish the required end-to-end communication.

Example troubleshooting sequence

If the HMI can communicate with the PLC but SCADA cannot obtain data:

  1. Verify that PLC-to-HMI communication remains normal.
  2. Check the PLC's and gateway's IP configuration.
  3. Verify that the gateway has a valid route to the SCADA subnet.
  4. Check the return route from the SCADA network.
  5. Verify VLANs, access-control rules, and firewalls.
  6. Test the specific application service required by SCADA.
  7. Review relevant diagnostics and logs.
  8. Record the root cause and update the network documentation.

This approach separates a local machine communication problem from a routed network or application problem.

23. IP address register template

Maintain one authoritative record of assigned network addresses. Avoid multiple spreadsheets with conflicting values, an unfortunate but common way to turn a simple network into a detective novel.

Field Example

Location Cell 01 control panel
Ethernet interface CPU Ethernet port
MAC address Recorded from the actual device
IP address 192.168.10.10
Subnet mask 255.255.255.0
Default gateway 192.168.10.1

VLAN According to the approved design
Communication partners HMI, remote I/O, SCADA gateway

The register should distinguish planned addresses from verified installed addresses. It should also record who authorised significant changes and when they were made, according to site policy.

24. Interview questions and answers

1. What is an IP address?

An IP address is a logical address used to identify a network interface for communication over an IP network.

2. What is the difference between an IP address and a MAC address?

An IP address provides logical network addressing. A MAC address is a link-layer identifier used for communication on the local Ethernet segment.

3. What is the purpose of a subnet mask?

It determines which IPv4 address bits identify the subnet and which identify the host portion.

4. What is the purpose of a default gateway?

It provides the next hop for traffic destined outside the local subnet when no more specific route applies.

5. What is the difference between static IP and DHCP?

Static addressing is manually configured on the device. DHCP dynamically supplies IP configuration from a DHCP server.

6. What is a DHCP reservation?

It is a server-side configuration intended to provide a consistent address to a recognised DHCP client.

7. Why can two devices with the same IP address cause intermittent faults?

Their conflicting network identities can cause traffic to reach the wrong device or result in changing address-resolution information.

8. Can two devices with different IP addresses communicate if they have different subnet masks?

They may communicate in some configurations, but inconsistent masks can cause incorrect local-versus-remote decisions. Both devices should use the approved subnet configuration.

9. Is a default gateway required for PLC-to-HMI communication?

Not normally when both devices are correctly configured on the same subnet and communicate directly. A gateway may be required for destinations outside that subnet.

10. Does a successful ping prove that the PLC application is working?

No. Ping verifies ICMP reachability, not the correctness of the required application protocol, data mapping, or application logic.

11. What should be checked if a device is unreachable after assigning an IP?

Check the active interface, IP address, subnet mask, duplicate-address risk, VLAN, physical link, routing, firewall rules, and application requirements.

12. Why is an IP allocation register important?

It provides a controlled record of assigned addresses and their associated devices, reducing conflicts and shortening troubleshooting time.

25. Final engineering principles

  • Obtain addresses from an approved allocation plan.
  • Verify subnet masks and prefix lengths rather than copying settings from unrelated devices.
  • Use static addressing or DHCP according to the device and network requirements.
  • Check duplicate-address and overlapping-subnet risks before commissioning.
  • Configure gateways, DNS, and routes only where required.
  • Distinguish local Ethernet connectivity from IP routing and application communication.
  • Treat IP addresses, MAC addresses, device names, and VLAN assignments as different configuration elements.
  • Use diagnostic commands as evidence, not as absolute proof of network health.
  • Apply production changes under the site's authorisation and rollback procedures.
  • Update the IP register and as-built network records after every approved change.

Core principle: IP assignment is not simply entering four numbers into a device. It is controlled network configuration that must preserve address uniqueness, subnet correctness, communication requirements, security boundaries, and maintainability.
