1. Definition and purpose

Network topology describes how network devices are physically connected and how data travels between them. In industrial automation, topology determines how PLCs, HMIs, robot controllers, remote I/O, drives, industrial PCs, and SCADA systems communicate.

A topology design must consider more than cable connections. It should address:

  • Communication requirements and traffic patterns.
  • Network availability and acceptable downtime.
  • Cable distance and physical installation constraints.
  • Bandwidth and latency.
  • Fault isolation and recovery.
  • Redundancy and recovery behaviour.
  • Network segmentation and security.
  • Maintenance access and future expansion.
  • Cost, complexity, and documentation.

A topology that works in a small test panel may be unsuitable for a production line with multiple robot cells and a shared plant network.

2. Physical and logical topology

2.1 Physical topology

Physical topology describes the actual cable paths and connections between devices.

Examples include:

  • One central switch connected to several devices.
  • Switches connected sequentially along a production line.
  • Switches connected in a physical ring.
  • Separate network paths between redundant switches.

2.2 Logical topology

Logical topology describes how communication is organised, forwarded, or separated, regardless of the exact cable arrangement.

Examples include:

  • VLAN-based separation.
  • Layer 2 broadcast domains.
  • Routed IP subnets.
  • Redundant logical paths.
  • Industrial protocol communication relationships.

A network can have a physical star topology but contain multiple logical VLANs. Conversely, a logical network can span multiple physical switches.

2.3 Physical versus logical topology example

Physical topology:

             Industrial Switch
              /      |      \
            PLC     HMI     Robot

Logical organisation:

VLAN 10 → PLC and machine control devices
VLAN 20 → Engineering access
VLAN 30 → Monitoring and data collection

The VLAN arrangement is illustrative. Actual VLANs and permitted communication must follow the plant network design.

4. Point-to-point topology

In a point-to-point topology, one device or network interface connects directly to another.

Device A ───────── Device B

Examples include:

  • A PLC connected directly to a programming computer.
  • A switch connected to another switch through a dedicated link.
  • Two devices communicating over a dedicated Ethernet connection.

Advantages

  • Simple to understand and troubleshoot.
  • No intermediate switch is required for the direct link.
  • Fault isolation is relatively straightforward.
  • Can provide a dedicated link between two endpoints.

Limitations

  • Connects only the endpoints served by that link.
  • The cable and endpoint interfaces become critical to communication.
  • A direct link does not automatically provide redundancy.
  • IP configuration may still be required for IP-based communication.

Practical example

An engineering laptop connects directly to a PLC Ethernet port for programming. The correct network interface, addressing, firewall settings, and PLC access permissions are still required.

5. Bus topology

A traditional bus topology connects multiple nodes to a shared communication medium.

Terminator ── Node A ── Node B ── Node C ── Terminator

Traditional shared-medium Ethernet used bus-like coaxial cabling. Modern switched Ethernet is generally not built as a shared coaxial bus.

Industrial systems may use bus topologies in other communication technologies, such as RS-485 networks and certain fieldbus systems. Some industrial Ethernet devices also provide multiple ports that permit line-like connections, but this does not make the physical Ethernet medium a traditional shared electrical bus.

Advantages

  • Can reduce cabling in systems designed for a shared medium.
  • May support multiple devices along a common communication line.
  • Can be cost-effective in appropriate fieldbus applications.

Limitations

  • A fault in the shared medium may affect multiple devices.
  • Termination and wiring rules can be critical for electrical buses.
  • Fault isolation can be more difficult.
  • Capacity and timing depend on the particular communication technology.

Important distinction: Do not apply RS-485 termination rules to ordinary switched Ethernet cabling. Ethernet and RS-485 use different physical-layer arrangements.

6. Star topology

In a star topology, each endpoint has a link to a central switch or other central network device.

             PLC
              |
HMI ───── Industrial Switch ───── Robot
              |
           Remote I/O
              |
          Plant Uplink

Advantages

  • Easy to identify which link serves each endpoint.
  • Failure of one endpoint cable usually affects that endpoint rather than every other device.
  • Adding or replacing a device is relatively straightforward.
  • Centralised diagnostics can simplify maintenance.
  • Fault isolation is usually easier than on a long daisy-chain arrangement.

Limitations

  • The central switch can be a single point of failure.
  • The switch requires sufficient port capacity.
  • Uplink capacity can become a bottleneck.
  • Central switch failure may disconnect every device attached to it.

Industrial application

Star topology is common inside control cabinets, robot cells, and machine networks.

A production cell may connect the PLC, HMI, robot controller, remote I/O, and engineering access port to one industrial switch.

7. Line or daisy-chain topology

In a line topology, devices or switches are connected sequentially.

Plant Network
      |
   Switch A
      |
   Switch B
      |
   Switch C
      |
   Switch D

This arrangement may use switches with multiple Ethernet ports or devices with integrated switching functions.

Advantages

  • Can reduce the number of separate home-run cables to a central switch.
  • Can simplify cable routing along a long machine.
  • May suit distributed equipment arranged along a production line.
  • Can reduce cabinet and cabling requirements in some designs.

Limitations

  • A broken link can isolate downstream devices.
  • Faults may affect multiple machines.
  • Traffic may traverse several intermediate devices.
  • Diagnostics can be more complex than in a simple star.
  • Recovery depends on the actual design and supported redundancy mechanism.

Example

A line of distributed machines uses a switch in each cabinet. Each cabinet connects to the next cabinet, and the final cabinet connects to the end device or another network segment.

Before selecting this design, determine what happens when a cable or intermediate switch fails.

8. Ring topology

A ring topology connects network nodes or switches in a closed loop.

        Switch A ───── Switch B
           |               |
           |               |
        Switch D ───── Switch C

A physical ring creates an alternative path, but the network requires an appropriate mechanism to prevent uncontrolled Layer 2 forwarding loops and manage recovery.

Advantages

  • Can provide an alternate path after a supported link or node failure.
  • May improve availability compared with a simple line.
  • Can suit distributed production equipment arranged along a route.

Limitations

  • Incorrect configuration can disrupt the network.
  • Recovery time depends on the protocol and failure type.
  • Not every switch supports every ring protocol.
  • Multiple failures can defeat the intended redundancy.
  • Troubleshooting and configuration management may be more demanding.

Industrial ring protocols

Examples include:

  • MRP: Media Redundancy Protocol, used by compatible industrial Ethernet equipment.
  • RSTP: Rapid Spanning Tree Protocol, used to manage certain redundant Layer 2 topologies.
  • Vendor-specific ring protocols: Supported by particular manufacturers and device families.

Do not assume these protocols are interchangeable. Confirm supported devices, roles, topology limits, and configuration requirements.

Ring commissioning

A ring should be tested under an approved procedure:

  1. Verify the topology and protocol support.
  2. Confirm all ring ports and roles are configured correctly.
  3. Check the normal operating state.
  4. Test the approved single-fault scenario.
  5. Measure recovery behaviour against the application requirement.
  6. Confirm devices resume normal communication.
  7. Restore the expected configuration and record the test.

A ring is not proven redundant merely because its cables form a circle.

9. Tree or hierarchical topology

A tree topology organises switches into levels, with a root or backbone connected to subordinate distribution points and access switches.

             Core Switch
             /         \
    Distribution A   Distribution B
       /      \         /      \
    Cell 1   Cell 2   Cell 3   Cell 4

Advantages

  • Supports expansion across large plants.
  • Separates network areas into manageable groups.
  • Allows centralised backbone connections.
  • Can help isolate faults to a production area.
  • Supports planned network segmentation.

Limitations

  • Failures in an upper-level switch or uplink can affect multiple downstream areas.
  • Backbone links can become bottlenecks.
  • More switches increase configuration and maintenance requirements.
  • Redundancy must be designed at the appropriate levels.

Industrial application

A plant may have a core switch in the main control room, distribution switches in production areas, and access switches inside machine cabinets.

This arrangement is useful when network infrastructure spans multiple production lines, buildings, or process areas.

10. Mesh topology

In a mesh topology, nodes have multiple interconnections. A full mesh connects every node to every other node; a partial mesh provides selected alternate paths.

        Switch A ───── Switch B
           |  \         /  |
           |    \     /    |
           |      \ /      |
        Switch C ───── Switch D

This diagram illustrates multiple interconnections rather than a recommended production configuration.

Advantages

  • Can provide multiple possible communication paths.
  • May improve resilience when alternate paths are correctly supported.
  • Can offer flexibility in large or specialised network designs.

Limitations

  • Requires more cabling and ports.
  • Increases configuration complexity.
  • Layer 2 loops must be controlled.
  • Routing or switching behaviour must be planned carefully.
  • Greater connectivity does not automatically guarantee higher availability.

Full mesh is uncommon as a simple design for ordinary machine-level Ethernet. Partial mesh or redundant uplinks are often more practical, depending on the required service.

11. Comparing common topologies

Topology Cabling complexity Fault isolation Redundancy potential Typical use
Point-to-point Low Simple Requires an alternate connection Direct device links
Bus Low in suitable shared-medium systems Can be difficult Depends on technology Legacy or specialised fieldbus networks
Star Moderate Usually straightforward Requires redundant equipment or paths Machine and cell networks
Line Low to moderate Downstream impact is possible Limited unless designed for recovery Distributed equipment along a production line
Ring Moderate Depends on diagnostics and protocol Yes, with compatible redundancy Industrial cells and distributed networks
Tree Moderate to high Depends on hierarchy and fault location Yes, when redundant links and devices are provided Plant and multi-cell networks
Mesh High Can be complex High potential with suitable design Specialised resilient networks

No topology is universally best. The correct choice depends on availability requirements, cost, latency, cable routes, equipment support, maintenance practices, and consequences of a network failure.

12. Redundant network architecture

Redundancy means providing an additional path or component so that a particular failure does not necessarily interrupt the required service.

Possible forms include:

  • Redundant network links.
  • Redundant switches.
  • Redundant power supplies.
  • Redundant fibre routes.
  • Redundant network interfaces.
  • Redundant control or supervisory systems.

12.1 Link redundancy

A second link can provide an alternate path, but only if the network supports and correctly manages it.

Connecting two ordinary Layer 2 paths without loop prevention can create a forwarding loop.

12.2 Switch redundancy

Two switches may provide an alternative connection point. However, endpoints, uplinks, addressing, and the selected redundancy mechanism must all support the intended design.

12.3 Physical route diversity

Two fibre cables placed in the same vulnerable tray may both fail in one incident. Where high availability is required, consider whether redundant paths are physically separated enough to reduce common-cause failures.

12.4 Common-cause failures

Redundant equipment can still fail together because of:

  • Shared power supplies.
  • Shared upstream switches.
  • Shared cable routes.
  • Common configuration errors.
  • Common environmental damage.
  • Incorrect firmware or design assumptions.

Redundancy should be assessed against the specific failure scenarios that matter to production.

13. Availability and recovery time

Availability describes how much of the required time a system or service is operational.

A simplified availability formula is:

\[ A = \frac{\text{Operating Time}}{\text{Operating Time}+\text{Downtime}} \]

For example, if a network service operates for 999 hours and is unavailable for 1 hour during a 1,000-hour observation period:

\[ A = \frac{999}{1000} = 0.999 \]

The observed availability is 99.9%.

This is a simple observation-based calculation. It does not predict future reliability or account for whether all outages have equal operational impact.

13.1 Mean time to repair

MTTR commonly refers to mean time to repair or restore, depending on the organisation's definition.

Lower repair time can improve availability, even without changing the topology. Clear cable labels, port maps, diagnostic logs, spare switches, and trained technicians can reduce restoration time.

13.2 Recovery time versus application tolerance

A network may recover its link quickly but still fail to meet the machine's operational needs if:

  • The PLC connection takes longer to re-establish.
  • An application session times out.
  • A device requires a restart.
  • Process data becomes stale.
  • Motion or production sequencing requires recovery.

Measure the application-level impact, not only the switch's reported network recovery time.

14. Bandwidth and traffic planning

Topology affects how much traffic travels through each link and switch.

Important factors include:

  • Number of endpoints.
  • Device transmission rates.
  • Frequency of data updates.
  • Packet size.
  • Multicast and broadcast traffic.
  • Engineering and diagnostic traffic.
  • SCADA polling and data logging.
  • Vision or high-volume data transfers.
  • Uplink capacity and oversubscription.

14.1 Example of uplink loading

Suppose a group of devices generates an aggregate average of 300 Mb/s of traffic that must pass through a 1 Gb/s uplink.

The nominal average utilisation is:

\[ U = \frac{300}{1000}\times100\\% = 30\\% \]

This does not guarantee acceptable performance. Traffic bursts, full-duplex directionality, packet-processing capacity, QoS, and traffic distribution also matter.

14.2 Oversubscription

Oversubscription occurs when the potential or offered traffic exceeds the capacity of a shared link or resource.

A design with many 1 Gb/s access ports and one 1 Gb/s uplink may experience congestion if several endpoints transmit heavily at the same time.

For normal PLC and HMI traffic, utilisation may be modest, but traffic from cameras, engineering systems, backups, and monitoring platforms should not be ignored.

15. Latency, jitter, and deterministic communication

Latency is the delay between sending and receiving data. Jitter is variation in that delay.

Industrial control applications may require predictable communication timing, particularly for motion control and synchronised devices.

Factors that can affect timing include:

  • Number of forwarding devices.
  • Switch forwarding behaviour.
  • Traffic congestion.
  • Packet prioritisation.
  • Device processing time.
  • Network protocol.
  • Link errors and retransmissions at higher layers.
  • Redundancy recovery events.
  • Traffic from non-control applications.

A low average ping time does not prove that a network meets a real-time control requirement. Appropriate protocol-specific diagnostics and timing measurements are needed.

16. Network segmentation and broadcast domains

Network segmentation separates traffic into distinct logical or physical areas.

Common methods include:

  • VLANs at Layer 2.
  • IP subnets and routing at Layer 3.
  • Physical separation.
  • Firewalls and access-control rules.
  • Industrial demilitarised zones (IDMZs), where required by the architecture.

16.1 Why segmentation matters

Segmentation can:

  • Reduce unnecessary broadcast traffic across the wider network.
  • Limit direct communication between unrelated devices.
  • Separate machine-control and business-system traffic.
  • Help restrict engineering access.
  • Make troubleshooting and monitoring more structured.

16.2 Important limitation

A VLAN does not automatically stop communication between devices within that VLAN, nor does it inherently enforce all security boundaries between VLANs.

Routing rules, firewalls, access controls, and other security measures may be required to enforce the intended policy.

17. Layer 2 versus Layer 3 network design

Layer 2 switching

Layer 2 switching forwards Ethernet frames using MAC addresses within the relevant switching domain.

It is commonly used inside machine networks and production cells.

Layer 3 routing

Layer 3 routing forwards IP packets between IP networks or subnets using routing information.

A router or Layer 3 switch may connect separate machine subnets while applying the appropriate routing policy.

Feature Layer 2 switching Layer 3 routing
Primary forwarding information MAC addresses IP addresses and routing table
Main function Forward frames within a Layer 2 network Forward packets between IP networks
Broadcast behaviour Broadcasts are forwarded within the applicable VLAN Routers do not normally forward ordinary Layer 2 broadcasts between subnets
Typical role Machine or cell switching Interconnecting IP subnets and enforcing network boundaries
Configuration needs VLANs and switch-port configuration where applicable IP addressing, routing, and potentially access controls

The precise division of functions depends on the equipment. Many managed switches support both Layer 2 and Layer 3 features.

18. Network topology and industrial protocols

Topology constraints vary by protocol and device implementation.

Protocol or technology Topology considerations
PROFINET Supports specified network arrangements and redundancy mechanisms depending on device capabilities and application
EtherNet/IP Topology options depend on devices, embedded switches, DLR support, and network design
EtherCAT Commonly uses line-oriented device connections; supported branching and redundancy depend on the hardware and implementation
Modbus TCP Uses standard Ethernet/IP connectivity; topology depends on the underlying switches, routers, and network design
OPC UA Uses IP connectivity; network topology must support endpoint reachability, security, and performance requirements
Standard TCP/IP monitoring Depends on the IP addressing, routing, firewall, and network availability design

18.1 Device-level support matters

A protocol may define a redundancy method, but a device without the required hardware or firmware cannot necessarily participate in that method.

Before selecting a topology, verify:

  • Protocol requirements.
  • Device interface capabilities.
  • Supported switch functions.
  • Redundancy compatibility.
  • Required timing and recovery behaviour.
  • Vendor-specific configuration rules.

19. Common topology failures and troubleshooting

Symptom Possible cause Investigation
One machine loses communication Endpoint cable, port, or device fault Check the affected endpoint and its direct network path
Several downstream devices fail Intermediate switch or upstream link failure Trace the shared path and inspect switch diagnostics
Entire cell loses communication Cell switch, power supply, or uplink failure Check switch status, power, uplink, and logs
Network becomes flooded Layer 2 loop or broadcast storm Check topology changes, loop indicators, and traffic counters
Communication fails after adding a cable Uncontrolled redundant path or incorrect connection Compare actual wiring with the approved topology
High latency under load Congestion, oversubscribed uplink, or excessive traffic Review utilisation, traffic distribution, and QoS
Recovery takes longer than expected Redundancy configuration or application timeout Measure network recovery and application restoration separately
Some devices cannot communicate across VLANs Incorrect VLAN, routing, or access-control configuration Verify port membership, routing, and security rules
Fibre uplink failure affects multiple cells Shared backbone link or transceiver fault Check optical diagnostics and upstream topology
Faults occur during maintenance Unplanned topology changes or undocumented connections Review change records and as-built drawings

19.1 Troubleshooting method

  1. Identify the affected devices and the time the fault started.
  2. Determine whether the fault affects one endpoint, a segment, or the whole network.
  3. Compare the actual topology with the approved drawing.
  4. Inspect power, link status, and physical connections.
  5. Review switch logs, interface counters, and relevant device diagnostics.
  6. Check for loops, VLAN changes, or failed uplinks.
  7. Test the suspected component or link using approved methods.
  8. Restore the network according to the recovery plan.
  9. Record the root cause and corrective action.

Do not change several topology or configuration settings simultaneously. That makes fault isolation unnecessarily difficult and can introduce additional failures.

20. Designing a topology for a production line

Topology selection should begin with operational requirements, not with whichever switch happens to be available in stores.

Step 1: Identify the communication endpoints

List the PLCs, HMIs, robot controllers, remote I/O, drives, industrial PCs, SCADA systems, and uplinks.

Step 2: Identify communication requirements

For each connection, determine:

  • Required data rate.
  • Communication protocol.
  • Expected traffic volume.
  • Timing and latency requirements.
  • Required availability.
  • Physical distance and cable route.
  • Environmental conditions.

Step 3: Identify failure consequences

Determine what happens if:

  • One endpoint cable fails.
  • One switch fails.
  • An uplink fails.
  • A backbone switch fails.
  • Power is lost to a network cabinet.
  • A redundant path becomes unavailable.

Step 4: Select the topology

Choose a star, line, ring, tree, or hybrid design that meets the requirements.

Step 5: Design redundancy and segmentation

Where required, select compatible redundancy mechanisms, VLANs, routing boundaries, and access controls.

Step 6: Validate the design

Check port capacity, uplink bandwidth, supported protocols, cable distances, switch compatibility, and recovery requirements.

Step 7: Commission and document

Test normal operation, approved failure scenarios, communication recovery, and application behaviour. Update the topology and port maps.

21. Practical example: robot production cell

Consider a production cell containing a PLC, robot controller, HMI, remote I/O, and a connection to the plant network.

A possible star arrangement is:

Plant Network
      |
Distribution Switch
      |
Cell Switch
  |    |     |     |
 PLC  HMI  Robot  Remote I/O

The cell switch provides a central connection point for the equipment.

Design considerations:

  • Confirm that every endpoint supports the selected Ethernet speed.
  • Check whether the robot and remote I/O require specific industrial protocol settings.
  • Determine whether the cell switch is a single point of failure.
  • Confirm the plant uplink has sufficient capacity.
  • Use the required VLAN and access-control design.
  • Decide whether redundant uplinks or switches are necessary.
  • Verify that a switch or uplink fault does not create an unacceptable production risk.
  • Record the switch port for each endpoint and the physical cable route.

If the cell requires continued communication after a single link failure, design and test a supported redundancy mechanism. Do not assume that adding a second cable will achieve this.

22. Network drawings and documentation

A topology drawing should allow a maintenance engineer to understand the network without having to discover every connection during a breakdown.

Useful records include:

  • Physical network topology.
  • Logical topology and VLAN assignments.
  • Switch names, models, and locations.
  • Port-to-device mapping.
  • Uplink and backbone connections.
  • Cable identifiers and routes.
  • Fibre-core allocation.
  • IP subnets and management addresses.
  • Redundancy protocol and configuration.
  • Network boundaries and security controls.
  • Link test and commissioning results.
  • Approved configuration backups.
  • Known single points of failure.
  • Recovery and rollback procedures.

Distinguish between the as-designed topology and the as-built topology. The as-built drawing must reflect the installed system, including authorised changes.

23. Standards and engineering references

Relevant standards and references depend on the network, devices, and project.

  • IEEE 802.3: Ethernet technology.
  • IEEE 802.1Q: VLAN tagging and related bridging functions.
  • IEEE 802.1w: Historical RSTP specification, incorporated into later IEEE bridging standards.
  • IEC 62439-2: Media Redundancy Protocol for supported industrial networks.
  • IEC 62439 series: High-availability industrial communication networks and redundancy technologies.
  • IEC 61784 series: Industrial communication profiles.
  • IEC 61158 series: Industrial communication networks and fieldbus specifications.
  • IEC 62443 series: Industrial automation and control system security.
  • Manufacturer manuals: Device-specific topology, redundancy, cabling, and commissioning requirements.

Standards and device capabilities evolve. Verify the applicable edition and the exact implementation before designing or modifying a production network.

24. Interview questions and answers

1. What is network topology?

It is the arrangement of network devices and their communication connections, including the physical cabling and logical forwarding structure.

2. What is the difference between physical and logical topology?

Physical topology describes actual device and cable connections. Logical topology describes how communication is organised, forwarded, or separated.

3. Which topology is commonly used inside an industrial control panel?

Star topology is common because devices connect to a central switch and individual links can generally be diagnosed independently.

4. What is the main disadvantage of a line topology?

A failed intermediate link or switch may isolate downstream devices, depending on the equipment and design.

5. Does a ring topology guarantee uninterrupted communication?

No. Correctly supported redundancy, compatible equipment, suitable configuration, and successful recovery testing are required.

6. What is a single point of failure?

A component whose failure can interrupt a required service because no effective alternative path or component is available.

7. What is the difference between a VLAN and a subnet?

A VLAN is a Layer 2 network segmentation mechanism. An IP subnet is a Layer 3 addressing concept. They are often mapped one-to-one, but this is not universally required.

8. Why can adding a cable create a network failure?

An unplanned connection may create a Layer 2 loop or an unintended network path, potentially causing broadcast storms or forwarding instability.

9. What is the difference between latency and jitter?

Latency is communication delay. Jitter is variation in that delay.

10. Why is a topology drawing important during breakdown maintenance?

It helps identify affected links, shared switches, upstream dependencies, and possible failure points, reducing the time needed to isolate a fault.

11. What is network convergence?

It is the process through which the network reaches a usable forwarding state after a topology change or failure.

12. How should a network topology be selected?

Evaluate communication requirements, availability, traffic, physical routes, equipment support, fault consequences, maintenance needs, security, and expansion plans.

25. Final engineering principles

  • Select a topology based on production requirements and failure consequences.
  • Distinguish physical connections from logical network organisation.
  • Identify single points of failure and assess common-cause failures.
  • Do not create redundant Layer 2 paths without a supported loop-prevention or redundancy design.
  • Verify bandwidth, latency, jitter, and recovery against application requirements.
  • Use VLANs, routing, and security controls according to the approved network architecture.
  • Test redundancy under controlled conditions.
  • Keep physical and logical topology drawings accurate.
  • Use switch diagnostics and systematic fault isolation during breakdowns.
  • Document every authorised topology change.

Core principle: A good industrial network topology provides the required communication performance and availability while remaining understandable, testable, and maintainable during real production faults.
