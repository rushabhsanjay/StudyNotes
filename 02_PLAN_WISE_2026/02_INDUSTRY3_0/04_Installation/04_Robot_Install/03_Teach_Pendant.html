1. Definition and purpose

A teach pendant is a handheld or portable operator interface used to interact with an industrial robot controller. It allows authorised personnel to jog robot axes, teach positions, create or edit robot programs, monitor status, diagnose faults, and perform controlled commissioning tasks.

Depending on the robot manufacturer and model, it may also be called a robot programming pendant, teach box, programming unit, or manual control pendant.

The teach pendant is not merely a screen with buttons. It is an operator interface that can include enabling devices, emergency-stop controls, mode selection, motion controls, and access to safety-related functions.

Typical uses include:

  • Teaching robot positions and paths.
  • Jogging individual axes or moving in a Cartesian coordinate system.
  • Creating and editing robot programs.
  • Selecting tools, work objects, and coordinate frames.
  • Monitoring alarms, I/O, and axis status.
  • Performing setup, recovery, and commissioning activities.
  • Checking payload, speed, and motion settings.
  • Viewing diagnostic information and system parameters.

Important: Exact functions, button layouts, safety features, and operating procedures vary by manufacturer and controller generation. Always use the applicable robot manual.

The pendant sends operator commands to the controller and displays the resulting status. The controller performs the actual motion control and enforces the configured operating restrictions.

The pendant does not directly control motor power in the way a simple switch controls a lamp. Motion commands are processed through the robot controller, drive system, and applicable safety functions.

Some modern systems use touchscreen interfaces, wireless programming devices, or separate hardware safety controls. A wireless or touchscreen interface must not be assumed to replace the required safety-rated hardware.

4. Teach pendant operating modes

The available modes depend on the robot system and the installed safety architecture.

Mode General purpose Typical restriction
Manual or teach mode Teaching positions and performing setup Reduced speed or other manual-mode safeguards may apply
Automatic mode Executing the production program Requires the applicable automatic-operation conditions
Remote or external mode Allows control from an external system Access and command permissions must be configured
Local mode Allows control from the local operator interface Behaviour depends on the controller design
Test or setup mode Supports designated commissioning or verification tasks Must follow the model-specific procedure

These labels are not universal. Some controllers use different mode names or combine mode selection with other access-control functions.

Key distinction: Selecting manual mode does not make every movement safe. The work area, enabling device, speed restrictions, tool, payload, and other hazards must still be considered.

5. Emergency-stop and enabling devices

5.1 Emergency-stop device

The pendant's emergency-stop control is intended to initiate the configured emergency-stop function when a hazardous situation requires it.

Important principles:

  • Keep the device accessible during manual operation.
  • Check its condition before use according to the approved procedure.
  • Never obstruct, tape down, or modify it.
  • Investigate unexpected emergency-stop events.
  • Resetting the device does not necessarily clear every fault or permit motion.
  • Verify the required restart conditions before resuming work.

An emergency stop is a risk-reduction measure, not a substitute for safe installation, guarding, or energy isolation.

5.2 Enabling device

Many industrial robot pendants have a three-position enabling device. Its intended behaviour is generally:

  • Released position: motion permission is not granted.
  • Intermediate held position: the required enabling condition may be satisfied.
  • Fully squeezed position: motion permission is removed.

The precise behaviour depends on the safety design and manufacturer. The enabling device is intended to stop permitted motion when the operator releases it or squeezes it beyond the specified position.

Never jam, tape, bypass, or mechanically defeat an enabling device. Do not assume that every pendant uses the same three-position arrangement.

5.3 Emergency stop versus enabling device

Feature Emergency-stop device Enabling device
Main purpose Initiate an emergency-stop function Permit movement under specified manual conditions
Typical use Hazardous situation requiring emergency stopping Manual jogging and teaching
Operator action Deliberately actuate to stop Maintain the required enabling position
Reset or recovery Requires the specified reset and restart procedure Releasing it removes the enabling condition
Safety role Part of the machine emergency-stop design Part of the manual-mode enabling design

These functions are not interchangeable. Their implementation and validation must follow the robot's safety documentation.

6. Teach pendant installation

The pendant is usually supplied with a dedicated cable and connector or an approved communication arrangement. Installation must preserve electrical integrity, mechanical protection, and the designed safety functions.

6.1 Pre-installation checks

  • Confirm the pendant is compatible with the controller model and generation.
  • Verify the correct part number and connector type.
  • Inspect the display, enclosure, keys, emergency-stop device, and enabling device.
  • Inspect the cable for cuts, crushing, kinks, or exposed conductors.
  • Confirm that the connector is clean and undamaged.
  • Review the pendant connection procedure in the controller manual.
  • Confirm the controller's required power state before connecting or disconnecting.
  • Verify the pendant's mounting or storage arrangement.

Some systems permit connection or disconnection only under specified power conditions. Do not assume hot-plugging is permitted.

6.2 Installation procedure

  1. Identify the correct controller pendant interface.
  2. Follow the manufacturer's isolation or power-state requirements.
  3. Inspect the pendant connector and controller receptacle.
  4. Align the connector using its keying and orientation features.
  5. Insert it without excessive force.
  6. Secure the locking mechanism.
  7. Route the cable to prevent crushing, snagging, or trip hazards.
  8. Position the pendant in an accessible and protected location.
  9. Restore power only as required by the approved procedure.
  10. Verify pendant recognition and basic function.

Do not force a connector that does not align. Incorrect insertion can damage pins or the connector housing.

7. Pendant cable management

The pendant cable may be exposed to repeated movement, handling, bending, and contact with machine structures.

Installation considerations include:

  • Maintain the specified bend radius.
  • Avoid sharp bends near the connector.
  • Provide appropriate strain relief.
  • Prevent the cable from being pinched by doors or guards.
  • Keep it clear of moving axes and tooling.
  • Avoid routing across walkways where practical.
  • Prevent contact with hot surfaces, coolant, oil, or sharp edges beyond its rating.
  • Do not use the cable to lift or carry the pendant.
  • Avoid unsupported hanging loads on the connector.
  • Keep the cable away from areas where vehicles or equipment can crush it.

A cable can fail internally even when the outer jacket looks normal. Intermittent pendant disconnections during movement may indicate conductor damage, connector wear, or a locking problem.

8. Pendant startup and recognition

After installation, the controller may detect the pendant automatically or require a particular startup sequence.

Verify:

  • The pendant powers up as expected.
  • The display is readable.
  • No unexplained hardware or communication fault is present.
  • The correct robot and controller information is displayed.
  • The required mode and access permissions are available.
  • Emergency-stop and enabling-device status are correctly indicated.
  • The controller reports the pendant as connected.
  • The pendant controls respond as specified.

If the pendant is not recognised, check its compatibility, cable, connector, controller interface, and diagnostic messages. Follow the model-specific procedure before replacing hardware.

9. Coordinate systems used during jogging

Robot jogging moves the robot in a selected coordinate system. Understanding the active coordinate system is essential because the same jog command can produce different physical movement depending on the selection.

9.1 Joint coordinates

Joint jogging commands movement of an individual robot axis.

Axis 1: Rotation of the base
Axis 2: Movement of the main arm
Axis 3: Movement of the forearm
Axis 4+: Wrist and additional axis movement

This is a simplified description. Actual axis functions depend on robot geometry.

Joint jogging is useful for:

  • Checking individual axis movement.
  • Moving away from a position using a controlled axis movement.
  • Performing certain maintenance and mastering procedures.
  • Diagnosing axis-specific motion problems.

9.2 World or base coordinates

World or base jogging commands movement relative to a defined reference coordinate system.

For example, a command to move along the positive X direction may correspond to a different physical direction depending on the coordinate system's orientation.

9.3 Tool coordinates

Tool-coordinate jogging commands movement relative to the active tool frame. This is useful when approaching a workpiece with a welding torch, gripper, dispensing nozzle, or other end effector.

If the tool frame is incorrect, the observed movement may differ from the operator's expectation.

9.4 Work-object or user coordinates

Some systems support a work-object or user-defined coordinate frame. This allows movement relative to a fixture, table, workpiece, or process reference.

9.5 Coordinate comparison

Coordinate system Motion reference Typical use
Joint Individual robot axes Axis checks and controlled positioning
World Defined global reference General setup and workcell movement
Base Robot base frame Movement relative to robot mounting
Tool Active end-effector frame Tool approach and process alignment
Work object or user frame Defined fixture or workpiece frame Teaching relative to the production task

Coordinate names and definitions vary across manufacturers. Verify the selected frame before jogging.

10. Manual jogging procedure

Manual jogging must be performed by trained and authorised personnel under the applicable robot operating procedure.

A typical controlled procedure is:

  1. Confirm the work area is clear and the robot can move without collision.
  2. Verify that guards, interlocks, and required safety measures are in the intended state.
  3. Select the approved manual operating mode.
  4. Verify the active coordinate system.
  5. Verify the active tool and payload configuration where applicable.
  6. Select a suitable low jogging speed.
  7. Maintain the required enabling condition.
  8. Apply short, deliberate jog commands.
  9. Observe the robot, tooling, cables, and nearby equipment.
  10. Stop movement before changing settings or approaching a hazard.
  11. Confirm the final position and system status.

Do not rely solely on the screen to judge physical clearance. The robot tool, payload, dress pack, and all moving links must be considered.

11. Teaching robot positions

A robot program often contains taught positions, motion instructions, speed settings, and process commands.

A taught position may include:

  • Joint values or Cartesian coordinates.
  • Tool frame selection.
  • Work-object or user frame selection.
  • Motion type.
  • Speed and blending parameters.
  • Configuration or posture information.
  • External-axis position.
  • Process-specific conditions.

The stored position is meaningful only in the context of the relevant robot configuration and reference frames.

11.1 Common motion types

Motion type General behaviour Typical application
Joint motion Moves joints toward the target configuration General repositioning
Linear motion Controls the tool path along a straight line in Cartesian space Welding, dispensing, approach paths
Circular motion Follows a defined circular or arc path Arc-shaped process paths
Spline or other advanced motion Follows a controller-supported continuous path Complex contour applications

The exact commands and path-planning behaviour are controller-specific. A joint move between two positions does not necessarily produce a straight-line tool path.

11.2 Position teaching workflow

  1. Select the correct program or create an approved new program.
  2. Verify tool and work-object frames.
  3. Jog to the intended position.
  4. Check the robot posture and nearby clearances.
  5. Record the position using the controller's teaching method.
  6. Configure the required motion instruction.
  7. Verify speed, blending, and process settings.
  8. Review the sequence for unintended motion.
  9. Test using the approved commissioning procedure.
  10. Save and back up the approved program.

12. Program editing and access control

Teach pendants may allow authorised users to create, edit, copy, delete, or execute programs.

Good practices include:

  • Confirm the active program before editing.
  • Check whether the controller is in edit, manual, or execution mode.
  • Save changes according to the approved workflow.
  • Use controlled program naming and revision records.
  • Avoid modifying production programs without authorisation.
  • Record parameter changes and their reasons.
  • Maintain backups before significant modifications.
  • Restrict access to configuration and safety-related functions.
  • Verify that the selected program is the intended one before testing.

A small edit to a position, speed, or frame can change the physical path substantially. Program review must consider the complete motion sequence, not just the edited line.

13. I/O monitoring through the pendant

Many teach pendants provide screens for monitoring digital inputs, digital outputs, analog signals, and communication data.

Typical examples include:

  • Gripper open and closed feedback.
  • Part-present sensors.
  • Fixture clamped feedback.
  • Robot ready and busy status.
  • Cycle start and cycle complete signals.
  • Weld enable or process-ready signals.
  • PLC handshake bits.
  • Fault and alarm states.

Diagnostic example

A robot program waits for a fixture-clamped input, but the program never advances.

A structured investigation is:

  1. Identify the exact input used by the program.
  2. Confirm its configured signal name and channel.
  3. Monitor the input status on the pendant.
  4. Verify whether the physical sensor or PLC signal changes.
  5. Check I/O mapping and communication status.
  6. Review the program's wait condition.
  7. Investigate the source of the missing signal.
  8. Correct the root cause and retest safely.

A signal shown as ON on the pendant does not by itself prove that the physical device is functioning correctly. Verify the full signal path when necessary.

14. Alarm and fault diagnosis

The teach pendant commonly displays alarms, event history, axis status, and diagnostic information.

Useful diagnostic details include:

  • Exact alarm code and text.
  • Alarm occurrence time.
  • Operating mode.
  • Active program and instruction.
  • Affected axis or subsystem.
  • Recent configuration changes.
  • Related PLC or peripheral faults.
  • Whether the fault is persistent or intermittent.

Common pendant-related faults

Symptom Possible cause Initial investigation
Pendant remains blank Power, cable, connector, or hardware fault Check approved connection and controller diagnostics
Pendant not recognised Compatibility or interface problem Verify model, cable, and controller interface
Keys respond intermittently Worn controls, contamination, or hardware fault Inspect and follow service procedure
Jogging unavailable Mode, enabling, safety, or drive condition Read status and alarms; verify required conditions
Unexpected jogging direction Incorrect frame or orientation assumption Verify active coordinate system and frame
Position data appears incorrect Wrong tool, work object, or configuration Check frame selection and robot configuration
Communication is intermittent Cable damage or connector problem Inspect cable routing, strain relief, and connectors
Emergency-stop status remains active Actuated device or safety-system condition Follow the approved emergency-stop recovery procedure
Program cannot be edited Access rights, mode, or program protection Verify authorised access and controller state
I/O status does not change Wiring, mapping, PLC, or field-device fault Trace the signal path from source to controller

Never clear alarms repeatedly without investigating why they occurred. Some faults indicate a condition that must be corrected before movement is permitted.

15. Pendant safety during commissioning

Teach-pendant operation often places the operator closer to the robot than automatic production operation does. This makes work-area awareness and procedural discipline essential.

  • Use the required manual operating mode and speed restrictions.
  • Verify the enabling device and emergency-stop functions according to the approved test procedure.
  • Keep clear of crush, shear, trapping, and reach hazards.
  • Consider the entire robot arm, tool, payload, and dress pack.
  • Avoid standing between the robot and fixed structures.
  • Do not enter a safeguarded area without the required authorisation and protective measures.
  • Never defeat guard interlocks or safety functions.
  • Use energy isolation for maintenance tasks that require hazardous-energy control.
  • Follow the site's lockout/tagout procedure where applicable.
  • Ensure all personnel are clear before permitted movement.
  • Confirm that safety validation has been completed before releasing the cell for production.

An emergency stop does not necessarily isolate electrical, pneumatic, hydraulic, or stored mechanical energy. Maintenance and intervention work may require additional isolation measures.

16. Pendant storage and preventive maintenance

The pendant is a frequently handled device and may be exposed to impact, dirt, oil, and repeated cable movement.

Routine inspection should include:

  • Display condition and readability.
  • Key and selector condition.
  • Emergency-stop actuator condition.
  • Enabling-device operation according to the approved procedure.
  • Cable jacket and strain relief.
  • Connector locking and pin condition.
  • Housing cracks or damaged seals.
  • Signs of moisture or chemical exposure.
  • Storage hook or holder condition.
  • Correct labelling and identification.

Store the pendant in its designated holder when not in use. Do not leave it where it can fall, be run over, become entangled in machinery, or be exposed to coolant.

Any damaged safety-related control must be assessed and repaired or replaced under the authorised maintenance procedure before the pendant is returned to service.

17. Pendant replacement or controller migration

When replacing a pendant, confirm compatibility rather than selecting one based only on connector appearance.

Verify:

  • Controller model and generation.
  • Pendant part number and hardware revision.
  • Firmware or software compatibility.
  • Required interface or adapter.
  • Supported functions and safety devices.
  • Configuration or setup requirements.
  • Approved connection and startup procedure.
  • Required functional tests after replacement.

A pendant from another controller family may have a similar appearance but use a different interface or support different functions.

After replacement, perform the manufacturer-prescribed checks, including the applicable emergency-stop, enabling-device, display, communication, and manual-operation checks. Do not release the system until the required tests are passed.

18. Practical teach pendant inspection checklist

Before use

  • Correct pendant for the controller.
  • Display and controls undamaged.
  • Cable and connector free from visible damage.
  • Connector secured correctly.
  • Emergency-stop device inspected according to procedure.
  • Enabling device inspected according to procedure.
  • Correct operating mode selected.
  • Active tool and coordinate frame verified.
  • Robot work area checked for hazards.

During operation

  • Jog speed appropriate for the task.
  • Enabling condition maintained as required.
  • Robot, tool, and dress pack observed.
  • Motion commands applied deliberately.
  • Alarms investigated rather than repeatedly reset.
  • Program and parameter changes controlled.

After use

  • Robot left in the required safe state.
  • Program changes saved and recorded.
  • Relevant alarms and defects documented.
  • Pendant stored in its designated holder.
  • Cable routed without crushing or trip hazards.
  • Required backup or handover records updated.

19. Interview questions and answers

1. What is a teach pendant?

A handheld or portable operator interface used to jog, teach, program, monitor, and diagnose an industrial robot through its controller.

2. What is the difference between joint and Cartesian jogging?

Joint jogging commands individual robot axes. Cartesian jogging commands movement relative to a selected coordinate frame, such as world, base, tool, or work-object coordinates.

3. Why must the active tool frame be verified?

The tool frame defines the reference orientation and location of the end effector. An incorrect tool frame can cause unexpected tool movement or positioning errors.

4. What is the purpose of a three-position enabling device?

It provides a manual-operation enabling function with defined actuator positions. The exact permitted state and stop behaviour depend on the safety design.

5. Is the enabling device the same as an emergency-stop device?

No. The enabling device controls permission for specified manual movement, while the emergency-stop device initiates the designated emergency-stop function.

6. Why might the robot refuse to jog?

Possible causes include an incorrect operating mode, unmet enabling conditions, an active safety stop, a drive fault, or a controller configuration problem.

7. Why can a joint move produce a curved tool path?

The controller moves the robot joints toward the target configuration. The resulting end-effector path is not necessarily a straight line.

8. What should be checked if pendant communication is intermittent?

Inspect compatibility, cable condition, connector locking, strain relief, controller diagnostics, and the manufacturer's connection requirements.

9. Can the teach pendant replace a safety PLC?

Not automatically. Safety functions must be provided by the approved safety architecture and validated for the required safety performance.

10. What must be verified after replacing a pendant?

Compatibility, connection, controller recognition, display and control functions, required safety-related functions, and all prescribed post-replacement tests.

20. Core principles

  • Treat the teach pendant as both a programming interface and an operator control device.
  • Verify the controller model and pendant compatibility before installation.
  • Protect the cable, connector, controls, and enclosure from damage.
  • Understand the active coordinate frame before jogging.
  • Verify the tool, work object, payload, and program before teaching positions.
  • Diagnose faults using exact alarms and the approved manual.
  • Never bypass the enabling device, emergency stop, or guard interlocks.
  • Control program edits and maintain approved backups.
  • Complete required functional checks after installation or replacement.
  • Follow the robot manufacturer's procedures and site safety requirements.
