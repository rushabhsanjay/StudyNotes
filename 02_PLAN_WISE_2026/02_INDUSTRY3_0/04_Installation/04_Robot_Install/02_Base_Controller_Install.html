1. Definition and purpose

Robot base and controller installation covers the mechanical positioning, electrical installation, grounding, interconnection, environmental protection, and commissioning preparation of an industrial robot's base-mounted equipment and robot controller.

The robot base provides the mechanical interface between the robot and its supporting structure. The robot controller is the control cabinet or integrated control unit that executes robot motion control, processes feedback from the robot axes, manages I/O, and communicates with other automation equipment.

These are separate installation tasks, even though they must work together as one system.

The main objectives are:

  • Install the robot base and associated mounting interfaces according to the approved design.
  • Position and secure the controller cabinet in an appropriate location.
  • Provide the required electrical supply, protective earthing, and bonding.
  • Connect robot power, feedback, communication, and peripheral cables correctly.
  • Maintain ventilation, environmental protection, and service access.
  • Integrate the controller with PLCs, safety systems, HMIs, networks, and process equipment.
  • Preserve manufacturer-required cable lengths, routing, and connector arrangements.
  • Prepare the system for controlled commissioning and safety validation.

Important distinction: The robot base is a mechanical structure. The robot controller is the electronic control system. Installing either one correctly does not establish that the complete robot cell is ready for operation.

3. Robot base versus robot controller

Item Robot base Robot controller
Primary function Supports the robot mechanically Controls robot motion and system functions
Main installation concern Strength, rigidity, alignment, fastening Power, grounding, cooling, wiring, configuration
Typical components Base plate, mounting interface, locating features Controller electronics, drives, power supplies, processors
Main failure risks Looseness, deformation, vibration, misalignment Electrical faults, overheating, communication loss, drive faults
Verification Mechanical inspection and dimensional checks Electrical inspection, configuration checks, diagnostic tests
Documentation Foundation and mounting records Electrical drawings, cable schedules, parameter and backup records

Some robot models integrate parts of the controller into the robot structure or use a compact controller. The specific hardware arrangement must be confirmed from the model documentation.

4. Robot base installation

The robot base must provide a stable reference for the robot and transfer operating loads into the foundation or supporting structure.

4.1 Installation requirements

Before installing the base, verify:

  • Correct robot model and base configuration.
  • Approved foundation and mounting drawings.
  • Base dimensions and mounting-hole pattern.
  • Surface flatness and cleanliness.
  • Required locating pins or alignment features.
  • Specified mounting bolts and anchor arrangement.
  • Required tightening sequence and torque.
  • Cable entry and routing clearances.
  • Access for maintenance and future removal.
  • Compatibility with the intended robot orientation.

The base and foundation must be treated as one structural system. A strong base installed on an unsuitable foundation can still produce movement or excessive vibration.

4.2 Base installation procedure

  1. Verify the installation drawing and manufacturer instructions.
  2. Inspect the foundation, base plate, fasteners, and locating features.
  3. Confirm that the foundation has passed the required acceptance checks.
  4. Position the base using the approved lifting and handling method.
  5. Align the mounting interface with the specified reference.
  6. Install the required anchors and fasteners.
  7. Complete levelling, shimming, or grouting only where specified.
  8. Tighten fasteners using the prescribed procedure.
  9. Verify the base position, orientation, and mechanical security.
  10. Record inspection results and any deviations.

Do not use uncontrolled shimming, excessive bolt tightening, or improvised modifications to compensate for an incorrectly prepared foundation.

5. Robot controller installation location

The controller cabinet contains sensitive electronic and power components. Its location affects cooling, reliability, accessibility, electrical safety, and maintenance.

5.1 Environmental requirements

Check the controller manufacturer's specifications for:

  • Permitted ambient temperature.
  • Relative humidity and condensation limits.
  • Required ingress protection.
  • Dust, oil mist, coolant, and chemical exposure.
  • Vibration and shock limits.
  • Required cooling-air clearance.
  • Maximum installation altitude, where specified.
  • Electromagnetic compatibility requirements.
  • Restrictions on direct sunlight or nearby heat sources.

Do not assume that a controller designed for an industrial cabinet can tolerate direct exposure to welding spatter, conductive dust, or coolant.

5.2 Location selection

Choose a location that provides:

  • Adequate front and side access for maintenance.
  • Required clearance above and below ventilation openings.
  • Access to approved power isolation devices.
  • Short, correctly routed robot cables within specified length limits.
  • Suitable separation from high-temperature equipment.
  • Protection from vehicle movement, forklifts, and mechanical impact.
  • Appropriate access for programming and diagnostic work.
  • Space for cable bends, connectors, and gland plates.
  • Suitable routing to PLCs, network switches, safety equipment, and peripherals.

A controller installed too far from the robot may exceed the manufacturer's permitted cable length. A controller placed too close to a heat source may overheat even when the room temperature appears acceptable.

6. Controller cabinet mounting

Controller cabinets may be floor-standing, wall-mounted, integrated into a machine enclosure, or installed on a designated equipment frame.

6.1 Mechanical checks

  • Confirm the cabinet mass and required support capacity.
  • Verify the mounting orientation.
  • Inspect the cabinet enclosure for damage.
  • Confirm the floor or supporting structure is level and stable.
  • Check anchoring and anti-tip requirements.
  • Maintain specified cooling and service clearances.
  • Ensure doors can open fully.
  • Confirm that cable entries do not interfere with cabinet mounting.
  • Check that the cabinet does not obstruct emergency exits or required access routes.

6.2 Cabinet installation procedure

  1. Verify the cabinet layout and installation drawings.
  2. Inspect the cabinet, doors, locks, filters, and cable-entry plates.
  3. Confirm the mounting surface and support structure.
  4. Position the cabinet using approved handling equipment.
  5. Secure the cabinet using the specified mounting arrangement.
  6. Verify levelling, alignment, and mechanical stability.
  7. Install approved cable glands, plates, and environmental seals.
  8. Verify cooling clearances and service access.
  9. Confirm that enclosure protection has not been compromised.
  10. Record the installation inspection.

Do not drill new cabinet openings without checking the manufacturer's restrictions and the effects on ingress protection, electromagnetic compatibility, internal clearances, and structural integrity.

7. Electrical supply requirements

Robot controllers may contain servo drives, power supplies, control electronics, braking circuits, and auxiliary equipment. Their supply requirements must be taken from the controller's electrical documentation.

Verify:

  • Rated supply voltage.
  • Number of phases.
  • Rated current and maximum input current.
  • Frequency.
  • Short-circuit current rating and required upstream protection.
  • Required isolator and protective devices.
  • Protective conductor requirements.
  • Neutral requirements, if applicable.
  • Permitted supply arrangements.
  • Power quality requirements.
  • Any dedicated auxiliary supplies.

Do not select an upstream breaker solely from the robot's nominal motor power. The controller's input characteristics, inrush current, manufacturer recommendations, cable sizing, and installation conditions also matter.

7.1 Basic three-phase power relationship

For a balanced three-phase load, an approximate relationship is:

\[ P = \sqrt{3} V_L I_L \cos\phi \]

Where:

  • \(P\) = real electrical power in watts.
  • \(V_L\) = line-to-line voltage in volts.
  • \(I_L\) = line current in amperes.
  • \(\cos\phi\) = power factor.

This relationship is useful for basic estimation. It is not sufficient by itself to size a robot controller supply or protective devices because actual input characteristics, efficiency, harmonics, duty, and manufacturer requirements must also be considered.

7.2 Supply verification

Before energisation, qualified personnel should verify:

  • Correct supply voltage and phase arrangement.
  • Correct conductor sizing and termination.
  • Protective device ratings and suitability.
  • Protective earthing continuity.
  • Required insulation and electrical tests.
  • Correct phase sequence where relevant.
  • Tightness of terminals according to the manufacturer's procedure.
  • Correct isolation and labelling.
  • Absence of exposed conductors and damaged insulation.

Electrical testing and energisation must follow the approved site procedure. Do not perform resistance or insulation tests through connected electronic equipment unless the manufacturer explicitly permits the test method.

8. Protective earthing and bonding

Protective earthing provides a path for fault current and supports operation of the electrical protection system. Bonding helps maintain electrical continuity between conductive parts.

Robot systems may include:

  • Controller protective earth.
  • Robot base earthing or bonding connection.
  • Cabinet doors and conductive panels.
  • External equipment frames.
  • Cable shield bonding.
  • Process equipment bonding.
  • Equipotential bonding between interconnected structures.

The exact requirements depend on the system design and applicable electrical standards.

8.1 Installation principles

  • Use the specified protective conductor size and termination.
  • Connect designated protective-earth points.
  • Ensure conductive mounting interfaces meet the approved bonding requirements.
  • Remove paint or coatings only where the approved bonding design requires it.
  • Use specified terminals, washers, and fasteners.
  • Prevent corrosion at bonding interfaces.
  • Verify continuity using the approved test method.
  • Record results where required.

Protective earth and cable shielding are not interchangeable. A cable shield may be bonded as part of the EMC design, but it must not be treated as a replacement for the protective conductor.

Never disconnect protective earth to troubleshoot noise or communication problems.

9. Controller ventilation and thermal management

Robot controllers can generate significant heat through servo drives, power electronics, transformers, power supplies, and internal components.

Poor cooling can cause:

  • Drive or controller overtemperature alarms.
  • Reduced component life.
  • Unplanned shutdowns.
  • Intermittent faults during high-duty operation.
  • Thermal derating.
  • Increased fan and filter maintenance.

9.1 Cooling checks

  • Confirm the specified mounting clearances.
  • Keep air inlets and outlets unobstructed.
  • Verify cabinet fans and filters are installed correctly.
  • Check that hot exhaust air is not recirculated into the intake.
  • Confirm cabinet cooling equipment has the required capacity.
  • Maintain the permitted ambient temperature.
  • Check filter condition and fan operation.
  • Avoid storing tools or materials in ventilation spaces.

If the controller is installed inside another enclosure, verify the complete enclosure's thermal design. The outer enclosure may require forced ventilation or a cooling unit.

The exact arrangement varies by manufacturer and controller generation.

11. Robot-to-controller cabling

The robot and controller may be connected by several cable groups. Some models use combined cable assemblies, while others use separate power, feedback, brake, communication, and auxiliary cables.

Typical cable groups include:

  • Servo motor power cables.
  • Encoder or resolver feedback cables.
  • Brake-control connections.
  • Robot signal and I/O cables.
  • Ethernet or fieldbus cables.
  • Tool and process cables.
  • Protective bonding conductors.
  • Auxiliary equipment connections.

11.1 Cable installation principles

  • Use the exact cable type and part number or approved equivalent.
  • Verify connector orientation and pin assignments.
  • Respect manufacturer-specified cable length limits.
  • Maintain minimum bend radius.
  • Avoid pulling cables by their connectors.
  • Protect cables against sharp edges and crushing.
  • Separate cables from noise sources as specified.
  • Secure cables without damaging insulation.
  • Maintain service loops only where approved.
  • Avoid excessive tension at robot and controller connectors.
  • Keep connectors clean and protected during installation.

11.2 Cable identification

Label both ends of each cable with a unique identifier where the installation standard requires it.

The cable schedule should identify:

  • Cable ID.
  • Source and destination.
  • Connector type.
  • Cable function.
  • Route.
  • Length where required.
  • Shielding details where applicable.
  • Test and inspection status.

Never interchange similar-looking motor, feedback, or brake connectors without confirming their exact identity and pinout.

12. Motor power and feedback wiring

Robot motion requires coordinated control of motor torque and joint-position feedback.

Motor power

Motor power wiring carries the electrical energy used to produce joint movement. Incorrect wiring may cause drive faults, damage, or unsafe behaviour.

Feedback wiring

Feedback wiring carries signals from encoders, resolvers, or other position and speed feedback devices. The controller uses these signals to determine axis position and coordinate motion.

Important precautions

  • Keep power and sensitive feedback wiring routed as specified.
  • Use approved cable assemblies.
  • Verify connector identities before mating.
  • Check cable condition and connector locking.
  • Do not substitute cable types without approval.
  • Follow manufacturer instructions for braking circuits.
  • Avoid applying test voltages to sensitive feedback electronics unless specifically permitted.
  • Complete required continuity or insulation tests using an approved method.

A feedback fault can prevent servo enabling or cause axis-position errors. A motor power fault may produce drive alarms or prevent movement. Diagnosis should use controller diagnostics and approved electrical tests.

13. Industrial network and PLC integration

The robot controller commonly communicates with a PLC, HMI, engineering workstation, SCADA system, or plant network.

Possible interfaces include:

  • EtherNet/IP.
  • PROFINET.
  • Modbus TCP.
  • OPC UA where supported.
  • Standard Ethernet services.
  • Vendor-specific communication interfaces.

The supported protocols and roles depend on the robot controller and installed options.

13.1 Network integration checks

  • Confirm the controller's network interface and protocol options.
  • Verify the assigned IP address and subnet.
  • Check for duplicate addresses.
  • Confirm the correct VLAN and switch port.
  • Verify the intended controller-to-PLC communication method.
  • Check I/O mapping and data layout.
  • Confirm device names where required.
  • Verify update rates, timeouts, and connection limits.
  • Check network status and controller diagnostics.
  • Test application-level data exchange.

Do not assume that connecting an Ethernet cable is sufficient to establish PLC communication. The controller, PLC, network configuration, and I/O mapping must all be compatible.

14. Safety system integration

Robot controller installation may include connections to safety equipment, depending on the approved machine architecture.

Examples include:

  • Emergency-stop circuits.
  • Guard-door interlocks.
  • Safety light curtains or scanners.
  • Enabling devices.
  • Safe torque off (STO).
  • Safety-rated robot stop functions.
  • Safety-rated monitored speed or position functions where supported.
  • Safety PLC or safety relay interfaces.

These functions must be implemented and validated according to the risk assessment, safety design, and equipment instructions.

Key distinction

A standard PLC communication signal that says "stop robot" is not automatically a safety-rated stop function. Safety functions require suitable hardware, configuration, diagnostics, and validation for the required risk reduction.

Do not bypass safety interlocks to test motion. Do not assume that a controller's emergency-stop input, an ordinary digital input, and a safety-rated input are equivalent.

The sequence must be adapted to the specific robot model and installation. Some checks must be completed before any power is applied; others can only be completed during a controlled commissioning phase.

16. Pre-energisation inspection

Before applying power, use the approved electrical safety procedure and verify the installation.

  • Correct controller model and rating.
  • Cabinet mechanically secure.
  • Supply voltage and phase arrangement verified.
  • Upstream protection and isolation installed.
  • Protective earth connected and verified.
  • Power and feedback cables connected to the correct interfaces.
  • Connectors fully seated and secured.
  • No visible cable or insulation damage.
  • No loose hardware or foreign objects inside accessible areas.
  • Cooling openings unobstructed.
  • Cabinet doors and covers correctly installed.
  • Required network and peripheral connections identified.
  • Safety interfaces connected according to the approved design.
  • Required inspection and test records completed.
  • Authorisation for energisation obtained.

Do not energise a system if critical installation checks have failed or if the wiring differs from the approved drawings without an accepted engineering review.

17. Initial power-up and status verification

The first energisation should follow the manufacturer's commissioning instructions.

Typical checks may include:

  • Controller startup status.
  • Power supply and drive diagnostics.
  • Alarm history.
  • Cooling fan operation.
  • Network interface status.
  • Communication with the robot axes.
  • Feedback-system status.
  • Safety-system readiness.
  • Parameter and firmware compatibility.
  • Battery or backup warnings where applicable.

An alarm should be investigated using its exact code and the correct controller manual. Do not repeatedly reset a fault without understanding the cause.

Important: A controller that powers up successfully is not necessarily ready for robot movement. Mechanical installation, safety validation, mastering status, payload configuration, and workcell readiness must also be confirmed.

19. Troubleshooting examples

Example A: Controller powers on, but the robot cannot move

Possible causes include a safety stop, drive fault, feedback fault, incorrect configuration, or an unmet enabling condition.

Investigation:

  1. Read the controller's exact alarm and status.
  2. Confirm the system is in the correct operating mode.
  3. Verify safety-system status using the approved diagnostic method.
  4. Check servo-drive and feedback diagnostics.
  5. Confirm that all required installation and configuration checks are complete.
  6. Follow the manufacturer's fault-recovery procedure.

Do not bypass a safety function to make the robot move.

Example B: Robot controller cannot communicate with the PLC

  1. Check physical link status at both interfaces.
  2. Verify the cable and switch port.
  3. Confirm IP address, subnet, and VLAN.
  4. Check duplicate-address and network diagnostics.
  5. Verify protocol role and connection configuration.
  6. Confirm PLC data mapping and connection status.
  7. Review recent network or configuration changes.
  8. Record the result after communication is restored.

A successful ping may establish IP reachability but does not prove that the industrial protocol or cyclic I/O exchange is healthy.

Example C: Controller overheats during production

  1. Check the controller's temperature alarms and diagnostic history.
  2. Verify ambient temperature against the manufacturer's limits.
  3. Inspect ventilation openings and filters.
  4. Confirm fan operation and airflow direction.
  5. Check whether hot exhaust air is recirculating.
  6. Verify any outer cabinet cooling system.
  7. Inspect for unapproved cabinet modifications.
  8. Record the cause and corrective action.

Do not remove covers or reach into powered equipment unless the procedure specifically permits it and the necessary protection is in place.

20. Controller configuration and backup

The controller configuration may include more than the robot program.

Depending on the model, relevant data may include:

  • Robot model and axis configuration.
  • Firmware and software versions.
  • Robot mastering or calibration data.
  • Tool and work-object definitions.
  • Payload and load data.
  • I/O configuration.
  • Network settings.
  • PLC communication configuration.
  • Safety-related configuration and validation records.
  • Process parameters.
  • User-defined programs and system settings.

Use the manufacturer's approved backup procedure and distinguish configuration exports from complete recovery backups.

Backup control

  • Record the robot controller model and serial number.
  • Record firmware and software versions.
  • Use the approved backup tool.
  • Confirm that the backup completed successfully.
  • Store it in the controlled repository.
  • Restrict access to sensitive configuration data.
  • Maintain revision history.
  • Verify recovery requirements and compatibility.
  • Test restoration only in an approved environment or procedure.

Some controller data may require special handling, separate export methods, or manufacturer support. Never assume that one backup file contains every parameter necessary to recover the system.

21. Maintenance requirements

Preventive maintenance for the controller installation should follow the manufacturer and site maintenance schedules.

Possible checks include:

  • Cabinet fan and filter condition.
  • Ventilation clearances.
  • Cable jacket and connector condition.
  • Cable support and strain relief.
  • Protective-earth and bonding condition.
  • Signs of moisture, contamination, or corrosion.
  • Cabinet door seals and locks.
  • Abnormal noise or overheating.
  • Network port and communication status.
  • Diagnostic alarms and event history.
  • Backup currency and accessibility.
  • Labels, drawings, and configuration records.

Internal inspection, cleaning, or replacement of electronic components must follow the prescribed isolation and service procedure. Observe electrostatic discharge precautions where required.

Do not use compressed air or cleaning agents inside a controller unless the manufacturer permits the method.

22. Documentation and handover

The installation handover package should include:

  • Controller model and serial number.
  • Robot model and serial number.
  • Controller mounting location.
  • Electrical supply and protective-device details.
  • Protective-earth verification records.
  • Robot and controller cable schedule.
  • Network settings and port mapping.
  • I/O and communication configuration references.
  • Firmware and software versions.
  • Safety-system integration records.
  • Commissioning alarms and corrective actions.
  • Configuration backup reference.
  • Maintenance requirements.
  • Approved electrical drawings.
  • Installation inspection and release records.

Any deviation from the approved drawings should be documented and reviewed before the final as-built package is released.

23. Practical installation checklist

Mechanical installation

  • Robot base and foundation accepted.
  • Controller cabinet mounted securely.
  • Required clearances maintained.
  • Cabinet doors and service access verified.
  • Cable entries and environmental protection completed.

Electrical installation

  • Supply requirements verified.
  • Correct protection and isolation installed.
  • Protective earth and required bonding verified.
  • Robot motor and feedback cables identified and connected correctly.
  • Power and signal cables routed according to requirements.
  • Required electrical inspection and testing completed.

Communication and safety

  • Network addresses and switch ports verified.
  • PLC communication configuration checked.
  • I/O mapping reviewed.
  • Safety interfaces installed according to approved drawings.
  • Required safety validation completed before production release.

Commissioning and handover

  • Controller startup and diagnostics checked.
  • Required configuration and compatibility checks completed.
  • Backup completed and stored.
  • Installation records and as-built drawings updated.
  • Outstanding defects resolved or formally controlled.
  • Required approvals obtained before operation.

24. Interview questions and answers

1. What is the difference between the robot base and the robot controller?

The robot base provides mechanical support and a mounting reference. The controller executes motion control and manages the robot's drives, feedback, I/O, and communication interfaces.

2. Why is controller location important?

It affects cooling, environmental protection, electrical safety, cable length, accessibility, and maintenance reliability.

3. Why must protective earthing be verified?

It provides the required fault-current path and supports electrical safety. It also forms part of the installation's bonding and EMC arrangements.

4. Why are motor and feedback cables treated differently?

Motor cables carry power, while feedback cables carry sensitive position or speed signals. They have different electrical requirements and must be installed according to the manufacturer's wiring design.

5. What should be checked before energising a robot controller?

Supply and protection, protective earthing, cable connections, mechanical installation, cooling, enclosure integrity, safety interfaces, and all required inspection records.

6. Why might a controller power up but fail to enable the robot?

Possible causes include safety stops, drive faults, feedback problems, configuration mismatches, or unmet enabling conditions.

7. Why is cooling important in a robot controller?

Servo drives and electronic components produce heat. Inadequate cooling can cause overtemperature faults, reduced component life, and production interruptions.

8. Why should the controller configuration be backed up?

The backup supports recovery after controller failure, replacement, configuration loss, or an unsuccessful approved modification.

9. Does a successful network ping prove PLC-to-robot communication is healthy?

No. The relevant industrial protocol, connection configuration, I/O mapping, and application data must also be verified.

10. Can a standard PLC signal replace a safety-rated robot stop function?

Not automatically. Safety functions must meet the required safety design and validation criteria. An ordinary control signal is not equivalent to a validated safety function.

25. Final engineering principles

  • Follow the exact robot and controller installation manuals.
  • Treat the robot base, foundation, controller, cables, and power supply as interconnected parts of one installation.
  • Verify supply, protection, protective earthing, and bonding before energisation.
  • Maintain cooling, environmental protection, and service access.
  • Use approved motor, feedback, and communication cables.
  • Verify network configuration and protocol communication separately.
  • Never bypass safety functions to overcome commissioning faults.
  • Preserve approved configuration backups and recovery instructions.
  • Record installation deviations and final as-built details.
  • Release the system only after required mechanical, electrical, communication, and safety checks are complete.

Core principle: A correctly installed robot base provides mechanical stability, while a correctly installed controller provides the electrical, computational, and communication foundation needed for controlled robot operation.
