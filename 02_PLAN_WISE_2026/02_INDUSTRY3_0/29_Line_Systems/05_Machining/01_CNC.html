1. Purpose and scope

Computer Numerical Control (CNC) is the automated control of machine-tool movements and machining operations using a programmed sequence of commands. CNC systems control axes, spindle motion, tool changes, cutting parameters, auxiliary functions, and process sequencing to manufacture components with defined dimensions and surface quality.

In an automotive machining line, CNC machines may perform operations on engine blocks, cylinder heads, crankshafts, camshafts, transmission housings, axle components, brake components, and other precision parts, depending on the plant's manufacturing process.

For an industrial maintenance and automation engineer, CNC knowledge is not limited to editing G-codes. It includes understanding the complete machine system: mechanical structures, servo drives, feedback devices, CNC control, PLC logic, tool management, hydraulic and pneumatic systems, coolant, lubrication, safety interlocks, metrology, communication networks, and production data.

The objective is to understand how the machine converts a part program into controlled physical motion, how machining quality is maintained, and how faults can be diagnosed without damaging the machine, tool, or workpiece.

2. CNC fundamentals

2.1 What CNC controls

A CNC machine typically controls the following functions:

  • Axis positioning: Movement of the tool or workpiece along defined axes.
  • Spindle control: Spindle start, stop, direction, speed, and orientation.
  • Feed control: Relative movement between the cutting tool and workpiece.
  • Tool management: Tool selection, tool change, tool length and radius compensation, and tool-life monitoring.
  • Program execution: Reading and executing a part program.
  • Auxiliary functions: Coolant, clamping, lubrication requests, chip conveyors, pallet changes, and other machine functions.
  • Process monitoring: Position errors, spindle load, tool status, alarms, and process measurements.
  • Safety-related control: Monitoring of guards, emergency stops, and other safety conditions through the designed safety system.

The CNC controller does not necessarily control every machine function directly. Many auxiliary sequences are handled by a separate PLC or integrated CNC PLC.

2.2 CNC versus conventional machining

Feature Conventional machine CNC machine
Motion control Primarily operator-controlled Programmed and electronically controlled
Positioning Manual scales, handwheels, or mechanical stops Axis feedback and numerical positioning
Repeatability Strongly dependent on operator and setup Depends on machine condition, control, setup, and process
Complex geometry Requires substantial manual skill or special tooling Can execute coordinated multi-axis paths
Program storage Limited or not applicable Programs stored in the control or connected systems
Process monitoring Often primarily visual and manual May include alarms, loads, offsets, and automatic measurement
Troubleshooting Mechanical and operator-process focused Mechanical, electrical, control, software, tooling, and process focused

CNC automation improves repeatability and productivity, but it does not automatically guarantee accuracy. Worn ball screws, thermal growth, poor fixturing, tool wear, incorrect offsets, and defective measurement systems can still produce unacceptable parts.

4. CNC axes and coordinate systems

4.1 Basic machine axes

For a typical three-axis milling machine:

  • X-axis: Horizontal movement along one principal direction.
  • Y-axis: Horizontal movement along the perpendicular direction.
  • Z-axis: Movement along the spindle axis, often vertical on a vertical machining centre.

Rotary axes may be designated A, B, and C, generally corresponding to rotations around X, Y, and Z respectively. Actual axis conventions depend on the machine configuration and applicable standards.

A turning centre may use X and Z as primary axes, with additional axes such as Y, C, or a second spindle.

4.2 Machine coordinates and work coordinates

Coordinate system Purpose
Machine coordinate system Reference established by the machine's coordinate architecture and reference-return procedure
Work coordinate system Reference used to position machining operations relative to the workpiece
Local or temporary coordinate system Additional coordinate transformation used for a particular operation or setup
Tool coordinate data Defines relevant tool geometry, such as length or radius, depending on the control
Absolute programming Coordinates refer to a defined coordinate origin
Incremental programming Coordinates describe movement relative to the applicable current reference position

The exact behavior of coordinate selection and compensation depends on the CNC controller and active program mode.

4.3 Homing and reference return

Reference return establishes the machine's required axis reference using the machine's configured reference mechanism. Depending on the design, this may use an encoder reference mark, a reference switch, or another approved reference method.

Important distinctions:

  • A machine reference position is not necessarily the workpiece zero.
  • A displayed zero does not prove that the machine's mechanical reference is correct.
  • A failed reference return may indicate sensor, encoder, drive, mechanical, or configuration problems.
  • Reference-return procedures must follow the machine builder's instructions.

Never change machine reference parameters or axis-grid settings as a casual troubleshooting experiment. Incorrect reference data can cause collisions or invalidate machine positioning.

G-code and M-code conventions vary across controllers and machine builders. Similar-looking commands can have different meanings or options on different systems, so the actual machine manual and approved program standard remain authoritative.

6. CNC interpolation and motion control

Interpolation calculates the coordinated positions required to move one or more axes along a programmed path.

6.1 Types of interpolation

  • Linear interpolation: Coordinates move along a straight path.
  • Circular interpolation: Coordinates follow a programmed circular arc.
  • Helical interpolation: Linear and circular motion occur together when supported.
  • Multi-axis interpolation: Multiple linear and rotary axes move in a coordinated relationship.

Interpolation is only one part of motion execution. Acceleration limits, jerk settings, feed limits, axis dynamics, machine geometry, and servo response influence the actual movement.

6.2 Feed rate and spindle speed

Feed rate determines the programmed rate of tool movement relative to the workpiece. Spindle speed determines spindle rotation.

For turning, the relationship between cutting speed, spindle speed, and workpiece diameter is commonly expressed as:

\[ V_c = \frac{\pi D n}{1000} \]

Where:

  • \(V_c\) = cutting speed in metres per minute.
  • \(D\) = workpiece diameter in millimetres.
  • \(n\) = spindle speed in revolutions per minute.

Rearranging:

\[ n = \frac{1000V_c}{\pi D} \]

For milling, a common spindle-speed relationship is:

\[ n = \frac{1000V_c}{\pi D_t} \]

Where \(D_t\) is the cutting-tool diameter in millimetres.

For a milling tool with \(z\) cutting teeth, feed per minute may be calculated as:

\[ v_f = f_z z n \]

Where:

  • \(v_f\) = feed rate in millimetres per minute.
  • \(f_z\) = feed per tooth in millimetres.
  • \(z\) = number of cutting teeth.
  • \(n\) = spindle speed in revolutions per minute.

These equations provide starting calculations, not complete machining recommendations. Actual values depend on the workpiece material, cutting tool, tool geometry, rigidity, coolant strategy, operation, and manufacturer recommendations.

7.1 Controller versus machine builder

The controller provides CNC functions, but the machine builder integrates the mechanical machine, PLC sequence, tooling systems, safety architecture, drives, sensors, and machine-specific software.

A CNC alarm may therefore originate from the controller, drive, feedback device, machine PLC, or an external subsystem. The alarm text is evidence, not automatically the root cause.

9. Machine PLC and CNC interaction

A CNC machine commonly contains two related control domains:

  • CNC control: Executes machining programs and coordinates axis and spindle motion.
  • Machine PLC: Executes auxiliary sequences such as clamping, tool changes, door control, coolant control, pallet exchange, and machine-state management.

The exact division varies by machine. Some controls integrate PLC functionality within the CNC platform, while others use additional controllers.

9.3 Troubleshooting a CNC-to-PLC interface

When a sequence stops:

  1. Identify the exact step at which it stopped.
  2. Read the CNC alarm and machine PLC diagnostic messages.
  3. Find the relevant request and completion signals.
  4. Determine which condition is missing.
  5. Verify the corresponding sensor, drive status, pneumatic or hydraulic condition, and interlock logic.
  6. Check whether the command was issued, received, and completed.
  7. Restore the fault through the approved recovery sequence.
  8. Verify the entire cycle before returning the machine to production.

Do not force a completion signal just to advance a stalled sequence. The PLC is usually refusing to proceed for a reason, and the machine may be protecting a tool, fixture, or person.

10. Servo axes and feedback systems

CNC positioning depends on coordinated motion commands, drive control, motor behavior, feedback devices, and mechanical transmission.

10.1 Servo-system components

  • CNC motion controller.
  • Servo drive or amplifier.
  • Servo motor.
  • Motor encoder or resolver, depending on design.
  • Linear scale or other direct-position feedback, where fitted.
  • Coupling, gearbox, ball screw, linear guide, or other mechanical transmission.
  • Power and feedback cables.
  • Cooling and braking components, where applicable.

10.2 Position feedback

An encoder provides information about motor position or rotation. Some machines also use a linear scale to measure the axis position more directly.

Motor feedback and direct linear feedback are not equivalent. A motor encoder can indicate motor rotation while mechanical transmission errors remain between the motor and the table. A direct scale may detect some of those errors, depending on the control architecture.

10.3 Following error

Following error is the difference between the commanded position and the measured position, as defined by the controller's control loop.

\[ e(t) = x\_{\text{commanded}}(t) - x\_{\text{measured}}(t) \]

A following error that exceeds the configured threshold may trigger an alarm.

Possible causes include:

  • Mechanical binding or excessive friction.
  • Excessive axis load.
  • Damaged coupling or ball screw.
  • Servo-drive or motor faults.
  • Feedback cable or connector problems.
  • Incorrect servo tuning or configuration.
  • Acceleration demands beyond the system's capability.
  • Brake or counterbalance problems on applicable axes.

The alarm threshold and control-loop behavior are machine-specific. Do not change servo gains or position-error limits without the appropriate engineering procedure.

10.4 Servo fault diagnosis

Symptom Possible causes Checks

11. Spindle system

The spindle rotates the cutting tool or workpiece. Its behavior influences machining accuracy, surface finish, productivity, and tool life.

11.1 Main spindle components

  • Spindle motor.
  • Spindle drive.
  • Spindle bearings.
  • Spindle shaft and tool interface.
  • Tool-clamping mechanism.
  • Orientation sensor or position feedback, where fitted.
  • Cooling or lubrication arrangements.
  • Belt, gearbox, or direct-drive mechanism, depending on the machine.

11.2 Common spindle faults

Symptom Possible causes Diagnostic approach
Spindle fails to start Interlock, drive fault, enable missing Check CNC state, PLC sequence, drive alarms
Spindle overload Excessive cutting load, dull tool, mechanical drag Review spindle load and machining conditions
Spindle vibration Tool imbalance, damaged holder, bearing wear Inspect tooling, holder condition, vibration trends
Poor surface finish Runout, chatter, tool wear, incorrect cutting parameters Inspect tool, spindle, fixture, and process conditions
Spindle orientation failure Feedback issue, drive fault, mechanical problem Check orientation command, feedback, and machine diagnostics

Spindle bearings and tool interfaces are precision components. Avoid unnecessary disassembly or adjustment without the correct service procedure and measurement equipment.

12. Tool management and tool-life control

Machining performance depends on the condition, identity, geometry, and suitability of the cutting tool.

12.1 Tool-management functions

  • Tool identification and magazine location.
  • Tool length and radius data.
  • Tool-life counters.
  • Tool wear compensation.
  • Tool-breakage detection.
  • Duplicate or sister-tool selection.
  • Tool-change sequence management.
  • Tool presetting and measurement.
  • Tool offset and program revision control.

12.2 Tool offsets and wear compensation

Tool offsets account for differences between the programmed geometry and the actual cutting tool or setup.

Common categories include:

  • Tool length compensation.
  • Cutter radius or diameter compensation.
  • Work-coordinate offsets.
  • Tool wear compensation.
  • Machine-specific geometric or kinematic compensation.

The terminology and storage structure differ between CNC families.

An offset change can alter finished dimensions without changing the underlying part program. Therefore, offset changes should be controlled, recorded when required, and verified through measurement.

12.3 Tool-life monitoring

Tool life may be monitored using:

  • Cutting time.
  • Number of machining cycles.
  • Number of parts produced.
  • Spindle load or torque patterns.
  • Tool-breakage sensors.
  • In-process measurement.
  • Operator inspection and scheduled replacement.

Tool-life counters must reflect the actual tool-management method. If a tool is physically replaced but the controller's tool identity or life counter is not updated, the displayed status may become misleading.

13. Workholding, fixtures, and clamping

A CNC machine must locate and hold the workpiece accurately throughout machining.

Typical elements include:

  • Locating pins and datums.
  • Fixture bodies and supports.
  • Hydraulic or pneumatic clamps.
  • Workpiece-presence sensors.
  • Clamp-position switches.
  • Pressure switches or transducers.
  • Pallets and zero-point clamping systems.
  • Fixture identification and setup data.

13.1 Common workholding faults

Symptom Potential cause Verification
Part moves during machining Insufficient clamping, poor location, excessive cutting load Inspect fixture condition and approved clamping parameters
Part is machined off-location Wrong datum, incorrect fixture, chips on locating surfaces Check setup and seating
Clamp confirmation missing Sensor, wiring, pressure, valve, or mechanical issue Check the sequence and actual clamp condition
Repeated dimensional variation Fixture wear, inconsistent seating, thermal changes Inspect location surfaces and measurement trends
Clamp releases unexpectedly Pressure loss, valve issue, control fault Review pressure history and sequence logs

A clamp sensor only confirms the state that its design detects. It may not prove that the workpiece is correctly seated or sufficiently secured unless the system has been designed and validated to establish those conditions.

14. Coolant, chip removal, and lubrication

14.1 Coolant system

Coolant may provide cooling, lubrication, chip transport, and improved tool life. Systems can include pumps, filters, tanks, heat exchangers, concentration monitoring, flow sensors, and high-pressure delivery.

Common faults include:

  • Low coolant level.
  • Pump overload or failure.
  • Filter blockage.
  • Low delivery pressure or flow.
  • Incorrect concentration.
  • Leaks and contamination.
  • Heat-exchanger failure.

14.2 Chip-management system

Chip conveyors and chip-handling equipment remove machining debris. Failure can cause chip accumulation, fixture interference, coolant contamination, and production stoppages.

Maintenance checks should include conveyor condition, drive faults, overloads, jam detection, coolant return paths, and safe access for cleaning.

14.3 Lubrication system

Machine lubrication protects guides, ball screws, bearings, and other specified components.

Check:

  • Reservoir level.
  • Lubrication pump operation.
  • Pressure or flow monitoring.
  • Distribution lines.
  • Leakage and blockage.
  • Alarm history.
  • Approved lubrication type and interval.

A lubrication alarm should not be bypassed simply because the machine continues moving. The required lubrication state and allowable operating response must follow the machine builder's procedure.

16. CNC electrical and control cabinet

The control cabinet may contain the CNC controller, PLC hardware, servo and spindle drives, power supplies, communication modules, safety components, contactors, protection devices, and cooling equipment.

16.1 Maintenance considerations

  • Cabinet temperature and cooling.
  • Fan and filter condition.
  • Drive ventilation.
  • Power-supply status.
  • Loose or damaged connectors.
  • Cable routing and shielding.
  • Protective earthing and bonding.
  • Backup battery status where applicable.
  • Alarm and diagnostic history.
  • Network device status.
  • Approved parameter and software backups.

16.2 Electrical safety

CNC equipment may contain hazardous mains voltages, high-energy DC buses, stored electrical energy, moving axes, rotating spindles, hydraulic pressure, and suspended or gravity-loaded mechanisms.

Before electrical or mechanical intervention:

  • Follow the plant's lockout/tagout and energy-isolation procedure.
  • Identify and isolate all relevant energy sources.
  • Wait for the specified discharge period and verify the required safe condition.
  • Use suitable test instruments and approved verification procedures.
  • Account for stored pressure, gravity, springs, and rotating components.
  • Restore guards, covers, interlocks, and safety functions before release.

An emergency stop is not a substitute for energy isolation. Servo-drive displays being OFF also does not prove that hazardous electrical energy has been removed.

17. CNC safety and machine interlocks

CNC safety must cover operator access, rotating equipment, moving axes, tool changes, workholding, maintenance access, and unexpected restart.

Typical safety functions may include:

  • Emergency stop.
  • Guard and door monitoring.
  • Safe torque off.
  • Safe stop functions.
  • Safe limited speed or position, where implemented.
  • Interlocked access during automatic operation.
  • Safe recovery or setup modes.
  • Prevention of unexpected restart.
  • Monitoring of safety-related pneumatic or hydraulic conditions where required.

The actual functions depend on the machine risk assessment, safety architecture, and applicable requirements.

17.1 Safety versus standard control

Standard PLC logic commonly handles normal process sequencing. Safety-related functions must be implemented using an appropriate safety-rated architecture and validated for the intended risk reduction.

A standard PLC bit labelled GUARD_OK is not, by itself, proof of a safety-rated guard function.

Never bridge safety inputs, force safety outputs, defeat guards, or modify safety logic to restore production. Investigate the fault, repair the underlying issue, and perform the required functional verification.

18. CNC communication and industrial networks

Modern CNC machines exchange information with PLCs, tool systems, measurement equipment, production systems, and maintenance platforms.

Depending on the machine, interfaces may include industrial Ethernet, fieldbus networks, serial communication, discrete I/O, OPC UA, or manufacturer-specific protocols.

18.1 Common communication requirements

  • CNC-to-PLC machine-state exchange.
  • Drive and feedback communication.
  • Tool identification and tool-management interfaces.
  • Probe and measurement equipment integration.
  • MES production-data exchange.
  • Program transfer and controlled revision management.
  • Diagnostic data collection.
  • Remote maintenance under approved access controls.

18.2 Network troubleshooting

Symptom Possible cause Checks
CNC unavailable to MES Network fault, service failure, incorrect address Verify link, addressing, routing, and service status
Intermittent communication Cable, connector, interference, or network congestion Review device diagnostics and communication errors
PLC I/O unavailable Fieldbus configuration or device fault Check module status, bus diagnostics, and configuration
Program transfer fails Access permissions, storage, network, or format issue Verify transfer method, destination, and approved program handling
Tool data missing Interface mapping or communication failure Check tool identity, source controller, and transaction logs
Data is delayed Queue backlog, application load, or communication issue Compare source event time with receipt time

Network recovery should be followed by verification of machine state and pending transactions. Reconnecting a device does not guarantee that the CNC, PLC, and MES have returned to a consistent state.

19. CNC program and configuration management

CNC programs, machine parameters, offsets, tool data, and PLC software can affect machine behavior and finished-part quality.

19.1 Controlled assets

  • Part programs and subprograms.
  • CNC parameters.
  • Machine PLC programs.
  • Servo and spindle-drive parameters.
  • Tool geometry and wear offsets.
  • Work-coordinate offsets.
  • Tool-management data.
  • Machine-builder configuration files.
  • Probe and measurement settings.
  • Communication configuration.
  • HMI configuration.
  • Safety configuration and validation records.

19.2 Backup strategy

A backup should be usable for the specific machine and its installed configuration. Copying only the part program may not be sufficient to recover a machine after a controller replacement.

A practical backup register should identify the machine, control model, software version, asset type, backup date, storage location, change reference, and verification status.

Asset Recommended control
Part program Approved revision, change history, and release status
CNC parameters Machine-specific backup and controlled restoration
PLC program Version-controlled source and verified backup
Drive parameters Model-specific parameter backup and compatibility check
Tool and offset data Controlled management and validation
HMI configuration Backup with relevant software and hardware versions
Safety configuration Controlled backup, authorization, and required safety validation
Network configuration Documented addresses, topology, and approved settings

19.3 Change-management procedure

  1. Identify the problem and the affected machine.
  2. Record the current program, parameter, or software revision.
  3. Back up the existing configuration using the approved procedure.
  4. Review the proposed change and obtain required authorization.
  5. Apply the change under the appropriate machine state and safety controls.
  6. Test the change under controlled conditions.
  7. Verify machining quality and all relevant machine functions.
  8. Record the final revision and test results.
  9. Retain the previous configuration according to the site's retention policy.

Never assume that restoring another machine's parameter set is safe simply because the controller models match. Machine geometry, drive sizing, feedback systems, options, and builder-specific settings may differ.

20. CNC alarms and diagnostics

An alarm is an indication that a defined condition has occurred. It is not necessarily a direct explanation of the root cause.

20.1 Alarm categories

Category Typical examples First diagnostic direction
CNC program Invalid command, format error, missing program Review program block and controller-specific syntax
Axis and servo Following error, drive fault, reference issue Check axis state, drive diagnostics, feedback, mechanics
Spindle Overload, orientation failure, drive alarm Review spindle load, command state, feedback, and drive
Machine PLC Tool changer timeout, clamp not confirmed Check sequence step, input states, and actuator condition
Tool management Tool missing, life expired, pot-position fault Verify tool identity, magazine status, and tool data
Hydraulic or pneumatic Low pressure, clamp fault Verify actual pressure, valves, and sensor status
Coolant or lubrication Pump fault, low level, flow alarm Inspect the corresponding utility system
Communication Device unavailable, interface timeout Check network, controller status, and interface logs
Safety Guard fault, safety channel discrepancy Follow the safety diagnostic procedure
Process quality Out-of-tolerance measurement, tool wear Check measurement validity, tooling, offsets, and process conditions

20.2 Structured alarm diagnosis

Use the following order:

  1. Record the exact alarm text, number, timestamp, and machine state.
  2. Determine whether the fault occurred during startup, reference return, tool change, machining, or unloading.
  3. Review the alarm history and preceding events.
  4. Check the actual physical state and the relevant input/output signals.
  5. Review CNC, PLC, and drive diagnostics.
  6. Check power, wiring, feedback, mechanics, utilities, and process conditions as appropriate.
  7. Identify the root cause before changing parameters.
  8. Clear the fault using the approved procedure.
  9. Run the required functional and quality checks.
  10. Document the repair and recurrence-prevention action.

Repeatedly resetting alarms without investigating the cause can erase useful evidence and turn an intermittent fault into a machine crash.

21. Common CNC breakdown scenarios

21.1 Machine does not start the automatic cycle

Potential causes:

  • Emergency-stop or guard conditions are not satisfied.
  • Machine is not referenced.
  • A required axis or spindle state is missing.
  • Workpiece clamping is not confirmed.
  • Tool or pallet status is invalid.
  • A prior operation remains incomplete.
  • CNC or PLC is in the wrong operating mode.
  • An alarm or maintenance condition blocks operation.

Diagnostic approach: identify the exact cycle-start permissive that is missing, then trace it to the relevant controller, sensor, or mechanical condition.

21.2 Tool changer stops midway

Potential causes:

  • Missing tool-pot or arm-position confirmation.
  • Spindle orientation incomplete.
  • Air or hydraulic pressure below the required level.
  • Magazine indexing problem.
  • Mechanical obstruction.
  • Sequence timeout.
  • Communication failure between CNC and PLC.

Diagnostic approach: determine the current sequence step, compare commanded and confirmed positions, verify the actual mechanism state, and follow the approved recovery procedure. Never enter the tool-changer envelope while hazardous movement or stored energy remains possible.

21.3 Axis moves but the dimension is incorrect

Potential causes:

  • Incorrect work offset.
  • Wrong tool geometry or wear offset.
  • Incorrect program revision.
  • Thermal expansion.
  • Backlash or mechanical wear.
  • Incorrect fixture location.
  • Tool wear or runout.
  • Probe or measurement-system error.

Diagnostic approach: first establish that the measurement is valid. Then compare the approved program, offsets, fixture, tool condition, machine geometry, and actual dimensional results.

21.4 Spindle overload during cutting

Potential causes:

  • Excessive depth of cut or feed.
  • Incorrect spindle speed.
  • Dull, damaged, or unsuitable cutting tool.
  • Chip packing.
  • Poor coolant delivery.
  • Mechanical spindle drag.
  • Workpiece material variation.

Diagnostic approach: compare spindle-load trends with the approved process baseline, inspect tooling and chip conditions, and check drive diagnostics. Do not increase the overload limit simply to keep the machine running.

21.5 CNC loses reference after power interruption

Potential causes:

  • Feedback or reference system issue.
  • Battery or absolute-position system problem where applicable.
  • Encoder cable fault.
  • Incorrect restoration procedure.
  • Axis movement while power was unavailable.
  • Configuration or parameter problem.

Diagnostic approach: follow the machine builder's recovery and reference procedure. Confirm machine position and required geometry checks before production. Do not invent a reference offset to make the position display look correct.

22. Machining quality and process capability

CNC performance must be evaluated through both machine condition and finished-part quality.

22.1 Important quality characteristics

  • Dimensional accuracy.
  • Geometric tolerances.
  • Surface roughness.
  • Hole diameter and position.
  • Thread quality.
  • Concentricity and runout.
  • Flatness and perpendicularity.
  • Burr formation.
  • Tool marks and surface damage.
  • Repeatability across consecutive parts.

22.2 Measurement systems

Quality checks may use coordinate measuring machines, gauges, probes, bore gauges, micrometers, air gauges, or other application-specific instruments.

Before concluding that the CNC machine is producing an error, verify:

  • Instrument suitability and calibration status.
  • Correct datum and measurement method.
  • Part cleanliness and temperature where relevant.
  • Fixture and part seating.
  • Measurement repeatability.
  • Applicable engineering drawing and revision.

A defective measurement system can create false evidence of a machine problem, while a poorly controlled measurement process can also hide a genuine defect.

22.3 Statistical process monitoring

Manufacturing processes may use statistical process control to detect changes before parts become unacceptable.

Common indicators include:

  • Process mean.
  • Process variation.
  • Control-chart patterns.
  • Out-of-control events.
  • Capability indices such as \(C_p\) and \(C\_{pk}\), when their assumptions and use are appropriate.

Process capability should not be confused with control-chart stability. A process can be stable but incapable of meeting the specification, or appear capable over a short period while exhibiting instability.

23. Preventive maintenance and condition monitoring

CNC maintenance should combine scheduled tasks, condition-based checks, alarm analysis, and evidence from production quality.

Frequency Typical checks
Each shift Check alarms, lubrication status, coolant level, abnormal noise, leaks, and visible machine condition
Daily Inspect chip removal, filters where specified, tool condition, fixture cleanliness, and coolant delivery
Weekly Review recurring alarms, inspect accessible cables and connectors, check utility conditions, and verify lubrication indicators
Monthly or scheduled interval Review drive and spindle trends, inspect specified mechanical components, check backup status, and perform prescribed maintenance
Manufacturer-defined interval Perform specified lubrication, geometry, spindle, ball-screw, backlash, and other service checks
After major repair Verify safety functions, reference return, axis movement, tool change, spindle operation, and relevant machining quality

The table is a planning framework, not a substitute for the machine-specific preventive-maintenance schedule.

23.1 Condition-monitoring parameters

Where equipment supports reliable monitoring, useful parameters include:

  • Spindle load and temperature.
  • Servo load and following error.
  • Vibration trends.
  • Lubrication pressure or flow.
  • Coolant temperature and flow.
  • Hydraulic pressure.
  • Tool-life consumption.
  • Cycle time.
  • Alarm frequency.
  • Dimensional drift.
  • Drive fault history.

A trend is useful only when it is tied to a known operating condition and a suitable baseline. For example, a spindle-load increase caused by a different machining operation should not automatically be interpreted as bearing degradation.

CNC machines can provide production and condition data to plant monitoring systems, historians, databases, and analytics platforms.

A typical architecture may be:

             ↓
    Edge Gateway / OPC UA
             ↓
      Node-RED / Middleware
             ↓
       SQL Database
             ↓
       Historian / Grafana

   Maintenance and Production Analysis

This is an example architecture, not a mandatory design. Actual connectivity must respect the controller's supported interfaces and plant cybersecurity requirements.

Data point Potential use

24.2 Data collection considerations

  • Use documented and supported interfaces.
  • Confirm signal meanings and engineering units.
  • Separate live machine status from historical production events.
  • Preserve timestamps and source equipment identity.
  • Avoid excessive polling that burdens the control system.
  • Validate data before storing or using it for automated decisions.
  • Apply network segmentation and approved access controls.
  • Define how data is buffered and reconciled after communication failures.

Do not connect an analytics system directly to a production CNC network without an approved architecture and risk assessment.

25. CNC maintenance documentation

Machine knowledge should be documented so that troubleshooting does not depend on one engineer remembering every undocumented modification.

A machine knowledge record should contain:

  • Machine ID, location, and manufacturer.
  • Machine model and serial number.
  • CNC and PLC models and software versions.
  • Axis and spindle configuration.
  • Drive and motor details.
  • Tool magazine and changer configuration.
  • Network topology and approved addresses.
  • Electrical drawings and pneumatic/hydraulic diagrams.
  • CNC and PLC backups.
  • Parameter and configuration backups.
  • Alarm history and known failure modes.
  • Critical settings and approved limits.
  • Preventive-maintenance requirements.
  • Spare-parts list and obsolete-part alternatives.
  • Vendor contacts and service history.
  • Repair records and RCA/CAPA.
  • Commissioning and post-repair test results.

Every important record should identify its revision, approval status, storage location, and relationship to the actual installed machine.

26. CNC troubleshooting examples for RCA/CAPA

Failure Potential root cause Corrective action Effectiveness verification
Repeated following-error alarms Axis binding or excessive mechanical resistance Repair the mechanical issue and verify axis condition Controlled axis movement and diagnostic review
Frequent tool-change timeout Unstable position sensor or mechanical wear Correct sensor mounting or repair the mechanism Repeated tool-change cycles under approved conditions
Recurring spindle overload Tool wear, chip packing, or unsuitable cutting conditions Correct the verified tooling or process issue Compare load trend and part quality
Incorrect finished dimensions Incorrect offset or worn locating feature Correct the offset or repair the fixture after measurement Inspect successive parts against the drawing
Tool breakage Tool-life control ineffective or cutting conditions unsuitable Improve verified tool-management or process controls Review breakage recurrence and tool-life performance
Lost CNC parameters after service Incomplete or unverified backup procedure Establish and test a machine-specific backup and restore process Conduct an approved restoration validation
Intermittent machine-network loss Faulty cable, connector, switch, or configuration Repair the identified communication fault Verify sustained communication and data completeness
Lubrication alarms Blocked line, pump fault, or incorrect monitoring Repair the actual lubrication-system defect Verify required pressure or flow and alarm clearance

RCA should distinguish the observed symptom from the physical or logical cause. “CNC alarm occurred” describes the event. “Axis movement was obstructed by a damaged guide component, causing following error” is a more useful causal explanation when supported by inspection and diagnostic evidence.

27. CNC commissioning and post-maintenance verification

After installation, repair, software change, or major maintenance, verification should be appropriate to the affected systems and the machine builder's requirements.

Typical checks include:

  • Confirm the installed hardware and software configuration.
  • Verify electrical connections and protective earthing.
  • Check utility supplies, lubrication, coolant, and hydraulic or pneumatic systems.
  • Confirm safety functions and interlocks.
  • Verify reference return and axis movement.
  • Check spindle operation and tool clamping.
  • Test the tool changer and auxiliary sequences.
  • Verify fixture clamping and workpiece detection.
  • Confirm the correct program and approved offsets.
  • Perform controlled trial machining where required.
  • Inspect finished-part dimensions and surface quality.
  • Verify alarms, production data, and traceability interfaces.
  • Record the repair, configuration changes, and verification results.

The scope of testing must reflect the work performed. A cabinet fan replacement does not necessarily require the same machining validation as a ball-screw replacement or a CNC parameter restoration.

28. Practical exercises

  • Identify the CNC controller, machine PLC, servo drives, spindle drive, and feedback devices on a selected machine.
  • Locate the approved electrical drawings and CNC/PLC backup files.
  • Select a historical alarm and trace it through the relevant controller, signal, and physical subsystem.
  • Explain the difference between machine coordinates and work coordinates.
  • Identify the active work offset, tool data, and program revision using approved diagnostic procedures.
  • Trace a tool-change request through the PLC sequence and completion feedback.
  • Examine an axis or spindle load trend and distinguish normal process variation from a potential abnormality.
  • Identify the sensors associated with workpiece presence and clamping.
  • Review the lubrication, coolant, chip-removal, and hydraulic or pneumatic maintenance requirements.
  • Identify the machine's safety functions and approved isolation procedure.
  • Verify that the current CNC and PLC configuration is covered by a valid backup.
  • Prepare an RCA for a recurring fault and define how the corrective action will be verified.
  • Identify which CNC signals can be collected for production monitoring through an approved interface.

29. Competency checklist

A maintenance and automation engineer working with CNC machining should be able to:

  • Explain the roles of the CNC controller, PLC, servo drives, spindle drive, and feedback system.
  • Understand basic G-code, M-code, modal states, coordinate systems, and tool offsets.
  • Diagnose machine-start and cycle-permissive failures.
  • Trace tool-change, clamping, and auxiliary sequences through PLC logic.
  • Interpret servo, spindle, encoder, and following-error alarms.
  • Distinguish mechanical, electrical, control, tooling, and process-related faults.
  • Understand the effects of tool wear, workholding, coolant, and thermal conditions on quality.
  • Follow safe isolation and machine-recovery procedures.
  • Manage CNC programs and machine configurations under revision control.
  • Maintain reliable backups and document restoration procedures.
  • Understand CNC networking and approved Industry 4.0 data interfaces.
  • Support RCA/CAPA, preventive maintenance, commissioning, and post-repair verification.

30. Final technical summary

CNC machining is an integrated engineering system combining numerical control, PLC sequencing, servo motion, spindle control, tooling, workholding, sensors, utilities, safety systems, and manufacturing process knowledge.

Effective troubleshooting begins by identifying the failed subsystem and understanding the sequence of events leading to the fault. Alarm resets and parameter changes are not substitutes for root-cause analysis. Correct diagnosis requires evidence from the controller, PLC, drives, feedback devices, mechanical components, and finished-part measurements.

For maintenance, the goal is not merely to restore motion. It is to restore safe, repeatable machining, protect product quality, preserve the approved machine configuration, and prevent the fault from recurring.
