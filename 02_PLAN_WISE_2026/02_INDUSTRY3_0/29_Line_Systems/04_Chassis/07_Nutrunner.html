1. Purpose and scope

A nutrunner is a controlled fastening tool used to tighten nuts, bolts, and other threaded fasteners to a specified assembly requirement. In chassis assembly, nutrunners are important because bolted joints secure components that must withstand vibration, cyclic loads, braking forces, suspension loads, and long-term service conditions.

Unlike a conventional hand tool, an industrial nutrunner can control and monitor fastening parameters such as torque, angle, speed, fastening time, and sequence. Depending on the system, it can also identify fastening results, detect certain assembly abnormalities, and transmit traceability data to a PLC, production database, or manufacturing execution system.

The maintenance objective is not simply to make the tool rotate. It is to ensure that the fastening system produces repeatable, validated results, correctly detects failures, communicates with the production line, and preserves the evidence needed to prove that each required joint was assembled correctly.

2. Applications in chassis assembly

Typical applications include:

  • Suspension and subframe fastening.
  • Steering-system component fastening.
  • Axle and wheel-end assembly, where specified by the process.
  • Bracket, cross-member, and mounting-point fastening.
  • Brake-system component fastening, where the approved process uses controlled bolted joints.
  • Powertrain or driveline mounting, depending on the production layout.
  • Seat, cab, body, or accessory mounting where included in the chassis station.
  • Multi-bolt joints requiring a defined tightening sequence.

The actual torque, angle, tightening sequence, tool type, and acceptance limits must come from the approved engineering specification for that joint. There is no universal torque value for a component simply because it looks similar to another one.

4. Nutrunner system architecture

A typical electronically controlled fastening system includes the tool, controller, production control system, mechanical fixture, and traceability layer.

Production PLC / Station Controller
        ↕
Industrial Network or Hardwired I/O
        ↕
Nutrunner Controller
        ↕
Tool Cable / Communication Interface
        ↕
Nutrunner Motor and Torque Measurement
        ↓
Gear Train / Output Spindle / Socket
        ↓
Fastener and Joint
        ↑
Torque / Angle / Position Feedback
        ↓
Fastening Result Evaluation
        ↓
OK / NOK + Result Data
        ↓
PLC Interlock + Traceability Database

The exact architecture depends on the manufacturer and tool family. Some systems use a separate controller for each tool; others support multiple spindles or integrated fastening modules.

A network-connected controller may communicate with the PLC through an industrial Ethernet protocol, while another installation may use hardwired signals. Protocols and supported features must be confirmed from the installed controller's documentation.

6. Nutrunner types

Type Description Common use
Manual torque wrench Operator applies torque using a calibrated mechanical or electronic tool Low-volume or service fastening
Pneumatic nutrunner Uses compressed air to drive the tool Production fastening where the control requirements suit the tool
Electric shut-off nutrunner Uses an electric motor and control logic to stop at configured criteria Controlled production fastening
Transducerized nutrunner Measures torque through an integrated or associated transducer Applications requiring measured torque feedback
Pulse tool Uses repeated torque impulses to achieve tightening Selected applications where reaction forces or process characteristics justify it
Multi-spindle system Operates multiple fastening spindles under a coordinated control system Multiple bolts tightened in one fixture or station
Battery-powered smart tool Uses a battery-operated drive with electronic fastening control Flexible assembly and selected production applications

A pneumatic tool with a clutch is not equivalent to a transducerized electric nutrunner. The measurement capability, control strategy, accuracy, repeatability, and traceability features differ by design.

7. Torque, angle, and clamp force

7.1 Torque

Torque is the rotational moment applied to a fastener.

\[ T=F\times r \]

Where:

  • \(T\) = torque in newton-metres.
  • \(F\) = force applied perpendicular to the lever arm in newtons.
  • \(r\) = perpendicular distance from the rotation axis in metres.

Torque is widely used because it is practical to control, but it does not directly measure clamp force.

7.2 Why torque does not uniquely determine clamp force

A simplified relationship is:

\[ T=KFd \]

Where:

  • \(T\) = applied torque.
  • \(K\) = empirical nut factor.
  • \(F\) = resulting clamp force.
  • \(d\) = nominal fastener diameter.

This is an approximate engineering relationship, not a universal law for every joint. The nut factor varies with thread friction, bearing-surface friction, lubrication, coating, material, and joint geometry.

Consequently, two fasteners tightened to the same torque can produce different clamp forces if friction conditions differ.

7.3 Angle

Angle monitoring measures the rotation of the tool or fastener during a defined portion of the tightening process. It is useful for checking whether a joint behaves within an expected rotational range.

An abnormal angle can indicate:

  • Cross-threading.
  • Incorrect fastener length.
  • Missing or incorrect components.
  • A joint gap.
  • Damaged threads.
  • Incorrect seating.
  • A different friction condition.
  • A process or measurement problem.

Angle is only meaningful when the fastening strategy defines the correct start point and acceptance window.

8. Tightening strategies

The correct strategy depends on joint design, fastener properties, process capability, and engineering requirements.

Strategy Basic principle Typical purpose
Torque control Stop when measured torque reaches a target, subject to other limits General controlled fastening
Torque plus angle monitoring Control torque while checking whether rotation falls within an acceptable window Detect abnormal joint behavior
Angle control after snug Rotate through a defined angle after a validated snug-point detection Control selected joints with known joint behavior
Yield or torque-angle strategy Uses a defined tightening process associated with fastener or joint behavior Specialized applications requiring validated engineering limits
Seating detection Detects a transition in resistance or another defined process signal Helps identify seating behavior
Multi-stage tightening Applies multiple stages with different speeds or limits Supports controlled rundown and final tightening
Multi-spindle coordinated tightening Controls multiple fasteners according to a defined sequence or synchronization strategy Helps manage joint alignment and load distribution

No strategy is automatically correct for every chassis joint. Torque-angle monitoring can improve process diagnostics, but it cannot compensate for an unvalidated fastening specification.

9. Rundown and seating behavior

The fastening process commonly has several phases:

Tool Ready
    ↓
Socket Engages Fastener
    ↓
Initial Rundown
    ↓
Fastener Approaches Joint Seating
    ↓
Snug / Seating Detection, if Used
    ↓
Final Tightening Strategy
    ↓
Torque and Angle Evaluation
    ↓
Result: OK or NOK
    ↓
Record Result and Release Sequence as Designed

During free rundown, the fastener rotates with relatively low resistance. As the joint seats and clamp force develops, resistance increases.

Unexpected resistance during early rundown may indicate cross-threading, contamination, damaged threads, or a wrong component. Excessively long rundown may indicate a missing component, incorrect fastener length, or a gap, depending on the joint design.

The controller's phase definitions and thresholds are strategy-specific. The diagram represents a general concept rather than a universal controller sequence.

10. Tool selection and sizing

Tool selection must consider more than the required torque range.

Important factors include:

  • Required torque and angle strategy.
  • Fastener size, pitch, grade, and joint design.
  • Production cycle time.
  • Tool speed and torque capability.
  • Tool accuracy and repeatability requirements.
  • Socket and extension geometry.
  • Reaction torque and operator ergonomics.
  • Access to the joint.
  • Cable routing and tool movement.
  • Environmental conditions.
  • Required traceability and network integration.
  • Calibration and verification arrangements.
  • Tool duty cycle and serviceability.

The selected tool must be capable of performing the validated fastening strategy within its approved operating range. Operating continuously at the extreme of the tool's capability may affect cycle time, wear, thermal loading, and process capability.

11. Socket, extension, and mechanical setup

The socket and transmission path form part of the fastening system.

Check that:

  • The socket is the correct size and approved type.
  • The socket is not cracked, rounded, or excessively worn.
  • Extensions and adapters are approved for the application.
  • The tool is aligned with the fastener axis.
  • The fixture holds the component in its intended position.
  • The reaction arm is secure and correctly positioned.
  • The tool can reach the joint without side loading.
  • Cables and hoses cannot snag or become trapped.
  • The output spindle and coupling show no abnormal play or damage.

Side loading, worn sockets, unsuitable extensions, and poor alignment can contribute to inconsistent results or premature mechanical failure.

Extensions can change the mechanical behavior of the fastening system. Where the controller or process requires a specific tool configuration, any change to socket, extension, adapter, or reaction arrangement must be evaluated and validated.

12. PLC integration and station sequencing

The PLC generally coordinates product presence, station readiness, job selection, tool enable, fastening completion, and part release.

Typical PLC signals include:

  • Station ready.
  • Product or fixture present.
  • Correct variant or job selected.
  • Nutrunner ready.
  • Start request.
  • Tool busy.
  • Fastening complete.
  • Overall OK or NOK.
  • Tool fault.
  • Result available.
  • Result acknowledged.
  • Traceability accepted.
  • Reset request.

A simplified station sequence is:

Part Arrives
    ↓
Confirm Part Identity and Variant
    ↓
Confirm Fixture and Safety Conditions
    ↓
Select Correct Fastening Job
    ↓
Verify Tool Ready
    ↓
Enable Fastening Cycle
    ↓
Receive Completion and Result
    ↓
Check Required Spindles and Fasteners
    ↓
Store and Associate Traceability Record
    ↓
Release Part Only When Required Conditions Are Met

The sequence must follow the actual process specification. A single overall OK bit is insufficient when the station requires independent results from multiple spindles or joints.

12.1 Job selection

Job selection is critical in mixed-model production. Different chassis variants may require different fasteners, torque targets, angle windows, or spindle sequences.

Verify that:

  • The product identifier is valid.
  • The correct variant maps to the correct fastening job.
  • The selected job exists and is approved.
  • The controller confirms the expected job.
  • A communication timeout cannot leave an unverified job active.
  • The result record contains the correct product and job identity.

Do not use a fallback job merely to bypass a selection fault unless the fallback is explicitly approved for the affected product.

12.2 OK/NOK handling

A robust sequence defines what happens when:

  • The fastening result is NOK.
  • The tool reports a fault.
  • One spindle fails while others pass.
  • The result is missing.
  • Traceability storage is unavailable.
  • The product identifier does not match.
  • The communication link fails during the cycle.

The station should prevent incorrect release according to the approved quality and safety design. Recovery, rework, retightening, and bypass processes must be controlled and traceable.

13. Traceability and production quality

Traceability links each fastening result to the correct product and fastening operation.

A useful result record may contain:

Field Purpose
Product or chassis identifier Identifies the assembled unit
Station identifier Identifies the production location
Job or program number Identifies the fastening strategy
Spindle or tool identifier Identifies the equipment that performed the operation
Fastener or joint identifier Identifies the specific fastening point
Torque result Records measured torque where supported
Angle result Records angle where supported
Result status Records OK, NOK, or another defined outcome
Timestamp Establishes when the operation occurred
Operator or production context Supports investigation where required
Controller fault or diagnostic data Helps explain abnormal cycles
Rework or retry status Distinguishes initial and subsequent operations

The exact data fields depend on the controller and plant systems.

13.1 Common traceability failures

  • Result generated but not stored.
  • Result associated with the wrong chassis.
  • Duplicate records after retries.
  • Incorrect timestamp or clock synchronization.
  • PLC receives OK but the result payload is incomplete.
  • One spindle result is missing from an overall station result.
  • Product release occurs before required data acceptance.
  • Rework result overwrites the original result without history.

The system should preserve the original operation and record subsequent rework or retightening as a distinct, auditable event.

14. Fastening faults and their interpretation

Fault or symptom Possible causes Initial checks
Torque not reached Stripped threads, tool limitation, joint not seating, incorrect program Review curve or result data, fastener condition, and program
Torque reached too early Cross-threading, obstruction, wrong fastener, premature resistance Inspect rundown behavior and physical joint
Angle too high Missing component, gap, incorrect fastener, damaged threads, abnormal friction Compare angle and torque behavior with known-good results
Angle too low Early obstruction, wrong component, incorrect snug detection Review phase transition and joint condition
Tool fails to start Missing enable, safety inhibit, controller fault, cable issue Check ready state, permissives, and diagnostics
Tool stops mid-cycle Fault, connection interruption, overload, or configured limit Review event history and fastening data
Repeated NOK results Worn tool, process variation, incorrect job, component variation Compare multiple results and inspect the process
Unstable torque readings Measurement issue, tool wear, loose setup, process variation Check tool, setup, measurement chain, and verification status
Incorrect spindle result Mapping or addressing error Check PLC data mapping and controller configuration
Result missing in database Network, application, or database failure Check controller output, PLC handshake, and data storage path
Job mismatch Incorrect product identification or selection logic Verify variant mapping and active job
Tool overheats Excessive duty, mechanical wear, blocked ventilation, unsuitable operating conditions Check duty cycle, cooling, and service condition

A NOK result is evidence that the configured acceptance criteria were not met. It is not, by itself, proof of a single root cause.

15. Troubleshooting methodology

15.1 Tool does not run

  1. Confirm the station and tool identifier.
  2. Read the controller's active fault and event history.
  3. Check supply and controller status.
  4. Confirm the tool is ready and enabled.
  5. Verify the PLC start request and all required permissives.
  6. Confirm the correct job has been selected.
  7. Check tool cable, connectors, and communication status.
  8. Verify that the tool is not inhibited by an active safety or station condition.
  9. Inspect the tool mechanically under the approved procedure.
  10. Record the evidence before resetting or replacing components.

15.2 Tool runs but repeatedly produces NOK results

  1. Identify the exact NOK criterion: torque, angle, time, rundown, or another configured limit.
  2. Compare the result with recent good cycles and historical trends.
  3. Confirm that the correct product variant and job are selected.
  4. Inspect fastener type, component presence, thread condition, and seating.
  5. Check socket condition, alignment, and fixture stability.
  6. Verify tool maintenance and calibration status.
  7. Review the tightening strategy and approved limits.
  8. Perform a controlled process or measurement verification as required.
  9. Implement corrective action only after the likely cause has been supported by evidence.

Do not widen the torque or angle limits simply to increase the OK rate. That changes the acceptance criteria and can conceal a real assembly defect.

15.3 Fastening passes but the traceability record is missing

  1. Confirm whether the controller generated a result.
  2. Verify the result was transferred to the PLC.
  3. Check the result-available and acknowledgement handshake.
  4. Confirm that the correct product identifier was active.
  5. Inspect network and application diagnostics.
  6. Check database or MES service availability.
  7. Determine whether the record was rejected, delayed, duplicated, or associated with another identifier.
  8. Recover data using the approved procedure and preserve audit history.

15.4 Fault returns after tool replacement

Check:

  • Tool model and torque range.
  • Controller compatibility.
  • Tool identification and spindle mapping.
  • Parameter and job configuration.
  • Firmware compatibility where applicable.
  • Cable and connector condition.
  • Mechanical mounting and reaction arrangement.
  • Torque measurement and calibration status.
  • PLC command/status mapping.
  • Result-data association and traceability.
  • Whether the original root cause remains in the joint or fixture.

Replacing the tool without correcting the underlying joint, fixture, cable, or program problem usually just relocates the same failure to a newer and more expensive tool.

16. Calibration, verification, and process validation

These activities are related but not interchangeable.

Calibration establishes the relationship between the tool's indication or measurement and a suitable reference under defined conditions. Whether adjustment is required depends on the results and the applicable procedure.

Verification checks that the tool or system meets specified requirements. It may include torque checks, functional checks, and confirmation that the correct job and results are handled.

Process validation establishes that the complete fastening process can reliably achieve the required joint outcome under defined conditions. It includes more than the tool's torque measurement.

A tool can pass a measurement check while the actual assembly process still has problems caused by incorrect fasteners, wrong components, poor seating, or an unsuitable tightening strategy.

16.1 Measurement equipment

Use the correct torque analyzer, transducer, test fixture, adapter, and procedure for the tool and application. Ensure the measurement range and equipment capability are appropriate.

The verification procedure must define:

  • Required measurement range.
  • Number and type of checks.
  • Test setup and adapter configuration.
  • Acceptance limits.
  • Reference equipment status.
  • Environmental and operating conditions where relevant.
  • Handling of failures.
  • Records and approval requirements.

Do not assume a bench test alone proves that every production joint is acceptable.

16.2 Calibration failure

If a tool fails calibration or verification:

  1. Identify the tool and affected measurement range.
  2. Follow the site's containment and quality procedure.
  3. Determine when the tool may have started producing unreliable results.
  4. Identify the products and fastening operations potentially affected.
  5. Arrange authorized adjustment, repair, or replacement.
  6. Repeat the required verification.
  7. Assess historical production records and the need for reinspection or rework.
  8. Document the decision and release authorization.

The scope of retrospective product assessment should be determined with quality and engineering personnel, based on risk and evidence.

18. Root-cause analysis and CAPA

Problem Possible root cause Corrective or preventive action
Repeated early torque cutoff Cross-threading or damaged threads Investigate fastener presentation, alignment, and thread condition
Abnormal angle on a specific variant Incorrect component or joint stack-up Verify variant-specific parts and engineering specification
Increasing NOK rate over time Tool wear or process drift Trend results, inspect the tool, and verify measurement performance
Intermittent tool communication Cable flex fatigue or connector damage Correct cable routing, replace damaged components, and validate communications
Wrong fastening job Incorrect variant mapping or stale selection Correct selection logic and add appropriate validation
Missing fastening records Incomplete handshake or data-storage failure Correct the interface, implement monitoring, and validate record recovery
Repeated controller faults Cooling, supply, configuration, or hardware issue Review event history and environmental/electrical conditions
Calibration failure Tool wear, damage, or measurement-chain issue Repair or replace, verify again, and assess potentially affected production
Fastener loosening in service Joint design, assembly process, material, or installation issue Escalate through engineering and quality; do not merely increase torque

CAPA should include containment, evidence collection, root-cause identification, corrective action, preventive action, and an effectiveness check. Any change to torque or angle acceptance criteria must be approved through the relevant engineering and quality process.

19. Production KPIs

KPI Purpose
First-pass fastening OK rate Measures successful fastening without retry or rework
NOK rate by joint Identifies problematic joints and process conditions
Repeat fastening rate Highlights rework and unstable assembly
Tool-related downtime Quantifies equipment availability impact
Mean time to repair Measures repair efficiency
Calibration compliance Tracks required calibration and verification activities

Define each KPI consistently. For example, first-pass OK rate must specify whether retries count as failures in the initial pass. Otherwise, different reports may produce different conclusions from the same production data.

20. Documentation and spare management

Maintain a fastening-system record for each critical station, including:

  • Machine and station identification.
  • Nutrunner manufacturer, model, serial number, and spindle identity.
  • Controller model, firmware, and communication interface.
  • Approved fastening jobs and their revision history.
  • Torque and angle limits approved for each joint.
  • Tool-to-joint and spindle-to-PLC mapping.
  • Wiring diagrams and network topology.
  • Tool cables, sockets, adapters, and reaction-arm details.
  • Calibration and verification records.
  • Fault history and repair details.
  • Traceability interface and database field mapping.
  • Approved spare tools and controller compatibility.
  • Replacement and commissioning procedures.
  • Change log and responsible approvals.

A replacement tool must be checked for mechanical fit, controller compatibility, measurement capability, job configuration, and traceability mapping. A similar-looking tool is not automatically an equivalent tool.

21. Practical exercises

  • Identify a chassis fastening station and map each nutrunner spindle to its physical joint.
  • Record the controller model, tool model, active job, and communication method.
  • Trace the PLC start request, tool-ready status, and result handshake.
  • Compare one OK and one NOK result and identify the exact acceptance criterion.
  • Review a fastening sequence and document its rundown, seating, and final tightening phases.
  • Verify that each required spindle result is included in the station-level decision.
  • Locate the approved job backup and check its revision and recovery procedure.
  • Review calibration or verification records for the installed tool.
  • Trace a fastening result from the controller to the product traceability record.
  • Prepare an RCA for a recurring NOK result using actual process evidence.

22. Competency checklist

A maintenance engineer responsible for nutrunner systems should be able to:

  • Explain torque, angle, clamp force, rundown, and seating.
  • Distinguish torque control from torque-angle monitoring and angle control.
  • Identify the tool, controller, spindle, transducer, and feedback architecture.
  • Diagnose a tool that does not start.
  • Interpret common torque, angle, and controller faults.
  • Verify job selection and PLC handshake logic.
  • Trace a result from the tool controller to the production record.
  • Explain calibration, verification, and process validation.
  • Apply controlled recovery for NOK results and communication failures.
  • Identify mechanical causes of abnormal fastening results.
  • Preserve configuration backups and tool identification.
  • Escalate changes to fastening specifications through engineering and quality approval.
  • Document the root cause and verify the effectiveness of corrective actions.

23. Final technical summary

A nutrunner is a controlled fastening system, not merely a powered wrench. Its performance depends on the tool, controller, fastening strategy, joint condition, fixture, PLC sequence, measurement capability, and traceability system working together.

Reliable chassis assembly requires correct job selection, validated fastening limits, sound mechanical setup, verified tool performance, robust OK/NOK handling, and complete product-associated records. Maintenance should investigate the fastening evidence and physical joint before changing limits or replacing equipment.

The central rule is simple: an accepted controller result is meaningful only when the tool configuration, fastening process, acceptance criteria, and traceability association are all correct.
