1. Purpose and Scope

Barcode and Radio Frequency Identification (RFID) systems identify products, components, pallets, fixtures or carriers as they move through a manufacturing line. In Body-in-White (BIW) production, identification systems help the control system determine what is being processed, which variant it belongs to, where it should go and which production instructions apply.

A robot or fixture can execute its programmed sequence correctly while processing the wrong body variant. Identification systems help prevent this type of error by linking physical products to production data and routing logic.

Typical BIW applications include:

  • Identifying body shells, subassemblies, pallets and carriers.
  • Selecting the correct vehicle or component variant.
  • Associating a body with its production order or traceability record.
  • Selecting approved robot, welding or fixture recipes.
  • Tracking production progress across stations.
  • Confirming routing and preventing incorrect station processing.
  • Recording genealogy, process results and rework history.
  • Supporting production reporting and quality investigations.
  • Identifying reusable carriers and tooling.

Barcode and RFID are identification technologies, not substitutes for machine safety devices. A valid identifier does not prove that a part is correctly located, that a fixture is closed or that a machine is safe to operate.

2. Barcode and RFID Fundamentals

2.1 Barcode

A barcode encodes information in a visual pattern that an optical reader detects and decodes.

Common forms include:

  • 1D barcode: Encodes data using bars and spaces.
  • 2D barcode: Encodes data in a two-dimensional pattern, often allowing more information in a compact area.

Examples include Code 128, Code 39, Data Matrix and QR Code. Actual support depends on the reader and application.

2.2 RFID

RFID identifies an item using radio-frequency communication between a reader and a tag. A tag may contain a chip and antenna, although some RFID technologies use chipless tag designs.

An RFID system commonly includes:

  • RFID reader or interrogator.
  • Antenna or integrated antenna.
  • RFID tag or transponder.
  • Communication interface to a PLC, industrial network or computer.
  • Application logic that interprets the tag data.

RFID does not generally require the same optical line of sight as a barcode, but detection depends on tag technology, orientation, material, antenna arrangement and the electromagnetic environment.

2.3 Comparison

Feature Barcode RFID
Detection method Optical scanning Radio-frequency communication
Line of sight Usually required for reliable optical reading Usually not required in the optical sense
Data storage Information encoded in the printed pattern Depends on tag type and memory
Tag or label cost Often relatively low Usually higher than a simple printed label
Environmental concerns Dirt, scratches, contrast and label damage Metal, liquid, interference, orientation and antenna tuning
Multiple-item reading Possible with suitable imaging and software, but application-dependent Possible in suitable systems, depending on tag population and reader configuration
Reusability Label may be disposable or reusable depending on application Many tags can be reused if designed for the environment
Maintenance Cleanliness, print quality, alignment and reader optics Tag condition, antenna alignment, communication settings and RF environment
Typical use Product labels, order identification and traceability Carrier tracking, reusable tooling identification and suitable automated tracking applications

Neither technology is universally superior. The correct choice depends on required read reliability, cycle time, data needs, environmental conditions, cost and integration requirements.

3. Typical BIW Identification Architecture

A typical identification system connects the physical identifier to the automation and production-data systems.

Body / Component / Carrier
        ↓
Barcode Label or RFID Tag
        ↓
Barcode Scanner or RFID Reader
        ↓
Reader Interface
(Ethernet / Industrial Network / I/O / Serial)
        ↓
PLC or Identification Controller
        ↓
Data Validation and Variant Selection
        ↓
Station Sequence / Approved Recipe / Routing
        ↓
Production Database / MES / Traceability System

Not every installation uses this exact arrangement. A reader may communicate directly with a PLC, through an industrial Ethernet interface, through a dedicated controller or through a middleware application.

A well-designed system separates several functions:

  • Acquisition: Read the barcode or RFID tag.
  • Decoding: Convert the scanned pattern or tag response into data.
  • Validation: Check format, length, expected identifiers and data integrity.
  • Resolution: Retrieve the corresponding product or production record.
  • Decision: Determine the permitted station route or recipe.
  • Execution: Allow the intended production sequence when all required conditions are met.
  • Traceability: Record the identifier and relevant process results.

A successful read is only the beginning. The application must also establish that the identifier is valid for the current production context.

4. Barcode Fundamentals

A barcode represents data through a pattern that a scanner illuminates or images and then decodes.

4.1 One-dimensional barcodes

A 1D barcode stores information along one dimension using bars and spaces of different widths.

Common symbologies include:

Symbology Characteristics Potential application
Code 39 Alphanumeric encoding with a relatively simple structure Equipment or component labels
Code 128 Compact encoding of a broad character set Production labels and tracking identifiers
Interleaved 2 of 5 Numeric encoding commonly used in certain logistics applications Selected industrial or logistics labels
UPC/EAN Standardized retail identification formats Retail-oriented identification where relevant

The symbology defines how data is encoded. It does not define what the data means to the BIW control system.

4.2 Two-dimensional barcodes

A 2D code stores information in two dimensions and can represent more data in a compact area than many 1D codes.

Common examples include:

  • Data Matrix: Widely used for compact industrial marking and part traceability.
  • QR Code: Commonly used for identification and data access across many applications.

Some 2D codes include error-correction features that help decode a partially damaged symbol. However, error correction does not guarantee successful reading under every condition.

4.3 Barcode terminology

Term Meaning
Symbology Rules defining how information is encoded in the barcode
Quiet zone Clear area around a barcode required by the applicable symbology
Module Smallest basic element of a 2D symbol
X-dimension Nominal width of the narrowest element or module, as applicable to the symbology
Contrast Difference between the code elements and background
Resolution Ability of the scanner or imager to distinguish the code's details
Decode Process of converting the symbol pattern into data
Read rate Measure of successful reads under defined operating conditions
No-read An attempt that does not produce a valid decoded result
Verification Assessment of barcode quality against a defined standard or specification

A reader that can decode a label is not necessarily a barcode verifier. Verification equipment evaluates symbol quality using specified criteria.

5. Barcode Scanner Types and Selection

Barcode readers vary in their optical design, operating range, field of view and integration options.

5.1 Common reader types

Reader type Operating principle Typical use
Laser scanner Uses a laser-based optical scanning mechanism Suitable 1D barcode applications
CCD or linear imager Captures optical information using a sensor array Selected 1D and related applications
Area imager Captures a two-dimensional image and decodes supported symbols 1D and 2D industrial identification
Fixed-mount reader Installed at a fixed location for automatic reading Automated BIW stations and conveyors
Handheld scanner Operated manually by a technician or operator Maintenance, rework and manual traceability
Smart camera or vision reader Uses image processing and code-reading functions More complex presentation or inspection conditions

5.2 Selection factors

  • Supported barcode symbologies.
  • Minimum code size and module dimensions.
  • Working distance and field of view.
  • Label or direct-marking quality.
  • Target speed and available reading time.
  • Ambient lighting and exposure conditions.
  • Vibration, temperature and contamination.
  • Mounting position and mechanical protection.
  • Trigger method and required read timing.
  • Communication interface and PLC integration.
  • Diagnostic capabilities and configuration software.
  • Required read performance under actual production conditions.

A reader should be selected and tested using representative codes, actual mounting geometry and expected production movement.

6. Barcode Read Triggers and Data Handling

Fixed barcode readers may operate continuously, on a trigger input, through a communication command or through a configured sequence. The correct trigger method depends on the reader and application.

6.1 Typical trigger sequence

Part Approaches Reading Position
        ↓
Presence Sensor or PLC Sequence Detects Part
        ↓
Reader Triggered
        ↓
Scanner Captures and Decodes Code
        ↓
Read Result Received
        ↓
PLC or Application Validates Data
        ↓
Result Associated with the Correct Part

The read result must be associated with the correct physical part. If two bodies pass close together or the trigger timing is wrong, a valid barcode can still be assigned to the wrong production record.

6.2 Data validation

Validation may include:

  • Expected character length.
  • Allowed character set.
  • Prefix or identifier format.
  • Check digit, where defined by the data format.
  • Identifier existence in the production system.
  • Duplicate or previously processed identifier detection.
  • Compatibility with the selected product variant.
  • Valid routing for the current station.
  • Freshness of the data and association with the current part.

The validation rules must be based on the site's actual identifier specification and production process.

6.3 No-read handling

A no-read condition should be handled explicitly. Depending on the production design, the system may retry, request operator intervention, route the part to a controlled recovery position or stop the sequence.

A safe application must not silently substitute the previous part's identifier when the current read fails.

7. RFID Fundamentals

RFID uses radio waves to exchange information between a reader and a tag. Different RFID families operate at different frequencies and have different range, data-transfer and environmental characteristics.

7.1 Main RFID components

Component Function Common concerns
Reader or interrogator Controls communication with tags Configuration, communication faults and power
Antenna Couples RF energy and tag responses Alignment, mounting, damage and interference
Tag or transponder Provides identification and, where supported, stored data Damage, orientation, memory or chip failure
Reader controller Processes tag responses and manages device operation Firmware, configuration and diagnostics
PLC or host interface Transfers tag data to the control system Mapping, communication and data handling
Mounting and protection Maintains a stable installation Mechanical damage, vibration and environmental exposure

Some readers integrate the antenna and controller. The separate blocks are logical functions, not a requirement for separate physical devices.

7.2 Passive, active and battery-assisted tags

Tag type Power arrangement Characteristics
Passive Harvests energy from the reader's RF field or communication signal Does not require a built-in battery for normal tag operation
Active Uses an onboard power source to support transmission Can support applications requiring longer communication ranges, depending on design
Battery-assisted passive Uses a battery to support tag electronics while communicating through the reader's field Offers different performance characteristics from a fully passive tag

Tag selection depends on the application, required read range, memory, environment, maintenance needs and total system cost.

7.3 RFID frequency families

Frequency family General characteristics Typical considerations
LF, low frequency Short-range communication and specific tag technologies Read range, data rate and application-specific constraints
HF, high frequency Includes common 13.56 MHz RFID technologies Reader/tag compatibility and suitable close-range applications
UHF, ultra-high frequency Often used for logistics and inventory tracking at greater distances than close-coupled systems Antenna arrangement, metal, liquids, orientation and multi-tag performance

Frequency alone does not determine performance. Protocol, regional radio regulations, antenna design, tag construction and the environment also matter.

8. RFID Standards and Compatibility

RFID systems use different air-interface protocols, tag memory structures and communication interfaces. Devices that operate at a similar frequency are not necessarily compatible.

Examples of relevant technology families include:

  • ISO/IEC 14443 for proximity cards and related applications.
  • ISO/IEC 15693 for vicinity cards and related applications.
  • EPC UHF Class 1 Gen 2 and ISO/IEC 18000-63 for widely used UHF RFID systems.

The exact standard and version must be verified for the installed system.

8.1 Compatibility checks

Before replacing an RFID reader or tag, verify:

  • Frequency band and regional compliance.
  • Supported air-interface protocol.
  • Tag type and memory organization.
  • Required identifier format.
  • Read/write capability and access permissions.
  • Antenna and connector compatibility.
  • Communication interface to the PLC or host.
  • Data format, byte order and character encoding.
  • Configuration software and firmware requirements.
  • Environmental suitability and mounting constraints.

A reader that detects an RFID tag may still return data that the existing PLC program cannot interpret correctly.

9. RFID Read/Write Operations and Memory

Some RFID applications only read a tag identifier. Others read or write application data to supported tag memory.

9.1 Common data categories

  • Unique identifier: An identifier associated with the tag or encoded identity.
  • User memory: Memory available for application-specific information on supported tags.
  • Access credentials or passwords: Security mechanisms supported by particular technologies.
  • Lock or access settings: Controls that limit certain memory operations, depending on the tag.

Not all tags have the same memory structure or security features. Some identifiers are factory-assigned, while application data may be written during production.

9.2 Data design principles

  • Define which system owns each data field.
  • Distinguish the tag's identity from the production order or body identity.
  • Avoid storing unnecessary sensitive information directly on the tag.
  • Define behavior for missing, invalid or corrupted data.
  • Control write permissions and configuration changes.
  • Verify written data by reading it back when the application requires it.
  • Maintain a traceable record of changes where appropriate.

RFID should not be treated as a universal, unrestricted database. Memory capacity, endurance, protocol and access controls depend on the particular technology.

10. RFID Antenna Placement and Read-Zone Design

A reliable RFID installation requires the tag to enter a suitable RF read zone under expected production conditions.

10.1 Important factors

  • Reader and tag frequency compatibility.
  • Antenna orientation and polarization.
  • Tag orientation and mounting position.
  • Distance between tag and antenna.
  • Metal surfaces near the tag or antenna.
  • Liquids and other materials that affect RF propagation.
  • Nearby readers and possible interference.
  • Carrier speed and available read time.
  • Multiple tags in the same read zone.
  • Mechanical vibration and impact.
  • Regional radio-frequency limits and approved power settings.

Metal can detune or shield some RFID tags, while liquids can affect certain RF configurations. Specialized on-metal tags and suitable antenna arrangements may be required.

10.2 Practical placement procedure

  1. Confirm the reader, tag and frequency specifications.
  2. Review the intended read zone and mechanical arrangement.
  3. Install the antenna using the approved mounting method.
  4. Test with the actual tag, target material and production orientation.
  5. Verify detection at minimum and maximum expected distances.
  6. Test under representative motion and production conditions.
  7. Check for missed reads, unintended reads and nearby-tag interference.
  8. Record the approved settings and acceptance results.

Increasing reader power without investigating the installation can create unintended reads from nearby tags and may violate applicable limits.

11. RFID Anti-Collision and Multiple Tags

When several RFID tags are within a reader's field, the system may need an anti-collision mechanism to identify and communicate with them. The details depend on the RFID protocol.

In BIW, multiple-tag situations can arise when several carriers, body shells, fixtures or tagged components are close together.

Potential problems include:

  • The reader detects a neighboring tag instead of the intended one.
  • Several tags are detected when only one is expected.
  • The read zone is too large for the application.
  • Tags are mounted too close together or in an unsuitable orientation.
  • The application accepts the first returned identifier without checking its identity.
  • Tag reads are associated with the wrong station or production event.

11.1 Read-zone control

A robust application should define:

  • Which tags are permitted in the read zone.
  • Whether exactly one tag or a known set of tags is expected.
  • How the intended tag is selected.
  • How duplicate and stale reads are handled.
  • How the reader determines that the current read event is complete.
  • What happens if multiple unexpected tags are detected.

The reader's ability to detect multiple tags does not automatically mean the PLC application can determine which one belongs to the current body.

12. PLC Integration and Communication Interfaces

Barcode readers and RFID systems may communicate with automation systems through discrete I/O, serial communication, industrial Ethernet or dedicated industrial networks.

12.1 Common interfaces

Interface Typical use Main diagnostic focus
Discrete I/O Trigger, busy, done, valid or error signals Wiring, input/output state and timing
Serial communication Structured reader data over a supported serial link Baud rate, parity, framing and protocol
Ethernet TCP/IP Reader data or control over an Ethernet connection IP configuration, connection state, port and application protocol
PROFINET Industrial communication with compatible devices Device name, IP configuration, connection and I/O mapping
EtherNet/IP Industrial communication with compatible devices Network settings, device configuration and connection status
IO-Link Supported sensor and identification devices through an IO-Link master Device compatibility, parameterization and process-data mapping

The specific reader model determines which interfaces and protocols are available.

12.2 Discrete handshake example

A reader may expose signals such as TRIGGER, BUSY, DONE, VALID and ERROR. These names are illustrative; actual signal definitions and timing must come from the device manual.

PLC Requests a Read
        ↓
Reader Accepts Trigger
        ↓
Reader Indicates Busy
        ↓
Reader Attempts to Decode or Read
        ↓
Reader Reports Result or Error
        ↓
PLC Captures and Validates the Data
        ↓
PLC Completes the Read Transaction

Some readers use a different handshake, a data buffer or a command-response protocol. The application must follow the documented sequence.

12.3 Communication troubleshooting

  • Verify reader power and diagnostic indicators.
  • Check the physical link and the correct port or connector.
  • Confirm network addressing and device identity.
  • Check the PLC connection status and diagnostic messages.
  • Verify I/O mapping or communication parameters.
  • Confirm trigger and result timing.
  • Check data length, terminators and encoding where relevant.
  • Determine whether the reader produced a valid result before investigating downstream parsing.

A network connection being established does not prove that the reader has decoded a tag or that the application has accepted the data.

13. Data Formats, Parsing and Validation

The reader's output must be interpreted consistently by the PLC or host application.

For example, a barcode may return a string containing a production identifier, while an RFID reader may return a tag identifier as hexadecimal data. These values may require normalization and mapping before the production system can use them.

13.1 Common data-handling issues

  • Leading zeros are removed during numeric conversion.
  • Uppercase and lowercase characters are treated inconsistently.
  • Incorrect byte order changes the interpreted identifier.
  • Data includes a carriage return, line feed or other terminator.
  • A fixed-length field is parsed using the wrong length.
  • A hexadecimal string is mistakenly treated as decimal text.
  • A valid read is associated with the previous part.
  • The reader returns an error status that is ignored by the PLC.
  • An identifier is valid syntactically but absent from the production database.

Identifiers should generally be treated as identifiers, not as quantities. Converting a code such as 00012345 into a number can destroy meaningful leading zeros.

13.2 Validation layers

Layer Validation question
Physical read Did the reader successfully acquire the code or tag?
Device result Did the reader report a valid result rather than a no-read or error?
Format Does the data match the defined format and length?
Identity Does the identifier correspond to a known item?
Production context Is this item expected at this station and time?
Variant Does the identified product match the physical setup and selected recipe?
Traceability Can the read event be recorded against the correct production record?

Validation rules should be explicit and tested against invalid, duplicate, stale and unexpected identifiers.

14. Variant Selection and Production Routing

BIW identification can support product-specific production decisions, such as selecting the correct approved recipe or routing a body through the intended stations.

The identifier itself should not directly bypass the station's normal permissives or safety requirements.

14.1 Example sequence

Body Enters Identification Station
        ↓
Barcode or RFID Data Acquired
        ↓
Identifier Format Validated
        ↓
Production Record Retrieved
        ↓
Variant and Route Confirmed
        ↓
Physical Setup and Station Conditions Checked
        ↓
Approved Recipe Selected
        ↓
Normal Machine Interlocks Evaluated
        ↓
Production Operation Permitted

14.2 Wrong-variant prevention

Potential failure scenarios include:

  • The identifier belongs to a different body.
  • The physical body variant does not match the production record.
  • A stale identifier remains in memory after a no-read.
  • The wrong recipe is selected after a network or database delay.
  • The operator loads the wrong component despite a valid body identifier.
  • A fixture changeover does not match the selected variant.

Where required, the system should cross-check product identity, station configuration, fixture or tooling status and other relevant conditions before allowing the process.

14.3 Failure handling

A robust design should define the response to:

  • No-read.
  • Invalid format.
  • Unknown identifier.
  • Duplicate identifier.
  • Database or MES unavailable.
  • Wrong variant.
  • Unexpected station route.
  • Reader communication failure.
  • Timeout or incomplete transaction.

The response may be a retry, controlled stop, hold, rejection route or operator recovery procedure according to the approved production design. It must not silently reuse an old identifier.

15. Traceability and Production Genealogy

Traceability links a physical product to its production history. Barcode and RFID systems can provide the identity event that allows process records to be associated with the correct body or component.

15.1 Typical traceability information

  • Body, component or carrier identifier.
  • Product variant and production order.
  • Station and operation identifier.
  • Read timestamp and read status.
  • Robot or process program identification.
  • Welding or process result references.
  • Quality inspection results.
  • Rework and repair history.
  • Rejection or hold status.
  • Operator or equipment information where required by the system.

The precise fields depend on the manufacturing execution and quality systems.

15.2 Traceability architecture

Barcode / RFID Read Event
        ↓
Identifier Validation
        ↓
Production Record Association
        ↓
Station and Process Results
        ↓
Traceability Database / MES
        ↓
Search, Quality Investigation and Reporting

A read event is not equivalent to a completed process event. The system should distinguish between identity acquisition, operation start, operation completion and accepted quality results.

15.3 Example investigation

If a body has a dimensional defect, traceability data may help identify:

  • Which station processed the body.
  • Which fixture and recipe were used.
  • Whether a relevant process alarm occurred.
  • Whether the body was reworked.
  • Whether similar defects occurred in neighboring production records.

Traceability helps narrow the investigation. It does not replace physical inspection or root cause analysis.

16. Reader Configuration, Diagnostics and Backup

Identification readers often contain settings that affect read performance, output formatting and communication.

16.1 Barcode reader parameters

  • Supported symbologies.
  • Trigger mode and timing.
  • Exposure or illumination settings.
  • Focus or working distance, where applicable.
  • Read timeout.
  • Output formatting and terminators.
  • Communication parameters.
  • Result and error signaling.
  • Firmware and device configuration revision.

16.2 RFID reader parameters

  • Supported frequency and protocol.
  • Antenna selection and configuration.
  • Transmit power within approved limits.
  • Read-zone behavior.
  • Tag filtering and selection rules.
  • Read/write permissions.
  • Memory access settings.
  • Communication and data-format parameters.
  • Firmware and device configuration revision.

16.3 Configuration control

  • Back up the approved configuration before changes.
  • Record the reader's model, firmware and device identity.
  • Store configuration files in the approved location.
  • Document the reason and approval for each change.
  • Verify compatibility before loading a configuration onto replacement hardware.
  • Validate reading, communication and PLC interpretation after restoration.
  • Maintain revision history and recovery instructions.

A configuration that works on one reader model may not be directly portable to another. Confirm model and firmware compatibility before restoring a backup.

17. Common Barcode and RFID Faults

17.1 Barcode faults

Symptom Possible causes Diagnostic approach
Barcode not read Damaged label, poor contrast, wrong distance or unsupported symbology Inspect label quality, reader alignment and supported formats
Intermittent reads Vibration, motion blur, marginal focus or inconsistent label position Observe actual production movement and mounting
Wrong code returned Wrong target, neighboring label or incorrect read timing Verify the read zone and association with the current part
Reader decodes but PLC receives no data Communication or output-mapping fault Check the reader result, interface and PLC data path
Data is truncated Buffer length, output format or parsing problem Compare the reader's raw output with the received data
Duplicate records Repeated trigger, retry logic or missing duplicate handling Review transaction identity and application logic
Reader works in manual mode but not automatic mode Trigger timing, movement or sequence configuration Compare trigger, busy and result behavior during both modes

17.2 RFID faults

Symptom Possible causes Diagnostic approach
Tag is not detected Incompatible tag, poor orientation, unsuitable distance or tag damage Verify compatibility, placement and reader diagnostics
Intermittent tag reads RF interference, metal effects, movement or marginal coupling Test the installed arrangement under representative conditions
Neighboring tag is read Read zone too broad or tag selection logic inadequate Review antenna arrangement, read-zone behavior and filtering
Reader detects tag but application rejects it Unknown identifier, format mismatch or incorrect mapping Inspect the returned data and validation result
Reader reports communication fault Network, configuration, power or interface issue Check device diagnostics and the communication path
Read/write operation fails Unsupported memory operation, access restriction or tag issue Verify tag capability, permissions and documented command sequence
Performance declines after a mechanical change Antenna or tag position has changed Inspect mounting, orientation and the modified surrounding structure

18. Step-by-Step Fault Diagnosis

Use a consistent diagnostic method to avoid replacing devices without evidence.

18.1 Barcode no-read

  1. Identify the reader, station and intended target.
  2. Check whether the label is present, legible and positioned correctly.
  3. Verify the reader's power and diagnostic status.
  4. Check focus, field of view, distance and illumination where applicable.
  5. Review the trigger timing and whether the part was in the read zone.
  6. Check the raw reader result and error information.
  7. Verify the communication path and PLC data reception.
  8. Check the data format and application validation.
  9. Correct the confirmed cause and test with representative labels and production conditions.

18.2 RFID no-read

  1. Confirm the reader and tag technology are compatible.
  2. Verify that the reader and antenna are operating.
  3. Check the tag's identity and physical condition.
  4. Confirm the tag is within the intended read zone.
  5. Inspect tag and antenna orientation, mounting and surrounding materials.
  6. Review reader diagnostics, protocol settings and read results.
  7. Check whether nearby tags are causing selection or association problems.
  8. Verify data transfer and application validation.
  9. Test under the actual operating conditions and record the outcome.

18.3 Reader data is correct but the wrong recipe is selected

This is not necessarily a reader fault.

Investigate the complete decision path:

  • Confirm the raw identifier received by the PLC.
  • Verify string handling, byte order, leading zeros and parsing.
  • Check the identifier-to-variant mapping.
  • Confirm the retrieved production record belongs to the current body.
  • Review recipe selection logic and data freshness.
  • Verify the physical fixture and tooling configuration.
  • Confirm the expected interlocks and validation checks.

Do not adjust the reader's optical or RF settings when the decoded data is already correct. The fault may be downstream in data handling or production logic.

19. Cybersecurity and Data Integrity

Barcode and RFID systems can influence production decisions, so their data and configuration require controlled handling.

Potential risks include:

  • Unauthorized changes to reader configuration.
  • Incorrect or duplicated identifiers.
  • Unauthorized RFID tag writes where the technology permits them.
  • Uncontrolled changes to recipe mapping.
  • Network access to identification devices.
  • Reuse of stale data after a communication failure.
  • Inadequate logging of changes or production transactions.

Recommended controls include:

  • Restrict configuration access to authorized personnel.
  • Apply the site's OT network and account-management policies.
  • Maintain approved backups and revision history.
  • Validate identifier formats and production context.
  • Define behavior for communication loss and invalid data.
  • Use supported authentication and tag-access controls where available.
  • Log critical changes and relevant identification events.
  • Test recovery procedures after reader replacement or configuration restoration.

An RFID tag's identifier is not automatically proof of authenticity. Security capabilities vary by technology and implementation; a basic identifier should not be treated as a cryptographic authentication mechanism.

20. Preventive Maintenance Checklist

  • Inspect barcode labels and direct markings for readability and damage.
  • Clean reader optics using the approved method.
  • Check reader mounting, alignment, vibration and protection.
  • Verify trigger timing and successful result signaling.
  • Inspect RFID tag mounting and physical condition.
  • Inspect RFID antenna mounting, connectors and cable routing.
  • Review reader diagnostics and recurring no-read events.
  • Verify PLC communication and data mapping.
  • Check that invalid or missing reads are handled correctly.
  • Confirm that old identifiers are not reused after a failed read.
  • Back up approved device configurations after authorized changes.
  • Review read performance and fault trends.
  • Verify the identification-to-production-record association.
  • Confirm that any relevant safety or process interlocks remain valid after maintenance.

Maintenance frequency should follow the equipment-specific plan, manufacturer requirements, operating conditions and actual fault history.

22. Practical Study Exercise

Select one barcode or RFID installation from a BIW station and document its complete identification chain.

  • Identify the station, reader and target.
  • Determine the barcode symbology or RFID technology.
  • Record the reader model and approved configuration.
  • Identify the physical read zone and target orientation.
  • Trace the communication interface to the PLC or host.
  • Identify the trigger, busy, done, valid and error signals where applicable.
  • Record the raw data format and validation rules.
  • Trace how the identifier maps to a body, variant or production record.
  • Document the response to no-read, invalid data and communication loss.
  • Verify how the application prevents stale or incorrect identifiers from being used.
  • Review the reader's configuration backup and recovery procedure.
  • Document the common faults and diagnostic evidence.
  • Record the approved maintenance and post-repair acceptance checks.

Use the actual reader manual, electrical drawings, PLC program and production-system specifications. Do not assume that another station uses the same data format or handshake.

23. Technical Review Questions

Q1. What is the main difference between barcode and RFID?

Barcode identification uses optical scanning of a printed or marked symbol. RFID uses radio-frequency communication with a tag.

Q2. Why can a barcode be readable in manual mode but fail in automatic production?

Automatic operation may introduce motion blur, changing orientation, vibration, different trigger timing or a shorter reading window.

Q3. Why can an RFID reader detect the wrong tag?

The read zone may include nearby tags, the tag-selection logic may be inadequate, or the application may associate the returned data with the wrong physical item.

Q4. What is a no-read condition?

A read attempt that does not produce a valid decoded barcode or RFID result according to the device's reporting rules.

Q5. Why should the previous identifier not be reused after a failed read?

It may belong to the previous body or carrier, creating incorrect variant selection, routing or traceability records.

Q6. What should be checked before replacing an RFID reader?

Frequency, protocol, tag compatibility, antenna requirements, communication interface, data format, configuration compatibility and application integration.

Q7. Why is traceability more than reading a code?

The system must correctly associate the identifier with the physical item, station, production event and relevant process results.

Q8. What should happen when an identifier is valid but the variant is wrong?

The application should follow its approved wrong-variant handling procedure and prevent the incompatible production operation from proceeding.

Q9. Does an RFID tag automatically authenticate a product?

No. Basic tag identification does not guarantee authenticity. Authentication depends on the technology and implemented security controls.

Q10. How should an identification fault be diagnosed efficiently?

Trace the path from the physical code or tag through the reader, communication interface, PLC, validation logic and production-system mapping. Test each stage before replacing hardware.

24. Final Acceptance Checklist

  • Barcode and RFID operating principles understood.
  • 1D and 2D barcode symbologies distinguished.
  • Barcode reader types and selection factors understood.
  • RFID tag types, frequency families and compatibility covered.
  • RFID antenna placement and read-zone design understood.
  • Multiple-tag and wrong-tag risks covered.
  • PLC interfaces, handshakes and communication diagnostics understood.
  • Data parsing, validation and stale-data prevention covered.
  • Variant selection and production routing understood.
  • Traceability and production genealogy covered.
  • Reader configuration, backups and change control documented.
  • Common faults and systematic troubleshooting covered.
  • Cybersecurity and data-integrity risks understood.
  • Preventive maintenance and machine knowledge base requirements documented.
  • Practical test and acceptance procedure defined.

Core principle: Barcode and RFID systems must reliably identify the correct physical item and associate it with the correct production data. A successful read is not enough unless the data is valid, current, correctly mapped and appropriate for the actual station configuration.
