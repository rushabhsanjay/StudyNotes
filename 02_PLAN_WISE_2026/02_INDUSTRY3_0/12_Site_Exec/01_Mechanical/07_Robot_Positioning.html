1. Definition and purpose

Robot positioning is the process of establishing, measuring, commanding, and verifying the position and orientation of an industrial robot, its tool, and the workpiece relative to the required manufacturing coordinate system.

In automotive manufacturing, robot positioning is critical for robotic welding, adhesive dispensing, sealing, material handling, machine tending, inspection, and assembly. The robot must reach the intended location with acceptable accuracy, repeatability, orientation, and process timing.

Robot positioning is not simply moving the robot to a coordinate. The final result depends on robot calibration, coordinate frames, tool geometry, workpiece location, mechanical installation, controller configuration, program data, payload, and the condition of the complete cell.

For example, a robot may repeatedly move to the same programmed point while consistently welding in the wrong location. The robot can be repeatable while the tool frame, workpiece datum, fixture, or program offset is incorrect.

2. What must be positioned?

A robotic cell contains several related but distinct positioning references:

  • Robot base: The fixed reference from which the robot's motion is defined.
  • Robot flange: The mechanical interface at the end of the robot arm.
  • Tool centre point (TCP): The defined reference point of the tool, such as the welding gun tip or gripper reference.
  • Workpiece: The component being processed.
  • Fixture or nest: The equipment that locates and supports the workpiece.
  • Work object or user frame: A coordinate frame used to describe the workpiece or process area.
  • Target point: A programmed destination for the TCP or another defined robot reference.
  • Process point: The position and orientation required to perform the operation correctly.

The distinction matters because the robot flange can be at the correct coordinates while the actual tool tip is not, particularly if the TCP definition is incorrect.

4. Coordinate systems used in industrial robots

Robot controllers use coordinate frames to describe position and orientation. Common frames include the world, base, joint, tool, and work-object or user frames. The exact names and available frame types depend on the robot manufacturer and controller.

4.1 World coordinate system

The world frame is a reference coordinate system for the robot cell or a larger installation. Its relationship to the robot base is defined by the cell configuration.

It is useful when multiple robots, fixtures, conveyors, or stations must be related to a common reference.

4.2 Robot base coordinate system

The base frame is attached to the robot base. Cartesian movement expressed in this frame is interpreted relative to the robot's base coordinate system.

If the robot base is relocated or its reference is incorrectly established, programmed relationships to external equipment may no longer be correct.

4.3 Joint coordinate system

In joint coordinates, each robot axis is commanded to a specified joint position, usually expressed in degrees for revolute axes and suitable linear units for prismatic axes.

Joint movement is useful for:

  • Moving to a known configuration.
  • Approaching a target while avoiding a particular posture.
  • Maintenance and setup operations.
  • Moving through a known joint-space path.

A joint target does not directly specify the TCP's Cartesian position. The resulting TCP pose depends on the robot's geometry, joint values, and configured tool data.

4.4 Tool coordinate system

The tool frame is attached to the robot tool or its defined TCP. Tool-coordinate movement is useful for moving along the tool's own axes.

For example, a welding gun may need to approach a panel along its tool Z-axis. If the tool frame is correctly defined, the movement can be programmed relative to the tool orientation rather than the robot base.

4.5 Work-object or user coordinate system

A work-object frame describes the component, fixture, or working area. Instead of defining every target relative to the robot base, targets can be defined relative to this frame.

This helps when:

  • The same process is performed on multiple fixtures.
  • A component's location changes within a known range.
  • A fixture is replaced or adjusted.
  • A robot program must be reused across similar workstations.

A work-object frame must represent the real installation. Changing its coordinates to hide an uncorrected mechanical fault may make one target work while introducing errors elsewhere.

5. Cartesian position and orientation

A robot tool pose includes both position and orientation.

Position is generally represented by three coordinates:

  • \(X\): position along the X-axis.
  • \(Y\): position along the Y-axis.
  • \(Z\): position along the Z-axis.

Orientation describes how the tool is rotated relative to the reference frame. Depending on the controller, it may be represented using Euler angles, a rotation matrix, a quaternion, or a manufacturer-specific orientation representation.

A Cartesian target can be represented conceptually as:

\[ \mathbf{p}= \begin{bmatrix} X\\\Y\\\Z \end{bmatrix} \]

A complete pose can be represented by a homogeneous transformation matrix:

\[ \mathbf{T}= \begin{bmatrix} \mathbf{R} & \mathbf{p}\\\ 0\ 0\ 0 & 1 \end{bmatrix} \]

Here, \(\mathbf{R}\) is a \(3\times3\) rotation matrix and \(\mathbf{p}\) is the position vector.

The matrix describes the position and orientation of one coordinate frame relative to another. The direction of the transformation must be interpreted consistently: a transform from tool to base is not interchangeable with a transform from base to tool.

5.1 Why orientation matters

A robot can reach the correct XYZ location with an incorrect orientation.

Examples:

  • A welding gun tip reaches the seam but the gun angle is incorrect.
  • A gripper reaches a component but its jaws are rotated incorrectly.
  • A dispensing nozzle reaches the path but the nozzle angle changes the bead geometry.
  • A camera reaches the inspection point but the viewing direction causes glare or hides the feature.

For many manufacturing processes, position and orientation must be validated together.

7. Tool Centre Point (TCP)

7.1 Definition

The Tool Centre Point (TCP) is the defined reference point used by the robot controller to describe the tool's position and orientation. Its location depends on the tool geometry and the chosen process reference.

Examples:

  • Welding robot: electrode tip or defined welding reference point.
  • Gripper robot: centre of the gripping reference or a specified pickup point.
  • Dispensing robot: nozzle tip or process reference.
  • Inspection robot: camera reference point or calibrated sensor reference.

The TCP is not necessarily the physical centre of the flange. It is a tool-specific reference defined relative to the robot flange.

7.2 Why TCP calibration is important

Suppose the tool is replaced and the new tool tip is 8 mm longer than the previous one. If the old TCP data remains active, the controller will calculate the tool pose using incorrect geometry. The robot flange may follow its expected trajectory while the real tip misses the required location.

Typical symptoms of incorrect TCP data include:

  • Consistent offsets between the taught target and the actual tool tip.
  • Position errors that change with tool orientation.
  • Incorrect approach and withdrawal paths.
  • Different process results after tool replacement.
  • A tool tip that appears correct in one orientation but deviates in another.

7.3 TCP calibration methods

Common methods include:

  • Multi-orientation pivot method: The robot rotates the tool around a common physical reference point. The controller uses the measured poses to estimate the TCP offset.
  • Known-reference method: The tool is brought into contact with a precisely defined reference using an approved procedure.
  • Measurement-based method: A calibrated measuring device or dedicated tool-calibration station determines the tool reference.
  • Manufacturer-specific calibration procedure: Some systems use dedicated software, fixtures, sensors, or automated calibration routines.

The chosen method must match the robot controller, tool geometry, and required accuracy. Contact-based calibration must use controlled, low-risk procedures and must not damage the tool or reference.

7.4 Conceptual pivot calibration

If the tool tip remains stationary while the robot flange changes orientation, the controller can use the different flange poses to calculate the tool offset.

Robot pose A → Tool tip touches reference point
Robot pose B → Tool tip remains at same reference point
Robot pose C → Tool tip remains at same reference point
    ↓
Controller calculates the common tool reference
    ↓
TCP data is checked and saved
    ↓
Independent verification at additional poses

The method depends on the tool tip remaining at the same reference point and on sufficiently different, well-conditioned robot orientations. Repeating nearly identical poses may produce poor calibration.

7.5 TCP verification

After calibration:

  1. Verify the tool is mounted securely.
  2. Confirm the active tool data and TCP selection.
  3. Move the TCP to a suitable reference using an approved low-speed setup procedure.
  4. Rotate the tool through different orientations while checking whether the TCP remains at the reference point.
  5. Verify additional targets and approach directions.
  6. Record the calibration result and tool identifier.
  7. Revalidate relevant process points before production release.

A successful calibration routine does not automatically prove that the tool is mechanically secure, undamaged, or suitable for the required process.

8. Robot mastering and calibration

8.1 Mastering

Mastering establishes the reference relationship between robot axis positions and the controller's robot model. Depending on the manufacturer, this may involve mastering marks, reference positions, absolute encoders, calibration fixtures, or specified recovery procedures.

Mastering may be required after certain encoder, motor, gearbox, or controller-related events, or when the controller indicates that the axis reference is invalid.

Incorrect mastering can cause:

  • Robot positions to shift.
  • Previously taught targets to be reached incorrectly.
  • Unexpected changes in joint configuration.
  • Collision risks when running existing programs.

Do not perform mastering as a general troubleshooting experiment. Follow the exact controller-specific procedure and confirm the consequences for existing programs and calibration data.

8.2 Robot calibration

Robot calibration concerns the relationship between the controller's model and the actual robot geometry or measured reference positions. The term can refer to different procedures depending on the manufacturer and context.

A useful distinction is:

  • Mastering: Establishes the required reference for robot axes.
  • TCP calibration: Establishes the tool reference relative to the flange.
  • Work-object calibration: Establishes the workpiece or fixture coordinate frame.
  • Robot geometric calibration: Estimates or corrects model parameters that affect the relationship between joint coordinates and the robot's physical pose.
  • External-axis calibration: Establishes the relationship between an external mechanism and its coordinate reference.

These procedures are related but not interchangeable.

9. Workpiece and fixture positioning

Robot positioning is only as reliable as the relationship between the robot, the tool, and the component being processed.

A component may be located by:

  • Fixture datum surfaces.
  • Locating pins and bushes.
  • Mechanical stops.
  • Clamps and supports.
  • Pallet locating features.
  • Vision-based part localization.
  • Probing or measurement systems.
  • External position sensors.

9.1 Fixture datums

A datum is a defined reference used to establish a component's location or orientation. The fixture must locate the component consistently relative to the process requirement.

If the component is shifted in the fixture, the robot may execute the same program perfectly but still process the wrong physical location.

9.2 Sources of workpiece-position error

  • Incorrect fixture installation.
  • Worn locating pins or bushes.
  • Loose or damaged clamps.
  • Incorrect pallet orientation.
  • Variation in the component itself.
  • Debris between locating surfaces.
  • Fixture thermal expansion or distortion.
  • Inconsistent seating or clamping force.
  • Incorrect work-object frame.
  • Wrong part variant or fixture recipe.

9.3 Mechanical locating versus robot correction

Mechanical locating should establish the component's intended reference wherever the process design requires it. Robot offsets, vision correction, or sensor-based compensation can then address defined residual variation within validated limits.

Software offsets should not conceal loose fixtures, damaged locating features, or uncontrolled part variation. Compensation is useful when deliberately engineered; it is a poor substitute for restoring the physical datum.

11. Robot motion types and path behavior

11.1 Joint-interpolated motion

Joint-interpolated motion commands the robot's axes to move from one joint configuration to another. The controller coordinates the axes to complete the movement.

Typical uses include:

  • Moving between separated process locations.
  • Moving to a safe or standby position.
  • Reaching a known target configuration.
  • Approaching a work area where the exact Cartesian path is not critical.

The TCP generally does not follow a straight line during joint-interpolated motion.

11.2 Linear motion

Linear motion commands the TCP to follow a straight Cartesian path between defined poses, subject to the controller's motion model and constraints.

Typical uses include:

  • Approaching a welding location.
  • Retracting a gripper from a fixture.
  • Moving a dispensing nozzle along a defined line.
  • Insertion or extraction where a controlled approach direction is needed.

The controller must find a feasible joint trajectory that achieves the commanded Cartesian motion while respecting axis limits and configuration constraints.

11.3 Circular motion

Circular motion commands the TCP along a circular arc or other controller-defined circular path using specified geometric references.

Typical uses include:

  • Following curved seams.
  • Applying material along an arc.
  • Processing circular features.
  • Moving around a component edge.

The exact programming method and required intermediate points vary by controller.

11.4 Blending and corner behavior

Many controllers allow motion blending so that the robot can pass near an intermediate target without fully stopping. This can reduce cycle time and create smoother paths.

However:

  • The robot may not pass exactly through the programmed intermediate point.
  • Excessive blending may reduce process accuracy.
  • Sharp changes in direction can create dynamic loads or process variation.
  • Process-critical points may require a defined stop or tighter path tolerance.

A target used only for navigation may tolerate blending. A weld start point, dispensing corner, inspection point, or precise insertion location may require stricter behavior.

11.5 Speed, acceleration, and payload

Robot motion settings influence actual performance. Higher speed and acceleration can increase dynamic deflection, vibration, settling time, and stress on tooling or workpieces.

Payload configuration should include the tool and all carried attachments as applicable. The centre of gravity and inertia can matter as much as mass, especially when the load is offset from the flange.

12.1 Error-vector calculation

If the intended point is \(\mathbf{p}\_{target}\) and the measured point is \(\mathbf{p}\_{actual}\), the positional error vector is:

\[ \mathbf{e}=\mathbf{p}\_{actual}-\mathbf{p}\_{target} \]

The magnitude of the three-dimensional positional error is:

\[ e=\sqrt{e_x^2+e_y^2+e_z^2} \]

For example, if the measured offsets are \(3\) mm in X, \(-4\) mm in Y, and \(2\) mm in Z:

\[ e=\sqrt{3^2+(-4)^2+2^2} \]
\[ e=\sqrt{29}\approx5.39\text{ mm} \]

This describes the magnitude of the measured positional deviation. It does not include orientation error, measurement uncertainty, or whether the result satisfies the process tolerance.

12.2 Repeatability range

For repeated measurements along one axis:

\[ R=x\_{max}-x\_{min} \]

If repeated X-position measurements range from \(99.6\) mm to \(100.4\) mm:

\[ R=100.4-99.6=0.8\text{ mm} \]

This range describes the spread of those observations. It is not by itself a complete repeatability specification because the number of samples, test conditions, measurement method, and statistical definition also matter.

12.3 Position and orientation must both be measured

A robot pose can have a small positional error but an unacceptable orientation error. Conversely, orientation may be correct while the TCP is displaced.

A valid acceptance method should define:

  • The target position and orientation.
  • The measurement reference frame.
  • The test locations and approach directions.
  • The number of repetitions.
  • The load and operating conditions.
  • The measurement instrument and uncertainty.
  • The acceptance tolerances.

13. Robot positioning during installation

Robot positioning during site installation begins with the physical base and progresses through calibration, tool setup, frame definition, and process validation.

13.1 Before installation

Verify the approved layout, robot model, payload requirements, reach, mounting orientation, foundation design, utility routing, and surrounding equipment clearances.

Check:

  • Robot and controller identification.
  • Foundation dimensions and mounting interfaces.
  • Anchor-bolt specification and installation requirements.
  • Robot operating envelope and potential collision zones.
  • Cable routing and dress-pack clearance.
  • Tool, fixture, conveyor, and safety-equipment interfaces.
  • Access for maintenance and emergency recovery.

The robot should not be positioned solely to maximize reach. The installation must also provide feasible joint configurations, collision-free trajectories, maintenance access, and appropriate cable movement.

13.2 Mechanical installation sequence

  1. Verify the foundation against the approved drawings and requirements.
  2. Confirm the mounting surface, anchor locations, and specified tolerances.
  3. Lift and position the robot using the manufacturer's approved handling method.
  4. Install and tighten mounting fasteners according to the specified procedure.
  5. Verify the robot base orientation and installation reference.
  6. Install the tool and confirm its mechanical mounting.
  7. Inspect cable routing, dress-pack movement, and clearance.
  8. Install and verify the fixture, workpiece supports, and relevant external axes.
  9. Complete the required electrical, pneumatic, hydraulic, and communication connections.
  10. Record installation measurements and unresolved deviations.

Do not assume that tightening the mounting bolts establishes correct robot calibration. The physical installation, controller reference, and process frames must each be verified.

14. Robot positioning in robotic welding

Robotic welding is particularly sensitive to the relationship between the robot TCP, welding gun, fixture, component geometry, and programmed seam.

14.1 Important positioning requirements

  • The electrode or process reference must reach the intended weld location.
  • The gun orientation must suit the joint and process requirements.
  • Electrode condition and tool geometry must remain within the defined limits.
  • The workpiece must be located consistently in the fixture.
  • The robot must approach and retract without collision.
  • The weld sequence must coordinate with clamps, part-present sensors, and process equipment.
  • The weld result must be checked using the defined quality method.

14.2 Example: welding point shifted from the actual seam

Suppose a robot repeatedly produces a weld that is 4 mm away from the intended seam.

A structured investigation should check:

  1. Workpiece: Is the component seated correctly? Are the locating pins, supports, and clamps in good condition?
  2. Tool: Has the welding gun tip changed, worn, or been replaced without updating TCP data?
  3. Frames: Is the active work-object frame correct? Has the fixture moved?
  4. Program: Is the correct program, part variant, tool, and offset active?
  5. Robot reference: Has mastering or calibration changed?
  6. External equipment: Is conveyor tracking or external-axis synchronization involved?
  7. Measurement: Was the seam location measured using a reliable and suitable reference?

If all weld points are displaced by a similar amount, a common frame or datum error is plausible. If the error changes with tool orientation or robot posture, TCP, geometric, mechanical, or dynamic effects deserve closer investigation. These are diagnostic clues, not definitive proof.

14.3 Robot touch sensing and seam finding

Some welding systems use touch sensing, laser seam tracking, or other sensors to locate the actual seam.

These systems can compensate for defined workpiece variation, but they require:

  • Correct sensor calibration and mounting.
  • Valid detection settings.
  • Defined search ranges and failure handling.
  • Suitable workpiece and seam conditions.
  • Clear limits on the compensation that can be applied.
  • Verification that the corrected path remains safe and process-capable.

A seam-finding system should report failed or implausible measurements instead of silently applying an excessive offset.

15. Robot positioning with conveyors and external axes

When a robot works with a moving conveyor, turntable, positioner, or linear track, the controller must account for the relationship between the robot and the moving equipment.

15.1 Fixed-position operation

The conveyor brings the workpiece to a defined station and stops. The fixture then locates and clamps the part before the robot starts processing.

This approach is comparatively straightforward because the workpiece is stationary during the robot's process cycle.

15.2 Conveyor tracking

In conveyor tracking, robot movement is coordinated with the measured conveyor motion. An encoder or other feedback device provides movement information to the tracking system.

Important requirements include:

  • Correct encoder scaling and direction.
  • Accurate relationship between the encoder and actual conveyor travel.
  • Correct workpiece detection and tracking initialization.
  • Synchronized controller timing.
  • Handling of stops, speed changes, missing parts, and tracking loss.
  • Defined behavior when the tracking data becomes invalid.

If the encoder measures motor rotation but the belt slips, the measured movement may differ from the actual workpiece movement. The tracking system must be suitable for the mechanical arrangement.

15.3 External robot axes

An external axis can move a robot, workpiece, or positioner independently of the robot's internal axes. Examples include a linear track, rotary positioner, or servo-driven workpiece table.

The control system must account for:

  • External-axis reference and calibration.
  • Axis limits and motion coordination.
  • Workpiece and tool frames.
  • Payload and inertia.
  • Collision zones and cable management.
  • Interlocks and coordinated stop behavior.

Poor synchronization between the robot and an external axis can create path errors even if each axis appears to operate correctly on its own.

16. Robot positioning with vision systems

Vision-guided positioning estimates the location or pose of a part using image data. The robot then uses that estimate to select or correct its motion.

    ↓
Process-result verification

16.2 Camera calibration and hand-eye calibration

Camera calibration establishes relevant camera parameters, such as the relationship between image coordinates and geometric measurements.

Hand-eye calibration establishes the relationship between the camera and the robot or tool, depending on the camera arrangement.

Common arrangements include:

  • Fixed camera: Camera mounted independently of the robot.
  • Eye-in-hand: Camera mounted on the robot or tool assembly.

The calibration procedure must suit the camera geometry and installation. A correct image detection is not enough if the transformation from camera coordinates to robot coordinates is wrong.

16.3 Vision-system failure modes

  • Poor lighting or reflections.
  • Occluded or damaged features.
  • Incorrect camera calibration.
  • Incorrect hand-eye transformation.
  • Wrong part model or recipe.
  • Detection of the wrong feature.
  • Excessive part variation.
  • Communication or timing errors.
  • Stale coordinates from a previous part.
  • A detected pose outside the robot's feasible reach.

A robust system validates detection quality, part identity, coordinate plausibility, and timing before allowing the robot to act on the result.

17. Robot collision avoidance and reachability

A target can be geometrically valid but unreachable in the robot's current configuration. It can also be reachable while the path to it collides with a fixture, conveyor, tool, or another robot.

17.1 Reachability

Reachability depends on:

  • Robot model and joint limits.
  • Target position and orientation.
  • Tool geometry and TCP.
  • Robot mounting orientation.
  • External-axis position.
  • Payload and motion constraints.
  • The required approach and withdrawal path.

A target inside a robot's approximate reach envelope is not necessarily reachable with the required orientation or joint configuration.

17.2 Singularities

A singularity is a robot configuration where the mapping between joint motion and Cartesian motion loses rank or becomes poorly conditioned. Near a singularity, small Cartesian movements can demand large or rapid joint changes, depending on the robot and trajectory.

Potential symptoms include:

  • Abrupt joint motion.
  • Unexpected changes in wrist orientation.
  • Motion restrictions.
  • Speed limitations.
  • Controller warnings or faults.

Possible mitigations include changing the approach direction, adjusting the path, selecting a different valid robot configuration, or modifying the cell design. Changes must preserve process requirements and collision clearance.

17.3 Collision-prevention checks

  • Verify the complete tool and payload geometry.
  • Check approach, process, and withdrawal paths.
  • Include fixtures, clamps, cables, dress packs, and carried components.
  • Consider all relevant external-axis positions.
  • Check shared workspaces when multiple robots operate in the same cell.
  • Validate the actual installation against the simulation.
  • Use approved low-speed setup and commissioning procedures.

Offline simulation is valuable, but it does not prove that the installed cell is collision-free. Differences in geometry, cable routing, calibration, and actual equipment position must be addressed during commissioning.

18. Troubleshooting robot positioning faults

18.1 A disciplined fault-isolation method

  1. Record the exact symptom, program, target, tool, frame, and operating conditions.
  2. Determine whether the error affects position, orientation, trajectory, repeatability, or reachability.
  3. Compare commanded and measured results using a defined reference.
  4. Check whether the error is constant, direction-dependent, posture-dependent, load-dependent, or time-dependent.
  5. Verify tool mounting, TCP, work-object frame, fixture location, mastering status, and active program data.
  6. Inspect mechanical components after applying the appropriate hazardous-energy controls.
  7. Change one verified cause at a time and repeat the measurement.
  8. Record the correction, affected programs, calibration data, and acceptance evidence.

Avoid changing several offsets at once. Doing so may hide the original cause and make future faults much harder to diagnose.

19. Robot positioning acceptance and validation

Robot positioning should be accepted against the specified process requirement and a defined measurement method.

Validation item What to verify
Base installation Mounting, foundation, orientation, and specified installation tolerances
Mastering and calibration Controller reference status and completion of required procedures
TCP Tool identity, mounting, calibration, and verification
Work-object frame Relationship to actual fixture datums and workpiece
Position accuracy Measured position compared with the intended target under defined conditions
Orientation accuracy Measured tool orientation compared with the required orientation
Repeatability Repeated measurements using the specified test method
Path performance Trajectory meets process and path-tolerance requirements
Payload Correct tool, mass, centre of gravity, and inertia configuration
Reachability Required targets and paths are feasible in the installed cell
Collision clearance Tool, robot, cables, fixtures, and external axes clear the intended path
Process result Weld, assembly, dispensing, inspection, or other process meets its quality criteria
Documentation Calibration records, program backup, frame data, test results, and unresolved deviations

Measurement should use a suitable instrument and reference system. The acceptance tolerance must account for the process requirement and the uncertainty of the measurement method.

A robot's published repeatability value is not a guarantee of the final workpiece process accuracy. The complete error chain includes the robot, tool, fixture, component, measurement system, and process.

20. Documentation and change management

Robot positioning data is part of the machine's controlled configuration. Important records include:

  • Robot model, serial number, and mounting configuration.
  • Controller version and relevant software configuration.
  • Mastering or reference data, where supported and appropriate.
  • Tool identifiers, TCP values, payload, centre of gravity, and inertia.
  • Work-object and user-frame data.
  • External-axis calibration and configuration.
  • Program versions and approved process offsets.
  • Fixture and locating-datum details.
  • Calibration and validation reports.
  • Collision and reachability assessment results.
  • Fault history and corrective actions.
  • Approved backup and restoration procedure.

Any change to the tool, fixture, robot mounting, external axis, controller configuration, or workpiece datum should be assessed for its effect on positioning and process quality.

After a change, verify which programs, frames, tools, and safety or process validations are affected. Do not assume that an old program remains valid simply because it can still be loaded.

21. Interview questions and answers

Q1. What is the difference between robot accuracy and repeatability?

Accuracy describes how closely the robot reaches the intended target. Repeatability describes how consistently it returns to the same position under defined conditions. A robot can repeatedly reach the wrong point because of an incorrect frame or systematic offset.

Q2. What is a TCP?

The Tool Centre Point is the defined tool reference used by the controller to calculate the tool pose. Correct TCP data is essential because the process acts at the tool, not necessarily at the robot flange.

Q3. What happens if the TCP is incorrect?

The controller calculates the tool position using incorrect geometry. The resulting tool-tip error can vary with orientation, causing inaccurate welding, gripping, dispensing, or other operations.

Q4. What is mastering?

Mastering establishes the required reference relationship between robot axis positions and the controller's robot model. It must be performed according to the manufacturer-specific procedure when required.

Q5. What is the difference between mastering and TCP calibration?

Mastering concerns the robot axes' reference relationship. TCP calibration establishes the tool reference relative to the flange. One does not replace the other.

Q6. What is a work-object frame?

It is a coordinate frame associated with the workpiece, fixture, or working area. It allows targets to be programmed relative to the process reference instead of being defined only in robot-base coordinates.

Q7. Why does a robot miss a welding seam even when the program has not changed?

The tool, fixture, workpiece, frame, mastering data, or external equipment may have changed. The robot may also be affected by wear, deformation, payload mismatch, or incorrect calibration.

Q8. What is the difference between joint and linear motion?

Joint motion coordinates the robot axes between joint configurations and generally does not produce a straight TCP path. Linear motion commands the TCP to follow a straight Cartesian path, subject to the controller's constraints.

Q9. What is a robot singularity?

It is a configuration where certain Cartesian movements become unavailable or poorly conditioned. It may lead to abrupt joint movement, speed limitations, or motion restrictions.

Q10. How does conveyor tracking work?

A tracking system uses measured conveyor movement, typically from an encoder, to coordinate robot motion with the moving workpiece. Correct scaling, synchronization, initialization, and error handling are essential.

Q11. What is hand-eye calibration?

It establishes the relationship between a camera coordinate frame and the robot or tool coordinate frame. It enables image-based measurements to be transformed into robot-relevant coordinates.

Q12. Why is a robot's repeatability specification not enough to guarantee weld quality?

The specification describes robot performance under defined conditions. Actual process quality also depends on TCP calibration, fixture location, workpiece variation, tool condition, path behavior, and the welding process itself.

Q13. How would you troubleshoot a consistent 5 mm positional shift?

Verify the physical datum, fixture, active work-object frame, TCP, program selection, and robot reference status. Measure the error against a known reference before changing offsets.

Q14. Why can a target be reachable in simulation but fail in the actual cell?

The installed cell may differ from the model in geometry, mounting, tool dimensions, calibration, cable routing, or external-axis configuration. The target may also require an infeasible orientation or joint configuration.

Q15. What should be verified after replacing a robot tool?

Check secure mounting, tool identity, TCP calibration, payload and inertia data, cable routing, clearance, and all affected process points. Revalidate the applicable process before production release.

22. Practical revision checklist

  • Explain robot base, flange, TCP, work-object, and world frames.
  • Distinguish Cartesian position from tool orientation.
  • Explain accuracy, repeatability, resolution, mastering, and calibration.
  • Describe TCP calibration and verification methods.
  • Explain fixture datums and the difference between mechanical locating and software correction.
  • Compare joint, linear, and circular motion.
  • Explain path blending, payload, inertia, reachability, and singularities.
  • Calculate a three-dimensional positional error and interpret repeatability measurements.
  • Describe robot positioning in welding, assembly, and dispensing.
  • Explain conveyor tracking, external axes, vision guidance, and hand-eye calibration.
  • Diagnose common positioning errors using evidence rather than random offsets.
  • Describe installation, commissioning, acceptance, and change-control requirements.

The key engineering principle is that robot positioning depends on the entire reference chain: robot geometry, axis reference, tool, fixture, workpiece, coordinate frames, motion program, and process verification. A robot that moves without an alarm is not necessarily positioned correctly.
