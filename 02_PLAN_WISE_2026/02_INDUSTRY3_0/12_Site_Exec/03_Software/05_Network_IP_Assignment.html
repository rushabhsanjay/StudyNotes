1. Definition and Purpose

Network IP assignment is the process of allocating, configuring, documenting, and verifying Internet Protocol (IP) addresses for devices connected to an industrial network.

In site execution, this typically includes PLCs, robot controllers, CNC machines, HMIs, SCADA computers, industrial PCs, managed switches with management interfaces, drives, remote I/O, and other Ethernet-enabled equipment.

Correct IP assignment enables devices to communicate with the intended systems without address conflicts, routing errors, or unintended connections to other networks.

IP assignment is not simply entering an address into a device. It requires a planned addressing scheme, correct subnet configuration, network documentation, and verification of actual communication.

2. Why IP Assignment Matters in Industrial Automation

Industrial devices exchange information for control, monitoring, diagnostics, production tracking, and engineering access.

Examples include:

  • A PLC communicating with remote I/O over an industrial Ethernet network.
  • A robot controller exchanging handshake signals with a cell PLC.
  • A CNC machine providing status and production information to a supervisory system.
  • An HMI communicating with a PLC.
  • A SCADA computer collecting data from PLCs and industrial devices.
  • An engineering workstation connecting to PLC, robot, and CNC programming environments.

Incorrect IP configuration can cause communication failures, duplicate-address conflicts, inaccessible engineering interfaces, incorrect routing, and production downtime.

A device can be powered up and appear healthy locally while remaining unreachable over the network. Electrical power and network communication are separate things, because apparently the universe required another way to make commissioning interesting.

3. Basic IP Address Concepts

An IPv4 address is a 32-bit address, normally written as four decimal octets separated by periods.

Example:

192.168.10.25

Each octet has a value from 0 to 255.

An IPv4 address consists of a network portion and a host portion, determined by the subnet mask or prefix length.

Term Meaning Example
IP address Logical address assigned to a network interface 192.168.10.25
Subnet mask Identifies the network and host portions 255.255.255.0
Prefix length Number of network bits /24
Network address Identifies the IP subnet 192.168.10.0/24
Host address Address assigned to a device interface 192.168.10.25
Default gateway Router used to reach destinations outside the local subnet 192.168.10.1
DNS server Resolves domain names to IP addresses An approved DNS server
MAC address Link-layer address associated with a network interface 00:1A:2B:3C:4D:5E

The example MAC address is illustrative. Actual device addresses must be obtained from the equipment or its network interface.

4. IPv4 Address and Subnet Mask

The subnet mask determines which addresses belong to the same IP subnet.

For example:

  • Device A: 192.168.10.25/24
  • Device B: 192.168.10.40/24

Both devices belong to the subnet 192.168.10.0/24. If they are connected through a suitable Layer 2 network and no other issue exists, they can communicate directly without a router.

Now consider:

  • Device A: 192.168.10.25/24
  • Device B: 192.168.20.40/24

These devices belong to different subnets. Communication between them normally requires routing and appropriate network configuration.

The subnet mask 255.255.255.0 is equivalent to prefix /24.

For a conventional IPv4 subnet:

\[ \text{Total addresses}=2^{32-p} \]

where \(p\) is the prefix length.

For /24:

\[ 2^{32-24}=256 \]

A conventional /24 IPv4 subnet has 256 total addresses, typically 254 usable host addresses because the all-zero host address identifies the subnet and the all-one host address is its directed broadcast address. Special-purpose subnets, including /31 and /32, follow different rules.

5. Private IPv4 Address Ranges

Industrial automation networks commonly use private IPv4 addressing. Private addresses are intended for internal networks and are not globally routable across the public internet.

Private range Prefix Typical application
10.0.0.0 to 10.255.255.255 /8 Large industrial or enterprise networks
172.16.0.0 to 172.31.255.255 /12 Segmented plant and departmental networks
192.168.0.0 to 192.168.255.255 /16 Small networks, machine cells, and local devices

These are private ranges defined for internal addressing. An organization must still coordinate their use to prevent overlaps between plants, production cells, remote-access networks, and connected corporate systems.

Do not assume that every address beginning with 192.168 is suitable for a particular machine. The assigned subnet must match the approved network plan.

6. Static IP Versus DHCP

Two common methods are used to assign IPv4 addresses.

Static IP assignment means the address is configured manually on the device or through an approved management system.

Dynamic Host Configuration Protocol (DHCP) allows a DHCP server to supply network configuration, including IP addresses, to clients.

Feature Static assignment DHCP
Address allocation Manually configured or centrally reserved Assigned by a DHCP server
Predictability High when properly managed Depends on lease and reservation configuration
Common industrial use PLCs, robots, CNCs, fixed infrastructure Managed computers and supported client devices
Main risk Manual entry errors and duplicate addresses Server dependency and unexpected address changes
Documentation Requires an accurate IP register Requires lease or reservation records
Recovery Often predictable if configuration is preserved Depends on DHCP availability and client behavior

Some industrial devices support DHCP reservations, where the DHCP server consistently assigns a planned address to a particular client. Whether this is suitable depends on the device, network architecture, and plant standard.

Do not change a device from static addressing to DHCP without confirming the approved configuration and recovery method.

7. Default Gateway and DNS

7.1 Default gateway

The default gateway is the router used when a device needs to communicate with an IP destination outside its local subnet.

For example:

Setting Example value
Device IP 192.168.10.25
Subnet mask 255.255.255.0
Default gateway 192.168.10.1
Destination IP 192.168.20.40

Because the destination is outside 192.168.10.0/24, the device normally sends the traffic to its configured gateway, provided routing and security policies permit it.

Devices communicating only within an isolated machine subnet may not require a default gateway. Configure one only when required by the approved network design.

7.2 DNS

The Domain Name System (DNS) resolves hostnames to IP addresses.

For example, an engineering workstation might connect to a server using its hostname instead of an IP address.

DNS is not required for every direct industrial communication. Some PLCs, robots, and CNC controllers communicate using configured IP addresses without DNS.

A failed hostname lookup does not necessarily mean that the destination device is offline. It may indicate a DNS problem while direct IP communication remains functional.

8. Industrial Network Address Planning

Before assigning addresses, establish the network scope and addressing plan.

The plan should identify:

  • Production line, machine cell, and network segment.
  • Device name and equipment identification.
  • Device manufacturer and model.
  • Ethernet interface or port identity.
  • IP address and subnet mask or prefix.
  • Default gateway, if required.
  • DHCP or static-addressing method.
  • VLAN or network segment, where applicable.
  • Responsible department and change approval.
  • Required communication partners and protocols.

A simple industrial network might use the following logical structure:

Plant Industrial Network
        ↓
Production Line Network
        ↓
Machine Cell Subnet
        ↓
PLC / HMI / Robot / CNC / Engineering PC

This is a logical hierarchy, not a requirement that every layer use a separate physical switch or subnet. The actual design depends on plant architecture, routing, VLANs, industrial protocols, and cybersecurity requirements.

9. Example IP Address Plan for a Machine Cell

The following example illustrates a dedicated machine-cell subnet. These addresses are examples only, not recommended assignments for an existing production network without approval.

Subnet: 192.168.10.0/24

Device Hostname Example IP address Purpose
Cell PLC CELL01-PLC 192.168.10.10 Machine control
HMI CELL01-HMI 192.168.10.11 Operator interface
Robot controller CELL01-ROB1 192.168.10.12 Robot control
CNC controller CELL01-CNC1 192.168.10.13 CNC operation
Industrial PC CELL01-IPC 192.168.10.20 Data collection or engineering
Managed switch CELL01-SW1 192.168.10.2 Switch management
Engineering laptop ENG-LAPTOP 192.168.10.100 Temporary engineering access

The network address is 192.168.10.0, and the conventional broadcast address is 192.168.10.255. Neither should be assigned to an ordinary host interface in this /24 subnet.

The address register must be checked against the plant's existing allocation records before implementation. A locally unused address may still be assigned elsewhere in the wider network.

10. IP Address Conflicts

An IP address conflict occurs when multiple devices use the same IP address within the same network context.

Possible symptoms include:

  • Intermittent communication.
  • Duplicate-address warnings.
  • Unexpected loss of connection.
  • A device becoming reachable inconsistently.
  • Communication working after one device is disconnected but failing when it returns.

Potential causes include manual assignment errors, overlapping DHCP pools, copied device configurations, replacement equipment retaining an old address, or unauthorized connection of a device.

Conflict investigation procedure

  1. Record the affected device's IP address, MAC address, and observed symptoms.
  2. Check the approved IP register and DHCP configuration where applicable.
  3. Inspect switch information and network diagnostics using authorized tools.
  4. Determine which interfaces are using the conflicting address.
  5. Identify the correct address assignment from the approved plan.
  6. Correct the configuration through the authorized change procedure.
  7. Verify communication with the intended devices.
  8. Update the address register and change record.

Do not randomly change IP addresses on production equipment to see what happens. That approach can disconnect additional systems and destroy useful diagnostic evidence.

11. Physical Connection and Ethernet Link Verification

IP configuration is only one part of network connectivity. The physical and data-link layers must also function correctly.

Check:

  • Ethernet cable condition and connector seating.
  • Correct switch port and device interface.
  • Link indicators at both ends, where provided.
  • Switch port administrative and operational status.
  • Correct VLAN assignment.
  • Port security and access-control restrictions.
  • Speed and duplex negotiation, where relevant.
  • Supported Ethernet interface specifications.

A link indicator usually confirms that an Ethernet link has been established. It does not prove that the IP address, subnet, routing, or application protocol is correct.

Similarly, a successful ping does not prove that the PLC programming software, robot engineering software, or industrial protocol connection will work.

12. Network Segmentation and VLANs

A Virtual Local Area Network (VLAN) logically separates devices into Layer 2 broadcast domains using managed network infrastructure.

VLANs may be used to separate:

  • Robot and machine-control devices.
  • Engineering workstations.
  • Supervisory systems.
  • Plant IT networks.
  • Remote-access infrastructure.

Devices in different VLANs generally require Layer 3 routing to communicate. The relevant routing, access-control, and security policies must permit the intended traffic.

An IP address alone does not determine VLAN membership. VLAN configuration is normally applied through the switch infrastructure and associated network design.

Incorrect VLAN assignment can make a correctly configured device unreachable even when its IP address and subnet mask are correct.

13. Industrial Protocols and IP Assignment

Industrial Ethernet protocols may use IP addressing, but they do not all use IP in the same way.

Protocol or technology Typical role IP-related consideration
Modbus TCP Industrial data exchange Uses TCP/IP and configured endpoints
EtherNet/IP Industrial control and device communication Uses IP networking; device-specific configuration may also be required
PROFINET Industrial Ethernet automation Uses IP for applicable services, while real-time communication also relies on Layer 2 mechanisms
OPC UA Structured industrial data exchange Commonly uses configured network endpoints and application security settings
HTTP/HTTPS Web interfaces and dashboards Uses IP connectivity and the relevant TCP port
ICMP Network diagnostics such as ping May be blocked even when application communication is allowed

Correct IP addressing is necessary for many industrial Ethernet connections, but it is not sufficient by itself.

For example, an EtherNet/IP device may also require correct controller configuration, device identity, compatible communication settings, and appropriate network infrastructure. A PROFINET device may require additional engineering configuration and correct device naming, depending on the system.

14. IP Assignment During Site Commissioning

A controlled site procedure reduces the risk of disconnecting equipment or introducing duplicate addresses.

Stage 1: Preparation

  1. Obtain the approved network topology and IP allocation register.
  2. Identify all relevant network interfaces, including multiple ports on the same device.
  3. Verify the intended subnet, prefix, VLAN, and gateway requirements.
  4. Confirm the device's existing configuration.
  5. Check for duplicate addresses and overlapping network ranges.
  6. Confirm the authorized maintenance window and rollback plan.

Stage 2: Configuration

  1. Access the device through its approved engineering interface.
  2. Record the existing address and network settings.
  3. Apply the approved IP address, subnet mask, and any required gateway or DNS settings.
  4. Apply VLAN or switch-port changes through the authorized network configuration process.
  5. Save the configuration using the device manufacturer's procedure.
  6. Restart or reconnect the device only if required by the documented procedure.

Stage 3: Verification

  1. Confirm the device's actual configured network settings.
  2. Check physical link status and switch-port information.
  3. Verify that the address is not conflicting with another device.
  4. Test connectivity from an authorized workstation in the appropriate network.
  5. Verify the required application protocol and engineering connection.
  6. Confirm communication with the intended PLC, robot, CNC, or supervisory system.
  7. Record the test result and update the network register.

Stage 4: Handover

  • Record the final IP address and subnet.
  • Document the device identity, port, and network segment.
  • Record the verification results.
  • Update drawings and network records.
  • Preserve the approved configuration and recovery instructions.

15. Windows Network Diagnostic Commands

An engineering PC can be used for basic network diagnostics when access is authorized.

Command Purpose Important limitation
ipconfig Displays local IP configuration Does not prove remote reachability
ipconfig /all Displays detailed interface configuration Review all interfaces, including virtual adapters
ping 192.168.10.10 Tests ICMP reachability ICMP may be blocked
arp -a Displays cached IPv4-to-MAC mappings The cache may be incomplete or stale
route print Displays local routing information Does not prove that remote routing works
tracert 192.168.20.40 Attempts to show the IP route to a destination Intermediate routers may not respond
nslookup hostname Tests DNS name resolution Relevant only when hostname resolution is involved
getmac Displays local MAC addresses Does not identify every remote device on the network

Example diagnostic sequence:

ipconfig /all
        ↓
Check IP address, subnet mask and gateway
        ↓
ping <approved-device-IP>
        ↓
Check local routing and ARP information
        ↓
Verify VLAN, switch port and network path
        ↓
Test the required industrial application

Replace the example destination with an authorized device address from the network register.

A failed ping alone does not prove that the destination is disconnected. ICMP may be disabled or filtered. Conversely, a successful ping does not establish that the required industrial application is working.

16. Troubleshooting by Symptom

Symptom Possible cause Diagnostic approach
Device is unreachable Incorrect IP, disconnected cable, wrong VLAN Verify configuration, physical link, and switch port
Ping reports destination unreachable Local route or network path problem Inspect subnet, routing table, and gateway
Ping times out Device offline, ICMP filtered, network issue Verify link and application-specific connectivity
Device works locally but not remotely Routing or access-control issue Check gateway, routes, VLANs, and firewall rules
Intermittent communication Duplicate IP, cabling issue, switch problem Check address conflicts and network diagnostics
HMI cannot connect to PLC Incorrect endpoint, protocol settings, or access restrictions Verify both endpoints and the required application connection
Robot or CNC engineering software cannot connect Wrong interface, subnet mismatch, unsupported connection method Verify engineering PC interface and controller settings
Hostname fails but IP works DNS or hostname configuration issue Check name resolution
Device becomes unreachable after address change New address is incorrect or outside the workstation's reachable network Verify the new settings and approved recovery method
Multiple devices lose communication Shared switch, power, VLAN, or upstream network fault Investigate common infrastructure before individual device settings

17. Multiple Network Interfaces

Some industrial devices contain multiple Ethernet interfaces. These interfaces may serve different purposes, such as controller communication, engineering access, safety-related communication, or connection to a separate machine network.

Important rules include:

  • Record each interface separately.
  • Confirm whether interfaces are independent, bridged, or configured for redundancy.
  • Avoid assigning addresses that create ambiguous routing.
  • Do not connect separate networks together without authorization.
  • Follow the manufacturer's requirements for port usage and network topology.
  • Verify that the intended application uses the correct interface.

A device with two Ethernet ports does not necessarily have two independent network interfaces. Some ports may be part of an internal switch or intended for a specific topology.

18. Cybersecurity and Change Control

Industrial network configuration must be managed to preserve availability, integrity, and controlled access.

Good practices include:

  • Use approved address plans and maintain a central register.
  • Restrict configuration access to authorized personnel.
  • Avoid unauthorized laptops, switches, routers, and wireless access points.
  • Segment industrial networks according to the plant security design.
  • Apply approved firewall and access-control rules.
  • Document remote-access paths and required communication endpoints.
  • Back up relevant switch and device configurations.
  • Coordinate network changes with maintenance, controls engineering, and IT/OT teams.
  • Validate the production process after authorized changes.

Do not expose PLCs, robot controllers, CNC controllers, or other control devices directly to public networks. Remote access should follow the organization's approved secure architecture.

19. Network IP Assignment Documentation

Maintain a controlled network register containing enough information to identify each interface and recover its configuration.

Field Example
Equipment ID CELL01-PLC
Device type PLC
Manufacturer and model Actual installed hardware

Subnet or prefix 192.168.10.0/24

Addressing method Static or approved DHCP reservation
VLAN or network zone As specified by the network design

Communication partners Approved PLC, HMI, SCADA, or other endpoints

For production systems, avoid recording sensitive credentials in an ordinary IP register. Store authentication information through the approved credential-management process.

20. Common Mistakes to Avoid

  • Assigning an address without checking the approved network register.
  • Using an incorrect subnet mask.
  • Configuring an unnecessary or incorrect gateway.
  • Ignoring DHCP reservations and address pools.
  • Assuming a successful ping proves the industrial protocol works.
  • Treating a link indicator as proof of correct IP configuration.
  • Overlooking VLANs, routing, and firewall rules.
  • Connecting multiple network interfaces without understanding their roles.
  • Changing production network settings without a rollback plan.
  • Failing to document the final configuration.
  • Assuming all devices use the same default IP address.
  • Copying network settings from another machine without checking for conflicts.

21. Interview Questions and Answers

Q1. What is IP assignment?

It is the process of allocating and configuring IP addresses and associated network settings for devices so they can communicate on the intended network.

Q2. What is the difference between an IP address and a MAC address?

An IP address provides logical addressing at the network layer. A MAC address is used for link-layer communication within the relevant local network technology.

Q3. What is the purpose of a subnet mask?

It identifies the network and host portions of an IPv4 address, allowing a device to determine whether a destination is local or requires routing.

Q4. What is a default gateway?

It is the router used to forward traffic to destinations outside the device's local subnet.

Q5. What is the difference between static IP and DHCP?

Static assignment uses a manually configured address or an approved fixed allocation. DHCP supplies network configuration dynamically, optionally using reservations to keep assignments predictable.

Q6. Why might a device fail to communicate even when its IP address is correct?

Possible causes include an incorrect subnet mask, wrong VLAN, missing route, firewall restriction, physical-link fault, duplicate address, or incorrect application settings.

Q7. What does a successful ping prove?

It shows that an ICMP echo exchange succeeded with the responding endpoint at that time. It does not prove that the required industrial application or control protocol works.

Q8. What is an IP address conflict?

It occurs when multiple interfaces use the same IP address within the same network context, potentially causing unstable or failed communication.

Q9. Why should IP addresses be documented?

Documentation prevents duplicate assignments, supports troubleshooting, preserves network traceability, and speeds up equipment replacement and commissioning.

Q10. What is a VLAN?

A VLAN is a logical Layer 2 network segment used to separate traffic into distinct broadcast domains.

Q11. Why can two devices on different subnets fail to communicate?

Communication normally requires a valid routing path and permitted traffic between the networks. Correct local IP settings alone are insufficient.

Q12. What should be checked after changing a PLC or robot IP address?

Verify the final address and subnet, link status, absence of conflicts, intended device reachability, application-level communication, and updated documentation.

22. Final Checklist

  • Approved IP address plan available.
  • Device identity and all relevant network interfaces verified.
  • IP address and subnet mask or prefix confirmed.
  • Gateway and DNS configured only as required.
  • Static or DHCP assignment method verified.
  • Address conflict and network overlap checks completed.
  • Ethernet link and switch-port configuration checked.
  • VLAN, routing, and security policies verified where applicable.
  • Connectivity and required industrial application tested.
  • Final settings recorded in the network register.
  • Change authorization and rollback information preserved.
  • Handover documentation updated.

23. Key Takeaways

IP assignment is a controlled network-engineering activity, not just a device setting. Reliable industrial communication requires correct addressing, subnet configuration, physical connectivity, network segmentation, routing where needed, compatible application settings, and accurate documentation.

During site commissioning, verify the actual network path and the intended application connection before declaring the system operational. Preserve the previous configuration, follow the approved change procedure, and update the address register after every authorized change.
