1. Definition and Purpose

I/O verification (Input/Output verification) is the systematic checking of signals between field devices and the control system to confirm that every input and output is correctly wired, assigned, configured, identified, and mapped to the approved control logic.

In industrial automation, I/O connects the physical machine to its control system. Sensors provide information about machine conditions, and output devices perform actions based on controller commands.

Examples include:

  • A proximity sensor indicating that a fixture is in position.
  • A limit switch confirming that a pneumatic cylinder has reached its end position.
  • A pressure transmitter providing an analog pressure measurement.
  • A PLC output commanding a contactor or solenoid valve.
  • A safety input reporting the state of an emergency-stop circuit to a safety controller.

I/O verification establishes that the intended field device corresponds to the correct controller channel and that the signal has the expected electrical behavior.

A signal can be wired to a physically valid terminal and still be wrong because the channel address, polarity, signal type, common connection, or program mapping is incorrect.

2. What Is an I/O System?

An I/O system provides the interface between field devices and a controller such as a PLC, CNC controller, robot controller, or distributed control system.

Physical Process
      ↓
Sensors and Switches
      ↓
Field Wiring and Terminals
      ↓
Input Modules
      ↓
PLC or Controller Logic
      ↓
Output Modules
      ↓
Field Wiring and Terminals
      ↓
Actuators and Loads
      ↓
Physical Process

For distributed I/O, communication networks and remote I/O adapters also form part of the signal path.

The complete path may include terminal blocks, marshalling terminals, isolation devices, safety relays, signal conditioners, remote I/O racks, and communication links.

3. Types of I/O

3.1 Digital Inputs

A digital input represents a discrete state, usually ON/OFF or TRUE/FALSE.

Typical devices include:

  • Proximity sensors.
  • Photoelectric sensors.
  • Limit switches.
  • Pushbuttons.
  • Selector switches.
  • Pressure switches.
  • Auxiliary contacts.
  • Valve-position feedback switches.

A 24 V DC digital input often interprets a voltage within a defined range as ON and a voltage within another range as OFF. The exact thresholds depend on the module specification.

Examples:

Field device Typical PLC input meaning
Fixture-closed sensor Fixture is closed
Part-present sensor Part is detected
Motor overload contact Overload trip status
Cylinder-retracted switch Cylinder is retracted
Drive-ready contact Drive reports ready
Guard-position switch Guard position status

The actual logic meaning must be verified against the electrical drawing and control program. A TRUE input does not always mean that the machine condition is safe or healthy.

3.2 Digital Outputs

A digital output commands a discrete action.

Typical loads include:

  • Relay coils.
  • Contactor coils.
  • Solenoid valves.
  • Indicator lamps.
  • Buzzer circuits.
  • Drive-enable signals.
  • Interposing relays.

Examples:

PLC output meaning Physical action
Conveyor run command Requests conveyor operation
Clamp solenoid command Commands the clamp valve
Tower lamp green Commands the green indicator
Lubrication command Requests lubrication operation
Drive enable Requests drive enable, subject to other conditions

A commanded output does not prove that the actuator operated. Output verification and feedback verification are separate checks.

3.3 Analog Inputs

Analog inputs measure continuously varying signals.

Common examples include:

  • 4–20 mA.
  • 0–20 mA.
  • 0–10 V.
  • 1–5 V.
  • Thermocouple signals.
  • RTD signals through suitable input modules or transmitters.

Typical measurements include pressure, temperature, flow, force, level, and speed feedback.

Analog input verification must include the signal range, polarity, scaling, engineering units, and fault behavior.

3.4 Analog Outputs

Analog outputs command a continuously varying reference.

Examples include:

  • Speed reference to a compatible drive.
  • Valve position reference.
  • Pressure setpoint to a compatible controller.
  • Position or process reference to another device.

Verify the output range, scaling, direction of change, electrical interface, and behavior during controller startup or fault conditions.

3.5 Pulse, High-Speed, and Specialized I/O

Some applications require specialized interfaces, including:

  • High-speed counters.
  • Encoder inputs.
  • Pulse-train outputs.
  • PWM signals.
  • Thermocouple and RTD inputs.
  • Load-cell interfaces.
  • Communication-based device data.
  • Safety-rated digital I/O.

These signals may require specific module types and configuration. Ordinary digital I/O cannot automatically replace a high-speed counter or safety-rated channel.

4. I/O List and Address Mapping

The I/O list is a controlled engineering document that maps physical field devices to controller channels and logical signals.

A useful I/O list includes:

  • Signal tag.
  • Signal description.
  • Equipment or process reference.
  • Signal type.
  • Field device type.
  • PLC or controller designation.
  • Rack, station, slot, and channel.
  • Address or symbolic tag.
  • Electrical characteristics.
  • Normal state.
  • Active state.
  • Terminal reference.
  • Cable reference.
  • Fail-state or diagnostic behavior where relevant.
  • Remarks and revision information.

4.1 Example I/O list

Signal tag Description Type Example address Expected behavior
DI_FIXTURE_CLOSED Fixture closed sensor Digital input I0.0 ON when closed
DI_PART_PRESENT Part detected Digital input I0.1 ON when detected
DI_MOTOR_TRIP Motor protection trip Digital input I0.2 ON when trip contact indicates fault
DO_CLAMP_CMD Clamp valve command Digital output Q0.0 ON requests clamping
DO_CONVEYOR_RUN Conveyor run request Digital output Q0.1 ON requests conveyor run
AI_PRESSURE Pressure measurement Analog input AIW64 Scaled to pressure units
AO_SPEED_REF Speed reference Analog output AQW64 Scaled to reference range

These addresses are illustrative only. Real addressing depends on the PLC family, hardware configuration, addressing mode, and project.

4.2 Physical address versus symbolic tag

A physical address identifies a channel or memory location according to the controller's addressing system. A symbolic tag gives the signal a meaningful name.

For example:

Physical Input Address: I0.0
Symbolic Tag: DI_FIXTURE_CLOSED
Description: Fixture closed sensor

Symbolic naming improves readability, troubleshooting, program maintenance, and cross-referencing between electrical drawings and PLC logic.

4.3 Address verification

Check that:

  1. The physical device is connected to the specified terminal.
  2. The terminal maps to the correct input or output channel.
  3. The configured hardware matches the installed module.
  4. The channel address matches the controller project.
  5. The symbolic tag references the intended channel.
  6. The HMI or SCADA tag references the intended controller signal.
  7. The functional description matches the actual machine behavior.

A single address mismatch can make the wrong signal appear active or cause a sequence to operate incorrectly.

5. Digital Input Verification

Digital input verification confirms that a field-device state reaches the intended controller channel with the expected electrical and logical interpretation.

5.1 Procedure

  1. Identify the device using the electrical drawing and I/O list.
  2. Confirm the device's supply voltage and output type.
  3. Verify terminal numbers, cable identification, and core assignment.
  4. Confirm the input module's electrical compatibility and common arrangement.
  5. Ensure the circuit is safe to test and that the required machine safeguards remain effective.
  6. Use the approved test method to operate or simulate the input.
  7. Observe the module's channel indicator, if available.
  8. Monitor the corresponding PLC input or symbolic tag.
  9. Compare the actual state with the expected device state.
  10. Verify the logical interpretation in the program.
  11. Record the result and restore the circuit to its normal condition.

5.2 PNP and NPN sensor considerations

For typical three-wire DC sensors:

  • PNP output: The sensor switches the output toward the positive supply when active.
  • NPN output: The sensor switches the output toward the 0 V reference when active.

The sensor output type must be compatible with the input module's electrical design and wiring arrangement.

Do not assume every PLC input is compatible with both types. Verify the module datasheet and approved circuit.

5.3 NO and NC behavior

Normally open (NO) and normally closed (NC) describe the contact's behavior in its defined unactuated state.

For solid-state sensors, manufacturers may use NO/NC to describe output switching behavior. Verify the datasheet and actual logic.

An NC contact is not automatically a safety-rated device, and its use does not by itself guarantee fault detection.

6. Digital Output Verification

Digital output verification confirms that the controller's intended command reaches the correct output channel and that the output circuit is suitable for its load.

6.1 Procedure

  1. Identify the output tag, address, terminal, and connected load.
  2. Verify the output module type and electrical rating.
  3. Check the load voltage, current, and inrush requirements.
  4. Verify the circuit protection and any interposing relay.
  5. Confirm that the test is authorized and the machine is in a safe state.
  6. Use the approved commissioning procedure to command the output.
  7. Observe the output-channel indicator and relevant controller status.
  8. Verify the electrical output at the designated test point if required.
  9. Confirm that the intended load responds correctly.
  10. Check the corresponding feedback signal where provided.
  11. Return the output and machine to the defined safe state.
  12. Record the result.

6.2 Why output feedback matters

Consider a PLC output commanding a solenoid valve.

The following are different conditions:

  • The PLC command is TRUE.
  • The output channel is energized.
  • The solenoid coil receives the required voltage.
  • The valve shifts.
  • The actuator moves.
  • The actuator reaches the expected position.

Each step can fail independently.

For example, a TRUE output tag with no actuator movement could indicate a failed output channel, missing supply, broken conductor, faulty coil, jammed valve, loss of air pressure, or mechanical obstruction.

Never bypass interlocks or force outputs on hazardous equipment merely to prove a signal. Use an approved test method and preserve required protective functions.

7. Analog Input Verification and Scaling

Analog verification must confirm both the electrical signal and its conversion into engineering units.

7.1 Example: 4–20 mA pressure transmitter

Assume:

  • Transmitter range: 0–10 bar.
  • Signal range: 4–20 mA.
  • Measured current: 12 mA.

The linear scaling equation is:

\[ PV = \frac{I-I\_{\min}}{I\_{\max}-I\_{\min}}(PV\_{\max}-PV\_{\min})+PV\_{\min} \]

Where:

  • \(PV\) is the process value.
  • \(I\) is the measured current.
  • \(I\_{\min}\) and \(I\_{\max}\) are the signal limits.
  • \(PV\_{\min}\) and \(PV\_{\max}\) are the engineering range limits.

For this example:

\[ PV = \frac{12-4}{20-4}(10-0)+0 \]
\[ PV = 5\text{ bar} \]

A 12 mA signal therefore represents 5 bar under the assumed linear configuration.

7.2 Why 4–20 mA is useful

A 4–20 mA signal uses a nonzero lower-range value, commonly called a live zero. This can help distinguish a valid zero-range measurement from some wiring faults, such as an open loop.

However, fault detection depends on the transmitter's configured failure-current behavior and the receiving module's diagnostic thresholds. Not every abnormal current is automatically detected.

7.3 Analog verification procedure

  1. Confirm the transmitter type and configured range.
  2. Verify the input module supports the required signal.
  3. Check polarity and loop wiring.
  4. Confirm shield and grounding arrangements.
  5. Use an approved calibrator or reference instrument where required.
  6. Apply specified test points across the range.
  7. Record the input signal and raw module value.
  8. Verify conversion to engineering units.
  9. Compare the PLC value with the expected reference.
  10. Check under-range, over-range, and diagnostic behavior where applicable.
  11. Verify HMI display, decimal places, and units.
  12. Record deviations and retest after correction.

7.4 Analog signal error

For a known reference value:

\[ \text{Error} = \text{Measured Value} - \text{Reference Value} \]

For a nonzero reference:

\[ \text{Percentage Error} = \frac{\text{Measured Value}-\text{Reference Value}}{\text{Reference Value}}\times100\\% \]

Percentage error can be misleading when the reference value is near zero. In that situation, use an appropriate absolute-error or full-scale-error criterion from the applicable specification.

8. Analog Output Verification

Analog output verification checks that the controller generates the intended signal and that the connected device interprets it correctly.

For example, a drive may accept a 0–10 V speed reference.

Verify:

  • Correct output module and channel.
  • Correct voltage or current range.
  • Correct wiring and polarity.
  • Correct raw output value.
  • Correct scaling in engineering units.
  • Correct direction and response.
  • Defined output behavior during startup, stop, and fault conditions.
  • Compatible receiving device.
  • Safe limits on the commanded value.

If the PLC program requests 50% speed, the corresponding electrical output depends on the configured scaling. The receiving drive may also apply minimum and maximum frequency limits, ramps, and other parameters.

Do not assume that 50% of the analog output range always means 50% of the machine's physical speed.

9. Remote I/O Verification

Remote I/O places input and output modules away from the main controller and communicates with them through an industrial network.

Typical components include:

  • Remote I/O adapter or coupler.
  • Digital and analog I/O modules.
  • Field power supplies.
  • Network cables and switches.
  • PLC or controller configuration.
  • Device names or network addresses.

9.1 Verification points

Check:

  • Correct adapter model.
  • Correct module sequence and slot configuration.
  • Correct network address or device name.
  • Correct firmware compatibility.
  • Correct network cabling.
  • Correct field power supply.
  • Correct module and channel diagnostics.
  • Correct controller I/O mapping.
  • Correct behavior after communication loss, as defined by the approved design.

A remote I/O rack may be powered and visible on the network while one or more modules remain incorrectly configured.

9.2 Communication loss behavior

Confirm that loss of communication produces the designed response.

Depending on the application, outputs may be configured to turn off, hold their last state, or enter another defined state. The correct behavior depends on the device, process risk, and approved control design.

Do not assume that holding the last output state is safe.

For safety-related outputs, the required behavior must follow the validated safety architecture and applicable standards.

10. Safety I/O Verification

Safety I/O includes safety-rated input and output channels used for functions such as emergency stops, guard monitoring, and safe actuator control.

Safety verification is not equivalent to checking whether an ordinary PLC input changes state.

Check:

  • Approved safety architecture.
  • Correct safety-rated modules and devices.
  • Channel assignment and wiring.
  • Dual-channel arrangements where specified.
  • Cross-short and discrepancy monitoring where required.
  • Reset and restart behavior.
  • Feedback monitoring and contactor monitoring where specified.
  • Defined response to wire breaks and faults.
  • Diagnostic reporting.
  • Required safety-function validation records.

Safety functions must be tested according to the approved validation plan. Never bypass an emergency stop, guard interlock, or safety input to make commissioning easier.

A standard PLC status bit must not be treated as proof that a safety function is valid.

11. Interlocks and Sequence Verification

I/O verification should establish that signals have the correct physical meaning. Interlock and sequence verification establishes that the control logic uses those signals correctly.

Example: a fixture-clamping sequence.

Part Present
      ↓
Clamp Command Permitted
      ↓
Clamp Solenoid Energized
      ↓
Clamp Closed Feedback
      ↓
Next Process Step Permitted

This is a simplified logical example. Actual permissives, safety conditions, timeouts, and fault responses must follow the approved machine design.

Check:

  • Correct permissive inputs.
  • Correct command outputs.
  • Correct feedback signals.
  • Correct interlock behavior.
  • Correct timeout handling.
  • Correct fault message.
  • Correct recovery sequence.
  • No unintended output activation.
  • No unexpected restart after power restoration or fault reset.

A machine can have perfectly wired I/O but still operate incorrectly because of an error in sequence logic.

12. I/O Forcing and Simulation

Forcing is a commissioning or troubleshooting method that overrides a normal controller signal or state. It can be useful but creates significant risks.

Potential hazards include:

  • Unexpected movement.
  • Energization of actuators.
  • Defeated process interlocks.
  • Misleading diagnostic results.
  • Unintended operation after testing.
  • Unsafe restart if overrides remain active.

12.1 Safe practices

  • Follow the site's approved forcing procedure.
  • Obtain authorization.
  • Establish the safe machine condition before testing.
  • Identify the exact tag or channel being overridden.
  • Confirm the effect on connected equipment.
  • Preserve required safety functions.
  • Use simulation or disconnected loads when suitable.
  • Maintain communication with affected personnel.
  • Record every applied force or override.
  • Remove all temporary forces and verify their removal.
  • Restore normal operation only through the approved process.

Forcing an ordinary PLC bit does not validate the field wiring. It only changes the controller's interpretation or command path at the point where the force is applied.

Output tag ON but load inactive Missing load supply, open circuit, failed output or load Check channel status, voltage, wiring, load condition

14. Practical Example: PLC Digital I/O Checkout

Assume a station contains:

  • One part-present sensor.
  • One clamp-closed sensor.
  • One clamp solenoid.
  • One conveyor-run command.
  • One motor-overload feedback.

A useful test record might look like this:

Signal Test action Expected result Actual result
Part-present input Present a test part under safe conditions Input changes to ON Record observation
Clamp-closed input Operate clamp under approved test conditions Feedback matches actual position Record observation
Clamp solenoid output Command through approved test mode Correct output channel operates Record observation
Conveyor-run output Test with the defined safe conditions Correct run circuit responds Record observation
Motor-overload input Use approved contact simulation or test procedure Fault status changes as designed Record observation

The table is a test template, not evidence that any test has passed.

For each point, record the signal tag, physical address, terminal reference, test method, result, defect reference, and retest result.

15. I/O Verification Documentation

A complete I/O checkout record should contain:

  • Machine or station identification.
  • PLC or controller name.
  • Module and channel identification.
  • Signal tag and description.
  • Signal type.
  • Field-device identification.
  • Physical address and terminal reference.
  • Cable identification.
  • Expected state or range.
  • Test method.
  • Actual result.
  • Acceptance criteria.
  • Defect or punch-list reference.
  • Corrective action.
  • Retest result.
  • Tester and date.
  • Approval status.

Maintain traceability between the I/O list, electrical drawings, PLC project, HMI tags, and commissioning records.

Any approved changes to addresses, wiring, or signal definitions must be reflected in the controlled documentation.

16. Common Mistakes to Avoid

  • Assuming that a module LED proves the complete signal path is correct.
  • Confusing the physical I/O address with the symbolic tag.
  • Ignoring PNP/NPN compatibility.
  • Ignoring input common and reference wiring.
  • Treating an output command as proof of actuator movement.
  • Testing analog signals without checking scaling.
  • Assuming 4 mA means zero electrical signal rather than the live-zero point.
  • Using an ordinary PLC bit to validate a safety function.
  • Leaving temporary forces or overrides active.
  • Bypassing interlocks during commissioning.
  • Ignoring remote I/O module configuration.
  • Failing to verify HMI tag mapping.
  • Testing outputs without considering connected machinery.
  • Failing to document defects and retest results.

17. Interview Questions and Answers

Q1. What is I/O verification?

It confirms that field signals are correctly wired, mapped, configured, and interpreted by the control system, and that output commands reach the intended devices.

Q2. What is the difference between digital and analog I/O?

Digital I/O represents discrete states, while analog I/O represents a continuously varying measurement or command within a specified range.

Q3. What is the difference between an input and an output?

An input brings field information into the controller. An output carries a controller command toward a field device or connected control circuit.

Q4. What is PNP versus NPN?

For typical three-wire DC sensors, PNP switches the output toward the positive supply when active, while NPN switches the output toward the 0 V reference. The input circuit must be compatible with the sensor.

Q5. Why can an output tag be ON while an actuator does not move?

The load supply may be missing, the output channel or wiring may be faulty, the load may have failed, or a mechanical or pneumatic condition may prevent movement.

Q6. How is a 4–20 mA signal scaled?

Use the measured current relative to the configured lower and upper signal limits, then map that fraction to the engineering range.

Q7. What is remote I/O?

Remote I/O consists of input and output modules located away from the main controller and connected through an industrial communication network.

Q8. Why is I/O forcing risky?

It can override normal control behavior and cause unexpected machine operation. Forces must be authorized, controlled, documented, and removed after testing.

Q9. How does I/O verification differ from sequence testing?

I/O verification checks signal identity, wiring, state, and mapping. Sequence testing checks whether the control program uses the verified signals correctly through the intended machine sequence.

Q10. Can ordinary PLC I/O prove an emergency-stop function is safe?

No. Safety-function acceptance requires verification and validation of the approved safety architecture, devices, wiring, diagnostics, and required performance.

18. Final Pre-Power I/O Checklist

  • Approved I/O list and electrical drawings are available.
  • Installed I/O modules match the configured hardware.
  • Channel addresses and symbolic tags are verified.
  • Field devices and cable tags match the drawings.
  • Input supply, output supply, commons, and references are checked.
  • Digital input behavior is verified.
  • Digital output circuits and connected loads are checked safely.
  • Analog input and output ranges are verified.
  • Scaling and engineering units are checked.
  • Remote I/O communication and module configuration are verified.
  • Safety I/O is tested under the approved validation procedure.
  • Interlocks and sequence permissives are checked where required.
  • Temporary forces and overrides are removed and verified.
  • Defects are corrected and required retests completed.
  • I/O checkout records and controlled drawings are updated.
  • Required authorization obtained before energization or functional commissioning.

19. Key Takeaways

I/O verification establishes the relationship between a physical device, its wiring, the controller channel, the program tag, and the intended machine behavior.

The most important checks are correct channel mapping, electrical compatibility, signal polarity and state, analog scaling, output-load behavior, remote I/O configuration, and safety-function integrity.

A successful I/O checkout is based on actual test evidence, not merely an illuminated module LED or a TRUE PLC bit. It provides the foundation for reliable sequence testing and safe machine commissioning.
