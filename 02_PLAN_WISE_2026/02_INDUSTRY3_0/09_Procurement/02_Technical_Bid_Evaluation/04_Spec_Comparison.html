1. What is specification comparison?

Specification comparison is the systematic, requirement-by-requirement evaluation of technical parameters offered by different suppliers or manufacturers against a common approved specification.

It establishes whether the proposed equipment meets the required ratings, performance, interfaces, environmental conditions, functionality, safety requirements, and other technical conditions.

In industrial automation procurement, specification comparison is essential because two products may have the same general purpose but differ significantly in their actual capabilities.

For example, two VFDs may both be rated at 7.5 kW, but one may have insufficient overload capacity, lack the required industrial communication protocol, or fail to support the required safety function.

The comparison must therefore evaluate the complete set of relevant parameters rather than a single headline specification.

2. Objectives of specification comparison

Specification comparison helps to:

  • Verify compliance with every technical requirement.
  • Identify differences between requested and offered parameters.
  • Compare alternative products on a common technical basis.
  • Detect missing, ambiguous, or unsupported specifications.
  • Identify technical deviations before supplier selection.
  • Verify electrical, mechanical, functional, and communication compatibility.
  • Prevent incorrect or undersized equipment from being purchased.
  • Establish an evidence-based technical recommendation.
  • Create traceability between the RFQ, supplier offer, purchase order, and acceptance tests.

The main objective is not simply to find the product with the largest ratings. It is to determine whether each proposed parameter is suitable for the actual application.

        ↓

Purchase Order and Acceptance Criteria

Specification comparison uses the compliance matrix and make comparison as supporting inputs.

The compliance matrix records the compliance status of each requirement. Specification comparison examines the actual parameter values and technical details behind those statuses.

4. Specification comparison versus related documents

Document or activity Primary purpose
Technical specification Defines the required parameters and performance
Make comparison Evaluates manufacturer and product suitability
Specification comparison Compares actual required and offered parameters
Compliance matrix Records compliance against each requirement
Technical deviation register Tracks proposed differences and their dispositions
Architecture comparison Evaluates system structure and design alternatives
Commercial comparison Evaluates prices and commercial conditions
FAT/SAT procedure Defines how the delivered system will be verified

These documents are complementary. A product can appear compliant in a high-level matrix while a detailed specification comparison reveals a critical mismatch.

5. Establish a common technical baseline

Before comparing suppliers, confirm that all offers are being evaluated against the same controlled requirement set.

The baseline may include:

  • Request for quotation.
  • User requirement specification.
  • Technical specification.
  • Functional specification.
  • Electrical drawings.
  • Mechanical drawings.
  • I/O list.
  • Network architecture.
  • Safety requirements.
  • Environmental conditions.
  • Performance requirements.
  • Applicable standards.
  • FAT and SAT acceptance criteria.

Record the document number, revision, and applicable clause for each requirement.

If the specification changes during the evaluation, control the revision and determine how the change affects every bid. Do not compare one supplier against revision A and another against revision C without explicitly addressing the difference.

6. Structure of a specification comparison sheet

A practical comparison sheet should contain the following fields.

Field Purpose
Requirement ID Unique reference to the requirement
Parameter Technical characteristic being evaluated
Required value Specified value or acceptance condition
Unit Consistent engineering unit
Supplier A value Exact value offered by Supplier A
Supplier B value Exact value offered by Supplier B
Supplier C value Exact value offered by Supplier C
Evidence reference Datasheet, drawing, manual, or offer section
Evaluation status Compliant, non-compliant, clarification, or other defined status
Deviation reference Link to the deviation register
Technical remarks Engineering assessment and limitations
Final disposition Approved, rejected, or pending under the evaluation rules

For larger projects, maintain separate comparison sheets for electrical, mechanical, automation, safety, instrumentation, and performance requirements.

7. Classify specification parameters

Not every parameter should be evaluated in the same way.

Parameter category Example Evaluation method
Minimum requirement Minimum I/O capacity Offered value must meet or exceed the required minimum
Maximum limit Maximum cycle time Offered or demonstrated value must remain within the limit
Exact requirement Required interface type Exact match unless an alternative is formally permitted
Range requirement Operating temperature range Required operating range must be covered
Performance requirement Measurement accuracy Verify the value and test method
Compatibility requirement Existing PLC protocol Confirm actual end-to-end interoperability
Safety requirement Required safety function Verify applicable safety evidence and validation
Documentary requirement Editable source project Confirm explicit inclusion and delivery conditions
Preferred parameter Additional diagnostic features Evaluate as a desirable feature if the criteria permit

The correct comparison depends on the meaning of the requirement, not merely whether the offered number is larger or smaller.

8. Numeric comparisons and engineering units

Numeric specifications must be compared using consistent units and a clear interpretation of the requirement.

For example, suppose the required maximum cycle time is 12 seconds.

  • Supplier A offers a guaranteed cycle time of 11 seconds under the specified conditions.
  • Supplier B estimates 13 seconds.
  • Supplier C states that cycle time depends on the production conditions without providing a guaranteed value.

Supplier A appears to meet the numerical limit, subject to verification of the test conditions and other requirements. Supplier B does not meet the limit if 12 seconds is mandatory. Supplier C requires clarification.

8.1 Unit conversion

For example:

\[ 1\text{ kW} = 1000\text{ W} \]
\[ 1\text{ bar} = 100\text{ kPa} \]
\[ 1\text{ s} = 1000\text{ ms} \]

Convert values before comparing them, and retain the original offered value for traceability.

8.2 Tolerances

A specification may define an acceptable range rather than a single exact value.

For example, if the required supply voltage is 24 V DC with an allowed range of 21.6 V to 26.4 V, the offered equipment must operate correctly within the required range.

Do not invent tolerances when the specification does not define them. Obtain clarification or apply the approved engineering standard where authorized.

9. Example: PLC specification comparison

Assume an RFQ requires a PLC for a new automated station.

Parameter Required specification Supplier A Supplier B Evaluation focus
CPU Approved performance class Meets class Lower class Verify execution and memory requirements
Digital inputs Minimum 64 80 64 Confirm usable capacity
Digital outputs Minimum 48 64 48 Confirm output type and loading
Analog inputs Minimum 8 8 4 Supplier B does not meet the stated minimum
Ethernet Required industrial protocol Supported Ethernet only stated Confirm exact protocol support
Remote I/O Required system compatibility Supported Gateway proposed Evaluate compatibility and architecture
Engineering software Required project tool Included License excluded Verify complete scope
Source project Editable source required Included Excluded Check mandatory handover condition

This example demonstrates why a single product rating is insufficient.

Supplier B's total I/O count might appear adequate, but its analog input capacity is below the requirement. Its Ethernet interface also does not prove that the required industrial protocol is supported.

A gateway may be technically acceptable if alternatives are permitted and the architecture is verified, but the extra hardware, software, diagnostics, and failure modes must be considered.

10. Electrical specification comparison

For electrical equipment, compare the parameters relevant to the actual duty.

Typical requirements include:

  • Rated voltage and frequency.
  • Phase configuration.
  • Rated current.
  • Short-circuit withstand capability where applicable.
  • Power consumption.
  • Insulation and dielectric requirements.
  • Earthing and protective arrangements.
  • IP rating.
  • Operating temperature.
  • Relative humidity.
  • EMC requirements.
  • Terminal and cable compatibility.
  • Required protective devices.
  • Applicable standards and certifications.

For control-panel equipment, check the complete arrangement. An individual component may meet its rating while the assembled panel fails the specified environmental, thermal, protection, or short-circuit requirements.

For example, selecting a circuit breaker based only on rated current is insufficient. Breaking capacity, protective coordination, conductor size, prospective fault current, and the applicable design requirements also matter.

11. VFD specification comparison

When comparing variable-frequency drives, evaluate the intended motor and machine duty.

Parameter What to verify
Supply voltage Required voltage range and supply configuration
Motor power Suitability for the specified motor and duty
Rated output current Must satisfy the motor and application requirements
Overload capacity Required overload percentage and duration
Control mode Required scalar, vector, or other control method
Speed range Required minimum and maximum operating speeds
Feedback Encoder or other feedback compatibility where needed
Communication Exact protocol and supported operating functions
Safety Required safety functions and integration
Braking Required braking method and duty
EMC Applicable installation and emissions requirements
Environmental rating Ambient temperature, altitude, enclosure, and cooling
Diagnostics Required fault history and monitoring
Parameter backup Required backup and restoration method

The drive's power rating must be assessed against the motor's current, load characteristics, acceleration requirements, and operating duty. A higher kilowatt rating alone does not guarantee suitability.

12. Sensor and instrumentation specification comparison

For sensors, transmitters, and measurement devices, compare:

  • Measurement principle.
  • Measurement range.
  • Accuracy and repeatability.
  • Resolution.
  • Response time.
  • Output type.
  • Supply voltage.
  • Environmental protection.
  • Process connection or mounting dimensions.
  • Cable and connector requirements.
  • Calibration requirements.
  • Communication and diagnostic functions.
  • Temperature and vibration limits.
  • Compatibility with PLC input modules.
  • Spare-parts and successor-product availability.

For analog instruments, distinguish accuracy from resolution.

  • Accuracy describes how close a measurement is to the true or reference value under stated conditions.
  • Resolution describes the smallest change the instrument can represent or distinguish.

A transmitter with a fine digital resolution can still have insufficient accuracy for the application.

For a 4–20 mA transmitter, confirm the measurement range, live-zero interpretation, input-card compatibility, fault-current behavior where specified, and engineering-unit scaling.

13. Mechanical specification comparison

Mechanical equipment should be compared against both functional and installation requirements.

Typical parameters include:

  • Dimensions and mounting.
  • Weight and center of gravity where relevant.
  • Shaft diameter and keyway.
  • Coupling arrangement.
  • Load and torque capacity.
  • Operating speed.
  • Material and surface finish.
  • Lubrication requirements.
  • Sealing and ingress protection.
  • Vibration and noise limits.
  • Thermal limits.
  • Maintenance clearances.
  • Access for inspection and replacement.
  • Compatibility with existing foundations and guards.

A replacement motor or gearbox can meet its power and torque requirements but still be unsuitable because its mounting dimensions or shaft arrangement differ from the installed machine.

Mechanical compatibility should be demonstrated using drawings and dimensions rather than assumed from the equipment category.

14. Network and communication specification comparison

Communication requirements are frequently underspecified or incorrectly evaluated.

Check:

  • Protocol and protocol role.
  • Physical interface.
  • Supported baud rates or link speeds.
  • Number of supported connections.
  • Data types and mapping.
  • Update rate.
  • Timing and latency requirements.
  • Network topology.
  • Redundancy requirements.
  • Addressing and configuration.
  • Diagnostics.
  • Cybersecurity capabilities.
  • Firmware compatibility.
  • Integration with existing switches, controllers, and devices.

For example, two devices may both support PROFINET, EtherNet/IP, Modbus TCP, or OPC UA, but that alone does not establish that the required data exchange, role, update time, or redundancy arrangement is supported.

Evaluate the complete communication path, including gateways and software drivers where applicable.

15. Environmental and operating-condition comparison

Industrial equipment must be suitable for its actual installation environment.

Compare:

  • Minimum and maximum operating temperature.
  • Storage temperature.
  • Humidity.
  • Dust and liquid exposure.
  • IP rating.
  • Vibration and shock.
  • Altitude.
  • Corrosive atmosphere.
  • Oil, coolant, and chemical exposure.
  • Electromagnetic disturbance.
  • Ventilation and cooling requirements.

An IP rating does not establish suitability for every environmental condition. It addresses specified ingress-protection characteristics, not all effects of temperature, corrosion, vibration, or chemical exposure.

Likewise, a device rated for a certain ambient temperature may require derating above a specified threshold.

16. Functional and performance specification comparison

Some requirements cannot be verified through a datasheet alone.

Examples include:

  • Machine cycle time.
  • Product changeover time.
  • Measurement accuracy under actual operating conditions.
  • Data logging completeness.
  • Alarm response.
  • Recovery from communication loss.
  • Robot and PLC handshake behavior.
  • Automatic sequence completion.
  • Production traceability.
  • Fault detection and restart behavior.

For such requirements, specify the measurement method and acceptance criteria.

For example, a required cycle time should define the relevant sequence start and end points, operating conditions, sample quantity, and whether loading, unloading, settling, or data processing is included.

A supplier's estimate is not equivalent to a guaranteed performance commitment.

17. Missing or ambiguous specification values

Not all suppliers provide complete information. The evaluator must distinguish noncompliance from insufficient evidence.

Situation Appropriate action
Required parameter is missing Request clarification or supporting evidence
Supplier value is below a mandatory minimum Record noncompliance
Supplier offers an alternative Assess under the deviation process
Supplier provides an incompatible unit Convert carefully and retain the original value
Supplier claims compliance without evidence Request appropriate evidence
Requirement itself is ambiguous Clarify and control the requirement baseline
Parameter is not applicable Require justification and follow approval rules
Supplier data conflicts across documents Identify the conflict and request a controlled resolution

Never fill in missing supplier data using assumptions about the manufacturer's product family. Verify the exact model and configuration.

18. Specification comparison for accuracy and tolerance

Consider a measurement system with a required accuracy of ±0.5% of full scale.

The offered instrument specifies ±1.0% of full scale.

If both values refer to the same measurement conditions and definition of accuracy, the offered instrument does not meet the requirement.

For a full-scale range of 100 units:

\[ \text{Required maximum error} = 100 \times \frac{0.5}{100} = 0.5 \]
\[ \text{Offered maximum error} = 100 \times \frac{1.0}{100} = 1.0 \]

The offered maximum error is twice the permitted error.

Before finalizing the comparison, verify whether the specification refers to percentage of full scale, percentage of reading, or another accuracy definition. These terms are not interchangeable.

19. Specification comparison for spare parts and accessories

A quoted product may require accessories or additional modules to satisfy the complete specification.

Check for:

  • Power supplies.
  • Communication modules.
  • Connectors and cables.
  • Mounting kits.
  • Braking resistors.
  • Feedback modules.
  • Safety modules.
  • Configuration adapters.
  • Software licenses.
  • Programming cables.
  • Replacement batteries where applicable.
  • Required terminal blocks and protective accessories.

For example, a PLC CPU may support a required network through an optional communication module. If that module is missing from the supplier's quoted bill of materials, the complete offer may not meet the requirement.

Compare the delivered configuration, not the maximum capabilities described in the manufacturer's catalogue.

20. Technical evaluation scoring

Specification comparison may use pass/fail decisions, weighted scoring, or a combination of both, depending on the procurement rules.

Mandatory requirements should be evaluated separately wherever required. Desirable capabilities may be scored to distinguish technically acceptable offers.

An illustrative weighted contribution is:

\[ \text{Weighted contribution} = \frac{\text{Score}}{\text{Maximum score}}\times\text{Weight} \]

Suppose a supplier receives 3 out of 5 for a criterion weighted at 10%.

\[ \frac{3}{5}\times10 = 6\\% \]

The supplier contributes 6 percentage points to the total score for that criterion.

The scoring method should be defined in advance. Evaluators should not alter weights or criteria after reviewing the bids simply to favor a particular supplier.

21. Technical deviation handling

Specification comparison frequently reveals deviations.

Examples include:

  • Lower current rating.
  • Different measurement range.
  • Unsupported communication protocol.
  • Reduced environmental rating.
  • Missing safety function.
  • Different mounting dimensions.
  • Lower accuracy.
  • Excluded software license.
  • Reduced warranty or support scope.

Each deviation should be recorded against the original requirement ID and evaluated for technical, safety, commercial, schedule, and lifecycle impacts as applicable.

A deviation may be acceptable when the procurement rules permit alternatives and the solution is demonstrably suitable. Mandatory requirements must not be waived outside the authorized process.

The compliance matrix should be updated when the deviation is clarified, accepted, rejected, or withdrawn.

22. Practical case study: Comparing two replacement VFDs

Assume a machine requires a replacement VFD with the following conditions:

  • Supply: 400 V AC, three-phase.
  • Motor: 5.5 kW.
  • Communication: specified industrial protocol.
  • Required overload capability: defined in the approved duty specification.
  • Safety: specified safety function.
  • Existing PLC integration: required.
  • Parameter backup and restoration: required.

Supplier A offers a drive with a compatible voltage rating and sufficient output current, provides the required protocol, and documents the necessary safety function.

Supplier B offers a drive with the same nominal power rating but has not demonstrated the required protocol or overload capability.

The evaluator should:

  1. Confirm the motor nameplate and actual load duty.
  2. Compare the offered voltage and current ratings.
  3. Verify overload ratings and operating conditions.
  4. Check the exact communication interface and control functions.
  5. Review the safety documentation.
  6. Check physical dimensions, cooling, and EMC requirements.
  7. Confirm required accessories and licenses.
  8. Verify PLC control-word, status-word, and speed-reference compatibility.
  9. Record missing evidence or deviations.
  10. Confirm the required FAT/SAT or commissioning checks.

Supplier B should not be considered equivalent solely because its drive is rated at 5.5 kW.

23. Building a specification comparison workbook

A practical Excel workbook can contain:

  • 00_README: rules, units, definitions, and revision.
  • 01_REQUIREMENTS: approved technical baseline.
  • 02_SUPPLIER_DATA: raw supplier values and document references.
  • 03_SPEC_COMPARISON: requirement-by-requirement comparison.
  • 04_COMPLIANCE: status and evidence evaluation.
  • 05_DEVIATIONS: differences and dispositions.
  • 06_CLARIFICATIONS: open questions and supplier responses.
  • 07_SCORING: approved technical scoring.
  • 08_SUMMARY: comparison and recommendation.
  • 09_APPROVALS: reviewer and approval history.

Recommended controls:

  • Use consistent engineering units.
  • Keep required values separate from offered values.
  • Record the exact model and configuration.
  • Use dropdowns for evaluation statuses.
  • Apply conditional formatting to identify mismatches and missing evidence.
  • Protect controlled formulas.
  • Keep mandatory requirements separate from weighted scores.
  • Include source-document references.
  • Track revisions and dates.
  • Preserve original supplier values even after conversion.
  • Avoid automatically marking a parameter compliant simply because a numeric value is greater than the requirement.

The last point matters because some parameters have minimum limits, others have maximum limits, and some require exact matches or range overlap.

24. Common mistakes in specification comparison

  • Comparing product names instead of exact model numbers.
  • Comparing ratings without checking units.
  • Assuming higher values are always better.
  • Ignoring operating duty and environmental conditions.
  • Treating a supplier's declared compliance as verified evidence.
  • Using different requirement revisions across suppliers.
  • Ignoring missing accessories and software licenses.
  • Comparing accuracy values with different definitions.
  • Overlooking communication roles and interface limitations.
  • Ignoring physical dimensions and maintenance clearances.
  • Treating a datasheet as proof of complete system performance.
  • Failing to record deviations and clarifications.
  • Using weighted scores to conceal mandatory noncompliance.
  • Failing to define acceptance tests for performance requirements.
  • Failing to carry approved specifications into the purchase order.

25. Specification comparison checklist

  • The approved requirement baseline and revision are identified.
  • Every requirement has a unique ID.
  • Required values, units, and tolerances are clear.
  • Supplier values are recorded against exact models and configurations.
  • Minimum, maximum, range, and exact-match requirements are distinguished.
  • Supporting datasheets, drawings, and test evidence are referenced.
  • Electrical, mechanical, functional, environmental, and communication requirements are evaluated.
  • Safety and regulatory requirements receive the required specialist review.
  • Missing information is flagged rather than assumed.
  • Technical deviations are entered in the deviation register.
  • Clarifications are documented and incorporated into the evaluation.
  • Mandatory requirements are evaluated according to the procurement rules.
  • Scoring criteria and weights are controlled.
  • Required accessories and software licenses are included.
  • Acceptance tests can verify the important performance requirements.
  • The final recommendation is documented and approved.
  • The approved configuration is transferred into contractual documents.

26. Interview questions and answers

1. What is specification comparison?

It is the systematic comparison of required and offered technical parameters to determine whether a proposed product or solution meets the approved specification.

2. Why is specification comparison necessary if a compliance matrix already exists?

The compliance matrix records the status of each requirement. Specification comparison examines the detailed parameter values, configuration, evidence, and technical differences behind those statuses.

3. Why should exact model numbers be recorded?

Different models within the same product family may have different ratings, interfaces, firmware requirements, options, and capabilities.

4. How should a missing supplier parameter be treated?

Record it as missing evidence or requiring clarification, according to the defined evaluation rules. Do not assume the offered equipment meets the requirement.

5. Why are units important?

Values cannot be compared reliably unless their units and definitions are consistent. Incorrect conversions or comparisons can result in selecting unsuitable equipment.

6. Is a higher rating always better?

No. A higher rating may be unnecessary or unsuitable, and it does not guarantee compatibility, accuracy, overload capability, or compliance with other requirements.

7. How do you compare VFDs with the same power rating?

Compare output current, overload capability, control mode, motor compatibility, communications, safety functions, environmental limits, braking requirements, and the intended operating duty.

8. How do you evaluate a technical deviation found during specification comparison?

Record the requirement and proposed difference, assess technical and lifecycle impacts, obtain clarification or evidence, and seek the appropriate authorized disposition.

9. Can a datasheet prove that a complete machine meets its cycle-time requirement?

Usually not by itself. Cycle time often requires a defined test method, representative operating conditions, and measured or otherwise substantiated performance evidence.

10. What should happen after specification comparison?

The evaluation should be finalized, deviations resolved according to the procurement rules, the recommended solution approved, and the accepted configuration reflected in the purchase order and acceptance criteria.

27. Final engineering principle

Specification comparison converts supplier claims into a structured engineering assessment. It reveals whether the exact product configuration meets the electrical, mechanical, functional, performance, environmental, communication, and safety requirements of the application.

For industrial automation, compare values with their units, definitions, operating conditions, and supporting evidence. Evaluate the complete configuration, including accessories, software, interfaces, and lifecycle obligations.

The correct product is not the one with the most impressive catalogue. It is the one whose specified and demonstrated capabilities satisfy the approved requirements with acceptable risk.
