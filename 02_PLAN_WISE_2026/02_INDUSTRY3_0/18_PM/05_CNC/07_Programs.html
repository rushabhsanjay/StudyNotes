1. Definition and Purpose

A CNC program is a structured set of instructions that tells a Computer Numerical Control (CNC) machine how to perform a machining operation. It defines the tool movements, spindle operation, feed rates, coordinate systems, tool selections, machining cycles, and supporting machine functions required to manufacture a component.

CNC programs are commonly written using G-code and M-code conventions, although the exact syntax and available functions depend on the controller and machine builder.

A CNC program can control or request operations such as:

  • Axis movement along linear and circular paths.
  • Spindle start, stop, direction, and speed.
  • Tool selection and automatic tool changes.
  • Coolant operation.
  • Coordinate-system selection.
  • Tool-length and cutter-radius compensation.
  • Drilling, boring, tapping, milling, and turning cycles.
  • Program branching, subprogram calls, and supported macro operations.
  • Controlled stops and program completion.

CNC programs are essential to production quality, repeatability, cycle-time optimization, machine safety, and traceability.

Important distinction: A CNC program defines the machining operation. CNC parameters define controller and machine behavior. The PLC controls many machine sequences and interlocks. These layers interact, but they are not interchangeable.

2. CNC Program Structure

A typical CNC program contains a program identifier, initialization commands, tool selection, machining instructions, and a safe ending.

Example of a simplified milling program:

%
O1001 (SAMPLE MILLING PROGRAM)

G21 G17 G90 G40 G49 G80
G54

T1 M06
S1500 M03
G00 X0 Y0
G43 H01 Z50.0
M08

G00 X10.0 Y10.0
G01 Z-2.0 F100
G01 X50.0 F250
G00 Z50.0

M09
M05
G49
G53 G00 Z0
M30
%

This is an illustrative example, not a production-ready program. The tool, workholding, coordinates, spindle limits, clearance positions, tool-change position, machine configuration, and controller syntax must be verified before execution. In particular, the machine-coordinate movement and tool-change sequence may require different instructions on different machines.

Common program elements include:

Element Purpose
Program number or name Identifies the program
Initialization block Establishes required modal states
Work coordinate selection Selects the workpiece coordinate system
Tool selection Identifies the required tool
Tool change Requests a tool change where supported
Spindle command Sets spindle direction and speed
Positioning commands Move axes to specified coordinates
Feed commands Define the programmed feed rate
Machining cycle Executes a defined machining operation
Coolant commands Control applicable coolant functions
End-of-program command Ends or resets program execution

The exact program format depends on the CNC controller, its configuration, and the machine builder's implementation.

3. G-Code and M-Code

3.1 G-code

G-codes generally control motion, coordinate interpretation, compensation, machining modes, and canned cycles.

Common examples include:

Code Common meaning Important consideration
G00 Rapid positioning Rapid motion requires verified clearance
G01 Linear interpolation Requires an appropriate feed setting
G02 Clockwise circular interpolation Plane and arc format matter
G03 Counterclockwise circular interpolation Plane and arc format matter
G17 XY plane selection Common on milling controls
G18 XZ plane selection Common on milling and turning controls
G19 YZ plane selection Availability depends on controller
G20 Inch programming mode Units must match the program
G21 Metric programming mode Units must match the program
G28 Reference return through a specified intermediate position on many controls Exact behavior and safe usage are controller-dependent
G40 Cancel cutter-radius compensation Confirm the applicable compensation state
G41 Cutter-radius compensation left Requires correct tool data and lead-in geometry
G42 Cutter-radius compensation right Requires correct tool data and lead-in geometry
G43 Positive tool-length compensation on many milling controls Verify H-offset conventions
G49 Cancel tool-length compensation on many milling controls Confirm the resulting tool-position behavior
G54 Select a work coordinate system The stored offset must be correct
G80 Cancel canned cycle on many controls Confirm the active cycle is cancelled
G90 Absolute programming on many controls Interpret coordinates from the active coordinate system
G91 Incremental programming on many controls Movement depends on the current position
G94 Feed per minute on many controls Common milling feed mode
G95 Feed per revolution on supported controls Common in turning and synchronized operations

These meanings are common conventions, not a guarantee of identical behavior on every CNC. Some codes have controller-specific extensions or different meanings.

3.2 M-code

M-codes generally request auxiliary machine functions.

Code Common meaning Important consideration
M00 Program stop Requires operator intervention to continue
M01 Optional stop Acts according to the optional-stop setting
M02 Program end Reset behavior varies by control
M03 Spindle clockwise Direction must match the tool and operation
M04 Spindle counterclockwise Confirm machine and tool requirements
M05 Spindle stop Does not necessarily mean every motion is stopped
M06 Tool change on many milling controls Often requires machine-specific sequencing
M08 Coolant on, commonly flood coolant Actual function depends on the machine
M09 Coolant off Confirm all relevant coolant functions
M30 Program end and reset on many controls Exact reset behavior is controller-dependent

M-code assignments are especially dependent on the machine builder. A code that controls coolant on one machine may control a different auxiliary function on another. Never assume that an M-code is safe based only on its number.

4. Modal and Non-Modal Commands

Modal commands remain active until another command changes their state or the controller resets them. Non-modal commands generally apply only to the current block or operation.

Examples of commonly modal states include:

  • Motion mode, such as G00 or G01.
  • Coordinate interpretation, such as G90 or G91.
  • Plane selection, such as G17 or G18.
  • Units, such as G20 or G21.
  • Feed mode.
  • Work coordinate selection.
  • Cutter and tool-length compensation states.

A dangerous programming mistake occurs when a programmer assumes that a command has automatically returned to its default state.

For example, if incremental positioning remains active, a coordinate value may be interpreted as a movement from the current position rather than as an absolute destination.

A good program explicitly establishes the required initial states rather than relying on whatever settings happened to remain from the previous operation.

5. Coordinate Systems and Positioning

CNC programming involves several coordinate concepts that must be kept separate.

5.1 Machine coordinates

Machine coordinates reference the machine's established coordinate system. Their relationship to the physical machine depends on successful reference establishment and the controller's coordinate conventions.

5.2 Work coordinates

Work coordinate systems define the location of the workpiece relative to the machine coordinate system. Common milling systems include G54 through G59, with additional systems available on some controls.

An incorrect work offset can shift an otherwise correct program into a fixture, workpiece, or machine component.

5.3 Tool offsets

Tool-length and cutter-radius offsets account for tool geometry. Their meaning and activation depend on the CNC configuration.

A program can contain correct coordinates but still machine the wrong location if the wrong work offset or tool offset is active.

5.4 Absolute and incremental positioning

In absolute positioning, a coordinate represents a destination relative to the active coordinate system.

In incremental positioning, a coordinate represents a displacement from the current position.

For example, a 10 mm command in absolute mode may request a position of X10, whereas the same numeric value in incremental mode may request a 10 mm movement from the current location.

The active mode must be confirmed before running or editing a program.

6. Tool Selection and Tool Compensation

CNC programs frequently combine tool selection with offset activation.

Typical functions include:

  • Selecting a tool number.
  • Requesting a tool change.
  • Activating a tool-length offset.
  • Activating cutter-radius compensation.
  • Selecting tool geometry and wear data.
  • Returning to a safe position before or after a tool change.

The tool number and offset number are not necessarily identical. For example, T1 may select a tool while H01 selects a tool-length offset, depending on the controller and machine convention.

Before production, verify:

  • The correct physical tool is installed.
  • The tool identity matches the program.
  • Tool length and radius data are correct.
  • Tool wear values are reasonable.
  • The tool assembly fits the machine and workholding arrangement.
  • Clearance exists during rapid positioning and tool changes.
  • Compensation is activated and cancelled in the intended sequence.

An incorrect tool offset can cause dimensional errors or collisions even when the programmed tool path is correct.

7. Feed Rate, Spindle Speed, and Cutting Conditions

CNC programs define cutting conditions that must remain within the capability of the machine, tool, workpiece, and process.

7.1 Feed rate

Feed rate defines the commanded rate of tool movement under the active feed mode.

Common modes include feed per minute and feed per revolution. Their availability and behavior depend on the controller and operation.

7.2 Spindle speed

Spindle speed is commonly programmed in revolutions per minute. The permitted range depends on the spindle, drive, gear range, tool, workholding, and machine configuration.

7.3 Feed and speed relationship

For milling, cutting speed is related to spindle speed and cutter diameter:

\[ V_c = \frac{\pi D N}{1000} \]

Where:

  • \(V_c\) is cutting speed in metres per minute.
  • \(D\) is cutter diameter in millimetres.
  • \(N\) is spindle speed in revolutions per minute.

For milling, the theoretical feed rate can be calculated as:

\[ F = f_z \times z \times N \]

Where:

  • \(F\) is feed rate in millimetres per minute.
  • \(f_z\) is feed per tooth in millimetres per tooth.
  • \(z\) is the number of cutting teeth.
  • \(N\) is spindle speed in revolutions per minute.

These equations support cutting-condition calculations, but the result must be checked against the tooling manufacturer's recommendations and the machine's capabilities.

8. Canned Cycles

Canned cycles simplify repetitive machining operations by replacing multiple low-level movement commands with a defined cycle.

Common operations include:

  • Drilling.
  • Peck drilling.
  • Boring.
  • Tapping.
  • Spot drilling.
  • Repeated hole machining.
  • Turning cycles on supported lathes.

Cycle codes and parameters differ across CNC families. The same cycle number must not be assumed to have identical behavior across different controllers.

Before using a canned cycle, confirm:

  • The cycle type and syntax.
  • The active plane and coordinate mode.
  • The hole position and depth.
  • The retract plane and return behavior.
  • The feed rate and spindle mode.
  • The required tool and work offsets.
  • Whether the cycle is modal.
  • The cancellation command and its behavior.

Incorrect retract settings or cycle depth values can cause a tool to collide with the workpiece or fixture.

9. Subprograms and Macros

9.1 Subprograms

A subprogram is a reusable sequence of instructions called from another program. It can reduce repetition and make a machining process easier to maintain.

Typical applications include repeated hole patterns, common machining sequences, and standardized operations.

Subprogram call syntax and return behavior depend on the CNC controller.

9.2 Macro programming

Macro programming introduces variables, calculations, conditions, and program flow into CNC programming.

Possible applications include:

  • Parametric machining.
  • Repeated patterns.
  • Calculated coordinates.
  • Conditional machining operations.
  • Part-family programs.
  • Measurement-based corrections where supported.
  • Production counters and controlled program branching.

Macro variables and syntax differ between controller families. Variable ranges, persistence, arithmetic behavior, and protected system variables must be checked in the applicable manual.

A poorly designed macro can repeatedly execute an incorrect movement or select the wrong machining conditions. Validate its logic and boundary conditions before production.

10. CNC Program Execution and Operating Modes

CNC programs are executed through a controlled sequence of operator and machine actions.

Common operating modes include:

  • EDIT: Create or modify a program.
  • MEMORY or AUTO: Execute a stored program.
  • MDI: Execute manually entered commands or short command sequences.
  • JOG: Move axes manually using the supported jog controls.
  • HANDLE or MPG: Move axes using a manual pulse generator.
  • SINGLE BLOCK: Execute one program block at a time.
  • DRY RUN: Use the controller's supported test behavior to check a program.
  • GRAPHICS: Simulate the tool path without normal physical cutting motion, where supported.

The exact modes and their behavior depend on the machine.

Single-block operation and graphics simulation are useful validation tools, but neither guarantees collision-free machining. Dry-run behavior may change feed rates or other functions and may not reproduce actual cutting conditions.

Before execution, verify the selected program, active tool, work offset, tool offsets, spindle commands, machine state, workholding, and travel envelope.

11. Program Validation Before Production

Program validation should be systematic rather than based on the optimistic belief that the previous shift probably checked everything.

11.1 Document and revision checks

  • Confirm the correct program number and file.
  • Verify the approved revision.
  • Check the part number and machining operation.
  • Confirm that the program matches the machine and controller.
  • Check any required postprocessor or machine-specific conventions.
  • Verify that the required tools and offsets are available.

11.2 Code and logic checks

  • Review initialization and modal states.
  • Confirm units and coordinate interpretation.
  • Check work coordinate selection.
  • Verify tool-change commands.
  • Confirm spindle direction, speed, and feed values.
  • Check movement order and clearance positions.
  • Review depth values, cycle parameters, and retract behavior.
  • Confirm compensation activation and cancellation.
  • Verify subprogram calls and macro logic.
  • Check end-of-program and reset behavior.

11.3 Physical and process checks

  • Verify workpiece clamping and fixture clearance.
  • Confirm the tool and holder assembly.
  • Check the machine's available travel.
  • Verify that spindle and feed commands are within approved limits.
  • Inspect the first-part measurement results.
  • Confirm the required surface finish and dimensional tolerances.

12. CNC Program Backup, Transfer, and Version Control

CNC programs may be stored in controller memory, an external computer, a DNC system, a network location, or a production-management system.

Program transfer methods may include USB storage, Ethernet, serial communication on legacy equipment, or approved networked manufacturing systems.

Important controls include:

  • Unique program identification.
  • Revision history.
  • Approved master copies.
  • Access control.
  • Transfer verification.
  • Machine-specific compatibility.
  • Traceability between the program and manufactured part.
  • Retention of validated previous revisions.
  • Protection against unauthorized edits.

The program displayed on the CNC should be verified against the approved version. A file with the correct name may still contain an incorrect revision.

Do not assume that copying a program file preserves tool offsets, work offsets, parameters, compensation tables, or machine-builder configuration. These are separate data sets unless the specific backup method explicitly includes them.

13. Common CNC Program Faults

Symptom Possible program-related cause Additional checks
Incorrect machining location Wrong work coordinate system or coordinate values Work offset, machine reference, setup
Unexpected axis movement Incorrect modal state or coordinate interpretation Active modes, previous blocks, offsets
Tool collision during rapid movement Incorrect clearance or movement sequence Fixture geometry, tool assembly, actual machine position
Incorrect component dimensions Wrong tool offsets or programmed geometry Tool measurement, work offset, tool wear
Spindle does not start Missing or incorrect spindle command Interlocks, spindle drive, PLC permissives
Tool change does not complete Incorrect tool-change request or sequence PLC status, tool changer sensors, mechanical condition
Canned cycle produces incorrect depth Wrong cycle parameters or coordinate mode Controller-specific cycle definition
Macro behaves unexpectedly Incorrect variable, condition, or loop logic Variable values, program flow, limits
Program stops with an alarm Invalid code or unmet operating condition Alarm history, controller manual, machine status
Program differs from approved file Unauthorized edit or transfer mismatch Revision control, file comparison, transfer logs

A program alarm does not automatically mean that the program is defective. Machine interlocks, tool data, configuration, feedback, and mechanical conditions can also prevent execution.

14. Preventive Maintenance for CNC Programs

Program management is a maintenance and production-control responsibility, not merely a programming task.

A practical periodic review can include:

  • Confirming that approved programs are available.
  • Checking that master copies and revisions are traceable.
  • Verifying that required backups are current and readable.
  • Reviewing unauthorized or undocumented program changes.
  • Checking for obsolete programs and duplicate versions.
  • Confirming machine compatibility after CNC software or hardware changes.
  • Reviewing recurring program-related alarms and production defects.
  • Confirming that tool and work-offset procedures are documented.
  • Verifying recovery arrangements after controller replacement or memory loss.

14.1 Program change register

A program change register may contain:

Field Purpose
Machine ID Identifies the CNC machine
Program number Identifies the program
Part number Links the program to the manufactured component
Revision Identifies the approved version
Change description Explains what was modified
Reason for change Links the change to a process or quality requirement
Original file reference Preserves the previous approved version
Approval Records required authorization
Validation result Documents testing and inspection
Release date Records when the revision became approved
Responsible person Establishes accountability

In SAP PM or an associated document-management system, program-related work can be linked to the equipment, functional location, maintenance order, technical documentation, or change-control record, according to the site's workflow.

15. Practical CNC Program Troubleshooting Method

When a program fails, use a structured investigation.

  1. Record the exact alarm text or number, active program, block number, operating mode, and machine condition.
  2. Determine whether the fault is repeatable and whether it began after a program edit, tool change, offset change, parameter change, or maintenance activity.
  3. Confirm that the program revision is correct.
  4. Check the active coordinate system, units, absolute or incremental mode, compensation state, tool data, and spindle/feed commands.
  5. Review the relevant program blocks and preceding modal commands.
  6. Check the CNC diagnostics and PLC status for unmet machine conditions.
  7. Inspect relevant sensors, actuators, drives, feedback, and mechanical components where indicated.
  8. Correct the confirmed cause using the approved procedure.
  9. Validate the change in a controlled manner before returning the machine to production.
  10. Record the fault, cause, corrective action, and verified result.

Do not delete or bypass an alarm simply to resume production. The alarm may be the only indication that a required condition has not been met.

16. Key Engineering Principles

  • CNC programs must match the exact machine, controller, tooling, workholding, and approved process.
  • Program syntax and code meanings can vary between manufacturers and machine configurations.
  • Initialization should establish required modal states explicitly.
  • Coordinate systems, tool offsets, machine parameters, and compensation data must be treated as separate configuration elements.
  • Program simulation helps detect errors but does not prove that physical machining is safe.
  • Changes must be version-controlled, authorized, and validated.
  • A backup of the program alone does not constitute a complete CNC machine backup.
  • Repeated faults should be investigated for their underlying causes rather than repeatedly corrected at the program level.
  • Production release requires both program validation and confirmation of the actual machine setup.
