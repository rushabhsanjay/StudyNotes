1. Definition of FAT planning

FAT planning is the structured preparation carried out before Factory Acceptance Testing to ensure that the correct requirements, people, equipment, test procedures, software versions, safety controls, and acceptance criteria are ready for verification.

The purpose is to make the FAT systematic, repeatable, safe, and efficient. Planning should prevent situations where the customer arrives, the machine is unavailable, the required test equipment is missing, the software is still being debugged, or nobody knows which requirement a test is supposed to prove. Industrial projects have enough genuine problems without manufacturing administrative ones.

FAT planning answers five fundamental questions:

  • What must be tested?
  • Who will execute, witness, review, and approve each test?
  • When will each test be performed?
  • How will the test be conducted, measured, and documented?
  • What conditions must be satisfied before the FAT can begin and before it can be accepted?

2. Objectives of FAT planning

A well-prepared FAT plan should:

  • Establish an agreed test scope based on approved specifications and contractual requirements.
  • Convert requirements into an ordered test agenda.
  • Allocate competent personnel and define responsibilities.
  • Confirm that the machine, utilities, software, test equipment, materials, and documentation are ready.
  • Define prerequisites, acceptance criteria, evidence requirements, and pass/fail rules.
  • Identify safety risks and controls for each test activity.
  • Allow sufficient time for testing, defect correction, and retesting.
  • Coordinate customer witnesses, suppliers, and internal engineering teams.
  • Establish procedures for recording deviations and obtaining acceptance.
  • Ensure the tested configuration can be identified and compared with the version ultimately shipped.

Approved requirements and contract
                 ↓
Define FAT scope and exclusions
                 ↓
Build requirement-to-test matrix
                 ↓
Prepare agenda and detailed procedures
                 ↓

                 ↓

                 ↓

                 ↓

                 ↓

Planning is iterative. A missing requirement, failed readiness check, or change to the machine configuration may require the agenda and procedures to be revised.

4. Define the FAT scope

The scope specifies which functions and deliverables will be verified during FAT.

Typical scope areas include:

  • Mechanical assembly and functional movement.
  • Electrical panels, wiring, grounding, and device identification.
  • PLC inputs, outputs, sequences, and operating modes.
  • HMI screens, operator commands, alarms, and diagnostics.
  • Robot, CNC, VFD, servo, vision, and inspection-system interfaces.
  • Communication-loss handling and recovery.
  • Production cycle and performance requirements.
  • Safety functions and required validation evidence.
  • Documentation, software backups, and configuration records.

4.1 Scope boundaries

The FAT plan must distinguish between tests that can be performed at the factory and tests that require actual site conditions.

Requirement area Typical FAT verification Potential SAT dependency
PLC sequence Simulated or actual equipment sequence Site-specific interfaces may require retesting
Field I/O Actual devices or approved test arrangements Final field wiring and installation
Robot integration Robot handshake and motion under approved conditions Site network and production-line handshake
HMI Screens, commands, alarms, and navigation Final plant user accounts or network services
Cycle time Measurement under defined factory conditions Actual production material and upstream/downstream constraints
Safety Required factory tests and validation activities Site-specific hazards and installation conditions
SCADA/MES Interface tests using the agreed environment Live plant connectivity and production data integration
Documentation Review of required document revisions Final as-built records after installation changes

A FAT exclusion must be documented, justified, and assigned to the appropriate later verification activity. Excluding a test does not eliminate the underlying requirement.

5. Requirement-to-test planning

The most important planning document is the requirement-to-test matrix, sometimes called a verification matrix or FAT traceability matrix.

It links each applicable requirement to one or more tests.

Requirement ID Requirement FAT test ID Preconditions Expected result
SWR-START-001 Automatic start requires all specified permissives FAT-PLC-001 Machine in ready state Start rejected if a required permissive is false
SWR-SEQ-004 Processing requires clamp confirmation FAT-PLC-002 Clamp sequence enabled Processing begins only after valid confirmation
SWR-ALM-014 Missing clamp feedback generates a timeout alarm FAT-ALM-001 Approved test arrangement available Correct alarm and specified fault response occur
SWR-COM-003 Invalid robot data prevents dependent sequence progression FAT-COM-001 Robot interface available Sequence does not progress on invalid data
SWR-HMI-001 HMI displays current sequence state FAT-HMI-001 PLC and HMI connected Display agrees with controller state
SAF-REQ-001 Specified safety function achieves its required response FAT-SAF-001 Approved safety test procedure available Required safety behavior is verified and recorded

These IDs are illustrative. Real IDs should match the project's document-control and traceability conventions.

5.1 Test prioritization

Prioritize tests according to risk, dependencies, and acceptance importance.

  1. Safety-critical and mandatory compliance activities.
  2. Machine readiness and foundational electrical checks.
  3. Basic I/O and equipment operation.
  4. Communication and interface verification.
  5. Automatic sequences and fault handling.
  6. Quality functions and production performance.
  7. Documentation, final configuration, and acceptance review.

The exact order should reflect the machine design. Some tests cannot be executed until earlier tests pass, and safety validation activities must follow the approved safety plan.

6. Preparing the FAT agenda

The FAT agenda is the time-based schedule that identifies what will be tested, who is involved, and what must be ready.

A useful agenda contains:

  • Date and planned time.
  • Test ID or test-group identifier.
  • Test description.
  • Responsible test engineer.
  • Customer witness or reviewer, where applicable.
  • Prerequisites and required equipment.
  • Estimated duration.
  • Required documents and evidence.
  • Planned break and issue-review periods.
  • Contingency time for failures and retesting.

6.1 Example FAT agenda

The following is an illustrative two-day agenda, not a universal duration. Complex production lines may require substantially more time.

Day Session Planned activity Responsible role
Day 1 Opening Scope, safety briefing, revisions, and readiness review FAT lead
Day 1 Morning Mechanical, electrical, panel, and documentation checks Mechanical and electrical engineers
Day 1 Midday I/O verification and equipment-level functional checks Automation and electrical engineers
Day 1 Afternoon PLC sequences, operating modes, and HMI functions Automation engineer
Day 1 Closing Defect review and next-day priorities FAT lead and project team
Day 2 Morning Robot, CNC, drive, and communication interfaces Automation and integration engineers
Day 2 Midday Alarms, interlocks, abnormal conditions, and recovery Automation engineer and relevant specialists
Day 2 Afternoon Performance tests and agreed process trials Process and quality engineers
Day 2 Closing Documentation review, retest summary, and acceptance review FAT lead and customer representatives

6.2 Schedule dependencies

The agenda must account for dependencies.

For example, a robot-interface test cannot be meaningfully completed if the robot controller is unavailable. A cycle-time test cannot be accepted if the process sequence is not stable or the required measurement method has not been agreed.

A schedule should identify:

  • Mandatory predecessor tests.
  • Supplier or customer dependencies.
  • Equipment and material availability.
  • Required engineering support.
  • Planned witness points.
  • Contingency time.
  • Activities that can proceed in parallel without creating unsafe or conflicting conditions.

Avoid scheduling every available minute as a test slot. Defects, clarification, instrument setup, and retesting are normal parts of FAT.

7. FAT team and responsibilities

The FAT team should include the people needed to execute tests, interpret results, resolve defects, and make acceptance decisions.

7.1 Typical team structure

Role Main responsibility
FAT lead Owns the agenda, coordination, readiness review, issue review, and final records
Customer representative Confirms customer requirements and witnesses agreed tests
Project manager Coordinates resources, contractual issues, and acceptance decisions
Automation engineer Verifies PLC, HMI, sequence, communication, and diagnostics
Electrical engineer Verifies electrical construction, wiring, protection, and drawings
Mechanical engineer Verifies assembly, movement, alignment, and mechanical functions
Process engineer Verifies process sequence, parameters, and operating conditions
Quality engineer Verifies inspection, rejection, measurement, and quality records
Safety specialist Supports risk assessment and required safety verification or validation
Robot/CNC specialist Supports controller-specific functions and integration
Supplier representative Supports specialized equipment and resolves supplier-related defects
Document controller Ensures test documents and revision records are controlled

A small project may combine roles. However, safety-critical verification and acceptance activities must still satisfy the required competence and independence rules.

7.2 Responsibility assignment

For larger projects, a RACI matrix can clarify responsibilities:

  • R - Responsible: Performs the activity.
  • A - Accountable: Owns the result and decision.
  • C - Consulted: Provides technical input.
  • I - Informed: Receives updates.

Example:

Activity FAT lead Automation engineer Customer Safety specialist
Approve agenda A/R C C C
Execute PLC tests A R C I
Witness agreed tests C R A/R for customer witness C
Safety validation C R where qualified and assigned I or C A/R as defined by project
Resolve software defect A for coordination R C C if safety-related
Final acceptance decision R for coordination C A as defined by contract C for relevant safety issues

The RACI assignment must be adapted to the contract and organizational authority. The customer is not automatically the only person with technical accountability, and a FAT lead cannot waive mandatory requirements simply to preserve the schedule.

8. FAT test setup

The test setup is the physical and digital environment required to conduct the planned tests.

8.1 Machine and equipment readiness

Confirm the availability and condition of:

  • Machine assembly and required guarding.
  • Electrical panels and approved power supplies.
  • Motors, VFDs, servo systems, and actuators.
  • Sensors, switches, instruments, and inspection devices.
  • PLC, HMI, robot, and CNC controllers.
  • Network switches and required communication infrastructure.
  • Pneumatic and hydraulic supplies.
  • Fixtures, tooling, and representative parts.
  • Required safety devices and test arrangements.
  • Approved simulation devices or test fixtures where actual equipment cannot be used.

8.2 Utilities and environmental conditions

Define and verify the utilities required by the machine:

  • Electrical supply voltage, frequency, and capacity.
  • Protective earthing and required electrical protection.
  • Compressed-air pressure and flow.
  • Hydraulic supply where applicable.
  • Cooling water or process cooling.
  • Exhaust, extraction, or other process utilities.
  • Network access and required external services.
  • Temperature or environmental conditions that affect measurement or equipment operation.

Any temporary factory supply must be suitable for the planned test and clearly identified. Site-specific utilities that cannot be reproduced should be recorded as dependencies for later verification.

8.3 Test instruments and tools

Prepare the instruments and tools required by the acceptance criteria.

Instrument or tool Typical use Planning requirement
Calibrated stopwatch or data logger Cycle-time measurement Define event boundaries and measurement accuracy
Multimeter Electrical measurements Confirm rating, condition, and calibration where required
Oscilloscope or protocol diagnostic tool Signal or communication analysis Confirm suitable bandwidth and access
Pressure gauge Pneumatic or hydraulic checks Confirm range and calibration status
Measurement instrument Dimensional or process checks Confirm resolution, range, and calibration status
PLC engineering software Logic monitoring and diagnostics Confirm license, project version, and access
Network diagnostic tool Connectivity and data checks Confirm approved access and configuration
Test fixture or simulator Controlled input or fault simulation Verify the method is approved and representative

Not every tool requires a calibration certificate for every use. Calibration and verification requirements depend on the measurement's intended use, contractual criteria, and applicable quality procedures.

9. Software and configuration readiness

A machine may be physically complete while the software configuration is still unsuitable for formal acceptance.

Before FAT, verify:

  • PLC, HMI, robot, CNC, and drive software versions are identified.
  • The loaded software matches the approved test baseline.
  • Hardware configuration and firmware compatibility have been checked.
  • Required communication connections and tag mappings are available.
  • HMI screens and alarm texts are sufficiently complete for the planned tests.
  • Test accounts and access permissions are prepared.
  • Approved parameter sets and recipes are available.
  • Diagnostic tools and engineering workstations are ready.
  • Source files and backups are available.
  • Changes since the last internal test have been reviewed.
  • Known limitations and open defects are recorded.

If software changes during FAT, record the changed components, revision or version, reason for the change, affected tests, and required regression tests.

Do not continue recording results against an obsolete software version after the tested configuration has changed.

10. Test data, materials, and samples

Some acceptance tests require representative production materials or controlled test samples.

Plan for:

  • Correct part numbers and product variants.
  • Representative raw material and workpieces.
  • Approved tooling and fixtures.
  • Known-good reference samples.
  • Defective samples for inspection-system testing, where safe and permitted.
  • Barcode, RFID, or traceability identifiers.
  • Recipe and program files.
  • Sample quantity and repeatability requirements.
  • Storage and identification of test results.

Where actual production parts are unavailable, an approved substitute or simulation may be used only if it can adequately verify the requirement. The substitution and its limitations must be recorded.

For quality-critical functions, define whether a sample demonstrates basic function, measurement accuracy, repeatability, process capability, or another acceptance objective. These are different claims and require different evidence.

11. Safety planning and test authorization

The FAT plan must specify how tests will be performed safely.

Before the test begins:

  • Complete the applicable risk assessment and test-specific safety review.
  • Identify hazardous movements, stored energy, electrical hazards, and process hazards.
  • Establish who may operate the machine and who may enter hazardous areas.
  • Confirm the status of guards, emergency stops, and protective devices.
  • Define communication and stop-work procedures.
  • Establish approved methods for simulation and fault injection.
  • Control PLC forcing, bypasses, and temporary test configurations.
  • Define isolation and restoration steps for work requiring energy control.
  • Ensure that required safety validation is carried out by competent personnel.

Tests involving bypasses or simulated faults must have specific authorization and risk controls. They must not defeat mandatory protection or expose personnel to hazardous motion.

12. Pre-FAT and readiness review

A pre-FAT is an internal readiness activity performed before the formal customer acceptance event.

Its purpose is to establish that the machine is sufficiently complete, stable, and documented for meaningful formal testing.

12.1 Readiness checklist

  • The approved FAT scope and agenda are available.
  • Required specifications and drawings are at controlled revisions.
  • The machine is mechanically and electrically ready for the planned tests.
  • Required utilities and test equipment are available.
  • Software versions and hardware configurations are identified.
  • Core I/O and equipment functions have been checked.
  • Known major defects are resolved or formally dispositioned.
  • Required safety controls and test procedures are in place.
  • Test parts, tooling, recipes, and programs are available.
  • The test team and required specialists are confirmed.
  • Customer witness points and approval responsibilities are understood.
  • Test records and defect logs are prepared.
  • Backup and recovery arrangements are available.

12.2 Readiness decision

The FAT lead should record one of the following outcomes:

  • Ready: The defined prerequisites are satisfied.
  • Ready with approved restrictions: Only permitted limitations remain, with documented conditions and authorization.
  • Not ready: A prerequisite is missing or a risk prevents formal testing.

A readiness review should not be used to hide unresolved safety or compliance issues. If a required function cannot be tested, its status must remain explicit.

13. FAT test procedure template

A standardized template improves consistency across test engineers and equipment suppliers.

Procedure Numbered execution steps

The template should be completed before formal testing. Acceptance criteria should not be invented after the result is observed.

14. Time, resources, and contingency planning

FAT planning must include realistic allowances for setup, execution, review, defect correction, and retesting.

For each test group, estimate:

  • Preparation time.
  • Test execution time.
  • Evidence recording time.
  • Customer witness or review time.
  • Defect diagnosis and correction allowance.
  • Retest time.
  • Equipment changeover time.
  • Availability of specialist personnel.

An illustrative schedule allocation might reserve most time for planned verification, with separate capacity for issue resolution and retesting. The appropriate proportions depend on machine maturity, complexity, project risk, and prior test results.

Track planned versus actual duration. Repeated delays may reveal poor preparation, unstable software, missing prerequisites, or an unrealistic test procedure.

15. Managing changes during FAT

Formal testing often reveals defects that require changes to software, wiring, settings, or mechanical components.

Every change should be managed through a controlled process:

  1. Record the issue and its impact.
  2. Identify the affected requirement and equipment.
  3. Assess safety, functional, interface, and documentation consequences.
  4. Approve the proposed correction through the defined process.
  5. Implement and identify the new configuration.
  6. Repeat the failed test.
  7. Execute regression tests for related functions.
  8. Update the test evidence, deviation log, and software baseline.

A change to a timer, for example, may affect sequence timing, alarm thresholds, robot synchronization, and cycle-time acceptance. Retesting only the exact line of code that changed may miss these interactions.

16. Example: planning FAT for an automated loading cell

Consider a cell containing a PLC, HMI, robot, pneumatic clamp, inspection sensor, and part-traceability interface.

16.1 Scope definition

The FAT plan includes:

  • PLC I/O mapping and equipment status.
  • Automatic and manual modes.
  • Clamp movement and position feedback.
  • Robot start, acknowledgement, busy, and completion handshakes.
  • Inspection result handling.
  • Alarm, timeout, and recovery behavior.
  • HMI commands and diagnostics.
  • Part identification and result logging.
  • Cycle-time measurement.
  • Applicable safety-function verification.

16.2 Planned test dependencies

Electrical and I/O checks
          ↓
Clamp and actuator checks
          ↓
Robot communication and handshake checks
          ↓
Individual sequence-step tests
          ↓
Integrated automatic-cycle test
          ↓
Inspection and traceability verification
          ↓
Fault handling and recovery tests
          ↓
Performance test and acceptance review

16.3 Example readiness issues

Issue Effect on FAT Required planning action
Robot controller unavailable Robot integration cannot be verified Coordinate supplier support and revise readiness status
Incorrect sensor mapping Sequence tests may produce invalid results Correct mapping and repeat relevant I/O checks
No representative parts Process and inspection tests may be limited Arrange approved samples or document the verification limitation
Missing network connection External traceability interface cannot be fully tested Provide an approved test environment or schedule the remaining verification
Unapproved software revision Results cannot be reliably linked to the intended baseline Establish and identify the correct test configuration
Missing safety test procedure Required safety verification cannot proceed as planned Obtain an approved procedure and competent test personnel

17. FAT planning documents and records

Typical planning outputs include:

  • FAT plan and scope statement.
  • FAT agenda and participant list.
  • Requirement-to-test traceability matrix.
  • Individual test procedures.
  • Test equipment and calibration records where required.
  • Test setup and configuration records.
  • Readiness review and pre-FAT checklist.
  • Safety and test authorization records.
  • Test data and sample identification.
  • Risk, dependency, and contingency register.
  • Defect and punch-list template.
  • Software revision and backup register.
  • Acceptance criteria and sign-off records.

The planning documents should be revision-controlled. If the agenda, scope, or acceptance criteria change, the team should know which version is currently approved.

18. Common FAT planning failures

  • Inviting the customer before the machine is ready.
  • Defining the agenda around available people rather than requirement coverage.
  • Failing to allocate time for abnormal-condition tests.
  • Assuming supplier equipment will be available without confirmation.
  • Omitting test prerequisites and dependencies.
  • Using uncalibrated or unsuitable instruments for acceptance measurements.
  • Testing an unidentified software revision.
  • Leaving responsibility for test execution or approval ambiguous.
  • Failing to arrange representative materials and production recipes.
  • Ignoring safety preparation because the activity is called a factory test.
  • Scheduling no contingency time for defect correction.
  • Failing to define how blocked and untested requirements will be reported.
  • Allowing uncontrolled software changes during witnessed testing.
  • Omitting regression testing after a correction.

19. Interview questions and answers

1. What is FAT planning?

FAT planning defines the test scope, agenda, team, setup, prerequisites, acceptance criteria, safety controls, and records required to demonstrate compliance before shipment.

2. What is the difference between a FAT plan and a FAT procedure?

The FAT plan defines the overall approach, scope, resources, schedule, and responsibilities. A FAT procedure gives the detailed steps, prerequisites, expected results, and acceptance criteria for a specific test or test group.

3. Why is a pre-FAT required?

Pre-FAT identifies readiness gaps and defects before formal acceptance, reducing wasted witness time and the risk of incomplete testing.

4. What is a requirement-to-test matrix?

It maps each applicable requirement to the test cases and evidence that demonstrate compliance, helping identify missing tests and unverified requirements.

5. Who is responsible for FAT?

The FAT lead coordinates the process, while individual engineers execute tests within their competence. The customer and project stakeholders witness or approve results according to the contract and responsibility matrix.

6. What should be checked before FAT starts?

Machine readiness, utilities, test equipment, software versions, required documents, test materials, team availability, safety controls, and approved test procedures should be confirmed.

7. Why is test setup important?

Incorrect test setup can produce misleading results. Suitable instruments, representative materials, known software revisions, valid communication interfaces, and controlled test conditions are necessary for credible evidence.

8. How should a blocked test be handled?

Record the blocker, affected requirement, reason, responsible owner, and planned verification date or stage. Do not report it as passed.

9. What happens when software changes during FAT?

The change must be recorded, its impact assessed, the new configuration identified, and the affected tests plus appropriate regression tests repeated.

10. How do you know the FAT agenda is complete?

Every applicable requirement has an assigned verification method, tests have suitable prerequisites and acceptance criteria, responsibilities are assigned, and all exclusions or later verification activities are documented.

20. Final FAT planning checklist

  • Scope and exclusions are agreed.
  • Applicable requirements are mapped to tests.
  • Agenda and schedule dependencies are defined.
  • Test roles, witness points, and approval authority are clear.
  • Machine, utilities, instruments, and network setup are ready.
  • Software and hardware configurations are identified.
  • Test materials, recipes, tooling, and sample quantities are available.
  • Safety controls and test authorization are established.
  • Pre-FAT and readiness review are completed.
  • Acceptance criteria and evidence requirements are approved.
  • Defect, retest, and change-control procedures are ready.
  • Contingency time and specialist support are available.
  • Test records and document revisions are controlled.

A successful FAT begins with preparation, not with the first press of the Start button. The plan must make every requirement testable, every responsibility clear, every test condition controlled, and every acceptance decision defensible.
