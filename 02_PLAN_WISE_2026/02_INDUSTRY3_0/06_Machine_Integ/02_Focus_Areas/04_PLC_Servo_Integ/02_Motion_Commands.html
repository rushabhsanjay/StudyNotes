1. Purpose of servo motion commands

Servo motion commands tell a motion controller or PLC how an axis should move, where it should move, or how its position reference should be established.

The three fundamental command categories are:

  • Move: Command the axis to travel to a target position or move by a specified distance.
  • Jog: Command the axis to move continuously or incrementally while an operator holds a control or while a jog request remains active.
  • Home: Establish a known reference position or coordinate relationship for the axis.

These commands are not interchangeable. A move command usually executes a defined trajectory, jog provides operator-controlled movement, and homing establishes a coordinate reference.

A typical servo motion system contains:

  • PLC or motion controller.
  • Servo axis configuration and motion-control software.
  • Servo drive.
  • Servo motor and feedback encoder.
  • Mechanical transmission, such as a screw, belt, gearbox, or direct drive.
  • Limit switches, reference sensors, brakes, and machine interlocks where applicable.

The controller generates motion commands, the drive controls motor torque and speed, and feedback is used to regulate the axis and monitor its behavior.

2. Motion-control architecture

HMI / Operator / Automatic sequence
                 ↓
          PLC application
                 ↓
        Motion-control function
                 ↓
       Axis state and interlocks
                 ↓
      Motion trajectory generation
                 ↓
             Servo drive
                 ↓
            Servo motor
                 ↓
          Mechanical load
                 ↓
       Encoder / position feedback
                 ↓
       Motion controller and drive

The motion controller may be integrated into the PLC, implemented as a dedicated motion module, or hosted in a controller that communicates with the PLC.

The servo drive generally closes the fast motor-control loops, while the motion controller coordinates commanded position, velocity, acceleration, and trajectory. Exact control-loop ownership depends on the system architecture.

3. Motion-command categories

Command Main purpose Typical completion condition
Absolute move Move to a specified coordinate Target position reached according to configured criteria
Relative move Move by a specified distance from the relevant starting reference Relative displacement completed
Continuous jog Move while the jog command remains active Jog released or stopped by another valid condition
Incremental jog Move by a fixed small distance per command Configured increment completed
Homing Establish a machine reference Homing sequence reports completion
Stop Decelerate or stop an axis according to the configured stop behavior Stop condition confirmed
Halt Interrupt or decelerate motion according to the motion library's defined behavior Halt condition completed or motion becomes inactive

The exact meaning of Stop, Halt, and other command names depends on the motion library and controller. Do not assume they have identical behavior across platforms.

4. Absolute positioning

An absolute move commands the axis to a target coordinate within the configured coordinate system.

For example, if an axis is at 120 mm and the target is 450 mm, an absolute move commands the axis to 450 mm.

The displacement is:

\[ \Delta x = x\_{\text{target}} - x\_{\text{actual}} \]

For the example:

\[ \Delta x = 450 - 120 = 330\text{ mm} \]

The axis moves 330 mm in the positive direction, subject to its motion profile and coordinate configuration.

An absolute command depends on the validity of the axis coordinate system. If the machine reference is not established or the position is not trustworthy, an absolute target may not represent the intended physical location.

Common uses include:

  • Moving a tool to a programmed machining position.
  • Positioning a fixture.
  • Moving a transfer unit to a station.
  • Positioning a robot-mounted linear axis.
  • Moving a servo-driven slide to a known inspection location.

Important considerations

  • Confirm that the target lies within the permitted travel range.
  • Verify that the coordinate system and units are correct.
  • Confirm that homing or another valid referencing method has established the required coordinate relationship.
  • Check that the target is reachable without violating machine constraints.
  • Consider whether the controller uses a shortest-path, directional, or multi-turn interpretation for rotary axes.

5. Relative positioning

A relative move commands a displacement from the relevant position reference used by the motion controller.

For a simple linear axis:

\[ x\_{\text{target}} = x\_{\text{start}} + \Delta x \]

If the axis starts at 120 mm and receives a relative move of 80 mm:

\[ x\_{\text{target}} = 120 + 80 = 200\text{ mm} \]

A relative move can be useful when the process requires a fixed displacement rather than a fixed machine coordinate.

Examples include:

  • Advancing a feed axis by a defined distance.
  • Moving a fixture a fixed offset.
  • Performing an incremental adjustment.
  • Moving between adjacent positions using a repeating displacement.

The reference point used for a relative command must be understood. Depending on the controller and command implementation, the relative distance may be interpreted from the actual position, commanded position, or another defined trajectory reference.

Repeated relative commands can accumulate positioning errors or produce unexpected locations if commands are issued before previous moves complete or if the reference semantics are misunderstood.

6. Velocity, acceleration, and deceleration

A move command typically includes or references motion-profile parameters.

Parameter Meaning Engineering concern
Target position Requested destination Must be valid and reachable
Velocity Requested travel speed Must respect axis and process limits
Acceleration Rate of velocity increase Affects torque demand and mechanical loading
Deceleration Rate of velocity reduction Affects stopping distance and mechanical stress
Jerk Rate of change of acceleration Affects smoothness and vibration
Direction Intended direction of movement Must be consistent with limits and machine geometry
Move mode Absolute, relative, or another supported mode Must match the process requirement

For constant acceleration from rest, an idealized relationship is:

\[ v = at \]

For an idealized move with constant acceleration and no speed limit reached, the distance is:

\[ d = \frac{1}{2}at^2 \]

These equations describe simplified motion. Actual servo trajectories may include acceleration ramps, constant-velocity sections, deceleration ramps, jerk limits, and controller-specific profile generation.

Trapezoidal motion profile

Velocity
   ↑
   |          __________
   |         /          \
   |        /            \
   |_______/              \_______ → Time
       Accel   Constant    Decel
               velocity

A triangular profile has no constant-velocity plateau because the move is too short to reach the requested maximum velocity.

Short moves may therefore never reach the programmed maximum speed. This is normal trajectory behavior, not necessarily a drive fault.

7. Jog operation

Jogging is used for manual movement, setup, alignment, maintenance, and controlled positioning.

A typical jog interface contains:

  • Positive jog command.
  • Negative jog command.
  • Jog speed selection.
  • Axis-enable state.
  • Directional limit conditions.
  • Mode and interlock conditions.
  • A defined response when the jog request is released.

For continuous jog, the axis generally continues moving while the jog request remains active, subject to the configured motion and stop behavior.

For incremental jog, each valid command requests a specified displacement, such as 0.1 mm, 1 mm, or 5 mm.

Continuous jog logic

Conceptually:

IF ManualMode
   AND AxisEnabled
   AND PositiveJogRequest
   AND PositiveDirectionPermitted
   AND NOT NegativeJogRequest THEN

    RequestPositiveJog := TRUE;
ELSE
    RequestPositiveJog := FALSE;
END_IF;

This is illustrative PLC logic, not a complete motion program. The actual command should use the controller's motion library and account for command ownership, active motion, stopping behavior, and error handling.

Jog interlocks

Before accepting a jog request, the controller may need to verify:

  • Manual or setup mode is active.
  • The axis is enabled.
  • No blocking fault is active.
  • The relevant direction is permitted.
  • Required guards and safety conditions are satisfied.
  • The machine is not in a conflicting automatic sequence.
  • The requested speed is within the permitted setup limit.
  • No incompatible motion command is active.

The specific safety requirements depend on the machine's risk assessment. A standard PLC jog bit is not, by itself, a safety function.

Positive and negative jog

The meaning of positive and negative direction must be established during commissioning. It depends on the configured coordinate system and mechanical installation.

Do not assume that positive direction always means clockwise rotation or movement to the right.

Incorrect direction mapping can cause collisions, cable damage, limit overtravel, and mechanical interference.

8. Homing and machine referencing

Homing establishes the reference relationship between the axis feedback and the machine coordinate system.

The axis may have encoder feedback before homing, but the controller may not yet know how that feedback relates to the machine's intended reference coordinate.

Common reference methods include:

  • Home switch plus an encoder reference marker.
  • Home switch only, where supported and appropriate.
  • Encoder index or reference marker.
  • Absolute encoder with a validated coordinate setup.
  • A mechanical reference procedure defined by the machine builder.

The available methods depend on the hardware and controller.

Typical homing sequence

Verify axis and homing permissives
              ↓
Check for blocking faults
              ↓
Start homing command
              ↓
Move according to the configured homing method
              ↓
Detect reference switch or reference event
              ↓
Establish the coordinate reference
              ↓
Complete the homing sequence
              ↓
Confirm homing status

Some methods use multiple movement stages, including searching for a switch, changing direction, and locating an encoder index. The order and speed depend on the selected homing method.

Home switch versus home position

A home switch provides a physical reference event. The machine's final home coordinate may be assigned at that event or established using an additional encoder reference or offset.

Therefore, the physical switch location and the final machine coordinate do not necessarily have to be identical.

A configured home offset may establish a coordinate relationship such as:

\[ x\_{\text{machine}} = x\_{\text{reference}} + x\_{\text{offset}} \]

The exact sign convention and implementation depend on the controller.

Absolute encoders

An absolute encoder can provide a position value without performing a traditional incremental homing search. However, an absolute position value does not automatically guarantee that the machine coordinate is correct.

The machine may still require:

  • Encoder initialization.
  • Correct encoder-to-machine calibration.
  • Valid reference offsets.
  • Verification of the mechanical position.
  • Confirmation that the stored reference data is valid.
  • A machine-specific reference or recovery procedure.

Do not assume that every absolute-encoder axis can safely skip homing.

9. Homing safety and direction limits

Homing can cause movement before the axis coordinate is established. It must therefore be treated as a motion operation, not merely a software initialization command.

Important checks include:

  • Confirm that the selected homing method matches the installed sensor arrangement.
  • Confirm the expected search direction.
  • Verify the switch input polarity and electrical behavior.
  • Check that the switch is located within the permitted travel range.
  • Verify the configured homing speed and acceleration.
  • Confirm the behavior if the switch is already active at startup.
  • Confirm the behavior if the reference event is never detected.
  • Verify the final coordinate and home offset.
  • Ensure that the procedure accounts for mechanical and safety constraints.

If a limit switch is active unexpectedly, do not repeatedly command motion toward the limit. Diagnose the sensor state, wiring, coordinate configuration, and permitted recovery procedure first.

10. Motion command execution and handshake

A motion command normally has a lifecycle.

Command conditions satisfied
            ↓
Command request issued
            ↓
Controller accepts command
            ↓
Motion becomes active
            ↓
Axis follows trajectory
            ↓
Target or completion condition reached
            ↓
Command reports completion

A command can be rejected because the axis is disabled, a previous command owns the axis, the parameters are invalid, the coordinate reference is unavailable, or a fault is active.

The controller may expose status values such as:

  • Busy
  • Active
  • Done
  • CommandAborted
  • Error
  • ErrorID

These names are common in some motion-control libraries, but the precise meaning and availability depend on the platform.

A command's Done indication generally relates to that command's completion criteria. It should not automatically be interpreted as proof that the complete machine operation has finished.

11. PLCopen-style motion function blocks

Many PLC motion systems provide function blocks with concepts similar to PLCopen Motion Control.

Function block concept Typical purpose Important consideration
MC_Power Request power or enable for an axis object Does not necessarily mean the axis is homed or moving
MC_Reset Request reset of an axis or motion error Does not guarantee that the fault cause is removed
MC_Home Execute a homing procedure Requires a valid homing configuration and safe movement conditions
MC_MoveAbsolute Move to an absolute target Requires correct coordinate interpretation
MC_MoveRelative Move by a relative distance Confirm the reference semantics
MC_MoveVelocity Command velocity-controlled movement Requires defined termination or stopping behavior
MC_Stop Execute the library's defined stop operation Stop semantics vary by implementation
MC_Halt Interrupt or decelerate motion according to the library's behavior Do not assume it is identical to every stop command

Function-block names alone do not guarantee identical behavior across vendors. Consult the applicable controller documentation.

Execute and edge-triggered commands

Some motion function blocks use a rising edge on an Execute input to start a command.

Conceptually:

Execute: FALSE → TRUE
             ↓
       Command triggered
             ↓
     Busy / Active status
             ↓
      Done or Error status

Holding Execute high does not necessarily mean the controller repeatedly starts the command. Many implementations trigger on an edge and manage the active command internally.

A robust program should define when Execute is asserted, how it is released, how retriggering is handled, and what happens when a command is aborted.

Avoid generating a new move command every PLC scan unless the specific motion architecture explicitly supports that behavior.

12. Axis command ownership and conflicts

An axis can be subject to multiple potential command sources:

  • Automatic sequence.
  • Manual jog controls.
  • Homing routine.
  • HMI positioning request.
  • Maintenance or commissioning interface.
  • Higher-level motion coordinator.

If multiple sources can issue commands simultaneously, the system needs a clear command-ownership strategy.

A conceptual priority arrangement might be:

Safety-related response
          ↓
Fault / required stop response
          ↓
Controlled recovery
          ↓
Homing or reference operation
          ↓
Manual jog
          ↓
Automatic positioning

This is only an example. Actual priorities must be designed around the machine's risk assessment, stop requirements, and operating modes.

A safety-related response must not depend solely on this ordinary PLC priority list.

Typical command conflicts include:

  • Jog request while an automatic move is active.
  • Homing requested during a positioning command.
  • Two HMI requests arriving before the previous command completes.
  • Automatic sequence restarting while a manual mode remains selected.
  • A new move replacing an active move unexpectedly.

Use explicit mode management, command arbitration, state checks, and clear operator feedback.

13. Position limits and travel protection

Motion commands should be checked against the configured travel envelope.

For a linear axis, an illustrative command validation is:

\[ x\_{\min} \leq x\_{\text{target}} \leq x\_{\max} \]

For relative moves, the expected target must be evaluated using the controller's relative-move semantics before accepting the command.

For jog operation, the controller must consider directional permissions and the configured stopping behavior near travel limits.

Software travel limits are useful but do not replace the machine's required physical limits or safety-related protection.

Important distinctions:

  • Software limit: A configured position boundary enforced by the control system.
  • Limit switch: A physical sensor that reports a position or travel condition.
  • Safety limit function: A safety-rated function, when provided and required, designed and validated for the specified safety purpose.
  • Mechanical stop: A physical feature that limits movement but may not be suitable as a routine stopping method.

Do not use a mechanical stop as the normal means of positioning an axis.

14. Stop behavior during motion

A stop command may be needed when an operator releases jog, a process sequence is cancelled, an interlock changes, or a fault occurs.

Different stop mechanisms can produce different responses.

Stop concept General behavior Important limitation
Controlled deceleration Reduces velocity according to a defined profile Requires the control and drive to function as expected
Motion halt Interrupts or decelerates motion according to the library's defined semantics Exact behavior varies by platform
Drive quick stop Uses the drive's configured quick-stop behavior Configuration and safety classification must be verified
Torque inhibition Prevents torque production through a specified mechanism The axis may coast or fall unless the system is designed to prevent hazardous movement
Emergency stop A machine-level safety function implemented according to the risk assessment Must not be treated as just another standard motion command

For a vertical axis, torque inhibition can allow the load to descend if a suitable mechanical holding or safety arrangement is not present. Brake sequencing and safety functions must be designed and validated for the application.

15. Units, scaling, and coordinate systems

Motion commands are only meaningful when the controller's units and scaling are correct.

An axis may use engineering units such as:

  • Millimetres.
  • Degrees.
  • Revolutions.
  • Encoder counts.
  • User-defined machine units.

The controller may convert between engineering units and internal counts.

For a simple linear axis, an illustrative conversion is:

\[ \text{Counts} = \text{Position} \times \text{Counts per unit} \]

If the configured scale is 10,000 counts/mm, a command for 25 mm corresponds to:

\[ 25 \times 10{,}000 = 250{,}000\text{ counts} \]

This example assumes a linear scale with no additional gear ratio, electronic gearing, or coordinate transformation.

Scaling errors can cause an axis to move much farther or less than expected. Validate scale, sign, gear ratio, direction, and reference offset at low-risk commissioning conditions.

16. Common motion-command faults

Symptom Possible cause Diagnostic action
Absolute move is rejected Axis not referenced, target invalid, or axis not enabled Check axis state, reference validity, and target limits
Relative move travels the wrong distance Incorrect scaling or misunderstood relative reference Verify engineering units, scaling, and controller semantics
Jog does not start Manual mode inactive, axis disabled, interlock missing, or command conflict Monitor permissives, axis state, and command ownership
Jog continues after operator release Incorrect request handling or unsupported command-release behavior Check input processing and documented stop behavior
Homing never completes Reference sensor failure, wrong direction, or incorrect homing configuration Monitor sensor transitions, axis position, and homing state
Homing completes at the wrong position Incorrect offset, scaling, direction, or reference configuration Verify the reference event and coordinate assignment
Move stops before reaching target Limit, stop request, fault, command replacement, or trajectory constraints Check motion status and the event that terminated the command
Move overshoots or oscillates Incorrect tuning, scaling, mechanics, or motion-profile configuration Review following error, feedback quality, tuning, and mechanics
New command aborts an active move Command replacement or arbitration behavior Review the motion library's command rules
Motion command reports error Invalid parameters, axis state, or active fault Read the error identifier and controller diagnostics
Axis moves in the wrong direction Direction mapping, motor phasing, or coordinate configuration issue Verify direction mapping using the approved commissioning procedure
Axis moves unexpectedly after restart Retained command, automatic restart logic, or stale request Review startup initialization and restart authorization

17. Practical commissioning procedure

A. Preparation

  • Confirm the servo motor, drive, encoder, and mechanical configuration.
  • Verify axis units, scaling, direction, and coordinate system.
  • Confirm the motion controller's command semantics.
  • Check enable, fault, communication, and safety status.
  • Verify software limits and applicable physical limit devices.
  • Confirm that command ownership and operating modes are defined.
  • Establish approved conditions for initial motion testing.

B. Jog test

  • Select the intended manual or setup mode.
  • Confirm that the axis is enabled.
  • Test positive jog at an appropriately limited speed.
  • Confirm actual direction and feedback.
  • Release the jog request and verify the expected response.
  • Test negative jog under the same controlled conditions.
  • Verify directional limit handling.
  • Confirm that automatic motion cannot conflict with manual control.

C. Homing test

  • Verify the selected homing method.
  • Confirm the expected search direction and speed.
  • Monitor the home sensor and reference feedback.
  • Verify the final machine coordinate.
  • Confirm that homing completion is reported correctly.
  • Test the documented response to a missing or invalid reference signal.
  • Verify that an incomplete homing operation does not incorrectly authorize absolute positioning.

D. Positioning test

  • Perform an absolute move to a suitable test position.
  • Confirm actual position and target interpretation.
  • Perform a relative move and verify the displacement.
  • Verify acceleration, velocity, and deceleration behavior.
  • Confirm command completion and error reporting.
  • Test command cancellation and stopping behavior.
  • Verify that invalid targets are rejected appropriately.
  • Record the final configuration and test results.

All tests must be performed under the approved machine commissioning procedure, with appropriate safeguards and personnel clear of hazardous movement.

18. Troubleshooting using PLC trends

For difficult intermittent faults, trend the signals that show both the command and the result.

Useful signals include:

  • Motion command request.
  • Command execute input.
  • Command busy or active status.
  • Command done and error status.
  • Axis-enabled status.
  • Homing-complete status.
  • Target position.
  • Actual position.
  • Actual velocity.
  • Following error.
  • Positive and negative limit status.
  • Drive fault and warning codes.
  • Relevant interlocks and mode status.

A time-aligned trend can show whether the command was rejected before motion, whether the axis started and then stopped, or whether the motion controller reported completion incorrectly relative to the machine's intended sequence.

Do not diagnose a motion issue using only the HMI's final alarm message when the controller provides more detailed state and error information.

19. Documentation requirements

For every servo axis, maintain documentation that identifies:

  • Axis name and machine function.
  • Drive, motor, and feedback hardware.
  • Engineering units and scaling.
  • Coordinate system and reference method.
  • Absolute and relative positioning behavior.
  • Jog direction and speed configuration.
  • Velocity, acceleration, deceleration, and jerk limits.
  • Software limits and relevant physical limit devices.
  • Motion function blocks and command-handshake behavior.
  • Axis state transitions and fault handling.
  • Command ownership and operating modes.
  • Stop behavior and safety-related interfaces.
  • Commissioning tests and verified results.
  • Recovery procedure for homing or position-reference loss.

This information is especially important after a drive replacement, controller migration, mechanical retrofit, or modification to the machine's motion sequence.

20. Interview questions and answers

1. What is the difference between absolute and relative positioning?

Absolute positioning commands a target coordinate. Relative positioning commands a displacement from the reference defined by the motion controller.

2. What is jog mode used for?

Jog mode provides controlled manual movement for setup, alignment, commissioning, and maintenance.

3. Why is homing required?

Homing establishes a known relationship between the axis feedback and the machine coordinate system when that relationship is not already valid.

4. Does an absolute encoder always eliminate homing?

No. The machine still needs a valid coordinate relationship, correct configuration, and verified reference data.

5. What is the purpose of acceleration and deceleration settings?

They control how quickly velocity changes, influencing cycle time, torque demand, mechanical stress, and positioning behavior.

6. What is the difference between command accepted and command completed?

Command accepted means the controller has accepted the request. Command completed means the command has reached its defined completion condition.

7. Why can a move command be rejected when the servo is enabled?

The axis may not be referenced, the target may be invalid, another command may own the axis, or a required interlock may be missing.

8. Why should jog and automatic motion be mutually managed?

To prevent conflicting command sources from producing unexpected movement or disrupting the intended machine sequence.

9. What is a motion profile?

It defines how position, velocity, acceleration, and sometimes jerk evolve during the commanded movement.

10. Why should actual position be monitored during commissioning?

It helps verify direction, scaling, coordinate interpretation, target tracking, and whether the axis follows the commanded trajectory.

11. Is a normal PLC stop command equivalent to an emergency stop?

No. A standard motion stop is a control operation. An emergency stop is a safety function that must be designed and validated for the machine's risks.

12. What is the most important check before an absolute move?

Verify that the coordinate reference is valid and that the target is correct, reachable, and within the permitted travel envelope.

21. Final engineering checklist

  • Understand absolute, relative, jog, and homing operations.
  • Verify the controller's command and completion semantics.
  • Confirm units, scaling, direction, and coordinate reference.
  • Check axis enable and command permissives.
  • Prevent conflicting command sources.
  • Configure and verify motion-profile limits.
  • Validate homing and reference recovery.
  • Confirm travel limits and stop behavior.
  • Monitor actual position, velocity, and motion errors.
  • Test command rejection, interruption, and recovery behavior.
  • Document the axis configuration and commissioning results.

The key principle is that a motion command is a request to execute a defined operation, not proof that the axis can safely execute it or has completed it. Reliable motion integration requires valid axis state, correct coordinates, controlled command ownership, and verified feedback.
