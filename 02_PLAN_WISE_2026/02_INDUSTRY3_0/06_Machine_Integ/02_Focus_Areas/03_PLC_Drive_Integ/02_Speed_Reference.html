1. Purpose of a speed reference

A speed reference is the commanded speed value sent by a PLC, HMI, motion controller, or other control source to a variable frequency drive (VFD) or servo drive.

The reference tells the drive what speed to target. It does not necessarily equal the motor's actual speed, because actual speed depends on the drive's control mode, motor characteristics, load, limits, and operating conditions.

Typical applications include:

  • Conveyor speed control.
  • Pump and fan speed adjustment.
  • Machine spindle speed control.
  • Roller and indexing systems.
  • Mixing and material-handling equipment.
  • Servo-axis velocity commands.
  • Coordinated speed control between machines.

Speed references may be transmitted through an analog signal, a network data word, a dedicated pulse interface, or a motion-control interface.

The engineering task is to convert the requested speed into the exact numerical representation expected by the drive, then verify that the resulting physical speed matches the intended command.

2. Speed reference architecture

HMI speed setpoint
        ↓
PLC engineering-unit value
        ↓
Range checks and operating limits
        ↓
Scaling and data conversion
        ↓
Analog output or network reference
        ↓
VFD / Servo drive
        ↓
Drive control mode and motor
        ↓
Actual speed feedback
        ↓
PLC comparison and diagnostics

A reliable implementation separates four values:

  • Requested speed: What the operator or sequence asks for.
  • Limited speed: The command after permitted minimum and maximum limits are applied.
  • Transmitted reference: The raw value sent to the drive.
  • Actual speed: The measured or reported speed of the motor or axis.

These values should not be treated as interchangeable. Keeping them separate makes commissioning and troubleshooting much easier.

3. Understand the different speed units

The word speed can refer to different physical quantities. Before writing scaling logic, identify exactly what the drive expects.

Quantity Unit Meaning
Electrical frequency Hz Frequency of the drive's output electrical waveform
Rotational speed rpm Mechanical revolutions per minute
Angular velocity rad/s Mechanical angular displacement per second
Linear speed m/s or mm/s Linear movement per unit time
Percentage reference % Normalized command relative to a defined reference
Raw reference Counts or integer units Digital value required by a device interface

A VFD may accept a reference in hertz, percentage of configured maximum frequency, or a normalized digital value. A servo drive may use rpm, engineering units per second, counts per second, or a vendor-specific scaled integer.

Always determine the reference unit from the drive configuration and interface documentation.

4. Electrical frequency versus motor rpm

For an AC motor, electrical frequency and mechanical speed are related, but they are not generally identical.

For a synchronous motor:

\[ n_s = \frac{120f}{P} \]

Where:

  • \(n_s\) is synchronous speed in rpm.
  • \(f\) is electrical frequency in Hz.
  • \(P\) is the number of motor poles.

For example, a four-pole motor has a synchronous speed of:

\[ n_s = \frac{120 \times 50}{4} = 1500\text{ rpm} \]

At 50 Hz, a four-pole induction motor therefore has a synchronous speed of 1500 rpm. Its actual rotor speed under load is normally lower because of slip.

For an induction motor:

\[ s = \frac{n_s-n_r}{n_s} \]

Where \(s\) is the slip ratio and \(n_r\) is the rotor speed in rpm.

If synchronous speed is 1500 rpm and rotor speed is 1450 rpm:

\[ s = \frac{1500-1450}{1500} = 0.0333 \]

The slip is approximately 3.33%.

Actual slip depends on motor design and operating conditions. Do not assume a fixed rpm-per-hertz relationship will give exact motor speed under every load.

5. Linear scaling fundamentals

A speed reference often needs to be converted from one numerical range to another.

The general linear scaling formula is:

\[ Y = \frac{X-X\_{\min}}{X\_{\max}-X\_{\min}} (Y\_{\max}-Y\_{\min})+Y\_{\min} \]

Where:

  • \(X\) is the input value.
  • \(X\_{\min}\) and \(X\_{\max}\) are the input range.
  • \(Y\_{\min}\) and \(Y\_{\max}\) are the output range.
  • \(Y\) is the converted value.

For a reference that begins at zero, the formula simplifies to:

\[ Y = \frac{X}{X\_{\max}}Y\_{\max} \]

This is valid only when the assumed input and output ranges are correct and the relationship is linear.

Important: Scaling does not itself impose safe or valid operating limits. Range validation, clamping, mode restrictions, and fault handling must be designed separately.

6. Scaling a percentage reference to hertz

Suppose a drive is configured so that a normalized command from 0 to 100% represents 0 to 50 Hz.

The conversion is:

\[ f\_{\text{ref}} = \frac{R}{100}\times 50 \]

Where \(R\) is the percentage reference.

PLC reference Calculated frequency
0% 0 Hz
20% 10 Hz
40% 20 Hz
60% 30 Hz
80% 40 Hz
100% 50 Hz

If the required speed is 30 Hz, the percentage reference is:

\[ R = \frac{30}{50}\times 100 = 60\\% \]

This example assumes the drive actually interprets 100% as 50 Hz. Some drives use a configured nominal frequency, maximum frequency, or another scaling base.

7. Scaling a PLC integer to hertz

Networked drives frequently accept an integer reference rather than a floating-point value in engineering units.

Suppose the interface specification states that:

  • 0 represents 0 Hz.
  • 10000 represents 50 Hz.

The conversion from hertz to raw reference is:

\[ R\_{\text{raw}} = \frac{f\_{\text{ref}}}{50}\times 10000 \]

For a 30 Hz command:

\[ R\_{\text{raw}} = \frac{30}{50}\times 10000 = 6000 \]

The PLC transmits the raw value 6000, assuming the configured drive interface uses this exact convention.

The reverse conversion is:

\[ f\_{\text{actual}} = \frac{R\_{\text{raw}}}{10000}\times 50 \]

A returned raw value of 6000 therefore represents 30 Hz under the same scaling convention.

This is a hypothetical interface example. Actual drive scaling may use signed integers, fixed-point representations, percentage units, or profile-specific conventions. Verify the manual before implementing the conversion.

8. Scaling an analog output to a speed reference

Some drives accept speed commands through a 0–10 V or 4–20 mA analog input.

Suppose the drive is configured so that 0–10 V corresponds to 0–50 Hz.

The conversion is:

\[ f\_{\text{ref}} = \frac{V}{10}\times 50 \]

At 6 V:

\[ f\_{\text{ref}} = \frac{6}{10}\times 50 = 30\text{ Hz} \]

For a 4–20 mA input configured to represent 0–50 Hz:

\[ f\_{\text{ref}} = \frac{I-4}{20-4}\times 50 \]

At 12 mA:

\[ f\_{\text{ref}} = \frac{12-4}{16}\times 50 = 25\text{ Hz} \]

These calculations describe the intended command mapping. Actual output voltage or current may differ because of module resolution, calibration, loading, wiring, and configuration errors.

8.1 Raw analog output conversion

A PLC analog output may use an integer raw range, such as a device-specific range representing 0–10 V. Do not assume that every analog module uses the same raw counts.

For a hypothetical output module where 0–10 V corresponds to raw values 0–27648:

\[ R\_{\text{raw}} = \frac{V}{10}\times 27648 \]

For a 6 V output:

\[ R\_{\text{raw}} = \frac{6}{10}\times 27648 = 16588.8 \]

The PLC must convert this value to the supported data type and handle rounding according to the implementation requirements.

The raw range 0–27648 is an example used by some Siemens analog interfaces, not a universal PLC convention. Confirm the exact module's representation.

9. Scaling hertz to rpm

A VFD may accept a reference in hertz while the operator expects a mechanical speed in rpm.

For a synchronous-speed estimate:

\[ n_s = \frac{120f}{P} \]

For a four-pole motor at 40 Hz:

\[ n_s = \frac{120\times40}{4}=1200\text{ rpm} \]

This estimates synchronous speed, not necessarily actual induction-motor speed.

If the application uses a configured linear approximation based on a measured operating point, the conversion may instead use a calibrated relationship.

For example, suppose a machine is calibrated so that 50 Hz produces approximately 1450 rpm at a particular operating condition. A simple proportional estimate gives:

\[ n\_{\text{estimated}} = \frac{f}{50}\times1450 \]

At 30 Hz:

\[ n\_{\text{estimated}} = \frac{30}{50}\times1450 = 870\text{ rpm} \]

This is an estimate based on the stated calibration point. It does not guarantee that an induction motor will run at exactly 870 rpm at 30 Hz under changing load.

For applications that require accurate speed, use suitable feedback and the drive's supported control mode rather than relying solely on frequency-based estimation.

10. Scaling rpm to a normalized drive reference

Suppose a drive interface specifies that a raw reference of 16384 corresponds to 1500 rpm.

The conversion is:

\[ R\_{\text{raw}} = \frac{n\_{\text{ref}}}{1500}\times16384 \]

For a command of 900 rpm:

\[ R\_{\text{raw}} = \frac{900}{1500}\times16384 = 9830.4 \]

The integer transmitted depends on the interface's defined rounding and data-type requirements.

Before using this formula, verify:

  • The reference value that corresponds to 100% or the defined full-scale value.
  • Whether the reference is signed or unsigned.
  • Whether negative values represent reverse direction.
  • The supported minimum and maximum speed.
  • The configured motor or axis speed base.
  • Whether the drive expects rpm, percentage, or another unit.
  • Whether direction is conveyed separately through a control bit.

A value of 16384 does not universally represent 1500 rpm. It is only valid for an interface that defines that relationship.

11. Minimum and maximum speed limits

A speed reference must respect the permitted operating range of the equipment.

Suppose an application allows a commanded frequency between 5 Hz and 45 Hz while running.

The PLC can apply a limit:

\[ f\_{\text{limited}} = \min(\max(f\_{\text{requested}},5),45) \]

This constrains the reference to the stated interval.

However, the machine must also define what zero speed means. Some applications allow a zero reference while enabled; others require a stop command or a separate operating state. A nonzero minimum-frequency parameter in the drive may cause the motor to continue running even when the speed reference is small.

The implementation should distinguish:

  • A stop request.
  • A zero speed reference.
  • A minimum permitted running speed.
  • A maximum permitted speed.
  • A drive parameter limit.
  • A process-specific limit that changes with operating mode.

Do not use clamping alone as a substitute for the required stop logic or safety function.

12. Signed speed references and direction

Some interfaces use a signed speed value. In such systems, positive and negative values may represent opposite directions.

For example, a hypothetical interface may define:

  • +1000 rpm as forward rotation.
  • -1000 rpm as reverse rotation.
  • 0 rpm as a zero-speed reference.

Other drives use a nonnegative speed reference and a separate direction bit.

Interface design Speed command Direction command
Signed reference Positive or negative value Encoded in the sign, if supported
Separate direction bit Nonnegative magnitude Separate control bit
Preset-speed selection Selects a configured speed May be separate or embedded in the mode

Do not mix signed and separate-direction conventions. If the interface expects an unsigned magnitude plus a direction bit, sending a negative integer may produce an invalid value or an unintended interpretation.

Direction changes must follow the drive's permitted operating sequence. Some applications require the drive to stop before the direction command changes.

13. Speed ramping and acceleration limits

The speed reference may change immediately, but the drive usually applies configured acceleration and deceleration behavior.

For a linear ramp:

\[ t = \frac{|n_2-n_1|}{a} \]

Where:

  • \(t\) is the ramp time.
  • \(n_1\) is the initial speed.
  • \(n_2\) is the target speed.
  • \(a\) is the speed-change rate in compatible units per second.

For example, increasing speed from 300 rpm to 900 rpm at a configured linear rate of 200 rpm/s gives:

\[ t = \frac{|900-300|}{200}=3\text{ s} \]

This is a simplified calculation. Actual behavior depends on the drive's acceleration settings, ramp shape, current and torque limits, load, and any application-specific restrictions.

The PLC should not assume that the actual speed immediately equals the new reference. A robust sequence may wait for actual speed to enter a defined tolerance band before proceeding.

14. Reference scaling versus drive parameters

Several different settings influence the final motor speed.

Parameter or value Function
PLC engineering setpoint Speed requested by the application
PLC scaling Converts the setpoint into the interface representation
Reference source selection Determines where the drive obtains its command
Reference normalization Defines how raw values map to speed
Minimum frequency or speed Restricts the lower operating range
Maximum frequency or speed Restricts the upper operating range
Acceleration/deceleration ramps Controls how quickly the target is approached
Motor data Supports the drive's motor-control calculations
Control mode Determines how the drive regulates motor behavior
Feedback configuration Defines how actual speed is measured or estimated

A correct PLC formula cannot compensate for a drive configured to use the wrong reference source or scaling base.

For example, the PLC may transmit a value intended to represent 30 Hz while the drive interprets it as 30% of a different configured maximum. The transmitted value can be correct at the network level while the resulting speed is wrong.

15. Data types, resolution, and rounding

Speed references may use integer or floating-point values.

A floating-point value can represent fractions, such as 27.5 Hz. An integer reference may require the PLC to scale the value into a larger numeric range.

For an integer representation:

\[ R\_{\text{raw}} = \operatorname{round}\left( \frac{f\_{\text{ref}}}{f\_{\max}}R\_{\max} \right) \]

Rounding introduces a small quantization error. The magnitude depends on the scaling range and the resolution of the transmitted reference.

Check for:

  • Integer overflow.
  • Incorrect signedness.
  • Truncation of decimal values.
  • Incorrect unit conversions.
  • Division by zero in scaling calculations.
  • Inconsistent raw ranges between PLC and drive.
  • Unsupported negative values.
  • Data-word or byte-order mismatches.

Where possible, perform the scaling in a suitable intermediate data type before converting to the drive's required representation.

16. PLC implementation example

Consider a VFD interface with these hypothetical specifications:

  • PLC engineering setpoint: 0–50 Hz.
  • Drive raw reference: 0–10000.
  • Valid commanded frequency: 0–50 Hz.
  • Separate run command.
  • Actual frequency returned through a separate feedback field.

The PLC calculation is:

\[ R\_{\text{raw}} = \frac{f\_{\text{ref}}}{50}\times10000 \]

A conceptual implementation is:

IF SpeedSetpoint_Hz < 0.0 THEN
    SpeedLimited_Hz := 0.0;
ELSIF SpeedSetpoint_Hz > 50.0 THEN
    SpeedLimited_Hz := 50.0;
ELSE
    SpeedLimited_Hz := SpeedSetpoint_Hz;
END_IF;

SpeedReference_Raw :=
    ROUND((SpeedLimited_Hz / 50.0) * 10000.0);

The code is illustrative pseudocode. Actual rounding functions, data types, and assignment syntax vary by PLC platform.

The real implementation should also define behavior for invalid values, communication faults, operating modes, stop requests, and any process-specific speed restrictions.

17. Commissioning and verification

17.1 Before testing

  • Confirm the drive model and the reference specification.
  • Verify the configured command and reference sources.
  • Confirm the units expected by the drive.
  • Check the raw range and scaling base.
  • Verify the data type, signedness, and word mapping.
  • Confirm minimum and maximum limits.
  • Check acceleration and deceleration settings.
  • Confirm that the test can be performed under approved operating conditions.

17.2 During testing

Test several reference points rather than only one.

Test point Expected command Verification
Minimum Defined minimum or zero Confirm correct interpretation and stop behavior
Low speed Example: 10 Hz Compare reference, drive display, and feedback
Midrange Example: 25 Hz Verify proportional scaling
High range Example: 45 Hz Confirm range limits and actual response
Maximum Defined maximum Confirm the configured upper limit
Invalid value Below minimum or above maximum Verify rejection or clamping behavior
Communication loss No valid reference update Verify the defined fault response

The numerical examples assume a 0–50 Hz range. Use the actual machine's approved test values.

17.3 Verify the physical result

Compare the following values:

  1. HMI requested speed.
  2. PLC engineering setpoint.
  3. PLC limited setpoint.
  4. PLC transmitted raw reference.
  5. Drive-interpreted reference.
  6. Drive-reported actual speed.
  7. Independently measured mechanical speed, if required.

If the drive reports frequency but the application needs mechanical rpm, verify the motor pole count, drive control mode, slip behavior, gearing, and measurement method.

18. Troubleshooting speed-reference faults

Symptom Possible cause Diagnostic action
Motor runs much faster than requested Incorrect scaling base or drive reference configuration Compare transmitted raw value with the configured drive range
Motor runs much slower than requested Wrong normalization, reference limit, or drive parameter Check raw reference, drive-interpreted value, and maximum-speed setting
Speed stays at a fixed value Drive using a preset or local reference Verify reference-source selection and operating mode
Speed reference changes but motor does not accelerate Missing run/enable condition, active limit, or load issue Check drive status, ramps, current limits, and process load
HMI displays rpm but drive expects Hz Unit conversion missing or incorrect Verify engineering units and conversion logic
Reference fluctuates Noisy analog signal, unstable setpoint, or inconsistent updates Inspect signal quality, filtering, task timing, and data source
Negative reference behaves unexpectedly Signedness or direction convention mismatch Check the interface specification and direction mapping
PLC value is correct but drive value is wrong Incorrect mapping, byte order, scaling, or data type Compare raw transmitted data with the drive's decoded reference
Actual rpm differs from frequency estimate Motor slip, pole count, gearing, or load effects Compare the expected motor model with actual feedback
Speed jumps after reconnection Stale or restored reference, retained command, or initialization problem Check startup state, reference validity, and recovery logic
High-speed command is rejected Upper limit, motor configuration, or operating restriction Verify configured limits and equipment ratings
Speed never reaches the reference Torque/current limit, load, ramp setting, or feedback issue Review drive diagnostics, ramp behavior, and actual speed

19. Documentation requirements

For each drive, record:

  • Equipment ID and drive model.
  • Motor nameplate data and configured control mode.
  • Speed-reference source and communication profile.
  • Engineering units used by the PLC and HMI.
  • Raw reference range and scaling formula.
  • Signedness, data type, and rounding convention.
  • Minimum and maximum permitted speed.
  • Acceleration and deceleration settings.
  • Actual-speed feedback source and scaling.
  • Direction convention.
  • Communication timeout and recovery behavior.
  • Commissioning test points and results.
  • Configuration revision and approved backup.

This information is especially important when replacing a drive or migrating from one manufacturer to another. A replacement may accept a similar command but use a different raw range, speed base, or sign convention.

20. Interview questions and answers

1. What is a speed reference?

It is the commanded speed sent to a drive. The reference may be expressed in Hz, rpm, percentage, engineering units, or a scaled raw value.

2. What is the difference between speed reference and actual speed?

The reference is the target. Actual speed is measured or estimated feedback from the drive or an external sensor. The two can differ because of ramping, load, limits, and control behavior.

3. How do you convert a percentage reference to hertz?

Multiply the percentage divided by 100 by the configured maximum frequency, assuming a zero-based linear mapping.

4. How do you convert a raw integer to hertz?

Use the raw minimum and maximum and the corresponding engineering-unit limits in the linear scaling formula, according to the drive interface specification.

5. Is electrical frequency equal to motor rpm?

No. For a synchronous machine, speed is related to frequency and pole count. An induction motor runs below synchronous speed under load because of slip.

6. Why can the drive run at the wrong speed even when the PLC formula is correct?

The drive may use a different reference source, normalization base, maximum frequency, unit convention, or data mapping than the PLC assumes.

7. Why should a speed reference be limited?

To keep the commanded value within the permitted operating range and prevent invalid or unintended commands. The limits must be based on equipment and process requirements.

8. What is the difference between frequency scaling and acceleration ramping?

Scaling determines how the numerical command maps to frequency or speed. Ramping determines how quickly the drive moves from its current operating point toward the target.

9. Why might a 50 Hz command not produce exactly the expected rpm?

The motor's pole count, slip, load, drive control mode, mechanical transmission, and feedback accuracy influence the actual mechanical speed.

10. What must be checked when replacing a VFD?

Verify reference scaling, units, signedness, command source, motor data, operating limits, ramp settings, direction logic, feedback scaling, and the complete control interface.

21. Final engineering checklist

  • Identify whether the drive expects Hz, rpm, percentage, or raw units.
  • Confirm the exact reference range from the manufacturer's documentation.
  • Implement the correct scaling formula and data conversion.
  • Apply the approved operating limits.
  • Keep requested, limited, transmitted, and actual values separate.
  • Verify direction and signed-reference behavior.
  • Check ramp settings and drive operating limits.
  • Validate several reference points during commissioning.
  • Compare drive feedback with the physical process where required.
  • Test invalid values and communication-loss behavior.
  • Document the interface and save the approved configuration.

The central rule is that a correct speed reference requires both correct arithmetic and correct interpretation by the drive. A perfectly calculated number is still useless if the receiving device interprets it using a different range or unit.
