1. Purpose of a VFD in Machine Integration

A Variable Frequency Drive (VFD) controls the speed and operation of an AC motor by controlling the electrical power supplied to it. Depending on the drive and motor, it can also support controlled acceleration, deceleration, torque-related functions, direction control, and motor protection.

In machine integration, the PLC typically decides when the motor should run and what operating reference it should follow, while the VFD performs the motor-control functions.

Common applications include:

  • Conveyor speed control.
  • Pumps and fans.
  • Hydraulic power-pack motors.
  • Machine spindle auxiliaries.
  • Cooling and lubrication systems.
  • Rollers, feeders, and material-handling equipment.
  • Process equipment requiring adjustable motor speed.
  • Coordinated machine sequences involving several drives.

The PLC and VFD must exchange commands and status information correctly. A PLC start command does not guarantee that the motor will run. The drive may be disabled, in the wrong control mode, missing a permissive, reporting a fault, or unable to produce the required torque.

The PLC can command a VFD using hardwired digital and analog signals or an industrial communication network.

The drive may return information such as ready status, running status, actual frequency, output current, warning status, and fault codes.

The exact signals available depend on the VFD model, configuration, and communication interface.

3. What a VFD Controls

A VFD typically consists of a rectifier, a DC link, and an inverter.

AC supply
    |
    v

    |
    v

    |
    v

    |
    v

    |
    v
AC motor

The rectifier converts the incoming AC supply into DC. The DC link stores and smooths energy. The inverter uses power semiconductor switching to synthesize an AC output suitable for controlling the motor.

Many drives use pulse-width modulation (PWM) to produce the required output waveform.

The VFD controls the motor according to its selected control method, motor data, limits, and operating configuration.

3.1 Frequency and motor speed

For an AC motor, the synchronous speed is:

\[ N_s = \frac{120f}{P} \]

Where:

  • \(N_s\) is synchronous speed in RPM.
  • \(f\) is electrical supply frequency in hertz.
  • \(P\) is the number of motor poles.

For an induction motor, actual rotor speed is normally lower than synchronous speed while operating as a motor because of slip.

For example, a four-pole induction motor at 50 Hz has a synchronous speed of:

\[ N_s = \frac{120 \times 50}{4} = 1500\ \text{RPM} \]

The actual motor speed depends on load, slip, and the drive's control method.

Changing the output frequency changes the motor's operating speed, subject to motor characteristics, control settings, mechanical limitations, and load requirements.

3.2 Frequency is not always equal to speed

A VFD display showing 30 Hz does not mean every motor will run at a fixed RPM determined solely by that frequency.

Consider:

  • Motor pole count.
  • Induction motor slip.
  • Gearbox ratio.
  • Belt or pulley ratio.
  • Load characteristics.
  • Vector-control or sensorless-control behavior.
  • Encoder feedback where applicable.

For a direct-drive induction motor, frequency provides a useful estimate of speed. For a geared conveyor, the final conveyor speed also depends on the mechanical transmission ratio and roller dimensions.

4. VFD Control Modes

A VFD can support different motor-control methods. Availability and performance depend on the drive and motor.

Control method Principle Typical application
Scalar V/f control Maintains a configured relationship between voltage and frequency Fans, pumps, general-purpose drives
Sensorless vector control Estimates motor behavior to improve torque and speed control without an encoder Conveyors and variable-load machines
Closed-loop vector control Uses feedback, commonly an encoder or resolver where supported Applications requiring improved low-speed or dynamic performance
Torque control Regulates motor torque or torque-producing current according to the drive's method Winding, tension, and specialized machinery
Position or motion control Coordinates position-related commands and feedback through suitable drive functions Applications requiring controlled positioning

Do not assume every VFD supports every mode. Confirm the drive's capabilities and suitability for the application.

5. PLC-to-VFD Command Types

The PLC must communicate the desired operating state and, where required, a speed or other reference.

5.1 Hardwired control

A simple hardwired interface may use:

  • One digital output for run enable or run command.
  • A second digital output for direction, where required.
  • An analog output for the speed reference.
  • Digital inputs for ready, running, and fault status.
  • An analog input or communication value for actual speed, if required.

Example architecture:

PLC digital output
        |
        v
VFD run input

PLC analog output
        |
        v
VFD speed-reference input

VFD ready output
        |
        v
PLC digital input

VFD fault output
        |
        v
PLC digital input

The signal assignment, common reference, and electrical ratings must be confirmed from the drive and PLC manuals.

5.2 Networked control

A communication interface may transfer several command and feedback values using one configured network connection.

Typical command data includes:

  • Control word.
  • Run and stop requests.
  • Direction.
  • Speed or frequency reference.
  • Reset request where supported.

Typical status data includes:

  • Status word.
  • Ready and running state.
  • Actual frequency or speed.
  • Current or torque-related values.
  • Warning and fault codes.
  • Communication or device status.

A networked drive requires correct protocol selection, device configuration, data mapping, update settings, and fault handling.

A green network indicator does not prove that the PLC is sending the correct command or that the drive is using the intended command source.

6. VFD Control Source and Command Ownership

A VFD may accept commands from several possible sources:

  • Local keypad.
  • Hardwired terminals.
  • Fieldbus or industrial Ethernet.
  • Integrated PLC or motion controller.
  • A configured combination of sources, where supported.

The drive's selected command source determines which interface controls its operation.

For example, the PLC may send a valid run command over a network while the drive is configured to accept run commands from its keypad or terminal inputs. The motor will not respond as expected.

6.1 Parameters to verify

Check the drive's configuration for:

  • Start/stop command source.
  • Speed-reference source.
  • Direction command source.
  • Local/remote operating mode.
  • Enable and permissive conditions.
  • Communication control selection.
  • Reference scaling.
  • Minimum and maximum frequency.
  • Acceleration and deceleration settings.
  • Fault-reset method.

Parameter names and numbering vary by manufacturer and model. Use the manual for the actual drive instead of copying a parameter number from another series.

7. Run, Stop, Enable, and Direction Commands

These signals have distinct meanings, although exact implementation varies.

Command Typical meaning Important consideration
Run Requests motor operation Does not prove the drive can start
Stop Requests the configured stopping behavior Stop mode depends on drive configuration
Enable Permits drive operation when required conditions are met May be separate from run
Forward Requests a configured direction Direction depends on wiring, parameterization, and mechanical convention
Reverse Requests the opposite direction Must be permitted by the machine design
Reset Requests fault reset when conditions allow Does not remove the underlying cause
Speed reference Requests a target frequency, speed, or other configured reference Must match the selected reference source and scaling

A PLC program should distinguish between a run request and confirmation that the drive is ready or running.

7.1 Stop behavior

A stop command may initiate different behaviors, depending on the selected drive configuration:

  • Ramp stop.
  • Coast stop.
  • DC injection braking or another configured stopping method.
  • A drive-specific controlled stop.

A standard stop command is not automatically a safety-rated stop function.

Where a safety function is required, use the appropriate safety architecture and validated function, such as a suitable Safe Torque Off (STO) implementation where applicable. STO removes the drive's ability to produce motor torque as specified by its design, but it does not necessarily bring the motor or load to an immediate standstill.

8. Speed Reference: Analog and Digital Methods

The PLC can provide a speed reference using an analog signal or communication data.

8.1 Analog voltage reference

A common interface is 0–10 V, where the voltage maps to a configured reference range.

For example, if 0–10 V is configured to represent 0–50 Hz, then 5 V corresponds to 25 Hz under linear scaling.

This relationship is valid only if the reference range is configured that way and the drive is actually using that input.

8.2 Analog current reference

A current signal, such as 4–20 mA, may be used for a speed reference where supported.

Current-loop interfaces can be useful in industrial environments because they are often less sensitive to some voltage-drop effects than voltage references.

The PLC output range and VFD input range must match. Confirm the lower and upper scaling limits and the expected behavior for out-of-range signals.

8.3 Network reference

A networked VFD may accept a numeric reference value through a control data structure.

The raw value may represent:

  • A percentage of a configured range.
  • A normalized signed or unsigned value.
  • Frequency units.
  • Speed units.
  • Another manufacturer-defined scaling.

Never assume that a raw value of 1000 represents 10.00 Hz or 100.0% without checking the drive's data mapping.

8.4 Reference scaling

For a linear reference:

\[ f\_{\text{cmd}} = f\_{\min} + \frac{R-R\_{\min}}{R\_{\max}-R\_{\min}}(f\_{\max}-f\_{\min}) \]

Where:

  • \(f\_{\text{cmd}}\) is the calculated frequency command.
  • \(R\) is the PLC reference value.
  • \(R\_{\min}\) and \(R\_{\max}\) are the configured reference limits.
  • \(f\_{\min}\) and \(f\_{\max}\) are the corresponding frequency limits.

The drive may apply additional limits, ramps, compensation, or internal scaling after receiving the reference.

9. Acceleration and Deceleration Ramps

VFD ramps determine how quickly the commanded operating frequency changes.

  • Acceleration time: The configured time for a specified frequency increase.
  • Deceleration time: The configured time for a specified frequency decrease.

The exact timing convention depends on the drive. Some drives define ramp time over a specified base-frequency range rather than from zero to every possible target.

For a simple linear ramp estimate:

\[ \text{Ramp rate} = \frac{\Delta f}{\Delta t} \]

If frequency changes from 10 Hz to 40 Hz over 6 seconds:

\[ \text{Ramp rate} = \frac{40-10}{6} = 5\ \text{Hz/s} \]

This is an illustrative average rate, not a guarantee of actual motor acceleration. Current limits, torque limits, load inertia, mechanical conditions, and drive control can affect the result.

9.1 Why ramp settings matter

A ramp that is too aggressive may cause:

  • Overcurrent trips.
  • Mechanical shock.
  • Belt slip.
  • Excessive tension.
  • High torque demand.
  • DC-bus overvoltage during deceleration.

A ramp that is too slow may cause:

  • Long cycle times.
  • Poor production throughput.
  • Delayed material movement.
  • Process instability.

Choose ramps based on the mechanical load, process requirements, drive capability, and motor characteristics.

10. PLC-VFD Handshake and Status Signals

A robust interface exchanges both commands and status.

A useful conceptual set of signals includes:

  • VFD_Run_Cmd
  • VFD_Ready_FB
  • VFD_Running_FB
  • VFD_Fault_FB
  • VFD_At_Speed_FB
  • VFD_Actual_Frequency
  • VFD_Reset_Cmd
  • VFD_Communication_OK

The actual set depends on the available drive interface.

10.1 Command and feedback relationship

PLC evaluates start permissives
        |
        v
PLC issues run command
        |
        v
VFD accepts command
        |
        v
VFD reports running
        |
        v
PLC evaluates actual operating condition
        |
        v
Machine sequence continues

The PLC should not assume that the motor has reached its target speed simply because the run command was accepted.

An at-speed condition may be derived from drive status, measured speed, or a process-specific feedback condition. Its definition should be documented.

10.2 Ready versus running

Ready typically means the drive is in a condition to accept or execute a command, according to the drive's status definition.

Running typically means the drive reports that its motor operation is active.

The two states are not interchangeable. A drive may be ready but stopped, or it may lose readiness due to a fault or another condition.

Always use the manufacturer's definition of the status bit or terminal.

11. PLC Logic for Starting a VFD

A start request should be generated only when the machine's defined conditions are satisfied.

Typical permissives include:

  • Correct operating mode.
  • No active drive fault.
  • Required machine conditions satisfied.
  • Required process pressure or lubrication available.
  • No prohibited operating condition.
  • Required communication or hardwired interface available.
  • Safety conditions satisfied through the appropriate safety system.

These conditions are application-dependent. Not every drive requires every permissive.

11.1 Conceptual logic

Run_Permissive =
    Auto_Mode
    AND Process_Ready
    AND NOT VFD_Fault
    AND Required_Interlocks_OK

VFD_Run_Cmd =
    Run_Request
    AND Run_Permissive

This is conceptual logic. Actual implementations must handle stop requests, command ownership, mode transitions, faults, and startup behavior explicitly.

11.2 Start sequence

  1. Verify that the machine is in the correct mode.
  2. Confirm the required permissives.
  3. Verify that the drive is available and fault-free.
  4. Send the run command.
  5. Wait for the required drive status.
  6. Verify speed or process feedback if the application requires it.
  7. Advance the machine sequence only when the defined confirmation conditions are met.
  8. Generate a timeout or fault response if the expected status does not arrive.

11.3 Start timeout

If a drive does not report running within the configured interval, the PLC can generate a start-failure alarm.

Potential causes include:

  • Drive fault.
  • Wrong command source.
  • Missing enable.
  • Invalid reference.
  • Missing input permissive.
  • Motor or power circuit fault.
  • Communication issue.
  • Incorrect feedback mapping.

A timeout is a diagnostic mechanism, not proof of a particular failure.

12. PLC Logic for Speed Control

The PLC may select a fixed speed, calculate a variable reference, or receive a reference from another controller.

Examples include:

  • Low speed for setup.
  • Normal production speed.
  • High production speed.
  • A recipe-defined process speed.
  • A speed calculated from a process variable.
  • A speed command received from a supervisory controller.

12.1 Speed selection

A machine might use predefined speed levels:

Operating condition Example reference
Stop 0 Hz command or configured stop request
Setup 10 Hz
Normal production 35 Hz
High production 45 Hz
Fault condition Defined fault response

These are illustrative values, not universal recommendations. The actual limits must be selected for the motor, drive, load, and process.

12.2 Reference limits

The PLC should apply appropriate reference limits when required by the machine design.

For example:

\[ f\_{\text{limited}} = \min(\max(f\_{\text{requested}},f\_{\min}),f\_{\max}) \]

This mathematical expression limits the requested reference between configured minimum and maximum values.

The drive should also be configured with appropriate limits. PLC-side limiting and drive-side limiting serve related but distinct purposes.

Never use a PLC speed limit as a substitute for required mechanical protection or safety functions.

13. Fixed Speeds and Preset References

Some drives support preset speeds selected through digital inputs or internal parameters.

For example, several digital inputs may select among configured speed references.

Advantages can include:

  • Simple field wiring.
  • Repeatable operating speeds.
  • Reduced dependence on an analog reference.
  • Useful operation with basic PLC hardware.

Potential limitations include:

  • Limited number of speed selections.
  • Additional configuration and wiring.
  • Less flexibility for continuously variable control.
  • Risk of mismatched PLC and drive preset definitions.

The PLC program and drive parameters must agree on which input combination selects each speed.

14. VFD Faults and Protective Functions

A VFD monitors electrical and operating conditions. Depending on the drive, it may detect and respond to:

  • Overcurrent.
  • DC-bus overvoltage.
  • DC-bus undervoltage.
  • Motor overload.
  • Drive overtemperature.
  • Motor overtemperature through supported sensors or models.
  • Ground fault or earth-fault conditions.
  • Input phase loss.
  • Output phase or motor-circuit problems.
  • Communication loss.
  • External fault input.
  • Stall or excessive load conditions.

The available protections and their behavior vary by model and configuration.

14.1 Overcurrent

Potential causes include:

  • Acceleration ramp too short.
  • Excessive mechanical load.
  • Jammed machine.
  • Incorrect motor data.
  • Motor cable or motor fault.
  • Inappropriate control settings.
  • Drive or power-stage problem.

Check the fault history, load condition, current behavior, motor parameters, and manufacturer troubleshooting guidance.

14.2 DC-bus overvoltage

Potential causes include:

  • Deceleration ramp too short.
  • High-inertia load returning energy to the drive.
  • Regenerative energy exceeding the drive's handling capability.
  • Supply or drive-related conditions.

Possible solutions depend on the drive and application and may include adjusted deceleration, a suitable braking resistor, or regenerative hardware. Verify the drive's design requirements before making changes.

14.3 Motor overload

Potential causes include:

  • Sustained excessive load.
  • Incorrect motor nameplate data.
  • Incorrect overload configuration.
  • Mechanical binding.
  • Cooling limitations.
  • Excessive operation at low speed for a self-cooled motor.

Do not increase protection limits merely to suppress repeated trips. Identify the cause and verify the motor and drive ratings.

15. VFD Fault Reset and Recovery

A fault-reset command acknowledges or clears a resettable fault when the drive permits it. It does not necessarily remove the underlying fault condition.

A sensible recovery sequence includes:

  1. Read the fault code and available diagnostic data.
  2. Identify the cause and correct it.
  3. Confirm that required operating conditions are restored.
  4. Issue a reset through the approved interface if permitted.
  5. Confirm that the drive has returned to the expected ready state.
  6. Re-establish the run command according to the machine's restart policy.
  7. Verify operation and record recurring faults.

Avoid continuously pulsing reset commands. Repeated resets can obscure the original fault and may create unpredictable restart behavior.

Automatic restart after a fault must be considered carefully. It should only be enabled when specifically justified, configured, and permitted by the machine's risk assessment and operating requirements.

16. VFD Stop Behavior and Machine Coordination

Stopping a VFD-controlled motor is a system-level behavior involving the PLC, drive, motor, and mechanical load.

16.1 Normal process stop

A normal stop request may use a configured ramp or other defined drive stop behavior.

The PLC may wait for a stopped status or another process confirmation before advancing the sequence.

16.2 Emergency stop and safety functions

An emergency stop is a safety-related function and must be implemented according to the applicable risk assessment and standards.

Do not assume that a standard PLC output turning OFF, or a standard VFD run command being removed, is sufficient to satisfy the required emergency-stop function.

Depending on the design, the safety system may use a suitable drive safety function, contactors, braking arrangements, or other safety-related measures.

STO prevents the drive from producing torque as specified by the drive's safety function. It does not guarantee immediate mechanical stopping, electrical isolation, or prevention of gravity-driven movement.

Additional measures may be required for high-inertia loads, vertical axes, stored energy, and other hazardous conditions.

Parameter names and numbers differ across manufacturers and drive families. The following list identifies the configuration categories to verify.

Reference source Selects the speed-reference interface Analog or network reference may not be used
Motor nameplate data Establishes motor operating information Incorrect data can affect control and protection

Maximum frequency Sets upper operating limit Must suit motor and machine limits

Deceleration time Controls frequency decrease Affects stopping time and DC-bus behavior

18. Hardwired Versus Networked VFD Integration

Characteristic Hardwired interface Networked interface

Speed reference Commonly analog or preset input Numeric reference data

19. PLC-VFD Commissioning Procedure

19.1 Before energization

  • Confirm the VFD model, rating, and motor compatibility.
  • Verify the approved electrical schematic.
  • Check incoming supply, protective devices, grounding, and motor wiring.
  • Confirm that the motor and driven machine can be tested safely.
  • Verify the PLC I/O or network configuration.
  • Record the existing drive parameter set where practical.
  • Confirm that required guards, interlocks, and safety functions are installed and validated for the commissioning stage.

19.2 Drive configuration

  • Enter the correct motor nameplate data.
  • Confirm the selected motor-control method.
  • Set the command source.
  • Set the reference source.
  • Configure permitted frequency limits.
  • Configure acceleration and deceleration.
  • Verify digital input assignments.
  • Verify analog scaling or communication reference scaling.
  • Confirm applicable protection settings.
  • Check fault-reset and restart behavior.

19.3 PLC interface checks

  • Verify run-command mapping.
  • Verify stop-command behavior.
  • Verify direction mapping if used.
  • Verify the speed reference at the PLC output or network data.
  • Confirm that the drive receives the intended reference.
  • Verify ready, running, and fault feedback.
  • Confirm actual frequency or speed reporting.
  • Test communication-loss behavior where applicable.
  • Verify alarm generation and fault-reset behavior.

19.4 Functional tests

  • Test start and normal stop.
  • Verify direction where applicable.
  • Check low-speed and normal-speed operation.
  • Verify acceleration and deceleration behavior.
  • Confirm motor current and load behavior are reasonable.
  • Test command-feedback timeouts.
  • Verify machine sequence coordination.
  • Confirm the approved response to faults and safety demands.
  • Record results and update the as-built documentation.

The test method must suit the machine and its hazards. Do not perform uncontrolled direction, speed, or stop tests on equipment with personnel or mechanisms exposed to risk.

20. VFD Troubleshooting

20.1 PLC run command ON, VFD not running

Check:

  • Selected drive command source.
  • Drive ready state.
  • Active faults and warnings.
  • Enable and permissive inputs.
  • Communication control ownership.
  • Terminal input assignment.
  • PLC output hardware and wiring.
  • Drive status word or terminal status.

20.2 VFD running, motor speed incorrect

Check:

  • PLC reference value.
  • Analog output configuration or network scaling.
  • Selected reference source.
  • Drive minimum and maximum limits.
  • Preset-speed selection.
  • Acceleration and deceleration ramps.
  • Actual frequency and speed feedback.
  • Motor and mechanical transmission characteristics.

20.3 VFD starts but trips during acceleration

Check:

  • Acceleration time.
  • Mechanical load and binding.
  • Motor nameplate data.
  • Current limit.
  • Motor cable and motor condition.
  • Drive sizing.
  • Selected control mode and tuning.

20.4 VFD stops unexpectedly

Check:

  • PLC run command and sequence state.
  • Drive fault history.
  • External fault input.
  • Communication status.
  • Supply conditions.
  • Overload or temperature conditions.
  • Interlocks and operating mode.
  • Drive restart configuration.

20.5 Drive keypad works but PLC commands do not

This often points toward command-source selection, interface configuration, or PLC-to-drive communication rather than an immediate motor fault.

Verify whether the drive is in local or remote mode, which source controls start/stop, which source provides the reference, and whether the PLC command is actually reaching the drive.

20.6 PLC command works but HMI speed is wrong

Check whether the HMI displays:

  • Requested speed.
  • PLC reference.
  • Drive output frequency.
  • Estimated motor speed.
  • Actual encoder speed.
  • Conveyor or machine speed after gearing.

These are different values. Tag naming and units should make the distinction clear.

21. Maintenance and Reliability

VFD maintenance should follow the manufacturer's instructions and the site's electrical safety procedures.

Useful maintenance activities include:

  • Inspect cooling fans and airflow paths.
  • Check for dust accumulation and contamination.
  • Inspect terminals and connections according to the approved procedure.
  • Review drive fault history.
  • Monitor current, temperature, and operating trends where available.
  • Verify parameter backups and configuration records.
  • Inspect motor and drive cooling.
  • Review recurring trips and load changes.
  • Confirm that spare drives and replacement models are compatible.
  • Document any changes to motor, drive, or PLC configuration.

VFD DC-link capacitors can retain hazardous energy after the supply is isolated. Follow the manufacturer's discharge waiting time and verify absence of voltage using an appropriate method before accessing the equipment.

Do not rely solely on a keypad display or status indicator to establish that a drive is electrically safe to work on.

22. Practical Exercise: Conveyor Speed Control

Design a PLC-VFD interface for a conveyor requiring automatic start, adjustable speed, running feedback, and fault reporting.

Required signals

Signal Direction Purpose
Conveyor_Run_Cmd PLC to VFD Requests operation
Conveyor_Speed_Ref PLC to VFD Requests target speed
VFD_Ready_FB VFD to PLC Reports drive availability
VFD_Running_FB VFD to PLC Reports running state
VFD_Fault_FB VFD to PLC Reports fault state
VFD_Actual_Frequency VFD to PLC Reports actual output frequency where available
Conveyor_Run_Request Internal PLC logic Represents the machine's operating request

Required behavior

  1. The PLC verifies the automatic mode and required permissives.
  2. The PLC confirms that the drive is available.
  3. The PLC sends the configured speed reference.
  4. The PLC issues the run command.
  5. The PLC verifies the expected running feedback.
  6. The sequence advances only when the required operating conditions are confirmed.
  7. A missing running signal generates a defined start-failure response.
  8. A drive fault inhibits further operation according to the machine design.
  9. A stop request produces the configured stopping behavior.
  10. A fault reset is allowed only under the approved recovery conditions.

Additional tests

  • Test the lowest permitted production speed.
  • Test the normal production speed.
  • Test speed-reference limits.
  • Disconnect or simulate loss of communication using an approved test method.
  • Verify fault alarm and recovery behavior.
  • Confirm that the HMI distinguishes commanded speed from actual speed.

23. Interview Questions and Answers

1. What is a VFD?

A VFD is a power-electronic drive that controls an AC motor by varying the frequency and appropriate voltage of the supplied power.

2. Why does a PLC control a VFD instead of switching the motor directly?

The PLC coordinates the machine sequence, while the VFD provides controlled motor operation, adjustable speed, and drive-specific monitoring and protection.

3. What is the difference between run command and running feedback?

The run command requests operation. Running feedback reports the drive's operating state according to its configured status definition.

4. What is the difference between command source and speed-reference source?

The command source determines where start/stop commands originate. The speed-reference source determines where the requested operating speed originates.

5. What is V/f control?

It is a scalar motor-control method that maintains a configured relationship between voltage and frequency to support motor operation over a range of speeds.

6. Why does an induction motor run below synchronous speed?

Under normal motoring operation, the rotor requires slip relative to the rotating magnetic field to produce torque.

7. What causes a VFD overcurrent trip during acceleration?

Possible causes include an aggressive acceleration ramp, excessive load, mechanical binding, incorrect motor data, wiring or motor faults, or inappropriate drive settings.

8. What causes DC-bus overvoltage during deceleration?

The load may return energy to the drive faster than the DC link can absorb or dissipate it. A short deceleration ramp is one possible cause.

9. Why might a VFD work from its keypad but not from the PLC?

The drive may be configured for a different command source, may not be in remote mode, or may have an incorrect hardwired or network interface configuration.

10. What is a speed-reference scaling problem?

It occurs when the PLC's numerical or analog reference does not correspond to the intended drive reference because the signal ranges, units, or mapping are configured incorrectly.

11. Why is actual frequency different from actual motor speed?

Frequency describes the drive's electrical output. Actual motor speed also depends on motor characteristics, slip, control method, and potentially feedback. Machine speed can differ further because of gearing.

12. What is STO?

Safe Torque Off is a drive safety function designed to prevent torque-producing operation according to its safety specification. It does not guarantee immediate stopping or electrical isolation.

13. Why is drive fault history useful?

It helps identify recurring conditions, timing, operating circumstances, and potential relationships between load, commands, and trips.

14. Why should a PLC verify running feedback after a start command?

Because the drive may reject the command, be faulted, lack a required enable, or fail to start the motor. Feedback confirms the reported operating state.

15. What should be checked before replacing a VFD?

Verify the actual fault, supply and motor circuit, drive configuration, load condition, PLC commands, communication, and parameter settings. Replacement should follow the approved equipment and configuration procedure.

24. Engineering Principles to Remember

  • The PLC requests operation; the VFD controls the motor according to its configuration.
  • A valid run command does not guarantee that the motor is running.
  • Command source and speed-reference source must be configured correctly.
  • Frequency, motor RPM, and machine speed are different quantities.
  • Confirm analog and network scaling rather than assuming the raw reference units.
  • Configure ramps and limits according to the motor, load, and process.
  • Use feedback and timeouts to detect unsuccessful operation.
  • Fault reset must not replace fault diagnosis.
  • Network communication health does not prove correct command mapping.
  • Normal stopping and safety-related stopping are different functions.
  • Preserve drive parameter backups and document all changes.
  • Follow electrical isolation and DC-link discharge procedures before servicing.
