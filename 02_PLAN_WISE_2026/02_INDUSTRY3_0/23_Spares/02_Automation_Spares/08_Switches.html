1. Definition and Purpose

An industrial network switch is a networking device that connects multiple Ethernet-enabled devices and forwards Ethernet frames between them according to their destination MAC addresses.

In industrial automation, switches connect PLCs, HMIs, SCADA computers, remote I/O adapters, VFDs, servo drives, robots, CNC machines, industrial PCs, and other networked equipment.

Industrial switches are designed for environments that may involve vibration, electrical noise, temperature variation, dust, and continuous operation. Their suitability depends on the actual product specifications and installation conditions.

Typical applications include:

  • PLC-to-PLC communication.
  • PLC-to-remote-I/O communication.
  • Robot, CNC, and drive connectivity.
  • HMI and SCADA network access.
  • Industrial PC and data-collection systems.
  • Segmentation of automation networks.
  • Redundant network paths where supported.
  • Connection between industrial Ethernet segments.

A switch can be a critical automation spare because its failure may interrupt communication with several machines or devices simultaneously.

2. Industrial Network Architecture

                 SCADA / Industrial PC
                           |
                     Core Switch
                    /     |      \
                   /      |       \
             PLC Network  HMI    Data Gateway
                |
          Industrial Switch
          /      |       \
        PLC    Robot    Remote I/O
         |
    Servo / VFD / CNC

This is a simplified example. Actual networks may use ring topologies, redundant links, separate VLANs, routed connections, or direct device connections.

A switch forwards Ethernet traffic within a network. It does not automatically translate PROFINET into EtherNet/IP or perform the routing functions of an IP router.

3. Switch Versus Hub Versus Router

Feature Ethernet hub Ethernet switch Router
Primary function Repeats incoming signals to connected ports Forwards frames using MAC addresses Routes packets between IP networks
Traffic handling Shared medium Selective forwarding Network-layer forwarding
Collision domains Shared Normally separated per switched port Separated by interfaces
Typical modern industrial use Legacy or specialized systems Common industrial Ethernet connectivity Connecting different IP networks
VLAN support No Available on managed switches Depends on router design
Protocol conversion No Normally no Normally no

Modern industrial Ethernet networks generally use switches rather than hubs.

A switch and a router may both appear in the same network architecture, but they solve different problems.

4. Industrial Switch Types

4.1 Unmanaged Switch

An unmanaged switch provides basic Ethernet connectivity without extensive user-configurable management functions.

Typical characteristics:

  • Simple installation.
  • Minimal configuration.
  • Basic link and activity indicators.
  • Limited diagnostic visibility.
  • Usually lower cost than comparable managed models.

It is suitable for small, stable networks where advanced diagnostics, VLANs, redundancy management, or detailed traffic monitoring are not required.

An unmanaged switch is not automatically unsuitable for industrial use. Its environmental ratings, port specifications, and performance must still match the application.

4.2 Managed Switch

A managed switch provides configurable networking and diagnostic functions.

Depending on the model, features may include:

  • VLAN configuration.
  • Port mirroring.
  • SNMP monitoring.
  • Quality of Service (QoS).
  • Access control.
  • Port statistics.
  • Network diagnostics.
  • Ring redundancy.
  • Rapid Spanning Tree Protocol (RSTP).
  • Time synchronization support.
  • Configuration backup and restoration.

Managed switches are useful when network visibility, fault isolation, segmentation, or redundancy is important.

4.3 Industrial PoE Switch

Power over Ethernet (PoE) allows compatible devices to receive power and data through an Ethernet cable.

Typical applications include supported industrial cameras, access points, and other networked devices.

Before selecting a PoE switch, verify:

  • Supported PoE standard.
  • Required voltage and power class.
  • Per-port power limit.
  • Total available PoE budget.
  • Cable and connector suitability.
  • Environmental rating.
  • Compatibility with the powered device.

A PoE port does not guarantee that every connected industrial device can be powered.

4.4 Fiber-Optic Industrial Switch

Fiber-optic Ethernet is useful where long cable distances, electrical isolation, or resistance to electromagnetic interference are important.

Advantages include:

  • Electrical isolation between fiber-connected endpoints.
  • Immunity to electromagnetic interference along the fiber.
  • Support for distances beyond typical copper Ethernet limits when the selected optical system permits.
  • Suitability for links between buildings, production areas, or electrically noisy sections.

The switch or transceiver must match the fiber type, connector, wavelength, optical budget, and required link distance.

4.5 Redundant-Ring Switch

Some industrial switches support ring-redundancy protocols that allow communication to continue after a supported link failure.

Examples of technologies include:

  • Media Redundancy Protocol (MRP).
  • Device Level Ring (DLR).
  • Ethernet Ring Protection Switching (ERPS).

These technologies are not interchangeable by default. The network devices and configuration must support the selected protocol.

5. Switch Hardware Components

An industrial switch may contain:

  • Ethernet switching ASIC or processor.
  • Copper Ethernet ports.
  • Fiber-optic interfaces or SFP slots.
  • Power-input terminals.
  • Power conversion and protection circuits.
  • Status LEDs.
  • Management interface.
  • DIN-rail or panel mounting hardware.
  • Cooling components, depending on design.
  • Alarm relay or digital diagnostic outputs on supported models.

Some industrial switches have redundant power inputs, while others have only one. Some models support external alarm contacts or configuration through a web interface, command-line interface, or network management software.

The exact specifications must be confirmed from the switch's model documentation.

6. Ethernet Ports and Link Speeds

Common Ethernet speeds include:

  • 10 Mbps.
  • 100 Mbps.
  • 1 Gbps.
  • Higher speeds on selected backbone or uplink equipment.

The supported speed depends on the specific switch port, connected device, cabling, and negotiated link settings.

A 100 Mbps device can normally connect to a compatible 10/100/1000 Mbps copper port, provided the physical interface and configuration support the connection. The negotiated speed is limited by the capabilities of both endpoints and the link.

Important specifications include:

Specification Why it matters
Number of ports Must accommodate the connected devices and planned expansion
Port speed Must meet device and traffic requirements
Copper or fiber Must match the installed cable and endpoint interface
SFP support Determines compatible modular optical or copper transceivers
Switching capacity Indicates the switch's internal forwarding capability
Forwarding rate Indicates packet-processing performance
MAC address table Limits how many source MAC addresses can be learned
Environmental rating Determines suitability for the installation environment
Power input Must match the available supply and redundancy arrangement
Mounting method Must suit the control panel or machine installation

Do not select a switch based only on port count. Industrial compatibility, redundancy, diagnostics, environmental limits, and protocol requirements may be more important.

7. MAC Addresses and Frame Forwarding

Ethernet switches learn source MAC addresses from incoming frames and associate those addresses with ports.

When a frame arrives, the switch checks its destination MAC address and uses its forwarding table to determine where to send it.

A simplified process is:

Ethernet Frame Arrives
        ↓
Learn Source MAC Address
        ↓
Check Destination MAC Address
        ↓
Destination Known?
   /             \
 Yes              No
  ↓                ↓
Forward to      Flood within
Known Port      Applicable VLAN

Flooding is normally limited to the relevant VLAN and excludes the port on which the frame arrived, subject to protocol-specific handling.

Switches also handle broadcast and multicast traffic according to their forwarding behavior and configured features.

7.1 MAC Address Table

A MAC address table records learned MAC addresses and their associated switch ports or VLANs.

Problems can arise when:

  • A device is disconnected or moved.
  • A loop causes MAC addresses to appear on unexpected ports.
  • The table reaches its supported capacity.
  • A device uses multiple MAC addresses.
  • Network topology changes cause relearning.

Managed switches often expose MAC-learning and port statistics that help diagnose these conditions.

8. Managed Switch Features

8.1 VLANs

A Virtual LAN (VLAN) logically separates Ethernet traffic into different Layer 2 broadcast domains.

For example:

Managed Industrial Switch
          |
          +-- VLAN 10: PLCs and Remote I/O
          |
          +-- VLAN 20: HMI and SCADA
          |
          +-- VLAN 30: Engineering Devices
          |
          +-- VLAN 40: Data Collection

This is only an example of network segmentation. VLAN IDs, membership, addressing, routing, and security policies must be designed for the actual plant.

VLANs can reduce unnecessary broadcast traffic and improve separation between network groups. However, VLANs alone do not provide complete cybersecurity or guarantee that one group cannot communicate with another. Routing and access-control policy also matter.

8.2 Port Mirroring

Port mirroring copies selected traffic to a designated monitoring port.

It can help with:

  • Diagnosing intermittent communication.
  • Inspecting protocol exchanges.
  • Identifying retransmissions or unexpected traffic.
  • Capturing data for a packet analyzer.

The monitoring computer and analyzer must be configured appropriately. Captures may contain sensitive process information or credentials, depending on the protocols in use.

8.3 Quality of Service

Quality of Service (QoS) prioritizes selected traffic according to configured rules.

It may help protect time-sensitive traffic when a network is congested, but it cannot compensate for fundamentally inadequate bandwidth, incorrect topology, or unsupported real-time requirements.

The actual effect depends on the switch's QoS implementation and configuration.

8.4 SNMP Monitoring

Simple Network Management Protocol (SNMP) allows compatible management systems to retrieve switch information and, where authorized, perform supported management operations.

Commonly monitored information includes:

  • Port status.
  • Link speed.
  • Traffic counters.
  • Error counters.
  • Device health.
  • Temperature or power information where exposed.
  • Redundancy status.
  • Alarms and events.

Use the security features supported by the equipment. Where available, prefer secure and appropriately authenticated management configurations rather than exposed legacy configurations.

8.5 Spanning Tree

Spanning Tree Protocol (STP) and Rapid Spanning Tree Protocol (RSTP) help prevent Layer 2 Ethernet loops by managing redundant paths.

An Ethernet loop can cause broadcast storms, repeated frames, unstable MAC learning, and widespread communication failures.

Do not disable loop-prevention features or change spanning-tree settings casually. Industrial redundancy schemes and managed topology must be configured according to the network design.

9. Industrial Network Redundancy

Redundancy provides an alternate communication path or device when a supported failure occurs.

Common approaches include:

  • Redundant ring links.
  • Dual-homing.
  • Redundant switches.
  • Redundant power inputs.
  • Controller-specific network redundancy.
  • Redundant uplinks.

Redundancy does not automatically guarantee uninterrupted communication. Recovery time, protocol support, topology, device compatibility, and configuration determine the actual behavior.

9.1 Ring Redundancy

A ring connects devices through a closed loop, while a redundancy mechanism prevents the loop from forwarding traffic indefinitely during normal operation.

If a supported link fails, the redundancy mechanism can activate an alternate path.

The recovery time depends on the protocol and implementation. Do not assume all ring protocols have the same recovery behavior.

9.2 Redundant Power Inputs

Some switches accept two independent power inputs. Depending on the design, the switch may continue operating if one input fails.

This does not protect against every possible failure. A common upstream supply failure, internal hardware fault, or incorrect wiring can still interrupt the switch.

Verify the manufacturer's power-input arrangement and alarm behavior.

10. Industrial Ethernet Protocol Considerations

Switch selection must account for the industrial protocol and its network requirements.

Technology Switch-related consideration
PROFINET Verify supported real-time features, topology, diagnostics, and redundancy requirements
EtherNet/IP Check network load, multicast behavior, QoS, and supported ring features where applicable
EtherCAT Confirm that the switch arrangement is supported by the EtherCAT topology and device requirements
Modbus TCP Verify link reliability, addressing, and network load
OPC UA Verify ordinary network connectivity and required security controls
General TCP/IP Check addressing, routing, congestion, and application requirements

Important: EtherCAT often relies on its own frame-processing architecture and commonly uses devices connected in a supported line, tree, or other specified topology. A conventional Ethernet switch must not be inserted into an EtherCAT path unless the EtherCAT master and network design explicitly support that arrangement.

Likewise, an industrial switch does not convert one automation protocol into another simply by connecting the devices.

11. Physical Installation and Wiring

Industrial switch reliability depends on installation quality.

11.1 Power Supply

Check:

  • Required input voltage and acceptable range.
  • Current consumption.
  • Polarity for DC inputs.
  • Protective grounding requirements.
  • Redundant input wiring, if provided.
  • Supply protection and conductor sizing.
  • Terminal tightness according to the manufacturer's specification.

Never assume every industrial switch uses the same DC voltage or terminal arrangement.

11.2 Copper Ethernet Cabling

Check:

  • Correct cable category and industrial rating.
  • Connector type and pinout.
  • Cable length limits.
  • Connector locking and strain relief.
  • Cable bend radius.
  • Routing near power cables and drives.
  • Oil, coolant, heat, and vibration exposure.

For conventional twisted-pair Ethernet, the common channel limit is 100 metres for many copper Ethernet implementations using suitable cabling and components. The actual permissible length depends on the Ethernet standard and installation design.

11.3 Fiber-Optic Connections

Check:

  • Single-mode or multimode fiber.
  • Correct optical transceiver.
  • Connector type.
  • Wavelength compatibility.
  • Optical power budget.
  • Transmit and receive polarity.
  • Cleanliness of optical connectors.

Never look directly into a fiber-optic transmitter or an exposed optical connector. Use suitable inspection and cleaning tools.

11.4 Mounting and Environment

Verify:

  • Operating temperature.
  • Ingress protection and enclosure requirements.
  • Vibration and shock limits.
  • Ventilation and heat dissipation.
  • DIN-rail or panel mounting.
  • Clearance for wiring and service.
  • Separation from high-energy electrical equipment where required.

A switch marketed for industrial use is not automatically suitable for every cabinet or outdoor installation.

13. Systematic Troubleshooting Procedure

13.1 Determine the Scope

Establish whether the fault affects one port, one switch, an entire network segment, or several interconnected segments.

If multiple unrelated devices fail at the same time, investigate shared infrastructure before replacing endpoint modules.

13.2 Check Power and Status

Inspect power indicators, alarm contacts where available, temperature conditions, and the switch's system status.

Verify that the actual supply voltage is within the model's specified range.

13.3 Check the Physical Link

Inspect the connected device's power, cable, connector, port status, and link speed.

Where authorized, use an approved known-good cable or spare port to isolate the fault. Record the original port and configuration before changing connections.

13.4 Review Managed-Switch Diagnostics

Where available, inspect:

  • Port up/down events.
  • Link speed and duplex.
  • Receive and transmit errors.
  • Discards and drops.
  • Broadcast and multicast counters.
  • MAC address learning.
  • VLAN membership.
  • Spanning-tree events.
  • Ring redundancy status.
  • Power and temperature alarms.

The exact diagnostic labels vary by manufacturer.

13.5 Check for Loops and Congestion

Unexpectedly high broadcast traffic, unstable MAC learning, or repeated topology changes may indicate a Layer 2 loop or an incorrectly configured redundant path.

Do not disconnect multiple links at random. Use the approved network diagram and diagnostic data to identify the affected segment.

13.6 Isolate and Verify

Determine whether the fault is associated with the switch, cable, endpoint, power source, or network configuration.

After corrective action, verify that all affected devices communicate correctly and that the network remains stable through the required production cycle.

14. Switch Replacement and Configuration Backup

Before replacing a managed switch, record the configuration and identify any protocol or topology dependencies.

A replacement may require:

  • Port speed and duplex settings.
  • VLAN configuration.
  • Trunk and access-port assignments.
  • Redundancy settings.
  • Management IP address.
  • SNMP configuration.
  • QoS rules.
  • Port security or access-control settings.
  • Alarm configuration.
  • Firmware and hardware compatibility.
  • Industrial protocol-specific features.

Replacement Procedure

  1. Identify the exact switch model, part number, and hardware revision.
  2. Determine whether the switch is managed or unmanaged.
  3. Record port-to-device connections and the network topology.
  4. Back up the managed-switch configuration where supported.
  5. Verify the replacement's environmental and electrical ratings.
  6. Confirm protocol, redundancy, and firmware compatibility.
  7. Obtain the required production approval and perform safe isolation where necessary.
  8. Replace the switch and restore the approved wiring and configuration.
  9. Verify link status, VLANs, addressing, and redundancy.
  10. Test affected PLCs, remote I/O, drives, robots, CNCs, and supervisory systems.
  11. Check network counters and confirm stable communication.
  12. Update the maintenance report and installed-base records.

Do not connect a replacement managed switch with a copied management IP address while the original device remains active on the same network. Duplicate addresses can create additional faults.

15. Cybersecurity Considerations

Industrial switches are part of the plant's operational technology (OT) network and can affect both communication reliability and security.

Good practices include:

  • Restrict management access to authorized systems.
  • Change default credentials according to approved procedures.
  • Use secure management protocols supported by the equipment.
  • Disable unused ports when appropriate and authorized.
  • Segment networks according to the approved OT architecture.
  • Restrict unnecessary communication between network zones.
  • Maintain configuration backups.
  • Control firmware changes.
  • Monitor relevant network events.
  • Document approved management addresses and access methods.

Do not connect a production OT switch directly to an external or corporate network without the approved architecture, routing, access control, and cybersecurity review.

VLANs alone are not a complete security boundary. Security depends on the combined design of switching, routing, firewalls, device configuration, and access controls.

16. Preventive Maintenance

Preventive maintenance should focus on the installed switch model, operating environment, and actual network risks.

Typical checks include:

  • Verify power and system status.
  • Inspect cable and connector condition.
  • Check port link status and speed.
  • Review error counters and communication alarms.
  • Inspect cabinet temperature and ventilation.
  • Verify grounding and mounting.
  • Check redundant power inputs where fitted.
  • Review ring or spanning-tree status.
  • Confirm configuration backup availability.
  • Verify the approved network diagram.
  • Check for unauthorized connections or configuration changes.
  • Review spare availability and obsolescence status.

Avoid unnecessary power cycling of production switches. Restarting a switch can interrupt multiple controllers and machines and may erase useful diagnostic evidence.

17.2 Choosing an Approved Alternate

Check more than the number of ports.

  • Electrical input range and redundancy.
  • Environmental and mounting requirements.
  • Copper and fiber interface compatibility.
  • Required port speeds.
  • Managed features and configuration.
  • VLAN and redundancy support.
  • Industrial protocol requirements.
  • Multicast and QoS behavior where relevant.
  • Firmware support.
  • Cybersecurity and management requirements.
  • Compatibility with the existing topology.

A replacement switch with the same number of ports can still be unsuitable if it lacks a required redundancy protocol, industrial feature, or environmental rating.

18. Practical Industrial Examples

18.1 Entire Robot Cell Loses Communication

Symptom: The PLC loses communication with a robot controller and several remote I/O devices connected through one switch.

Potential causes include switch power loss, uplink failure, a failed switch, or a network loop.

Start by checking whether the affected devices share the same switch or uplink. Review switch power and status, then inspect port and network diagnostics. Avoid replacing the robot controller before checking shared network infrastructure.

18.2 One Remote I/O Adapter Is Offline

Symptom: One remote I/O station is unavailable while other devices on the same switch continue operating.

Potential causes include a damaged cable, a failed switch port, adapter power loss, or incorrect device configuration.

Check the adapter and switch port indicators, then verify the physical connection and controller diagnostics. If an approved port test is required, record the original connection and ensure that VLAN and port configuration are preserved.

18.3 Communication Faults During Welding

Symptom: Intermittent network alarms occur during welding or high-current equipment operation.

Possible causes include electromagnetic interference, poor cable routing, grounding or bonding issues, damaged connectors, or supply disturbances.

Correlate the fault with equipment operation and inspect the network installation. Verify shield termination and cable selection against the manufacturer's requirements.

18.4 Production Data Collection Fails

Symptom: PLC control remains operational, but a SCADA or industrial PC stops receiving production data.

Possible causes include an uplink failure, VLAN misconfiguration, an application gateway issue, or a fault on the data-collection network.

Check the path between the data source and destination. Confirm switch port status and VLAN membership, then verify IP connectivity and application-level communication.

19. Common Mistakes

  • Treating an industrial switch as a protocol converter.
  • Assuming every industrial Ethernet protocol works through every topology.
  • Selecting a spare only by port count.
  • Ignoring fiber type and transceiver compatibility.
  • Treating link status as proof of application-level communication.
  • Changing VLAN or redundancy settings without an approved network plan.
  • Ignoring loops and broadcast storms.
  • Assuming redundant links automatically guarantee uninterrupted communication.
  • Failing to back up managed-switch configuration.
  • Connecting two switches with duplicate management IP addresses.
  • Power cycling switches before capturing diagnostic evidence.
  • Replacing endpoint hardware before checking shared network infrastructure.
  • Ignoring switch temperature, power, and environmental limits.
  • Connecting OT networks to other networks without approved security controls.
  • Failing to validate communication across all affected machines after replacement.

20. Interview Questions and Answers

Q1. What is the main function of an Ethernet switch?

It forwards Ethernet frames between connected devices using learned MAC addresses and the applicable forwarding rules.

Q2. What is the difference between a managed and unmanaged switch?

An unmanaged switch provides basic connectivity with limited configuration. A managed switch offers configurable functions and diagnostics such as VLANs, port statistics, mirroring, and supported redundancy features.

Q3. What is a VLAN?

A VLAN logically separates Ethernet traffic into distinct Layer 2 broadcast domains. Communication between VLANs generally requires routing or another explicitly configured Layer 3 function.

Q4. What is port mirroring?

Port mirroring copies selected network traffic to a monitoring port so that an engineer can inspect communication using suitable diagnostic tools.

Q5. What causes a broadcast storm?

A Layer 2 loop is a common cause. Excessive broadcast or multicast traffic can also arise from device behavior or network configuration problems.

Q6. Why can a switch failure affect several machines?

Multiple controllers, drives, robots, or remote I/O stations may depend on the same switch or uplink. Failure of that shared component can interrupt communication with all affected devices.

Q7. What is the purpose of industrial network redundancy?

It provides an alternate communication path or supported failover mechanism to improve network availability when a link or component fails.

Q8. Why are fiber-optic links used in industrial networks?

They provide electrical isolation along the fiber and are immune to electromagnetic interference on the optical transmission path. They can also support longer distances with suitable equipment.

Q9. How can an engineer distinguish a physical link fault from a protocol fault?

Check physical link indicators, cable condition, and port status first. If the physical link is healthy, inspect IP configuration, protocol connection status, device configuration, and application data exchange.

Q10. Why must a managed-switch configuration be backed up?

A backup preserves important settings such as VLANs, redundancy, management access, and port configuration, reducing restoration time and configuration errors after replacement.

21. Practical Competency Checklist

  • Explain the difference between a switch, hub, and router.
  • Identify managed, unmanaged, PoE, fiber, and redundant-ring switches.
  • Understand MAC addresses and frame forwarding.
  • Explain VLANs, port mirroring, QoS, and SNMP.
  • Understand industrial network redundancy and loop prevention.
  • Check copper and fiber interface compatibility.
  • Read switch status indicators and diagnostic counters.
  • Diagnose network-wide versus single-port faults.
  • Identify possible loops, congestion, and intermittent link problems.
  • Understand industrial Ethernet topology requirements.
  • Back up and restore managed-switch configuration.
  • Replace switches while preserving the approved network design.
  • Verify communication with all affected devices after repair.
  • Maintain a switch installed-base and critical-spares register.
  • Apply approved OT network security and change-control procedures.
