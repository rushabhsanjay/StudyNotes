1. Definition

As-built drawings are the controlled technical drawings updated to represent the equipment, installation, wiring, piping, instrumentation, mechanical arrangements, and other systems as they actually exist after approved changes during manufacturing, installation, commissioning, and testing.

They document the final installed configuration rather than merely showing what was originally designed.

In industrial automation, as-built documentation is essential because the delivered machine may differ from its initial design due to approved component substitutions, cable-routing changes, terminal modifications, sensor relocation, panel revisions, or commissioning adjustments.

The purpose is to ensure that maintenance engineers, automation engineers, electricians, and future project teams can understand the actual installed system without relying on assumptions or undocumented modifications.

Key principle: An as-built drawing must reflect the verified final condition. It must not simply be a copy of the original drawing with the revision number changed.

2. Purpose of As-Built Drawings

  • Document the final installed configuration of the machine or automation system.
  • Record approved changes made during manufacturing, installation, and commissioning.
  • Provide accurate references for troubleshooting, maintenance, and fault diagnosis.
  • Support safe isolation, electrical work, and equipment modifications.
  • Preserve traceability between installed hardware and engineering documentation.
  • Record actual cable routes, terminal connections, device locations, and interfaces where included in the drawing scope.
  • Support spare-parts identification and component replacement.
  • Provide a reliable baseline for future upgrades, retrofits, and migration projects.
  • Support technical handover from the project or supplier to the operating organization.
  • Reduce dependence on individual engineers' undocumented knowledge.

3. Design Drawings vs. Redline Drawings vs. As-Built Drawings

Document type Meaning Typical status
Design drawing Represents the intended design Approved design baseline
Issued-for-construction drawing Defines the configuration authorized for construction or installation Controlled construction issue
Redline drawing Marks observed changes or corrections against an existing drawing Working record awaiting review or incorporation
As-built drawing Represents the verified final installed condition Controlled final record
Record drawing A drawing maintained as a record of the completed installation Meaning depends on project terminology and contractual definition

The terms as-built and record drawing are sometimes used interchangeably. Their exact meanings must be established by the project's document-control procedure.

A redline is not automatically an approved as-built drawing. Changes must be reviewed, validated, and incorporated into the controlled final document.

The project scope determines which drawings are required. An as-built package may also include updated PLC I/O lists, network schedules, equipment registers, and other controlled technical records even when they are not formally classified as drawings.

5. Information That Must Be Updated

An as-built drawing should capture all applicable changes that affect the accuracy, safety, operation, maintenance, or traceability of the system.

Electrical changes

  • Cable numbers and cable destinations.
  • Terminal assignments and wire connections.
  • Breaker, fuse, overload, and protective-device details.
  • Control-circuit modifications.
  • Power-supply ratings and distribution details.
  • Earthing and bonding arrangements.
  • Panel components and their installed locations.
  • Approved changes to safety-related circuits.

Automation changes

  • PLC input and output assignments.
  • Remote I/O module arrangement.
  • PLC, HMI, and drive identifiers.
  • Network device connections and topology.
  • Communication interfaces.
  • Installed sensor and actuator tags.
  • Approved hardware substitutions.
  • Cross-references between device tags and electrical drawings.

Mechanical and utility changes

  • Actual machine and component locations.
  • Sensor and actuator mounting positions.
  • Pipe, hose, and pneumatic connections.
  • Approved fixture or bracket modifications.
  • Utility connection points.
  • Cable-tray and conduit routing where included in the drawing scope.

Not every parameter belongs on a drawing. For example, a VFD's full parameter set may be maintained in a controlled parameter backup, while the electrical drawing shows the drive's connections, ratings, identification, and relevant interfaces.

6. Revision Control and Document Identification

Every controlled as-built drawing should have sufficient identification to prevent confusion between obsolete, working, and current versions.

Common document-control fields include:

Field Purpose
PROJECT_ID Identifies the project
MACHINE_ID Identifies the machine or station
DRAWING_NUMBER Unique drawing identifier
DRAWING_TITLE Describes the drawing content
REVISION Identifies the document revision
DOCUMENT_STATUS Identifies the approved document state
DRAWN_BY Person who prepared the drawing
CHECKED_BY Person who checked technical accuracy
APPROVED_BY Authorized approver
ISSUE_DATE Date of the controlled issue
CHANGE_DESCRIPTION Summary of the changes
RELATED_DOCUMENTS Links to associated drawings or records
SOFTWARE_OR_HARDWARE_REFERENCE Relevant configuration reference where applicable

The actual field names and approval workflow depend on the organization's document-control system.

Example revision history

Revision Change description Status
A Initial approved electrical design Approved design
B Approved addition of a remote I/O module Revised design
C Final field wiring and terminal changes incorporated As-built candidate
C Verified final configuration and authorized release Controlled final issue

The repeated revision C above represents the same revision progressing through different workflow states, not two separate revision releases. In an actual register, maintain distinct status and approval records so that the document's history remains unambiguous.

7. As-Built Drawing Preparation Workflow

Approved Design Baseline
        ↓
Manufacturing / Installation / Commissioning
        ↓
Identify Actual Changes
        ↓
Mark Redlines and Collect Field Evidence
        ↓
Review Approved Change Records
        ↓
Verify Installed Configuration
        ↓
Update CAD Drawings and Related Registers
        ↓
Independent Technical Check
        ↓
Approval and Document Control
        ↓
Release Controlled As-Built Package
        ↓
Handover and Archive

Step 1: Establish the baseline

Identify the latest approved drawings and confirm their document numbers and revisions.

Do not begin updating drawings using an uncontrolled printout when a newer approved revision may exist.

Step 2: Collect change information

Gather approved engineering change requests, site redlines, inspection records, wiring changes, equipment substitutions, and commissioning records.

Step 3: Verify the actual installation

Compare the installed configuration with the drawings. Inspect actual terminal connections, component identification, routing, and equipment locations as applicable.

Never assume that a marked change was implemented exactly as intended.

Step 4: Update the drawings

Incorporate verified changes using the organization's approved CAD software, templates, symbols, layers, title blocks, and revision conventions.

Step 5: Perform a technical check

Check that the drawings are internally consistent and match the installed equipment. Review cross-references, cable identifiers, terminal numbers, component tags, and associated schedules.

Step 6: Obtain approval

Route the updated drawings through the required technical review and approval process.

Step 7: Release the controlled version

Issue the approved files in the required formats, such as PDF and native CAD, according to the project requirements.

Step 8: Archive and hand over

Store the controlled drawings in the designated document repository and link them to the machine, project, and relevant equipment records.

8. Electrical As-Built Verification Example

Consider an automation panel with a PLC, remote I/O, a pressure sensor, and a pneumatic valve.

The original drawing identifies the pressure sensor as PT-101, connected to remote analog input channel AI-02.

During commissioning, the sensor is moved to another approved input channel because of a hardware configuration change.

The as-built process must verify and document all affected records, including:

  • Actual field wiring and terminal assignments.
  • Remote I/O module and channel identification.
  • PLC input mapping and relevant signal descriptions.
  • Updated electrical schematic and terminal plan.
  • Updated I/O list and equipment register, where applicable.
  • Relevant software or configuration revision records.

Updating only the drawing while leaving the I/O list incorrect would create a documentation inconsistency. Updating only the PLC program while leaving the drawings incorrect would create a different one.

The objective is to maintain consistency across all records that describe the installed system.

9. As-Built Drawings and Software Configuration

For automated equipment, the physical drawings and software configuration must agree wherever they describe related functions.

Relevant records may include:

  • PLC source project and installed program revision.
  • HMI application and screen configuration.
  • VFD and servo parameter backups.
  • Robot programs and configuration files.
  • CNC parameters and machine-builder configuration.
  • Industrial network topology and device addressing.
  • Firmware versions and hardware identifiers.
  • Safety PLC or safety-relay configuration records, where applicable.
  • Password, access, and recovery procedures handled through approved secure channels.

As-built drawings do not replace these records. They describe the physical and electrical configuration, while software backups preserve the relevant programmable configuration.

Where a software change affects wiring, I/O assignments, safety behavior, or system interfaces, the applicable drawings, registers, test records, and software baselines must be reconciled.

11. As-Built Drawing Quality Checklist

  • The latest approved design baseline has been identified.
  • Actual installed changes have been collected and verified.
  • All applicable redlines have been reviewed and incorporated.
  • Equipment tags and component identifiers match the installation.
  • Cable numbers, terminal assignments, and connection details are correct.
  • Relevant PLC I/O assignments and network connections are consistent.
  • Mechanical, pneumatic, hydraulic, and utility drawings are updated where applicable.
  • Approved component substitutions are documented.
  • Safety-related modifications have undergone the required review and validation.
  • Related schedules and technical registers are consistent with the drawings.
  • Revision history and change descriptions are complete.
  • Required technical checking and approvals are recorded.
  • Controlled PDF and native drawing files are included where required.
  • Superseded revisions are controlled to prevent accidental use.
  • The final package is stored in the approved repository.
  • The document register and handover checklist are updated.

12. As-Built Drawing Register

A master register helps verify that the complete required drawing package has been delivered.

Field Purpose
DRAWING_NUMBER Unique drawing identifier
DRAWING_TITLE Drawing description
SYSTEM Electrical, mechanical, pneumatic, network, or other system
MACHINE_ID Associated machine
REQUIRED Indicates whether the document is required
CURRENT_REVISION Latest controlled revision
AS_BUILT_STATUS Not started, in progress, checked, or approved
REDLINE_STATUS Indicates outstanding redline work
APPROVAL_STATUS Indicates review and approval state
FILE_LOCATION Controlled repository reference
NATIVE_FILE_AVAILABLE Indicates whether the required editable file is present
HANDOVER_STATUS Indicates whether the drawing has been delivered
REMARKS Outstanding issues or document-specific notes

For a larger plant, the register can be filtered by machine, system, drawing category, revision, and handover status. Automated validation can flag missing documents, unresolved redlines, inconsistent revisions, and files awaiting approval.

13. Standards and Engineering Practices

The applicable requirements depend on the system, industry, country, contract, and organization.

Relevant frameworks may include:

  • IEC 61082-1: Preparation of documents used in electrotechnology.
  • IEC 81346 series: Structuring principles and reference designations for industrial systems and equipment.
  • IEC 60204-1: Electrical equipment of machines.
  • ISO 7200: Data fields in title blocks and document headers.
  • ISO 9001: Documented information and control of relevant quality-management records.
  • Project-specific CAD standards: Drawing formats, layers, symbols, title blocks, and revision practices.
  • Site engineering procedures: Change management, technical approval, and handover requirements.

These references are not interchangeable, and their applicability must be confirmed for the project. An as-built drawing's validity also depends on accurate field verification, controlled revision, and authorized release, not merely on following a drawing standard.

14. Final Handover Acceptance Checklist

  • All required as-built drawings are included in the document register.
  • Drawings reflect the verified final installed configuration.
  • Approved changes and substitutions are documented.
  • Redlines have been incorporated or formally dispositioned.
  • Related cable schedules, I/O lists, and equipment registers are consistent.
  • Required technical reviews and approvals are complete.
  • Native and PDF files are delivered according to the contract.
  • Current revisions are clearly identified.
  • Superseded versions are controlled.
  • Files are stored in the designated repository.
  • Relevant software backups and configuration records are included as separate deliverables where required.
  • Outstanding documentation gaps are recorded and managed through the approved acceptance process.
  • The final document package is formally handed over.

Final principle: As-built drawings establish the verified technical record of the installed system. Their value lies in accuracy, traceability, revision control, and consistency with the actual equipment. A drawing package is not complete simply because every file exists; the files must describe the system that is actually present.
