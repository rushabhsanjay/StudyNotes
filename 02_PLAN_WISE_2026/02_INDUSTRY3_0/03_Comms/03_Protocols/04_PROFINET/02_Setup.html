1. Purpose and scope

PROFINET setup involves configuring the controller, identifying each field device, assigning network parameters, describing device capabilities in the engineering project, and establishing the correct input/output data exchange.

The three central elements are:

  • Device name: Identifies the PROFINET station within the automation system.
  • IP address: Provides network-layer addressing for IP-based communication and engineering services.
  • GSDML file: Describes the device's capabilities and configuration options to compatible engineering software.

A device can have a working Ethernet link and still fail to establish its expected PROFINET IO relationship. Correct physical connectivity, device identity, IP configuration, hardware configuration, and process-data mapping must all be considered separately.

This topic focuses on PROFINET IO commissioning, particularly in Siemens TIA Portal and STEP 7-based industrial automation environments. Exact procedures depend on the PLC, engineering-software version, device model, and firmware.

During commissioning, the engineering workstation discovers or accesses devices, assigns or verifies their identity and network settings, and downloads the controller configuration as required.

During operation, the controller establishes the configured communication relationships and exchanges process data with the devices.

3. Understand the three main configuration elements

Element Main purpose Typical failure if incorrect
Device name Identifies the intended PROFINET device Controller cannot establish the expected IO relationship
IP address Enables IP-based communication and services Engineering access or other IP communication fails
GSDML Describes the device to the engineering tool Device missing from catalog or incorrect configuration options
Hardware configuration Defines the expected devices and modules Device or module configuration mismatch
I/O mapping Assigns process data to controller addresses PLC reads or writes the wrong data
Ethernet connection Carries communication traffic Link failure, packet errors, or unreachable devices

These elements are related but not interchangeable. Changing an IP address does not automatically correct a device-name mismatch, and installing a GSDML file does not assign a physical device its name or configure its IP address.

4. PROFINET device name

4.1 What is a device name?

A PROFINET device name is a configured identifier used to identify a device in the PROFINET IO system. It is an important part of the relationship between the controller's hardware configuration and the actual field device.

Example device names might be:

  • remoteio_line1
  • drive_conveyor1
  • valve_terminal2

These are illustrative names, not necessarily suitable for every device or project. The allowed character set, syntax, and naming constraints must follow the applicable PROFINET specification and engineering tool.

A useful plant naming convention reflects the device's function or location while remaining unique within the relevant network.

4.2 Why the device name matters

Suppose the PLC project expects a remote I/O device named remoteio_line1, but the physical device is configured as remoteio_line2.

Even if the device is powered and its Ethernet link is active, the controller may fail to establish the intended IO relationship because the device identity does not match the expected configuration.

The correct procedure is to compare the expected project name with the actual name stored in the device, then correct the discrepancy through an approved commissioning process.

4.3 Device name versus hostname

The PROFINET device name is not automatically identical in purpose to every hostname or label used by the operating system, DNS, or engineering workstation.

A device may have several identifiers:

Identifier Purpose
PROFINET device name Identifies the PROFINET station for the IO system
IP address Identifies the device at the IP layer
MAC address Identifies the Ethernet interface at the data-link layer
DNS hostname Provides a name-to-IP mapping where DNS is used
Engineering project tag Human-readable identifier used in the automation project

Some names may be configured to match by convention, but they should not be assumed to be the same parameter.

4.4 Assigning or changing a device name

A typical commissioning sequence is:

  1. Identify the physical device and its Ethernet interface.
  2. Open the engineering tool's supported online device-discovery or accessible-device function.
  3. Confirm the intended device using available identity information, such as MAC address, model, and physical port.
  4. Compare its current name with the expected name in the project.
  5. Assign the approved name using the supported device-naming function.
  6. Verify that the device now reports the intended name.
  7. Check whether the controller establishes the configured IO relationship.

The exact menu and assignment procedure vary by engineering software and device. Some devices support alternative commissioning methods, so use the manufacturer's documentation.

Critical maintenance rule: Identify the physical device before assigning a name. Accidentally assigning the name to a different device can create a confusing fault that appears to be a controller or network problem.

5. IP addressing

5.1 What is an IP address?

An IP address identifies a network interface at the Internet Protocol layer. PROFINET devices commonly use IPv4 addressing for engineering access, diagnostics, and other IP-based services.

A typical IPv4 address consists of four decimal octets:

192.168.10.21

Each octet ranges from 0 to 255, subject to the rules governing usable addresses and special-purpose ranges.

An IP address is not the same as the PROFINET device name or MAC address.

5.2 IP address, subnet mask, and default gateway

Parameter Purpose Example
IP address Identifies the interface at the IP layer 192.168.10.21
Subnet mask Defines which IPv4 addresses are considered part of the local subnet 255.255.255.0
Default gateway Provides a next-hop router for traffic destined outside the local subnet 192.168.10.1
MAC address Identifies the Ethernet interface on the local Ethernet link Device-specific hardware address

These example values are for illustration only. Use the approved plant network plan rather than copying example addresses into production equipment.

5.3 Understanding the subnet

For a common subnet mask of 255.255.255.0, the first three octets identify the network portion and the final octet identifies the host portion.

For example:

  • Engineering PC: 192.168.10.100
  • PLC: 192.168.10.1
  • Remote I/O: 192.168.10.21
  • Subnet mask: 255.255.255.0

These addresses are in the same IPv4 subnet under this mask. They can normally communicate directly at the IP layer if the interfaces are connected correctly and no other configuration or security issue prevents communication.

Two devices using the same IP address can create an address conflict. Symptoms may include intermittent reachability, failed engineering access, or communication going to the wrong interface.

5.4 Default gateway in an industrial network

A default gateway is generally used when communication must reach destinations outside the device's local IP subnet.

A simple isolated machine network may not require a default gateway for local controller-to-device communication. A routed or integrated network may require one for approved services.

Do not enter a gateway address merely because the configuration form offers the field. Follow the plant's network design and cybersecurity requirements.

5.5 Device name and IP address: the practical difference

Consider a remote I/O station:

  • Its PROFINET device name is remoteio_line1.
  • Its IP address is 192.168.10.21.
  • Its MAC address is specific to its Ethernet interface.

If the IP address is changed, the device name does not necessarily change. If the device name is changed, the IP address does not automatically become correct for the network.

This distinction matters when diagnosing a device that is discoverable at Ethernet level but does not establish the expected IO relationship.

5.6 Avoid duplicate IP addresses

Before assigning an IP address:

  1. Consult the approved address register.
  2. Verify that the address is intended for the specific device.
  3. Check for an existing device using that address through approved network tools.
  4. Confirm the subnet mask and any required gateway.
  5. Apply the configuration using the supported commissioning procedure.
  6. Verify reachability and controller communication afterward.

A failed ping does not prove that an IP address is unused. A device may block ICMP, be temporarily offline, or exist on a network segment that the test cannot reach. Use the plant's approved discovery and address-management process.

6. GSDML files

6.1 What does GSDML mean?

GSDML is the XML-based description language used for PROFINET device descriptions. A GSDML file allows compatible engineering software to understand a device's supported functions and configuration options.

GSDML is the PROFINET counterpart to the GSD device-description approach used by PROFIBUS, but the file formats and described capabilities differ.

A GSDML file commonly has an .xml extension and may be supplied alongside associated graphics or other files by the manufacturer.

6.2 What information can GSDML describe?

Depending on the device, its description can include:

  • Manufacturer and device identification.
  • Supported device and interface characteristics.
  • Module and submodule choices.
  • Input and output data structures.
  • Process-data lengths.
  • Supported parameters and configuration options.
  • Diagnostic capabilities.
  • Port and topology-related properties.
  • Device-related configuration constraints.

The file describes the device to the engineering environment. It does not replace device firmware, assign the device's physical name, or automatically make an unsupported feature available.

6.3 When is a GSDML file needed?

A GSDML file is commonly required when the engineering software does not already contain a suitable device description in its hardware catalog.

For example, a third-party PROFINET valve terminal may need its manufacturer's GSDML file installed before it can be configured with the correct module and process-data layout.

Some devices are supported through built-in catalog entries or other vendor-provided integration methods. Do not assume every device requires a separate manual GSDML installation.

6.4 How to identify the correct GSDML file

Before installation, verify:

  • Exact manufacturer and product family.
  • Device model and supported revision.
  • Compatible engineering-software version.
  • GSDML version and publication information.
  • Required associated files.
  • Whether the installed firmware is supported.
  • Whether the device's modules and process-data options match the intended application.

Use the manufacturer's official support portal or an approved plant engineering repository. Avoid choosing a file based only on a similar product name.

6.5 Installing GSDML

The exact menu names depend on the engineering software and version. A typical process is:

  1. Obtain the correct GSDML package from an approved source.
  2. Check its compatibility with the installed engineering tool.
  3. Open the hardware-configuration environment.
  4. Use the supported GSDML installation or import function.
  5. Install any associated files supplied by the manufacturer.
  6. Refresh or reopen the hardware catalog if required.
  7. Locate the device in the catalog.
  8. Add it to the project and configure its modules.
  9. Compile the project and review configuration messages.

Installation adds a device description to the engineering environment. It does not configure the physical device automatically.

6.6 GSDML versus firmware

GSDML Firmware
Describes device capabilities to engineering software Runs on the actual device
Helps define available modules, parameters, and process data Implements device behavior and communication functions
Installed or imported into the engineering environment Installed or updated on the hardware
Does not repair faulty device firmware Does not automatically update the engineering catalog

Using a new GSDML file does not necessarily require a firmware update. Conversely, updating firmware does not necessarily install the corresponding device description in the engineering tool. Follow the manufacturer's compatibility guidance.

7. Configuring PROFINET in Siemens TIA Portal

The following is a typical workflow. The precise interface and available options depend on the TIA Portal version, CPU, network interface, device family, and installed hardware support.

7.1 Step-by-step setup

  1. Open the existing project. Confirm the PLC model, firmware, communication interface, and current hardware configuration.
  2. Back up the project. Preserve the current configuration before making changes.
  3. Install GSDML if needed. Use the supported device-description installation function and verify that the device appears in the catalog.
  4. Add or identify the IO Device. Select the correct manufacturer and model.
  5. Connect the device to the PROFINET network. Assign it to the intended controller and network interface.
  6. Configure the device modules. Select the modules or submodules that match the installed hardware.
  7. Review I/O addresses. Verify input and output data lengths, address ranges, and program references.
  8. Configure the intended network parameters. Set or verify the device name and IP configuration according to the plant's address plan.
  9. Compile the project. Resolve relevant errors and review warnings.
  10. Discover the physical device online. Confirm the actual hardware identity and current network parameters.
  11. Assign or verify the device name. Ensure the physical device matches the intended project configuration.
  12. Download the required configuration under controlled conditions. Follow the site's authorization and safe-state procedures.
  13. Verify online diagnostics. Confirm that the device establishes the expected IO relationship and that process data is valid.

The order of device naming, IP assignment, and downloading can vary by device and engineering workflow. Follow the documented commissioning method for the specific equipment rather than treating this sequence as universal.

7.2 Hardware catalog versus online device discovery

These two functions solve different problems.

  • The hardware catalog tells the engineering software which devices and modules it can configure in the project.
  • Online device discovery helps identify actual network devices and inspect or assign supported network parameters.

A device can be visible in online discovery but absent from the engineering catalog. In that case, the engineer may need to install the correct GSDML file or use another supported integration method.

Conversely, a device can appear in the hardware catalog even when no physical device is connected.

7.3 Downloading the configuration

Before downloading:

  • Verify the target PLC and network.
  • Confirm that the project represents the installed hardware.
  • Check for unintended changes to I/O mapping.
  • Review whether the download could affect machine operation.
  • Follow the plant's authorization, change-control, and safety procedures.
  • Preserve a recoverable version of the existing project.

After downloading, confirm the actual online state. A successful download alone does not prove that every field device is correctly named, reachable, or exchanging valid process data.

8. Example: configuring a PROFINET remote I/O station

Assume a PLC controls a machine through a remote I/O station and a variable-frequency drive.

Parameter PLC Remote I/O Drive
Role IO Controller IO Device IO Device
Example device name Not applicable as a slave name remoteio_line1 drive_conveyor1
Example IP address 192.168.10.1 192.168.10.21 192.168.10.31
Device description PLC hardware support Matching GSDML or built-in catalog support Matching GSDML or built-in catalog support
Process data Reads and writes configured I/O Sensor inputs and actuator outputs Drive commands and status data

All addresses and names are illustrative. A real installation must follow the approved network plan.

8.1 Commissioning procedure

  1. Identify the PLC interface and confirm that it supports the required PROFINET configuration.
  2. Confirm the remote I/O model, installed modules, and firmware.
  3. Install the correct GSDML if required.
  4. Add the remote I/O to the PLC hardware configuration.
  5. Select modules matching the physical station.
  6. Assign the planned I/O addresses.
  7. Set or verify the intended device name and IP configuration.
  8. Discover the physical station and confirm its identity.
  9. Download the approved configuration using the correct engineering workflow.
  10. Confirm that the controller establishes the IO relationship.
  11. Verify input values and output behavior using the approved commissioning procedure.
  12. Save the final project and update the network and device inventory.

8.2 Example of a name mismatch

Suppose the project expects remoteio_line1, but the physical device is named remoteio_line2.

The appropriate approach is to:

  1. Confirm the intended device using its MAC address, model, physical location, and switch connection.
  2. Verify the name expected by the project.
  3. Confirm that no other device should use the intended name.
  4. Assign the correct name through the supported commissioning tool.
  5. Verify the device identity and controller diagnostics.
  6. Confirm normal process-data exchange.

Do not change names on every discovered device to make them match a project without first establishing which physical device corresponds to each project entry.

9. Common setup faults

Symptom Possible cause First check
Device has no Ethernet link Cable, connector, port, device power, or hardware fault Check power and physical link indicators
Device is discoverable but the controller reports it missing Device-name mismatch, controller configuration issue, or unsupported configuration Compare the actual name with the configured project
Device name is correct but engineering access fails IP configuration, subnet, duplicate IP, routing, or access restrictions Verify IP settings and network reachability
Device is missing from the hardware catalog GSDML not installed or device unsupported by the engineering version Check the official device description and software compatibility
Configuration compile fails Incorrect module selection, incompatible device support, or invalid parameters Compare the project with the device manual
Device is online but module diagnostics are active Module arrangement, channel fault, parameters, or field wiring Inspect detailed module and channel diagnostics
Device name was assigned to the wrong physical unit Incorrect device identification during commissioning Verify MAC address, model, location, and switch port
Device communicates but PLC values are wrong Incorrect I/O mapping, data layout, data type, or scaling Compare the project configuration with the actual device
Device became inaccessible after an IP change Incorrect subnet, duplicate IP, or loss of the known access address Verify the current address through the approved discovery method

These are diagnostic starting points, not guaranteed root causes. Use the controller's diagnostic information and the actual device documentation to confirm the fault.

10. Configuration management and maintenance

PROFINET configuration is part of the machine's controlled engineering baseline. A replacement device or a small naming change can affect commissioning and diagnostics.

Maintain a device register with fields such as:

Field Purpose
Machine and location Identifies where the device is installed
Device tag Links the physical equipment to drawings and PLC logic
Manufacturer and model Identifies the hardware
MAC address Helps distinguish the physical Ethernet interface
PROFINET device name Records the configured device identity
IP address and subnet Records network configuration
GSDML version Identifies the device-description version used
Firmware version Records the installed device software
I/O configuration Documents module selection and process-data mapping
Engineering project version Identifies the approved configuration baseline
Change record Documents modifications and verification

For maintenance and retrofits, this information reduces the risk of installing an incompatible replacement, assigning an incorrect identity, or unintentionally changing PLC data mapping.

11. Safety and cybersecurity considerations

  • Do not change device names, IP addresses, or hardware configuration on a running machine without authorization and an impact assessment.
  • Back up the project and relevant device parameters before changes.
  • Use the approved network address register to avoid duplicate IP addresses.
  • Restrict engineering access to authorized personnel and approved workstations.
  • Follow plant network segmentation and firewall policies.
  • Verify the device's actual identity before writing configuration to it.
  • Use approved firmware and device-description files.
  • Test the required machine interlocks and operating behavior before returning equipment to production.

An Ethernet connection or successful device discovery does not prove that a machine is safe to operate.

12. Interview questions and answers

Q1. What is the purpose of a PROFINET device name?

It identifies a PROFINET device within the configured IO system and is important for establishing the expected controller-device relationship.

Q2. What is the difference between a device name and an IP address?

The device name identifies the PROFINET station, while the IP address provides network-layer addressing for IP-based services. They serve different purposes.

Q3. What is GSDML?

GSDML is an XML-based device-description format that allows compatible engineering software to represent and configure PROFINET devices.

Q4. Does installing GSDML assign the device's IP address?

No. Installing GSDML makes the device description available to the engineering environment. The actual device's network parameters must be configured separately using a supported method.

Q5. Can a device have an Ethernet link but still be offline in the PLC?

Yes. Physical link status does not prove correct device identity, successful IO relationship establishment, or valid process-data exchange.

Q6. What happens if two devices use the same IP address?

An IP conflict can cause intermittent reachability or traffic to reach the wrong interface. The address plan and actual network configuration must be checked.

Q7. Is the MAC address the same as the PROFINET device name?

No. The MAC address identifies the Ethernet interface at the data-link layer, while the PROFINET device name identifies the station in the PROFINET configuration.

Q8. Why might a device be visible online but missing from the hardware catalog?

The engineering tool may not contain a suitable device description. Installing the correct GSDML or using another supported integration method may resolve the catalog limitation.

Q9. Does a newer GSDML file update the device firmware?

No. GSDML is a description used by the engineering environment. Firmware is software installed on the physical device.

Q10. What must be checked after configuring a PROFINET device?

Verify the device identity, network configuration, controller diagnostics, module configuration, I/O mapping, and actual process-data behavior.

13. Practical exercises

  1. Device inventory: Select one PROFINET remote I/O station and record its model, MAC address, device name, IP address, firmware, and physical location.
  2. Project comparison: Compare the actual device name and network settings with the approved engineering project.
  3. GSDML review: Identify the device description used by an installed third-party device and record its version and compatibility information.
  4. I/O trace: Follow one sensor input from the physical terminal through the remote I/O module and PLC address to the program logic.
  5. Address-plan review: Verify that the selected device IP address and subnet are consistent with the approved machine network plan.
  6. Diagnostic exercise: Using a training device or approved online session, distinguish between physical link status, device identity, and the controller's IO relationship status.
  7. Change-control exercise: Document the checks required before replacing a remote I/O station with a compatible unit.

Do not deliberately create IP conflicts, rename live devices, or change production network settings for practice. Use an offline project or an approved training setup.

14. Final mental model

  • Device name: Identifies the PROFINET station expected by the controller.
  • IP address: Provides IP-layer addressing for relevant network services.
  • MAC address: Identifies the Ethernet interface.
  • GSDML: Describes device capabilities to the engineering software.
  • Hardware configuration: Defines the expected device, modules, and communication relationship.
  • I/O mapping: Determines how process data appears in the PLC program.
  • Online diagnostics: Confirm whether the configured communication relationship is operating correctly.

A correct PROFINET setup requires the physical device, network identity, engineering description, controller configuration, and PLC application to agree. A successful cable link is only the first checkpoint.
