1. Purpose and scope

PROFINET is an industrial Ethernet communication standard used to connect PLCs, remote I/O, drives, sensors, actuators, robots, and other automation devices.

It supports cyclic real-time process-data exchange, device configuration, diagnostics, and communication with higher-level systems. It is widely used in modern industrial automation systems, particularly in Siemens-based installations, while also supporting devices from many other manufacturers.

The main concepts in this topic are:

  • Ethernet-based communication: PROFINET uses industrial Ethernet technology rather than the RS-485 physical layer used by PROFIBUS DP.
  • IO Controller: Usually the PLC that controls the PROFINET I/O system.
  • IO Device: A field device that exchanges process data with the controller.
  • IO Supervisor: An engineering or diagnostic system used to configure, monitor, and troubleshoot devices.
  • Real-time communication: Time-sensitive cyclic exchange of input and output data.
  • Device identity and configuration: The controller must recognize and configure the intended device.
  • Diagnostics: Devices can report communication faults, module errors, channel faults, and other conditions.

This topic explains the architecture and operating principles. Detailed device naming, IP configuration, and GSDML installation belong to the next topic.

2. What is PROFINET?

PROFINET stands for Process Field Network. It is an industrial communication standard maintained by PROFIBUS & PROFINET International (PI).

It builds on Ethernet technology but adds industrial automation functions such as:

  • Cyclic process-data exchange between controllers and devices.
  • Real-time communication for time-sensitive automation.
  • Device discovery, identification, and configuration.
  • Standardized device descriptions.
  • Diagnostics and maintenance information.
  • Integration with drives, distributed I/O, and other automation equipment.
  • Support for network topologies such as line, star, and ring, depending on the devices and network design.

PROFINET is not simply ordinary office Ethernet with a different cable color. It uses Ethernet infrastructure and protocols together with industrial communication mechanisms designed for automation.

3. PROFINET architecture

A typical PROFINET system contains a controller, field devices, Ethernet connections, and an engineering or diagnostic system.

3.1 Main roles

Role Meaning Typical example
IO Controller Controls the PROFINET I/O system and exchanges cyclic process data PLC
IO Device Provides input/output data to a controller or receives output data from it Remote I/O, drive, valve terminal
IO Supervisor Performs engineering, commissioning, monitoring, or diagnostics Engineering laptop or maintenance workstation

These are communication roles, not necessarily separate physical computers. A single device can support multiple communication functions, depending on its design and the PROFINET features implemented.

4. IO Controller

4.1 Definition

The IO Controller is the automation controller responsible for establishing and managing cyclic I/O relationships with configured IO Devices.

In a typical PLC-controlled machine, the PLC executes the control program and exchanges process data with distributed field devices.

The controller typically handles:

  • Configured device relationships.
  • Cyclic reading of input data.
  • Cyclic writing of output data.
  • Monitoring communication status.
  • Reporting device and module diagnostics.
  • Applying the configured process-data layout.
  • Making I/O data available to the PLC program.

A PROFINET IO Controller is commonly a PLC, but the exact supported role depends on the device and its communication interface.

4.2 Example

Consider a PLC controlling a conveyor through remote I/O and a drive.

The PLC reads:

  • Conveyor start permissive.
  • Motor overload status.
  • Photoelectric sensor status.
  • Drive-ready feedback.
  • Actual speed or drive status data, if configured.

The PLC writes:

  • Contactor or actuator commands through remote outputs.
  • Drive control data.
  • Operating mode or setpoint data where supported.

The controller uses these inputs and outputs within its control logic. The physical field devices still require correct wiring, power, and parameterization.

5. IO Device

5.1 Definition

An IO Device is a PROFINET participant that exchanges configured process data with an IO Controller.

Common examples include:

  • Remote digital and analog I/O.
  • Distributed motor starters.
  • Variable-frequency drives.
  • Servo drives.
  • Valve terminals.
  • Identification systems.
  • Certain robot controllers.
  • Specialized measurement and inspection equipment.

The term IO Device does not mean the equipment must contain only digital input/output channels. A drive, for example, may exchange control words, status words, setpoints, actual values, and diagnostic information.

5.2 Device structure

A modular IO Device may contain several layers:

  • Device: The complete PROFINET station.
  • Access point or interface: The communication interface connecting it to the network.
  • Module: A functional hardware unit, such as a digital input or output module.
  • Submodule: A smaller configured data unit within a module or device structure.
  • Channel: An individual input, output, or functional signal point.

The exact hierarchy depends on the device and its engineering description.

For example, a remote I/O station could contain a PROFINET interface module, a digital input module, an analog input module, and a digital output module. The engineering configuration must represent the installed arrangement correctly.

5.3 Input and output direction

Input and output direction is defined from the controller's perspective in the I/O relationship.

Data direction Meaning from controller perspective Example
Device to controller Input data Sensor state or drive status
Controller to device Output data Valve command or drive setpoint
Device diagnostics to engineering system Diagnostic information Module fault or channel error

A drive's status word may be controller input data even though it describes the drive. Its control word may be controller output data because the PLC sends it to the drive.

This distinction matters when configuring I/O addresses and troubleshooting incorrect values.

6. IO Supervisor

An IO Supervisor is an engineering or diagnostic participant used to access device information and perform commissioning or maintenance activities.

Examples include an engineering workstation running Siemens TIA Portal or another compatible engineering environment, and diagnostic tools that support the relevant PROFINET functions.

Typical activities include:

  • Configuring the controller and devices.
  • Assigning or verifying device names and network parameters.
  • Downloading controller configuration.
  • Viewing diagnostic buffers and device status.
  • Identifying accessible devices.
  • Monitoring process values.
  • Performing approved maintenance and commissioning tasks.

The supervisor is not normally the controller executing the machine's cyclic control logic. Its role is primarily engineering, configuration, and diagnostics.

7. PROFINET versus PROFIBUS

Both technologies connect industrial controllers to field devices, but their physical layers and engineering details differ.

Feature PROFIBUS DP PROFINET
Typical physical layer RS-485 serial bus Industrial Ethernet
Typical cabling Shielded PROFIBUS cable Ethernet cabling, often industrial shielded twisted pair
Common connector PROFIBUS D-sub or compatible industrial connector RJ45 or industrial Ethernet connector, depending on equipment
Addressing and identity Station address Device name and network parameters, including IP address where applicable
Engineering description GSD GSDML
Typical cyclic communication DP master/slave data exchange IO Controller/IO Device data exchange
Network infrastructure Bus segments, repeaters, termination Ethernet switches, ports, cables, and supported topologies
Common physical-layer fault Termination, RS-485 cable, address Cable or port fault, Ethernet link issue, device identity/configuration
Diagnostics Master and slave diagnostics Controller, device, module, channel, and network diagnostics

PROFINET is not simply a newer version of PROFIBUS using the same physical layer. Their configuration models, physical wiring, and diagnostic workflows differ.

8. PROFINET uses Ethernet, but it is industrial Ethernet

PROFINET uses Ethernet as its network foundation and supports multiple communication mechanisms according to the application's requirements.

Important distinctions include:

  • Standard Ethernet communication: Used for many configuration, diagnostic, and non-real-time communication functions.
  • Real-Time (RT): Used for cyclic industrial process data with timing behavior suited to many machine-automation applications.
  • Isochronous Real-Time (IRT): A specialized mechanism for applications requiring highly synchronized, predictable communication, subject to compatible hardware and network design.

Not every PROFINET device supports every communication class. The required performance depends on the application, controller, device capabilities, network architecture, and configuration.

8.1 Real-time communication

A PLC may need to read sensor inputs and update outputs at regular intervals. PROFINET cyclic communication supports this exchange without requiring the PLC program to establish a separate application-level request for every signal.

The configured update time and actual communication performance depend on the system. A network should not be assumed to meet a particular cycle time merely because the devices support PROFINET.

8.2 PROFINET and ordinary TCP/IP

PROFINET can coexist with ordinary Ethernet communication, but not all PROFINET data uses TCP/IP.

Cyclic real-time process data commonly uses Ethernet-based mechanisms designed for automation timing. Engineering access and other services may use standard Ethernet and IP-based protocols.

This distinction is important when configuring firewalls, diagnosing traffic, selecting switches, or interpreting packet captures. Blocking or misconfiguring required traffic can disrupt communication even when the physical Ethernet link remains up.

9. PROFINET device identity: name and IP address

A fundamental difference between PROFIBUS and PROFINET is how a controller identifies and establishes communication with a field device.

In a common PROFINET IO installation, a device has a configured PROFINET device name and may also have an IP address, subnet mask, and other network parameters.

These serve related but different purposes.

  • Device name: Identifies the PROFINET device within the configured automation system and is important for establishing the expected IO relationship.
  • IP address: Provides IP-layer addressing for services that use IP, including relevant engineering and diagnostic communication.
  • MAC address: Identifies the Ethernet interface at the data-link layer.

A device's MAC address is normally associated with its Ethernet interface. Its PROFINET device name and IP configuration are assigned or managed according to the device's supported commissioning method.

The detailed naming, addressing, and assignment procedures are covered in the next topic.

9.1 Why device identity matters

Imagine a machine with three identical remote I/O stations. If a replacement station is given the wrong device name, the controller may not establish the intended configured relationship even if the replacement has a valid Ethernet link and IP address.

Similarly, a device name may be correct while the IP configuration is wrong for engineering access or other IP-based communication.

Therefore, distinguish between:

  1. Physical Ethernet connectivity.
  2. Correct device identity.
  3. Correct network configuration.
  4. Successful IO relationship establishment.
  5. Correct process-data exchange.

These are separate verification steps.

10. PROFINET network topology

PROFINET supports different Ethernet topologies, depending on the devices, switches, redundancy features, and application requirements.

10.1 Line topology

PLC
 |
Remote I/O 1
 |
Remote I/O 2
 |
Drive
 |
Valve terminal

This arrangement may use devices with integrated Ethernet switch ports. A device or cable failure can affect devices further along the line, depending on where the fault occurs and how the equipment is designed.

10.2 Star topology

             Remote I/O
                 |
                 |
PLC -------- Ethernet switch -------- Drive
                 |
                 |
             Valve terminal

The switch provides separate connections to devices. A failed individual link generally affects the device on that link, while a failed central switch may affect all connected devices.

10.3 Ring topology

PLC / network node
      |
    Device 1
      |
    Device 2
      |
    Device 3
      |
  Network node

This is a conceptual ring representation. A functioning redundant ring requires compatible devices and an appropriately configured redundancy mechanism, such as a supported PROFINET Media Redundancy Protocol arrangement. Merely connecting cables in a circle does not guarantee redundancy.

10.4 Topology comparison

Topology Advantages Considerations
Line Simple wiring and reduced switch count in suitable devices A break may isolate downstream devices
Star Straightforward isolation of individual links Central switch is a potential common failure point
Ring Can support recovery from a single link failure when correctly designed Requires compatible hardware and correct redundancy configuration

Choose topology based on machine layout, cable length, required availability, device support, and maintenance strategy. Do not assume every industrial Ethernet switch supports every PROFINET redundancy feature.

11. PROFINET process-data exchange

11.1 Cyclic data

Cyclic data is exchanged repeatedly according to the configured communication relationship and update behavior.

Examples include:

  • Digital sensor states.
  • Actuator commands.
  • Analog process values.
  • Drive control and status data.
  • Robot handshake signals.
  • Machine-ready and fault status signals.

The controller uses input data in its logic and sends output data to the devices.

11.2 A simple example

Suppose a photoelectric sensor is connected to a PROFINET remote I/O station.

  1. An object enters the sensor's detection area.
  2. The sensor changes its electrical output.
  3. The remote I/O reads the channel and makes the corresponding input data available to the controller.
  4. The PLC program evaluates the input.
  5. The PLC updates an output command if its control conditions are satisfied.
  6. The remote I/O updates the physical output, energizing the intended actuator if the circuit and device conditions permit.

PROFINET transports the configured data. It does not replace the sensor wiring, PLC logic, output electronics, or actuator power circuit.

11.3 Cyclic data versus diagnostics

Data type Purpose Example
Cyclic process data Regular control and feedback exchange Sensor state, drive speed feedback
Acyclic record data Parameter access or other supported data exchange Reading or writing a device parameter
Diagnostic information Reports device, module, channel, or communication conditions Channel short-circuit diagnostic
Engineering/configuration data Supports commissioning and device setup Hardware configuration and device parameters

The exact services available depend on the device and controller. Not every device exposes the same parameters or diagnostic detail.

12. PROFINET and drives

PROFINET is commonly used to integrate variable-frequency drives and servo drives with PLCs.

A configured drive may exchange:

  • Control word.
  • Status word.
  • Speed or torque reference, depending on the application.
  • Actual speed or other feedback values.
  • Fault or warning information.
  • Additional parameters or process values supported by the selected configuration.

The precise data layout depends on the drive family, communication option, configured telegram or process-data assembly, and engineering setup.

Example: conveyor drive

The PLC may send a run command and speed reference to the drive. The drive returns a status word, actual speed, and fault information.

If the drive is online but the conveyor does not run, check more than the Ethernet link:

  • Is the control word mapped correctly?
  • Is the drive ready?
  • Are hardware and software interlocks satisfied?
  • Is the selected operating mode correct?
  • Is the speed reference scaled and mapped correctly?
  • Is a drive fault active?
  • Are the drive's local control and safety conditions permitting operation?

A healthy PROFINET connection does not guarantee that the drive is enabled or that the motor can safely operate.

13. PROFINET and remote I/O

Remote I/O allows sensors and actuators to be connected close to the machine rather than routing every signal directly to the PLC cabinet.

A remote I/O station typically contains a PROFINET interface and one or more I/O modules.

Common applications include:

  • Machine sensor acquisition.
  • Solenoid valve control.
  • Digital status collection.
  • Analog pressure, temperature, or flow measurements.
  • Local actuator commands.
  • Distributed machine sections.

Common remote I/O diagnostic categories

Symptom Possible area to investigate
Device not accessible Power, Ethernet link, device identity, network configuration
Device accessible but IO relationship fails Configuration mismatch, device-name mismatch, unsupported module arrangement
Entire station reports a fault Interface module, device configuration, supply, or network issue
One channel reports a fault Field wiring, sensor, actuator, channel configuration, or module diagnostic
Process values are incorrect Channel mapping, data type, scaling, or field-device problem

A station-level fault and a channel-level fault are not equivalent. The diagnostic details help determine whether the whole device or only a particular signal is affected.

14. PROFINET hardware and infrastructure

14.1 Industrial Ethernet cable

PROFINET installations commonly use industrial Ethernet cable selected for the environment and transmission requirements.

Important properties include:

  • Cable category and supported data rate.
  • Shielding and connector compatibility.
  • Flexibility for moving equipment and cable carriers.
  • Resistance to oil, coolant, vibration, temperature, and mechanical wear as required.
  • Suitable bend radius and strain relief.
  • Installation distance and electromagnetic compatibility.

Cable jacket color is not sufficient to determine suitability. Verify the cable markings and manufacturer's specifications.

14.2 Ethernet switches

Switches forward Ethernet frames between connected devices. In industrial automation, switches may also provide useful monitoring and management functions.

Relevant features can include:

  • Port and link status.
  • Port speed and duplex status.
  • VLAN support where the network design requires it.
  • Network diagnostics.
  • Redundancy features supported by the system.
  • Port mirroring for packet analysis.
  • Environmental ratings for industrial installations.

A managed switch is not automatically necessary for every PROFINET network. Selection depends on network complexity, diagnostic needs, topology, and application requirements.

14.3 Device LEDs

PROFINET devices often have indicators for power, Ethernet link/activity, system status, and communication or module status. LED labels and meanings vary by manufacturer.

Use the device manual to interpret the indicators. For example, an Ethernet link indicator may confirm a physical link but does not prove that the controller has established a valid PROFINET IO relationship.

15. PROFINET troubleshooting fundamentals

The detailed setup and troubleshooting procedures will be covered in later topics, but the basic diagnostic sequence is important from the beginning.

15.1 Layer-by-layer diagnosis

Layer or function What to verify
Power Device supply, interface power, and status indicators
Physical Ethernet Cable, connector, port, link status, and cable integrity
Network addressing IP configuration and subnet consistency where applicable
PROFINET identity Correct device name and expected device identity
IO configuration Controller configuration, module structure, and supported features
Process data Input/output mapping, data length, scaling, and application logic
Field operation Sensor, actuator, drive, wiring, interlocks, and supply

15.2 Example: device has Ethernet link but is offline in the PLC

An active Ethernet link establishes only that the physical connection is present. It does not prove that the configured PROFINET communication relationship is operating.

Possible causes include:

  • Incorrect device name.
  • Wrong or duplicate IP address affecting IP-based access.
  • Device configured in the wrong controller project.
  • Hardware or module configuration mismatch.
  • Unsupported device or firmware combination.
  • Incorrect topology or network configuration.
  • Device not powered or initialized correctly despite a link indication.

Use controller diagnostics and the engineering tool to narrow the fault. Do not assume the IP address is the cause simply because the device is offline.

16. PROFINET security and network design

PROFINET networks are part of the operational technology environment. Uncontrolled connections can create availability, integrity, and security risks.

Good practices include:

  • Separate industrial control networks from office networks according to the approved architecture.
  • Restrict engineering access to authorized systems.
  • Use approved switches, routers, and firewall rules.
  • Document device identities and IP assignments.
  • Preserve controller and device configurations.
  • Control firmware and engineering-software changes.
  • Monitor unexpected devices and network changes where suitable tools are available.
  • Follow vendor recommendations for supported security features.

Do not assume that using Ethernet makes a control network secure by default. Industrial communication requires deliberate network design and change control.

17. PROFINET versus PROFIBUS: practical maintenance example

Consider an existing machine with PROFIBUS remote I/O and a newer machine with PROFINET remote I/O.

On the PROFIBUS machine, a technician may investigate the RS-485 cable, termination switches, station addresses, and GSD configuration.

On the PROFINET machine, the technician may investigate Ethernet links, switches, device names, IP settings, GSDML device descriptions, and the controller's IO configuration.

The troubleshooting philosophy remains similar:

  1. Determine which devices are affected.
  2. Identify the communication layer involved.
  3. Check diagnostics before changing configuration.
  4. Compare the installed hardware with the approved project.
  5. Apply a controlled correction.
  6. Verify communication and actual machine behavior.

The tools and physical-layer checks differ, but systematic fault isolation remains essential.

18. Interview questions and answers

Q1. What is PROFINET?

PROFINET is an industrial Ethernet communication standard used for automation, including cyclic I/O exchange, device configuration, and diagnostics.

Q2. What is an IO Controller?

It is the device, commonly a PLC, that controls the PROFINET IO system and exchanges configured cyclic process data with IO Devices.

Q3. What is an IO Device?

It is a field device, such as remote I/O or a drive, that exchanges configured process data with an IO Controller.

Q4. What is an IO Supervisor?

It is an engineering or diagnostic participant used for configuration, commissioning, monitoring, and maintenance.

Q5. What is the difference between PROFINET and PROFIBUS DP?

PROFINET uses Ethernet technology, while PROFIBUS DP commonly uses RS-485 serial communication. They also differ in device identification, configuration, physical-layer requirements, and troubleshooting methods.

Q6. What is the difference between a PROFINET device name and an IP address?

The device name identifies the PROFINET station for the configured IO relationship. The IP address provides network-layer addressing for IP-based services. They are related but not interchangeable.

Q7. Does every PROFINET message use TCP/IP?

No. PROFINET uses different communication mechanisms. Cyclic real-time process data commonly uses Ethernet-based mechanisms that do not require TCP/IP for the cyclic data exchange.

Q8. What is the difference between RT and IRT?

RT provides real-time communication suitable for many industrial automation applications. IRT supports highly synchronized communication for applications with stricter timing requirements and requires compatible hardware and network design.

Q9. Does an active Ethernet link prove that the PROFINET device is communicating correctly?

No. It confirms physical link connectivity, not correct device identity, successful IO relationship establishment, or valid process-data exchange.

Q10. What is GSDML?

GSDML is the XML-based language used for PROFINET device description files. It describes device capabilities and configuration options for compatible engineering tools.

Q11. Can PROFINET connect a PLC to a variable-frequency drive?

Yes. A compatible drive can exchange configured control data, status information, setpoints, feedback, and other supported process data with the PLC.

Q12. Does PROFINET automatically make a machine safe?

No. Communication does not replace the machine's safety design. Safety functions require appropriately designed and validated safety-related systems.

19. Practical exercises

  1. Architecture identification: Select a machine and identify its PLC, PROFINET IO Controller, remote I/O stations, drives, switches, and engineering workstation.
  2. Device inventory: Record each device's manufacturer, model, physical location, role, and Ethernet connection.
  3. Data-direction exercise: Trace one sensor signal from the remote I/O to the PLC and one PLC command from the program to a field output.
  4. Topology review: Identify whether the existing network is a line, star, or supported redundant ring. Record the possible impact of a cable or switch failure.
  5. Diagnostic exercise: Examine the status of an existing device using approved engineering tools and distinguish physical link status from IO relationship status.
  6. PROFIBUS comparison: Compare one PROFIBUS DP station with a similar PROFINET station, documenting the differences in cabling, identity, configuration, and diagnostic methods.
  7. Drive integration: Identify the control and status data exchanged between a PLC and a drive, using the actual drive manual and approved project.

Do not intentionally disconnect devices or alter network settings on a running production machine for practice. Use an offline project, simulator, or approved training setup.

20. Final mental model

  • PROFINET is the industrial Ethernet communication system.
  • IO Controller is typically the PLC responsible for the configured I/O relationship.
  • IO Device is the field device exchanging process data with the controller.
  • IO Supervisor is the engineering or diagnostic participant.
  • Device name identifies the PROFINET station within the configured system.
  • IP address supports IP-layer communication and services.
  • GSDML describes the device's capabilities to compatible engineering software.
  • RT and IRT provide different real-time communication capabilities.
  • Ethernet link status does not prove that the IO relationship or process data is correct.

For maintenance and development work, the important skill is understanding the complete path from the physical device and Ethernet connection through the PROFINET configuration and PLC program to the actual machine response.
