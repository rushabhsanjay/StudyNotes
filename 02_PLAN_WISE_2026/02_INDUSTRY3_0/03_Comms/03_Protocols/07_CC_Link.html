CC-Link: Industrial Fieldbus Communication

1. Purpose and scope

CC-Link (Control & Communication Link) is an industrial fieldbus technology originally developed in Japan and closely associated with Mitsubishi Electric and the broader CC-Link partner ecosystem. It is used to exchange control data between PLCs, remote I/O stations, drives, intelligent devices, and other factory automation equipment.

CC-Link is especially relevant in manufacturing environments using Mitsubishi PLCs, distributed I/O, machine tools, assembly equipment, and automated production lines.

The key idea is that a controller can exchange cyclic control data with multiple network stations over a shared industrial communication network instead of wiring every signal directly to the PLC.

CC-Link is a family of technologies. This topic focuses on classic CC-Link fieldbus, not CC-Link IE, which is the next topic.

2. Where CC-Link fits in industrial automation

A CC-Link network can reduce field wiring by connecting distributed devices through a communication cable. The PLC exchanges control and status information with configured stations, while each station performs its assigned function.

Examples include:

  • A PLC reading proximity sensors through remote input modules.
  • A PLC commanding remote output modules to operate solenoid valves.
  • A PLC exchanging run commands, status bits, and selected parameters with an inverter.
  • A machine controller communicating with an intelligent field device.
  • Distributed control stations exchanging cyclic data for machine sequencing.

The exact functionality depends on the CC-Link version, master module, station type, device capabilities, and configuration.

3. CC-Link terminology

Term Meaning
Master station Controls the network's cyclic communication and manages the configured network
Remote station A network device that exchanges data with the master
Remote I/O station A station primarily exchanging discrete input and output signals
Remote device station A station supporting richer cyclic data, depending on device capabilities
Local station A station that can participate in supported data exchange with other stations, depending on the system configuration
Intelligent device station A device with additional communication functions or data beyond simple remote I/O
Station number The configured network address of a station
Station type The class of station and its supported communication behavior
Occupied stations The amount of network station capacity assigned to a device
Cyclic communication Repeated exchange of control and status data during normal operation
Transient communication On-demand communication for specific data or services, where supported
Link refresh Transfer of network data between the communication module and the PLC CPU's assigned memory areas
Link scan time Time associated with completing a network communication cycle or scan

Do not treat these terms as interchangeable. A remote I/O station, a remote device station, and an intelligent station can differ in data capacity, station occupancy, and supported services.

4. Classic CC-Link architecture

Classic CC-Link typically uses a master-controlled fieldbus arrangement. The master manages cyclic communication with configured stations over a shared network.

PLC CPU
  |
  | PLC link refresh / device memory
  v
CC-Link master module
  |
  | Dedicated CC-Link network cable
  |
  +------ Remote I/O station
  |
  +------ Remote device station
  |
  +------ Inverter or intelligent station
  |
  +------ Additional configured stations

The physical network is commonly wired as a bus or daisy-chain arrangement using the specified CC-Link cable. Exact wiring, permitted branches, repeaters, and distance limits depend on the CC-Link specification and installation design.

4.1 Main components

PLC CPU: Executes the control program and uses link data to read station status and command remote devices.

CC-Link master module: Interfaces the PLC CPU to the fieldbus, manages communication, and reports network status. Depending on the PLC family, CC-Link functionality may be built in or provided by a separate module.

Remote I/O: Provides distributed digital or analog inputs and outputs. It reduces the need to route every sensor and actuator wire back to the main PLC cabinet.

Remote device station: Exchanges cyclic control data and may support additional parameters or functions beyond simple I/O.

Network cable and connectors: Carry communication signals between stations. The correct cable type, termination, grounding, and wiring method are essential to reliable communication.

Engineering software: Used to configure the master, station numbers, communication speed, station occupancy, link assignments, and diagnostics. For Mitsubishi systems, the specific software depends on the PLC generation and hardware, such as GX Works2 or GX Works3.

5. Cyclic communication and data exchange

CC-Link's main control function is cyclic communication. The network repeatedly exchanges configured data between the master and participating stations.

For example:

  1. A remote input station reads field sensors.
  2. Its input data is transferred through the CC-Link network.
  3. The master updates the relevant link data.
  4. The PLC program evaluates that data and executes its logic.
  5. The PLC updates output commands.
  6. The master transfers the output data to the appropriate remote station.
  7. The remote station drives its outputs according to its configuration and operating state.

The precise timing depends on network speed, station count, occupied stations, configured data, hardware, and the PLC's link-refresh behavior.

5.1 Cyclic versus transient communication

Feature Cyclic communication Transient communication
Purpose Regular control and status exchange On-demand data access or commands
Timing Repeated during network operation Initiated when needed
Typical data Inputs, outputs, status words, commands Parameters, diagnostics, supported service requests
Main consideration Predictable update behavior May add communication load or delay
Typical use Machine sequence and remote I/O Device information or parameter access

Not every station supports every transient service. Check the relevant device manual and CC-Link version.

6. CC-Link link devices and memory mapping

Mitsubishi PLC systems commonly use dedicated link-device areas for CC-Link data. These areas allow the PLC program to exchange information with remote stations.

The exact available devices and assignment rules depend on the master module, PLC family, and network configuration.

Link device General purpose Typical use
RX Remote input data Read input/status bits from remote stations
RY Remote output data Send output/command bits to remote stations
RWr Remote register read data Receive word data from remote devices
RWw Remote register write data Send word data to remote devices

These names describe common Mitsubishi CC-Link link-device conventions. Verify data direction and allocation in the specific module manual and engineering project.

6.2 Bit data versus word data

Bit-oriented data is useful for discrete states and commands:

  • Sensor ON/OFF.
  • Valve command.
  • Drive running status.
  • Ready, alarm, or interlock status.

Word-oriented data is useful for numerical or grouped information:

  • Speed reference.
  • Actual speed.
  • Position or count value.
  • Alarm code.
  • Device status word.
  • Selected parameters.

Word data can contain signed or unsigned integers, scaled values, or parts of larger values. The PLC program must interpret the received data using the device's documented data format.

7. Station numbering and occupancy

A CC-Link network must be configured so each station has a valid address and the master knows what each station occupies on the network.

7.1 Station number

The station number identifies a station within the network. Duplicate station numbers can prevent correct network operation or cause stations to fail to participate as intended.

During commissioning, record each device's physical station setting and compare it with the network configuration.

7.2 Occupied stations

Some CC-Link devices occupy more than one station's worth of network capacity because they exchange more data than a simple station.

The master configuration must reflect the station's specified occupancy. An incorrect occupancy setting can cause address allocation conflicts or incorrect expectations about the data exchanged.

Do not assume that every physical device always occupies exactly one station. Check the device's specification.

7.3 Network configuration checklist

  • Confirm the supported CC-Link version.
  • Confirm the master module model and compatibility.
  • Assign unique station numbers.
  • Configure the correct station type.
  • Set the correct occupied-station count.
  • Configure communication speed and applicable network parameters.
  • Verify link-device allocation and link-refresh settings.
  • Confirm that all configured stations match the actual installed devices.

8. Physical layer, cable, and topology

Classic CC-Link commonly uses a dedicated shielded twisted-pair cable specified for the network. Ordinary Ethernet patch cable should not be substituted merely because both use connectors or carry digital communication.

8.1 Cable and wiring principles

  • Use the specified cable type and connectors.
  • Follow the manufacturer's terminal and polarity markings.
  • Maintain the prescribed trunk-line wiring arrangement.
  • Use the correct termination at the two ends of the main line.
  • Avoid unintended branches or stubs beyond permitted limits.
  • Separate communication cabling from sources of electrical noise where practical.
  • Follow grounding and shield-bonding requirements for the selected equipment.
  • Avoid loose terminals, damaged insulation, and poor shield continuity.
  • Verify the approved maximum distance and repeater requirements for the selected speed and cable type.

8.2 Termination

Termination reduces signal reflections at the ends of the communication line. Missing, incorrect, or excessive termination can degrade signal quality and cause intermittent communication faults.

Termination requirements are specification-dependent. Use the prescribed CC-Link termination components and install them at the correct physical endpoints, not at arbitrary intermediate stations.

8.3 Network speed and distance

Classic CC-Link supports multiple communication speeds. Higher speeds generally allow shorter main-line distances, while lower speeds can support longer distances within the specification.

Typical classic CC-Link distance guidance for a conventional network is shown below. These figures are illustrative of commonly specified configurations, not a substitute for the exact cable and hardware manual.

Communication speed Commonly cited maximum main-line distance
10 Mbps 100 m
5 Mbps 160 m
2.5 Mbps 400 m
625 kbps 900 m
156 kbps 1200 m

Actual permissible distance depends on the CC-Link specification version, cable type, topology, station count, repeater use, and installation conditions. Some versions and cable arrangements have different limits.

Never choose a speed based only on the distance table. Verify the applicable network specification and device manuals before commissioning.

9. Communication timing and performance

CC-Link is designed for cyclic industrial control. However, its data update time is not identical to the PLC program scan time.

Several timing components contribute to the overall response:

  • CC-Link network communication cycle.
  • Link refresh between the communication module and PLC CPU.
  • PLC program scan and task execution.
  • Remote station input filtering and output response.
  • Device-specific processing time.
  • Additional delays caused by communication errors or recovery.

A signal may therefore take more than one PLC scan to travel from a field sensor to the PLC logic and then to an output.

9.1 Factors affecting link scan time

  • Number of stations.
  • Number of occupied stations.
  • Total cyclic data exchanged.
  • Configured network speed.
  • CC-Link version and master hardware.
  • Additional communication services and network load.
  • Error conditions and recovery behavior.

If an automated machine has a timing problem, do not automatically blame the fieldbus. Measure the actual signal path and determine whether the delay originates in the sensor, remote I/O, network, link refresh, PLC logic, or actuator.

9.2 CC-Link versus hardwired I/O timing

Hardwired I/O generally avoids a fieldbus communication cycle, while remote I/O over CC-Link adds communication and refresh timing.

However, a well-designed fieldbus system can still provide suitable timing for many machine-control applications. The appropriate choice depends on the required response time, network design, and equipment specifications.

Safety-critical functions must use an appropriate, validated safety architecture. Standard CC-Link communication must not be assumed to provide a safety-rated control path.

10. CC-Link integration with PLCs, drives, and machines

10.1 Mitsubishi PLC integration

In a Mitsubishi PLC system, engineering software is used to configure the network and assign link devices. The PLC program then uses those devices to exchange control and status information.

A typical commissioning sequence is:

  1. Confirm that the PLC CPU and master module support the intended CC-Link configuration.
  2. Configure station numbers, station types, occupied stations, and communication speed.
  3. Assign the link-device ranges and link-refresh settings.
  4. Download the approved configuration and perform the required restart or initialization.
  5. Confirm that the master and remote stations report healthy communication.
  6. Verify that received inputs change as the field signals change.
  7. Verify output commands using an approved, safe test procedure.
  8. Confirm diagnostic and recovery behavior.

The exact menu names and parameter locations vary between PLC families and software versions.

10.2 Inverter or drive integration

A CC-Link-compatible inverter may exchange cyclic data such as:

  • Run command.
  • Forward or reverse command, where supported.
  • Speed or frequency reference.
  • Running status.
  • Ready status.
  • Alarm indication.
  • Actual frequency or other monitoring values.

The actual command and monitoring fields depend on the inverter model, option module, and configuration.

For a drive retrofit, verify the communication option, parameter settings, control-source selection, station configuration, and PLC data mapping. A drive may be communicating correctly while still ignoring a network command because its run-command source is configured for terminal control or another interface.

Before testing run commands, confirm the machine's safe state, interlocks, and approved commissioning procedure.

10.3 Mixed-vendor equipment

CC-Link-compatible equipment from different manufacturers can interoperate when each device conforms to the relevant specification and its supported features are configured correctly.

Compatibility does not mean that every vendor uses identical parameters, diagnostic codes, register maps, or engineering tools.

Maintain the exact model, firmware, network interface, device profile, and manual revision for each station.

11. CC-Link diagnostics and common fault indicators

Network diagnostics depend on the master and remote station. Typical indicators include network run status, error status, transmit activity, receive activity, and module status.

The meaning of each LED must be checked against the exact module manual. Do not assume that every manufacturer or generation uses identical labels or blink patterns.

11.1 Diagnostic interpretation

Observation Possible cause What to inspect
Master reports a network error One or more stations are not communicating correctly Master diagnostics, station status, cable and termination
A remote station is not detected Incorrect station number, power failure, wiring fault Station settings, supply voltage, network wiring
Network runs but one device's data is wrong Mapping or configuration error Link-device allocation, station type, occupancy
Communication is intermittent Noise, loose wiring, termination or distance issue Cable route, connectors, shield, error history
Error begins after replacing a module New module configuration differs from the original Model compatibility, station settings, firmware
All stations fail together Master, trunk cable, network power, or configuration issue Master status, common cable path, network parameters
Only one station fails Local station, connector, branch or station configuration Station-specific diagnostics and physical connection
Data updates slowly High network load, configuration or application timing Link scan time, station count, PLC scan, polling and refresh
Drive communicates but does not run Drive control source or permissive issue Drive parameters, interlocks, command mapping, fault state

12. Step-by-step CC-Link troubleshooting

Step 1: Establish the failure scope

Determine whether the fault affects:

  • The entire CC-Link network.
  • A group of stations.
  • One remote I/O station.
  • One drive or intelligent device.
  • Only particular bits or word values.

This distinction helps separate a common network fault from a local device or application fault.

Step 2: Inspect the master and station diagnostics

Record the master status and the diagnostic state of affected stations. Use the specific module's error codes and diagnostic buffer rather than relying only on LED appearance.

Determine whether the station is absent, intermittently communicating, or communicating normally with incorrect data.

Step 3: Verify the configuration

Compare the installed hardware with the engineering project:

  • Master module model.
  • CC-Link version and supported speed.
  • Station number.
  • Station type.
  • Occupied-station setting.
  • Network parameters.
  • Link-device assignments.
  • Link-refresh configuration.

A replacement module may have different default settings from the original device. A visually identical module is not proof of identical configuration.

Step 4: Inspect physical wiring

Check the network cable, terminals, connectors, and termination. Confirm that the cable type and topology are approved for the network.

Look for crushed cable, loose terminal screws, damaged connectors, unauthorized branches, and routing near high-noise power conductors.

Step 5: Verify the data path

For an input signal, trace the data through the entire chain:

Physical sensor
      ↓
Remote input terminal
      ↓
Remote station input data
      ↓
Master link data
      ↓
PLC link refresh
      ↓
PLC program logic

For an output signal, trace the path in the opposite direction from the PLC logic through the master link data to the remote output terminal and the final actuator.

This helps identify whether the problem is electrical, network-related, or caused by the PLC program.

Step 6: Compare known-good and faulty stations

Where the design and safety procedure permit, compare the affected station with a healthy station of the same type.

Compare station settings, wiring, diagnostic status, assigned link addresses, and observed input/output behavior. Do not swap live network devices or alter addresses without an approved change procedure.

Step 7: Validate recovery

After correcting the identified cause:

  1. Confirm that the master and affected stations report healthy communication.
  2. Verify input data against actual field states.
  3. Verify output commands using a controlled test.
  4. Confirm that relevant PLC interlocks and alarms behave correctly.
  5. Observe operation long enough to check for intermittent faults.
  6. Record the root cause and preventive action.

13. Maintenance, backups, and retrofit practices

For an industrial maintenance team, CC-Link should be managed as a system, not merely as a cable connecting modules.

Maintain a network inventory containing:

  • PLC CPU and master-module model.
  • CC-Link version and communication speed.
  • Station numbers and device types.
  • Station occupancy and assigned link-device ranges.
  • Cable type, route, termination locations, and approved distances.
  • Remote I/O module types and channel assignments.
  • Drive or intelligent-device communication options.
  • Engineering project backup and revision.
  • Module parameter backups where supported.
  • Known-good diagnostics and recovery procedure.
  • Obsolescence status and approved replacement alternatives.

Before replacing a module, preserve the existing configuration and verify the replacement's compatibility. After replacement, validate both communication health and actual process behavior.

A network that reports no errors may still have an incorrect data map. Preventive maintenance should therefore include selected functional checks, not just a quick glance at the master LEDs.

14. Safety and operational considerations

  • Standard CC-Link is not automatically a safety-rated network.
  • Do not rely on ordinary cyclic communication as the sole protection against hazardous machine motion.
  • Follow the machine's safety procedures before testing outputs or drive commands.
  • Do not disconnect network cables or remove modules from a live system unless the equipment documentation and approved procedure explicitly permit it.
  • Confirm the effects of network loss on outputs, drives, and machine sequencing.
  • Verify fail-safe behavior and restart conditions after communication recovery.
  • Back up PLC and network configuration before changing parameters.
  • Avoid changing station numbers, communication speed, or link assignments during production without authorization.

Communication recovery does not necessarily mean that a machine is safe to restart. The application logic and machine safety system must be validated independently.

15. CC-Link versus other industrial communication technologies

Technology General characteristics Common application
CC-Link Classic fieldbus with cyclic data exchange; strongly associated with Mitsubishi automation Distributed I/O, drives, machine control
CC-Link IE Industrial Ethernet-based CC-Link family; details depend on the IE variant Higher-capacity industrial networking and controller/device communication
PROFIBUS DP Serial fieldbus commonly used for distributed peripherals Remote I/O, drives, process and factory automation
PROFINET Industrial Ethernet communication technology PLCs, distributed I/O, drives, machine networks
Modbus RTU Serial master/client-to-server request-response protocol Meters, drives, instruments, gateways
Modbus TCP Modbus messaging over TCP/IP Ethernet-connected PLCs, meters, gateways, SCADA

These technologies are not directly interchangeable simply because they can all transfer control data. Hardware interfaces, engineering configuration, timing behavior, diagnostics, and data models differ.

CC-Link IE is the next topic because it builds on the CC-Link ecosystem but uses industrial Ethernet technology rather than the classic CC-Link fieldbus physical layer.

16. Interview questions and answers

Q1. What is CC-Link?

CC-Link is an industrial fieldbus technology used to exchange control and status data between PLCs and networked devices such as remote I/O, drives, and intelligent stations.

Q2. What is the role of the master station?

The master manages the configured network's communication and exchanges cyclic data with participating stations. It also provides network status and diagnostics through the supported PLC and module interfaces.

Q3. What is the difference between cyclic and transient communication?

Cyclic communication repeatedly exchanges configured control and status data. Transient communication is initiated for specific on-demand data or services supported by the devices.

Q4. What are RX, RY, RWr, and RWw?

They are common Mitsubishi CC-Link link-device areas. RX is generally used for remote input data, RY for remote output data, RWr for remote register read data, and RWw for remote register write data. Exact allocation and direction must be verified for the hardware configuration.

Q5. Why are station numbers important?

Each station must have a valid unique network address. Duplicate or mismatched station numbers can prevent the master from communicating with the intended stations.

Q6. What does occupied-station configuration mean?

It defines the network capacity allocated to a device. Some devices use more than one station's worth of capacity, so the master configuration must match the device specification.

Q7. What causes intermittent CC-Link communication faults?

Possible causes include incorrect termination, cable damage, electrical noise, loose terminals, unsupported topology, incorrect settings, or other hardware and network problems. Diagnostics should determine which cause is supported by evidence.

Q8. Why might a remote input module communicate correctly but the PLC display the wrong signal?

The fault may be in the link-device mapping, link-refresh configuration, PLC program logic, or the physical input wiring rather than the network itself.

Q9. What is the difference between classic CC-Link and CC-Link IE?

Classic CC-Link is a fieldbus technology with its own network physical layer and communication arrangement. CC-Link IE is an industrial Ethernet-based family with different network architecture and capabilities depending on the variant.

Q10. What should be checked before replacing a CC-Link station?

Verify the replacement model and compatibility, station number, station type, occupied-station requirements, communication settings, and required configuration. Then validate communication and actual machine behavior.

17. Practical exercises

  • Identify the CC-Link master module and record its exact model number.
  • Create a station inventory containing station number, model, station type, and occupied stations.
  • Locate the CC-Link network parameters in the relevant engineering project.
  • Identify the assigned RX, RY, RWr, and RWw ranges, where applicable.
  • Trace one physical sensor signal from its terminal to the PLC logic.
  • Trace one PLC output command from the program to the remote output terminal.
  • Review the cable route, termination, and documented maximum network distance.
  • Find the module's diagnostic codes and record the meaning of its status indicators.
  • Review a known-good project backup and compare it with the installed configuration.
  • Write a fault report for a simulated station failure, including evidence, root cause, corrective action, and validation.

18. Final mental model

CC-Link is a cyclic industrial fieldbus connecting a master PLC system to distributed stations. The master exchanges data with configured stations, and the PLC program uses the resulting link data to make control decisions.

When diagnosing a CC-Link problem, separate three questions:

  1. Is the network healthy? Check the master, station status, cable, termination, configuration, and diagnostics.
  2. Is the data mapped correctly? Check link devices, station occupancy, link refresh, and PLC program logic.
  3. Is the physical process responding correctly? Verify sensor states, output terminals, drive settings, interlocks, and actuator behavior.

That distinction prevents a common maintenance mistake: replacing communication hardware when the real problem is a data mapping or application configuration error.
