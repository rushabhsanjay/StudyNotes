1. Purpose and scope

Switches and routers connect devices and networks, but they make forwarding decisions using different types of addresses.

In industrial automation, understanding the distinction helps troubleshoot PLC-to-HMI communication, SCADA connectivity, VLAN segmentation, communication between production lines, plant-to-office connectivity, and routing between different IP subnets.

The fundamental difference is:

  • Layer 2 switch: Primarily forwards Ethernet frames using destination MAC addresses within a Layer 2 network.
  • Layer 3 router: Forwards IP packets between IP networks using destination IP addresses and a routing table.
  • Layer 3 switch: Combines Ethernet switching with IP routing capabilities, often at high speed inside enterprise and industrial networks.

These roles overlap in modern equipment. A managed switch may support VLANs, routing, access-control lists, and other Layer 3 functions. Therefore, the correct distinction is based on the function being performed, not merely the device's name.

2. Position in the OSI model

OSI Layer 7  Application
              SCADA, HMI, PLC protocols
                    ↑
OSI Layer 4  Transport
              TCP, UDP
                    ↑
OSI Layer 3  Network
              IPv4, IPv6, routing
                    ↑
OSI Layer 2  Data Link
              Ethernet frames, MAC addresses, VLANs
                    ↑
OSI Layer 1  Physical
              Copper, fiber, electrical and optical signaling

A conventional Layer 2 switch makes forwarding decisions primarily at Layer 2. A router makes forwarding decisions at Layer 3. Both depend on the physical and link layers to transmit traffic.

3. Layer 2 switch

A Layer 2 switch connects devices within an Ethernet LAN. It learns source MAC addresses from incoming frames and uses its MAC address table to forward frames toward the appropriate ports.

3.1 How a switch learns MAC addresses

Suppose a PLC sends an Ethernet frame into switch port 3.

The switch examines the source MAC address and learns that this address is reachable through port 3 in the relevant VLAN.

If the destination MAC address is already known, the switch can forward the frame toward the associated port. If the destination is unknown, the switch generally floods the frame within the relevant VLAN, excluding the port on which the frame arrived, subject to forwarding rules and filtering.

A broadcast frame is also normally flooded within that VLAN.

PLC A ───── Port 1
              |
          Layer 2 Switch ───── Port 2 ───── HMI
              |
           Port 3
              |
             PLC B

If PLC A sends a frame addressed to PLC B and the switch knows PLC B's MAC address, it forwards the frame toward PLC B rather than sending it out every port.

3.2 MAC address table

The switch maintains a forwarding database containing learned MAC addresses, VLAN information, and associated ports.

MAC address VLAN Port Meaning
00:11:22:33:44:01 10 1 Device learned on port 1
00:11:22:33:44:02 10 2 Device learned on port 2
00:11:22:33:44:03 20 3 Device learned on port 3

These are illustrative entries. Actual tables vary by switch vendor and configuration.

A MAC address learned in VLAN 10 is not automatically treated as the same forwarding entry in VLAN 20. VLAN membership is part of the Layer 2 forwarding context.

3.3 What a switch does with unknown traffic

When a switch receives a frame, it generally follows this logic:

  1. Learn or refresh the source MAC address against the incoming port and VLAN.
  2. Inspect the destination MAC address.
  3. If the destination is known and permitted, forward the frame toward the associated port.
  4. If the destination is unknown, flood it within the VLAN according to the switch's forwarding rules.
  5. If the frame is a broadcast, flood it within the VLAN according to the relevant rules.
  6. Do not forward a frame back out the same port on which it arrived.

Filtering, port security, spanning tree, multicast controls, and other features can modify the actual behavior.

3.4 Managed versus unmanaged switches

Feature Unmanaged switch Managed switch
Basic Ethernet forwarding Yes Yes
MAC learning Usually automatic Usually automatic
Configuration interface Usually absent Usually available
VLAN configuration Usually absent or very limited Commonly supported
Port diagnostics and counters Limited More extensive
Spanning Tree configuration and monitoring Usually limited or absent Commonly supported
Port security and access controls Limited Often supported
SNMP or remote monitoring Usually absent Often supported
Layer 3 routing Usually absent Depends on model

An industrial unmanaged switch can be perfectly suitable for a small, stable machine network. A managed switch is more useful when diagnostics, redundancy, VLANs, security, or detailed network monitoring are required.

Do not assume every managed switch supports Layer 3 routing. Check the model's feature set and firmware capabilities.

4. Layer 3 router

A router connects IP networks and forwards IP packets toward their destinations.

Unlike a conventional Layer 2 switch, a router does not simply forward a received Ethernet frame unchanged to the remote network. It removes the incoming link-layer framing, examines the IP packet, selects an outgoing route, and constructs a new link-layer frame for the next hop.

4.1 Example of routing between subnets

Consider this network:

Device IP address Subnet
Engineering PC 192.168.10.50/24 192.168.10.0/24
Router interface A 192.168.10.1/24 192.168.10.0/24
Router interface B 192.168.20.1/24 192.168.20.0/24
PLC 192.168.20.20/24 192.168.20.0/24

The PC and PLC are on different IP subnets. If routing and security rules permit communication, the PC sends its traffic to the router's local interface.

Engineering PC
192.168.10.50/24
        |
        | Ethernet frame to router MAC
        v
Router interface A
192.168.10.1/24
        |
        | IP routing decision
        v
Router interface B
192.168.20.1/24
        |
        | Ethernet frame to PLC MAC
        v
PLC
192.168.20.20/24

The PC's Ethernet destination MAC address is the router's MAC address on subnet 10. The router then forwards the IP packet toward subnet 20, using the PLC's MAC address as the destination Ethernet address on that outgoing network if the PLC is directly connected there.

The IP source and destination generally remain 192.168.10.50 and 192.168.20.20 when ordinary routing is used without address translation. The Ethernet MAC addresses change at the routed boundary.

4.2 Default gateway

A default gateway is the router IP address a host uses when the destination is outside the host's directly connected IP networks and no more-specific route applies.

For example:

PC IP address:      192.168.10.50
Subnet mask:        255.255.255.0
Default gateway:    192.168.10.1

With this configuration, the PC treats 192.168.10.0/24 as its directly connected subnet. A destination such as 192.168.20.20 is outside that subnet, so the PC normally sends the packet to its configured gateway.

If the gateway is incorrect or unavailable, local communication may still work while communication with remote subnets fails.

4.3 Routing table

Routers use routing tables to determine where to forward packets.

A routing table may contain:

  • Directly connected networks.
  • Static routes configured by an administrator.
  • Routes learned through routing protocols.
  • A default route used when no more-specific route matches.

The router generally chooses the route with the longest matching destination prefix. Route metrics and other selection rules can matter when multiple routes are available.

A routing table determines the next hop or outgoing interface. It does not, by itself, guarantee that a firewall will permit the traffic or that the destination application is working.

5. Layer 2 switching versus Layer 3 routing

Feature Layer 2 switch Layer 3 router
Primary forwarding unit Ethernet frame IP packet
Main forwarding information MAC address table Routing table and next-hop information
Primary address used for decision Destination MAC Destination IP
Main purpose Connect devices within a Layer 2 network Connect different IP networks
Broadcast handling Broadcasts normally remain within the VLAN Does not normally forward Layer 2 broadcasts between interfaces
IP subnet separation VLANs can separate Layer 2 domains Routing enables communication between IP subnets when permitted
ARP behavior Forwards ARP broadcasts within the VLAN and may implement related protections Resolves next-hop MAC addresses on its outgoing Ethernet links for IPv4
Typical use Connecting PLCs, HMIs, servers, and other local devices Connecting machine networks, plant networks, and remote IP networks
Security functions Depends on switch features Depends on router, firewall, and access-control features
Typical limitation A conventional Layer 2 switch does not route between subnets Routing requires appropriate IP addressing, routes, and permitted traffic

The simplest mental model is that a Layer 2 switch forwards frames within a Layer 2 domain, while a router forwards IP packets between networks.

6. Layer 3 switches

A Layer 3 switch combines Layer 2 switching with routing functionality. It can route between VLANs or connected IP subnets while also forwarding ordinary Ethernet frames.

For example, a managed Layer 3 switch may host:

  • VLAN 10 for machine controls.
  • VLAN 20 for SCADA servers.
  • VLAN 30 for engineering workstations.

It may use switched virtual interfaces (SVIs) as the default gateways for those VLANs.

VLAN 10: PLCs and machine controls
                  |
VLAN 20: SCADA servers
                  |
         Layer 3 Switch
          /           \
         /             \
VLAN 30: Engineering   Upstream router
workstations           or firewall

This is a conceptual architecture. The actual routing and security design depends on the equipment and configuration.

6.1 Inter-VLAN routing

VLANs divide a switched network into separate Layer 2 broadcast domains. Devices in different VLANs generally need Layer 3 routing to communicate with one another.

For example, a PLC in VLAN 10 and a SCADA server in VLAN 20 cannot exchange ordinary direct Layer 2 frames across the VLAN boundary. Their traffic must be routed, and the configured routing and security policy must permit the communication.

A Layer 3 switch may perform this routing internally. Alternatively, a router or firewall may route between the VLANs.

Important: Creating VLANs alone does not automatically permit or deny all communication in every possible topology. Inter-VLAN communication depends on the routing arrangement and any applicable access controls.

7. VLANs and broadcast domains

A VLAN is a logical Layer 2 network. It separates Ethernet broadcast domains even when devices connect to the same physical switch.

Example:

VLAN Purpose Example subnet
VLAN 10 Machine controls 192.168.10.0/24
VLAN 20 SCADA and data collection 192.168.20.0/24
VLAN 30 Engineering workstations 192.168.30.0/24

These are illustrative design choices, not universal requirements.

7.1 Access ports

An access port typically carries traffic for one configured VLAN toward an endpoint such as a PLC, HMI, or PC. The endpoint usually sends and receives ordinary untagged Ethernet frames unless its network configuration explicitly supports tagging.

7.2 Trunk ports

A trunk carries traffic for multiple VLANs between network devices, using VLAN tagging where configured. IEEE 802.1Q is the common Ethernet VLAN-tagging standard.

Trunks are commonly used between switches, between a switch and a router, or between a switch and a virtualization host.

Incorrect access-port VLAN assignment, missing trunk VLANs, or inconsistent tagging can prevent devices from communicating even when their IP addresses appear correct.

8. What happens to ARP when a router is involved?

ARP resolves an IPv4 address to a MAC address on the local Ethernet network.

If a PC wants to communicate with a remote subnet, it normally resolves the MAC address of the gateway rather than the remote device.

Example:

  • PC: 192.168.10.50/24
  • Gateway: 192.168.10.1
  • Remote PLC: 192.168.20.20/24

The PC sends an ARP request for 192.168.10.1 if the gateway's MAC address is not already cached. It then sends an Ethernet frame to that gateway MAC address containing an IP packet destined for 192.168.20.20.

The router receives the packet, consults its routing table, and forwards it toward the remote network. If the remote PLC is directly connected to that outgoing Ethernet network, the router resolves the PLC's MAC address on that network.

This is why arp -a on the PC may show the gateway's MAC address but not the remote PLC's MAC address.

9. Common industrial network architectures

9.1 Small machine network

A small machine may contain a PLC, HMI, engineering port, and a few networked devices connected to a Layer 2 industrial switch.

All devices may share one subnet. A router is not necessarily required for communication within that local network.

9.2 Multiple production cells

A plant may use separate VLANs or subnets for different machine cells, SCADA servers, engineering workstations, and infrastructure services.

A Layer 3 switch or router provides routing between selected networks, subject to the security design.

Separating traffic can improve organization and reduce unnecessary broadcast exposure, but VLANs alone are not a complete security boundary if routing and access controls are not designed appropriately.

9.3 Plant network connected to an enterprise network

Industrial networks may connect to a plant backbone or enterprise network through a router or firewall.

The connection should be designed around required communication flows, controlled access, monitoring, and operational safety. Directly connecting a control network to an untrusted network without appropriate protections can expose critical equipment.

10. Troubleshooting switch and router problems

10.1 When local devices cannot communicate

Check:

  1. Physical link state, cabling, and switch-port errors.
  2. IP address and subnet mask on both endpoints.
  3. Whether the devices belong to the expected VLAN.
  4. Whether the switch has learned the expected MAC addresses.
  5. Whether ARP resolution succeeds.
  6. Whether duplicate IP addresses or MAC flapping are occurring.
  7. Whether the application service is listening and configured correctly.

If two devices are in the same IP subnet but different VLANs, their apparent subnet match does not automatically make them directly reachable.

10.2 When local communication works but remote communication fails

Check:

  1. The host's subnet mask.
  2. The configured default gateway.
  3. The gateway interface's IP address and operational state.
  4. Routing tables on the host and routers.
  5. Return-path routing.
  6. Firewall rules and access-control lists.
  7. NAT configuration, if address translation is involved.
  8. Whether the remote application service is available.

One-way routing is a common source of confusion. The outbound packet may reach the destination, but the return packet may have no valid route back to the source network.

10.3 When ARP works but the application fails

If the host has learned the expected local MAC address, that is evidence that address resolution succeeded. It does not prove that all subsequent communication works.

Continue by checking IP reachability, the transport port, firewall policy, application configuration, and the endpoint's logs.

10.4 Useful Windows commands

Inspect IP configuration:

ipconfig /all

Inspect the local routing table:

route print

Inspect the ARP cache:

arp -a

Test IP reachability:

ping 192.168.10.1

Test a specific TCP service:

Test-NetConnection 192.168.20.20 -Port 502

The final example tests TCP connectivity to port 502, commonly used by Modbus TCP. Use the actual target IP and port for the system being diagnosed. A successful test does not validate the complete application protocol.

For managed switches and routers, use authorized management interfaces or command-line tools to inspect VLAN membership, MAC address tables, interface counters, routing tables, and access-control rules.

11. Network security considerations

Switches and routers can enforce different parts of a network's security design.

  • Use VLANs and subnets to separate traffic according to operational requirements.
  • Apply appropriate access controls to restrict which systems can communicate across network boundaries.
  • Use firewalls or suitable Layer 3 access-control mechanisms where required.
  • Disable unused switch ports where operationally appropriate.
  • Document port-to-device mappings, VLAN assignments, IP addresses, and default gateways.
  • Monitor link errors, broadcast storms, MAC address flapping, and unusual traffic.
  • Keep network-device configurations backed up and changes controlled.
  • Test routing, redundancy, and security changes in a controlled manner before applying them to production equipment.

A VLAN is not equivalent to a firewall. VLANs separate Layer 2 broadcast domains, while firewalls and access-control mechanisms enforce permitted communication according to their rules.

12. Practical exercises

Perform these exercises on a lab network or an approved test system.

Exercise 1: Identify local and remote destinations

  1. Record the PC's IP address, subnet mask, and default gateway.
  2. Identify a device on the same subnet.
  3. Identify a device on a different subnet.
  4. Determine which destination requires the default gateway.
  5. Inspect arp -a and explain which local MAC addresses are present.

Exercise 2: Inspect switch forwarding

  1. Connect two lab devices to a managed switch.
  2. Generate traffic between them.
  3. Inspect the switch's MAC address table.
  4. Identify the learned MAC addresses, ports, and VLANs.
  5. Observe how entries change when a device moves ports or remains inactive long enough for its entry to age out.

Do not move production equipment or change live switch ports for this exercise.

Exercise 3: Understand VLAN separation

  1. Review a lab switch's access-port and trunk configuration.
  2. Identify which VLAN each endpoint belongs to.
  3. Verify each endpoint's IP subnet and gateway.
  4. Test communication within the same VLAN.
  5. Test permitted communication between VLANs through the configured Layer 3 device.
  6. Explain how a VLAN mismatch can block communication even when the endpoints' IP settings appear plausible.

Exercise 4: Read the routing table

  1. Run route print on a Windows lab PC.
  2. Identify the directly connected subnet.
  3. Identify the default route.
  4. Find the route that would be used for a remote destination.
  5. Compare the expected route with the actual communication result.

13. Interview questions and answers

Q1. What is the main difference between a Layer 2 switch and a router?

A Layer 2 switch forwards Ethernet frames primarily using MAC addresses. A router forwards IP packets between networks using IP addresses and routing information.

Q2. Does a Layer 2 switch use IP addresses?

It may have a management IP address, but ordinary Layer 2 frame forwarding primarily uses MAC addresses.

Q3. Why does a host need a default gateway?

The default gateway provides a next hop for destinations outside the host's directly connected networks when no more-specific route applies.

Q4. Why does a remote IP destination use the gateway's MAC address?

Ethernet delivers the local frame to the next hop. The router then forwards the IP packet toward the remote destination using the appropriate link-layer addressing on the outgoing network.

Q5. What is a Layer 3 switch?

A switch that performs Layer 2 forwarding and supports IP routing, often including inter-VLAN routing.

Q6. What is the purpose of a VLAN?

A VLAN creates a separate Layer 2 broadcast domain on a switched network.

Q7. Do devices in different VLANs need routing to communicate?

They generally require Layer 3 routing between the VLANs, and the relevant security rules must permit the traffic.

Q8. Can two devices on the same physical switch be unable to communicate?

Yes. Different VLANs, incorrect IP configuration, port security, access-control rules, or physical and protocol faults can prevent communication.

Q9. Why might local communication work while remote communication fails?

Possible causes include an incorrect default gateway, missing route, failed router interface, blocked traffic, or a missing return route.

Q10. What is the difference between a switch MAC table and a router routing table?

A switch MAC table maps MAC addresses to ports and VLANs. A routing table determines the next hop or outgoing interface for IP destinations.

Q11. Is a VLAN a complete security boundary?

No. It separates Layer 2 broadcast domains, but communication between VLANs must be controlled through appropriate routing and security policies.

Q12. What should be checked first when a PLC is reachable locally but not from another subnet?

Verify IP addressing, subnet masks, default gateway configuration, routing in both directions, and firewall or access-control rules.

14. Final mental model

  • Layer 2 switch: Connects devices within Ethernet broadcast domains and forwards frames using MAC address learning.
  • Router: Connects IP networks and forwards packets using routing information.
  • Layer 3 switch: Performs switching and routing, commonly including inter-VLAN routing.
  • VLAN: Separates Layer 2 broadcast domains.
  • Default gateway: Provides the next hop for traffic destined outside the local subnet.
  • ARP: Resolves the local IPv4 next hop to a MAC address.
  • Firewall or access-control list: Controls which traffic is allowed between endpoints or networks.

For troubleshooting, first determine whether the problem is within one VLAN or crosses a routed boundary. Then verify the relevant MAC learning, ARP resolution, IP addressing, routing, and security policy. That sequence narrows the fault far more reliably than rebooting switches and hoping the network regains its will to live.
