1. Purpose and scope

MAC addressing and ARP are fundamental to communication within an Ethernet local area network (LAN). They help devices determine where to send Ethernet frames and how to deliver IP packets to the correct local network interface.

In industrial automation, these concepts are useful when diagnosing PLC communication failures, HMI connectivity problems, duplicate IP addresses, incorrect network configuration, switch-table issues, and devices that respond to ping intermittently.

The central distinction is:

  • IP address: Identifies a network-layer endpoint and supports communication across IP networks.
  • MAC address: Identifies a network interface at the data-link layer for local-link frame delivery.
  • ARP: Resolves an IPv4 address to a MAC address on a local network.

ARP does not discover every device in the plant, assign IP addresses, or route packets between networks. It performs a much narrower job: mapping an IPv4 address to a link-layer address on the local network.

2. MAC address fundamentals

A MAC address is a link-layer address used by Ethernet interfaces to identify the source and destination of frames on a local network.

A typical Ethernet MAC address is 48 bits long, or 6 bytes.

Example:

00:1A:2B:3C:4D:5E

The same address may be displayed in different formats:

00:1A:2B:3C:4D:5E
00-1A-2B-3C-4D-5E
001A.2B3C.4D5E

These formats represent the same 48-bit value.

2.1 MAC address structure

A conventional globally administered unicast MAC address contains two main portions.

48-bit MAC address
┌────────────────────────┬────────────────────────┐
│ First 24 bits          │ Last 24 bits           │
│ OUI / assigned prefix  │ Interface identifier   │
└────────────────────────┴────────────────────────┘
  • OUI (Organizationally Unique Identifier): A prefix allocated by the IEEE Registration Authority to an organization.
  • Interface identifier: The remaining bits assigned by the organization, subject to the relevant allocation rules.

This structure is a useful general model, not a universal guarantee. Some MAC addresses are locally administered, and newer allocation formats also exist.

A MAC prefix can help identify the organization to which an address block was assigned. It does not reliably prove the manufacturer of the complete device, because network interfaces can use customized or virtual addresses.

2.2 Types of MAC addressing

Type Description Example use
Unicast Identifies one destination interface A PC sending a frame to a PLC
Multicast Identifies a group of interfaces Industrial multicast traffic
Broadcast Targets all stations on the local Ethernet broadcast domain ARP requests
Globally administered Assigned under globally coordinated address allocation Factory-installed network interface
Locally administered Configured locally rather than relying on a globally assigned interface address Virtual interfaces or customized network configurations

The least significant bit of the first transmitted address octet distinguishes individual versus group addressing. The next bit distinguishes globally versus locally administered addressing. When inspecting the address as hexadecimal text, these bits are in the two least significant positions of the first octet.

2.3 The Ethernet broadcast MAC address

The Ethernet broadcast destination is:

FF:FF:FF:FF:FF:FF

A broadcast Ethernet frame is delivered to all participating interfaces within the relevant Layer 2 broadcast domain, subject to the network's behavior and filtering.

A typical ARP request uses this broadcast destination because the sender does not yet know which MAC address owns the requested IPv4 address.

Broadcasts are not normally forwarded by routers into other IP networks. This limits their scope to the local broadcast domain.

3. IP address versus MAC address

These addresses operate at different layers and solve different problems.

Feature IP address MAC address
Primary role Network-layer addressing Local-link frame addressing
Typical layer OSI Layer 3 OSI Layer 2
Example 192.168.10.20 00:1A:2B:3C:4D:5E
Used by routers Yes, for IP forwarding Used on each Ethernet link for frame delivery
Used by Ethernet switches Not normally the primary forwarding key Yes, for ordinary Layer 2 forwarding
Can change? Yes Yes, depending on interface configuration
Scope Local subnet or routed IP network, depending on configuration Relevant local link or Layer 2 domain
Resolution mechanism IPv4 ARP or IPv6 Neighbor Discovery for next-hop link addressing Already carried in the Ethernet frame header

An IP address is not permanently tied to one physical device. It may be assigned dynamically, changed manually, or reused after a device is removed.

Likewise, a MAC address is not an infallible physical identity. It can be overridden, spoofed, virtualized, or replaced with a different interface.

4. Why ARP is needed

When a PC wants to send an IPv4 packet to another device on the same Ethernet subnet, it needs the destination device's MAC address to construct the Ethernet frame.

For example:

  • PC IP: 192.168.10.50
  • PLC IP: 192.168.10.20
  • PC subnet mask: 255.255.255.0

The PC determines that the PLC's IP address is on the same IPv4 subnet. It checks its ARP cache for a mapping to the PLC's MAC address.

If the mapping is missing, the PC broadcasts an ARP request asking which device owns 192.168.10.20. The PLC can respond with its MAC address, allowing the PC to send the Ethernet frame directly to the PLC.

ARP maps IPv4 addresses to link-layer addresses. It does not translate IP addresses into other IP addresses.

5. ARP operation step by step

Assume the following lab network:

Device IPv4 address Example MAC address
Engineering PC 192.168.10.50 00:11:22:33:44:50
PLC 192.168.10.20 00:11:22:33:44:20
HMI 192.168.10.30 00:11:22:33:44:30

These are illustrative addresses, not a recommended configuration for any particular production network.

Step 1: Check the ARP cache

The PC checks whether it already knows the MAC address associated with 192.168.10.20.

If a valid mapping exists, it may use that entry without broadcasting a new request.

Step 2: Broadcast an ARP request

If the mapping is unavailable, the PC sends an ARP request.

Conceptually, the request asks:

Which device owns IPv4 address 192.168.10.20? Send the answer to 192.168.10.50.

The Ethernet destination is the broadcast MAC address, FF:FF:FF:FF:FF:FF.

Step 3: The PLC receives the request

Devices in the same broadcast domain receive the broadcast frame and inspect the ARP request. The device whose IPv4 address matches the target protocol address can respond.

Step 4: The PLC sends an ARP reply

The PLC typically replies directly to the PC, providing its MAC address.

Engineering PC                              PLC
      |                                      |
      |--- ARP request: Who has .20? ------> |
      |                                      |
      | <--- ARP reply: .20 is at MAC ... ---|
      |                                      |
      |--- Ethernet frame + IP packet ------>|

The ARP reply allows the PC to build an Ethernet frame addressed to the PLC's MAC address.

Step 5: Cache the mapping

The PC stores the mapping in its ARP cache for a limited time. The entry can later expire or be updated.

Subsequent packets can use the cached mapping without repeating the ARP exchange, until the entry is no longer usable.

6. What happens when the destination is on another subnet?

This is one of the most important networking concepts to understand.

Suppose:

  • PC: 192.168.10.50/24
  • Remote server: 192.168.20.100
  • Default gateway: 192.168.10.1

The PC determines that the server is not on its local IPv4 subnet. It therefore sends the IP packet to its default gateway.

The PC does not normally ARP for the remote server's MAC address. It ARPs for the MAC address of the gateway interface on the local subnet, assuming the gateway's MAC address is not already cached.

PC
192.168.10.50
    |
    | Ethernet frame:
    | Destination MAC = gateway MAC
    | IP destination = 192.168.20.100
    v
Router / default gateway
    |
    | Routes the IP packet
    | Builds a new link-layer frame
    v
Remote network
192.168.20.100

At each routed Ethernet hop, the router uses the appropriate outgoing link-layer address for the next hop. The IP destination generally remains the remote endpoint's IP address, while the Ethernet source and destination MAC addresses are replaced for the new link.

This explains why an IP packet can travel through multiple routers while its Ethernet frame addresses change at each routed hop.

7. ARP packet fields

An ARP message includes fields that identify the address formats and the addresses being resolved.

Field Purpose
Hardware type Identifies the link-layer hardware type, such as Ethernet
Protocol type Identifies the network-layer protocol, such as IPv4
Hardware address length Specifies the hardware address length
Protocol address length Specifies the protocol address length
Operation Indicates a request or reply
Sender hardware address MAC address of the sender
Sender protocol address IPv4 address of the sender
Target hardware address MAC address of the target, often unknown in a request
Target protocol address IPv4 address being queried or answered

For conventional Ethernet with IPv4, ARP commonly uses hardware type 1, protocol type 0x0800, a hardware address length of 6, and a protocol address length of 4.

A typical Ethernet/IPv4 ARP message uses an operation value of 1 for a request and 2 for a reply.

8. ARP cache and ARP table

An ARP cache stores IPv4-to-link-layer address mappings learned or configured by a host. It avoids repeated broadcasts for destinations whose mappings are already known.

On Windows, inspect the cache with:

arp -a

A more specific view can be obtained with:

arp -a -N 192.168.10.50

The interface address must match a local interface on the PC. If that command does not show what you need, use arp -a to inspect all available interface tables.

You can also use:

Get-NetNeighbor -AddressFamily IPv4

This PowerShell command shows neighbor entries, including their IP addresses, link-layer addresses, and states.

Common neighbor states include:

State General meaning
Reachable The neighbor is considered reachable
Stale A previously learned entry exists, but current reachability has not recently been confirmed
Delay The system is delaying further probing while waiting for upper-layer traffic to confirm reachability
Probe The system is actively probing to confirm reachability
Incomplete Address resolution has not yet completed
Permanent A static or permanent entry is configured

Exact state names and behavior depend on the operating system and networking implementation.

8.1 Clearing an ARP entry

In a controlled troubleshooting situation, an administrator may remove a stale or incorrect mapping so that the host performs fresh resolution.

For example, on Windows:

arp -d 192.168.10.20

Depending on the interface and operating-system configuration, elevated permissions may be required.

Use this carefully. Clearing a mapping does not repair a duplicate IP address, broken cable, incorrect VLAN, or faulty switch. It simply removes cached information so the host can resolve the address again.

9. Common MAC and ARP faults

9.1 Duplicate IPv4 addresses

Two devices using the same IPv4 address can cause intermittent or confusing communication failures.

Symptoms may include:

  • Communication working only intermittently.
  • A PLC appearing to disappear from an engineering PC.
  • Different MAC addresses being associated with the same IP address at different times.
  • ARP cache entries changing unexpectedly.
  • Duplicate-address warnings from devices or network tools.

When two devices respond to ARP requests for the same IPv4 address, hosts may learn different MAC addresses at different times. This can cause packets to reach the wrong device.

Corrective approach:

  1. Verify the intended IP assignment from the approved address plan.
  2. Compare the MAC address reported by the expected device with the address learned by the PC.
  3. Check device configuration records, DHCP reservations, and static assignments.
  4. Locate the conflicting device using authorized switch-management tools.
  5. Correct the duplicate assignment through the approved change process.

Do not resolve a suspected conflict by arbitrarily changing the PLC's IP address. It can disrupt HMI connections, SCADA communication, controller references, and other dependent equipment.

9.2 Stale ARP entries

A stale entry can remain after a device or interface has changed its MAC address. The host may temporarily send frames to the old address.

Possible causes include device replacement, network-interface replacement, virtual interface changes, or certain redundancy transitions.

Verify the current MAC address and the neighbor entry before clearing the cache. If the entry immediately becomes incorrect again, investigate the network rather than repeatedly deleting it.

9.3 Wrong subnet mask or default gateway

A host with an incorrect subnet mask may incorrectly classify a destination as local or remote.

  • If it incorrectly considers a remote device local, it may ARP for that device directly and receive no reply.
  • If it incorrectly considers a local device remote, it may try to send traffic to the default gateway instead.

Check the IP address, subnet mask, and gateway together. An IP address that looks correct in isolation is not enough.

9.4 VLAN mismatch

Two devices can be physically connected to the same switch yet be separated into different VLANs.

Broadcast ARP requests ordinarily remain within the same VLAN's Layer 2 broadcast domain. If the devices are in different VLANs, they normally cannot resolve each other's addresses directly through a shared Ethernet broadcast.

Check the access-port VLAN, trunk configuration, allowed VLANs, and Layer 3 routing arrangement.

9.5 Switch MAC-table problems

An Ethernet switch learns source MAC addresses from incoming frames and associates them with switch ports and VLANs.

If the table changes unexpectedly, traffic may be forwarded to an unexpected port or dropped according to the switch's security and forwarding behavior.

Potential causes include:

  • A device being moved to another port.
  • A loop or unstable Layer 2 topology.
  • MAC address flapping.
  • Incorrect VLAN membership.
  • Port security or MAC filtering.
  • A device or endpoint using a cloned MAC address.

ARP and switch MAC learning are related but separate processes. ARP resolves an IPv4 address to a MAC address, while the switch learns where that MAC address is reachable.

10. ARP versus DNS and DHCP

These protocols are often confused because they all help systems communicate, but they perform different jobs.

Protocol Main function Example
ARP Resolves IPv4 address to a local link-layer address 192.168.10.20 to a MAC address
DNS Resolves names to records, commonly IP addresses scada-server.example to an IP address
DHCP Provides network configuration to clients Assigns an IP address, subnet mask, gateway, and possibly DNS servers
ICMP Supports control and diagnostic messages Ping echo request and reply
IPv6 Neighbor Discovery Performs IPv6 neighbor and router discovery functions Resolves an IPv6 next-hop address to a link-layer address

ARP is for IPv4. IPv6 uses Neighbor Discovery Protocol (NDP), which operates using ICMPv6, instead of ARP.

A device can have a valid DHCP lease but still fail to communicate because of VLAN problems, a duplicate IP address, a missing ARP response, an incorrect route, or a blocked application service.

11. Security implications

ARP was designed primarily for address resolution on local networks, not strong authentication. Conventional ARP replies are not cryptographically authenticated.

An attacker with access to the same Layer 2 network may attempt ARP spoofing or ARP poisoning, in which false mappings associate a legitimate IP address with an attacker's MAC address.

Possible consequences include traffic interception, disruption, or redirection within the affected network.

Defensive measures include:

  • Segmenting operational technology networks into appropriate VLANs and security zones.
  • Restricting physical and logical access to industrial network ports.
  • Using managed-switch security features where supported and appropriately tested.
  • Considering Dynamic ARP Inspection and DHCP snooping in networks whose addressing and topology support them.
  • Monitoring unexpected MAC address changes and duplicate IP alerts.
  • Maintaining approved device-to-IP-to-MAC records.
  • Using authenticated and encrypted application protocols where available.

Dynamic ARP Inspection is not a universal drop-in fix. It depends on switch support, correct configuration, and a suitable trust model. Static IP devices and specialized industrial topologies require particular care.

12. Practical troubleshooting workflow

When a PC cannot communicate with a PLC or HMI on an IPv4 Ethernet network, follow a layered approach.

  1. Verify the physical link. Check link LEDs, cabling, interface status, and switch-port status.
  2. Check local configuration. Run ipconfig /all and verify the PC's IP address, subnet mask, and gateway.
  3. Check the destination. Confirm the PLC or HMI IP address from approved configuration records.
  4. Inspect ARP. Run arp -a or Get-NetNeighbor -AddressFamily IPv4.
  5. Compare MAC addresses. Confirm whether the learned MAC address matches the expected device.
  6. Test IP reachability. Use ping where permitted, remembering that ICMP can be blocked.
  7. Inspect the switch. Verify VLAN membership, port state, MAC learning, and relevant security counters.
  8. Test the application service. If the network path appears correct, test the required TCP port or inspect the relevant UDP traffic.
  9. Capture packets if needed. Use an authorized capture to determine whether ARP requests and replies are exchanged and whether subsequent application traffic follows.
  10. Record findings. Document the IP address, expected and observed MAC addresses, switch port, VLAN, timestamp, and corrective action.

Useful Windows commands

ipconfig /all

Displays interface configuration, including IPv4 address, subnet mask, gateway, and DHCP information.

arp -a

Displays the IPv4 ARP cache.

Get-NetNeighbor -AddressFamily IPv4

Displays IPv4 neighbor entries and their states.

ping 192.168.10.20

Tests ICMP reachability to the example address, subject to filtering and device configuration.

Test-NetConnection 192.168.10.20 -Port 502

Tests TCP connectivity to the example Modbus TCP port. It does not test ARP alone or verify that Modbus communication is functioning correctly.

13. Industrial maintenance examples

Example A: Engineering PC cannot find a PLC

The PC and PLC appear to be on the same subnet, but the engineering software reports a connection failure.

  • Verify the PC and PLC IP configuration.
  • Check whether an ARP entry exists for the PLC's IP address.
  • If no mapping appears, inspect the ARP request and response, VLAN membership, and physical link.
  • If a mapping exists, compare the MAC address with the PLC's expected interface address.
  • If the mapping is correct, proceed to transport and application-level diagnostics.

This prevents wasting time on PLC software when the actual problem is a Layer 2 or addressing fault.

Example B: Communication intermittently reaches the wrong device

Two devices may be configured with the same IPv4 address.

  • Observe the MAC address associated with the IP address over time.
  • Compare the learned address with the approved equipment record.
  • Check switch MAC tables to locate the relevant interfaces.
  • Identify and correct the duplicate assignment under the plant's change-control process.

A changing ARP mapping is an important clue, but it must be correlated with the device configuration and switch evidence.

Example C: A replacement PLC does not communicate

A replacement PLC may have a different MAC address from the old controller.

  • Confirm the replacement PLC's configured IP address.
  • Verify the physical switch port and VLAN.
  • Inspect the PC's neighbor cache.
  • Confirm that the expected device responds to ARP.
  • Test the actual application protocol once Layer 2 and IP connectivity are confirmed.

Do not assume a replacement device must have the same MAC address as the original controller. That depends on the hardware and configuration.

14. Interview questions and answers

Q1. What is a MAC address?

A link-layer address used for Ethernet frame delivery on a local network.

Q2. What is ARP?

Address Resolution Protocol maps an IPv4 address to a link-layer address, normally a MAC address on Ethernet.

Q3. Why does an ARP request use a broadcast destination?

The sender does not yet know the target's MAC address, so it broadcasts the request to the local broadcast domain.

Q4. Does ARP work across routers?

Ordinary ARP requests are not routed across IP networks. A host normally resolves the MAC address of its local next hop, often the default gateway, when the destination is remote.

Q5. What is the difference between ARP and a switch MAC table?

ARP maps an IPv4 address to a MAC address. A switch MAC table maps learned MAC addresses to switch ports and VLANs.

Q6. What happens if two devices use the same IP address?

Communication may become intermittent or reach the wrong device because multiple devices can respond to requests for the same IPv4 address.

Q7. Does a MAC address uniquely identify a physical device forever?

No. MAC addresses can be changed, locally administered, spoofed, virtualized, or replaced with a new interface.

Q8. What does arp -a show?

It displays the local system's IPv4 ARP cache entries.

Q9. Does IPv6 use ARP?

No. IPv6 uses Neighbor Discovery Protocol, based on ICMPv6, for related neighbor-resolution and discovery functions.

Q10. Can a device have the correct IP address and still fail to communicate?

Yes. Physical faults, VLAN separation, incorrect masks or gateways, ARP failures, routing problems, firewall rules, and application-level failures can all prevent communication.

Q11. What is ARP spoofing?

An attack in which false ARP information is supplied to associate an IP address with an incorrect MAC address.

Q12. Why is MAC-address documentation useful in maintenance?

It helps correlate an IP address with the expected interface and can assist with duplicate-address investigation, replacement-device verification, and switch-port tracing.

15. Final mental model

  • MAC address: Identifies the link-layer destination for local Ethernet frame delivery.
  • ARP: Finds the MAC address associated with a local IPv4 destination or next hop.
  • ARP cache: Stores recently learned IPv4-to-MAC mappings.
  • Switch MAC table: Helps a Layer 2 switch forward Ethernet frames toward learned destination ports.
  • Router: Forwards IP packets between networks and uses link-layer addressing appropriate to each outgoing link.
  • Duplicate IP: Can cause competing ARP responses and intermittent communication.
  • VLAN mismatch: Can prevent devices from exchanging ordinary local broadcast ARP requests.
  • IPv6: Uses Neighbor Discovery rather than ARP.

The practical diagnostic rule is to verify the expected IP-to-MAC mapping before moving up to TCP, UDP, or the application protocol. If the destination mapping or Layer 2 path is wrong, troubleshooting the PLC application first is simply troubleshooting the wrong layer.
