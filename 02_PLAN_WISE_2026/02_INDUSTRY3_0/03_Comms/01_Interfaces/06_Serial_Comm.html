1. Definition and purpose

Serial communication is a method of transferring data by transmitting bits sequentially over a communication channel. It is widely used in industrial automation because it can connect controllers, drives, CNC equipment, instruments, barcode readers, printers, and legacy devices with relatively simple wiring.

Serial communication defines how data bits are transmitted, but a complete working connection also needs electrical signaling, compatible communication settings, and an agreed protocol.

For example, an RS-485 connection between a PLC and a VFD may use Modbus RTU as its communication protocol. RS-485 defines the electrical interface, while Modbus RTU defines how requests, addresses, commands, and responses are organized. Confusing these layers is a reliable way to spend an afternoon diagnosing a perfectly healthy cable.

2. Serial communication versus parallel communication

Feature Serial communication Parallel communication
Data transfer Bits sent sequentially Multiple bits sent simultaneously
Signal conductors Often fewer Typically more
Cable complexity Usually lower Usually higher
Distance suitability Many serial interfaces suit longer links Timing skew limits many parallel links
Typical applications PLCs, drives, instruments, embedded systems Internal buses and short-distance interfaces
Main limitation Throughput and timing depend on interface and protocol More conductors and signal-timing complexity

Serial does not automatically mean slow. High-speed USB, PCI Express, and modern network links use serial signaling. The achievable speed depends on the electrical interface, encoding, clocking, cable, and protocol.

3. The layers of a serial connection

A reliable connection requires several compatible layers.

Layer What it defines Example
Physical interface Voltage levels, differential signaling, wiring RS-232, RS-422, RS-485
Bit transmission Timing and how bits are sampled UART asynchronous transmission
Framing Boundaries and interpretation of transmitted data Start bit, data bits, parity, stop bit
Protocol Addresses, commands, responses, errors Modbus RTU
Application Meaning of the data VFD speed reference or motor status

These layers are related but not interchangeable. A device can have a working RS-485 electrical connection and still fail to communicate because the protocol, baud rate, device address, or data format is incorrect.

4. Major serial communication modes

4.1 Asynchronous communication

Asynchronous serial communication sends each character or data unit without a continuously shared clock between the communicating devices. UART-based serial links commonly use this method.

A typical UART character contains:

Idle | Start | Data bits | Optional parity | Stop bit(s) | Idle
  • Idle: The line rests in its configured idle state.
  • Start bit: Indicates the beginning of a character.
  • Data bits: Carry the payload, commonly 7 or 8 bits.
  • Parity bit: Optional basic error-detection bit.
  • Stop bit(s): Mark the end of the character.

Both devices must agree on the framing configuration. A common configuration is 9600 baud, 8 data bits, no parity, 1 stop bit, abbreviated 9600 8N1.

4.2 Synchronous communication

Synchronous communication uses a clock or another defined timing mechanism to coordinate data sampling. The receiver uses that timing reference to determine when bits are valid.

Examples include SPI and I²C in embedded electronics. These are serial interfaces, but they are not electrically or operationally interchangeable with RS-232 or RS-485.

4.3 Simplex, half-duplex, and full-duplex

Mode Data direction Example
Simplex One direction only A one-way telemetry link
Half-duplex Both directions, but not simultaneously A typical two-wire RS-485 bus
Full-duplex Both directions simultaneously Four-wire RS-422 arrangements and many RS-232 links

The mode depends on the interface implementation and wiring, not merely on the fact that a connection is serial.

5. Baud rate, bit rate, and throughput

Baud rate is the number of signaling symbols transmitted per second. Bit rate is the number of bits transmitted per second. They are equal in a simple binary signaling system where each symbol represents one bit, but they are not universally identical.

For a UART configuration using 8N1, each 8-bit data byte generally requires 10 transmitted bits:

  • 1 start bit
  • 8 data bits
  • 1 stop bit

Ignoring additional protocol delays, the approximate maximum character throughput is:

\[ \text{Bytes per second} \approx \frac{\text{Baud rate}}{10} \]

At 9,600 baud:

\[ \frac{9600}{10} = 960\text{ bytes/s} \]

This is a theoretical estimate for continuous 8N1 traffic. Real application throughput is lower when protocol headers, device processing time, inter-frame gaps, polling, retries, and turnaround delays are included.

Common industrial settings include 1,200, 2,400, 4,800, 9,600, 19,200, 38,400, 57,600, and 115,200 baud, although device capabilities vary.

6. Common serial interfaces

Interface Signaling Typical characteristics Common uses
UART TTL/CMOS Single-ended logic levels Board-level communication; voltage depends on device Embedded controllers and modules
RS-232 Single-ended, bipolar signaling Usually point-to-point; limited cable length compared with differential links Legacy PLC ports, CNCs, instruments
RS-422 Differential signaling Good noise immunity; commonly one driver to multiple receivers Industrial equipment and longer links
RS-485 Differential signaling Supports multidrop buses; often half-duplex over two wires PLC networks, VFDs, meters
USB Differential signaling with its own protocol Host-controlled peripheral connection PCs, programming adapters, USB serial devices
SPI Clocked serial, usually multiple signals Short-distance, board-level peripheral bus Displays, converters, embedded hardware
I²C Clock and data lines Addressed board-level bus Sensors and integrated circuits
CAN Differential serial bus with arbitration and error handling Robust multi-node network Automotive and industrial control

A critical distinction: UART, RS-232, RS-422, and RS-485 are not synonyms. UART describes a common way to frame asynchronous serial data. RS-232, RS-422, and RS-485 specify electrical signaling characteristics. A UART can be connected to an RS-232 or RS-485 transceiver to communicate over the corresponding physical interface.

Also, USB is not simply another name for RS-232. A USB-to-serial adapter converts between a USB connection and a serial interface, usually exposing a virtual COM port to the PC.

7. RS-232, RS-422, and RS-485 in practical maintenance

7.1 RS-232

RS-232 is commonly found on older CNC machines, PLCs, drives, programming ports, and measurement equipment.

Practical points:

  • Usually connects two devices point-to-point.
  • Uses signal voltages different from ordinary 3.3 V or 5 V UART logic.
  • Common signal names include TXD, RXD, and signal ground.
  • Hardware flow control may use RTS/CTS or other control signals.
  • Connector shape alone does not guarantee the pinout or signal assignment.

A PC's legacy DB9 connector, for example, may use a common DTE pinout, but the equipment documentation must confirm the actual arrangement. Null-modem wiring may be required when connecting two DTE devices.

7.2 RS-422

RS-422 uses differential signaling, where the receiver evaluates the voltage difference between a pair of conductors. This generally improves immunity to common-mode noise compared with single-ended signaling.

It is useful for longer point-to-point or one-driver-to-multiple-receiver arrangements, subject to the applicable standard and device specifications.

7.3 RS-485

RS-485 is especially important in industrial automation because it supports multi-device buses. Many Modbus RTU installations use two-wire half-duplex RS-485.

Common wiring labels include:

  • A and B
  • D+ and D-
  • 485+ and 485-

Unfortunately, vendors do not always use A/B polarity labels consistently. Never assume the same label means the same polarity on every device. Check the manufacturer's documentation or verified wiring diagram.

RS-485 is an electrical interface, not a protocol. It can carry Modbus RTU or other proprietary protocols, provided all devices use compatible signaling and communication rules.

8. UART framing and serial parameters

Serial ports must agree on the settings required by the interface and protocol.

Parameter Meaning Typical fault when mismatched
Baud rate Signaling speed Corrupted characters, framing errors, timeouts
Data bits Number of payload bits per character Incorrect or corrupted data
Parity Optional character-level parity check Parity errors or rejected characters
Stop bits Character-ending timing Framing errors or unreliable reception
Flow control Regulates transmission based on receiver readiness Data loss or stalled transmission
Device address Identifies a device on a multidrop network No response or wrong device response
Protocol mode Defines message interpretation Valid bytes but meaningless commands

Common configurations include 8N1, 8E1, and 8O1.

  • 8N1: 8 data bits, no parity, 1 stop bit.
  • 8E1: 8 data bits, even parity, 1 stop bit.
  • 8O1: 8 data bits, odd parity, 1 stop bit.

Parity is not a substitute for a robust message-level integrity check. It can detect certain bit errors within a character but does not guarantee that an entire message has arrived correctly.

9. Data framing and error detection

A serial protocol typically groups transmitted bytes into messages or frames. The frame may include:

  • Start or synchronization information
  • Device address
  • Function or command code
  • Payload data
  • Length information
  • Error-detection field
  • End marker or timing-defined boundary

The exact format depends on the protocol. For example, Modbus RTU uses a defined message format and CRC-based error checking, with frame boundaries determined partly by timing on the serial line.

Error-detection methods

Method Purpose Limitation
Parity Detects certain single-character bit errors Does not reliably detect all errors
Checksum Calculates a value from message contents Detection strength depends on the algorithm
CRC Uses polynomial-based error detection Does not correct errors and is not a security mechanism
Timeout Detects a missing or late response Does not identify the root cause
Sequence number Helps identify missing or duplicated messages in protocols that support it Requires protocol-level implementation

Do not confuse error detection with error correction. Many industrial serial protocols detect corrupted messages and discard or retry them rather than repairing the data.

10. Industrial protocols carried over serial connections

Protocol or family Common physical interface Typical application
Modbus RTU RS-485 or RS-232 PLCs, VFDs, meters, temperature controllers
Modbus ASCII RS-232 or RS-485 Legacy or specialized serial installations
DF1 Commonly RS-232 or compatible serial hardware Allen-Bradley legacy PLC communication
Mitsubishi serial protocols Interface depends on PLC and module PLC programming or data exchange
Proprietary CNC protocols Equipment-dependent Program transfer, status data, machine integration
Barcode reader protocols Often RS-232, USB, or Ethernet Part identification and traceability

The physical interface, connector, and protocol must all be compatible. Two devices can both have DB9 connectors and still be unable to communicate because their pinouts, electrical standards, or protocols differ.

11. Wiring, grounding, shielding, and termination

Serial wiring is often the real source of a communication failure. The configuration screen tends to receive the blame because it is easier to click through than to inspect a cable.

11.1 Wiring principles

  • Confirm the exact electrical interface at both ends.
  • Verify transmit and receive connections for point-to-point links.
  • Check whether a straight-through or null-modem cable is required.
  • For RS-485, verify differential-pair polarity using the vendor's definitions.
  • Follow the specified signal-reference and grounding arrangements.
  • Use the cable type and maximum length specified by the equipment manufacturer and interface standard.
  • Separate low-level communication wiring from noisy motor and power wiring where practical.
  • Use shielding and bonding according to the equipment design and plant EMC practices.

11.2 RS-485 termination

Termination resistors reduce signal reflections on a transmission line. On an RS-485 bus, termination is normally applied at the two physical ends of the main bus, with the resistor value selected to match the cable's characteristic impedance and the interface design. A common value is around 120 ohms, but the actual cable and manufacturer guidance take priority.

Do not install a termination resistor at every device. Excessive termination can overload the bus and reduce signal amplitude.

11.3 Biasing

Biasing establishes a defined idle differential state when no driver is actively transmitting. Some devices include internal bias resistors; others require external biasing.

Multiple strong bias networks can overload the bus, so verify the design rather than adding resistors until the line appears to behave.

11.4 Topology

A daisy-chained bus is generally preferred for a conventional RS-485 multidrop network. Long stubs and star arrangements can create reflections and communication instability unless the hardware and topology specifically support them.

12. Serial communication in a PLC and VFD system

A common architecture is:

PLC serial port or communication module
        ↓
RS-485 differential pair
        ↓
VFD communication interface
        ↓
Modbus RTU request and response
        ↓
PLC program interprets register values
        ↓
Speed reference, run command, status and fault data

The details depend on the equipment. A PLC may use a built-in serial port, an expansion module, or a gateway. The VFD may expose holding registers, input registers, coils, or other protocol-defined data.

Typical data exchanged includes:

  • Run and stop commands
  • Speed or frequency reference
  • Actual output frequency
  • Motor current and status
  • Fault codes
  • Ready, running, warning, and trip states

Communication commands do not replace hardwired or safety-rated controls where required. A standard serial link should not be treated as an emergency-stop or personnel-protection circuit unless the complete system is specifically designed, validated, and certified for that safety function.

13. Serial-to-Ethernet gateways and converters

A gateway or converter can connect serial equipment to a computer or Ethernet network, but its capabilities vary.

Device type Function Important distinction
USB-to-RS-232 adapter Connects a PC USB port to RS-232 Usually creates a virtual COM port
USB-to-RS-485 adapter Connects a PC USB port to RS-485 May handle direction control and provide isolation
Serial device server Makes a serial port accessible over Ethernet May tunnel serial bytes without translating the protocol
Protocol gateway Converts between protocols or data models Requires explicit configuration and supported mappings
PLC communication module Adds a serial interface to a controller Depends on module capabilities and PLC configuration

Serial tunneling is not necessarily protocol conversion. A device server may simply transport serial data over TCP or UDP while preserving the original serial byte stream. A protocol gateway may instead parse messages and translate their meaning into another protocol.

Before selecting a device, confirm electrical interface, supported protocol, baud rates, isolation, operating temperature, mounting, power supply, configuration method, and recovery behavior after network or power failure.

14. Commissioning a serial communication link

Use a controlled sequence so that a fault can be isolated to a specific layer instead of changing five settings at once and learning nothing.

  1. Identify both endpoints. Record the device model, serial port type, connector, pinout, and supported protocol.
  2. Verify electrical compatibility. Confirm RS-232, RS-422, RS-485, or UART logic levels. Never connect incompatible signal levels directly.
  3. Inspect the wiring. Check conductor continuity, TX/RX crossover where applicable, RS-485 polarity, common reference requirements, shielding, and termination.
  4. Confirm port configuration. Set baud rate, data bits, parity, stop bits, and flow control to match the device.
  5. Confirm protocol settings. Check device address, command format, register map, operating mode, and any required permissions.
  6. Test with one device. Where possible, isolate the target from the multidrop network and test a single link.
  7. Send a valid request. Use the correct protocol, address, and command. Random characters on a terminal are not a valid test of every industrial protocol.
  8. Check the response. Inspect response bytes, error codes, timeouts, and device diagnostic indicators.
  9. Reconnect the full network. Verify operation with all devices connected and with the intended bus topology.
  10. Document the working configuration. Save wiring details, port settings, device addresses, protocol parameters, and test results.

15. Troubleshooting serial communication

Symptom Possible causes Diagnostic action
No response Wrong port, wiring fault, incorrect address, device offline Check power, port selection, wiring, address, and device status
Garbled characters Baud rate or framing mismatch, electrical noise Verify serial parameters and inspect signal quality
Intermittent communication Loose wiring, noise, poor termination, long stubs Inspect cable routing, connectors, grounding, and topology
One device works but another does not Duplicate address, incompatible settings, device-specific wiring Test devices individually and compare configurations
RS-485 works only over short distances Cable mismatch, termination or biasing problem, poor wiring Inspect cable specification, topology, termination, and biasing
PLC receives data but values are wrong Wrong register mapping, byte order, scaling, signedness Validate the protocol map and conversion logic
Communication stops after a restart Changed COM port, missing configuration, gateway startup issue Check assigned port, saved configuration, and startup sequence
CRC or framing errors Noise, timing mismatch, incorrect frame handling, damaged cable Confirm parameters, inspect wiring, and capture raw frames
Requests succeed but commands do not act Device mode, command permissions, interlocks, invalid command value Check drive or controller status and command requirements
Multiple devices respond incorrectly Address conflict or bus wiring problem Verify unique addresses and test the network in sections

15.1 A practical fault-isolation order

For a failed PLC-to-VFD Modbus RTU link, use this order:

  1. Check VFD power, communication settings, and fault status.
  2. Confirm the PLC port or communication module is configured correctly.
  3. Verify the correct serial interface and wiring.
  4. Confirm baud rate, parity, stop bits, and slave address.
  5. Check RS-485 polarity, termination, biasing, and cable topology.
  6. Inspect the request and response, including CRC and exception codes.
  7. Verify register addresses, data types, scaling, and command permissions.
  8. Check timeout and retry settings only after confirming the physical and protocol layers.

Changing the timeout from 500 ms to 5 seconds may hide a slow-response issue, but it will not repair reversed wiring or an incorrect device address.

16. Diagnostic tools

Tool Purpose Limitation
Digital multimeter Checks continuity, resistance, supply voltage, and basic electrical conditions Cannot fully characterize serial signal timing
USB-to-serial adapter Connects a PC to a compatible serial interface Adapter electrical standard must match the equipment
Serial terminal software Sends and receives raw serial data Does not automatically understand every protocol
Protocol master/client software Sends structured requests such as Modbus RTU Requires correct settings and device mapping
Oscilloscope Observes signal voltage and timing Requires correct probing and safe measurement practice
Differential probe Measures differential signaling more appropriately Availability and bandwidth may limit diagnosis
Serial protocol analyzer Captures and decodes communication frames Decoding depends on supported interfaces and protocols
PLC diagnostics Shows communication errors, status, and module faults Available details depend on the PLC and module

For a differential RS-485 signal, a multimeter may show a plausible voltage even when communication is failing. Dynamic signal problems generally require more suitable diagnostic equipment.

17. Maintenance, reliability, and documentation

Serial interfaces are often installed once and forgotten until a machine stops. Include them in normal automation maintenance rather than treating them as mysterious legacy wiring.

Preventive maintenance checklist

  • Inspect connectors, terminal blocks, cable glands, and cable damage.
  • Verify cable identification and device-address labels.
  • Check for loose conductors and signs of corrosion.
  • Inspect communication cables near VFD output cables, contactors, and other noise sources.
  • Confirm termination and biasing against the approved network design.
  • Review PLC, VFD, CNC, and gateway diagnostic logs.
  • Check for recurring retries, timeouts, CRC errors, and intermittent-device faults.
  • Verify that replacement adapters and communication modules use compatible interfaces.
  • Preserve known-good port settings, register maps, and gateway configurations.
  • Test communication after repairs, module replacement, or wiring changes.

Recommended configuration record

Field Example of recorded information
Equipment identification PLC panel, VFD tag, CNC machine number
Physical interface RS-232 or two-wire RS-485
Protocol Modbus RTU or vendor-specific protocol
Serial settings Baud rate, data bits, parity, stop bits
Addressing Device or slave address
Wiring Cable type, terminal numbers, connector pinout
Network design Bus topology, termination, biasing
Data mapping Register addresses, data types, scaling
Diagnostics Timeout, retries, error history
Change control Approved revision, date, responsible person

18. Safety and cybersecurity considerations

  • Isolate electrical power and follow the site's lockout/tagout procedure before modifying wiring where hazardous energy may be present.
  • Confirm that the equipment's communication terminals are not connected to hazardous potentials before handling them.
  • Use galvanically isolated adapters or repeaters where the installation design, ground potential differences, or manufacturer instructions require them.
  • Do not connect an ordinary PC or USB adapter directly to industrial terminals without confirming the electrical interface and signal levels.
  • Do not assume serial communication is secure because it is physically wired. Many legacy protocols lack authentication and encryption.
  • Restrict access to programming ports, gateways, and maintenance laptops.
  • Do not use ordinary serial commands as substitutes for required safety-rated control circuits.

19. Common interview questions and answers

1. What is serial communication?

A method of transferring data sequentially over a communication channel, using an agreed signaling method, timing arrangement, and data format.

2. What is the difference between UART and RS-485?

UART commonly defines asynchronous data framing and timing. RS-485 defines electrical signaling for differential serial communication. A UART can connect to an RS-485 transceiver.

3. What is the difference between baud rate and bit rate?

Baud rate measures symbols per second; bit rate measures bits per second. They are equal only when each symbol represents one bit.

4. Why is RS-485 widely used in industrial automation?

It supports differential signaling, good noise immunity, and multidrop bus arrangements suitable for connecting multiple industrial devices.

5. What is the difference between two-wire and four-wire RS-485?

Two-wire RS-485 commonly uses one differential pair for half-duplex communication. Four-wire arrangements use separate transmit and receive pairs and can support full-duplex operation when the equipment is designed for it.

6. What does 8N1 mean?

Eight data bits, no parity, and one stop bit. With a start bit, each transmitted character normally occupies ten bit times.

7. What is the purpose of an RS-485 termination resistor?

It matches the transmission line at the bus ends to reduce signal reflections. The value and placement must suit the cable and network design.

8. Why can a serial connection fail even when the cable has continuity?

Continuity does not verify correct pinout, signal levels, polarity, baud rate, protocol, device addressing, signal quality, or timing.

9. What is Modbus RTU?

An industrial communication protocol commonly carried over serial interfaces such as RS-485. It defines device addressing, function codes, data fields, and CRC-based message checking.

10. Does a serial-to-Ethernet converter always translate protocols?

No. A serial device server may tunnel serial bytes over a network. A protocol gateway translates between supported protocols or data models.

11. Why should every device on a multidrop network have a unique address?

Address conflicts can cause incorrect responses or communication collisions, depending on the protocol and network behavior.

12. What should be checked first when a PLC cannot communicate with a VFD?

Confirm that both devices are powered and configured for compatible interfaces, then check wiring, serial settings, device address, and protocol configuration.

20. Practical exercises

  1. Identify the interface: Inspect a PLC, CNC, or VFD manual and identify its serial ports, supported electrical standards, pinout, and protocols.
  2. Calculate throughput: For a 19,200-baud 8N1 link, estimate the theoretical maximum character throughput as \(19200 / 10 = 1920\) bytes per second, before protocol overhead.
  3. Build a settings sheet: Record baud rate, data bits, parity, stop bits, flow control, address, and protocol for a selected device.
  4. Analyze a failed connection: Given a timeout, create a fault tree covering power, interface compatibility, wiring, framing, addressing, protocol, and device state.
  5. Inspect a Modbus RTU setup: Identify the master, slave addresses, RS-485 bus topology, termination arrangement, register map, and CRC diagnostics.
  6. Compare gateway types: Determine whether a proposed serial-to-Ethernet product tunnels bytes or actually translates protocols.
  7. Create a maintenance record: Document the verified wiring, communication settings, test results, and recovery procedure for a real serial link.

21. Final mental model

Remember serial communication as five connected questions:

  • Physical layer: What electrical interface carries the signal?
  • Transmission: How are the bits timed and framed?
  • Configuration: Do both devices use compatible settings?
  • Protocol: How are addresses, commands, responses, and errors represented?
  • Application: What do the received values mean, and what should the equipment do with them?

A reliable serial connection requires all five to agree. A good technician diagnoses each layer systematically instead of replacing the communication module simply because the machine has stopped talking.
