1. Definition and purpose

Word order is the sequence in which multi-word data values are arranged or interpreted when a communication system transfers, stores, or reconstructs them.

In industrial communication, a word commonly means a 16-bit unit, although the term can mean different sizes in different platforms. A 32-bit value typically contains two 16-bit words, while a 64-bit value typically contains four 16-bit words.

Word order matters when a PLC, VFD, energy meter, CNC controller, SCADA system, gateway, or software application exchanges values that span multiple registers.

For example, a device may report a 32-bit value using two 16-bit Modbus registers. The communication can succeed, both registers can contain valid data, and yet the final number can be wrong because the receiver combines the registers in the wrong order.

2. Word order versus byte order

These concepts are related, but they are not interchangeable.

  • Byte order describes the arrangement of bytes within a multi-byte value or data unit.
  • Word order describes the arrangement of the words that make up a larger value.
  • Data type defines how the reconstructed bits are interpreted, such as an integer or floating-point value.
  • Scaling converts a correctly interpreted raw value into an engineering value, such as amperes or rpm.

Consider a 32-bit value represented by four bytes:

Logical 32-bit value: 0x12345678

High word: 0x1234
Low word:  0x5678

Each 16-bit word contains two bytes:

High word:  0x12 0x34
Low word:   0x56 0x78

If the bytes inside each word remain in the same order but the two words are exchanged, the resulting byte sequence changes from 12 34 56 78 to 56 78 12 34.

That is a word swap, not a byte swap.

Property Byte order Word order
Unit being rearranged Bytes Words, commonly 16-bit
Typical scope Bytes inside a data value or word Multiple words forming one value
Example transformation 12 34 becomes 34 12 1234 5678 becomes 5678 1234
Common symptom Incorrect interpretation of a register or multi-byte value Incorrect 32-bit or 64-bit value
How to verify Compare byte sequences Compare register sequence

Important: Do not assume every vendor uses the word word to mean exactly 16 bits. Confirm the data representation in the relevant device and software documentation.

3. High word and low word

For a 32-bit hexadecimal value 0x12345678, divide the value into two 16-bit sections.

32-bit value: 0x12345678

Bits 31 to 16: 0x1234  → High word
Bits 15 to 0:  0x5678  → Low word

The high word contains the more significant 16 bits. The low word contains the less significant 16 bits.

The numeric value represented by this bit pattern is:

\[ 0x12345678 = 305419896 \]

If the receiver reverses the two words, it reconstructs:

Received word 1: 0x5678
Received word 2: 0x1234

Combined value:  0x56781234
Decimal value:   1450709556

Both registers can be read correctly. The error occurs when the receiver assigns the registers to the wrong parts of the 32-bit value.

4. Common word-order arrangements

Suppose a device defines a 32-bit value using four logical bytes:

A = 0x12
B = 0x34
C = 0x56
D = 0x78

The following arrangements are commonly encountered when configuring multi-register values.

Arrangement Byte sequence Operation
ABCD 12 34 56 78 Original sequence
BADC 34 12 78 56 Swap bytes within each 16-bit word
CDAB 56 78 12 34 Swap the two 16-bit words
DCBA 78 56 34 12 Reverse the complete byte sequence

The CDAB arrangement is the classic example of a word swap when each 16-bit word's internal byte order remains unchanged.

The BADC arrangement is primarily a byte swap within each word. DCBA reverses the complete sequence, changing both the internal byte order and the order of the words.

These labels are useful shorthand, but manufacturers and software libraries may define their settings differently. Verify the documented behavior rather than relying on a label alone.

5. Word order in Modbus communication

Modbus commonly represents data as 16-bit registers. A 32-bit value therefore occupies two consecutive registers, and a 64-bit value typically occupies four.

Modbus defines the byte transmission order within a 16-bit register: the most significant byte is sent first. However, the order in which multiple registers represent one larger value is not universally fixed across all devices. The device's register map must specify the arrangement.

5.1 Example: Two holding registers

Suppose a device exposes a 32-bit unsigned integer:

Logical value: 0x12345678

Register A: 0x1234
Register B: 0x5678

If the device uses high-word-first order, the receiver reads:

Register at address N:     0x1234
Register at address N + 1: 0x5678

Reconstructed value:       0x12345678

If the device uses low-word-first order, the register sequence may instead be:

Register at address N:     0x5678
Register at address N + 1: 0x1234

Reconstructed value:       0x12345678

The receiver must know which arrangement the device uses.

5.2 Why register addresses matter

Even a correct word-order setting cannot repair an incorrect starting address or register pairing.

For example, if a 32-bit value occupies registers N and N+1, reading N+1 and N+2 does not produce the intended value. The resulting number may look like a word-order issue, but the actual fault is the register mapping.

Also distinguish the address notation in a manufacturer's manual from the offset expected by a communication library. Some manuals use reference numbers such as 40001, while software commonly uses zero-based register offsets. The conventions vary.

6. Word order with FLOAT32 values

A 32-bit floating-point value, often called FLOAT32 or REAL, is widely used for industrial measurements.

Consider the number 230.0, which has the IEEE 754 single-precision representation:

Decimal value: 230.0
32-bit pattern: 0x43660000

High word: 0x4366
Low word:  0x0000

If the device uses high-word-first order:

Register 1: 0x4366
Register 2: 0x0000
Combined:   0x43660000
Decoded:    230.0

If the device uses low-word-first order:

Register 1: 0x0000
Register 2: 0x4366

A receiver that incorrectly assumes high-word-first order may reconstruct 0x00004366 instead of 0x43660000. Interpreted as FLOAT32, that is a very different number.

This example assumes the byte order within each register is already correct. If the bytes within each register are also reversed, the result changes again.

6.1 Symptoms of incorrect word order

  • Voltage or current values that are wildly different from the instrument display.
  • FLOAT32 values that appear extremely small or extremely large.
  • A measurement that appears invalid despite successful communication.
  • A 32-bit counter that changes by implausible amounts.
  • A value that is correct in the device's configuration software but wrong in SCADA.
  • Correct 16-bit values but incorrect combined 32-bit values.

Do not immediately blame the floating-point calculation. Verify the raw register sequence and the intended representation first.

7. Word order with signed and unsigned integers

Word order also affects integers. It is not a floating-point-only issue.

Consider the 32-bit pattern 0x00010000.

High word: 0x0001
Low word:  0x0000

As an unsigned 32-bit integer, the correct value is 65536.

If the words are reversed, the reconstructed pattern becomes 0x00000001, which represents 1.

Intended 32-bit pattern Correct decimal value Value after word swap
0x00010000 65536 1
0x00000001 1 65536
0x12345678 305419896 1450709556
0x00020000 131072 2

For signed 32-bit integers, the same reconstructed bit pattern is interpreted using two's-complement signed representation. A word-order error can therefore produce an incorrect magnitude or even a negative result.

The receiver must get all three things right:

  1. Register addresses and pairing.
  2. Word and byte order.
  3. Data type and signedness.

8. Word order in 64-bit values

A 64-bit value typically occupies four 16-bit registers.

Suppose the logical bit pattern is:

64-bit value:
0x1122334455667788

Word 1: 0x1122
Word 2: 0x3344
Word 3: 0x5566
Word 4: 0x7788

A device might expose the words in the same order:

1122 → 3344 → 5566 → 7788

Another device might expose them in reverse word order:

7788 → 5566 → 3344 → 1122

Other arrangements may be possible depending on the device's data format. A 64-bit value cannot safely be interpreted by assuming that a two-register swap setting will always cover every case.

For 64-bit counters, timestamps, energy totals, and FLOAT64 measurements, document the complete four-word sequence and verify it with a known test value.

9. Configuring word order in PLCs, gateways, and SCADA

Word order may be configured through communication drivers, data conversion instructions, tag properties, or gateway settings.

Common setting names include:

  • High word first.
  • Low word first.
  • Word swap.
  • Swap 16-bit words.
  • ABCD, BADC, CDAB, or DCBA.
  • Swap words or swap bytes and words.

The exact behavior depends on the platform. One setting may apply to a complete 32-bit value; another may operate on a particular data type or buffer. Confirm the manufacturer's documentation.

9.1 PLC integration

When a PLC reads a 32-bit value from an external device:

  1. Read the documented register range.
  2. Store or inspect the raw 16-bit registers.
  3. Verify the high-word and low-word assignment.
  4. Apply the correct conversion to the target data type.
  5. Compare the result with the source device's display or documented test value.

Do not assume that the order used by one PLC manufacturer matches the conventions of another. A retrofit from one PLC platform to another should explicitly verify register order and data type.

9.2 Gateway and SCADA integration

A typical data path is:

Instrument / VFD / PLC
    ↓
Modbus registers
    ↓
Communication driver or gateway
    ↓
Word-order reconstruction
    ↓
Correct data type and engineering value
    ↓
SCADA / OPC UA / database / dashboard

The conversion should ideally be performed once at a clearly defined layer. If both a gateway and SCADA apply word swapping, the two transformations may cancel each other or produce another incorrect representation.

Document which component owns the conversion, and verify values at that boundary.

10. Troubleshooting word-order faults

Symptom Likely cause Verification
Two registers read correctly but the 32-bit value is wrong Incorrect word order Compare the raw registers with the device specification
FLOAT32 is extremely small or large Wrong word order, byte order, or data type Reconstruct the exact 32-bit pattern
A counter is incorrect by a large factor Word swap or wrong register pairing Check all registers in the documented sequence
One device works but another does not Different manufacturer-specific register formats Compare both register maps
Vendor software shows the right value but SCADA does not Incorrect driver or tag conversion Compare raw data at the device and SCADA boundaries
Values are inconsistent across scans Incorrect register addresses, non-atomic reads, or changing source data Check the register range and device update behavior
The value is consistently ten times too large Possible scaling error rather than word order Verify scaling independently
A 64-bit value is incorrect Wrong register sequence or incomplete data reconstruction Verify all four words and the data type

10.1 Recommended diagnostic procedure

  1. Confirm communication: Verify that the device responds and the correct registers are being read.
  2. Capture raw values: Record every register in hexadecimal.
  3. Check the data type: Establish whether the value is UINT32, INT32, FLOAT32, or another type.
  4. Check word order: Determine which register contains the high word and which contains the low word.
  5. Check byte order: Verify the byte sequence inside each register.
  6. Check the conversion layer: Confirm whether the PLC, gateway, driver, or SCADA system performs the reconstruction.
  7. Compare against a known value: Use a documented test value or the instrument's local display.
  8. Verify downstream systems: Confirm the resulting value in SCADA, SQL, trends, alarms, and dashboards.

When the expected value is known, test the documented arrangement first. Randomly switching conversion settings until a plausible number appears is not a reliable commissioning method.

11. Industrial applications

11.1 VFD integration

A VFD may expose 32-bit parameters for speed feedback, accumulated operating time, energy, or other measurements.

If the PLC reads the registers successfully but the displayed speed is unreasonable, verify the parameter's data type, register addresses, word order, and scaling.

11.2 Energy meters

Meters commonly expose voltage, current, power, energy, and accumulated counters. Some measurements use FLOAT32 or 32-bit integers, while others use 64-bit values.

When replacing a meter, do not copy the old driver's word-order setting without checking the new meter's register map.

11.3 CNC and machine data collection

A CNC or machine interface may transfer counters, measurement values, status words, or custom data structures. Where a communication gateway reconstructs multi-register values, confirm that the gateway's interpretation matches the controller's documented format.

11.4 SQL and dashboard integration

If a wrong value enters the data collection layer, SQL Server and Grafana may faithfully store and plot it. They generally cannot determine whether the original register sequence was interpreted correctly.

Verify the engineering value before storing it, and retain raw register data where practical for troubleshooting and traceability.

12. Documentation and maintenance checklist

For every multi-register parameter, record:

  • Device manufacturer and model.
  • Communication protocol and device address.
  • Register reference and software offset convention.
  • Number of registers occupied by the value.
  • Data type and signedness.
  • Byte order within each register.
  • Word order across registers.
  • Scaling factor and engineering unit.
  • Valid range and special-value definitions.
  • Location of the conversion logic.
  • Verified raw data and expected engineering value.
  • Configuration backup and date of last validation.

For a retrofit, compare the old and replacement devices field by field. Preserve the existing configuration before changing settings, test the new mapping in an approved environment, and verify any alarms or control calculations that depend on the converted value.

13. Interview questions and answers

Q1. What is word order?

Word order is the sequence in which multiple words are arranged or interpreted to reconstruct a larger data value.

Q2. What is the difference between high-word-first and low-word-first?

High-word-first places the most significant word before the least significant word. Low-word-first places the least significant word first.

Q3. Does Modbus define a universal word order for 32-bit values?

No. Modbus defines the byte transmission order within a 16-bit register, but the arrangement of multiple registers used to form larger values must be confirmed from the device specification.

Q4. How does a word-order fault differ from a byte-order fault?

A word-order fault exchanges the positions of words in a multi-word value. A byte-order fault changes the arrangement of bytes. They can occur independently or together.

Q5. Why can a 32-bit integer be wrong when both registers are correct?

The receiver may combine the registers in the wrong order, producing a different 32-bit bit pattern.

Q6. How do you diagnose an incorrect FLOAT32 reading?

Capture the raw registers, verify the register addresses and data type, confirm byte and word order, and compare the decoded value with a trusted reference.

Q7. Can word order affect signed integers?

Yes. Changing the order of the words changes the complete bit pattern, which can alter both the magnitude and the sign when interpreted as a signed integer.

Q8. How many 16-bit registers are required for a 64-bit value?

Four registers, assuming the value is represented as four consecutive 16-bit words.

Q9. Where should word-order conversion occur?

At a clearly documented layer, such as the PLC, communication driver, gateway, or SCADA system. Avoid duplicate conversion across multiple layers.

Q10. What is the most important practice during commissioning?

Verify the raw register values and compare the reconstructed value against the device specification or a known source value.

14. Practical exercises

Exercise 1: Reconstruct a 32-bit integer

Two registers contain:

Register N:     0x5678
Register N + 1: 0x1234

Assuming the first register is the low word, reconstruct the value.

Answer: 0x12345678, which is 305419896 as an unsigned 32-bit integer.

Exercise 2: Identify a word swap

A device is expected to report 65536, represented by 0x00010000. The receiver displays 1.

The likely explanation is that the high and low 16-bit words have been exchanged:

Expected: 0x0001 0000
Received: 0x0000 0001

Confirm the raw registers before changing the configuration.

Exercise 3: Diagnose a voltage measurement

An energy meter displays 230.0 V, but SCADA displays an implausible value.

Prepare a checklist covering:

  • Register addressing.
  • Register count.
  • FLOAT32 interpretation.
  • Byte order.
  • Word order.
  • Scaling and engineering units.
  • Gateway and SCADA conversion settings.

Exercise 4: Prepare a retrofit specification

Choose a VFD or energy meter used in an industrial installation. Document one multi-register parameter, including its address, data type, register count, byte order, word order, scaling, and expected engineering value. Use a known source value to validate the configuration.

15. Final mental model

Read the correct registers
    ↓
Identify the data type
    ↓
Determine byte order within each word
    ↓
Determine word order across registers
    ↓
Reconstruct the complete bit pattern
    ↓
Interpret signedness and data type
    ↓
Apply scaling and engineering units
    ↓
Validate against a known value

The central lesson is that word order determines how multiple registers are combined into one value. Correct communication, correct register addresses, correct byte order, correct word order, correct data type, and correct scaling are separate requirements. All must be verified before the value is trusted.
