1. Definition and purpose

IP addressing is the method used to identify devices and network interfaces so that Internet Protocol (IP) packets can be delivered across an IP network.

In industrial automation, IP addressing allows PLCs, HMIs, SCADA computers, engineering workstations, remote I/O adapters, VFDs, robots, CNC machines, OPC servers, and industrial gateways to communicate over Ethernet networks.

An Ethernet connection alone does not guarantee IP communication. Devices may be physically connected but unable to communicate because of incorrect IP addresses, subnet masks, gateways, VLANs, firewall rules, or duplicate addresses.

IP addressing is a fundamental part of troubleshooting industrial Ethernet systems.

2. Where IP addressing fits in the network

Industrial application
PLC logic / HMI / SCADA / OPC UA
            ↓
Transport layer
TCP / UDP
            ↓
Network layer
IPv4 / IPv6 addressing and routing
            ↓
Data-link layer
Ethernet frames / MAC addresses
            ↓
Physical layer
Copper cable / fiber / Ethernet ports

This is a simplified view of the TCP/IP networking stack. The key distinction is that IP addresses identify network interfaces at the network layer, while MAC addresses identify interfaces at the Ethernet data-link layer.

For example, a PLC might have:

  • IP address: 192.168.10.20
  • Subnet mask: 255.255.255.0
  • Default gateway: 192.168.10.1
  • MAC address: a hardware or interface identifier assigned to its Ethernet adapter

The IP address helps determine where an IP packet should be delivered. The MAC address is used to deliver Ethernet frames across the local network segment.

3. IPv4 address structure

IPv4 uses a 32-bit address, normally written as four decimal numbers separated by periods. Each number is an octet and ranges from 0 to 255.

Example:

192.168.10.20

The four octets correspond to 32 bits:

192        .168        .10         .20
11000000   10101000    00001010    00010100

Each octet contains 8 bits, so the complete address contains 32 bits.

An IP address is not inherently divided into a fixed network part and host part based on the first octet. The subnet mask or prefix length determines which bits represent the network prefix and which bits identify addresses within that subnet.

For example, 192.168.10.20/24 means that the first 24 bits form the network prefix, leaving 8 bits for addresses within the subnet.

4. Private and public IPv4 addresses

Industrial networks commonly use private IPv4 addresses. These are intended for internal networks and are not directly routable across the public internet.

The three private IPv4 ranges are:

Private range CIDR notation Common use
10.0.0.0 to 10.255.255.255 10.0.0.0/8 Large enterprise and plant networks
172.16.0.0 to 172.31.255.255 172.16.0.0/12 Segmented corporate and industrial networks
192.168.0.0 to 192.168.255.255 192.168.0.0/16 Small networks and machine-level cells

A device using a private address may still communicate with other networks through routing, a firewall, or network address translation (NAT), when configured. Private addressing does not automatically provide isolation or security.

4.1 Common address categories

Address type Example Meaning
Private address 192.168.10.20 Internal network address
Loopback address 127.0.0.1 Refers to the local host
Link-local address 169.254.10.20 Commonly used for IPv4 self-assigned addressing when DHCP configuration fails
Limited broadcast 255.255.255.255 Broadcast on the local network, subject to host and network behavior
Network address 192.168.10.0/24 Identifies the subnet, not an ordinary host address
Directed broadcast 192.168.10.255/24 Broadcast address for this example subnet, normally restricted by routers

A device using a 169.254.x.x address may have failed to obtain its intended DHCP configuration. In a static industrial network, it can also indicate that the device was connected without a valid configured address. Always confirm the device's addressing method and expected network.

5. Static IP versus DHCP

There are two common ways to assign an IP address.

5.1 Static IP addressing

A static IP is manually configured and remains unchanged until an administrator or configuration process changes it.

Common industrial applications include:

  • PLC Ethernet interfaces.
  • Fixed-address remote I/O adapters.
  • Robot controllers and CNC Ethernet interfaces.
  • VFD communication adapters.
  • HMI panels.
  • SCADA servers and industrial gateways.

Advantages include predictable addressing and easier documentation of machine configurations.

Risks include duplicate addresses, configuration errors, and address conflicts when equipment is replaced or moved.

5.2 DHCP addressing

Dynamic Host Configuration Protocol (DHCP) allows a DHCP server to provide IP configuration to clients, typically including an address, subnet mask, lease duration, and optional gateway and DNS information.

DHCP is common on office networks, laptops, and some managed industrial networks. Industrial use depends on the device capabilities and the plant's network design.

A DHCP reservation can associate a device identifier with a predictable address, but the actual behavior depends on the DHCP server and client.

5.3 Comparison

Property Static IP DHCP
Assignment Manually configured Assigned by a DHCP server
Address predictability Predictable when managed correctly Depends on leases and reservation policy
Duplicate-address risk High if manually managed poorly Reduced by coordinated server allocation, but not impossible
Typical industrial use Fixed automation equipment Managed networks and supported devices
Maintenance requirement Maintain an address register Maintain DHCP scopes, reservations, and lease policies

Important: Do not change a production PLC, robot, or drive from static addressing to DHCP simply to make it easier to connect. The device, control architecture, and plant network policy must support the change.

6. IP address, subnet mask, and default gateway

These three settings must be understood together.

6.1 IP address

The IP address identifies a network interface within the IP addressing plan.

Example: 192.168.10.20

6.2 Subnet mask

The subnet mask identifies which bits belong to the network prefix and which bits identify addresses within that subnet.

Example: 255.255.255.0, equivalent to /24.

For 192.168.10.20/24, the network is 192.168.10.0/24.

6.3 Default gateway

The default gateway is the router IP address that a host uses to reach destinations for which it has no more specific route.

Example: 192.168.10.1

For a device at 192.168.10.20/24, the gateway is commonly configured as 192.168.10.1, assuming a router interface exists at that address on the same subnet.

A gateway is not automatically required for communication between devices on the same subnet. It is needed when the device must send traffic to destinations outside its directly connected network and no other suitable route exists.

6.4 Example configuration

Device IP address Subnet mask Default gateway
PLC 192.168.10.20 255.255.255.0 192.168.10.1
HMI 192.168.10.30 255.255.255.0 192.168.10.1
Engineering PC 192.168.10.40 255.255.255.0 192.168.10.1
Router interface 192.168.10.1 255.255.255.0 Configured according to router design

All three end devices are in the same /24 subnet. They can normally communicate directly at the IP layer if the interfaces, VLAN, Ethernet connectivity, and host or device settings permit it.

7. Network prefix and CIDR notation

CIDR stands for Classless Inter-Domain Routing. It represents the network prefix using a slash followed by the number of prefix bits.

Examples:

CIDR notation Subnet mask Total IPv4 addresses
/8 255.0.0.0 16,777,216
/16 255.255.0.0 65,536
/24 255.255.255.0 256
/25 255.255.255.128 128
/26 255.255.255.192 64
/27 255.255.255.224 32
/28 255.255.255.240 16
/30 255.255.255.252 4
/32 255.255.255.255 1 address

For conventional IPv4 subnets, the number of host addresses available for ordinary host assignment is generally the total address count minus the network and broadcast addresses. Special-purpose prefixes and point-to-point designs have exceptions.

Subnetting will be covered in the next topic. For now, remember that /24 means 24 network-prefix bits and 8 remaining bits.

8. Same-subnet communication versus routed communication

When an IP host sends data, it determines whether the destination belongs to a directly connected network based on its IP address, prefix or subnet mask, and routing table.

  • If the destination is on the same subnet, the host normally sends the Ethernet frame directly to the destination's MAC address.
  • If the destination is on another network, the host sends the frame to the next-hop router's MAC address.
  • The IP packet retains its source and destination IP addresses as it passes through ordinary routers, although network address translation or other mechanisms may change them.
  • The Ethernet source and destination MAC addresses are replaced as the packet traverses routed Ethernet segments.

Example:

PLC: 192.168.10.20/24
HMI: 192.168.10.30/24
            ↓
Same subnet
            ↓
Direct local Ethernet communication

PLC: 192.168.10.20/24
SCADA server: 192.168.20.50/24
            ↓
Different subnets
            ↓
A valid route and permitted network path are required

A PLC and SCADA server on different subnets may communicate successfully if routing, return routes, firewall rules, and application settings are correct. A different subnet does not automatically mean communication is impossible.

9. IP addresses and MAC addresses

An IP address and a MAC address perform different jobs.

Property IP address MAC address
Networking layer Network layer Data-link layer
Purpose Logical addressing and routing Local-link frame delivery
Example 192.168.10.20 00:1A:2B:3C:4D:5E
Assignment Static, DHCP, or other configuration Usually assigned to an interface, with possible overrides
Changes across a routed path IP addresses usually remain the same, absent translation Ethernet frame addresses change at each routed link

The MAC address example is illustrative, not a real device identity.

9.1 ARP

Address Resolution Protocol (ARP) resolves an IPv4 address to a link-layer address on a local Ethernet network.

If a PLC needs to send a packet directly to another device on the same subnet, it may use ARP to discover the destination MAC address.

If the PLC needs to reach a remote subnet, it normally resolves the MAC address of its next-hop gateway instead.

An ARP failure can cause IP communication to fail even when the IP address and subnet mask look correct.

10. TCP, UDP, ports, and IP addressing

IP addressing identifies the network interfaces involved in communication. TCP and UDP use port numbers to identify transport-layer endpoints.

For example:

  • IP address: 192.168.10.20
  • TCP port: 44818
  • Application: EtherNet/IP explicit messaging or related services using that port, depending on the communication type

Common industrial ports include:

Protocol or service Common port Transport
HTTP 80 TCP
HTTPS 443 TCP
Modbus TCP 502 TCP
OPC UA TCP 4840 TCP, commonly
EtherNet/IP explicit messaging 44818 TCP
EtherNet/IP messaging and discovery 44818 UDP
EtherNet/IP I/O 2222 UDP, commonly
PROFINET real-time communication No single universal TCP/UDP port Ethernet-based real-time communication, depending on service

These are common defaults, not guarantees for every installation. Devices may use additional ports or configurable services.

Important distinction: Successful ping replies do not prove that an industrial protocol is working. ICMP ping tests IP reachability, not whether the required TCP or UDP port, application service, PLC connection, or real-time I/O exchange is healthy.

11. IP addressing in industrial Ethernet protocols

Industrial Ethernet protocols may use IP addressing in different ways.

11.1 EtherNet/IP

EtherNet/IP commonly uses standard IPv4 networking for device addressing and uses CIP for industrial communication.

Typical checks include:

  • IP address, subnet mask, and gateway.
  • Duplicate IP addresses.
  • Correct device path and target address in the PLC configuration.
  • Required TCP/UDP services and firewall rules.
  • Correct I/O connection configuration, including connection parameters and requested packet interval where applicable.

11.2 Modbus TCP

Modbus TCP uses an IP address to locate the server or device and TCP port 502 by default.

A successful ping does not prove that the Modbus TCP server is listening, that the register map is correct, or that the requested data is valid.

11.3 PROFINET

PROFINET devices commonly use IP addressing for configuration, diagnostics, and other services. Real-time PROFINET communication can use Ethernet Layer 2 mechanisms rather than ordinary TCP/UDP transport.

Some PROFINET device discovery and naming procedures use a device name and configuration tools. An IP address alone may not complete device commissioning.

11.4 OPC UA

OPC UA clients connect to a server endpoint that includes a host address or name, a port, and an endpoint path. A working IP connection is only one requirement; endpoint configuration, certificates, authentication, and access rights may also matter.

12. Industrial network design and address planning

A structured IP addressing plan makes commissioning and maintenance significantly easier.

Example plant addressing scheme:

Network segment Example subnet Example equipment
Machine cell A 192.168.10.0/24 PLCs, local HMI, machine devices
Machine cell B 192.168.20.0/24 Separate machine or production cell
SCADA services 192.168.30.0/24 SCADA and data collection servers
Engineering access 192.168.40.0/24 Approved engineering workstations
Network management 192.168.50.0/24 Managed switches and network infrastructure

These are example ranges only. Actual network segmentation must follow the plant's approved design and address register.

12.1 Recommended address register

For each device, document:

  • Device name and equipment or machine identifier.
  • Manufacturer, model, and Ethernet interface.
  • MAC address or another stable interface identifier, where useful.
  • IP address, subnet mask or prefix, and default gateway.
  • VLAN or network segment.
  • Address assignment method: static, DHCP, or reservation.
  • Protocols and required services.
  • Firmware and configuration backup location.
  • Commissioning date, owner, and change history.

12.2 Duplicate IP addresses

Two devices configured with the same IPv4 address on the same network can cause intermittent or persistent communication failures.

Possible symptoms include:

  • Intermittent PLC or HMI connections.
  • Connections switching between devices.
  • Duplicate-address warnings.
  • Unexpected ARP table changes.
  • Devices that respond inconsistently to ping.
  • A device working correctly until another device is connected.

Do not resolve a suspected duplicate IP by randomly changing production addresses. Identify both devices, verify the approved address register, and implement a controlled correction.

13. IPv6 awareness

IPv6 is the newer Internet Protocol and uses 128-bit addresses rather than IPv4's 32-bit addresses.

Example IPv6 address:

2001:db8:10::20

The 2001:db8::/32 range is reserved for documentation and examples. The address above is illustrative, not a real plant address.

IPv6 uses hexadecimal groups separated by colons. Consecutive zero groups can be compressed using ::, but this compression can be used only once in a single address.

Important IPv6 concepts include:

  • Global unicast: Addresses intended for globally routed communication.
  • Unique local: Addresses intended for private internal use.
  • Link-local: Addresses used for communication on a local link, commonly within fe80::/10.
  • Prefix length: Identifies the network prefix, such as /64.
  • Neighbor Discovery: IPv6's mechanisms for discovering neighboring devices and resolving link-layer addresses.

IPv6 does not use IPv4-style broadcast addressing. It uses multicast and other mechanisms for relevant local-network functions.

Many industrial networks still rely heavily on IPv4. Do not enable or disable IPv6 on a production machine without understanding its dependencies and following the approved network configuration.

14. Windows tools for IP troubleshooting

An engineering workstation can provide useful information before any PLC or machine configuration is changed.

14.1 ipconfig

Run:

ipconfig /all

This shows network interface configuration, including IP addresses, subnet masks, gateways, and DHCP information.

Use it to confirm which network adapter is being used. A workstation connected to both a plant network and an office network may have multiple adapters and routes.

14.2 ping

Run:

ping 192.168.10.20

This tests ICMP reachability to the specified address.

Interpretation:

  • Replies indicate that the target or an answering device is reachable through ICMP.
  • Timeouts may indicate a network problem, a disabled ICMP response, or filtering.
  • An unreachable message can indicate a routing or local network issue.
  • Successful replies do not prove that the required PLC communication protocol works.

14.3 arp

Run:

arp -a

This displays the workstation's IPv4 ARP cache.

It can help determine which MAC address is associated with an IP address on a local network. An unexpected MAC address may indicate a duplicate IP, device replacement, or another network change. It is evidence to investigate, not proof of a duplicate by itself.

14.4 route print

Run:

route print

This shows routing information. It is useful when a workstation has multiple network adapters or must access devices across several subnets.

14.5 tracert

Run:

tracert 192.168.20.50

This attempts to show the route toward the destination using traceroute probes. Some industrial networks block or restrict the responses used by traceroute, so incomplete output does not necessarily prove that the destination is unreachable.

14.6 Test-NetConnection

In PowerShell:

Test-NetConnection 192.168.10.20 -Port 44818

This tests TCP connectivity to the specified port. It is useful for TCP-based services but does not validate UDP communication, protocol correctness, or industrial I/O health.

Use the actual device IP and required port. Do not scan production networks indiscriminately.

15. Troubleshooting workflow for a PLC that cannot communicate

Assume an engineering PC cannot connect to a PLC at 192.168.10.20.

  1. Confirm the physical link. Check link LEDs, cable condition, switch port status, and the selected Ethernet interface.
  2. Check the PC address. Use ipconfig /all and verify the address and mask of the adapter connected to the PLC network.
  3. Check the PLC address. Confirm the configured address, subnet mask, and gateway through the approved device configuration method.
  4. Check the subnet. Determine whether the PC and PLC should communicate directly or through a router.
  5. Check for duplicates. Compare the address register, ARP observations, and device identities.
  6. Test IP reachability. Use ping where permitted, while remembering that ICMP may be blocked.
  7. Check routing. Use route print and verify the correct interface and next hop when crossing subnets.
  8. Check protocol access. Confirm the required application service, port, device configuration, and firewall rules.
  9. Check application-level configuration. Verify the PLC target address, device path, protocol settings, and connection parameters.
  10. Record and verify the correction. Document the cause and test the intended communication path without disturbing unrelated equipment.

Troubleshooting matrix

Symptom Possible cause Next diagnostic step
No Ethernet link Cable, port, power, or interface fault Check link LEDs and switch diagnostics
PC has 169.254.x.x DHCP failure or absent valid static configuration Verify the intended addressing method
PLC does not respond to ping Wrong address, network fault, filtering, or ICMP disabled Verify configuration and test the required protocol
Local devices communicate, remote devices do not Routing, gateway, VLAN, or firewall problem Check routes and inter-network policy
Ping works, PLC software cannot connect Required service blocked or application configuration incorrect Verify protocol and application settings
Intermittent communication Duplicate IP, physical errors, congestion, or device instability Check address conflicts, switch counters, and device diagnostics
PLC connects from one PC but not another Different subnet, route, firewall, or adapter selection Compare both PC configurations
HMI cannot connect after device replacement Replacement has different addressing or protocol settings Verify the replacement against the approved configuration
Device is visible at an unexpected MAC address Address conflict, replacement, or stale cache Confirm physical device identity and network records
Communication fails after a subnet change Inconsistent mask, gateway, route, or peer configuration Review every affected interface and route

16. Production maintenance and cybersecurity considerations

IP addressing is part of both availability and security.

  • Maintain an approved IP address register and update it after every authorized change.
  • Back up PLC, HMI, robot, CNC, gateway, and network-device configurations before planned changes.
  • Avoid connecting unknown laptops or replacement devices to production networks without checking their addressing.
  • Do not use arbitrary static addresses on a network with centrally managed addressing.
  • Use approved segmentation, access controls, and firewall policies to restrict unnecessary communication.
  • Keep machine-control networks separated from office or internet-facing networks according to the plant's approved architecture.
  • Avoid making live address changes during production unless the approved procedure permits them and the impact is understood.
  • Treat successful ping responses as one diagnostic result, not proof of secure or fully operational communication.

A private IP address does not itself provide cybersecurity. Isolation, authentication, authorization, monitoring, and controlled network paths remain necessary.

17. Interview questions and answers

Q1. What is an IP address?

A logical address used by IP to identify a network interface for packet delivery.

Q2. What is the difference between an IP address and a MAC address?

IP addresses support logical addressing and routing. MAC addresses support frame delivery on a local data-link network.

Q3. What is a subnet mask?

It defines the network prefix and the remaining address bits for the subnet.

Q4. What is a default gateway?

It is the next-hop router used for destinations that are not covered by a more specific route.

Q5. What is the difference between static IP and DHCP?

Static addressing is manually configured. DHCP dynamically provides IP configuration to clients.

Q6. What is a duplicate IP address?

Two devices use the same IP address on a network where that address is expected to identify one interface, potentially causing unstable communication.

Q7. Can two devices with different IP addresses communicate without a router?

Yes, if they are on the same IP subnet and the local network and device settings permit communication.

Q8. Can devices on different subnets communicate?

Yes, if suitable routing and return paths exist and network policies permit the traffic.

Q9. Does successful ping prove that Modbus TCP or EtherNet/IP works?

No. Ping tests ICMP reachability, not the health of the required application service or industrial protocol.

Q10. What should be checked when replacing a PLC?

Verify the approved IP configuration, subnet mask, gateway, device identity, protocol settings, hardware configuration, and application connection paths before returning the machine to service.

18. Practical exercises

Exercise 1: Identify the network

A PLC has the address 192.168.10.20/24. Identify its network address and explain whether a PC at 192.168.10.40/24 is in the same subnet.

Exercise 2: Find the configuration problem

A PLC is configured as 192.168.10.20/24. An engineering PC is configured as 192.168.20.40/24, with no router between them. Explain why direct communication normally fails and identify two valid ways the network could be designed to permit communication.

Exercise 3: Diagnose an intermittent connection

An HMI communicates with a PLC until a maintenance laptop is connected to the machine switch. Communication then becomes intermittent. Explain how a duplicate IP address could cause this symptom and list the evidence you would collect before changing an address.

Exercise 4: Interpret a successful ping

A PC successfully pings a PLC, but the engineering software cannot establish a connection. List at least four checks beyond ping.

Exercise 5: Plan a small machine network

Design an example address register for a PLC, HMI, VFD, robot controller, and engineering PC. Assign suitable addresses, a consistent subnet mask, and a gateway only where appropriate. Explain how you would prevent duplicate addresses.

19. Final mental model

IP address
    ↓
Identifies the network interface logically

Subnet mask / prefix
    ↓
Determines the directly connected IP network

Routing table and gateway
    ↓
Determine how to reach remote networks

MAC address and Ethernet switching
    ↓
Deliver frames across the local Ethernet segment

TCP / UDP and application services
    ↓
Provide the communication mechanisms used by industrial protocols

PLC / HMI / SCADA application
    ↓
Uses the connection to exchange meaningful automation data

The key maintenance principle is to diagnose communication layer by layer. Verify physical connectivity, IP configuration, subnet and routing, address conflicts, protocol access, and application configuration in that order. Changing an IP address without identifying the cause can turn one communication fault into several.
