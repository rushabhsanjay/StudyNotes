1. Definition and purpose

Subnetting is the process of dividing an IP network into smaller logical networks called subnets. It uses a subnet mask or CIDR prefix to determine which portion of an IP address identifies the network and which portion identifies an address within that network.

In industrial automation, subnetting helps organize communication among PLCs, HMIs, robot controllers, CNC machines, remote I/O, engineering workstations, SCADA servers, and network infrastructure.

Subnetting is useful for:

  • Separating machine cells and production lines into manageable IP networks.
  • Organizing IP address allocation without conflicts.
  • Controlling traffic paths between different network segments.
  • Supporting routing, firewall policies, and network access controls.
  • Reducing unnecessary Layer 2 broadcast traffic within each subnet.
  • Making network documentation and troubleshooting more systematic.

Important distinction: Subnetting defines IP network boundaries. It does not, by itself, create physical separation, a VLAN, a firewall boundary, or a security policy. Those require appropriate network configuration.

2. Network bits and host bits

An IPv4 address contains 32 bits. A subnet prefix identifies how many of those bits belong to the network portion.

For example:

192.168.10.20/24

  • IPv4 address: 192.168.10.20
  • Prefix length: /24
  • Network bits: 24
  • Remaining host bits: 8
  • Subnet mask: 255.255.255.0

The subnet mask has 24 consecutive binary 1 bits followed by 8 binary 0 bits.

IP address:  192.168.10.20
Prefix:      /24

Network bits                 Host bits
11111111.11111111.11111111 | 00000000
255      .255      .255    | 0

The network prefix is 192.168.10.0/24. The address 192.168.10.20 is one host address within that subnet.

The network boundary is determined by the prefix, not by assumptions about whether an address begins with 10, 172, or 192.168.

3. Subnet masks and CIDR prefixes

A subnet mask represents the network prefix in dotted-decimal notation. CIDR notation represents the same prefix as a slash followed by the number of network bits.

CIDR prefix Subnet mask Host bits Total addresses
/8 255.0.0.0 24 16,777,216
/16 255.255.0.0 16 65,536
/20 255.255.240.0 12 4,096
/22 255.255.252.0 10 1,024
/24 255.255.255.0 8 256
/25 255.255.255.128 7 128
/26 255.255.255.192 6 64
/27 255.255.255.224 5 32
/28 255.255.255.240 4 16
/29 255.255.255.248 3 8
/30 255.255.255.252 2 4
/31 255.255.255.254 1 2
/32 255.255.255.255 0 1 address

For conventional IPv4 LAN subnets, the ordinary usable host count is generally:

\[ \text{Usable hosts} = 2^h - 2 \]

where \(h\) is the number of host bits. The two excluded addresses are the network address and directed broadcast address.

This formula has important exceptions:

  • /31 networks are commonly used for point-to-point links, where both addresses can be used as endpoint addresses.
  • /32 represents one specific address or host route.
  • Special-purpose networks and platform-specific configurations may have additional constraints.

For most conventional industrial Ethernet machine networks, the familiar /24, /25, /26, /27, and /28 prefixes are the most immediately useful to understand.

4. The subnetting formulas

Three calculations form the foundation of IPv4 subnetting.

4.1 Number of addresses

\[ \text{Total addresses} = 2^h \]

Here, \(h\) is the number of host bits.

4.2 Conventional usable host count

\[ \text{Usable hosts} = 2^h - 2 \]

This applies to conventional IPv4 subnets that reserve network and broadcast addresses.

4.3 Number of subnets created

If \(s\) bits are borrowed from the host portion of an existing prefix, the number of resulting equal-size subnets is:

\[ \text{Number of subnets} = 2^s \]

For example, splitting one /24 network into /26 subnets borrows 2 additional network bits.

\[ 2^2 = 4 \text{ subnets} \]

Each /26 has 64 total addresses and normally 62 usable host addresses.

Subnetting is ultimately bit arithmetic. The notation looks fussy, but the calculations follow a repeatable pattern.

5. Calculate subnet ranges using block size

A fast manual method is to calculate the block size in the octet where the subnet mask stops being 255 and becomes a partial value.

\[ \text{Block size} = 256 - \text{mask value in the changing octet} \]

Examples:

Prefix Subnet mask Changing octet Block size
/25 255.255.255.128 128 128
/26 255.255.255.192 192 64
/27 255.255.255.224 224 32
/28 255.255.255.240 240 16
/29 255.255.255.248 248 8
/30 255.255.255.252 252 4

For /26, the block size is 64, so the subnet boundaries in the final octet are:

0, 64, 128, 192

For a /27, the boundaries are:

0, 32, 64, 96, 128, 160, 192, 224

These boundaries identify where each subnet starts. The method applies to whichever octet contains the partial mask, not only the final octet.

6. Worked example: divide a /24 into four /26 subnets

Suppose a plant has the network 192.168.10.0/24 and wants four smaller networks.

The original /24 contains 256 total addresses. A /26 prefix leaves 6 host bits, so each resulting subnet contains \(2^6 = 64\) addresses.

The mask for /26 is 255.255.255.192, giving a block size of 64.

Subnet Network address First usable host Last usable host Broadcast address
1 192.168.10.0/26 192.168.10.1 192.168.10.62 192.168.10.63
2 192.168.10.64/26 192.168.10.65 192.168.10.126 192.168.10.127
3 192.168.10.128/26 192.168.10.129 192.168.10.190 192.168.10.191
4 192.168.10.192/26 192.168.10.193 192.168.10.254 192.168.10.255

Each subnet has 64 total addresses and 62 conventional usable host addresses.

A possible logical allocation is:

  • Subnet 1: Machine cell A.
  • Subnet 2: Machine cell B.
  • Subnet 3: Machine cell C.
  • Subnet 4: Reserved for a future machine cell or another approved purpose.

This is an addressing example, not a recommendation to change a running plant network without planning and authorization.

7. Worked example: identify the subnet of an IP address

Given:

  • IP address: 192.168.10.77
  • Subnet mask: 255.255.255.192
  • Prefix: /26

The block size is:

\[ 256 - 192 = 64 \]

The subnet boundaries are 0, 64, 128, and 192.

The host value 77 lies between 64 and 127. Therefore:

  • Network address: 192.168.10.64
  • First usable host: 192.168.10.65
  • Last usable host: 192.168.10.126
  • Broadcast address: 192.168.10.127

So 192.168.10.77/26 belongs to 192.168.10.64/26.

Practical rule: Find the subnet boundary at or below the IP address in the changing octet. That boundary is the start of the subnet.

8. Worked example: a subnet mask in the third octet

Subnetting is not restricted to the final octet.

Given the network 192.168.0.0/22:

  • Mask: 255.255.252.0
  • The changing octet is the third octet.
  • Block size: \(256 - 252 = 4\)
  • Third-octet subnet boundaries: 0, 4, 8, 12, and so on.

The subnet 192.168.8.0/22 covers:

  • Network address: 192.168.8.0
  • First usable host: 192.168.8.1
  • Last usable host: 192.168.11.254
  • Broadcast address: 192.168.11.255

This subnet spans third-octet values from 8 through 11, because its block size is four.

For industrial networks, this matters when addressing plans use larger ranges or when engineers need to understand a route configured with a prefix such as /22 or /20.

9. Binary AND operation: the underlying calculation

The network address is calculated by performing a bitwise AND between the IP address and subnet mask.

For each bit:

  • 1 AND 1 = 1
  • 1 AND 0 = 0
  • 0 AND 1 = 0
  • 0 AND 0 = 0

Example using the final octet of 192.168.10.77/26:

IP octet 77:       01001101
Mask octet 192:    11000000
                   --------
Network octet:     01000000 = 64

Therefore, the network address is 192.168.10.64.

The block-size method is usually faster by hand. The bitwise AND method explains what the calculation actually does and is useful when reading networking documentation or implementing subnet calculations in software.

10. Variable-length subnetting and address allocation

A network does not always need to be divided into equal-size subnets. Variable-Length Subnet Masking (VLSM) allows subnets of different sizes to be allocated from a larger address range.

For example, a hypothetical plant has 192.168.100.0/24 available for a planned design:

Network purpose Example prefix Total addresses Conventional usable hosts
Larger machine cell /26 64 62
Medium machine cell /27 32 30
Small machine cell /28 16 14
Point-to-point router link /30 4 2

These rows describe subnet sizes, not four subnets that can all begin at the same address. The network designer must allocate non-overlapping ranges with correctly aligned boundaries.

One valid illustrative allocation within 192.168.100.0/24 is:

Purpose Network Address range
Larger machine cell 192.168.100.0/26 .0 to .63
Medium machine cell 192.168.100.64/27 .64 to .95
Small machine cell 192.168.100.96/28 .96 to .111
Router link 192.168.100.112/30 .112 to .115
Remaining space 192.168.100.116 to 192.168.100.255 Requires further valid subnet allocation

The remaining space cannot be treated as one arbitrary subnet without considering valid prefix boundaries and overlap. Address allocation must follow CIDR alignment.

11. Subnetting and industrial network segmentation

Subnetting is often part of a larger industrial network design involving managed switches, VLANs, routers, and firewalls.

Plant industrial network
          ↓
Managed Ethernet switching
          ↓
VLANs / logical Layer 2 segments
          ↓
IP subnets assigned to segments
          ↓
Routing and approved security policy
          ↓
Permitted communication between networks

The exact architecture varies by plant.

Important distinctions:

  • Subnet: An IP-layer network boundary defined by the prefix.
  • VLAN: A logical Layer 2 broadcast domain configured on compatible network equipment.
  • Router: Forwards packets between IP networks according to routing rules.
  • Firewall: Enforces traffic policies between interfaces or network zones.
  • Managed switch: Can provide VLANs, monitoring, port controls, and other features depending on its model and configuration.

A VLAN and subnet are commonly designed together, but they are not the same thing. A subnet mask configured on a PLC does not create a VLAN on the switch.

A poorly planned subnet change can prevent communication between devices that previously worked together. For example, if a PLC's mask is changed from /24 to /26 but its HMI remains configured with /24, their interpretation of which addresses are local can differ. This can create asymmetric communication behavior and difficult-to-diagnose faults.

12. Common subnetting errors in industrial automation

Error Why it causes trouble Correct approach
Wrong subnet mask Devices may classify destinations as local or remote incorrectly Verify the approved prefix and mask
Overlapping subnets Routing becomes ambiguous or inconsistent Allocate unique, non-overlapping networks
Incorrect gateway Remote-network traffic goes to the wrong next hop or fails Verify the gateway is reachable on the local subnet
Duplicate IP addresses Multiple devices claim the same address Check the address register and identify both devices
Network address assigned to a host The address represents the subnet, not a conventional host Use a valid host address
Broadcast address assigned to a host The address is reserved for subnet broadcast in conventional IPv4 subnets Select an ordinary host address
Incorrect assumptions about /24 The same address can belong to different subnets under different masks Evaluate the full address and prefix together
VLAN and subnet mismatch Layer 2 and Layer 3 configurations may not agree Verify switch VLAN, port assignment, and IP plan
Unplanned mask change Existing devices may make different routing decisions Plan and validate changes across all affected devices
Incorrect VLSM allocation Ranges may overlap or fail CIDR alignment Calculate boundaries before assigning subnets

13. Subnetting troubleshooting procedure

When an industrial device cannot communicate with another device, use a structured process.

  1. Record the actual configuration. Capture IP addresses, masks, gateways, VLANs, and the physical network connections for both endpoints.
  2. Calculate each subnet. Determine each network address and broadcast address from the IP and prefix.
  3. Determine whether the endpoints are in the same subnet. Do not rely on the first three octets alone.
  4. If they are on the same subnet, check Layer 2 connectivity, VLAN membership, duplicate IP addresses, ARP resolution, and device settings.
  5. If they are on different subnets, verify routing, the correct gateway, return routes, and firewall policies.
  6. Test progressively. Confirm link status, local IP configuration, permitted IP reachability, required TCP/UDP services, and finally the industrial application.
  7. Record the cause and correction. Update the address register and configuration backups when an authorized change is made.

Useful Windows commands include:

ipconfig /all
route print
arp -a
ping 192.168.10.20
tracert 192.168.20.50

Use actual addresses from the network being diagnosed. A ping timeout alone does not prove that subnetting is wrong, because ICMP responses may be filtered or disabled.

14. Worked industrial scenario

A PLC has the following configuration:

  • IP address: 192.168.10.70
  • Subnet mask: 255.255.255.192
  • Gateway: 192.168.10.65

An HMI has:

  • IP address: 192.168.10.100
  • Subnet mask: 255.255.255.192
  • Gateway: 192.168.10.65

The PLC belongs to 192.168.10.64/26, which covers addresses 192.168.10.64 through 192.168.10.127.

The HMI belongs to 192.168.10.64/26 as well? No. The HMI address 192.168.10.100 is also between 64 and 127, so it belongs to that same subnet.

Both devices are in the same subnet. If their communication fails, the subnet boundary alone is not the likely explanation. Check the physical link, VLAN, duplicate addresses, ARP, device configuration, and required protocol.

Now change the HMI address to 192.168.10.130/26.

The HMI now belongs to 192.168.10.128/26, while the PLC remains in 192.168.10.64/26. They are on different subnets and require a valid routed path to communicate. The configured gateway must also correspond to a real router interface reachable from each device's own subnet. Configuring the same gateway address on both devices would not make it valid for both subnets.

This example demonstrates why subnet masks must be checked alongside IP addresses.

15. Interview questions and answers

Q1. What is subnetting?

Subnetting divides an IP network into smaller logical IP networks using a subnet mask or CIDR prefix.

Q2. How many bits are in an IPv4 address?

Thirty-two bits, divided into four 8-bit octets.

Q3. What does /26 mean?

It means 26 network-prefix bits and 6 remaining host bits. The subnet contains 64 total addresses and normally 62 usable host addresses.

Q4. What is the subnet mask for /27?

255.255.255.224.

Q5. How many conventional usable host addresses are available in a /28 subnet?

There are 16 total addresses and 14 conventional usable host addresses.

Q6. How do you calculate block size?

For a subnet mask's partial octet, subtract its value from 256. For example, a mask octet of 224 gives a block size of 32.

Q7. What is the difference between a network address and a broadcast address?

The network address identifies the subnet. The IPv4 directed broadcast address identifies the subnet's broadcast destination.

Q8. Does subnetting automatically isolate machines physically or securely?

No. Subnetting defines IP network boundaries. VLANs, routing, firewalls, and other network controls determine the actual segmentation and access policy.

Q9. Can two devices in different subnets communicate?

Yes, if routing and return paths are configured correctly and security policies permit the traffic.

Q10. Why can an incorrect subnet mask cause intermittent or asymmetric communication?

Devices may make different decisions about whether to send traffic directly or through a gateway, causing inconsistent packet delivery.

17. Exercise answers

Answer 1

For 192.168.5.130/25:

  • Mask: 255.255.255.128
  • Block size: 128
  • Network: 192.168.5.128
  • First usable host: 192.168.5.129
  • Last usable host: 192.168.5.254
  • Broadcast: 192.168.5.255

Answer 2

For 10.20.30.45/27:

  • Mask: 255.255.255.224
  • Block size: 32
  • Network: 10.20.30.32
  • Broadcast: 10.20.30.63
  • Usable host range: 10.20.30.33 through 10.20.30.62
  • Conventional usable hosts: 30

Answer 3

The PLC belongs to 192.168.1.0/24. The HMI belongs to 192.168.1.192/26, which covers .192 through .255. They are in different subnets, despite sharing the first three octets.

Answer 4

A /26 provides 62 conventional usable host addresses, so it meets the requirement of at least 50 hosts per cell. Two /26 subnets require 128 total addresses and fit within a /24.

Answer 5

Verify that both devices have correct subnet masks and gateways, the routing table contains valid routes in both directions, the appropriate VLANs and router interfaces are configured, and firewall policies permit the required protocol. Then verify the application's endpoint, protocol, ports, and device-specific connection settings. Ping success alone does not establish application connectivity.

18. Final mental model

  • The IP address identifies a device interface logically.
  • The subnet mask or prefix defines the network boundary.
  • The block size helps identify subnet ranges quickly.
  • The network and broadcast addresses have special roles in conventional IPv4 subnets.
  • The default gateway and routing table determine how traffic reaches other subnets.
  • VLANs, switches, routers, and firewalls implement the wider network architecture and its access controls.
  • Correct subnetting makes industrial networks easier to organize, diagnose, and maintain, but it does not replace a properly engineered network design.
