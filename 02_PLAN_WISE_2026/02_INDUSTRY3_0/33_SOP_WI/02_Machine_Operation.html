1. Definition and Purpose

Machine operation is the controlled use of industrial equipment to perform a defined task while maintaining personnel safety, equipment integrity, process stability, and product quality.

In industrial automation, a machine may support several operating modes, such as Manual, Jog, Setup, Automatic, Single Cycle, Maintenance, and Recovery. Each mode determines which commands are permitted, how motion is initiated, which conditions must be satisfied, and how the machine responds to operator actions.

Manual mode and Automatic mode are operating modes, not safety states. A machine in Manual mode can still produce hazardous movement, and a machine in Automatic mode can be safe only when its designed safeguards and operating conditions are satisfied.

The objectives of a machine-operation SOP are to:

  • Define authorized operating modes and mode-selection rules.
  • Establish safe procedures for starting, stopping, positioning, and operating equipment.
  • Explain operating controls, indicators, alarms, and permissives.
  • Prevent unexpected movement, collisions, product defects, and equipment damage.
  • Define mode-transition requirements and recovery from abnormal conditions.
  • Ensure consistent operation across operators and shifts.
  • Establish traceable records for production, quality, faults, and handover.

2. Essential Terminology

Term Meaning
Operating mode A defined set of machine behaviors and permitted commands
Manual mode The operator directly commands selected machine functions
Jog mode The operator commands movement incrementally or while holding an authorized control
Setup mode A mode intended for preparing or adjusting the machine for a task
Automatic mode The controller executes a programmed sequence when required conditions are met
Single-cycle mode The machine executes one defined cycle per authorized command
Continuous mode The machine repeats its programmed cycle while permitted conditions remain satisfied
Maintenance mode A manufacturer- and site-defined mode for authorized servicing activities
Recovery mode A defined operating state used to recover from a fault or interrupted sequence
Permissive A condition that must be satisfied before an operation is allowed
Interlock A condition or function that prevents or restricts an operation
Sequence An ordered set of operations executed by a controller or operator
Feedback Information confirming a command's result or the actual equipment condition
Setpoint The desired value for a controlled variable
Actual value The measured or reported value of a variable
Cycle time Time required to complete a defined operating cycle
Safe state The state determined by the machine's risk assessment and safety design for a given situation

The exact definitions and behavior of operating modes must be taken from the machine's approved documentation. Different OEMs may use the same mode name for different functions.

3. Manual Mode

Manual mode allows an authorized operator or technician to command selected functions individually rather than relying on the complete automatic sequence.

Typical manual operations include:

  • Moving an axis or mechanism to a permitted position.
  • Opening or closing a fixture.
  • Operating a clamp or actuator.
  • Starting or stopping a conveyor section.
  • Testing an actuator or sensor response.
  • Positioning tooling during setup.
  • Performing approved maintenance diagnostics.

Manual mode is useful for setup, inspection, controlled testing, and troubleshooting. However, manual commands can bypass parts of the normal production sequence, so the operator must understand the consequences of each action.

3.1 Typical characteristics

  • Individual functions may be controlled separately.
  • The operator decides when to issue permitted commands.
  • Some automatic sequence checks may not apply.
  • Position, speed, pressure, or movement restrictions may differ from Automatic mode.
  • Commands may require continuous operator action, depending on the design.
  • Safety functions and applicable interlocks must remain effective.

Manual mode does not mean unrestricted movement. The machine may still require closed guards, correct pressure, valid position feedback, or other permissives before a command is accepted.

3.2 Manual-mode operating procedure

  1. Confirm authorization and the purpose of the manual operation.
  2. Verify the selected machine and operating mode.
  3. Check that the area is clear and the relevant safeguarding is in its required condition.
  4. Identify the component that will move and the potential consequences.
  5. Verify the required permissives, utilities, tooling, and workpiece conditions.
  6. Issue the specific approved command.
  7. Observe actual movement and feedback.
  8. Stop the command if movement is unexpected or the expected result is not achieved.
  9. Return the equipment to the specified position or state.
  10. Record any abnormal behavior and report unresolved defects.

3.3 Manual-mode example

A technician needs to verify a pneumatic clamp on an assembly fixture.

  • Confirm that the fixture is in the approved state for the test.
  • Verify that the hazardous area is clear and all required safeguards are effective.
  • Check air pressure and the clamp's initial position feedback.
  • Issue the authorized clamp command.
  • Confirm the clamp reaches its intended position and the corresponding sensor changes state.
  • Stop and investigate if movement is incomplete, delayed, or inconsistent with feedback.
  • Return the fixture to the required state before leaving it.

A PLC output turning ON does not prove that the clamp moved. The valve, air supply, actuator, mechanical linkage, and feedback sensor must all be considered.

4. Jog Mode

Jog mode is a form of manual control used to move an axis, robot, or mechanism in a controlled manner.

Depending on the equipment, jog movement may continue while a command is held, or it may move by a configured increment.

4.1 Types of jogging

Type Operating principle Typical use
Continuous jog Movement continues while the authorized command remains active Controlled positioning
Incremental jog Each command moves the axis by a defined increment Fine positioning
Handwheel jog A handwheel or electronic pulse generator commands movement CNC axis positioning
Robot jog Authorized commands move selected robot axes or coordinate directions Robot setup and teaching
Slow-speed setup movement Movement occurs under a defined setup arrangement Approved commissioning or adjustment

These descriptions are general. Actual movement behavior, speed limits, enabling devices, and safeguarding depend on the equipment design.

4.2 Jogging precautions

  • Verify the correct axis, direction, and coordinate system.
  • Understand the effect of positive and negative commands.
  • Check nearby tooling, fixtures, workpieces, and mechanical limits.
  • Use only the approved speed and movement method.
  • Confirm that the required enabling device and safeguards are functional.
  • Avoid relying solely on the displayed position if feedback integrity is uncertain.
  • Stop before a potential collision or travel-limit condition.
  • Never defeat a limit switch or safety function to complete a movement.

For CNC and robot equipment, incorrect coordinate-system selection can cause a movement in a direction different from what the operator expects.

5. Automatic Mode

Automatic mode allows the machine controller to execute a programmed sequence with limited operator intervention.

The sequence may include sensor checks, clamping, movement, machining, assembly, testing, transfer, quality verification, and cycle completion.

Automatic operation normally depends on several conditions being satisfied before a cycle can start.

5.1 Typical automatic-cycle conditions

  • Correct operating mode selected.
  • Required safety functions ready.
  • Machine and controllers ready.
  • No fault prohibiting operation.
  • Required utilities available.
  • Correct tooling, fixture, recipe, and program selected.
  • Workpiece or material available where required.
  • Upstream and downstream equipment ready where necessary.
  • Initial mechanism positions confirmed.
  • Required quality or process conditions satisfied.

The exact conditions must be defined by the machine's sequence logic and approved operating procedure.

5.2 Typical automatic sequence

Automatic mode selected
        ↓
Operator requests cycle start
        ↓
Controller evaluates start permissives
        ↓
Initial machine conditions are verified
        ↓
Workpiece is positioned and secured
        ↓
Programmed operations execute
        ↓
Sensors and process conditions are monitored
        ↓
Cycle completion conditions are verified
        ↓
Workpiece is released or transferred
        ↓
Machine reaches the defined end-of-cycle state
        ↓
Next cycle becomes available if permitted

This is a conceptual sequence. A real machine may have parallel operations, synchronized axes, multiple stations, and independent safety-related controls.

5.3 Automatic-mode procedure

  1. Verify that startup checks have been completed.
  2. Confirm that the machine is in the approved Automatic mode.
  3. Check the correct program, recipe, tooling, fixture, and workpiece.
  4. Confirm the machine's initial state and all required permissives.
  5. Check that the safeguarded area is clear.
  6. Issue the authorized cycle-start command.
  7. Observe the first cycle and verify expected sequence behavior.
  8. Confirm the required process and quality acceptance conditions.
  9. Continue production only while the machine operates within its specified limits.
  10. Stop or escalate if a fault, abnormal movement, or quality deviation occurs.

6. Manual Mode vs Automatic Mode

Feature Manual mode Automatic mode
Command source Individual authorized operator commands Programmed controller sequence
Operation Function-by-function Ordered or coordinated sequence
Typical purpose Setup, positioning, testing, diagnosis Normal production
Operator involvement Generally higher Generally lower during the cycle
Sequence execution Selected functions are commanded individually Controller executes the defined sequence
Permissives Required conditions depend on the command and design Cycle-start and sequence permissives are typically evaluated
Typical risks Unexpected movement, incorrect positioning, wrong command Sequence faults, collisions, incorrect recipes, unexpected automatic restart
Troubleshooting Can help isolate individual functions Helps reveal sequence and coordination problems
Quality controls May require separate verification May include automatic checks plus required operator checks
Safety requirements Remain applicable Remain applicable

Neither mode is inherently safe in every circumstance. Risk depends on the machine, task, mode-selection design, safeguards, and operator actions.

7. Other Operating Modes

Industrial equipment may include several additional modes. Their presence and behavior are machine-specific.

Mode Purpose Important consideration
Setup Prepare tooling, fixture, parameters, or workpiece Use the approved setup instructions
Single cycle Execute one cycle per command Confirm the defined end-of-cycle behavior
Continuous Repeat cycles while permitted Verify material flow and downstream readiness
Teach Program or adjust robot movements Follow the robot-specific access and enabling procedure
Maintenance Perform authorized servicing functions Apply required isolation and safeguards
Recovery Return the machine to a known operating state Follow the defined recovery sequence
Simulation Execute simulated logic or virtual operations Confirm whether physical outputs are disabled or remain active
Dry run Test movement or sequence without normal production processing Verify the exact meaning and limitations of the machine's dry-run function

Dry run does not universally mean that the machine is harmless or that all physical outputs are disabled. A dry-run function may still move axes, rotate a spindle, actuate fixtures, or operate robots.

8. Mode Selection and Transition Rules

Mode selection changes the behavior permitted by the control system. It must therefore be treated as an operational control, not merely a button press.

8.1 Before changing modes

  • Determine why the mode change is required.
  • Confirm the current machine state.
  • Complete or safely interrupt the current cycle.
  • Verify the required area and safeguarding conditions.
  • Follow the OEM procedure for selecting the new mode.
  • Confirm that the indicated mode matches the requested mode.
  • Verify the expected behavior before issuing movement commands.

Some machines prohibit mode changes during an active cycle. Others permit defined transitions under specific conditions. Never assume the behavior is universal.

8.2 Example: Automatic to Manual

Suppose a conveyor is operating automatically and a sensor needs to be inspected.

  1. Stop or place the machine in the approved state for inspection.
  2. Confirm that material flow and adjacent stations are managed.
  3. Select Manual mode according to the approved procedure.
  4. Verify the displayed mode and permitted functions.
  5. Perform the inspection using the required safeguards.
  6. Correct any identified defect.
  7. Return the machine to the required production state.
  8. Verify readiness and obtain any required restart authorization.
  9. Select Automatic mode and confirm the expected state before resuming production.

Do not assume that changing the selector to Manual automatically makes the equipment safe for physical access. The risk controls for the task determine whether additional isolation is necessary.

8.3 Example: Manual to Automatic

Before returning to production, confirm:

  • Manual commands have ended.
  • The machine is in the correct initial or recovery position.
  • Fixtures and actuators are in expected states.
  • Tooling and workpieces are correctly positioned.
  • No person or tool remains in a hazardous zone.
  • Temporary diagnostic arrangements have been removed.
  • Required guards and safety functions are restored.
  • The automatic sequence's start conditions are satisfied.
  • The responsible person has authorized restart where required.

9. HMI Controls, Indicators, and Status Messages

An HMI provides operator commands and information about the machine. The HMI is an interface to the control system, not proof that the displayed state perfectly matches the physical state.

HMI item Meaning Operator response
Mode indicator Selected operating mode Confirm it matches the intended operation
Machine Ready Defined readiness conditions are satisfied Verify the machine is ready for the intended command
Cycle Start Requests cycle initiation Use only after all required checks
Cycle Stop Requests the designed normal stop behavior Confirm the machine reaches the expected state
Reset Requests reset of permitted fault or sequence states Investigate the initiating cause first
Alarm banner Reports an abnormal condition Read the alarm and follow the response procedure
Interlock message Indicates a condition preventing an operation Identify and correct the missing condition
Actual position Reports a position value Verify reference and feedback validity
Setpoint Desired operating value Confirm it matches the approved process requirement
Actual value Reported or measured process value Compare against the specified limits
Communication status Indicates communication health according to the system design Verify data freshness and actual device state
Cycle complete Indicates a defined completion condition Confirm the required quality and transfer conditions

A Reset button is not a repair function. A green status indicator may represent only a subset of the conditions needed for safe operation.

10. PLC Logic Behind Manual and Automatic Operation

In many machines, the PLC implements the operating sequence, evaluates process permissives, controls actuators, and exchanges status information with the HMI.

A conceptual mode-selection arrangement is:

Mode selector
        ↓
PLC evaluates selected operating mode
        ↓
Manual mode → Authorized individual commands
        ↓
Automatic mode → Cycle-start request and sequence logic
        ↓
Controller checks process conditions and interlocks
        ↓
Outputs are commanded according to the approved logic
        ↓
Input feedback confirms or rejects expected progress

This is an explanatory model, not a recommended universal control architecture. Safety-related functions may be implemented in safety relays, safety PLCs, drives, or other appropriately designed systems.

10.1 Illustrative automatic start condition

AUTO_START_ALLOWED =
    AUTO_MODE_SELECTED
    AND MACHINE_READY
    AND REQUIRED_PERMISSIVES_OK
    AND NO_PROHIBITIVE_FAULT
    AND INITIAL_STATE_CONFIRMED

The condition above illustrates process-sequence logic. It is not a complete safety function and must not be used as a substitute for the required safety design.

10.2 Typical PLC signals

Signal Example tag Purpose
Manual mode selected MODE_MANUAL Indicates manual-mode selection
Automatic mode selected MODE_AUTO Indicates automatic-mode selection
Cycle-start request PB_CYCLE_START Requests an automatic cycle
Machine ready MACHINE_READY Indicates defined readiness conditions
Fixture clamped FIXTURE_CLAMPED Feedback that the fixture reached its required state
Part present PART_PRESENT Confirms workpiece detection
Drive ready VFD_READY Indicates the drive's reported readiness
Cycle active CYCLE_ACTIVE Indicates that the programmed cycle is executing
Cycle complete CYCLE_COMPLETE Indicates completion of the defined sequence
Fault active FAULT_ACTIVE Indicates an abnormal condition
Safety status SAFETY_STATUS_OK Illustrative status from the designed safety system

These are example tag names, not standardized universal tags.

10.3 Command and feedback verification

Consider a PLC command to close a pneumatic clamp.

  • PLC output requests the valve to energize.
  • Valve changes state.
  • Pneumatic pressure drives the actuator.
  • Clamp reaches its intended position.
  • Position sensor changes state.
  • PLC evaluates the feedback and sequence timeout.
  • The next operation is permitted only if its required conditions are met.

If the command is issued but feedback never arrives, possible causes include loss of air, a faulty valve, a jammed mechanism, a failed sensor, wiring problems, or incorrect PLC logic.

The correct response is to investigate the cause, not to force the feedback signal and continue production.

11. Operating a VFD-Controlled Motor

Manual and automatic operation also apply to individual motor-control systems.

Manual operation

  • Verify the correct operating mode and authorized command source.
  • Confirm that the load is mechanically ready.
  • Check the specified speed reference and rotation direction.
  • Verify required permissives and safeguards.
  • Issue the approved run command.
  • Monitor speed, current, feedback, vibration, and other relevant indicators.
  • Stop if the motor or load behaves abnormally.

Automatic operation

  • Confirm that the PLC or designated controller has the correct command source.
  • Verify start permissives and process conditions.
  • Confirm that the speed reference and operating parameters are approved.
  • Allow the programmed sequence to command the drive.
  • Verify that actual feedback follows the expected behavior.
  • Investigate faults rather than repeatedly resetting the drive.

A VFD in Local mode may ignore remote commands; a drive in Remote mode may accept commands from a PLC or network. The exact behavior depends on the configured command source and drive parameters.

Never switch between Local and Remote or change control-source parameters without understanding the resulting machine behavior and following the approved procedure.

12. CNC and Robot Manual/Automatic Operation

12.1 CNC operation

Manual or setup activities may include:

  • Jogging individual axes.
  • Referencing axes.
  • Setting work coordinates and tool offsets.
  • Loading and verifying programs.
  • Positioning tooling and fixtures.
  • Performing approved dry runs.

Automatic operation may include:

  • Executing the approved part program.
  • Coordinating axes and spindle movement.
  • Controlling coolant and tool changes.
  • Monitoring cycle completion and machine alarms.

Before automatic CNC operation, verify program identity, tool data, offsets, fixture condition, workpiece setup, machine reference, and collision risk.

12.2 Robot operation

Manual or teach activities may include:

  • Moving the robot using approved jog controls.
  • Teaching or adjusting points.
  • Checking tool and workpiece positions.
  • Verifying peripheral-device signals.

Automatic operation may include:

  • Executing the programmed path.
  • Coordinating with PLC-controlled fixtures.
  • Waiting for upstream/downstream handshakes.
  • Performing material handling, welding, assembly, or other programmed tasks.

Robot mode selection, enabling devices, speed restrictions, access rules, and safeguarding must follow the specific robot and cell design. A robot's Teach or Manual mode must never be assumed to make entry into the cell safe.

13. Abnormal Operation and Stop Criteria

Stop or inhibit operation according to the approved procedure when:

  • Movement differs from the expected direction or position.
  • A mechanism does not respond within its specified timeout.
  • An unexpected restart or automatic movement occurs.
  • A safety device reports a fault or is found damaged.
  • A motor, drive, spindle, or actuator produces abnormal noise, vibration, heat, or odor.
  • Process values exceed approved limits.
  • Product quality checks fail.
  • Communication loss makes the actual machine state uncertain.
  • A fixture, clamp, guard, or sensor does not reach its required state.
  • The controller displays a fault that prohibits continued operation.

If an immediate hazard exists, use the applicable emergency response. Do not continue operation merely because the machine has not yet stopped itself.

13.1 Example: Sensor does not confirm a clamp

Expected behavior: The clamp reaches its required position and a sensor confirms the condition within the specified sequence time.

If confirmation is missing:

  1. The controller should prevent the dependent operation according to the approved logic.
  2. The operator should identify the displayed alarm or interlock.
  3. The responsible person should investigate the sensor, actuator, valve, air supply, wiring, and mechanism as appropriate.
  4. Any physical inspection or repair requiring isolation must follow LOTO.
  5. The cause must be corrected and the required functional checks completed.
  6. The machine may return to production only after the specified recovery and authorization requirements are met.

The timeout and response must be derived from the approved machine design, not invented during troubleshooting.

Changing modes during an active cycle without authorization Unexpected sequence behavior Follow the approved mode-transition procedure
Using the wrong coordinate system Incorrect axis or robot movement Confirm axis, direction, coordinate system, and reference
Forcing sensor feedback Hidden fault and unsafe progression Diagnose and repair the actual feedback path
Repeatedly pressing Reset Repeated faults or equipment damage Identify the initiating cause
Ignoring stale HMI values Incorrect operational decisions Confirm actual device state and data freshness

15. Operator Checklist

Before operation

  • Confirm training, authorization, and the intended task.
  • Verify the machine and safeguarded area are ready.
  • Confirm the selected mode is correct.
  • Check alarms, utilities, and required machine status.
  • Verify the correct program, recipe, fixture, and material.
  • Confirm that no maintenance activity or LOTO conflicts with operation.

During Manual operation

  • Confirm the intended function, axis, and direction.
  • Verify required safeguards and permissives.
  • Issue only the authorized command.
  • Observe actual movement and feedback.
  • Stop and report unexpected behavior.

During Automatic operation

  • Verify the automatic start conditions.
  • Confirm the area is clear and required safeguards are active.
  • Monitor the first cycle and required quality results.
  • Watch for abnormal movement, faults, and process deviations.
  • Follow the approved stop and fault-response procedures.

Before changing modes or ending the task

  • Stop or safely interrupt the current operation.
  • Confirm the required machine state.
  • End manual commands and verify the machine's position.
  • Restore the required tooling, guards, and operating conditions.
  • Complete restart authorization and records where required.
  • Communicate outstanding faults and abnormal conditions during handover.

16. Documentation and Training Requirements

A complete machine-operation SOP should identify:

  • Equipment name, asset number, and applicable configuration.
  • Permitted operating modes and their intended uses.
  • Mode-selection and transition instructions.
  • Operator controls and expected indications.
  • Required startup checks and operating permissives.
  • Normal operating sequence and acceptance criteria.
  • Stop conditions and abnormal-response procedures.
  • Safety controls, restricted actions, and LOTO references.
  • Product-quality checks and traceability requirements.
  • Recovery and restart requirements.
  • Training and authorization requirements.
  • Revision number, approval, and review history.

Training should combine theory with supervised practical demonstration. An operator should demonstrate that they can select the correct mode, recognize permissives, identify abnormal conditions, stop correctly, and explain when escalation or isolation is required.

Competency should be evaluated against the actual machine and approved procedure rather than relying solely on attendance at a training session.

17. Interview Questions and Answers

Q1. What is the main difference between Manual and Automatic mode?

Manual mode allows authorized individual commands, while Automatic mode executes a programmed sequence when its required conditions are satisfied.

Q2. Is Manual mode safer than Automatic mode?

Not inherently. Manual mode can create hazardous movement through individual commands, while Automatic mode can create hazards through programmed sequences or unexpected restarts. The machine's safeguarding and task-specific controls determine risk.

Q3. What is a permissive in an automatic machine?

A condition that must be satisfied before a particular operation is allowed, such as correct fixture status, drive readiness, or downstream availability.

Q4. Why is feedback important in machine operation?

Feedback confirms whether the physical process achieved the expected result. A command alone does not prove that a motor started, a clamp closed, or an axis reached its position.

Q5. What is the difference between Jog and Automatic operation?

Jog commands controlled movement of a selected axis or mechanism, whereas Automatic operation executes a programmed sequence of coordinated actions.

Q6. What should an operator do if a machine moves unexpectedly?

Follow the approved stop or emergency response based on the hazard, keep clear of the hazardous area, report the event, and prevent restart until the cause and required safety conditions are assessed.

Q7. Why must mode transitions be controlled?

The set of permitted commands and the sequence behavior may change between modes. An uncontrolled transition can cause unexpected motion, incomplete operations, or invalid machine states.

Q8. Can a PLC permissive replace a safety function?

No. Standard process logic does not automatically provide the safety performance required for personnel protection. Safety functions must be designed, implemented, and validated for the identified risks.

Q9. Why can a machine fail to start in Automatic mode even when no alarm is present?

A required permissive may be missing, the machine may not be in the initial state, the selected mode or command source may be incorrect, or a sensor may not be reporting the expected condition.

Q10. What must be verified before returning from Manual to Automatic mode?

Verify that manual commands have ended, the machine is in the required state, the area is clear, safeguards are restored, tooling and parameters are correct, all required permissives are satisfied, and restart authorization is obtained where required.

18. Key Takeaways

  • Manual mode supports individual authorized commands; Automatic mode executes a programmed sequence.
  • Jog, Setup, Teach, Single Cycle, Continuous, and Recovery modes may be available depending on the equipment.
  • Operating mode is not a substitute for a safe state or hazardous-energy isolation.
  • Mode changes must follow the machine-specific procedure.
  • Permissives and interlocks must be understood before operating the machine.
  • Commands must be checked against actual physical feedback.
  • Never force a sensor, bypass a safeguard, or repeatedly reset unexplained faults to keep production running.
  • CNC and robot operations require particular attention to position, coordinate systems, tooling, safeguarding, and collision risk.
  • Restart after a fault or maintenance requires the specified checks and authorization.
  • The current approved OEM and site procedures take precedence over generic guidance.
