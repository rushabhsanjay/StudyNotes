1. Definition of Output Commissioning

Output commissioning is the systematic verification that commands generated by a PLC, CNC, robot controller, HMI-driven control system, or other automation controller correctly operate the intended field devices.

An output signal travels from the controller through its output hardware and electrical circuit to a field device. The field device must respond correctly, safely, and consistently with the intended machine sequence.

Examples include:

  • Energizing a contactor to start a motor.
  • Switching a solenoid valve to extend a pneumatic cylinder.
  • Controlling a stack light or audible alarm.
  • Sending a speed reference to a variable frequency drive (VFD).
  • Sending an analog command to a proportional valve.
  • Issuing a run, enable, or reset command to a CNC or robot through hardwired I/O or industrial communication.

Output commissioning verifies both the electrical command path and the physical response. A PLC output LED turning ON does not prove that the contactor has energized, the valve has shifted, or the machine has moved correctly.

2. Purpose of Output Commissioning

The primary objectives are to:

  • Confirm that each PLC output address is mapped to the correct physical output channel.
  • Verify wiring, polarity, supply voltage, common connections, and protective devices.
  • Confirm that output modules can operate their intended electrical loads.
  • Verify that contactors, relays, solenoid valves, lamps, drives, and other devices respond correctly.
  • Confirm that interlocks, permissives, sequencing, and fault responses work as designed.
  • Detect wiring mistakes, incorrect addressing, short circuits, open circuits, overloads, and incompatible electrical interfaces.
  • Verify that outputs return to their intended states during stop commands, power loss, communication failure, and controller faults.
  • Record actual results against approved drawings, I/O lists, and functional specifications.

Output commissioning is not merely switching outputs ON and OFF. It verifies that the intended command produces the intended physical result under the required safety conditions.

3. Output Signal Path

A typical digital output path is:

PLC program logic
        ↓
PLC output tag or address
        ↓
PLC output module channel
        ↓
Field wiring and terminal blocks
        ↓
Interposing relay or interface device, if required
        ↓
Field load
        ↓
Physical response

For a motor starter, the path may be:

PLC output command
        ↓
Digital output module
        ↓
Interposing relay or contactor coil circuit
        ↓
Contactor energizes
        ↓
Main contacts close
        ↓
Motor receives power, subject to protection and permissives
        ↓
Motor rotates
        ↓
Feedback confirms the expected state

The feedback path is separate from the command path. A command and its confirmation must not be treated as the same signal.

For example, Motor_Start_Command = TRUE indicates that the controller is requesting a start. A contactor auxiliary contact or drive status signal may indicate whether the commanded equipment has actually reached the expected state.

4. Main Categories of Industrial Outputs

Output category Typical devices Common signal form
Digital discrete output Lamps, relays, contactors, solenoid valves ON/OFF
Analog output VFD speed reference, proportional valve, control valve 4–20 mA or 0–10 V
Pulse or high-speed output Stepper drives, pulse-command interfaces Pulse train
Communication-based command VFD, servo, robot, CNC Network data or control word
Safety-related output Safety contactors, safe drive interfaces Safety-rated switching or safety communication
Relay output Interposing relays, control relays Switched contact
Transistor output High-speed switching loads Electronic switching
Triac output Compatible AC loads AC switching

Each category has different electrical characteristics and commissioning requirements. A test method suitable for a 24 VDC lamp may be unsuitable for a high-current solenoid, an analog control signal, or a safety-rated output.

5. Digital PLC Outputs

A digital output has two logical states:

  • 0 or FALSE: output command is inactive.
  • 1 or TRUE: output command is active.

The electrical behavior depends on the output module, its wiring, the external supply, and the load.

5.1 Source-type and sink-type outputs

In DC circuits, source and sink describe the direction of conventional current relative to the switching device.

Output type Switching behavior Typical load connection
PNP or sourcing transistor output Supplies positive voltage to the load when ON Load connected between output and 0 V
NPN or sinking transistor output Connects the load toward 0 V when ON Load connected between +24 V and output
Relay output Opens or closes an isolated contact Depends on external circuit design
Triac output Switches a compatible AC circuit Depends on rated AC supply and load

Do not assume every PLC output module is PNP, NPN, or relay-based simply because it belongs to a familiar manufacturer. Confirm the exact module catalog number and wiring diagram.

5.2 Example: PNP transistor output

Assume a 24 VDC PNP output module drives a compatible 24 VDC indicator lamp.

When the output is ON:

  • The transistor output switches toward the positive supply.
  • Current flows from the positive supply through the output stage and load toward 0 V.
  • The lamp illuminates if the circuit is correctly wired and the load is functional.

When the output is OFF, the output stage stops supplying the intended load current.

An OFF command does not automatically mean every output terminal is at 0 V. Leakage current, diagnostic circuitry, induced voltage, and the specific module design can affect measured voltage. Verify against the module specification and measure safely.

5.3 Group commons and isolation

Output modules often have multiple channels sharing a common supply or return.

For example, a module may have several output groups, each supplied by a separate 24 VDC feed. An incorrect common connection can cause several outputs to malfunction together.

Verify:

  • Module supply voltage.
  • Group supply voltage and polarity.
  • Common terminal wiring.
  • Fuse or circuit protection for each group.
  • Isolation requirements between circuits.
  • Permitted current per channel and per group.

A common-terminal error may affect multiple outputs, making the fault appear to be a software problem when it is actually an electrical distribution problem.

6. Relay, Transistor, and Triac Output Selection

6.1 Relay outputs

Relay output modules use electromechanical contacts to switch a compatible external circuit.

Advantages:

  • Can switch AC or DC loads when the contact ratings permit.
  • Provide contact isolation between the control circuit and switched circuit.
  • Can accommodate different circuit voltages within specified limits.

Limitations:

  • Mechanical wear and finite contact life.
  • Slower switching than transistor outputs.
  • Contact arcing, welding, or increased contact resistance.
  • Switching frequency and inductive-load limitations.

Use relay outputs only within their specified voltage, current, switching frequency, and load-category ratings.

6.2 Transistor outputs

Transistor outputs are commonly used for DC loads and faster switching.

Advantages:

  • Fast switching.
  • No mechanical contacts.
  • Suitable for pulse outputs when specifically rated for the required function.
  • Useful for frequent switching.

Limitations:

  • Usually polarity-sensitive.
  • Restricted to specified voltage and current ranges.
  • Leakage current may be present in the OFF state.
  • Inductive loads may require appropriate suppression.
  • Short-circuit behavior and protection vary by module.

6.3 Triac outputs

Triac outputs are used for compatible AC switching applications.

Limitations include:

  • AC-only operation for typical triac output designs.
  • OFF-state leakage current.
  • Minimum load-current requirements on some modules.
  • Incompatibility with some electronic loads.
  • Different behavior from relay contacts when switching very small loads.

Never substitute a triac, transistor, or relay output module without verifying electrical compatibility.

7. Output Load Characteristics

An output channel must be capable of driving the connected load.

7.1 Resistive loads

Examples include compatible resistive indicators and heaters.

Their current is approximately described by Ohm's law:

\[ I=\frac{V}{R} \]

Where:

  • \(I\) is current in amperes.
  • \(V\) is voltage in volts.
  • \(R\) is resistance in ohms.

For a 24 VDC resistive load with a resistance of \(120\ \Omega\):

\[ I=\frac{24}{120}=0.2\text{ A} \]

The load draws 200 mA under these assumed conditions. The output channel must support this current continuously, including any relevant temperature derating.

7.2 Inductive loads

Examples include:

  • Contactor coils.
  • Relay coils.
  • Solenoid valves.
  • Electromagnetic brakes.
  • DC motor windings.

Inductive loads store energy in their magnetic fields. When the current is interrupted, they can generate a voltage transient that damages switching electronics or causes electromagnetic interference.

Suitable suppression may include:

  • Flyback diodes for compatible DC coils.
  • Diode-plus-Zener or other specified DC suppression circuits.
  • RC snubbers for suitable AC or DC applications.
  • Manufacturer-approved surge suppressors or interface modules.

A plain flyback diode is not universally suitable. It can slow the release of a DC coil, which may be unacceptable for some contactors, valves, or safety-related applications. Select suppression based on the device manufacturer's requirements and the required release time.

7.3 Capacitive and electronic loads

Electronic devices, LED indicators, and interface modules can draw inrush current when switched ON. Their steady-state current may be small while the initial current exceeds the output's switching capability.

Check:

  • Inrush current.
  • Continuous current.
  • OFF-state leakage compatibility.
  • Minimum load requirements.
  • Output module short-circuit protection.
  • Required interface relays.

8. Digital Output Electrical Checks

Before testing an output, identify its rated voltage, expected load current, output type, wiring arrangement, and protection.

For a typical 24 VDC output circuit, verify:

  1. The correct DC supply is present.
  2. Polarity is correct.
  3. The output module is powered and healthy.
  4. The channel is assigned to the intended device.
  5. The field wiring matches the drawing.
  6. The load is correctly rated.
  7. The circuit protection is suitable.
  8. The output command produces the expected voltage and current.
  9. The device physically responds.
  10. Feedback, where provided, confirms the expected state.

A voltage reading alone is not enough. A damaged output transistor may show voltage with no load but fail when asked to supply current. Conversely, electronic loads may produce misleading readings because of leakage or high-impedance meters.

Measure current only using a suitable method and instrument arrangement. Never connect an ammeter directly across a voltage source.

9. Analog Outputs

Analog outputs produce a continuously variable command within a defined range.

Common examples:

  • VFD speed reference.
  • Servo or process reference signals.
  • Proportional hydraulic or pneumatic valves.
  • Modulating control valves.
  • Temperature or pressure controller setpoints.

Common industrial output ranges include:

  • 4–20 mA.
  • 0–20 mA.
  • 0–10 V.
  • Other manufacturer-specific voltage or current ranges.

The PLC output value must be converted to the intended electrical signal and then interpreted by the receiving device.

9.1 Current output: 4–20 mA

A 4–20 mA output often represents a command from 0% to 100%.

The linear conversion is:

\[ I=4+16\left(\frac{P}{100}\right) \]

Where:

  • \(I\) is output current in mA.
  • \(P\) is command percentage.

Examples:

Command Expected current
0% 4 mA
25% 8 mA
50% 12 mA
75% 16 mA
100% 20 mA

The 4 mA live zero helps distinguish a valid zero-percent command from some fault conditions, such as a broken wire that causes current to fall close to zero. The actual fault thresholds depend on the device configuration.

9.2 Voltage output: 0–10 V

For a 0–10 V output configured for 0–100%:

\[ V=10\left(\frac{P}{100}\right) \]
Command Expected voltage
0% 0 V
25% 2.5 V
50% 5 V
75% 7.5 V
100% 10 V

Confirm that the output module and receiving device use compatible ranges. A 0–10 V signal connected to a 0–5 V input can produce incorrect scaling or overrange conditions.

9.3 Analog scaling from engineering units

Suppose a PLC output is configured to command a VFD from 0 to 50 Hz using a 4–20 mA signal.

The relationship between frequency command and current is:

\[ I=4+16\left(\frac{f}{50}\right) \]

For a 30 Hz command:

\[ I=4+16\left(\frac{30}{50}\right)=13.6\text{ mA} \]

If the output module is configured correctly, the receiving drive should interpret 13.6 mA as approximately 30 Hz, subject to its own scaling, limits, and control configuration.

Important: A correct analog current does not prove that the VFD will run at the commanded speed. The drive may be disabled, faulted, limited, configured for a different command source, or prevented from running by an interlock.

9.4 Analog output commissioning procedure

  1. Confirm the output channel and engineering-unit range.
  2. Verify the output module's configured signal type.
  3. Confirm wiring polarity and the receiving device's input terminals.
  4. Check the analog common or return arrangement.
  5. Verify the output at a known low command.
  6. Verify one or more intermediate command values.
  7. Verify the maximum permitted command without exceeding equipment limits.
  8. Compare the measured electrical signal with the calculated expected value.
  9. Confirm that the receiving device interprets the command correctly.
  10. Confirm that the actual equipment response matches the approved specification.

Do not command maximum speed, pressure, force, or flow simply to prove the analog output. The test range must be approved for the machine's current mechanical and safety conditions.

10. Pulse Outputs and High-Speed Commands

Some controllers provide pulse outputs for stepper drives or pulse-command interfaces. These signals communicate motion commands through pulse frequency and, in many designs, a separate direction signal.

The receiving device must support the output's:

  • Voltage level.
  • Input current.
  • Pulse frequency.
  • Pulse width.
  • Duty cycle.
  • Electrical interface.
  • Direction and enable conventions.

For a pulse-commanded axis, the controller may generate a number of pulses corresponding to the commanded movement. The relationship between pulses and physical travel depends on the drive's electronic gearing, motor resolution, and mechanical transmission.

If the configured system requires \(N\) pulses per millimetre, a movement command of \(d\) millimetres requires:

\[ \text{Pulses}=N \times d \]

For example, if the configured relationship is 800 pulses/mm and the command is 10 mm:

\[ \text{Pulses}=800 \times 10=8000 \]

This calculation is only valid when the configured pulses-per-distance relationship is correct and the motion system supports the requested movement.

Commissioning must verify pulse generation, direction, drive readiness, motion limits, and actual movement. Never test motion outputs with an axis free to collide with tooling, fixtures, or personnel.

11. Communication-Based Outputs

Modern drives, robots, CNC systems, and remote I/O devices may receive commands over industrial networks rather than dedicated output wires.

Examples include:

  • PROFINET.
  • EtherNet/IP.
  • EtherCAT.
  • PROFIBUS.
  • Modbus TCP or RTU.
  • Manufacturer-specific industrial networks.

A communication-based command may contain:

  • Run or stop request.
  • Speed or torque reference.
  • Direction command.
  • Reset request.
  • Operating mode.
  • Control word.
  • Position or motion command.

A valid communication connection does not prove that a command is being accepted or executed.

Verify:

  1. The controller and device are communicating.
  2. The correct device identity and data mapping are used.
  3. Command and status words are mapped correctly.
  4. The device is in the required control mode.
  5. The command source is configured for the network interface.
  6. The drive or machine is enabled and fault-free.
  7. The command is within permitted limits.
  8. Feedback confirms the expected response.
  9. Communication-loss behavior matches the approved design.

A frequent commissioning fault is sending a valid run command while the drive is configured to accept commands from its local terminals. The network may show healthy communication while the drive ignores the command.

12. Output Mapping and Address Verification

The PLC program address, physical output channel, terminal number, and field device must correspond.

Example:

Item Example
PLC tag CV01_Contactor_Cmd
PLC output address %Q0.0
Module Digital output module
Channel Channel 0
Terminal As defined by the module wiring diagram
Field device Conveyor 1 contactor coil
Feedback tag CV01_Contactor_FB
Expected response Contactor energizes when all start conditions are satisfied

Address notation varies by PLC platform. %Q0.0 is only an illustrative address, not a universal PLC syntax.

For every output:

  • Verify the program tag.
  • Verify the physical module and channel.
  • Verify the terminal number.
  • Verify the field cable and destination.
  • Verify the actual device.
  • Verify the associated feedback.
  • Update the I/O list if approved changes are made.

Never identify a channel solely by guessing from the physical module position. Use the actual hardware configuration and electrical drawings.

13. Output Interlocks and Permissives

An output should only energize when its required operating conditions are satisfied.

For example, a conveyor motor command may require:

  • Emergency-stop system healthy.
  • Guarding system healthy.
  • Motor protection healthy.
  • Downstream equipment ready.
  • No active process fault.
  • Correct operating mode selected.
  • Start request present.

A simplified conceptual expression is:

\[ \text{MotorCmd}=\text{StartRequest}\land\text{PermissivesOK} \]

Here, \(\land\) represents logical AND. Every required permissive must be true before the command can become active.

Real machine logic may include latches, sequencing, timers, mode selection, fault handling, and separate safety functions. This expression is not a replacement for the approved functional specification.

13.1 Command versus feedback

Consider these three states:

Command Feedback Interpretation
OFF OFF Expected stopped state, if the device is designed to de-energize
ON ON Command and feedback agree
ON OFF Possible failure to energize, wiring fault, device fault, or feedback issue
OFF ON Possible welded contact, delayed release, incorrect feedback, or wiring fault

Feedback must be interpreted according to the device and circuit design. Some equipment has inverted logic or delayed feedback, and not every output has dedicated physical feedback.

14. Output Forcing and Manual Testing

Forcing an output means overriding normal program control to set a signal to a chosen state for testing or troubleshooting.

Forcing can be useful during commissioning, but it can also bypass the intended sequence and cause unexpected machine movement.

Before forcing an output:

  1. Obtain the required authorization.
  2. Review the electrical drawings and the device's function.
  3. Confirm that the area is clear and the machine is in a safe test condition.
  4. Identify all stored-energy sources and mechanical hazards.
  5. Confirm the correct device and channel.
  6. Ensure that safety functions remain effective.
  7. Use the approved testing procedure and permitted operating conditions.
  8. Monitor the physical response and relevant feedback.
  9. Remove the force immediately after the approved test.
  10. Verify that no forces remain and that normal program control has been restored.

Important distinctions:

  • A PLC output force may override program logic.
  • A forced standard PLC signal is not an acceptable substitute for a safety function.
  • A safety-rated output or safety controller must be tested according to its approved safety procedure.
  • An output must never be forced ON merely to defeat an interlock or enable hazardous motion.

A force that remains active after commissioning can create a serious maintenance hazard. Force status must be explicitly checked and documented.

15. Safety-Related Outputs

Safety-related outputs may control:

  • Safety contactors.
  • Safe torque off (STO) interfaces.
  • Safety-rated drive functions.
  • Safety valves.
  • Other safety-related final switching elements.

Safety-related outputs may use safety relays, safety PLCs, redundant output channels, test pulses, feedback monitoring, and diagnostic coverage.

Commissioning must verify the actual safety design, including:

  • Correct device and channel assignment.
  • Wiring and terminal integrity.
  • Required redundancy.
  • Cross-short and short-circuit detection, where applicable.
  • Feedback monitoring and contactor monitoring.
  • Correct response to loss of supply.
  • Reset behavior and restart prevention.
  • The specified safe state under relevant faults.
  • Required validation tests and documented results.

Standard PLC logic must not be treated as a safety-rated control system unless the complete architecture is specifically designed, implemented, and validated for that purpose.

STO generally prevents a drive from producing torque, but it does not necessarily isolate electrical power or eliminate all mechanical hazards. Stored energy, gravity, inertia, and other hazards must be considered separately.

16. Fail-Safe Output Behavior

The expected output state during a fault depends on the machine's risk assessment and control design.

Examples include:

  • A motor command de-energizes on a stop request.
  • A valve moves to a specified position on loss of power.
  • An alarm activates when a fault is detected.
  • A drive stops according to its configured stop behavior.
  • A communication-controlled device transitions to its specified fault response.

Do not assume that OFF is always safe. A valve may need to remain energized to hold a load, or a process may require a controlled shutdown rather than an immediate loss of power.

For each output, document:

Condition Required behavior
Normal operation Correct commanded state and physical response
Normal stop Approved stop behavior
Emergency stop Response defined by the validated safety design
PLC fault Defined system response
Output module fault Defined response based on hardware and risk assessment
Communication loss Configured device response
Control power loss Expected de-energized or mechanically defined state
Feedback disagreement Alarm, timeout, or controlled fault response as specified

The commissioning engineer verifies the designed behavior. They should not invent a supposedly safer response without engineering review.

17. Output Sizing and Electrical Protection

Before energizing an output, verify that the module, interface device, wiring, and protective devices are suitable for the connected load.

17.1 Continuous current

The connected load's continuous current must remain within the permitted rating of:

  • The output channel.
  • The output group.
  • The common terminal.
  • The interposing relay or contactor.
  • The field wiring.
  • The power supply.

The module's total current limit may be lower than the sum of individual channel ratings. Ambient temperature and installation conditions may also require derating.

17.2 Inrush current

Coils, lamps, capacitive inputs, and electronic devices can draw an initial current greater than their steady-state current.

Check the manufacturer's ratings for:

  • Resistive loads.
  • Inductive loads.
  • Lamp loads.
  • Capacitive or electronic loads.
  • Switching frequency.
  • Permitted inrush current.

17.3 Protection

Verify the correct:

  • Fuse or circuit breaker.
  • Wire size.
  • DC supply rating.
  • Short-circuit protection.
  • Surge suppression.
  • Grounding and bonding.
  • Segregation between power, control, and analog wiring.

A fuse should not be replaced with a larger rating simply because it repeatedly opens. Repeated fuse operation indicates a fault, incorrect sizing, inrush problem, or another condition requiring investigation.

18. Output Commissioning Procedure

Step 1: Review documentation

Collect and verify:

  • Approved electrical drawings.
  • PLC I/O list.
  • PLC hardware configuration.
  • Control narrative or functional specification.
  • Interlock and cause-and-effect documentation.
  • Field device manuals.
  • Drive or actuator parameter records.
  • Risk assessment and safety validation requirements.

Step 2: Confirm the equipment is ready

Before electrical testing:

  • Confirm that mechanical installation is complete enough for the intended test.
  • Check device mounting, linkage, couplings, and actuator connections.
  • Confirm that moving parts will not collide.
  • Identify stored pneumatic, hydraulic, electrical, and mechanical energy.
  • Apply the required isolation and lockout/tagout measures for work on exposed or hazardous circuits.
  • Establish an approved controlled test condition for functional operation.

Isolation must be maintained during work that requires de-energization. Energized functional testing should only occur under an approved procedure with appropriate safeguards.

Step 3: Inspect the electrical installation

Check:

  • Correct terminal connections.
  • Wire numbers and ferrules.
  • Polarity and common connections.
  • Cable continuity, where appropriate.
  • Terminal tightness according to manufacturer requirements.
  • Fuses and circuit breakers.
  • Relay and contactor ratings.
  • Suppression components.
  • Separation of signal and power wiring.
  • Earthing and bonding.

Never perform continuity or resistance tests on an energized circuit. Disconnect sensitive electronics where required by the test procedure.

Step 4: Verify the PLC hardware

Confirm:

  • Correct module type and slot.
  • Correct channel configuration.
  • Correct output voltage and switching type.
  • Module health and diagnostic status.
  • Output group supply.
  • Correct tag-to-channel mapping.
  • No unintended force or override is active.

Step 5: Verify the load circuit

Before commanding an output:

  • Confirm the field device's rated voltage.
  • Check that the load is connected to the intended output.
  • Verify the appropriate return or common.
  • Confirm that the load is not short-circuited.
  • Check the suitability of the output channel and protection.
  • Confirm that the device can be operated safely under the test conditions.

Step 6: Perform a controlled output test

For each output:

  1. Record the device tag and PLC address.
  2. Confirm the intended device and expected behavior.
  3. Establish the required safe test conditions.
  4. Apply the approved command through the intended control method.
  5. Observe the PLC output status and module indication.
  6. Measure the electrical output when required.
  7. Observe the physical device response.
  8. Check relevant feedback signals.
  9. Return the device to its required state.
  10. Record pass, fail, or the fault found.

For a motion-related output, begin with the safest suitable test condition, such as an approved low-speed or limited-range test, where the machine design allows it.

Step 7: Verify the automatic sequence

After individual point checks, verify outputs within the intended operating sequence.

Examples:

  • A cylinder extends only when the required permissives are satisfied.
  • A motor starts only after its start conditions are met.
  • A valve returns to the designed state when the sequence ends.
  • A drive receives the correct command and reports the expected state.
  • Faults trigger the correct alarm and stop response.

An output that works when manually commanded may still fail in automatic mode because of incorrect sequencing, interlocks, mode logic, timers, or program mapping.

Step 8: Verify fault responses

Where required by the approved procedure, test:

  • Missing permissives.
  • Device feedback timeout.
  • Drive fault.
  • Communication failure.
  • Power-supply failure.
  • Output module diagnostic fault.
  • Safety-related stop conditions.

Use the documented test method. Do not create hazardous faults by randomly disconnecting live circuits or bypassing protection.

Step 9: Restore and document

Before handing over:

  • Remove temporary forces and overrides.
  • Restore normal operating modes.
  • Confirm that all devices are in the required state.
  • Clear test-only settings and temporary wiring.
  • Confirm that safety functions remain operational.
  • Record failures, corrective actions, and retest results.
  • Update approved documentation where required.
  • Obtain the required commissioning sign-off.

19. Output Commissioning Checklist

  • Output tag matches the approved I/O list.
  • PLC address matches the configured hardware channel.
  • Correct module type and output switching technology confirmed.
  • Correct supply voltage and polarity verified.
  • Output group common and supply connections verified.
  • Field wiring and terminal numbers checked.
  • Load voltage, current, and inrush ratings checked.
  • Fuse or circuit breaker rating verified.
  • Interposing relay or interface module verified, if fitted.
  • Suppression components verified where required.
  • Output status and module indication checked.
  • Electrical output measured where required.
  • Physical device response confirmed.
  • Feedback and interlocks verified.
  • Analog output scaling verified, where applicable.
  • Pulse or communication-based commands verified, where applicable.
  • Stop and fault responses verified according to the test plan.
  • Safety-related output tests completed by the approved method.
  • All temporary forces and overrides removed.
  • Results, defects, corrective actions, and retests documented.

20. Common Output Commissioning Faults

Symptom Possible causes Checks
PLC output command ON, module LED OFF Wrong address, inhibited output, module fault, configuration mismatch Verify tag mapping, module status, channel configuration, and force status
Module LED ON, field device OFF Missing supply, broken wire, incorrect common, failed load, damaged output stage Measure voltage under appropriate conditions, inspect wiring, test load safely
Output works without load but fails under load Excessive load current, high-resistance connection, damaged output stage, inadequate supply Check load current, supply voltage under load, terminals, and module ratings
Device remains ON after command OFF Welded relay contact, short circuit, wiring bypass, incorrect logic, leakage-sensitive load Isolate safely and inspect the switching path and device requirements
Several outputs fail together Missing group supply, blown group fuse, incorrect common, module fault Check shared supply, protection, commons, and module diagnostics
Relay chatters Unstable supply, loose connection, undervoltage, control oscillation Measure supply under load, inspect wiring, examine control sequence
Solenoid fails to release promptly Incorrect suppression, residual pressure, mechanical sticking, wrong valve configuration Check suppression design, pneumatic or hydraulic conditions, and valve operation
Analog command is incorrect Wrong output range, scaling error, polarity or wiring error, incorrect receiving input configuration Verify configuration, measured current or voltage, scaling, and device settings
VFD ignores run command Wrong command source, missing enable, active fault, interlock, invalid control word Check drive control mode, status word, fault state, and permissives
Output fails intermittently Loose terminals, thermal overload, electrical noise, failing module, unstable supply Inspect terminals, monitor diagnostics, check load current and noise sources
Output works manually but not automatically Sequence logic, interlock, mode selection, timer, tag mapping error Monitor program conditions and verify the functional specification
Output reports ON but equipment does not operate Mechanical jam, failed actuator, missing energy supply, feedback mismatch Check the complete device system, not just the PLC output

21. Troubleshooting Example: Contactor Does Not Energize

Scenario: A PLC command requests that a conveyor motor start, but the contactor does not energize.

Diagnostic sequence

  1. Verify the command. Confirm that the PLC program is requesting the start and that required permissives are satisfied.
  2. Verify the output channel. Confirm that the intended physical output changes state and that the module has no relevant diagnostic fault.
  3. Verify the control supply. Check the coil supply and the required return path.
  4. Verify the output circuit. Inspect the fuse, terminals, wiring, interposing relay, and contactor coil connections.
  5. Verify the coil. Check its rated voltage, resistance when safely isolated, and condition according to the manufacturer's instructions.
  6. Check voltage under load. A nominal voltage reading with the coil disconnected may hide a high-resistance connection or weak supply.
  7. Check the feedback. Determine whether the auxiliary contact changes state when the contactor operates.
  8. Verify the root cause. Identify whether the problem lies in software logic, output hardware, wiring, supply, the interface relay, or the contactor.
  9. Retest. Verify correct operation after the fault is corrected and document the result.

Never bypass motor protection or safety interlocks to make the contactor energize. The purpose of commissioning is to prove that the control system works correctly, not to persuade a machine to move by any means available.

24. Important Interview Questions and Answers

Q1. What is output commissioning?

Output commissioning verifies that controller commands reach the correct field devices and produce the expected electrical and physical response.

Q2. What is the difference between an output command and output feedback?

The command represents the controller's request. Feedback represents an observed or reported state of the device or equipment. The two can disagree if a fault exists.

Q3. What is the difference between relay and transistor outputs?

Relay outputs use mechanical contacts and can switch compatible AC or DC circuits. Transistor outputs use electronic switching, typically for DC circuits, and are generally faster but have different polarity, leakage, and load limitations.

Q4. Why can a PLC output LED turn ON while the device remains OFF?

Possible causes include a missing external supply, broken wiring, incorrect common connection, failed load, incompatible electrical interface, or damaged output hardware.

Q5. Why must inductive loads be considered separately?

Inductive loads can generate voltage transients when switched off. Appropriate suppression is required to protect switching components and control electromagnetic interference.

Q6. Why is a 4–20 mA signal useful?

It supports analog command transmission, provides a live-zero value, and can help distinguish a valid zero-percent command from certain low-current fault conditions.

Q7. Why is forcing an output risky?

A force can override normal program logic and energize equipment without the intended sequence or permissives. Forces must be controlled, documented, and removed after testing.

Q8. What is the purpose of an interposing relay?

It provides an interface between the PLC output and a field load when electrical isolation, switching capacity, circuit separation, or a different switching arrangement is required.

Q9. What is the difference between output testing and sequence testing?

Output testing verifies an individual command and its device response. Sequence testing verifies that outputs operate in the correct order and under the correct conditions during machine operation.

Q10. What should be checked if a VFD receives a speed reference but does not run?

Check the drive's command source, run enable, fault status, control word, operating mode, interlocks, and configured reference source. A valid speed reference alone does not establish a run command.

Q11. Does STO mean that a drive is electrically isolated?

No. Safe torque off prevents torque production through the specified safety function, but it does not necessarily isolate electrical power or remove all mechanical and stored-energy hazards.

Q12. What proves that an output has passed commissioning?

The correct mapping and electrical behavior are verified, the intended device responds correctly, required feedback and fault responses pass, and the test results are documented.

25. Key Takeaways

  • Output commissioning validates the path from controller command to physical device response.
  • Correct PLC logic does not guarantee correct electrical wiring or functioning field equipment.
  • Output type, voltage, current, inrush, load characteristics, and suppression must all be considered.
  • Analog outputs require verification of scaling and the receiving device's interpretation.
  • Communication-based commands require checks of command mapping, control mode, status, and permissives.
  • Individual output testing and automatic sequence testing are both necessary.
  • Safety-related outputs must be commissioned and validated according to the approved safety design.
  • Forcing outputs requires strict control, and all forces must be removed before handover.
  • Fault responses, feedback behavior, documentation, and retesting are part of commissioning, not optional paperwork.
