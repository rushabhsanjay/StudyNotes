1. Definition of Inputs

In industrial automation, an input is a signal or data value received by a control system from an operator, sensor, switch, measuring instrument, another controller, or connected device.

Inputs allow a PLC or other controller to observe the state of a machine or process and make decisions based on its control program.

Examples include:

  • A proximity sensor detecting a metal component.
  • A limit switch indicating that a cylinder has reached its end position.
  • A pressure transmitter measuring hydraulic pressure.
  • A pushbutton requesting a machine start.
  • An overload relay indicating a motor fault.
  • An encoder providing position or speed feedback.
  • A drive reporting that it is ready.
  • A safety device providing status through an approved safety interface.

Input commissioning is the systematic verification that each intended field signal reaches the correct control-system input, is interpreted correctly, and produces the expected status or measured value.

The objective is to prove the complete signal path, not merely confirm that an input LED illuminates.

2. Purpose of Input Commissioning

Input commissioning establishes that the installed instrumentation and control wiring match the approved design.

Its main objectives are:

  • Verify the physical device and its identification.
  • Confirm the correct electrical supply and wiring.
  • Check signal polarity and electrical compatibility.
  • Verify PLC channel assignment and addressing.
  • Confirm correct ON/OFF behavior for digital inputs.
  • Verify measurement range and scaling for analog inputs.
  • Check signal stability and detect electrical noise.
  • Confirm correct HMI indication and PLC logic interpretation.
  • Verify fault indications and diagnostic behavior.
  • Document the results for commissioning and future maintenance.

A signal can appear correct at one point while remaining incorrect elsewhere. For example, a sensor may detect an object and illuminate its indicator, but the PLC may not receive the signal because of incorrect common wiring or an incompatible input circuit.

The exact order depends on the project. Some checks require the PLC to be online, while others must be performed with circuits isolated.

Safety-related inputs require the applicable safety commissioning and validation procedures. A standard PLC input test is not a substitute for validating a safety function.

4. Types of Industrial Inputs

Industrial inputs are broadly classified as digital, analog, pulse or high-speed, communication-based, and safety-related inputs.

Input type Signal representation Examples
Digital input Discrete ON/OFF state Pushbutton, limit switch, proximity sensor
Analog input Continuously varying electrical signal Pressure, temperature, flow, level
Pulse input Countable electrical transitions Encoder, pulse meter, speed sensor
High-speed input Fast transitions processed by dedicated hardware High-speed counter, encoder interface
Communication input Data received through a network or serial link Drive status, remote I/O data, smart sensor values
Safety-related input Safety information processed by an appropriate safety system Emergency-stop device, safety light curtain

These categories can overlap. For example, an encoder may provide pulse signals to a high-speed input module, while a smart sensor may transmit measured values through an industrial network.

5. Digital Inputs

5.1 Definition

A digital input represents a discrete state, typically ON or OFF. The actual electrical voltage corresponding to these states depends on the input module's design and specified thresholds.

Common industrial digital input devices include:

  • Pushbuttons.
  • Selector switches.
  • Limit switches.
  • Inductive proximity sensors.
  • Capacitive proximity sensors.
  • Photoelectric sensors.
  • Pressure switches.
  • Thermostat contacts.
  • Relay auxiliary contacts.
  • Drive-ready and fault contacts.

5.2 Typical digital input signal path

Physical Condition
        ↓
Sensor or Switch
        ↓
Field Wiring
        ↓
PLC Input Terminal
        ↓
Input Conditioning Circuit
        ↓
PLC Input Status
        ↓
Program Logic
        ↓
HMI or Sequence Response

Each stage must be verified independently when troubleshooting.

5.3 Input ON and OFF states

A digital input module normally interprets a voltage or current range as ON and another range as OFF. Between those ranges, the state may be undefined or unreliable.

Condition Electrical behavior Commissioning interpretation
Valid ON state Signal meets the specified ON threshold Input should be recognized as ON
Valid OFF state Signal meets the specified OFF threshold Input should be recognized as OFF
Intermediate voltage Signal lies between defined thresholds May produce unreliable interpretation
Floating input Input lacks a defined electrical reference May change state unpredictably
No signal No valid ON-level signal is present Input is usually OFF, subject to circuit design
Short circuit or wiring fault Signal is forced to an unintended state Must be investigated rather than assumed to be a normal state

Never assume that all PLC input modules use identical ON/OFF thresholds. Refer to the exact module datasheet.

6. Digital Input Wiring: Sourcing, Sinking, PNP, and NPN

Understanding input wiring is essential when commissioning proximity sensors and other three-wire DC devices.

6.1 PNP sensors

A PNP sensor typically sources positive voltage at its output when activated.

Conceptually:

+24 VDC → PNP Sensor → PLC Input → Input Return

The precise arrangement depends on the PLC input module's common-terminal design.

6.2 NPN sensors

An NPN sensor typically sinks current from the connected input circuit toward 0 V when activated.

Conceptually:

PLC Input Circuit → NPN Sensor Output → 0 V

These are conceptual current paths, not universal wiring diagrams. Always follow the manufacturer's terminal diagram.

6.3 Sourcing and sinking terminology

Term Meaning
Sourcing output Supplies current to the connected circuit
Sinking output Provides a path for current to return toward the reference
PNP output Commonly sources positive voltage when ON
NPN output Commonly sinks current toward 0 V when ON
Input common Shared reference or return terminal for a group of inputs

A PNP sensor generally requires a compatible sinking input arrangement. An NPN sensor generally requires a compatible sourcing input arrangement. The actual compatibility must be confirmed from both devices' specifications.

6.4 Three-wire sensor connections

Many three-wire DC sensors use the following color convention:

Common color convention Typical function Verification required
Brown Positive supply Confirm the device wiring diagram
Blue 0 V supply return Confirm the device wiring diagram
Black Switching output Confirm output type and terminal assignment

Wire colors are conventions, not proof of correct wiring. Special devices, connectors, and manufacturer-specific arrangements may differ.

6.5 Common digital input wiring faults

  • PNP sensor connected to an incompatible input circuit.
  • NPN sensor connected to an incompatible input circuit.
  • Missing input common connection.
  • Incorrect sensor supply polarity.
  • Broken or shorted output conductor.
  • Incorrect terminal assignment.
  • Floating input.
  • Incorrect PLC channel address.
  • Damaged input channel.
  • Sensor output current or voltage incompatible with the module.

7. Mechanical Switches and Dry Contacts

A dry contact is a contact that does not itself supply a voltage. It simply opens or closes an electrical circuit supplied by an external source.

Common examples include:

  • Pushbuttons.
  • Limit switches.
  • Relay auxiliary contacts.
  • Pressure-switch contacts.
  • Thermostat contacts.

Normally open and normally closed contacts

Contact designation Normal mechanical state State when actuated
NO Open Closed, if the mechanism operates as designed
NC Closed Open, if the mechanism operates as designed
Changeover contact Common connected to one contact Common transfers to the other contact

The term normal refers to the defined unactuated condition of the device, not necessarily the normal operating condition of the machine.

For example, a normally closed limit switch may provide a healthy signal during ordinary operation and open when actuated. A broken wire may also produce an open circuit, depending on the circuit design.

For ordinary control inputs, NO and NC selection affects signal interpretation. For safety-related circuits, contact arrangement, fault detection, architecture, and validation must follow the safety design.

8. Two-Wire and Three-Wire Sensors

Two-wire sensors

A two-wire sensor is connected in series with its load. The sensor draws operating current through the same two conductors used to switch the circuit.

Potential characteristics include:

  • OFF-state leakage current.
  • Voltage drop across the sensor.
  • Minimum load-current requirements.
  • Compatibility limitations with particular input modules.

A two-wire sensor may not behave like a dry contact. Leakage current can sometimes keep an input partially energized, especially when the input circuit is sensitive.

Three-wire sensors

A typical three-wire sensor has separate supply-positive, supply-return, and output connections.

Advantages include clearer separation between power and signal conductors and broad availability in industrial automation.

The output may be PNP, NPN, push-pull, or another type. The output type must match the PLC input requirements.

9. PLC Input Modules and Addressing

A PLC input module receives the electrical signal and makes its state or measured value available to the controller.

9.1 Local and remote I/O

  • Local I/O: Input modules installed in or directly connected to the main PLC rack or controller assembly.
  • Remote I/O: Input modules located away from the main controller and connected through a fieldbus or industrial network.
  • Integrated I/O: Input channels built into a controller or compact device.

Remote I/O adds a communication dependency. A field signal may be electrically correct at the remote module but unavailable to the PLC because the remote station is disconnected or in a fault state.

9.2 Physical channel versus program address

A physical input channel and its program-level variable are related but not necessarily identical in naming or representation.

For example, a physical channel might be identified as:

  • Rack 0, slot 2, channel 5.
  • A manufacturer-specific address such as I0.5.
  • A symbolic tag such as LS_101_Extended.

These are examples only. Addressing conventions differ between PLC platforms.

The commissioning engineer must verify the mapping from the physical terminal to the PLC program variable.

9.3 Input mapping errors

Typical mapping errors include:

  • Wrong channel address.
  • Wrong module or slot reference.
  • Incorrect symbolic tag.
  • Reused tag names.
  • Incorrect remote I/O mapping.
  • Inverted logic interpretation.
  • Incorrect data type.
  • Wrong byte or bit order in a communication mapping.
  • Incorrect engineering-unit scaling for analog signals.

A correct electrical signal mapped to the wrong program variable is still an input commissioning failure.

10. Input Filtering and Debouncing

10.1 Input filtering

An input filter prevents very short disturbances from being interpreted as valid state changes. Filtering may be implemented in the input module, PLC configuration, or application logic.

Excessive filtering can delay the detection of legitimate signals.

10.2 Contact bounce

Mechanical contacts can open and close rapidly for a short period when they change state. This is known as contact bounce.

Debouncing methods include:

  • Hardware input filtering.
  • PLC input delay configuration.
  • Software timers.
  • State-validation logic.

10.3 Filter selection

Application Filtering consideration
Operator pushbutton Moderate filtering may prevent multiple detections
Mechanical limit switch Filtering may reduce contact bounce
Fast production sensor Excessive filtering can miss events
High-speed counter Standard input filtering may be unsuitable
Safety-related input Use only the filtering and response configuration permitted by the safety design

Filtering must be selected according to the required response time and signal characteristics. A delay that is harmless for an operator pushbutton may be unacceptable for a fast-moving machine.

11. Analog Inputs

11.1 Definition

An analog input measures a continuously varying signal and converts it into a numerical value for the PLC or control system.

Common industrial analog input signals include:

  • 4–20 mA.
  • 0–20 mA.
  • 0–10 V.
  • 1–5 V.
  • Resistance or temperature sensor signals through suitable input modules.
  • Thermocouple and RTD signals through compatible specialized modules.

The supported signal type depends on the input module. A voltage input must not be assumed to accept a current signal without the correct configuration or approved interface.

11.2 Typical analog input signal path

Physical Process
        ↓
Transmitter or Measuring Device
        ↓
Analog Electrical Signal
        ↓
PLC Analog Input Module
        ↓
Raw Digital Value
        ↓
Engineering-Unit Scaling
        ↓
PLC Logic and HMI Display

A correct analog signal can still produce an incorrect process value if the module configuration, raw-value range, scaling, or units are wrong.

12. Understanding 4–20 mA Signals

The 4–20 mA current loop is widely used for industrial process measurement.

For a typical linear transmitter:

  • 4 mA represents the lower range value.
  • 20 mA represents the upper range value.
  • Values between these limits represent intermediate process values.

The 4 mA lower endpoint is often called live zero. It allows the system to distinguish a valid zero-range measurement from a zero-current condition, although fault interpretation depends on the transmitter and receiving system.

12.1 Scaling formula

For a linear transmitter:

\[ PV = LRV + \frac{I-4}{16}(URV-LRV) \]

Where:

  • \(PV\) = process value.
  • \(I\) = measured loop current in mA.
  • \(LRV\) = lower range value.
  • \(URV\) = upper range value.

Example

A pressure transmitter measures 0–10 bar using 4–20 mA. The measured signal is 12 mA.

\[ PV = 0+\frac{12-4}{16}(10-0) \]
\[ PV = 5\text{ bar} \]

The calculation assumes a correctly configured linear transmitter and input channel.

12.2 Why 4–20 mA is useful

  • Good suitability for industrial transmission over appropriate cable lengths.
  • Relative robustness against certain forms of electrical interference.
  • Live-zero capability.
  • Compatibility with many industrial transmitters and analog input modules.
  • Straightforward scaling into engineering units.

A current loop is not immune to noise, incorrect grounding, wiring errors, or voltage-compliance limitations.

12.3 Two-wire transmitter

In a typical two-wire loop-powered transmitter, the same two conductors carry both the operating power and the measurement current.

The loop supply must provide sufficient voltage for the transmitter, input burden, cable resistance, and any other series devices.

12.4 Three-wire or four-wire transmitter

A three-wire transmitter typically has separate supply and signal connections with a shared reference or return arrangement defined by the manufacturer.

A four-wire transmitter generally has separate power and signal circuits.

The exact wiring arrangement varies. Do not infer the correct loop wiring merely from the number of terminals.

13. Understanding 0–10 V Signals

A 0–10 V analog signal represents a measurement using a voltage level within the specified range.

For a linear 0–100% measurement:

\[ \text{Percentage} = \frac{V}{10}\times100 \]

If the input measures 6 V:

\[ \text{Percentage} = \frac{6}{10}\times100 = 60\\% \]

Voltage signals may be more susceptible to errors caused by cable voltage drop, ground-potential differences, and electrical interference than appropriately designed current-loop systems.

During commissioning, check the signal at the source and at the input terminals, using the correct reference point.

14. Analog Raw Values and Engineering-Unit Scaling

An analog input module converts its electrical measurement into a numerical value. Depending on the module, the raw value may be represented as an integer, signed integer, normalized value, or another data format.

Do not assume that every PLC maps 4–20 mA to the same raw-value range.

For a generic linear input mapping:

\[ EU = EU\_{\min} + \frac{Raw-Raw\_{\min}}{Raw\_{\max}-Raw\_{\min}} (EU\_{\max}-EU\_{\min}) \]

Where:

  • \(EU\) = engineering-unit value.
  • \(Raw\) = measured raw input.
  • \(Raw\_{\min}\) and \(Raw\_{\max}\) = configured raw range.
  • \(EU\_{\min}\) and \(EU\_{\max}\) = engineering-unit range.

Example

Suppose a configured analog input maps raw values from 0 to 27648 into a pressure range of 0–10 bar. The current raw value is 13824.

\[ EU = 0+\frac{13824-0}{27648-0}(10-0) \]
\[ EU = 5\text{ bar} \]

The raw range of 0–27648 is illustrative and is not universal. Confirm the input module's actual data representation and configured range.

15. Analog Input Faults

Symptom Possible cause Verification
Reading stays at zero Missing supply, open loop, incorrect channel mode, or wiring fault Measure the source signal and inspect channel diagnostics
Reading remains at full scale Incorrect wiring, signal outside range, or scaling error Verify signal type, raw value, and configured range
Reading fluctuates Electrical noise, unstable transmitter, loose terminals, or poor reference Inspect wiring, grounding, source stability, and filtering
Correct current but wrong engineering value Incorrect scaling, range, or units Compare raw value and scaling parameters
Signal is below the expected range Transmitter fault, low loop supply, excessive burden, or cable fault Measure loop current and verify loop voltage requirements
Input indicates overrange Signal exceeds configured limits or fault current is present Check transmitter diagnostics and module range
Input indicates underrange Signal falls below configured limits or a loop fault exists Check loop continuity, transmitter state, and configuration
One channel differs from others Wiring, channel configuration, calibration, or device variation Compare wiring, configuration, and reference measurements

Never diagnose an analog fault solely from the displayed engineering value. Compare the actual electrical signal, module raw value, scaling, and final displayed value.

16. Pulse and High-Speed Inputs

Pulse inputs detect transitions rather than simply interpreting a steady ON/OFF state.

Common applications include:

  • Incremental encoders.
  • High-speed counters.
  • Flow meters with pulse outputs.
  • Speed sensors.
  • Position measurement systems.

16.1 Frequency and pulse counting

Frequency is the number of cycles per second:

\[ f = \frac{N}{t} \]

Where:

  • \(f\) = frequency in hertz.
  • \(N\) = number of counted cycles.
  • \(t\) = measurement time in seconds.

For example, 500 pulses counted in 2 seconds correspond to:

\[ f = \frac{500}{2} = 250\text{ Hz} \]

The result depends on the counting method and whether the system counts pulses, edges, or encoder transitions.

16.2 High-speed input checks

  • Confirm input voltage and electrical interface.
  • Verify sensor or encoder output type.
  • Check maximum input frequency.
  • Confirm pulse-width requirements.
  • Verify shielding and cable routing.
  • Check encoder supply and signal reference.
  • Confirm counter configuration and scaling.
  • Compare measured motion with the expected count or frequency.

A standard digital input may not detect fast pulses because of input filtering, scan timing, or module limitations. Use a suitable high-speed input or counter interface when required.

17. Communication-Based Inputs

Not every PLC input arrives through a physical input terminal. A controller may receive process values and device status over an industrial network.

Examples include:

  • VFD ready status.
  • VFD fault code.
  • Servo actual position.
  • Remote I/O channel status.
  • Smart sensor measurement.
  • Industrial scale weight.
  • Robot status and position.
  • Data from another PLC.

Verification procedure

  1. Confirm the communication connection is established.
  2. Verify device identity and data mapping.
  3. Check data type, length, byte order, and scaling where relevant.
  4. Confirm values update at the expected rate.
  5. Verify status and quality indicators.
  6. Check timeout behavior and communication-loss diagnostics.
  7. Compare the transmitted value with the source device.
  8. Confirm that the PLC program uses the intended mapped variable.

A numeric value of zero does not necessarily mean that a process is at zero. It may indicate a default value, communication timeout, invalid data, or an uninitialized variable. Use the device's quality and diagnostic information.

18. Input Commissioning Procedure

Step 1: Identify the input

For each input point, identify:

  • Equipment tag.
  • Device type and model.
  • Physical location.
  • PLC or remote I/O station.
  • Module and channel.
  • Program tag or address.
  • Expected signal state or range.
  • Required operating conditions.

Step 2: Review the drawings

Compare the physical installation with the latest approved electrical drawings and I/O list.

Check terminal numbers, cable identifiers, wire numbers, supply source, signal return, shield termination, and channel mapping.

Step 3: Inspect the field device

Verify mechanical mounting, alignment, sensing distance, operating range, connector condition, and environmental suitability.

For example, a proximity sensor can be wired correctly but remain permanently OFF because the target never enters its sensing range.

Step 4: Verify electrical compatibility

Confirm:

  • Supply voltage.
  • Signal type.
  • Polarity.
  • PNP/NPN or sourcing/sinking compatibility.
  • Input voltage or current thresholds.
  • Channel configuration.
  • Required isolation and grounding arrangement.

Step 5: Verify wiring safely

Use the approved isolation procedure before continuity checks, conductor changes, or other work requiring a de-energized circuit.

Check for loose terminals, broken conductors, incorrect terminal assignment, shorts, and missing common connections.

Step 6: Energize the relevant circuit

Apply power according to the approved commissioning procedure. Confirm the device's power and status indicators.

Do not apply a test voltage directly to a PLC terminal unless the method is approved for that input and the terminal's electrical characteristics are known.

Step 7: Stimulate the input

Operate the physical switch, move the target, vary the measured process, or use the approved signal simulation method.

For analog inputs, use an appropriate calibrated source or process stimulus when required.

Step 8: Verify the physical signal

Measure the signal at the relevant point using an appropriate instrument and reference. Confirm that the electrical behavior matches the device specification.

Step 9: Verify the PLC channel

Observe the input channel status and the corresponding program variable.

Confirm that the correct channel changes and that no unrelated channel changes unexpectedly.

Step 10: Verify application behavior

Check that the PLC program interprets the input correctly and that the intended sequence, permissive, alarm, or HMI indication responds as specified.

Do not force PLC variables as a substitute for verifying the real field signal.

Step 11: Test both states or the operating range

For a digital input, verify both ON and OFF states under the specified conditions.

For an analog input, test the required calibration points or representative values across the specified range.

For a pulse input, verify the required pulse count, frequency, or position response.

Step 12: Record the result

Record the expected result, actual result, test conditions, pass/fail status, fault details, and corrective action.

19. Point-to-Point Input Testing

Point-to-point testing confirms that the physical device is connected to the intended control-system channel and software variable.

For a digital sensor, the complete verification might be:

Sensor Detects Target
        ↓
Sensor Output Changes
        ↓
Voltage Reaches Correct PLC Terminal
        ↓
Correct PLC Input Channel Changes
        ↓
Correct Program Tag Changes
        ↓
Expected Logic or HMI Status Appears

For an analog transmitter, the equivalent test verifies the electrical signal, raw input value, engineering-unit conversion, and final displayed value.

Example: Proximity sensor

Suppose sensor PE_101 is intended to indicate that a component has reached a station.

Expected behavior:

  • No target: sensor output OFF.
  • Target detected: sensor output ON.
  • PLC tag: PE_101_Detected.
  • HMI status: Component Present.

The commissioning test should verify all four stages. If the sensor LED illuminates but the PLC tag remains OFF, investigate the electrical output, wiring, input compatibility, and channel assignment before changing the application logic.

20. Input Simulation and Forcing

Input simulation can be useful during commissioning, but it must be controlled carefully.

Possible methods include:

  • Operating the real field device.
  • Using a manufacturer-approved signal simulator.
  • Applying a specified test signal to a suitable input.
  • Using a documented PLC simulation environment.
  • Forcing a PLC variable where the platform and approved procedure permit it.

These methods do not prove the same things.

Test method What it can verify What it does not necessarily verify
Operate the real sensor Physical sensing and the downstream signal path Every fault condition or full operating range
Simulate a digital signal at the approved terminal Input channel and downstream logic Sensor operation and field wiring upstream of the test point
Inject a calibrated analog signal Input conversion and scaling downstream of the injection point Transmitter accuracy and upstream loop wiring
PLC software simulation Program behavior under simulated conditions Real electrical signals, wiring, and hardware behavior
Force a PLC variable Logic response to the forced state The physical input path and actual field device

Forcing bypasses the normal relationship between the physical signal and the program variable. It can also cause outputs to operate unexpectedly.

Before using a force, follow the site's authorization and risk-control procedure. Identify the force, document it, understand its effect, and remove it afterward. Verify that no forces remain before releasing the machine.

Never use input forcing to bypass a safety function or to declare an unverified safety-related input healthy.

21. Noise, Shielding, and Signal Integrity

Input signals can be affected by electromagnetic interference, ground-potential differences, poor wiring, and unstable power supplies.

Common sources include:

  • VFD output cables.
  • Servo drives.
  • Contactors and solenoids.
  • Long parallel runs of power and signal wiring.
  • Poorly terminated shields.
  • Loose terminals.
  • Incorrect signal references.
  • Inadequate suppression of inductive loads.

Good practices include:

  • Follow approved cable-routing and separation requirements.
  • Use suitable shielded cable for the signal and environment.
  • Terminate shields according to the equipment and system design.
  • Maintain correct protective bonding and signal-reference arrangements.
  • Use appropriate suppression for inductive loads.
  • Avoid unnecessary 0 V-to-PE connections.
  • Verify that the input filter is suitable for the required response time.

If an input flickers, record whether the behavior coincides with motor starts, contactor switching, or other events. Correlation with a switching event can help identify interference or a shared power-supply problem.

22. Input Commissioning and Safety

Some inputs are ordinary process signals. Others form part of a safety-related control system.

Examples of safety-related devices include:

  • Emergency-stop devices.
  • Safety door switches.
  • Interlocking guards.
  • Safety light curtains.
  • Safety laser scanners.
  • Two-hand control devices.
  • Safety-rated enabling devices.

A standard PLC input may monitor the status of a safety device, but it does not automatically perform the required safety function.

For safety-related inputs, verify the approved safety architecture, wiring, diagnostic behavior, reset logic, fault response, and required validation tests.

Do not:

  • Bridge an emergency-stop input to make the machine run.
  • Force a guard-closed status.
  • Bypass a light curtain.
  • Assume a single ordinary input channel provides the required safety performance.
  • Accept a safety function merely because its HMI status appears normal.

The required safety performance depends on the complete design and applicable standards. Use the machine's approved safety-validation procedure.

23. Common Input Commissioning Mistakes

  • Checking only the sensor LED.
  • Confirming only the PLC input LED.
  • Ignoring the difference between physical channel and program address.
  • Assuming PNP and NPN sensors are interchangeable.
  • Treating a dry contact as though it supplies its own voltage.
  • Ignoring the effects of two-wire sensor leakage current.
  • Using the wrong meter mode or reference point.
  • Measuring analog signals only at the transmitter.
  • Assuming every analog module uses the same raw-value range.
  • Changing program logic before confirming the electrical signal.
  • Using excessive input filtering.
  • Testing high-speed signals through an unsuitable standard input.
  • Treating communication data with invalid quality as a valid process value.
  • Leaving PLC forces active after testing.
  • Skipping documentation of failed points.
  • Bypassing safety-related inputs during commissioning.

Corrective action Record the repair or configuration change
Final verification Record the retest result and sign-off

For analog points, include the signal type, configured range, engineering units, calibration points, raw values, scaled values, and applicable tolerance.

For pulse and communication-based inputs, record the relevant frequency, count, data mapping, update behavior, quality status, or timeout response.

25. Practical Industrial Example

A machine uses an inductive PNP proximity sensor to detect a component at a fixture. The sensor's indicator illuminates when the component arrives, but the PLC input remains OFF.

A disciplined investigation proceeds as follows:

  1. Verify the sensor model and confirm that it is a PNP device.
  2. Confirm its supply voltage and polarity.
  3. Check the sensor's output voltage relative to the correct reference when the target is detected.
  4. Verify that the PLC input module is compatible with the sensor output.
  5. Check the input common connection.
  6. Measure the voltage at the PLC input terminal.
  7. Confirm the physical module and channel address.
  8. Compare the channel status with the symbolic program tag.
  9. Verify the HMI indication after the PLC tag changes.
  10. Record the root cause and repeat the test.

Possible findings include an open output conductor, missing input common, incorrect terminal assignment, incompatible input wiring, or an incorrect program address.

The sensor LED alone cannot distinguish among these possibilities. The signal must be traced through the complete path.

26. Interview Questions and Answers

Q1. What is input commissioning?

Input commissioning verifies that field signals are correctly generated, wired, received by the correct control-system channel, interpreted by the program, and displayed or used as intended.

Q2. What is the difference between digital and analog inputs?

A digital input represents discrete states, typically ON and OFF. An analog input represents a continuously varying measurement, such as pressure, temperature, or flow.

Q3. What is the difference between PNP and NPN sensors?

A PNP sensor typically sources positive voltage at its output when ON. An NPN sensor typically sinks current toward 0 V. Their compatibility depends on the PLC input circuit.

Q4. Why can a sensor LED be ON while the PLC input is OFF?

The sensor may have power and detect its target, but the output wiring, input common, electrical compatibility, channel assignment, or PLC input circuit may be incorrect.

Q5. Why is 4–20 mA widely used in industrial measurement?

It provides a widely supported current-loop signal with a live-zero feature and good suitability for industrial transmission when the loop is correctly designed.

Q6. What is live zero?

In a typical 4–20 mA system, 4 mA represents the lower range value rather than zero current. This helps distinguish a valid lower-range measurement from certain open-loop or fault conditions.

Q7. What is the difference between an input channel and a PLC tag?

The channel is the physical or configured hardware input. The tag is the program-level variable that represents the signal. Correct mapping between them must be verified.

Q8. Why should analog scaling be checked during commissioning?

A correct electrical signal can produce an incorrect engineering value if the raw-value range, configured signal type, scaling formula, or engineering units are wrong.

Q9. What is input filtering?

Input filtering rejects short disturbances or transitions that should not be recognized as valid signals. Excessive filtering can delay or miss legitimate events.

Q10. What is point-to-point testing?

It verifies the signal path from the physical field device through wiring and the input channel to the correct program variable and expected indication.

Q11. Does PLC simulation prove that field wiring is correct?

No. Software simulation can verify program behavior under simulated conditions, but it does not necessarily verify real sensors, field wiring, electrical compatibility, or physical input channels.

Q12. Why must input forces be removed after testing?

A force overrides the normal input state used by the program. An active force can hide a field fault or create unexpected machine behavior. Forces must be tracked, removed, and verified according to the approved procedure.

27. Final Input Commissioning Checklist

Digital inputs

  • Correct field device and tag identified.
  • Supply voltage and polarity verified.
  • Signal type and input compatibility confirmed.
  • Wiring, terminal numbers, and common connections checked.
  • ON and OFF states physically tested.
  • Correct PLC channel and program tag verified.
  • HMI indication and relevant logic behavior checked.
  • Signal stability confirmed under relevant conditions.

Analog inputs

  • Correct transmitter and measurement range identified.
  • Signal type and module configuration verified.
  • Loop supply, wiring, and signal reference checked.
  • Electrical signal measured using a suitable instrument.
  • Raw input value verified.
  • Scaling and engineering units checked.
  • Required calibration points tested.
  • Fault and out-of-range behavior verified where specified.

Pulse and communication inputs

  • Correct device interface identified.
  • Input frequency or data update requirements confirmed.
  • Addressing, mapping, and scaling checked.
  • Signal or data validity verified.
  • Timeout and diagnostic behavior checked where required.
  • Relevant limits and operating conditions tested.

Final acceptance

  • All required points tested.
  • Deviations documented and resolved or formally assessed.
  • Temporary test connections removed.
  • PLC forces removed and verified.
  • Safety-related inputs validated using the approved procedure.
  • I/O records updated.
  • Required commissioning sign-off obtained.

28. Key Takeaways

  • Input commissioning verifies the entire path from the physical field condition to the control-system interpretation.
  • Digital, analog, pulse, communication, and safety-related inputs require different test methods.
  • Sensor indicators and PLC input LEDs are useful diagnostic evidence, but neither proves the entire signal path is correct.
  • Correct wiring, electrical compatibility, channel mapping, and scaling are essential.
  • Measure analog signals and compare the electrical value, raw value, and engineering-unit value.
  • Use suitable high-speed interfaces for pulse signals that exceed ordinary input capabilities.
  • Simulation and forcing have limited scopes and cannot replace physical verification.
  • Safety-related inputs must be tested and validated using the approved safety procedures.
  • Record expected values, actual results, deviations, corrective actions, and final acceptance.
