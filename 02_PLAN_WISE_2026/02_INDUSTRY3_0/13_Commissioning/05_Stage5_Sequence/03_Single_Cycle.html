1. Definition and Purpose

Single-cycle operation is a machine operating mode in which the control system executes one complete, predefined production cycle and then stops the sequence at its designated end condition, waiting for the next start command or another defined operating-mode transition.

A complete cycle usually begins with a valid start request, executes the required sequence of operations, verifies relevant conditions, and reaches a defined cycle-complete state.

Single-cycle commissioning verifies that the machine can execute one complete automatic sequence correctly before continuous automatic operation is enabled.

Typical applications include:

  • Automotive assembly and fixture stations.
  • Robotic loading and unloading cells.
  • CNC machining and component transfer.
  • Pneumatic and hydraulic assembly machines.
  • Conveyor indexing and transfer systems.
  • Leak-testing and functional-test stations.
  • Pressing, clamping, fastening, and inspection equipment.
  • Packaging and material-handling systems.

The objective is not merely to make the machine finish one cycle. It is to verify that every sequence step executes in the correct order, required conditions are satisfied, feedback is valid, faults are handled correctly, and the machine reaches the intended end state without unintended repetition.

2. Where Single-Cycle Operation Fits in Commissioning

Single-cycle commissioning follows the verification of individual manual functions and jog movements.

Mechanical and electrical installation
                 ↓
Device and I/O commissioning
                 ↓
Communication verification
                 ↓
Manual function commissioning
                 ↓
Jog movement commissioning
                 ↓
Single-cycle commissioning
                 ↓
Automatic continuous-cycle commissioning
                 ↓
Integrated performance testing
                 ↓
Final acceptance and handover

The distinction between the stages is important:

  • Manual mode: Verify individual functions independently.
  • Jog mode: Verify controlled movement and stopping behavior.
  • Single-cycle mode: Verify one complete automatic sequence.
  • Auto-cycle mode: Verify repeated automatic production cycles and sustained operation.

A machine that works in manual mode may still fail in single-cycle mode because automatic sequencing introduces additional requirements such as step transitions, part-presence checks, device handshakes, timing, fault recovery, and cycle-completion logic.

3. Single-Cycle Operating Principle

In single-cycle mode, the machine normally starts from a defined initial condition, performs its programmed sequence, confirms completion, and waits for a new start request.

Machine in defined initial state
               ↓
Operator requests cycle start
               ↓
PLC validates start permissives
               ↓
Automatic sequence begins
               ↓
Individual steps execute in order
               ↓
Sensors and device feedback are checked
               ↓
Required operations complete
               ↓
Cycle-complete conditions are satisfied
               ↓
Sequence returns to its defined end state
               ↓
Machine waits for the next start request

The exact sequence depends on the machine design. Some systems return to a home position at the end of the cycle; others remain at the final process position until the next cycle or an explicit reset action.

A cycle-complete signal must represent the defined completion criteria, not merely the expiration of a timer or the fact that the last command was issued.

4. Operating Modes and Cycle Behavior

Mode Start behavior Sequence behavior Expected end behavior
Manual Individual function request Selected functions operate independently Function-specific completion or stop
Jog Directional or incremental movement request Controlled movement Defined stop or completed increment
Single cycle One valid cycle-start request Executes one complete sequence Waits for the next start request
Auto cycle Start or automatic-run request Repeats cycles according to the design Continues until stopped, inhibited, or faulted
Recovery Approved recovery command Performs defined restoration actions Returns to a valid recovery or initial state

These operating modes may have different names or implementations across PLC platforms and machine builders. Commissioning must follow the approved functional specification.

5. Single-Cycle Control Architecture

A typical machine uses a PLC sequence controller to coordinate actuators, drives, robots, CNC equipment, and inspection devices.

HMI or operator start request
              ↓
Operating-mode validation
              ↓
Start permissives and initial-state checks
              ↓
PLC sequence controller
              ↓
Actuator and device commands
              ↓
Sensor and device feedback
              ↓
Step-transition evaluation
              ↓
Fault handling and cycle supervision
              ↓
Cycle-complete status
              ↓
Wait for the next cycle

For a robot or CNC machine, the PLC may issue high-level requests while the robot or CNC controller manages its internal program or motion sequence. The PLC must verify the required device status and handshake signals before advancing the machine sequence.

6. Important Single-Cycle Signals

The following are illustrative PLC tag names. Actual tags must follow the project's I/O list, naming convention, and sequence specification.

The meaning of each signal must be documented. For example, DEVICE_COMPLETE must indicate the correct operation has finished, not simply that the device received a command.

7. Cycle Start Conditions and Permissives

A valid start request should be accepted only when the machine is in an approved state for beginning the cycle.

Typical conditions include:

  • Single-cycle mode is active.
  • The machine is in the defined initial state.
  • No blocking fault is active.
  • Required guards and safety conditions are satisfied.
  • Required drives and devices are ready.
  • Required workpiece or fixture conditions are satisfied.
  • Required utilities are available.
  • No conflicting operation is active.
  • Connected devices are communicating correctly.
  • Any required homing or position-reference conditions are satisfied.

The exact conditions depend on the machine's risk assessment and functional specification.

7.1 Start permissive versus start command

These concepts must remain separate.

  • Start command: The operator requests a cycle.
  • Start permissive: The machine is allowed to start.
  • Start acceptance: The control system accepts the request.
  • Sequence active: The sequence has entered its executing state.

A start command may be rejected because a permissive is missing. The HMI should provide useful information about the blocking condition when appropriate.

7.2 Start-command handling

A cycle-start button may produce a momentary signal, a rising-edge event, or a request handled by a command handshake.

The control logic must prevent a held or stale start signal from unintentionally initiating repeated cycles.

A robust design defines:

  • How a start request is detected.
  • Whether the request is accepted only on a rising edge.
  • Whether the request can be queued.
  • Whether a request is discarded when the machine is not ready.
  • What happens if the HMI communication fails.
  • How the request is cleared.
  • Whether another cycle can start without a new operator action.

8. Sequence Steps and State Transitions

A single cycle consists of defined steps. Each step performs an operation and advances when the specified transition conditions are satisfied.

For example, an assembly station might use these steps:

Step Operation Transition condition
0 Wait for start Valid start request and start permissives
10 Verify workpiece Required part-presence condition satisfied
20 Clamp workpiece Clamp-closed feedback valid
30 Perform assembly operation Assembly device reports completion
40 Release workpiece Clamp-open feedback valid
50 Confirm cycle completion All required cycle-end conditions satisfied
60 Return to ready state Defined initial-state conditions satisfied

The step numbers are illustrative. Some machines use sequential integers, enumerated states, function blocks, state machines, or vendor-specific sequence instructions.

8.1 Step entry and exit conditions

A well-designed sequence defines:

  • Entry conditions.
  • Commands active during the step.
  • Expected feedback.
  • Transition conditions.
  • Step timeout.
  • Fault response.
  • Reset or recovery behavior.

This makes sequence behavior easier to commission and diagnose.

8.2 Transition conditions

A transition may depend on one or more conditions.

For example:

Clamp step complete =
    Clamp command accepted
    AND Clamp-closed feedback valid
    AND No blocking clamp fault

This is conceptual logic. Actual completion criteria may require additional checks, such as pressure confirmation, device acknowledgement, position tolerance, or safety-related conditions.

8.3 Avoiding skipped steps

The sequence should not advance simply because the command was issued. It should evaluate the specified completion conditions.

For example, after commanding a clamp, the sequence should not proceed to assembly until the required clamp-state feedback has been verified.

This prevents the controller from progressing while the physical mechanism is still moving or has failed to reach the expected position.

9. Cycle Completion and Return-to-Ready Behavior

Cycle completion is a defined machine state indicating that the required cycle operations have finished.

Possible completion criteria include:

  • All required sequence steps are complete.
  • The process result is valid.
  • Required device operations have completed.
  • The workpiece has reached the specified end state.
  • Required inspection or traceability results are available.
  • No blocking fault is active.
  • Required end-position feedback is valid.

The machine may then:

  • Set CYCLE_COMPLETE.
  • Clear the sequence-active indication.
  • Return to the initial step.
  • Retain the final process state.
  • Wait for a new start command.

The correct behavior depends on the machine design.

Returning the sequence pointer to Step 0 does not necessarily mean the physical machine is ready for another cycle. The controller must verify the relevant machine-state conditions before accepting another start request.

10. Single-Cycle State Machine

A conceptual state model is:

IDLE / READY
     ↓ Valid start request
START VALIDATION
     ↓ Permissives satisfied
EXECUTING SEQUENCE
     ↓ All required steps complete
CYCLE COMPLETION
     ↓ End conditions satisfied
WAIT FOR NEXT START

Any executing state
     ↓ Detected blocking fault
FAULT HANDLING
     ↓ Approved recovery and reset
RECOVERY / READY VALIDATION
     ↓ Valid machine state restored
IDLE / READY

This is a conceptual model, not a universal PLC program. Some systems include separate states for homing, setup, part loading, inspection, unloading, fault acknowledgement, or operator intervention.

11. Single-Cycle Commissioning Procedure

Step 1: Review the functional specification

Review the documents that define the intended cycle:

  • Functional specification.
  • Sequence description or state-transition table.
  • Electrical and pneumatic/hydraulic drawings.
  • PLC I/O list and program structure.
  • HMI operating-mode and alarm design.
  • Robot and CNC interface documentation.
  • Device handshake definitions.
  • Safety requirements.
  • Timeout and recovery requirements.
  • Cycle-time and acceptance criteria.

Confirm the expected initial state, each sequence step, transition condition, cycle-end state, and fault response.

Step 2: Verify the initial state

Before starting the cycle, confirm:

  • The correct operating mode is selected.
  • The sequence is not already active.
  • The machine is in the defined initial state.
  • Required axes are in permitted positions.
  • Required actuators are in their expected states.
  • The required workpiece or fixture condition is valid.
  • Required devices are ready.
  • No blocking faults are present.
  • Required safety conditions are satisfied.

Do not rely only on the HMI's READY indication. Compare the indication with the actual PLC states and relevant physical feedback.

Step 3: Verify start acceptance

Issue one approved cycle-start request.

Check that:

  • The start request is received.
  • The start permissives are evaluated correctly.
  • The command is accepted only under valid conditions.
  • The sequence enters the expected first step.
  • The active step is displayed or otherwise diagnosable.
  • The start request does not remain latched unintentionally.

Step 4: Observe each sequence step

For every step, verify:

  1. The expected command is issued.
  2. The intended device responds.
  3. Feedback matches the physical condition.
  4. The transition occurs only when its criteria are satisfied.
  5. The next step is correct.
  6. No unexpected output remains active.
  7. Any timeout or fault is handled according to the design.

Record the results rather than relying on memory. Human memory is an unreliable commissioning instrument, despite its widespread deployment.

Step 5: Verify device handshakes

For connected equipment such as robots, CNCs, scanners, printers, vision systems, and test instruments, verify the relevant handshake.

Typical signals may include:

  • Ready.
  • Start request.
  • Busy.
  • Complete.
  • Result valid.
  • Fault.
  • Acknowledgement.
  • Reset request.

The exact handshake varies by device.

A device must not be considered complete merely because a start command was sent or because a communication connection exists. The required acknowledgement, completion state, and result validity must be verified.

Step 6: Verify the cycle-end state

At the end of the cycle, verify:

  • All required operations are complete.
  • The process result is valid.
  • Required actuators are in their expected end states.
  • Required feedback is valid.
  • CYCLE_COMPLETE is set under the defined conditions.
  • The sequence stops or returns to its designated end state.
  • A new cycle does not start without the required new request.

Step 7: Test rejected-start conditions

Where permitted by the approved test procedure, verify that the cycle does not start when a required permissive is missing.

Examples include:

  • Wrong operating mode.
  • Missing workpiece.
  • Required device not ready.
  • Blocking fault active.
  • Invalid initial position.
  • Invalid communication status.

Confirm that the HMI or diagnostic system identifies the blocking condition appropriately.

Do not create unsafe conditions or defeat safety functions to test start rejection.

Step 8: Test fault handling and recovery

Using approved test methods, verify relevant failure scenarios such as:

  • Device fails to complete an operation.
  • Feedback does not arrive.
  • A device reports a fault.
  • Communication is lost.
  • A process result is invalid.
  • A step timeout occurs.

Check that the sequence stops or transitions according to the defined fault strategy, that relevant commands are handled correctly, and that recovery requires the appropriate conditions.

Step 9: Repeat the test

After the first successful cycle, repeat the single-cycle test as required by the project test plan.

Repeated testing can expose issues such as:

  • Incomplete reset of step flags.
  • Retained start commands.
  • Stale device-complete signals.
  • Incorrect counter initialization.
  • Actuators not returning to the expected state.
  • Previous-cycle data contaminating the next cycle.

The required number of successful cycles should come from the approved commissioning and acceptance plan.

12. Practical Example: Automotive Fixture Assembly Station

12.1 Machine description

Consider an assembly station with:

  • Part-presence sensor.
  • Pneumatic clamp.
  • Servo positioning slide.
  • Assembly tool.
  • Result sensor or process controller.
  • PLC and HMI.

The purpose is to position and clamp a component, perform an assembly operation, release the component, and report cycle completion.

12.2 Illustrative sequence

Step Command Required feedback Fault condition
0 Wait for start Machine ready Start permissive missing
10 Verify part Part present Part absent or invalid
20 Clamp part Clamp closed Clamp timeout
30 Position slide Target position reached Motion fault or timeout
40 Execute assembly Tool complete and result valid Tool fault or invalid result
50 Return slide if required Defined return position reached Return-motion fault
60 Unclamp part Clamp open Unclamp timeout
70 Complete cycle All required end conditions satisfied End condition not satisfied

This is only an example. Actual order depends on the mechanical process, tooling design, and risk assessment.

12.3 Commissioning observations

Suppose the clamp closes correctly, but the sequence never advances to Step 30.

The correct diagnostic process is:

  1. Confirm the sequence remains in Step 20.
  2. Check whether the clamp command was issued.
  3. Check the actual clamp-closed input.
  4. Compare the physical clamp state with the sensor state.
  5. Verify the PLC input mapping and feedback logic.
  6. Check for a blocking fault or missing additional permissive.
  7. Review the transition condition from Step 20 to Step 30.

Do not simply increase the clamp timeout. If the sensor is misaligned or the transition condition is incorrect, a larger timer only delays the same failure.

13. Cycle Time and Performance Monitoring

Single-cycle commissioning is primarily concerned with correct operation, but cycle-time measurements can reveal timing and performance issues.

Cycle time is the elapsed time between the defined start and end events of one cycle.

\[ T\_{\text{cycle}} = t\_{\text{end}} - t\_{\text{start}} \]

The start and end events must be defined consistently. For example, the project may measure from accepted cycle start to cycle complete.

A cycle may include:

  • Part verification.
  • Clamping.
  • Positioning.
  • Processing.
  • Inspection.
  • Unloading or release.
  • Return-to-ready operations.

The total time depends on whether operations execute sequentially or overlap.

For sequential operations:

\[ T\_{\text{cycle}} \approx \sum\_{i=1}^{n} T_i \]

For operations that run in parallel, total cycle time depends on the timing and synchronization of the overlapping operations, not simply the sum of all individual operation times.

During commissioning, record:

  • Start timestamp.
  • End timestamp.
  • Total cycle time.
  • Step durations where available.
  • Unexpected waiting time.
  • Device timeouts.
  • Process result.
  • Any operator intervention.

Do not optimize cycle time by removing necessary interlocks, feedback checks, or safety-related conditions.

14. Fault Handling, Timeouts, and Recovery

14.1 Step timeout

A step timeout detects that an expected operation has not completed within its defined time limit.

For example, after a clamp command, the PLC expects closed-position feedback within the approved timeout.

A timeout should identify the failed operation and lead to the defined response. It should not automatically assume that the actuator is physically in a safe state.

14.2 Fault response

Depending on the machine design, a fault may cause the sequence to:

  • Stop advancing.
  • Cancel or remove specified commands.
  • Request a controlled stop.
  • Set a cycle fault.
  • Display the failed step.
  • Record diagnostic information.
  • Require operator intervention.

The required response depends on the type of fault, the equipment, and the approved safety and control design.

14.3 Recovery after a fault

Before restarting a failed cycle, the system must establish a valid recovery state.

Questions that must be answered include:

  • Which step failed?
  • Which outputs or device commands remain active?
  • Did the workpiece move or change state?
  • Is the process result valid?
  • Are device states known and trustworthy?
  • Is the machine in the expected physical position?
  • Does the machine need a defined recovery sequence?
  • Must the current part be rejected or reprocessed?

A generic reset must not blindly restart a cycle from the beginning if the physical machine is partway through an operation.

14.4 Reset versus recovery

  • Reset clears a fault or restores a controller state when the reset conditions are satisfied.
  • Recovery restores the machine and process to a valid operating condition.

Resetting a fault does not prove that the machine is ready to resume production.

15. PLC Programming Considerations

A robust single-cycle sequence should define:

  • Operating-mode selection.
  • Start-command acceptance.
  • Initial-state validation.
  • Sequence state or step number.
  • Commands for each step.
  • Transition conditions.
  • Step timeout handling.
  • Fault-state behavior.
  • Cycle-complete behavior.
  • Reset and recovery logic.
  • Prevention of unintended repeated starts.
  • Appropriate handling of communication loss and stale device status.

15.1 Preventing accidental multiple starts

A single-cycle command should be processed according to a clearly defined command-handling method.

For example:

IF Single_Cycle_Mode
   AND Start_Request_Edge
   AND Start_Permissive
   AND NOT Sequence_Active
   AND NOT Cycle_Fault
THEN
    Start_Sequence
END_IF

This is conceptual pseudocode. It does not include every condition required by a real machine.

The implementation must also handle retained requests, reset behavior, HMI communication failures, mode changes, and command ownership.

15.2 Avoiding stale completion flags

Suppose a robot's COMPLETE signal remains true after the previous cycle. If the PLC does not correctly reset or handshake that signal, the next cycle may treat the previous result as the current result.

The design should define when completion signals are cleared, when they are accepted, and how the PLC confirms that the result belongs to the current operation.

15.3 Retained state and power restoration

If power is lost during a cycle, the PLC or device controller may retain some values while physical actuators move or lose their state.

On restoration, the machine must not automatically resume solely because a retained step number indicates that the cycle was in progress.

The restart strategy must establish the current physical state, validate device readiness, apply required safety and process checks, and follow the approved recovery design.

16. HMI Design for Single-Cycle Operation

The HMI should make the cycle state clear to the operator and commissioning engineer.

Useful information includes:

  • Selected operating mode.
  • Start permissive status.
  • Cycle-start request and acceptance.
  • Current sequence step.
  • Active operation.
  • Device feedback.
  • Remaining or elapsed step time where appropriate.
  • Cycle-complete status.
  • Fault and failed-step information.
  • Recovery instructions or required operator action.
  • Process result and traceability information.

The HMI should distinguish between START REQUESTED, SEQUENCE ACTIVE, CYCLE COMPLETE, and CYCLE FAULT.

These states are not interchangeable. Clear status indication reduces the risk of repeated commands and unnecessary troubleshooting.

17. FAT and SAT for Single-Cycle Operation

FAT (Factory Acceptance Test) verifies the sequence and expected behavior against the agreed design before shipment or site acceptance.

SAT (Site Acceptance Test) verifies the installed system with its actual field devices, communications, tooling, and site conditions.

Test area FAT objective SAT objective
Start permissives Verify defined acceptance and rejection logic Verify actual site conditions and devices
Sequence order Verify the programmed step order Verify the real machine follows the intended order
Feedback Verify signal mapping and transition logic Confirm physical sensors and devices
Device handshake Verify request, busy, complete, and fault handling Verify actual connected equipment behavior
Timeouts Verify configured timeout and fault logic Confirm timing under actual installed conditions
Cycle completion Verify defined end-state logic Confirm physical machine state matches completion status
Fault handling Verify expected diagnostic and stop behavior Verify relevant real-device faults and approved recovery
Repeatability Verify repeated single-cycle execution Confirm stable behavior under site conditions
Traceability Verify data and result handling Confirm actual production data and result recording
Safety Review and test according to the approved plan Complete required site safety validation

Acceptance criteria should be taken from the approved project specification. Do not invent universal timeout values or cycle-time limits.

18. Common Single-Cycle Commissioning Mistakes

  • Treating a successful start command as proof of a successful cycle.
  • Advancing steps based on command status instead of required feedback.
  • Failing to verify the initial machine state.
  • Ignoring stale completion signals from a previous operation.
  • Allowing a held start command to trigger repeated cycles.
  • Failing to distinguish cycle completion from machine readiness.
  • Using arbitrary timeout increases to conceal a device or feedback problem.
  • Resetting a fault without checking the physical machine state.
  • Restarting from a retained step without validating recovery conditions.
  • Testing the sequence only once.
  • Ignoring the result-valid handshake of robots, CNCs, scanners, printers, or test equipment.
  • Optimizing cycle time before confirming correct and safe sequence behavior.

19. Interview Questions and Answers

Q1. What is single-cycle operation?

It is a mode in which the machine executes one complete automatic sequence and then stops at its defined end condition, waiting for another start request or a specified operating-mode transition.

Q2. Why is single-cycle testing performed before auto-cycle testing?

It verifies the complete sequence, transitions, feedback, timing, and fault behavior without immediately introducing repeated production cycles.

Q3. What is the difference between cycle start and cycle complete?

Cycle start initiates a request to execute the sequence. Cycle complete indicates that the defined operations and end conditions have been satisfied.

Q4. Why must each step use valid feedback?

Feedback confirms that the expected physical or device state has been reached. Without it, the sequence may advance despite a failed or incomplete operation.

Q5. What is a step timeout?

A step timeout detects that an expected operation has not completed within its specified time limit and triggers the defined diagnostic or fault response.

Q6. Why can a machine report cycle complete when the workpiece is not ready to unload?

The completion logic may omit an essential end condition, use incorrect feedback, or accept stale status data. The functional specification and cycle-end logic must be checked.

Q7. What is the difference between reset and recovery?

Reset clears a fault or restores a control state when permitted. Recovery establishes a valid machine and process state after a fault or interruption.

Q8. Why must single-cycle operation be repeated during commissioning?

Repeated tests can reveal retained flags, incomplete resets, stale device handshakes, incorrect counters, and other faults that do not appear during the first cycle.

Q9. How should a PLC handle a device that never reports completion?

It should apply the defined timeout and fault-handling strategy, provide useful diagnostics, and prevent invalid sequence progression.

Q10. What is the difference between single-cycle and auto-cycle operation?

Single-cycle operation executes one complete cycle per accepted start request. Auto-cycle operation repeats cycles according to the defined automatic-run logic until stopped, inhibited, or faulted.

Q11. Should the PLC resume the previous sequence step automatically after power restoration?

Not unless the approved design explicitly permits it and the required recovery, physical-state, process, and safety conditions have been validated. Retained software state alone is insufficient.

Q12. What proves that single-cycle commissioning is complete?

Documented successful execution of the required sequence, correct feedback and transitions, verified end-state behavior, fault handling, recovery, repeatability, and satisfaction of the approved acceptance criteria.

20. Final Single-Cycle Commissioning Checklist

  • Functional specification and sequence documentation are available.
  • Initial machine state and start permissives are verified.
  • Single-cycle mode selection is correct.
  • Start requests are accepted and cleared as designed.
  • Sequence steps execute in the correct order.
  • Commands and physical feedback are independently verified.
  • Device handshakes and result-valid signals are correct.
  • Step transitions depend on the required completion conditions.
  • Timeouts and fault responses are verified.
  • Cycle completion matches the defined end state.
  • The machine does not repeat the cycle unintentionally.
  • Fault reset and recovery behavior are verified.
  • Power-restoration behavior follows the approved design.
  • Required traceability and process results are recorded correctly.
  • Repeated single-cycle tests meet the acceptance criteria.
  • No unauthorized bypasses, forced commands, or temporary commissioning changes remain.
  • FAT/SAT results and outstanding deviations are documented.

Core principle: Single-cycle commissioning proves that one complete automatic sequence executes in the correct order, uses valid feedback, handles faults properly, and finishes in the intended machine state without unintended repetition.
