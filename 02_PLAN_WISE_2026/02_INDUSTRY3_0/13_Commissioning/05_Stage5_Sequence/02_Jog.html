1. Definition and Purpose

Jog mode is an operating mode or motion-control function that allows an operator or authorized commissioning engineer to move a machine, actuator, axis, or mechanism in a controlled manner, usually for a limited distance, direction, or duration.

Depending on the equipment, jog movement may continue while a command is held, stop when the command is released, or move by a configured incremental distance.

Jog mode is commonly used during:

  • Machine positioning and alignment.
  • Robot and CNC setup.
  • Conveyor direction verification.
  • Servo-axis movement and homing preparation.
  • Fixture, slide, and actuator adjustment.
  • Tooling alignment and clearance checks.
  • Commissioning of motion limits and feedback.
  • Maintenance and controlled recovery.

The central purpose is to verify controlled movement before running a complete production cycle.

Jog does not automatically mean slow, safe, or limited-distance movement. Speed, direction, distance, enabling conditions, and stopping behavior must be defined by the equipment design and applicable safety requirements.

2. Manual Mode vs Jog Mode

Manual mode and jog mode are related but not identical.

Feature Manual mode Jog mode
Main purpose Operate individual machine functions Produce controlled movement or incremental operation
Typical command Clamp, unclamp, conveyor forward Axis positive, axis negative, jog forward
Movement behavior May be a discrete action or maintained operation Commonly held-command or incremental movement
Position control Depends on the function Often position- or direction-oriented
Typical application Pneumatic actuator, motor, machine function Servo axis, CNC axis, robot setup, conveyor positioning
Completion Feedback, sequence condition, or command completion Command release, target increment reached, or defined stop condition
Safety requirements Depend on the machine and task Depend on movement hazards, access, controller, and operating mode

Some machines implement jog as a function inside manual mode. Others provide separate setup or jog modes. The machine specification defines the actual behavior.

3. Where Jog Fits in Commissioning

Jog commissioning follows the verification of individual manual functions and precedes single-cycle testing.

Installation and device checks
             ↓
I/O and communication verification
             ↓
Safety and operating-mode checks
             ↓
Manual function commissioning
             ↓
Jog movement commissioning
             ↓
Single-cycle commissioning
             ↓
Continuous automatic operation
             ↓
Integrated performance and acceptance testing

The distinction is important:

  • Manual commissioning verifies that individual functions operate correctly.
  • Jog commissioning verifies controlled movement, direction, speed, distance, feedback, and stopping behavior.
  • Single-cycle commissioning verifies that the machine can execute one complete automatic sequence.

A machine should not progress to single-cycle testing if the relevant movement controls, motion limits, or stopping behavior remain unverified.

4. Types of Jog Operation

4.1 Continuous jog

Continuous jog usually commands movement while the jog command remains active.

Example:

  • The operator holds JOG_FORWARD.
  • The controller permits movement.
  • The axis moves in the configured direction.
  • Releasing the command requests stopping according to the defined control behavior.

The axis may travel a considerable distance if the command remains active. A held command is not inherently distance-limited.

4.2 Incremental jog

Incremental jog moves an axis by a configured distance for each accepted command.

For example, a CNC or servo axis might support increments of:

  • 0.01 mm
  • 0.1 mm
  • 1 mm

These are illustrative values, not universal settings. Actual increments depend on the machine, controller, axis, units, and engineering specification.

If the selected increment is \(d\), the requested position change is:

\[ \Delta x = \pm d \]

The sign indicates the requested direction in the configured coordinate system.

Incremental movement must account for axis limits, target-position validation, and controller-specific motion behavior.

4.3 Speed-limited jog

A controller may support different jog speeds for setup, positioning, or maintenance.

The selected speed must comply with the machine's approved operating restrictions. A software speed command alone does not establish a safety-rated speed limit.

4.4 Robot jog

Robot jog can involve movement along different coordinate systems:

  • Joint coordinates.
  • Cartesian coordinates.
  • Tool coordinates.
  • User or work-object coordinates.

The direction and resulting physical movement depend on the selected coordinate system and active tool or work-frame configuration.

4.5 CNC axis jog

CNC jog typically moves a selected axis using the machine control panel or handwheel.

Relevant settings include:

  • Axis selection.
  • Positive or negative direction.
  • Jog speed or feed setting.
  • Increment selection.
  • Machine coordinate and work coordinate displays.
  • Software and hardware travel limits.
  • Machine operating mode and enabling conditions.

4.6 Servo and linear-axis jog

Servo jog commands movement through a motion controller or drive interface.

Typical requirements include:

  • Servo-ready status.
  • Valid axis configuration.
  • Required homing or reference status.
  • Permitted travel range.
  • Velocity and acceleration limits.
  • Motion-command acceptance.
  • Position feedback.
  • Following-error monitoring.
  • Drive fault handling.

Not every axis requires homing before all forms of movement. The requirement depends on the machine design and whether the controller can determine a valid position reference.

5. Jog Control Architecture

A typical PLC-controlled jog function follows this logical structure.

Operator selects the axis and direction
                 ↓
Controller checks operating mode
                 ↓
Command and motion permissives are evaluated
                 ↓
Requested movement is validated
                 ↓
PLC or motion controller issues the command
                 ↓
Drive or actuator produces movement
                 ↓
Position, speed, and status feedback are evaluated
                 ↓
Movement continues or stops according to the design
                 ↓
HMI displays position, status, or fault

For a robot or CNC, the internal controller may manage the actual jog operation. The PLC may only exchange permission, status, or high-level commands. Do not assume that the PLC directly controls every movement.

7. Jog Permissives and Interlocks

A jog command should be accepted only when the conditions defined for that machine are satisfied.

Typical conditions include:

  • Correct operating mode is active.
  • The selected axis or mechanism is valid.
  • Required operator authorization is present.
  • Drive or controller is ready.
  • No blocking fault is active.
  • Required safety conditions are satisfied.
  • The requested direction is permitted.
  • The target movement does not violate configured limits.
  • No incompatible command is active.
  • Required position-reference conditions are met.
  • Required communication data is valid.

The exact conditions vary. A robot, CNC axis, pneumatic slide, and conveyor do not share one universal set of permissives.

7.1 Opposite-direction command exclusion

Positive and negative jog commands should not unintentionally be active simultaneously.

For example:

IF Jog_Positive_Command
   AND NOT Jog_Negative_Command
   AND Jog_Permissive
THEN
    Accept_Positive_Jog
ELSE
    Reject_Or_Stop_As_Defined
END_IF

This is conceptual pseudocode, not production-ready PLC logic. The actual controller must define how simultaneous commands, command cancellation, and direction changes are handled.

7.2 Limit handling

Jog commissioning must verify the relevant travel restrictions.

Possible restrictions include:

  • Hardware limit switches.
  • Software travel limits.
  • Position targets.
  • Mechanical end stops.
  • Robot workspace limits.
  • Drive or controller motion limits.
  • Safety-rated motion restrictions where required.

Do not deliberately drive an axis into a mechanical stop to test a limit. Use the approved commissioning procedure and the manufacturer's recommended method.

8. Speed, Distance, and Motion Parameters

8.1 Jog speed

Jog speed determines how quickly the mechanism moves when the jog command is active.

For a linear axis, velocity may be expressed in mm/s or mm/min. For a rotary axis, it may be expressed in degrees/s or revolutions/minute.

A speed setting must be verified against the controller's units and scaling. A value of 100 has little meaning without knowing whether it represents mm/min, mm/s, a percentage, or an internal drive unit.

8.2 Incremental distance

For incremental jog, the controller executes a requested movement distance.

If the starting position is \(x_0\) and the requested increment is \(\Delta x\), the target position is:

\[ x\_{\text{target}} = x_0 + \Delta x \]

The controller must validate the target against the permitted travel range before executing the move.

8.3 Acceleration and deceleration

The acceleration and deceleration settings determine how rapidly the axis changes velocity.

Incorrect settings can cause:

  • Excessive mechanical shock.
  • Vibration or oscillation.
  • Positioning errors.
  • Following-error faults.
  • Excessive stress on tooling or workpieces.
  • Unacceptable stopping behavior.

Jog commissioning should use the approved parameters and verify the physical response rather than changing motion parameters experimentally without authorization.

8.4 Stopping behavior

Releasing a jog command may initiate a controlled deceleration rather than an instantaneous stop.

The actual stopping behavior depends on the controller, drive, actuator, load, configured ramp, and applicable safety function.

Verify:

  • What happens when the command is released.
  • Whether a stop request is accepted immediately.
  • Whether the axis stops within the specified limits.
  • Whether the drive remains enabled after stopping.
  • Whether an active fault changes the stopping response.
  • Whether communication loss produces the documented behavior.

An ordinary jog stop and an emergency stop are not interchangeable.

9. Robot Jog Commissioning

Robot jog requires special attention because the same command can produce very different movement depending on the selected coordinate system.

9.1 Joint-coordinate jog

Joint jog commands an individual robot joint.

For example, a positive command may rotate a particular joint in its defined positive direction.

Verify:

  • Correct robot and joint selection.
  • Correct direction.
  • Actual joint-angle feedback.
  • Configured joint limits.
  • Approved speed and enabling conditions.
  • Correct response when the jog command is released.

9.2 Cartesian jog

Cartesian jog commands movement along or around the selected Cartesian axes.

Depending on the controller, the displayed axes may represent the base, tool, or user coordinate system.

Verify:

  • Correct coordinate system.
  • Correct active tool.
  • Correct work or user frame.
  • Correct displayed coordinate values.
  • Expected physical movement direction.
  • Permitted workspace and motion restrictions.

If a robot moves in an unexpected direction, check the active frame and tool configuration before changing the program or wiring.

9.3 Robot operating restrictions

Robot jog must follow the controller's approved operating mode and safety architecture.

Requirements may include:

  • Correct operating-mode selection.
  • Authorized enabling device or enabling switch.
  • Required reduced-speed operation where applicable.
  • Correct protective-device status.
  • Restricted access to the robot's hazard zone.
  • Valid motion limits and safety functions.
  • Approved procedure for entry into the cell.

Do not assume that a standard PLC bit is sufficient to establish a safety-rated robot operating condition.

10. CNC Axis Jog Commissioning

CNC machines often provide manual axis movement through a jog control, handwheel, or equivalent interface.

Before movement, verify:

  • Correct machine mode.
  • Correct axis selection.
  • Correct jog direction.
  • Correct increment or speed selection.
  • Position-reference or homing status where required.
  • Travel limits and interlocks.
  • Drive-ready status.
  • Correct position display.
  • Machine-specific restrictions on spindle, tool, fixture, or door conditions.

10.1 Machine coordinates versus work coordinates

Machine coordinates refer to the machine's reference coordinate system. Work coordinates represent a workpiece or programmed reference frame.

The displayed position can change meaning depending on the selected coordinate display and offsets.

During commissioning, compare the commanded movement with the correct coordinate system. Do not assume that a displayed coordinate of zero means the physical axis is at its mechanical center or end of travel.

10.2 Handwheel movement

A CNC handwheel may command incremental movement according to a selected scale or multiplier.

Verify:

  • Correct axis selection.
  • Correct increment multiplier.
  • Correct direction.
  • Expected position change per detent.
  • Position feedback and travel limits.
  • No unintended movement when the selected axis or multiplier changes.

11. Jog Commissioning Procedure

Step 1: Review the machine design

Review the following before commanding motion:

  • Mechanical layout and axis arrangement.
  • Electrical and drive drawings.
  • PLC I/O list and motion interface.
  • Motion-controller and drive manuals.
  • Axis configuration and scaling.
  • Homing and position-reference requirements.
  • Software and hardware travel limits.
  • Operating-mode and safety requirements.
  • Approved speed, acceleration, and stopping parameters.
  • Machine-specific commissioning procedure.

Step 2: Establish the required safe condition

  • Confirm that personnel are clear of hazardous movement.
  • Verify required guards and safety functions.
  • Confirm the correct operating mode and authorization.
  • Check for mechanical obstruction, unsecured tooling, or loose workpieces.
  • Verify required utility and drive readiness.
  • Apply hazardous-energy isolation when the task requires work on the equipment rather than powered movement testing.

Never use jog mode to reach into a moving mechanism or to replace a required isolation procedure.

Step 3: Verify axis or mechanism identification

Confirm the displayed axis name matches the intended physical mechanism.

Examples include:

  • X_AXIS
  • Y_AXIS
  • Z_AXIS
  • CONVEYOR_01
  • ROBOT_JOINT_3
  • FIXTURE_SLIDE

Verify identification using approved documentation and a controlled test. Do not assume that a label on an HMI proves the physical axis mapping is correct.

Step 4: Verify direction

Using the approved initial test conditions, command a permitted movement and confirm the actual direction.

Record:

  • Commanded direction.
  • Actual physical direction.
  • Position feedback change.
  • Coordinate system or reference direction.
  • Any unexpected movement or fault.

If the movement is wrong, stop testing and investigate the axis mapping, motor direction, mechanical transmission, coordinate system, and controller configuration.

Step 5: Verify movement and feedback

Confirm that:

  • The motion command is accepted.
  • The drive or controller enters the expected state.
  • Actual movement occurs.
  • Position feedback changes in the expected direction.
  • The reported velocity is plausible.
  • The controller does not report an unexplained following error.
  • No unexpected vibration, noise, or mechanical interference occurs.

Step 6: Verify release and stop behavior

For held-command jog, release the command and verify the defined stopping response.

For incremental jog, verify that the commanded increment completes correctly and that no additional movement occurs beyond the expected behavior.

Check stopping and cancellation behavior using the approved procedure.

Step 7: Verify limits and fault handling

Verify the configured limit behavior and relevant fault responses using the approved commissioning method.

Do not intentionally exceed a travel limit, create an unsafe motion condition, or disable a safety function to prove that the controller can detect it.

Step 8: Record results

Document axis identity, command direction, observed movement, position feedback, selected speed or increment, limit behavior, faults, and acceptance result.

Resolve deviations before proceeding to single-cycle testing.

12. Example: Servo Slide Jog Commissioning

Scenario

An automotive assembly fixture uses a servo-driven slide to position a component before clamping.

The slide has positive and negative jog commands, position feedback, drive-ready status, and travel limits.

Expected behavior

  1. The operator selects the approved jog mode.
  2. The controller confirms the required permissives.
  3. The operator requests movement in the positive direction.
  4. The motion controller validates the request and applicable limits.
  5. The servo axis moves according to the configured motion parameters.
  6. Position feedback changes in the expected direction.
  7. Releasing the jog command produces the defined stopping behavior.
  8. The HMI displays the actual position and axis state.

Diagnostic cases

Observation Possible issue Diagnostic action
Jog command is visible but axis does not move Missing enable, fault, permissive, or command ownership Check motion-controller and drive status
Axis moves in the wrong direction Direction mapping, coordinate system, motor configuration Stop and verify approved axis configuration
Position feedback does not change Feedback or communication fault Check encoder, drive feedback, and controller data
Axis stops unexpectedly Limit, interlock, drive fault, or following error Review fault history and axis status
Axis continues moving after command release Incorrect command lifecycle or controller behavior Stop according to the approved procedure and investigate command handling
Axis moves farther than the selected increment Incorrect increment configuration or scaling Verify units, scaling, and motion-command configuration
Axis faults near a limit Travel restriction or incorrect reference position Check reference status, limits, and configured travel range

The commissioning objective is to prove that command, movement, feedback, and stopping behavior agree with the approved design.

13. Troubleshooting Jog Faults

Symptom Likely causes First diagnostic check
Jog button has no effect Mode, permissive, authorization, or command mapping Monitor the request and permissive states
Drive is not ready Drive fault, enable condition, power issue Check drive diagnostics and readiness conditions
Axis moves in the wrong direction Incorrect mapping, configuration, or coordinate frame Compare command and actual direction
Axis does not stop as expected Incorrect command handling, stop configuration, or fault Follow the approved stop procedure and inspect controller status
Position changes incorrectly Feedback scaling, encoder configuration, units Compare actual feedback with the controller's reference
Axis reaches a limit unexpectedly Incorrect reference, travel configuration, or position mapping Verify homing, limit settings, and actual axis position
Jog speed is incorrect Wrong units, scaling, speed selection, or parameter Check approved motion settings
Robot moves along an unexpected axis Wrong coordinate frame, tool, or axis selection Verify the active coordinate system and tool
CNC moves an unexpected distance Increment multiplier or handwheel scaling Verify the selected increment and position display
Servo following-error fault Excessive commanded motion, mechanical resistance, tuning, or feedback problem Review drive diagnostics and mechanical condition
Communication loss during jog Network, device, or controller connection fault Check connection status and defined motion-loss response
Jog works but automatic movement fails Different command ownership, sequence permissives, or motion profile Diagnose the automatic command path separately

Do not repeatedly reset drive faults without identifying the cause. A fault may be protecting the equipment from an actual mechanical or control problem.

14. FAT and SAT for Jog Mode

Factory Acceptance Testing (FAT) verifies the intended jog behavior under the agreed factory test conditions.

Site Acceptance Testing (SAT) verifies the installed machine and actual motion behavior at the production site.

Test area FAT objective SAT objective
Axis selection Verify correct command-to-axis mapping Confirm the correct physical axis moves
Direction Verify configured positive and negative movement Confirm actual physical direction
Speed or increment Verify approved settings and command behavior Confirm actual movement and feedback
Limits Verify defined limit and command-rejection logic Confirm installed limit devices and configured restrictions
Feedback Verify position and status mapping Confirm actual feedback and physical response
Command release Verify defined stop behavior Confirm installed equipment stops as designed
Fault handling Verify diagnostic and recovery logic Verify actual device faults and approved recovery
Safety Verify design against the approved safety requirements Complete the required site validation of safety functions
Documentation Record configuration and test results Record as-built settings, deviations, and acceptance

Numerical limits for speed, position error, stopping distance, or recovery time must come from the approved machine specification, controller documentation, risk assessment, and test plan.

15. Common Jog Commissioning Mistakes

  • Assuming jog mode automatically limits speed or distance.
  • Confusing PLC command status with actual physical movement.
  • Testing direction without verifying the coordinate system.
  • Ignoring encoder scaling or engineering units.
  • Jogging before confirming the correct axis and position reference.
  • Using arbitrary speed or acceleration settings.
  • Driving an axis into a mechanical stop to test a limit.
  • Assuming the release of a jog command always produces an instantaneous stop.
  • Treating a standard stop command as equivalent to an emergency stop.
  • Ignoring robot enabling devices or operating-mode restrictions.
  • Assuming PLC mode selection controls the internal mode of every robot or CNC.
  • Proceeding to single-cycle testing while motion feedback or limits remain unverified.

16. Interview Questions and Answers

Q1. What is jog mode?

Jog mode allows controlled movement of a machine mechanism or axis, commonly through a held command or a configured movement increment.

Q2. What is the difference between continuous jog and incremental jog?

Continuous jog typically commands movement while the command remains active. Incremental jog requests a defined movement distance for each accepted command.

Q3. Why must jog direction be verified during commissioning?

Incorrect direction can cause collisions, incorrect positioning, mechanical damage, and failures during later automatic operation.

Q4. What is the difference between commanded position and actual position?

Commanded position is the target requested by the controller. Actual position is the measured or controller-reported position of the axis.

Q5. What is a following error?

Following error is the difference between commanded and actual position, where the controller supports that diagnostic. Excessive error may indicate mechanical resistance, incorrect tuning, excessive motion demand, or a feedback problem.

Q6. Why is homing important?

Homing establishes a known reference position when required by the motion-control system. Without a valid reference, absolute position and travel-limit interpretation may be unreliable.

Q7. Does releasing a jog button stop an axis immediately?

Not necessarily. The controller may execute a configured deceleration or another defined stopping response. Actual behavior must be verified against the machine specification.

Q8. Why might a robot move in an unexpected direction during Cartesian jog?

The active coordinate frame, tool configuration, user frame, axis selection, or controller configuration may differ from what the operator expects.

Q9. What should be checked if a servo axis does not move during jog?

Check mode selection, command acceptance, permissives, drive readiness, active faults, enable conditions, limits, and motion-controller status.

Q10. Why should limits not be tested by deliberately hitting mechanical stops?

Mechanical impact can damage the mechanism and does not necessarily verify the correct operation of the intended limit system. Use the approved test procedure.

Q11. What must be verified before single-cycle commissioning?

Relevant motion directions, feedback, speed or increments, stopping behavior, travel restrictions, command handling, and required safety functions must meet the approved commissioning criteria.

17. Final Jog Commissioning Checklist

  • Approved motion and safety documentation is available.
  • Correct operating mode and authorization are verified.
  • Correct axis or mechanism identification is confirmed.
  • Positive and negative directions match the approved design.
  • Speed, increment, acceleration, and units are verified.
  • Position reference and homing requirements are satisfied.
  • Actual position and status feedback are correct.
  • Travel limits and movement restrictions are verified.
  • Opposing commands and command cancellation are handled correctly.
  • Command release and stopping behavior are verified.
  • Relevant drive, following-error, and communication faults are diagnosed.
  • Required safety functions remain effective and are validated.
  • No unauthorized forced commands or configuration changes remain.
  • FAT/SAT results and deviations are documented.
  • The machine is ready for single-cycle commissioning.

Core principle: Jog commissioning proves that each movement command produces the intended physical motion, in the correct direction, within approved operating limits, with valid feedback and predictable stopping behavior.
